## Findings considered and rejected

(So nobody re-audits these.)

- `cacheLife("minutes")` "under-specified" — it is a documented Next.js 16
  named cache profile; by-design, not a gap.
- Contributions search pipeline "waterfall"
  (`packages/api/src/admin/contributions/service.ts`) — resolving donor IDs
  before the filtered donation query is inherent to the search semantics;
  batching elsewhere in that service is already correct (`.in()` +
  `Promise.all`). Low leverage.
- Consolidating `packages/api`'s ~99 granular package exports into barrel
  index files — granular entry points are the better pattern for
  tree-shaking/bundle size; barrels would regress performance. Not worth
  doing.
- "Admin vs missionary authenticated-fetch divergence" — evidence did not
  hold up: `createBrowserClient` has zero grep hits in `apps/missionary`.
- Deep relative imports in admin CMS API routes (`../../../../../../src/cms/*`)
  — cosmetic; a tsconfig alias is mechanical but low-value. Do during the
  next CMS refactor.
- View-transition name registry / API docs — documentation suggestion, not a
  defect.
- Staged-gift check-then-insert "race" — already idempotent by design via
  the 23505 unique-violation fallback.
- Staged-gift allocation with null fund AND null missionary — by design:
  `determineInitialReview` routes undesignated gifts into the `needs_review`
  flow.
- `saga.ts` nullable `clientSecret` passthrough — the only caller
  (`packages/api/src/donate/index.ts:129`) already null-checks; type
  tightening only, fold into any future saga work.
- Missionary donors-page hook re-filtering (`use-donors-page-view.tsx`) —
  audited for missing memoization; the filtering IS correctly memoized
  (`filterAndSortDonors` behind `useMemo`). Clean.
- CMS `supabase-strategy` unit-test timeouts — pre-existing P0 already
  documented with a fix sketch in `CODE_QUALITY_AUDIT.md`; test-infra is
  outside this audit's requested categories (perf/bugs/architecture).
