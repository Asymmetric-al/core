# Multi-Site Foundation Documentation Design

## Authority

`CONTEXT.md` defines Site. Phase 2's solution and A1–A5 define the foundation;
explicit Phase 24 amendments govern domain (D72 onward), exact-locale public
publication (D15/D66), account host/brand (D57/D58), Site Brand (D59), and
proof-qualified donor presentment (D61). Legal Entity and payment owners retain
financial authority. The current Phase 22/23/24 and parity active changes remain
in force; this change neither duplicates their requirements nor qualifies them.

## Scope And Compatibility

Preserve existing requirement titles and all still-valid scenarios so active
MODIFIED targets remain usable. Add one distinct foundational boundary
requirement; keep four product areas while allowing several public Sites.
Asym Postgres `public.*` owns operational identity, CRM and money; CMS owns
content/presentation. Operational Domain authority supplies read-only domain
projections rather than mutable CMS fields. SiteStacker site channel maps
approximately to Site for future import without another hierarchy.

Only the three assigned platform specs, Area 14 of the parity matrix, and this
active documentation change are affected. No app, package, API, job, store,
provider, route, or migration changes. Structural checks provide documentation
evidence only. Runtime qualification and activation remain unexecuted.

## Rollback

Revert this patch without changing source PRDs, runtime state, or active
implementation changes. Keep this change active until accepted repository
integration permits a separately authorized archive.
