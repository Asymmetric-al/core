## ADDED Requirements

### Requirement: Phase25 Exact Donor Context And Native Authentication Qualification

Donor-facing access SHALL use the existing current Tenant Authorization Context and validated assignment; exact record grants narrow, never replace, that context. Personal, represented, reader, credential and document subjects remain distinct. Native social linking SHALL remain unactivated until the supported direct-endpoint possession guarantee is established; a Core callback or hidden button is insufficient.

#### Scenario: Exact task return

- **WHEN** a qualified represented or record-specific task crosses authentication
- **THEN** the same current permitted task/subject is restored without fabricated donor records or broader list rights

#### Scenario: Native linking not qualified

- **WHEN** the selected native social profile lacks the required supported pre-link guarantee
- **THEN** affected activation remains blocked; no experimental isolation, broker/fork or provider removal is silently substituted

#### Scenario: Personal contact update

- **WHEN** a donor changes a permitted ordinary contact field
- **THEN** the exact owner atomically records the current personal change and audit without mutating Auth, legal/public/billing/represented identity

### Requirement: Phase25 Guest-Origin Newsletter Recipient Access

Before the Q25 consumer is dispatched, P28 and P12 SHALL implement and qualify the already-ratified narrow guest-origin recipient-access extension. The recipient view SHALL project the same immutable P23 request to its frozen intended human only while current exact Page/typed-subject/purpose, field and safety authority still admits it. Guest origin SHALL NOT require a fabricated donor, supporter, follower, account linkage or fifth Tenant context. Read, Archive, Copy, authentication and replay SHALL preserve the original source identity and payload-access lifetime and SHALL NOT create a request, enrollment or broader permission.

#### Scenario: Intended recipient reads a guest-origin request

- **GIVEN** a qualified P23 request is addressed to its frozen intended human and its detail remains available
- **WHEN** that human opens it through a currently authorized P28/P12 context
- **THEN** the admitted source detail is available without inventing a financial or supporter relationship for the visitor
- **AND** the displayed request and body-access deadline retain their original source meaning

#### Scenario: An unrelated or newly assigned person attempts access

- **WHEN** a new assignee, spouse, Page editor, generic missionary role, same-email account or revoked context attempts the request through any exposed path
- **THEN** access is denied unless that exact frozen recipient and current source-purpose authority independently admit it
- **AND** expired or withdrawn detail is not restored by reassignment, authentication, local engagement or replay
