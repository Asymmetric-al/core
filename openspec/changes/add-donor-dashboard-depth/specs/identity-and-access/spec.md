## ADDED Requirements

### Requirement: Phase25 Exact Donor Context And Native Authentication Qualification

Donor-facing access SHALL use the existing current Tenant Authorization Context and validated assignment; exact record grants narrow, never replace, that context. Personal, represented, reader, credential and document subjects remain distinct. Native social linking SHALL remain unactivated until the supported direct-endpoint possession guarantee is established; a Core callback or hidden button is insufficient.

#### Scenario: Exact task return

- **WHEN** a qualified represented or record-specific task crosses authentication
- **THEN** the same current permitted task/subject is restored without fabricated donor records or broader list rights

#### Scenario: Native linking not qualified

- **WHEN** the selected native social profile lacks the required supported pre-link guarantee
- **THEN** affected activation remains blocked; no experimental isolation, broker/fork or provider removal is silently substituted

#### Scenario: Personal contact update

- **WHEN** a donor changes a permitted ordinary contact field
- **THEN** the exact owner atomically records the current personal change and audit without mutating Auth, legal/public/billing/represented identity
