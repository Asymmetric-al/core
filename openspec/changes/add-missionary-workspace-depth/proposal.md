# Phase 28 — Missionary Workspace Depth & Support-Raising CRM

## Why

Missionaries need one useful support-raising workspace within their sending organization, with truthful relationships, commitments, received gifts, follow-through, communication and optional coaching. Existing UI and legacy storage do not establish the selected Phase 28 source, privacy or lifecycle contracts. The founder completed D1–D50 and the whole-journey review, invoked `/to-spec`, and confirmed the existing testing seams on October 18, 2026.

- Formalize restricted preparation, deliberate contact sharing, reviewed import, native relationship work, referrals, departure/return and organization-controlled retention.
- Formalize distinct financial measures, authorized goal management, native purpose-specific stewardship, optional missionary gift reporting, tenant correction policy and preserved campaign attribution.
- Complete native newsletter signup/authoring/sending/print and narrow personal-email/calendar journeys through existing source owners, with optional bounded writing help.
- Formalize voluntary own-principal coaching, exact summary/history/duration, activity targets, check-ins, selected next steps, curated resources, optional starting guide and public-safe regional discovery.

## Capabilities

### New Capabilities

- `missionary-workspace-depth`: the composed, permission-scoped Phase 28 product journeys and their exact source contracts.

### Modified Capabilities

Existing CRM, identity, communication, contribution, recurring, Page/CMS and donor-development owner contracts receive only the explicit coordinated amendments listed in the owner-reconciliation volume. Their existing active projections remain synchronized with their canonical sources. This consumer phase does not acquire their write authority.

## Impact

The missionary, authorized Mission Control, own-principal coach and public/donor-reader experiences consume canonical API/auth/database and shared UI modules. P9/P12 source extensions, P13/P14/P15/P16 financial sources, P6/P17 communication, P21/P22/P23/P27/P29/P31 purpose interfaces and exact existing implementation issues remain separately qualified dependencies. Optional products do not back-gate native work.

## Non-goals

This change publishes a specification. It does not implement features, activate integrations, dispatch real messages or decompose implementation tickets. No shadow CRM/ledger/subscriber master, compulsory coaching/reporting/course, general inbox/contact sync, new workflow engine or precise-location publication is introduced.

## Rollout and rollback

Implementation must inventory retained data, ship compatible source contracts and readers, prove migrations/replay/restore, retire competing writers and activate only qualified capabilities. A disable or rollback stops the affected new work while preserving accepted obligations, financial facts and exact recovery. It cannot restore an unsafe legacy writer or reinterpret retained consent/history. This planning change remains active until implementation becomes accepted repository reality.
