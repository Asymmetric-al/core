# Files and Documents — implementation design

## Status and authority

This design implements the ratified Phase 29 contracts through the testing seams confirmed by the user. It describes future implementation; no migration, provider configuration, native qualification or feature activation has occurred through this publication. The canonical requirement volumes and their complete incorporated source clauses govern. A summary here never narrows a requirement or changes a specialist owner's permission, clock or retention rule.

The source/consumer registers enumerate 23 existing and 11 future consumers individually. They distinguish an actual current producer, an intended contract, a missing source binding and a future conditional file lane. Implement the applicable row, not a generic adapter inferred from its phase title. Independently qualified foundation work does not wait for an unrelated future phase. Missing material policy meaning blocks the affected consequential behavior; it cannot be replaced by a permissive default or a nominally green test.

## Architecture and ownership

Use the existing shared server API boundary for source commands, permission-filtered queries and file-serving operations. Mission Control, donor/recipient, missionary and public surfaces remain thin clients of those contracts. Reuse native Auth, the P12 decision point, prescribed coarse Tenant RLS, shared static field classification and subtract-only projection, existing background execution and the source-owned P6/P17 delivery contracts. No second CRM, generic drive, event-sourcing platform, parallel permission engine, scheduler or global policy language is selected.

The ordinary request source owns issuance, item requirements, recipient access, contributions, review, acceptance, fulfillment and their corrections. The resource source owns exact publication and audiences, review, reports and personal preferences. Partner-reference admission owns its distinct ongoing purpose without granting the original request transcript. The ordinary records source owns supported tenant policy definitions, effective versions, assignments and interpretation of accepted typed facts. Shared custody owns immutable bytes, representations, copies, protected references and qualified serving/processing. Specialist sources retain issuance, posted facts, public release, import, Support and records meaning.

Source adapters supply exact typed commands, current capability checks, reference protection and current restriction/repair results. They do not return a generic `allowed` boolean that erases which source, action, scope, version and representation were evaluated. The actual native command can be called without installing a configurable Workflow. Workflow consumes or invokes that same contract with its own qualified identity; an event label or registry entry is not a source implementation.

## Source command and query contract

Each command has a narrow action, exact target, complete intended payload, relevant expected basis and operation identity. The server derives actor, Tenant/environment and permitted source context from the current native session or qualified NHI. Client values select or describe intent; they are not authority. Commands retain the existing request-origin/CSRF protections. GET, render, prefetch, menu inspection, blur and IME confirmation are inert; deliberate focused controls remain usable.

Common command processing follows this order, with source-specific exceptions explicitly preserved:

1. Establish trusted current context and sufficient authority to disclose or recover the requested operation. Reject foreign scope without revealing hidden existence.
2. Recover a matching committed semantic result before evaluating the request as new work. Return that original result with a separately authorized current projection; do not relabel an old Add as an End or revive a retracted event. Changed meaning under an existing operation identity conflicts.
3. For genuinely new work, validate the exact current target, source-qualified schema/profile, current capability, relevant expected revision, semantic equivalence and actual dependencies after waits. Stale change-away-and-back remains stale. Unrelated display metadata is not a universal conflict trigger.
4. Commit the authoritative effect, required current controls, history, original result and durable necessary follow-through coherently in the owning database boundary. Return only facts established by that commitment. A failed projection refresh cannot turn known success into failure.
5. Perform qualified external processing or delivery from durable intent with its actual per-call fences and bounded identity. Reconcile partial/unknown effects without inventing distributed atomicity or new retry entitlement.

A true complete semantic no-op creates no new business revision or clock. Equal display values can nevertheless be a material evidence/assignment correction. Q59 desired-state Save/Remove commands may need a private ordering generation to fence an older opposite intent even when presentation is unchanged; this does not alter visible Save date, reorder the list or turn original replay into a new effect. Control cleanup and restore must prove stale intent rejection without mandating a particular tombstone algorithm.

Queries apply current source permission and shared field projection before serialization, counts or candidate cues. Lists use bounded set-wise access and stable unique cursors with current checks per page. An authorized page, browser hash or cached selection is not authorization for later pages, a hidden match cue or a subsequent command. Original-result recovery, current status, historical evidence and protected bytes are separately projected.

## Strong transaction and ordering cases

### Selected acceptance and fulfillment

Q52 is one finite explicit selection inside one request. Reject duplicate/conflicting item identities; UI order does not change semantic identity. Under a real enclosing database transaction, partition the frozen selected basis into exact still-applicable pre-existing acceptances and items requiring new decisions. All new decisions commit together or none do. Existing matching acceptances keep original actor/time. Only advancement caused solely by that matching acceptance can be recognized; changed requirements, evidence or concerns cannot be silently rebased.

An all-existing selection may reconcile read-only after F when current facts/disclosure permit. Any remaining new decision requires current lifecycle and authority for the full selected act. Q22 evaluates its whole current predicate separately; required fulfillment follow-through can still be pending after the new acceptances commit. Source clocks use the actual admitted boundary after waits, not a transaction-start or browser timestamp.

Current `withTenant` prior art encloses one allowlisted RPC; it is not a general callback transaction around multiple SDK calls. Implementation must provide the actual qualified enclosing database operation required here and prove it with native rollback and concurrent sessions. A mocked loop, Promise.all or sequential RPC wrapper cannot meet this requirement.

### Acceptance correction and source changes

Test both correction-versus-F orders. A qualified unfinished correction removes current applicability of the exact erroneous acceptance and restores staff review on retained evidence without automatically blaming the recipient or requesting another upload. If F/terminal closure wins, the terminal error/current-reliance route preserves F and original acceptance history. Correcting a mistaken error finding removes only its own blocker. Fresh same-person corrective work has its own reviewed issuance and the ratified automatic-reminder exclusion; Q49 different-person replacement is not that authority.

New intake, corrected evidence, item/instruction changes, Q30 clarification and structurally relevant Q45 mutations fence only their actually dependent uncommitted review. They cannot undo a committed decision or generate a universal unrelated-revision conflict. Current review work uses a new qualified source basis and eligible responsibility, not blind reopening of a completed task or historical notice.

### Local attention and external effects

Q51 successful Notify requires the exact one-member source/P6 plan, native available event, P17 projection, history and result in the same local transaction. There is no invented queued pending state or email provider. Availability uses server materialization time in the transaction that commits, not an unknowable future commit timestamp. Exact visible comment revision plus stable staff person/purpose defines the slot; original assignment/access basis controls projection. Mutations do not automatically notify.

Other notice/reminder purposes keep their actual source producers, controls, candidate compiler, original publication order, counts, sealed envelopes and finite per-call deadlines. P6 owns transport. No generic outbox consumer may infer a new message purpose. Q48 manual/automatic coordination, possible-call counting, stop generations, original windows and exact calendar/DST rules remain its contract, not a universal scheduler default.

## Private intake, processing and serving

Allocate only after actual Q02 source/purpose admission. Bind grants/resume to exact intake, actor/context and immutable generations; reconcile unknown grant issuance before reminting. Track every grant/session and admitted in-flight writer relevant to closure. Token expiry, abort or lease expiry does not prove all writes stopped. Retired locators cannot be reused while late writes could create an untracked copy.

Verify actual stored completeness, identity, type and required hygiene before source promotion. Source profiles decide permitted post-admission Checking. One normal Upload and add intent can cover transfer/finalization without a routine second modal. Multi-file selection has truthful per-file results unless the source explicitly defines one indivisible unit. Q56 trusted assembly requires sealed verified inputs, exact order/rotation recipe, qualified inert output and coherent protection of every required input/output before one whole-unit receipt. Browser lineage claims do not prove correspondence. An admitted Assembled PDF is evidence, not a disposable D32 preview.

Qualify processor isolation, installed versions/licenses, egress and finite resource profiles. Preserve D32 exact formats, fidelity, Find coverage, bounds, retry and copy clocks. Do not borrow its preview caps for ordinary upload/assembly. No unapproved external viewer, remote reference fetch, ambient credential or active embedded content is a recovery path.

The serving boundary checks current whole-representation authority before metadata, HEAD, conditional, range, manifest and byte disclosure and during streams as the source requires. Resume stays on one immutable generation. Every distinct egress receives its actual budget/audit admission; preparation replay does not grant unlimited downloads. Private data remains request-bound and out of shared caches/telemetry. P12 R6 limits logical governance/ledger work with its exact physical carve-out and stricter unstriped pre-egress rules, not all database queries. Apply the installed Core cache boundary rather than copying incompatible framework configuration advice.

Q44 builds and verifies one exact immutable ZIP before Ready, with distinct intended selection, evaluated omissions, admitted subset and transfers. Safe partial download is deliberate; loss of included-byte or manifest authority blocks the old indivisible archive. The original received names, Q50 staff label and export alias remain separate. P21 records packages, P25/P3 CSV, official artifacts and assembly downloads keep their own products and clocks.

## Policy meaning, events and physical disposition

Tenant managers create blank/authorized-copy drafts and change supported business values without vendor intervention. Activated governing meaning changes through a successor; only the source can classify non-operative metadata correction. Retire stops new assignments; current qualified reactivation of unchanged meaning preserves history. Default changes and deliberate existing-record application are distinct. Mandatory current impact installs restrictive controls before asynchronous reconciliation, while unaffected lawful work continues. GF drafts remain mapping evidence, not installed legal policy or live Tenant identity.

Supported external recording is an input route into an actual owner/event contract. The profile fixes occurrence identity/cardinality and date precision. Preserve occurred and recorded times separately; unknown, approximate, planned and actual facts are not interchangeable. Human/native/integration reports resolve by the source's evidence rules. Retraction of one input cannot erase independent proof; wrong-target containment works without waiting for a valid replacement. Late facts may affect explicitly qualified current records duties but do not replay old enrollment, access, workflow or communications.

Discovery is nonauthorizing. Each final destructive admission must serialize current policy/mode, complete registered references, independent holds, retention eligibility, processor/writer state and exact copy target. Record durable attempt/fence and finite permit before external IO. Do not hold a long database lock across the provider to claim a global transaction. A protection before this final gate wins; after possible escape, stop still-preventable remaining work and reconcile without claiming recall. Every genuinely new delete submission requalifies current authority, even with the old key. Late physical observations can be recorded without another delete. Permit/lease expiry cannot clear ambiguity or reopen promotion of a possibly deleting target.

Stop is a cause-owned barrier across scans, keys, workers and manual routes until qualified resolution. It is not a hold release, legal extension or automatic restart. Source disposition and physical copies have separate outcomes: a use may end while another still requires bytes. Complete physical removal requires the actual adapter's copy-specific proof; SQL metadata removal, generic absence or a delete marker is insufficient. Mistaken loss allows only lawful qualified recovery, otherwise an honest incident and source remedy.

## Security, schema and effective database doors

One trusted Tenant Authorization Context must agree across app and database and reset on pooled success/error/cancel/retry. Current membership, assignment, revocation, purpose and capability supplement authenticated identity; a signed unexpired JWT is not universal proof of an unrevoked session. Native staff, limited recipients and qualified NHI do not gain authority from a broad role label or service credential.

Enforce both old-row and resulting-row safety across SELECT/RETURNING, INSERT/UPDATE/DELETE/UPSERT/MERGE/COPY/bulk and trigger-transformed writes. Check effective named/PUBLIC/default/inherited schema/table/column/sequence/function EXECUTE grants, overloads, invoker/definer owners/search paths, views/materializations and ENABLE/FORCE/BYPASS behavior. Omitted WITH CHECK may inherit USING; DEFINER does not universally bypass all RLS. Test actual composition. Include raw REST/GraphQL/RPC, approved collections, import, worker, operator, restore and every Storage sign/list/read/write/copy/delete path; an unsafe alternate door stays closed. Zero affected rows is not successful source acceptance.

Record body access, source management, policy administration, report-return, own-preference cleanup, audit and operator repair as distinct current decisions. Static shared field classification is not per-value provenance authorization. No general settings-row edit, filename, content hash, row owner or relationship supplies a new business permission.

## Migration, recovery and operation

Census reached legacy producers/readers/copies before cutover, including editor upload, public assets/avatar, email, CMS, PDF, Support, import and specialist paths. Classify source meaning and reliance using actual evidence; unknown is neither absent nor disposable. Install guards before favorable writers, use one authority cutover, prove both mixed-version directions and preserve original identifiers, receipts, current restrictions and byte integrity. Do not destructively reset existing data or fabricate prior policy approval.

Backup qualification covers actual required object bytes, keys and source/copy/control metadata. Restore applies later adverse facts before any item is readable, selectable, public or executable. A recipe, database snapshot or synthetic restore probe is not evidence-output recovery. Provider exit copies, verifies, registers custody, switches one read authority and observes continuity before independently disposing eligible former copies. P22 raw-intake discard and P23 released generation/Media Trash contracts remain distinct; no global retained-original or purge rule is introduced.

Each profile publishes measured finite input/output/processing, query/page, lock/claim, retry/queue, control-retention and total retained-copy budgets with units and responsible operators. Keep inherited numeric profiles exact; unknown new limits block their affected activation. Include orphan, held and deletion-claimed bytes in accounting. Saturation has fair bounded refusal and real recovery, never permission relaxation or deletion of held material to meet a quota. Kill switches stop new affected actions while preserving lawful result recovery and current protection. Reenablement cannot revive old intent.
