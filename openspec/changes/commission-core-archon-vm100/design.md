# VM 100 Native Factory Design

## Installation Boundary

Use Archon 0.14.0, commit `8def159a6b2c23e832a5283b4131cfffd9af9344`,
and matching official Claude/forge binary checksums as the qualification
baseline. Preserve Core's Bun/Node/lockfile pins. Deliberate upgrades require
renewed compatibility evidence, not a moving latest install.

Provision with root where necessary, but run engine/native Claude as verified
Ubuntu `admin`. Use absolute executables, HOME, engine state and per-request
profile paths. Use one trigger-host identity matching installed bindings.
Do not set IS_SANDBOX to evade the ordinary-VM root guard.

## Native Identity

An operator-owned alias configuration binds a real owner, permitted scope and
absolute native profile before preflight. Do not pass connected-user tokens
or API credentials. Construct a controlled service environment, qualify the
provider's actual precedence and retain effective settings/binary identity.
The same binding follows children, quota waits and resumes. Ownership transfer
requires reconciliation and a new linked attempt, not session transplantation.

## Admission And Execution

Pure trusted rules determine the eligible frontier from explicit scope,
dependency evidence, existing owners/PRs, holds, conflicts and resources.
Samson ranks only that frontier using the current roadmap and bounded aging.
Serialize the short assignment/reservation update with native capacity-one
resource admission. Store bounded JSON in Archon's conditional state documents.

The delivery run acquires its own native execution lease. Selector completion
cannot release that lease. Keep durable pending assignments, conflict
reservations and dispatch reconciliation together; per-issue writes alone
cannot atomically reserve shared areas. Actual capacity admission is distinct
from the durable assignment and the paused-but-live execution lease.

## Specialist Graph

Use supported graph/script/command/wait/child shapes validated by the pinned
loader. Do not put child workflows inside a v0.14 loop_group. Prepare each
child's actual candidate explicitly; worktree isolation is not revision proof.

Samson scopes; Ezra defines acceptance; Bezalel writes; normal hooks freeze the
candidate; Micaiah and Luke independently review separate views; Samson
consumes both sealed reports; Agabus handles actual disputes; repairs return
to their implementation or acceptance owner; Ezra verifies every criterion.
Each decision binds assignment, attempt, base/head, context, acceptance and
installed policy/prompt identities plus an actual completed provider envelope.

Installed policy is outside candidate writes. Read-only tool inventory does
not prove path isolation. Use actual qualified tool/path boundaries and a
simple disposable credential-free, network-denied candidate-check environment.
Record owned executor/process identity and confirm cleanup before slot reuse.

## Delivery And Controls

Publish through normal hooks and verify the resulting remote head. Read current
GitHub rules, check App/current attempt, reviews, resolvable threads, comments,
requirements, base/head, permissions, holds and mergeability immediately before
protected delivery. Preserve unchanged valid evidence across restart but never
cache a stale external-boundary decision. Reconcile uncertain effects first.

Use server-owned `/api/workflows/runs/{id}` cancel/resume and declared durable
gates. There is no assumed generic hold/pause/retry endpoint. Ordinary Stop
preserves work and cannot map blindly to abandon. Store holds/cancellation so
queued retries/children cannot re-admit canceled work. One bounded retry owner
stops repeated no-progress attempts without blocking unrelated scope.

## Console And Qualification

First prove actual execution with Archon's Console. Then implement the thin
Core Console using exact base-maia, Base UI, shared ownership and configured
shadcn/ReUI workflows. Backend records own status, timers, controls, chat and
evidence; unsupported usage data is unavailable, never invented.

Bound qualitative analysis by material events, freshness and budgets. Its
failure cannot block delivery. Verify all 23 governing acceptance rows,
including real native/GitHub/browser paths, two issue flows, reboot and an
isolated unpushed-candidate restore. Fixtures supplement but never replace
live integration. An independent review qualifies the installation itself.
