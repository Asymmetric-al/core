## Why

The September 22 complete roadmap supplies a shared Workflow Studio and 96 cross-product recipes, but its original whole-program backlog would make the core depend on its future consumers. Reconcile the full specification with accepted source owners and publish an explicit, cycle-free implementation contract.

## What Changes

- Adopt the complete Studio planning package, typed dialect, inert reference definitions, 352 specified scenarios and all 26 stable work-package identifiers.
- Allocate shared CORE to Phase 34, applications to Phase 41, and Giving/Events/Care to Phases 35/37/38, with independently scoped acceptance and FULL as a rollup.
- Bind authority to Phase 12 current human-owner-bounded NHI and exact source operations; preserve native owner clocks, messages, business decisions and source-receipt-only shared tasks.
- Add purpose-scoped participant experience within existing surfaces, with an explicit identity/admission qualification gate rather than widening anonymous access.

## Capabilities

### New Capabilities

- `workflow-studio`: authoring, compilation, execution coordination, source-bound participants and separately qualified domain packs.

### Modified Capabilities

- `platform-surfaces`: add the authenticated purpose-scoped participant journey requirement; existing donor/missionary/staff boundaries remain intact.

## Impact

Planning only. Future implementation touches Mission Control, existing participant app projections, `packages/api`, pure shared contracts/compiler, database hooks, shared UI and existing dispatch/claim infrastructure. No feature runtime, migrations, provider activation or completed implementation is supplied. Durable `workflow-orchestration` and Eve governance remain separate owners. Detailed capability names, source bindings and deployment/provider profiles stay visibly unresolved until qualified.

Non-goals: tenant scripts/SQL/raw HTTP, shadow CRM/financial/clinical records, independent authorization or orchestration engines, or automatic domain approval. Future rollout disables optional new enrollment while preserving source history, active compatible runs, durable work and manual recovery; no external effect is undone by editing a definition.
