## Approach

Correct the consumer that an agent reads, and leave the owning source alone.
Each fix points at the rulebook, spec or script that already owns the rule
instead of restating it.

- **Orientation.** The root addition stays inside the existing always-on
  budget and links to `openspec/specs/platform-product-intent/spec.md`,
  `openspec/specs/platform-surfaces/spec.md` and
  `docs/guides/architecture/overview.md`. It adds no second product brief.
- **Client loading.** Claude Code reads `CLAUDE.md`, so each scoped
  `AGENTS.md` gets a one-line sibling import, the pattern three directories
  already used. Cursor applies an `AGENTS.md` found in a skill directory as an
  always-on rule and falls back to the next skill root when one is ignored, so
  `.cursorignore` lists the compiled guides under `.cursor`, `.claude` and
  `.agents`. The runtime mirrors are not forked: the accepted mirror-parity
  scenario requires the three mirrors to hold the same canonical files.
- **Commands.** `.cursor/commands/*` is canonical and `.claude/commands/*` is
  regenerated by `bun run skills:sync`.
- **Scratch.** Local scratch moves to an ignored path. The tracked
  `docs/ai/working-set.md` is a historical record and is not edited.

## Constraints

- `docs/ai/rules/frontend.md` and `packages/ui/AGENTS.md` are hash-bound
  review proof, so they are not edited here. `frontend.md` therefore still
  tells agents to build a Nia preamble from `docs/ai/working-set.md`;
  `docs/ai/nia.md` now owns the scratch path.
- Cursor's agent cannot open an ignored file, so the "complete guide" pointer
  in five `SKILL.md` files is not followable there. Each of those skills
  still ships its individual rule and reference files.
- OpenSpec is not upgraded here. The upgrade to 2.0.0 is its own change,
  `upgrade-openspec-2` (#2661).
- `.cursorignore` does not stop Cursor listing the vendored
  `vendor/payload-upstream/**/.cursor/rules` files as on-request rules. Two
  patterns were tried. Those rules are never always-applied, so they stay.

## Verification

- Structural: `bun run skills:verify`, `bun run format:check`,
  `bun run openspec:validate`, `bun run verify:openspec-deltas`, and the root
  budget and link assertions in `tests/unit/docs`.
- Unit: the sibling-import assertion fails when a `CLAUDE.md` is missing.
- Runtime, per client: Claude Code loads a scoped `AGENTS.md` after reading a
  file in that directory; a Cursor session no longer lists the compiled guides
  among its always-applied rules.
- Protection: every protected path has the same blob hash before and after,
  and the changed-file list is a subset of the declared edit set.
- Not claimed: smoke, provider or cross-application proof. No product code
  changes.
