# Delta for Platform Surfaces

## ADDED Requirements

### Requirement: Mission Control Presents One Calm Document Studio

Mission Control MUST present **Templates**, **Documents**, and **Batches** as the
three primary generated-document destinations. **Needs attention** MUST be a
saved view and derived count rather than another subsystem.

The routine experience MUST use plain product statuses, one context-correct
primary action, progressive technical evidence, and one repair item per root
cause. It MUST NOT expose render attempts, hashes, provider jobs, storage paths,
fallback candidates, legal-rule internals, or architecture nouns as ordinary
workflow.

#### Scenario: Staff open Document Studio

- WHEN authorized staff open Document Studio
- THEN they see Templates, Documents, and Batches
- AND each actionable exception has one plain cause, accountable owner, and safe
  next action
- AND no migration, legacy, renderer-selection, or records-management console is
  presented

#### Scenario: Compatible publication recovery succeeds

- WHEN a request uses a currently proved compatible recovery publication
- THEN its ordinary status remains Ready and generation proceeds without a
  confirmation, warning, toast, modal, or notification
- AND only accountable setup or batch staff may see one quiet effective-source
  explanation and one grouped maintenance item

### Requirement: Recipients See One Logical Document And One Current PDF

Every donor or missionary surface MUST show at most one row or card for an
authorized logical document and one current canonical PDF action. Semantic HTML
status and details MAY accompany the artifact for accessibility, but MUST NOT be
presented as another official file.

Superseded, replaced, cancelled, preview, staging, validation, storage-replica,
and delivery records MUST NOT appear as peer recipient files. Missionaries MUST
NOT receive donor tax-document access merely from fund, designation, or donor
visibility.

#### Scenario: A donor opens a corrected acknowledgment

- GIVEN an acknowledgment has an authorized current correction
- WHEN the donor opens their document list
- THEN one logical acknowledgment is shown with the current publication
- AND the replaced publication is absent from normal download choices
- AND authorized staff can inspect the predecessor only in evidence history

#### Scenario: A missionary can see a related contribution

- GIVEN a missionary may view a contribution's permitted fund and donor facts
- WHEN that contribution has an official donor document
- THEN the missionary receives no PDF, reference, access grant, signer evidence,
  or specialist detail unless a separate purpose and capability authorize it

### Requirement: Document Authoring Is Accessible And Purpose-first

The visual editor MUST expose one structured document through both direct visual
controls and an equivalent keyboard-operable outline/non-drag path. It MUST lead
with purpose, recommended content, human-named information, synthetic examples,
and grouped checks rather than raw schemas or tokens.

Publishing, scheduling, generation, batch review, correction, access, and repair
MUST meet WCAG 2.2 AA and the documented keyboard, focus, status-announcement,
touch-target, zoom/reflow, forced-color, long-locale, RTL, and supported
screen-reader proof.

#### Scenario: A keyboard user builds a document

- WHEN a template author uses only the keyboard and outline controls
- THEN they can add, reorder, configure, inspect, and remove every permitted
  block and information field
- AND protected blocks remain understandable and non-removable
- AND validation returns focus to the exact actionable issue without requiring
  drag-and-drop

#### Scenario: Staff schedule a ready publication

- WHEN authorized staff choose the secondary Schedule publication action
- THEN one sheet asks only for date, time, and named time zone
- AND a complete consequence summary identifies the current and scheduled
  versions, exact local time and offset, and frozen-work behavior
- AND publishing now never requires answering a scheduling question
