## Why

The September 22 program roadmap requires one Web Studio where staff create websites visually and ministry-appointed developers deliver custom presentation without losing editable CMS content. The earlier Phase 23/24 contracts own the content, publication and Site boundaries; this change supplies their explicit Phase 42 successor and a complete implementation handoff.

## What Changes

- Adopt the Phase 42 planning contract with 48 HW requirements, 96 paired scenarios, 18 WF journeys, 12 native AU behaviors and 27 HA work packages.
- Define bounded ordinary-Page composition/2 while preserving flat composition/1, Article constraints and specialized Phase 22 grammars.
- Specify the replaceable Puck adapter, private Payload transaction boundary, public presentation SDK, ministry-controlled source, isolated builds and independent admission.
- Split WEB-VISUAL, WEB-SOURCE and WEB-HYBRID evidence/dependencies so Git delivery and optional Workflow Studio cannot block ordinary visual authoring.
- Reconcile earlier owner clauses and preserve D1/D9/D10/D12/D13/D25/Phase 24 authority. No runtime, provider, database or deployment change is made by this planning PR.

## Capabilities

### New Capabilities

- `web-studio-hybrid-authoring`: bounded visual and conventional source authoring through existing CMS and release owners.

### Modified Capabilities

None in durable `openspec/specs`. The active Phase 23 `add-web-studio-cms` planning package receives explicit successor scope amendments while retaining every original scenario; it is not silently treated as merged implementation.

## Impact

Canonical planning sources live in `docs/prds/web-studio-hybrid/`, reconciled against the supplied roadmap and immutable reference assets under `docs/prds/program-roadmap/source-2026-09-22/`. Later implementation affects the admin Web Studio/private Payload adapter, provider-neutral API ports, public rendering, shared UI and authorized database projections. Exact module exports, toolchain and isolated-origin deployment require qualified implementation evidence. The source path additionally consumes the Phase 31 connection minimum and Phase 29 custody profiles.

Non-goals include a new CMS, Workflow Studio engine, generic tenant code runtime, hosted IDE/AI prerequisite, Git-backed content mirror, arbitrary CSS/HTML/JS in content or a second publisher. Runtime rollback remains source-owned: pause new writers/intake independently, preserve safe admitted generations and restore through compatible successors.
