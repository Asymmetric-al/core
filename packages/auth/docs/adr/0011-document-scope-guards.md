# 0011. Withhold a page on a scope mismatch and bound its reload

**Status:** Recorded on 2026-11-22 from code comments in `packages/auth`
([#2751](https://github.com/Asymmetric-al/core/issues/2751)). It describes the
code as it is and ratifies no product intent. Accepted platform intent is in
[`docs/adr/`](../../../../docs/adr/README.md).

## Context

A signed-in layout supplies the scope for its page: the person, organization and membership assignment. After a client-side navigation the address can change while the browser still has the old document. A new document can repair that navigation, but repeatedly loading a page that the server gave the wrong scope cannot repair a server fault. The donor portal needs the same isolation even though its address names no organization.

## Decisions

1. **Distinguish a bad first render from a later navigation.** `TenantDocument` in `packages/auth/tenant-navigation.tsx` compares the current tenant prefix, including any staff sub-role, with the supplied scope. If the prefixes differ, the guard throws `TenantScopeMismatchError` immediately when the document has never fixed a scope and is at its load prefix. `isAtLoadedAddress` answers yes on the server and compares prefixes, not complete URLs, in the browser. If the browser cannot identify the load prefix, the guard requests a bounded reload instead. `neverFixedScope` uses `isDocumentScopeFixed`, not a null scope lookup: leaving a segment can hide a scope without erasing it. For a later mismatch, the guard requests the reload in an effect. The effect does not run while React Activity hides the layout. Cited: [council round 1, A6, A8 and A12][reviews].

2. **Do not adopt a tenant scope after entering its segment without a document load.** Even when the current address matches the supplied scope, `TenantDocument` in `packages/auth/tenant-navigation.tsx` withholds the page if the document never fixed a scope and `loadedElsewhere` finds a different load prefix. It asks for a fresh document rather than treating a matching destination as proof that this document started there. The comparison does not depend on a previous mount of the guard. Cited: [council round 1 ruling, A7 and A8][reviews].

3. **Share one reload attempt and give the person a way out.** `TenantDocument` in `packages/auth/tenant-navigation.tsx` shows `ScopeReloadNotice` instead of page content while its effect requests the reload. The notice announces the status and can offer a manual reload or a link home; it does not make a second automatic request. `requestDocumentReload` in `packages/database/document-reload-claim.ts` treats a reload another guard already started as underway. If the claim is refused, `TenantDocument` throws `TenantScopeMismatchError` on its next render, even when the prefixes match after entry without a document load. After a render in the correct scope, `forgetDocumentReload` clears crossing claims so a later organization switch gets its own attempt. Cited: [council round 1, A12; joined release JB2; fix-list check JR3 and JR10][reviews].

4. **Scope the donor portal to the person's one resolved donor membership.** `readPortalDocumentScope` in `packages/auth/tenant-server.ts` takes the signed-in user, tenant and assignment from the resolved auth context, with an empty address prefix because the portal path names no tenant. It returns `null` without a matching donor assignment; with `CORE_SERVE_UNDER_PATHS` off, the resolver refuses multiple donor rows rather than choosing an organization for the person, while with the switch on the resolver picks the verified name's donor row and `readPortalDocumentScope` awaits `readServerNameTenantState()`, returning `null` when the name is refused or differs from the assignment's organization (see [0016](0016-donor-organization-from-the-verified-name.md)). `PortalDocument` in `packages/auth/portal-document.tsx` passes this scope to the same provider used by the staff apps so the API wrapper, browser client and query cache do not need a separate donor implementation. Cited: [plan §12, WP2, “Interim rules until WP3,” and WP2b][work], [AL-2675][issue].

5. **Keep portal scope out of public pages.** The donor root uses `PortalSegmentBoundary` in `packages/auth/portal-document.tsx` so links and router calls can load a new document when entering or leaving `/donor-dashboard`, including after sign-in or when following a Give link. `PortalDocument` gives that same path to `DocumentScopeProvider` in `packages/database/document-scope.tsx`. `/checkout` is outside `/donor-dashboard`, so its authenticated requests to `/api/donate` carry no portal tenant or assignment headers. If navigation bypasses the helpers, the provider checks for a soft entry and requests a reload on unmount outside the portal. If a different person's scope reaches the same document, it shows a reload notice instead of the portal content. Cited: [record D-41][decisions], [council round 2 on slice B, BR1 and BR2][reviews].

6. **Expose the rendered scope to production end-to-end tests without visible text.** `TenantDocument` in `packages/auth/tenant-navigation.tsx` writes its address prefix to a hidden `data-tenant-scope` marker; `PortalDocument` in `packages/auth/portal-document.tsx` writes the tenant ID because it has no address prefix. Both include `data-tenant-assignment`. The tests can verify which row actually rendered, and the marker tells the browser nothing it did not already receive in the component's scope prop. Cited: [council round 1, A13][reviews].
