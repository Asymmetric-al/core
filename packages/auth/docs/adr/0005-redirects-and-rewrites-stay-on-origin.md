# 0005. Keep redirects and rewrites on the request's origin and confirm sign-out there

**Status:** Recorded on 2026-11-22 from code comments in `packages/auth`
([#2751](https://github.com/Asymmetric-al/core/issues/2751)). It describes the
code as it is and ratifies no product intent. Accepted platform intent is in
[`docs/adr/`](../../../../docs/adr/README.md).

## Context

A redirect tells the browser where to go. A rewrite instead asks Next.js to serve a different path, and Next.js may fetch it over HTTP with the request headers and session cookie. A tenant rewrite must therefore stay on the app's origin and keep the tenant decision when it reaches the page. Sign-out also needs an answer from that origin: clearing browser state cannot confirm that the server invalidated its cookies.

## Decisions

1. **Build configured redirects on the request's origin.** `buildRedirectUrl` in `packages/auth/middleware.ts` resolves its path against `request.nextUrl.origin`. It does not select a base from `Origin`, `Referer` or forwarded headers, which would let the caller steer the destination. This helper expects a configured or already sanitized path; it is not the check for an untrusted URL.
2. **Validate the return path before carrying it through sign-in.** `safeNextParam` in `packages/auth/demo-login.ts` accepts a root-relative path on the same origin. It refuses `/login`, `/register` and the sign-in callback `/auth/callback`, each with its subpaths, and any `/api/auth/` path, to avoid loops and callback reuse. The password-recovery callback `/forgot-password/callback` is not on that list. `hasEmptySegmentOrBackslash` checks the parsed pathname and its once-decoded form for a double slash or backslash, and rejects invalid encoding. Parsing can normalize characters, and removing a tenant prefix later must not turn a local path into another host. Rejected values return `null` so the caller can use its own default. Cited: [council round 1, A1][reviews].
3. **Check the resolved destination before attaching scope.** `ownOriginUrl` in `packages/auth/middleware.ts` requires a path starting with `/`, the request's origin after URL resolution, and a resolved pathname that does not start with `//`. The last check matters because Next.js can shorten a same-origin redirect to a pathname that a browser would interpret as a different host. `authMiddleware` checks the rewrite target before setting the tenant, assignment and marker. `refusedAddress` returns an empty 404 with no reflected address or session cookie rather than forwarding the request. The proxy makes its own check instead of depending on a front server's URL handling. Cited: [council round 1, A1 and A2; round 2, AR5][reviews]; [`tenant-address-rewrite-origin.test.ts`][origin-test] and [`tenant-address-rewrite-refusal.test.ts`][refusal-test].
4. **Treat a tenant rewrite returning to the same proxy process as an error.** An origin check does not prove Next.js served the rewrite internally. `authMiddleware` in `packages/auth/middleware.ts` stamps an approved rewrite with its process-private `TENANT_REWRITE_MARKER` in `TENANT_REWRITE_HEADER` from `packages/auth/request-headers.ts`. If the marker returns, `rewriteLeftServerResponse` in `packages/auth/middleware.ts` answers 500 instead of serving the inner page without its tenant. Another instance does not recognize the value: it strips it and may redirect to the tenant address or chooser, producing a loop instead of that diagnostic. The [hosted smoke suite][smoke] checks the rendered scope, that no response the page observes carries the rewrite marker or a middleware override header, and that an unsafe address gets a 404 or a first redirect on the same origin. Cited: [record D-19][record], [council round 1, A4][reviews].
5. **Confirm server sign-out before clearing the browser session.** `signOutOnServer` in `packages/auth/client-signout.ts` posts to the app's own `/api/auth/signout` through `ownApiFetch`. A failed HTTP response or a request error returns `{ ok: false }`, and so does a call from a document whose scope is retired, which `ownApiFetch` answers with a local 401 without sending it. `signOutClientSession` in `packages/auth/client-session.ts` then stops before local sign-out or redirect, so the browser does not report success while server-managed cookies may still be active. With the end-to-end bypass enabled, the endpoint answers success after clearing only the test cookies, even when a real Supabase session is present.
