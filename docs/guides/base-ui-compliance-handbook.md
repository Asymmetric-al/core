# Base UI 1.8 handbook and utility compliance audit

Reviewed: 2026-09-23. Source baseline: c955455 plus this change.

## Scope and evidence limits

Reviewed against Base UI 1.8 official docs and the recovered Core checkout at c955455 with the compliance working diff on 2026-09-23. This document covers the six handbook pages, four utility pages, quick-start and accessibility; component details and final repository gates belong to the master compliance guide. Optional utilities are applied when an actual supported workflow needs them.

The matrix distinguishes source/API coverage, focused regressions and Chromium fixture evidence. It does not assert live-provider, iOS, screen-reader, production-header or universal WCAG verification.

## Regression and browser evidence

`mergeBaseUIClassName` preserves string results for static inputs and deferred full-state callbacks for functional inputs. Caller classes override wrapper defaults. Initial helper RED: 3 failures / 1 pass; current helper suite 4/4. Composition RED: 4 failures / 9 passes; current suite 15/15 after two additional custom-upload regressions. Hero link RED: invalid type=button; current navigation test 1/1. Choice controls RED: 3 new keyboard failures; current Support Hub/offline suites 10/10. Auth loading RED: missing aria-disabled and disabled=false overriding loading; current suite 2/2. A SupportFailureBanner retry regression also fails without the focusability opt-in and passes after restoration, preserving duplicate-activation suppression and completion. The final focused selection passed 38 tests across eight files. Existing offline success, rejection, malformed-response and abort tests remain green.

The seven browser contracts cover loading focus/name/opacity/duplicate prevention, sidebar render-state and tooltip composition, cancellation, native-link Enter, layout/tone arrows and Space, saved tone at the stub boundary, offline donor-mode selection/Escape/refocus, and 390px accessible names/overflow. No pageErrors. A separate 390px dark-theme axe run reproduced 13 contrast failures in LabelForm; semantic card/border/foreground tokens fixed them, and the scoped rerun had zero violations. The screenshot was visually inspected. Browser sessions closed. Evidence is in ignored `test-results/base-ui-compliance/composition-check.mjs` and `composition-mobile.png`; the shared Vite fixture uses actual components and a narrowly scoped LabelForm mutation stub. It submits no live requests.

The typed census builds a TypeScript program over tracked and untracked UI TSX sources, examines declared/inferred first-parameter className unions for call signatures, and inspects implementations for cn/CVA/helper/forwarding paths. It covered 153 callable wrapper contracts, including indirect Button/Input/Separator consumers. No unhandled typed cn/CVA-discard paths remain. Raw scratch artifacts are `.tmp/base-ui-compliance/audit/classname-census.json` and `render-census.json`. The manual custom-child audit additionally found ImageUpload erasing a Button state-class callback, accessible name and disabled prop; a public-component regression now covers their preservation plus ref forwarding. A second regression proves preventBaseUIHandler cancels picker activation. These casts are not detected by the parameter-type census.

Fresh shadcn info confirms base-maia/Base UI, Zinc and Tailwind v4. The final committed `bun run typecheck` passed all 15 tasks. Final aggregate tests/type/lint/build are recorded in the master guide; use workspace-owned tooling versions, not a root bunx TypeScript version override.

## Component applicability decisions

- CheckboxGroup: current direct Checkbox consumers are task completion, consent, receipt confirmation, and TanStack table/grid selection. Table selection is a table-owned state/ARIA contract, not an ordinary form value group. No unsupported multi-checkbox form set was found; no unused CheckboxGroup wrapper is installed solely for catalog coverage.
- Autocomplete: no application free-text suggestion/datalist/handmade combobox replica was found. Existing Command/Combobox usages select discrete records or commands; editor suggestion behavior belongs to the editor. Add Autocomplete for a genuine free-entry suggestion workflow.
- ToggleGroup: the inbox layout, label tone and offline donor-mode sets had hand-built pressed-button groups. They now use the shared primitive while keeping domain callbacks, one required selection and existing content.
- Loading actions: AuthButton now delegates behavior to shared Button, preserves focus only during loading and supplies an explicit label target. Shared table refresh/reset/pagination and comment/upload initiators opt in to focusableWhenDisabled; ordinary disabled peers retain native disabling. The final AST inventory removed state-name predicates and inspected all 151 disabled JSX Button-family nodes, including multiline expressions: 101 initiating actions, one popup return-focus target, 10 disabled peers, and 39 static or data-readiness prerequisites. All 102 async-action/return-focus entries explicitly preserve focus while pending. The Eve global reset control is a peer blocked during agent streaming, not an async initiator. Full source expressions, label branches and classifications are recorded in `.tmp/base-ui-compliance/audit/all-disabled-button-classification.json`; Toolbar aliases were reviewed separately. No isLoading prop or global focusability default was added.
