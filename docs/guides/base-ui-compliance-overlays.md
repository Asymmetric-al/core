# Base UI overlay, navigation, and display contracts

Verified against installed Base UI 1.8.0 and the official component/handbook pages on 2026-09-23. This matrix covers 16 Base UI families and the intentional Sonner boundary. Sheet and CommandDialog are Dialog compositions. Core keeps its `base-maia` styling and shared `packages/ui` ownership.

## Shared requirements

- [Styling](https://base-ui.com/react/handbook/styling): Base UI `className(state)` stays deferred through `mergeBaseUIClassName`; caller classes override wrapper defaults. Plain HTML layout classes still use `cn`. Accordion deliberately applies caller classes to its inner padding element while preserving the Panel's custom render target and ref.
- [Composition](https://base-ui.com/react/handbook/composition): primitive props, events, refs, and render contracts remain intact. A custom button-like target must forward them; use `nativeButton` only on parts exposing that contract. Tooltip is visual supplementary help and its trigger needs its own accessible name.
- [Quick start](https://base-ui.com/react/overview/quick-start): all three applications isolate `.app-root`, independently of body-level portals. Body is relative; absolute modal backdrops include `min-h-dvh` so short documents still cover the screen.
- [Animation](https://base-ui.com/react/handbook/animation): existing `data-open`/`data-closed` keyframe selectors and `data-starting-style`/`data-ending-style` transition selectors are supported. Preserve official sizing variables. Retained or lazy content is an explicit lifecycle choice, not a blanket optimization.

## Evidence and reproduction

The focused unit suites are `base-ui-overlay-contracts.test.tsx` (8), `base-ui-overlay-consumers.test.ts` (6), and `base-ui-overlay-setup.test.tsx` (8), under `tests/unit/packages/ui/`. They cover behavioral regressions and the coordinated consumer migration. Wrapper callback contracts and the global callback census are shared with the wider Base UI audit.

The committed fixture and standard Playwright specs live under `tests/fixtures/base-ui-compliance/`. Run `bun run test:e2e:base-ui`; its dedicated webServer builds the complete static fixture before starting port 5198, then stops it after the run, imports actual shared/product components, and compiles `packages/ui/styles/globals.css` through the existing Tailwind/PostCSS pipeline. It has no product route. The original matrix rejects external/API requests and records LabelForm's submitted value through a local provider stub. The added focused support-form case uses inert loader/navigation adapters and intercepts one exact local ticket request to inspect and fulfill it without a live write; all unexpected requests are rejected. Generated CSS, reports, screenshots and failure traces stay under ignored root `test-results/base-ui-compliance/`. See the fixture README for browser installation and host-specific setup.

The four projects cover desktop/mobile, light/normal motion and dark/reduced motion, including overlays, form controls, the actual editor, application choice groups and loading-button focus. This is a component integration gate, separate from provider-backed production E2E qualification.

The original overlay/component matrix passes 76 tests (19 contracts × four projects). The final aggregate passes 77 tests with three intentional skips: the additional support-form case runs on desktop and is skipped in the other three projects. Chromium checks covered 1280×844 and 390×844, plus the toolbar’s 700px breakpoint. All 28 axe scans passed, including actual form, popup, drawer, and resting-fixture states. There were no page/console errors or unexpected requests; the original matrix made no external/API requests. Normal styles compute Dialog/Popover enter animations at 220ms and Drawer transform transitions at 320ms. Reduced-motion styles compute 0.01ms for each. The short-body test forces body height to 100px and still measures an 844px backdrop. These checks do not substitute for physical iOS/Safari software-keyboard testing, assistive-technology testing, or end-to-end provider-backed application flows.

## Eve initiating actions

The six Eve panels under `apps/admin/app/(app)/admin/eve/` contain 23 pending initiating Button occurrences: admin-memory (3), approval-budget (5), launch-readiness (8), model-policy (2), notifications (3), and retention (2). `focusableWhenDisabled` matches the pending operation and row identity where applicable. Existing disabled expressions still enforce validation, permission, and peer-action blocking. Labels do not change to loading text, so no additional label spans are needed.

Dialog-opening triggers and cancel/local-navigation controls are not treated as pending mutation initiators. Existing AlertDialog confirmations intentionally dismiss through Close and retain their original handler/error behavior. A held-promise regression in `eve-approval-budget-panel.test.tsx` proves that the initiating allowance button keeps focus and `aria-disabled`, a different allowance row remains native-disabled, and duplicate activations do not issue a second request. The approval-budget, memory-concurrency and launch-readiness suites pass 7 tests without live API calls.
