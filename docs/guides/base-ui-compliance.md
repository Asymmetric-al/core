# Base UI 1.8 documentation compliance

This is the expanded AL-1894 audit against the [official documentation index](https://base-ui.com/llms.txt), checked on 2026-09-23. It supersedes the initial upgrade's bounded adoption assessment. Implementation, independent review, local preflight, and the repeatable browser gate are complete. Published-head CI and review status are tracked on the current pull request, separately from the prior PR's checks.

## Release and scope

The official releases page and npm registry both identify **1.8.0** as latest. On 2026-09-23 the registry had only the `latest` tag and no newer published beta or release candidate. Core pins that version in `packages/ui`; applications consume its shared wrappers. Per-commit canaries are available but no verified requirement needs one.

The current index has 37 component pages, six handbook pages, four utilities, and five overview pages. The review also covers the 1.6, 1.7, and 1.8 release notes; older historical release notes are superseded by the installed APIs and current component references. Community and About describe project/support context and impose no product runtime contract.

Each component below has a reviewed interaction model. Using the complete library means preserving applicable behavior and choosing the right primitive for actual workflows; it does not require mounting dormant APIs or adding a second owner for form state, notifications, or specialist editors.

## Wrapper API changes

- Base UI className functions and style functions remain available through typed wrappers. Static classes continue to work. `mergeBaseUIClassName` resolves the callback with the primitive's live state before merging Core defaults.
- `SelectControlLabel` labels the control. The existing `SelectLabel` remains the group-label export; callers must put it with its related items inside SelectGroup.
- The existing OTP exports keep their names but now expose Base UI types. Use `length`, `onValueChange`, `onValueComplete`, and `normalizeValue`; slots follow DOM order and are actual inputs. The repository had no product consumers of the previous `maxLength`/`onChange`/indexed-slot API. The unused input-otp dependency was removed.
- NumberField is a composed primitive, not a blanket replacement for domain-specific money parsing. Existing donation/payment custom-amount state remains separately owned and tested.
- ToolbarButton is a behavioral composition part. Render it through an existing Button, Toggle, or popup Trigger to preserve the intended Maia visual variant.
