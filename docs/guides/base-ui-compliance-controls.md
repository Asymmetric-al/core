# Base UI 1.8 controls compliance

Reviewed against the current official component pages and [forms handbook](https://base-ui.com/react/handbook/forms) on 2026-09-23. This is the controls portion of the Base UI adoption verification, not a claim that every product route was exercised with every browser or assistive technology.

## Verification

Focused regressions reproduce the original callback loss, scalar-thumb count, missing form labels/error IDs, nested select-cell clear button, missing spacing style, and pending-submit focus behavior before their corresponding fixes. Numeric behavior was characterized before migration and checked again afterward.

The focused suite consists of:

- `tests/unit/packages/ui/base-ui-controls.test.tsx`: 12 state/composition/form/number/measurement/submit tests.
- `tests/unit/packages/ui/searchable-select.test.tsx`: 3 ID/search/empty/disabled/refresh tests.
- `tests/unit/apps/admin/features/support-hub/components/report-scope-select.test.tsx`: 2 real-consumer route-state and visible-label tests.
- `tests/unit/apps/admin/features/support-hub/components/settings-row.test.tsx`: real SettingsRow label/description/focus plus distinct popup-input naming and IDs.
- Existing filter-select and cell-variant suites: 7 tests covering selection/filter keyboard behavior and display compatibility.

The combined focused run passed 25 tests. All three app consumer typechecks and the shared UI typecheck passed through the committed Turbo package commands. Focused ESLint and Prettier checks passed for the changed controls files.

The browser matrix uses the actual shared components, TanStack adapters and SettingsRow with a 200-record fixture. It exercises duplicate labels with unique IDs, disabled records, empty live regions, keyboard selection/focus return, scalar/range sliders, checkbox/switch/radio keyboard state, form error descriptions, precise numeric edits, bounded values, disabled fields, finite Select labels and pending submission. Browser findings repaired during this check included an unnamed searchable popup dialog and insufficient dark-mode contrast in the old SettingsRow text classes. The actual responsive toolbar also has a durable regression at 390px and 700px: Columns and Export retain names when their visible text is hidden, column selection and export callbacks work, and mobile search/clear controls are named. This test reproduced the missing Columns name before the fix and passed afterward with zero axe violations.

The Chromium matrix passed at 1280px and 390px in normal-motion light mode and reduced-motion dark mode. All four states passed keyboard, label, form, numeric, selection, focus, radio-indicator alignment, duplicate-ID and overflow checks. Eight axe scans (open searchable popup and complete controls section in each state) reported zero violations; there were zero page errors. Generated results and four screenshots are under `test-results/base-ui-compliance/controls-*`; the durable harness is registered by the overall verification ledger. These component fixtures validate browser behavior without production accounts; they do not claim that all authenticated routes, provider effects, physical iOS Safari or screen-reader combinations were exercised. Source naming coverage and a clean axe scan are different evidence layers.

## Nullable Select callback follow-up

The final census covers all 42 single-Select roots: 35 inline handlers and one named handler explicitly handle `null`, while six roots have no value-change handler. All 25 SearchableSelect consumers now explicitly ignore implicit null values (24 inline guards and one named guard); explicit product options such as None, Workspace and 24/7 still map to their intended null values. Required enum/form values and the editable grid cell ignore an implicit null rather than persisting it; pagination accepts only positive integers and includes its current supported nondefault size in the choices.

The callback-boundary suite renders the actual consumers and explicitly injects the documented nullable callback value; all 23 cases pass, with the newly repaired paths observed failing first. A separate actual-table test preserves page size 5 across reopening and selects another valid size. The alleged automatic-clear sequence was not reproduced in jsdom. Installed TanStack clamps a coerced zero to one, so the proven old behavior under injected null was 5 to 1, not infinity. Invalid report URL scope values already normalize to all, and new task defaults are valid enums. These distinctions keep contract coverage separate from unproved production narratives.

The final native-control sweep migrated nine ordinary selects in support intake (three), server GET ticket filters (two), and Eve memory/allowance/model settings (four). No native `<select>` remains in first-party app/package TSX. Small bundled contact choices remain a bounded Select; this does not prescribe a nonsearchable control for a future large live contact catalog. The server filter page remains a server component, using serializable `defaultValue`, `name` and `items` props. Unknown filter defaults retain the former native fallback to All.

Fifteen affected consumer tests pass. The intake regression preserves required-selection validation and form values, holds a request to reject duplicate submission, and verifies a full reset. Capturing the form before awaiting fixes React's cleared `event.currentTarget`; explicit controlled-select reset state restores the former native reset behavior. The durable browser harness has one focused desktop Chromium case for these form contracts, with a locally intercepted ticket request and inert loader/navigation adapters. It does not create a real ticket or qualify the support API.
