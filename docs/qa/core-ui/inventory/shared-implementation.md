# Shared Core UI implementation

The static inventory covers the 275 baseline first-party shared TS/TSX/CSS modules and authored-content renderer boundaries. The first completed slice improved 34 files and retained 241; the licensed Pro addition brings the final total to 279 modules,38 improved and241 retained. Module reachability includes barrels; the ledger does not claim that every exported symbol has a live route or that every route was reviewed in a browser.

Reusable Maia controls remain shared. Floating table actions now appear once at each viewport with mobile-hidden actions reachable in overflow. Saved filters retain their existing storage key and serialization while providing stable external-store snapshots and same-window updates. Sidebar shortcuts leave editable controls, cancelled events and composition alone. Disabled image removal is guarded; PDF clipboard feedback waits for actual success and reports failure. Actual DataGrid headers are named column headers, and its toolbar wraps with an InputGroup search instead of clipping controls.

PageHeader and PageShell titles/actions wrap naturally. Dialog/Sheet close targets use the existing Base UI render composition with shared 32px icon Buttons. Filter popups fit Base UI's available width; filter inputs use existing owners. Shared reactions wrap and use the current semantic motion system. Status, inverse and media tokens are centralized with light/dark contrast calculations. Badge/Alert/Button variants preserve existing default Maia geometry. Carousel inside placement and explicit SidebarTrigger sizes are compatible optional owner APIs.

Shared public pages use semantic inverse/media surfaces while preserving intentional content and brand logos. Shared Studio search and device controls have persistent names. PDF setup dialogs scroll. Email preview preserves its fixed 390px mobile canvas with contained horizontal scrolling; desktop width remains available-width based. Final desktop/mobile narrow recapture is pending the runtime owner.

The original chart zero result was already visible as a bare React text node. Tests passed at baseline. The change only places zero inside the existing formatted numeric value span; it is not a data visibility fix or a claimed RED result. Animated AppIcon now keeps a stable Motion span with `initial=false`, deliberately removing its entrance animation to avoid the verified reduced-motion span/SVG hydration mismatch. This does not claim to repair every pre-existing motion hydration issue.

Generic shadcn controls, TanStack table/Form adapters, server pagination/state serialization, chart engines, specialized editors, crop/upload backend and public authored-content renderer boundaries were retained because a registry transplant would weaken compatibility or offer no material benefit. Current ReUI Filters query trees and file-upload ownership do not match Core's persistent filters and crop/backend pipeline. No source from those examples was copied. No dependency, lockfile, theme preset, primitive base or behavior ownership was migrated.

Public MIT ReUI APIs/examples and official shadcn documentation informed this first slice; exact artifacts and source decisions appear in [shared.json](./shared.json). A later commercial Pro settings composition is separately authorized by the owner's public-distribution agreement confirmation and must not be labelled MIT.

## Licensed Pro settings addition

After the owner explicitly confirmed an agreement covering public AGPL distribution and contributors, actual current `base-maia` Pro settings source was selectively integrated. `SettingsLayout` derives its responsive rail and controlled tabs from settings-7/account-settings; `SettingsCard` preserves settings-7/settings-card's header/content/footer composition using Core's untouched default Maia Card geometry; `NotificationPreferencesMatrix` derives settings-11's centered channel table while retaining existing app-owned controlled Switches, icons, descriptions and save/dirty state. Original vendor demo tabs, records, Checkbox state, file-upload hooks and appearance overrides were not imported. Commercial source attribution is present in each derived file; this source is not MIT.

The new public module is `@asym/ui/components/settings`, with three components and their props types exported. Donor consumes the rail and card sections; missionary consumes the cards and channel matrix. A native table caption, scoped column/row headers, contained table scrolling and wrapped descriptions make channel relationships explicit. The layout uses the existing `useIsDesktop` hook at Core's 1024px breakpoint and stable server/initial-client horizontal markup; app-owned TabsContent panels remain in place.

The initial new-module RED was the absent public export, so no executed behavior failure is claimed for that log. Missionary separately reproduced the actual missing named-table semantics at its existing settings page seam before integration. Four shared tests now pass for controlled pointer updates, keyboard focus/activation at both orientations and table naming/caller Switch ownership. The final shared suite passes **103 files / 461 tests**; canonical UI TypeScript 5.9.3 typecheck and raw shared lint pass with zero new findings. Source hashes, adaptation decisions, actual permission scope and precise results are in `docs/qa/core-ui/sources/reui-pro-settings.json`; app owners record their field/save/error/pending preservation tests. Final Pro settings browser recapture is requested from the runtime owner.

The shared ledger now covers 279 modules: 275 baseline modules plus four new settings source/barrel modules, with 38 improved and 241 retained dispositions.
