## Remaining defect

### P2 — A saved draft hides the live page even when an older version is published

**Verified in current source and an isolated logic probe; no browser reproduction claimed.** With a configured site origin, publish a page, retain its slug, then save a newer draft. The visibility model correctly supports “Older version public”, but the header, phone action and inspector lose the live-page link.

- [NativeCollectionEditView.tsx:628](C:/Users/Conrad/.t3/worktrees/core/t3-5a24111d-r12/apps/admin/src/cms-ui/web-studio/collections/shared/document-workspace/NativeCollectionEditView.tsx:628) requires the latest editable `data._status` to be `published` before returning `publishedHref`. It does not accept `hasPublishedDoc`. The inspector calls the helper at [line 748](C:/Users/Conrad/.t3/worktrees/core/t3-5a24111d-r12/apps/admin/src/cms-ui/web-studio/collections/shared/document-workspace/NativeCollectionEditView.tsx:748), and the header at [line 891](C:/Users/Conrad/.t3/worktrees/core/t3-5a24111d-r12/apps/admin/src/cms-ui/web-studio/collections/shared/document-workspace/NativeCollectionEditView.tsx:891).
- This is a real supported Payload state: the installed [getDocumentData.js:27](C:/Users/Conrad/.t3/worktrees/core/t3-5a24111d-r12/apps/admin/node_modules/@payloadcms/ui/dist/utilities/getDocumentData.js:27) loads the editable document with `draft: true`; [getVersions.js:48](C:/Users/Conrad/.t3/worktrees/core/t3-5a24111d-r12/apps/admin/node_modules/@payloadcms/ui/dist/utilities/getVersions.js:48) separately looks up a published copy when that editable document is a draft, and [line 78](C:/Users/Conrad/.t3/worktrees/core/t3-5a24111d-r12/apps/admin/node_modules/@payloadcms/ui/dist/utilities/getVersions.js:78) sets `hasPublishedDoc`.
- [editor-state.ts:193](C:/Users/Conrad/.t3/worktrees/core/t3-5a24111d-r12/apps/admin/src/cms-ui/web-studio/collections/shared/document-workspace/editor-state.ts:193) explicitly renders “Older version public” for that state. Staff can therefore be told a public copy exists while their action to inspect it disappears.

**Smallest safe remedy:** use the provider's published-copy state to decide whether a live-page action exists. Resolve its address from the published copy when a draft can change the slug; changing only the status condition could otherwise link to an unpublished address. Keep the action absent without a configured origin or a published copy. Add a regression at the link-resolution/editor boundary for published → newer draft with the same slug, plus a changed draft slug. The current [preview action tests:10](C:/Users/Conrad/.t3/worktrees/core/t3-5a24111d-r12/tests/unit/apps/admin/web-studio-document-preview-links.test.tsx:10) receive already-resolved URLs, so they cannot catch this defect.
