# D24 evidence — source-qualified activity summaries and comparable targets

Research date: **2026-10-17, Asia/Bangkok**. The founder selected **A — optional
activity summaries for an invited read-only coach**, then explicitly selected
**Continue into future periods of the selected target**. D23 and its amendments
are ratified. The precise profile and safeguards below, including continued
availability of admitted periods from the exact reviewed start, are review
recommendations, not a new ratification or implementation.
Research is limited to this note; no app, formal owner/spec, schema, dependency,
ticket, live data or provider changes. No runtime or model tests are run here.

## Minimal permanent recommendation

Add one purpose-qualified activity-summary module to the existing coaching share.
For each deliberately included supported measure and **currently admitted exact
period**, show its canonical meaning, a qualified recorded count and the applicable
chosen target. Use the same P28 Goal Version and P9/P27/P6 sources as D23, through a
distinct authorized coaching projection. Do not copy Maya's private card payload,
build a coaching activity ledger or grant the coach constituent-row access.

The simplest initial numeric contract is **a compatible, complete admitted
comparison or an honest unavailable comparison**. Do not silently compare a smaller
coach-admitted subset against a target whose meaning includes a different cohort.
Independently permitted target information may remain useful when its count is
unavailable. Do not invent a replacement target, reduce the quantity in proportion
to excluded records or present a partial subset as Maya's target attainment.

This is a recommendation for the review, not evidence that every source projection
already supports it. Qualify an ordinary useful same-basis summary through the real
owners; “aggregate-only” must not become a permanent excuse to suppress every
measure. An unsafe or unqualified case blocks only its affected output/profile.

Use canonical measure names for this initial summary, **not personal free-text
target names**. “Call the Smith family about their crisis” is not safe merely
because it is a target title. Do not add a second shared-name field, an AI sanitizer
or copied private explanation. The existing voluntary check-in owner remains a
separate place for newly authored sharing-eligible context. Target quantities and
lifecycle fields themselves still require admission; they are not automatically
public because they are numbers rather than source records.

No donor names/initials, addresses, individual event dates, event IDs, message
subjects/bodies, encounter narratives, contact links or **View activities** action

giving the coach SELECT or drilldown access. Do not widen table or row grants to
make a convenient aggregate view work.

## Exact counting and comparison meaning

For reasoning only, let a target-period identity name:

`Tenant + actual target owner + exact typed ministry/workspace + canonical measure
and definition version + accepted period/calendar + applicable target revision`.

These are conceptual proof inputs, not a proposed SQL key or client-controlled
authorization token. The trusted source first admits the evidence for the exact
coaching-summary purpose under P12's current scope/classification/history/privacy
floor. It then counts distinct canonical occurrences satisfying that measure and
period. The output independently passes current coach/relationship/module/field
and aggregate-release authorization. A service credential or Maya's personal read
permission substitutes for neither decision. Raw coach history access is not a
prerequisite for properly authorized aggregate production.

**Comparison requires a shared meaning, not equal numbers.** The source must certify
that the admitted numerator covers the same measure, actual participant, typed
subject, period/calendar and recorded-activity cohort meant by that target. Its
coverage/currentness must support the claim. Different source sets can coincidentally
both count five; equality of those numbers is not a compatibility proof. Likewise,
two targets with the same label and quantity need not refer to the same scope.

If Maya's personal count is five and the coach purpose admits only three of those
occurrences, silently publishing **3 recorded / target 8** as her progress is wrong.
Do not reveal **2 private activities excluded**, publish her personal five using
privileged credentials, or invent an adjusted target. The simple initial fallback
is an unavailable comparison; show the target alone only if independently permitted.
A partial count could be a truthful separate measure only with an explicit qualified
limited-coverage contract and safe interpretation. This initial recommendation does
not introduce that extra profile or silently transform it into target attainment.

Conversely, a source-qualified complete summary of all five intended occurrences
may be authorized even when the coach can inspect none of the five underlying rows.
“Post-floor inputs” means admission to this exact summary purpose, not a requirement
that the coach have raw data access. Protected constituents, private/care facts,
field-classification floors and declared source-use restrictions still cannot be
bypassed by aggregation. The applicable floor is retained, not relaxed by consent to
share a target.

### Four independent measures retain D23 meaning

- **Calls made:** one actual outbound attempt by the counted missionary, including
  answered/unanswered/busy/voicemail. A call launch, planned call or generic Done
  does not qualify. An inbound call is not a call made.
- **Personal messages:** one authored personal outreach occurrence with qualified
  manual sent evidence or provider acceptance. Keep the help: **“Recorded as sent
  or accepted for sending. Delivery is not confirmed.”** Unknown/local queue does
  not count as confirmed submission; a real acceptance later bounced remains a
  submission. Newsletters and automatic receipts are excluded.
- **Conversations:** one source-qualified underlying actual encounter/exchange, not
  every message fragment, note or delivery. A brief human decline or relevant inbound
  without a stored outbound can qualify. Canonical asynchronous encounter identity
  remains a real source-integration gate; D24 adds no conversation classifier.
- **Meetings held:** one actual relevant meeting with qualified personal participation,
  not a calendar booking/end time, no-show or passive attendance.

One answered call can belong to Calls made and Conversations; one meeting can belong
to Meetings held and Conversations. Five calls and two conversations are not seven
unique activities. Conversations also include qualifying inbound and meeting exchanges,
so `conversations / calls` is not an authorized conversion rate. Do not combine targets
into a weighted score or average of their percentages.

A joint event remains one occurrence. Each actual participant's independently admitted
personal summary may include that person's participation once. A multi-missionary
coach portfolio must not sum those personal counts as unique team activity. Likewise,
one event in independently qualified subject views cannot be summed across projects
without a separately authorized distinct-occurrence measure. D24 selects no such
rollup, ranking or cross-organization total. Sender/participant remains distinct from
recorder, current assignee, recipient, CC and household/team membership.

## Periods, corrections, zero and inference

**Subsequent founder clarification selects future-period continuation for the same
selected target.** The proposed amendment is to bind that continuation to the exact
first reviewed period and the selected target's admitted meaning while sharing is
active. Qualified future periods enter that scope; already admitted periods remain
reviewable only under current rights, sharing duration and qualified source/retention
bounds. This retained-period behavior is a proposed D24 amendment, not an inheritance
from D10 or an assertion that retention/access limits already exist in implementation.

No period before the reviewed start, new/replacement target, materially changed
measure/participant/ministry scope, arbitrary lookback, export or notification is
included automatically. The first reviewed whole period may include dates before
Save; review its actual dates rather than manufacturing a partial period. A one-off
target still has no invented successor period. Paused intervals and resumed targets
retain D23 semantics without missing-period backfill. Current corrections to an
already admitted period do not create new temporal authority. Re-invitation, restored
data or a previously displayed count cannot revive ended sharing. D10's financial
history remains a separate grant.

Within any admitted period, source date and precision govern membership. A late
record/import or corrected occurrence date cannot use its processing timestamp to
enter a newly visible period. Unknown or cross-calendar-ambiguous occurrence cannot
be placed by guesswork. Preserve D23's accepted calendar meaning without revealing
restricted geographical metadata: an authorized “target calendar” explanation can
identify whose date boundaries apply without publishing an otherwise forbidden
IANA city identifier. If a truthful safe period explanation cannot be supplied,
the affected profile is not qualified.

The count is current authorized source truth for the admitted period, not a claim
about what was displayed at some earlier instant. A qualified correction, merge,
deduplication, restriction, allowed deletion or newly established source fact can
change the count or its certainty. Pair it with the applicable P28 period target
revision; do not project today's recurring quantity backward or freeze an erroneous
count. Review/snapshot evidence does not become another immutable activity ledger.
Pause removes the active comparison under D23; sharing must not keep a paused
attainment counter alive or turn paused/ended/unset into target zero.

**Zero is a qualified recorded fact.** It requires complete current admitted coverage,
an exact zero result and a permitted aggregate release under the applicable floor.
It never establishes zero actual activity, no relationships or poor effort. Missing,
stale, unknown-date, denied, suppressed and incomplete states must not become zero.
Nor may state labels reveal which hidden event or private record caused a different
answer. Existing uniformity and safe availability semantics still apply.

**Protect the whole offered output, not isolated fields.** If a count is withheld,
target plus percentage, progress bar/ARIA value, remaining quantity, “met/not met,”
trend delta or a complementary period/measure must not reconstruct it. Distinct
measures, overlapping admitted dates, multiple subjects and successive corrections
can reveal an individual encounter despite removing names. P12's existing applicable
tenant-tunable small-cell floor remains. Do not invent a universal N, define cell size
as the number of activity rows without owner qualification, or conclude that every
one-missionary summary is forbidden merely because its target owner is one person.
Qualify the finite offered profile and its release behavior through the existing
floor; unsafe exact results and revealing complements are withheld, not fabricated.
No arbitrary noise, general statistics platform or promise against all external
background knowledge is introduced.

## Material concerns — eight dimensions each

### SS24-01 — Personal count is copied into a broader coaching purpose

1. **Harm:** private/forbidden activity is disclosed, or implementation grants raw records solely to compute the summary.
2. **Severity:** critical for protected-person/care/identity disclosure.
3. **Likelihood:** plausible when reusing the personal card API or privileged query.
4. **Cause:** treating Maya's read rights or a service credential as the coach-summary input authorization.
5. **Evidence:** S01 C14; S04; S06; S08; S09 C06.
6. **Effect on A:** requires a bounded summary-purpose source producer, preserving useful aggregate-only access without raw grants.
7. **Clause:** “The trusted producer SHALL admit inputs for the exact coaching-summary purpose under current source/scope/classification/history/privacy floors before arithmetic and independently authorize the resulting output. Personal-read or service privileges SHALL NOT substitute. No constituent-row read or wider source-table grant follows from summary eligibility.”
8. **Proof:** a permitted aggregate works with coach raw reads denied; prohibited source input is absent even with service credentials; wrong tenant/subject/purpose/grant fails; personal card payload cannot be reused as the coaching result.

### SS24-02 — A subset is compared with the wrong target

1. **Harm:** Maya appears further from her goal, or privacy is breached to force equality.
2. **Severity:** high for semantic truth and disclosure.
3. **Likelihood:** likely with filter-then-count and an unchanged personal denominator.
4. **Cause:** assuming a complete coach-eligible subset is complete for the target's intended recorded-progress basis.
5. **Evidence:** S01 C05/C10/C13/C14; S09 C05/C11; source grain analysis above.
6. **Effect on A:** require compatible cohort/coverage; initial fallback is unavailable comparison, not partial attainment or an invented adjusted target.
7. **Clause:** “A count-to-target comparison SHALL certify the same measure/version, actual owner, typed subject, exact period/calendar and recorded-activity cohort meaning, with complete admitted coverage. Numerical equality alone SHALL not establish compatibility. If only a different/partial cohort is admissible, the comparison SHALL be unavailable; independently permitted target information may remain without ratio, remaining or attainment.”
8. **Proof:** personal five versus coach subset three; equal-sized different cohorts; one measure with different actor/scope/calendar; full aggregate with zero raw access; target-only state neither exposes excluded counts nor fabricates failure.

### SS24-03 — Count rows or overlapping measures inflate coaching activity

1. **Harm:** one joint encounter becomes several events, or five calls plus two exchanges becomes seven activities.
2. **Severity:** high for factual interpretation; potentially high privacy consequences in small groups.
3. **Likelihood:** high with recipient-copy joins, card sums or project portfolio totals.
4. **Cause:** communication/person-copy, narrative, participant and subject relations are mistaken for underlying occurrence identity.
5. **Evidence:** S03; S05:31; S01 C05–C07; S12.
6. **Effect on A:** reuse exact D23 distinct units/actor attribution; no team total or cross-measure conversion formula.
7. **Clause:** “Each admitted measure SHALL count its canonical qualifying source occurrence once for the exact personal scope. Recipient copies, narratives, known provider/manual corroboration and subject joins SHALL not multiply it. Overlapping measures and independently attributable personal summaries SHALL not be summed into unique team activity, conversion, effort or performance.”
8. **Proof:** group message recipient fan-out; two missionaries in one meeting; five/two call example; inbound exchange without outbound; same event in two subject views; separate genuine calls remain separate; unknown correlation stays honest.

### SS24-04 — Safe-looking fields reconstruct withheld activity

1. **Harm:** count suppression fails through ratio, target-minus-remaining, overlapping periods, cross-measure differences or correction deltas.
2. **Severity:** high; critical where a protected contact is identified.
3. **Likelihood:** plausible with independently approved fields but unreviewed combinations/releases.
4. **Cause:** names removed or each field separately permitted is mistaken for inference safety.
5. **Evidence:** S06:1664; S07; S08 C12; S09 C07/C08.
6. **Effect on A:** qualify a finite whole output profile under the existing floor; no universal N/noise/new statistics engine.
7. **Clause:** “The offered measure/period/target/count/status profile and successive releases SHALL pass the applicable aggregate floor and combined-output inference qualification. Unsafe counts and reconstructing complements—including percentages, bars/ARIA, remaining, attained flags and deltas—SHALL be withheld together. No new universal threshold or private-exclusion count is inferred.”
8. **Proof:** hidden count with public target and percent; low-count measures, overlapping dates, multiple subject views and a one-event correction; compare whole JSON/accessible text/error/cache output; no claim of safety against all external background knowledge.

### SS24-05 — Personal labels, calendar metadata or links leak context

1. **Harm:** a target title names a donor/crisis, a raw timezone reveals restricted location, or drilldown opens individual history.
2. **Severity:** high; critical for sensitive location/identity.
3. **Likelihood:** plausible with whole-target serialization or reused personal cards.
4. **Cause:** nonnumeric fields are assumed harmless or necessary for numerical clarity.
5. **Evidence:** S01 C13/C14; S04; S06:1638–1641; S08/S09 output boundaries.
6. **Effect on A:** canonical labels and admitted contextual/date meaning only; no extra shared-name editor or content sanitizer.
7. **Clause:** “The initial summary SHALL use canonical measure labels and independently permitted subject/calendar descriptions. It SHALL omit personal free-text target names, protected context and individual source identifiers/links. Exact calendar semantics remain authoritative without automatic disclosure of restricted geographic metadata. No activity drilldown follows from this module.”
8. **Proof:** personal title contains a donor, note extract, phone number or location; aliases differ from legal names; forbidden raw IANA city; response JSON and accessibility labels contain no hidden source ID/body or View activity route.

### SS24-06 — Zero, unknown and incomplete become a performance judgment

1. **Harm:** missing/withheld logs are read as inactivity or failure; hiding an unsafe cell reveals its existence.
2. **Severity:** high for autonomy, privacy and trust.
3. **Likelihood:** high with zero defaults and red empty-progress widgets.
4. **Cause:** count scope/coverage and optional recording are not part of the output contract.
5. **Evidence:** S01 C13; S03:2373/2377/2417; S06 uniformity; S08 C11; S09 C11.
6. **Effect on A:** exact permitted recorded zero only, safe neutral availability, no quota interpretation.
7. **Clause:** “Zero SHALL require source-proved complete current admitted coverage, an exact zero result and a permitted release under the applicable floor. Missing, withheld, unknown-date, partial or stale evidence SHALL not become zero or target failure. Availability labels SHALL not identify protected exclusions. Recorded activity SHALL never imply all actual activity, effort, negligence or a compulsory duty.”
8. **Proof:** genuine admissible zero, no optional logs, source outage, stale source, undated fact, forbidden/suppressed cell and partial page; no automatic alert, rank, failure or disclosure of the omitted-record count.

### SS24-07 — Target and count revisions describe different realities

1. **Harm:** a corrected past count is divided by today's unrelated quantity, paused targets keep scoring, or old snapshots permanently retain invalid evidence.
2. **Severity:** high correctness/privacy risk.
3. **Likelihood:** plausible with copied denominator fields, generic current-head joins or additive counters.
4. **Cause:** target-period revision, current source evaluation and sharing scope are conflated.
5. **Evidence:** S01 C09–C12/C18; S02; S03:2373/2401/2409; S10 conceptual separation.
6. **Effect on A:** use applicable source-owned target version and current qualified historical facts for the admitted period; no extra history engine.
7. **Clause:** “Every comparison SHALL bind the applicable target-period revision and a current qualified activity evaluation. Authorized corrections, deduplication, reattribution, restriction and disposal SHALL reconcile counts/certainty without changing occurrence identity or silently rewriting target history. Pause/end/unset SHALL retain D23 meaning, not zero denominators or continued active attainment.”
8. **Proof:** temporary quantity edit; past period versus today's recurrence; date correction across a boundary; merge/duplicate removal; source restriction after a count was shown; paused/ended target; restore before correction cannot revive stale output.

### SS24-08 — Selected continuation silently expands beyond its target/start

1. **Harm:** coach sees periods before the reviewed start, other/new targets, changed private contexts or retained data outside the qualified sharing scope.
2. **Severity:** high disclosure risk.
3. **Likelihood:** likely with an unbounded all-target query, history defaults or D10 financial-grant reuse.
4. **Cause:** interpreting selected same-target future continuation as authority over all targets/history or as permanent retention.
5. **Evidence:** S08 C08; S10:20–55; S01 Q24 boundary.
6. **Effect on A:** implement selected continuation for the exact target/start; proposed retention of admitted periods remains current-rights/source bounded, with no arbitrary lookback.
7. **Clause:** “Continuation SHALL admit qualified future periods of the same selected target from the exact reviewed first period while sharing is active. Already admitted periods SHALL remain reviewable under the expressly disclosed retained-period amendment while current rights, duration and qualified source/retention bounds allow. Earlier periods, other/new targets and material meaning/scope changes SHALL NOT enter automatically. Each response SHALL re-prove current scope; financial-history permission, retained data, later import and earlier disclosure SHALL not supply missing authority.”
8. **Proof:** selected target rolls into its next eligible period and retains an admitted past period under current rights; earlier period/new target/materially changed scope do not follow; one-off has no invented next period; pause/resume creates no missed-period backfill; late correction respects occurrence date; D10 alone and repeat invitation cannot restore activity history; old tab after Stop fails.

### SS24-09 — A safe count is released under stale authority or unsafe transport

1. **Harm:** revoked coaches receive cached results or retained private derivatives survive body disposal and scope changes.
2. **Severity:** critical for unauthorized disclosure.
3. **Likelihood:** plausible with cache-first personal-card reuse, background summaries or logging whole responses.
4. **Cause:** computation-time authority treated as lasting permission to release all derivative fields.
5. **Evidence:** S06:1586–1587/1609–1615/1645–1650; S01 C14/C18; S04 retention; S09 output boundary.
6. **Effect on A:** source/profile/current-authority bound derived results; no special activity-sharing engine or indefinite cached truth.
7. **Clause:** “Preview, save recovery, read, cache, background computation and every reached egress SHALL retain exact current tenant/actor/subject/module/period/field authority and source revision/coverage. Recheck at protected release; revoked or stale results SHALL not be emitted. Metric retention, audit and body-free facts remain independently governed; source body disposal grants no indefinite summary archive.”
8. **Proof:** compute/revoke/release in both orders; source update versus cached result; missionary preview beyond own rights; direct endpoint/JSON/export attempts; restored grants; logs/cache keys reveal no hidden count or source body.

### SS24-10 — Numeric exactness or unsupported abstraction changes meaning

1. **Harm:** large counts round during transport, unsafe sums overflow, or a custom dashboard invents effort/money relationships.
2. **Severity:** high for false totals at bounds; medium for avoidable complexity.
3. **Likelihood:** plausible with JavaScript Number coercion, summed card totals or generic report builders.
4. **Cause:** assuming every database count is API-safe and every mathematical transformation is a permitted metric.
5. **Evidence:** D23 C16 exact finite quantity bounds; S01 canonical units; S07 derived-field/type fidelity; S08 no performance inference.
6. **Effect on A:** plain exact integer count and chosen target are sufficient; retain source/API bounds without money, percentages or custom formulas.
7. **Clause:** “Count and target quantities SHALL remain exact through database, API and display using qualified finite representation/bounds; reject overflow or unsafe coercion without a false value. This module SHALL not introduce cross-measure sums, financial ratios, weighted scores or arbitrary formulas. Counts above a compatible target SHALL remain truthful rather than capped away.”
8. **Proof:** zero/one/max supported integer and unsafe-range rejection; transport preserves exactness; a permitted twelve against eight remains twelve; no weighted target score, currency conversion, or conversations-to-calls success claim.

## Required owner extension and proof limits

Extend the existing P28/D8 sharing profile with the supported activity fields and
exact source/target compatibility contract. P9/P27/P6/P17 certify the actual units,
participants, canonical occurrence/correction relationship, dates and body-free
evidence; P28 supplies target-period revisions; P12 supplies one current purpose and
disclosure decision. The applicable source/floor/profile must qualify an ordinary
usable comparison without raw coach access before the module is offered. Implement
the founder-selected same-target continuation and explicitly review the proposed
retained-period amendment; do not silently add earlier periods, other targets,
unlimited retention or a separate activity-history engine.

Production proof must exercise real source adapters, permission inputs, count
completeness, output combinations, repeated release/correction, target revision and
revocation paths. Small synthetic set examples establish why cohort equality, raw
row counting or a single suppressed field is insufficient; they do not establish
an actual safe coach projection. D23's 27 finite counterexamples are not rerun or
promoted to D24 authorization/inference proof. No provider calls, user observation,
database experiment, deployment or measured usability/capacity result is claimed.
