# D9 — optional coaching support summaries: UX evidence and proposed journeys

Research only, 2026-10-16. Repository baseline: `9cada8f3d8ab59db391d3fd20df77fcadeb09813`. The founder selected optional organization-permitted expected/received-support summaries through the parent task; the Q9 question note and session were still awaiting their decision update when inspected. This evidence does not edit or ratify those records. Only this file was written. No application, database, invitation, notification, GitHub or hosted-data action occurred.

**Recommendation:** put a small, clearly labeled support-summary section inside the D8 native Coaching subject view. Prefer source-certified dated expected and received measures for the same approved interval, with received-so-far coverage explicit. Make inclusion deliberate, show the exact effective sharing scope before saving, and distinguish each measure by basis, currency, population and currentness. Two readable amounts can complete the immediate coaching job. A chart, report builder, donor drill-down, portfolio total or new inbox is not a prerequisite.

The choice admits optional modules; it does not decide initial control state, exact financial projection, historical range, access duration or FX conversion. All examples below assume a separately qualified source projection and already authorized interval. They are proposed copy and interaction sketches, not implemented screens or evidence from user interviews.

## Minimum meaning visible at the point of reading

Every amount needs a human-readable **measure, unit/currency, scope, basis and time coverage**. Keep the safe subject and organization in the header, the measure and ISO currency with the value, and the period or planning cadence next to it. Explain source inclusion, adjustments and freshness in a compact **About these numbers** disclosure. Do not bury the distinction between a planned monthly equivalent and actual receipts in a tooltip.

| Situation                                                    | Clear presentation                                                                                                                                                                                                           | Misleading shortcut to exclude                                                                                                                                                                 |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dated expected amount                                        | **Expected support — [approved date interval]**, only for a producer-qualified population. If only exact automatic occurrences are qualified, say **Online recurring planned in [interval]** and explain that bounded scope. | Calling an automatic-only subset all expected support, summing linked automatic/fixed-total obligations twice, or treating a normalized annual/quarterly amount as scheduled in that interval. |
| Monthly-equivalent planning amount, if admitted              | **Monthly support committed — USD [amount]/month**; **Monthly equivalent for planning; not scheduled receipts.**                                                                                                             | Labeling it “Received,” “Due this month” or guaranteed income; dividing fixed-total pledges into sustaining coverage.                                                                          |
| Effective received amount                                    | **Received support — [approved interval] — USD [amount]**; specify source coverage/cutoff and approved adjustment basis.                                                                                                     | Calling it spendable balance, take-home pay, available funds or cash on hand; counting processing/recognition/promise as receipt.                                                              |
| Goal comparison, only if separately permitted and compatible | Name the shared goal and period; render a ratio only when subject, currency, basis, period, coverage and goal version are compatible and disclosure-safe.                                                                    | Generic “% funded,” using a private goal as denominator, clamping away over-goal facts, or deriving a hidden numerator from a visible ratio.                                                   |
| More than one source currency                                | Separate clearly labeled authorized currency rows/cards, bounded by source policy. Use each currency's correct minor units and display rounding.                                                                             | Sum unlike currencies; assume `$` means USD; add an FX dropdown or converted grand total without its own approved source contract.                                                             |
| Different cutoffs/coverage                                   | Show the relevant cutoff beside each affected measure. A partial month says **so far**.                                                                                                                                      | One “Updated now” based on browser fetch time; a partial-period comparison presented as final.                                                                                                 |

Expected and received often overlap economically: a commitment can later produce the received gift. Do not stack them into a larger “Total support,” subtract them into “Overdue,” or turn their difference into pressure on donors. An explicit source-owned comparable variance may be a different later projection; this note does not add it. Source-approved corrections can decrease a received amount without implying reduced effort or misconduct.

P16's exact dated automatic occurrences support a bounded planning population; they do not by themselves qualify one unified automatic/manual/fixed-total expected-support producer. A recurring mechanism can fulfill a fixed-total commitment, so adding those records naively can double count. Until the finance owner qualifies the broader population and overlap treatment, name the available subset honestly. Matching dates and currency do not make a subset of planned support comparable to all received support for a fulfillment ratio. Monthly-equivalent planning remains a separately admitted alternative explanation, not the primary dated-pair recommendation or a fallback when dated expectations are unavailable.

## Proposed journeys and screen sketches

### 1. Missionary reviews inclusion in one coach's existing sharing scope

Entry: **Coaching → Jordan Lee → Sharing**. Show the actual current source state, not a hardcoded On/Off default. A single binary inclusion control for the finite, admitted summary profile is sufficient. If future policy independently offers expected and received modules, render only those exact choices; do not invent a per-field permission builder. Keep the review inline so a routine choice does not require several confirmation dialogs.

```text
Hope Mission · Coaching                         Maya Chen
Sharing with Jordan Lee
Community Ministry

Support summary
[✓] Include the permitted support summary
Jordan can view the expected and received support described below.
They cannot edit your records.

What Jordan will see
Expected support: [plain-language approved measure and currency]
Received support: [plain-language approved measure and currency]
Visible dates: [exact approved dates or current-view rule]
Access ends: [the existing source-approved access terms]

[Review coaching view]
                               [Cancel] [Save sharing]
```

The checked state illustrates a deliberate draft choice, not a default for new invitations or existing coaches. Do not require the missionary to choose new dates or duration here unless the owning sharing flow actually supports and requires it; render the already qualified terms. Missing scope prerequisites must be resolved before the module can activate, rather than silently choosing “all time” or “forever.”

**Review coaching view** uses the exact proposed safe projection, bounded by the missionary's own read authority; it must not reveal a coach's independent staff rights or inaccessible source facts. Safely explain any part the missionary cannot preview. Scope includes whether amounts are current-only or cover specified dates; a two-number card is not automatically free of history. The summary profile must not silently widen because another currency, module or field becomes available later.

Plain exclusions can follow the scope summary when they describe the actual contract: **“This summary does not include donor identities, individual gifts, account balances or export access.”** Do not say “anonymous” or “only between you and Jordan”: aggregate inference and other independently authorized audiences remain possible. Names, amounts and scope labels themselves still require disclosure qualification.

### 2. Saving, stopping and changing a summary share

Use **Saving sharing…** while the exact command is unresolved. Success is **“Support summary sharing updated.”** with the saved effective scope visible. An ordinary rejected command shows **“Sharing was not changed. [Safe reason.]”** only when the source proves no change. A lost/unknown response shows **“We couldn't confirm the sharing change.”** with **Check status**; do not falsely restore a previous grant or report success from the local toggle alone.

If policy or sharing scope changed since preview, show **“Sharing options changed. Review the current scope before saving.”** Preserve safe unsaved intent; never silently add newly permitted fields or overwrite another editor's source state. Ordinary source amount updates follow the approved projection semantics and do not require a new consent dialog on every refresh.

Turning off this module saves **“Support summary removed from this coaching share.”** It does not delete financial records or end independently permitted goals/check-ins/coaching access. Do not promise to erase information already seen. Current protected reads and retained browser views must obey the source revocation boundary; an optimistic animation or toast is not enforcement. Other separately authorized rights must be explained accurately, without claiming this control globally removes all financial access.

### 3. Coach opens one subject from the D8 portfolio

Keep the existing one-organization Coaching portfolio: search permitted people/projects, then open one. Financial amounts need not appear on every portfolio row. Do not add a “Total coached support,” ranking, auto-selected project descendants or simultaneous charts per person. Separate grants may cover overlapping support allocations; adding cards does not create a valid aggregate.

The following **illustrative example** assumes the owner has admitted exact dated automatic recurring occurrences, a received-support projection, USD and the displayed October interval in the organization's governed giving timezone. It does not establish that these producers are implemented, choose a default interval or grant these historical dates for D9 generally. Because the broader expected population is not yet qualified, the planned card names its automatic-only subset.

```text
Hope Mission · Coaching                         Jordan Lee
[Back to Coaching]
Maya Chen · Community Ministry                  View only

Support summary                                 [View sharing]
Period: 1–31 October 2026 · USD

Online recurring planned in this period
USD 4,200
Automatic recurring gifts only.
As of 16 October 2026, 13:00 UTC

Received support so far
USD 1,600
All included received gifts, 1–16 October 2026.
Records through 16 October 2026, 13:00 UTC

[About these numbers]                           [Refresh]
```

On desktop the measures may sit side by side; on a phone they stack in the same reading order. All key words, currency codes and dates remain visible. The cards are not links to donors, gifts, payment recovery or Field Accounts. The received projection's exact included scope must be explained: in this example it may include gifts outside automatic recurring, so these are not matched paid-versus-due amounts. If the broader dated expected producer is later qualified, its title and explanation can describe that approved population; do not relabel the existing automatic-only sum as total expected support.

**About these numbers** should explain the admitted inclusion/adjustment basis, planned-versus-received populations and useful source freshness in ordinary language. It need not expose ledger cursors, schema names or internal IDs. **Refresh** rechecks current permission and source facts; it does not make a stale ledger current by changing the display timestamp. Dated planned support and received-so-far can inform the conversation without a percentage, subtraction or a stacked bar. If a monthly-equivalent alternative is separately admitted, label it explicitly as planning equivalence rather than substituting it under the dated title. A separately shared goal may remain in the Overview; no goal or unshared goal means no manufactured denominator or warning to set one.

### 4. Complete, partial, withheld and interrupted states

| Source-qualified state               | Proposed visible copy/behavior                                                                                                                                    | Important boundary                                                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Complete, known zero                 | **USD 0 received in [permitted period].** Relevant cutoff remains visible.                                                                                        | Use only when the authorized source proves complete coverage and zero. No inference of failed effort or missing donor action. |
| Known incomplete coverage            | **Support records are incomplete for this period.** A partial amount, if explicitly safe/approved, is labeled **Partial total** with its exact coverage.          | No percentage, forecast or “nothing received” from a capped list, omitted currencies or unsettled source.                     |
| Source not available                 | **We couldn't load this support summary. Try again.** Keep other independently available coaching material usable.                                                | A network/server error is neither zero nor a source-confirmed change in sharing.                                              |
| Authorized but stale                 | **Last confirmed [source time]. Current figures are unavailable.** Retain a value only if the owner explicitly permits stale display and access is still current. | Never label request time as financial freshness or show a prior value under a new subject/context.                            |
| Privacy-limited projection           | **This summary isn't available in this coaching view.** Use source-approved neutral wording; omit where even existence is unqualified.                            | Do not say “only one donor,” reveal a suppressed count, show an inferable percentage, or distinguish secret causes.           |

Do not flatten these to a bare dash. User-facing causes remain subject to disclosure policy: an unavailable state must not become an oracle for hidden grants, donors or records. Keep the underlying distinctions even where two causes deliberately share neutral copy.

### 5. History and charts remain explicit scope, not decoration

A sparkline, prior-period delta, average, chart tooltip, date selector and downloadable data table all disclose historical or derived facts. D9's two-summary eligibility does not authorize any of them automatically. Do not copy the missionary analytics six/twelve-month selector or MPDX's thirteen-month report. The UI can be complete and useful with the two qualified current summaries.

If a later exact history projection is admitted, show its approved range and coverage directly, use only compatible measures/currencies, and supply the same authorized values in readable text/table form. No arbitrary date/filter builder, small-cohort drilldown or range differencing escape is implied. Goal revisions must be identified correctly rather than reapplying today's goal to every past period. Private table values cannot be justified as an accessibility alternative to a safer chart.

## Phone, accessibility and bandwidth requirements

Use Core's shared `base-maia` composition and semantic tokens. Visible labels associate each amount with its measure/currency/period; a currency symbol, tooltip or color is insufficient. The inclusion field has a stable accessible name, description and checked/pending state. A staged checkbox plus one save is simpler than a switch that appears committed while a hidden review remains pending. Neither control implies a default policy.

At 320 CSS pixels and 400% zoom, keep organization, subject, View only, period, scope review and save/status controls readable without page-wide horizontal scrolling. Wrap long names, translated measures and ISO currency codes; do not truncate the distinction between planned and received. Use keyboard-operable disclosures and logical focus restoration. A failed save leaves actionable text beside the field; a confirmed update is announced without moving focus gratuitously. Visible status is not toast-only. No red/green effort grading or forced chart animation.

Fetch the bounded authorized summary needed for the selected subject. Do not download donor rows to derive totals in the browser, prefetch every subject's financial history, or require a chart bundle for two amounts. Handle partial request failures per module and maintain useful navigation. Protect context changes from late responses, and scope any cache by current authorization rather than the user's identity alone. These are proposed experience requirements; no bandwidth, latency, browser or assistive-technology measurements were performed.
