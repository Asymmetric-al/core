## The single product choice

Maya already keeps a contact list in a spreadsheet or has exported it from
another support-raising tool.

**When her organization permits it, should Maya be able to review and import
that contact list herself, or should staff handle file imports initially?**

- **A — Missionary self-service import (recommended).** Maya uploads a supported
  contact file, reviews the proposed additions and any problems, then deliberately
  imports eligible contacts into her permitted workspace. Newly supplied prospects
  retain their restricted start.
- **B — Staff-assisted import initially.** Authorized staff handle file imports
  through the governed import process; Maya can still add contacts individually.

This concerns reviewed file-based contact intake, not ongoing synchronization,
mailbox/address-book access, importing historical giving or automatically enrolling
newsletter recipients. “One-time” distinguishes a file intake from a live
connection; it does not mean one upload per person forever or prohibit safe
reimport/recovery. A contact is not automatically a financial supporter.

**Recommendation rationale:** A reduces repeated entry and migration handoffs
for missionaries who already maintain a list, while organization permission and
the same source/identity controls retain governance. B is a legitimate initial
centralized option but makes ordinary list intake dependent on staff availability.
This is product judgment supported by documented comparable workflows, not a
measured adoption or task-time result. Neither answer grants staff access to
existing restricted preparation or authorizes a duplicate private CRM.

- [Ratified D2](phase28-d2-adversarial-review.md) keeps staff CRM availability
  deliberate and distinct from private context and consent. [Ratified D5](phase28-d5-adversarial-review.md:25)

- [Retained P30 obligations](../../../prds/program-roadmap/owner-constraints.md:326)

## Original consequences identified before the answer

If A is selected, use one bounded P28 entry into P30's reviewed intake contract,
P29 custody and the exact P9/P4/P12 source boundaries. Do not create another
parser/mapping/merge authority or choose a vendor merely because old plans name
one. Raw file, staging, preview, error downloads and accepted rows must preserve
the actual audience. Staff-assisted intake likewise requires permission for the
submitted file and exact target; it grants no general restricted-roster access.

The smallest useful journey is upload → review/fix → import → accurate results.
Preview changes no contact facts. Commit rechecks current authority and target
revisions, accepts only eligible fields, retains source provenance and resolves
repeat/interrupted work without duplicates. Imports do not override opt-outs,
subscribe recipients, send messages or manufacture donor/commitment/history facts.
Do not promise universal undo after merges or later edits.

Exact format/size profiles, field mapping, duplicate cases, restricted target
admission, row outcomes and recovery require the subsequent review if A is
selected. This question does not preselect bulk modification of existing shared
records, all historical data types or a full competitor migration. Manual entry
continues to work under either answer.

Source-qualified assistance remains a separate frontier. The original note
