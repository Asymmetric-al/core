# D37 — repository governance for optional starting guidance

Research date: **October 18, 2026 Asia/Bangkok**. Repository
`9cada8f3d8ab59db391d3fd20df77fcadeb09813` plus the current working tree.

The founder selected Q37 A: authorized staff arrange suggested steps linking to
approved resources and existing workspace actions; missionaries can use, skip
and return. The latest clarification explicitly confirms **optional use**:
tenants may offer, edit or disable the guide, but cannot require completion.
That clarification is a selected product fact, not an unanswered ambiguity.
The precise clauses below are recommendations for the answer review, not
separately ratified amendments or implementation evidence. The original Q37
research's unanswered status is historical and does not override this answer.

Only this new research note is written. No earlier evidence, model, probe or
verifier is executed or changed. No formal specification, owner contract,
application, schema, ticket, provider, live permission or external data is changed.

## Recommendation and strongest alternative

Accept A with the narrow amendments below. Deliver a small native, organization-
authored starting guide, using a short ordered set of safe suggestions and
links. It is useful orientation, not a learner record, a personal task list or
another workflow. Its value over a PDF is that it connects approved advice to
the actual permitted workspace entry points. No real ministry interviews,
usability results or comparative performance were established by this note.

The strongest simpler alternative remains a well-organized D12 resource library
with a starting guide document and ordinary contextual help. That alternative
has lower maintenance cost and may be sufficient for some organizations; A was
selected to add the native connection between steps and workspace destinations.
Keep that cost explicit: somebody must maintain the guide and invalid references.
Do not justify a course, automatic assignment or tracked checklist merely because
the selected native guide needs a publication contract.

Recommend one organization guide with one draft and one currently offered
release, using compatible existing publication components. **Publish/update and
Hide** can express offer/edit/disable without a second independent enablement
state machine. Draft changes are not live until deliberately published. A
disabled guide remains editable; publishing again is deliberate and uses current
authority and current eligible destinations. This is proposed minimal design,
not a founder-selected schema, button vocabulary or mandatory extra approval.

## Current code observations and bounded negative evidence

The header imports shared `@asym/ui` controls and uses an ordinary Next Link for
Help/About. The About page describes deployment/build/licensing information.
`navigation-items.ts` uses a `UserRole` switch to choose visible links, and the
sidebar renders them as navigation. This is UI composition, **not** proof that
matching a role string authorizes a guide or destination. Do not copy that
presentation switch as the new content/action permission rule.

A scoped search for `getting-started`, `starting guide`, `onboarding`,
`guide_steps` and `guideSteps` in `apps/missionary`,
`packages/api/src/missionary-portal`, and shared collection/hook directories
found unrelated sample support/admin onboarding references but did not establish
a native tenant-authored guide publication source. No claim is made that every
repository screen or deployed product was inspected. Existing D12 research also
does not prove its resource producer implemented. No database, live roles,
provider, browser, accessibility or performance qualification was performed.

## Exact proposed decision clauses

**G-C01 — Always optional.** “The starting guide is advisory. Tenants may offer,
edit and disable it; they cannot configure required completion, mandatory
acknowledgment, a feature-access gate, a compulsory sequence or an assigned
training program through this capability. Missionaries can use, skip or return
without penalty. Ordinary currently authorized workspace work remains usable
when the guide is missing, disabled, ignored or temporarily unavailable.”

This clause implements the founder's explicit clarification. It does not claim
that software can police all organizational expectations expressed elsewhere or
that free text automatically detects coercive wording; no new classifier is implied.

**G-C02 — One bounded guide source.** “P28 owns the internal starting-guide
publication purpose, suggested wording/order and typed destination references
through a qualified native source contract. Reuse compatible resource/publication
components and existing server/data/UI boundaries. P29 retains byte custody and
each destination retains its own truth. No new public CMS, storage provider,
LMS, workflow engine, generic form builder or app-local business database is
introduced. One organization guide is the proposed initial profile; no role-
based curriculum matrix or inferred novice/veteran classification is selected.”

**G-C03 — Current curation and readership.** “Resolve exact tenant, acting
context and current scoped prepare/publish/hide/read authority through P12.
Reading a guide, being called staff, being a resource curator, owning a linked
document or being a missionary does not independently grant every other guide
or destination action. Explicitly qualify compatible existing capabilities or
their narrow extension; do not invent a parallel permissions system or silently
grant access by navigation membership. Ordinary missionaries receive no guide
authoring rights from this feature; a separately qualified staff context remains
usable under its own authority.”

**G-C04 — Deliberate safe publication.** “Prepared wording and order remain a
draft until deliberate publication of that exact reviewed version. Save draft,
publish/update and hide have truthful source outcomes and current authority;
use the existing compatible publication mechanism, with expected revisions,
atomic state/audit and minimal safe retry recovery. A failed replacement leaves
the prior independently safe release unchanged. A stale publish, old replay or
lost-response retry cannot silently reverse a later hide or publish another
draft. Deliberate re-offering requires fresh current review. No routine second
approver is added; actual projection-policy widening retains ADR-0211.”

**G-C05 — Hide guide, preserve independent work.** “Disabling/hiding stops new
guide discovery and release through that purpose, with current access enforced
on stale links and caches. It does not withdraw linked resources from their own
qualified library, delete retained bytes, cancel tasks, revoke independent
destination rights or erase source history. Editing remains available to
currently authorized staff while hidden. A failed hide is not success; an
uncertain outcome is recovered through current source status. Previously
lawfully released bytes cannot be recalled.”

**G-C06 — Links navigate; sources act.** “A step links to a qualified approved
resource or a finite registered existing workspace entry point. Rendering,
prefetching, opening or returning from the guide never performs the linked
mutation. The destination re-proves current authority, presents its own required
facts/consequences, and accepts any action through its existing deliberate
source command. Do not accept arbitrary executable URL/query payloads,
tenant-supplied scripts, commands, cross-tenant references or a new global
deep-link engine. External material, if supported, goes through the existing
qualified resource-link profile, not a new guide-specific browser/integration.”

**G-C07 — Current resource and destination safety.** “Guide publication does not
publish a referenced resource, freeze an expired resource permission or certify
an unbuilt action. At render and use, resolve each destination through its
current source contract. Protected target names, titles, snippets, counts,
routes or refusal reasons cannot leak through guide copy, editor pickers,
errors, previews or stale caches. Where existence itself is not permitted, use
the owner's omission/uniform-unavailable behavior; do not display hidden-step
counts or numbered gaps that reveal suppressed destinations. A genuinely
permitted general entry can explain its own ordinary unavailable state without
claiming completion. One bad optional destination need not block independent
eligible guide content or ordinary workspace work.”

**G-C08 — No completion or behavioral record.** “No guide completion state,
percentage, deadline, overdue badge, acknowledgment, course result, assigned
task, reminder, coaching enrollment or staff progress dashboard follows from
this feature. Viewing, opening a link or returning records no actual encounter,
source-action completion or performance conclusion. Existing source actions
may produce only their separately authorized effects. Keep legitimate security
or content-publication audit distinct from a missionary behavioral report.”

**G-C09 — Simple reusable presentation.** “Provide a discoverable optional entry
and a readable ordered presentation through shared base-maia/Base UI components.
Keep resource/action links descriptive; do not use disabled progress checkboxes
or a forced tour to imply completion tracking. Support phone, keyboard, touch,
screen reader, long/localized text and weak-network loading/recovery. No saved
progress or permanent dismiss preference is required merely to let someone
leave and return. Current empty, hidden, loading and error states remain honest
without exposing protected source reasons.”

**G-C10 — Classified, bounded content and release.** “Qualify guide fields,
authoring limits, supported text/link formats and exact destination kinds before
activation. Use safe text rendering and permitted source references; no arbitrary
HTML, embeds, dynamic donor/context interpolation, resource-body copying or
AI personalization is selected. The shared current resolver governs every
read/preview/search/cache/error/recovery path. A staff preview is not permission
to fetch another person's protected content or execute a live action. Published
generic guidance must not become a back door to private CRM/care history.”

**G-C11 — Bounded rollout and proof.** “Preserve qualified retained publication
and independent resource/source uses; no inferred backfill from an About page,
uploaded folder, default template or old task. Do not auto-publish a starter or
re-enable a hidden guide during upgrades/restores. Qualify exact source/policy
commands, current read/target access, revision/recovery, publication/hide races,
actual composed accessibility and useful operation before activation. Future
implementation uses the qualified native owners; documentary review does not
prove a working guide.”

## Required owner amendments and acceptance evidence

**P28/resource-purpose source:** explicitly add the bounded internal guide
publication meaning, content/order/destination references, optional behavior and
offer/edit/hide lifecycle. Reuse compatible D12 primitives only after qualification.
D37 does not ratify the whole D12 recommendation set by association. Whether one
shared implementation represents resources and guidance is an engineering choice;
there must remain one authority for each published fact.

**P12/P3/P10:** qualify exact guide preparation/publication/withdrawal/read and
destination pickers, field/purpose classification, current context and safe
release/recovery. Existing authorization owns the decision. An editor gains no
automatic target-content read, grant-management power or unrestricted impersonation.
Actual projection-policy widening keeps ADR-0211; routine edits to permitted
guide content under a qualified policy do not create a new approval service.

**P29 and destination owners:** preserve exact approved resource/version access,
custody/withdrawal and independent uses. Register only safe entry destinations
that actually exist and are qualified. P9/P27/P6/P17/finance actions retain their
own acceptance, completion and evidence; D37 cannot make them implemented by
linking to their names. This does not require every roadmap action to ship before
an independently complete guide can offer its qualified subset.

**Platform/active OpenSpec reconciliation:** the later authorized formalization
must describe this bounded native extension and tests without a second CMS,
task model, workflow or permissions engine. The existing platform source and
shared-package boundaries remain. No formal artifact is edited in this review.

Required proof before activation:

- Authorized staff prepare, reorder, review, publish, edit and hide a guide;
  a missionary can discover, ignore and return without any access gate or
  completion record. Drafts stay private and no actor gets an unrelated right.
- Clicking/prefetching a step only navigates. Actual target mutation follows
  its own current deliberate source path; unsupported or cross-tenant targets,
  executable URL payloads and unauthorized editor selections are rejected.
- Guide hide, destination withdrawal, privilege loss and tenant/context switch
  prevent new unauthorized content/target disclosure across editor, read,
  recovery and caches. An old retry cannot republish or reverse a later hide.
  Independent resource access and independently created work remain intact.
- A changed or unavailable optional destination does not expose its protected
  identity/count or fabricate completion. Independently permitted content and
  ordinary workspace work remain usable. Actual null/error/loading states are
  distinguishable only where authorized.
- The composed guide and authoring flow works with actual shared controls,
  mobile widths, keyboard/screen-reader navigation, long/localized text and
  interrupted requests. No measured usability or performance result is claimed
  until obtained on the implemented flow and representative qualified workload.

No numerical step, body-size, load, retention or user-success threshold is
invented here. Qualify supported finite profiles and ordinary operational
budgets in the source implementation. Publication audit and content safety
operations are necessary; individual guide-progress monitoring is not selected.
