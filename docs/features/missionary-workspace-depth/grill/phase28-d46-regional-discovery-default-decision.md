# Phase 28 D46 — regional discovery starts Off

October 18, 2026. **Q46 answered A; accepted as selected.** The founder answered
**“A — Off until staff enable it.”** This records the initial product policy,
not an implemented setting or a live configuration change.

## Decision

For a **new organization**, regional discovery starts **Off**. Authorized staff
may deliberately enable it through the one organization-wide control already
selected in [D13](phase28-d13-regional-map-decision.md). It governs both regional
browsing and the world map in the missionary workspace. Readiness alone never
automatically enables it. Enabling still requires qualified sources and current
authority; it grants no additional information access.

Preserve existing organizations' explicit choices. Missing or unreadable policy
does not mean On; legacy unknown settings require qualified migration treatment,
not an inferred preference. Independently published ministry Pages, their public
reach, the resource library and other source permissions remain separate.

Keep the staff journey small: one clearly named control and a concise explanation
of what missionaries will gain. Staff see the confirmed saved state and honest
pending/failure feedback. No approval queue, setup wizard, per-missionary override
or second map-specific switch is added. If prerequisites are unavailable, explain
that fact where staff configure the feature; do not present a working On state.

While Off, ordinary missionaries do not see an inactive Explore ministries menu
item. An old direct link gives a safe unavailable state and a way back to the
workspace. Off is enforced on the source response as well as navigation. When
enabled, the existing map/list journey uses current approved broad-region
information. No precise or inferred private locations are introduced.

## Scope and supersession

D46 adopts only D13's **initial Off default for new organizations**. D13's
selected map/list scope and single tenant control are unchanged. Its initial
List presentation and remaining detailed amendment packet retain their separate
reviewed status. The [pre-D46 review](d46-evidence/d13-before-d46.txt) preserves
the earlier recommendation. This does not retroactively turn existing tenants
Off, adopt every D13 requirement or declare the feature ready to activate.

## Adversarial check

### What could go wrong with this answer?

A default migration could reset an existing On choice, or a UI-only Off could
leave a direct data route available. Preserve explicit existing state and apply
the current source-owned control to every regional response. Stale On retries
cannot overwrite a newer Off.

### What hidden assumptions are we making?

The recommendation assumes organizations benefit from deliberately offering this
optional workspace entry. That is a product judgment, not measured tenant demand.
The existing settings source and qualified geography consumer still need delivery
proof; a recommended control is not an already implemented capability.

### How does this affect the whole product?

Only initial availability of D13's missionary regional views changes. Public Page
publication, resources, identity, source permissions and other tenants keep their
owners and scope. Existing tenant choices remain authoritative.

### How does this affect the end-user experience?

Staff take one deliberate action if the feature is useful. Missionaries get a
working entry when available, rather than a persistent disabled feature. Safe
old-link recovery and distinct empty/error/unavailable states remain required.

### Does this follow modern best practices?

The [recent D13 primary-source review](phase28-d13-regional-map-decision.md#evidence-and-limits)
supports one reversible control, truthful feedback, accessible list/map navigation
and minimal setup. It does not establish a universal default. The strongest
alternative, automatic availability when qualified, reduces setup but was not
selected. No fresh usability study or conversion result is claimed.

### Does this fit Asym's existing repo and product direction?

Yes as planning intent: use the current settings and permission owners, approved
public-source projection and shared Base UI/base-maia design. No parallel policy
store, location directory, map provider or component system is introduced.

### Should we adjust the recommendation?

**Accept.** Record the selected Off default without another ratification question.
The safety and feedback requirements preserve the selected behavior; they do not
create additional product settings.
