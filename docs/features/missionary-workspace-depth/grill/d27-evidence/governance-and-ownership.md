This independently reviews the founder's Q27 A selection: Maya may deliberately resume her own eligible retained preparation after returning, with useful flexibility and no needless complexity. ## Recommended exact decision

> **D27 — Deliberate resumption of eligible own retained preparation.** A returning missionary may find, review and deliberately include selected preparation they originally authored in their current work, when the organization permits that purpose and the current source/history rules admit it. This is limited to the same Tenant and qualified original ministry context. It establishes no automatic access from login, email, authorship, role, old membership or restored data. Exact current history authority is required before any earlier body, snippet, count, search result or preview is disclosed.
>
> Resume uses the same preparation identity and preserves original author, origin, supplied assertions and lawful provenance. Its durable business effect is explicit inclusion in the missionary's exact current working context; it is not a replacement contact, copied note, new read grant, restored membership or new task. Reuse the preparation owner's existing assignment/inclusion mechanism where qualified. The action must not create a second workflow ledger or another Active/Archived status.
>
> Earlier preparation does not all reappear in current work merely because the missionary returns or history becomes readable. Deliberate inclusion and access are separate. Existing Active/Archived working state remains intact. For an archived item, the existing, clearly labeled **Return to active prospects** action may combine current-work inclusion and D4 return in one authorized transaction; review alone changes neither.
>
> Resume does not restore earlier sharing, staff/coach access, consent, subscriptions, provider connections, scheduled messages, reminders, managed-work enrollment or completed/cancelled obligations. Contact assertions retain their age/provenance and are not newly verified. Current source restrictions and retention still apply. Held evidence is not automatically a readable body; purged or irreversibly anonymized content cannot be recovered by this feature.

This is a proposed bounded correction to A. “Full flexibility” means useful permitted discovery, selection, ongoing edits and archive/return within this source. It does not mean cross-tenant transfer, successor access, a mutable author, bypassing retention, returning all records by default, a general recovery product or a second permission engine.

## Durable Resume meaning: choose inclusion, not navigation alone

A pure navigation action can open a retained record but cannot persist which earlier items Maya deliberately chose for current work. Inferring that selection from `last_viewed_at` would make reading secretly change workflow; enumerating all old Active entries after a new grant would skip deliberate selection. Both conflict with Q27's small, controlled journey.

The minimal permanent meaning is **current-work inclusion of the existing preparation identity**. Its required invariants are enough; this note does not freeze a new table, column or event vocabulary:

- Original source ID, author identity and origin Tenant/ministry/membership provenance remain immutable to the ordinary command.
- A current-work association records the exact currently authorized working context and its participation/admission generation. An association from an ended participation does not become current solely because the same membership row is reactivated.
- There is at most one current inclusion for the same preparation/context. Retry or two tabs resolve that same business effect. A later genuine new return is a distinct source transition, not replay of an old acceptance.
- Association is a query/work-organization fact, never an access grant or evidence the source content is still retained. Current history/source checks remain necessary after inclusion.
- Active/Archived is still the preparation source's one working-state axis. Resume does not introduce resumed/pending-resume/completed-resume workflow states users must manage.
- A normal edit to an included entry uses the source's existing current command. No separate resumption editor, copied contact list or duplicate live draft is introduced.

For an eligible earlier Active entry, **Resume preparation** can include it in current work. For an archived entry, Maya can read permitted earlier content without changing state; **Return to active prospects** can clearly perform inclusion plus D4's existing state transition once. A user who only wants to review archived context should not be forced to activate it. Core ordinary work remains available if recovery is disabled or unavailable.

## Verification obligations for the integrated review

The review should require real owner-command/role/source proof of: original author versus reused email; same valid participation versus ended/recreated membership; all before/after source-policy orders; list/count/search/preview uniformity; current inclusion versus history read; two simultaneous Resume requests; lost response after commit; archived combined return; source restriction/erasure during review; retained audit without body; same-user context/cache changes; restore without effects; and independent ordinary/source tasks remaining unchanged.

A positive test must demonstrate one complete useful return: Maya receives the separately qualified current history right, finds only eligible retained own preparation, selects one original entry, sees its current inclusion acknowledged, edits once through the source, and can still find lawful archived context without activating everything. Negative tests must prove staff/coach/successor/unrelated missionaries gain nothing from administration, departure or return.

This note does not execute those future source tests. It adds no new database experiment, retention duration, runtime guarantee, arbitrary total-record cap, provider dependency, governance approval queue or formal artifact. Exact source implementation and lawful retention qualification remain activation prerequisites; the user has selected the product direction, not certified those prerequisites.
