## Default judgment

The UX note correctly warned against inventing activation/defaults from a vendor
example or silently enrolling users during this research session. Root and
governance review resolve the proposed default explicitly: On only at exact
qualified Live activation, preserving explicit tenant Off and current audience
qualification. No source visibility or recipient membership is granted by this
choice. This remains a proposed product amendment, not a separately selected
founder preference or current installed behavior. The independent note is
preserved rather than rewritten to hide the trade-off.

## Alternatives rejected

- Automatic review for this narrow event: founder selected A; other independently
  required source work remains.
- Hiding source facts with the notice toggle: conflicts with financial truth and
  current permission boundaries.
- Tenant thresholds, per-missionary exceptions or a channel/task matrix: no need
  established; the existing exact optional slot is sufficient.
- Purging all history on Off: more state, surprising loss of context, no benefit
  required for stopping new attention.
- Extending the old pledge row or restoring browser task grants: conflicts with
  native source ownership and authorization qualification.
- One task forever per missed occurrence: prevents distinct human work; use
  same-intent recovery instead.
