# D33 analytical counterexamples: optional missionary receipt reports

**October 18, 2026 UTC.** The selected direction is an optional missionary entry
point into P15's existing actual offline-gift intake. The organization starts
Off and may disable the entry point. This is documentary pressure testing of
intended contracts, not a runtime, SQL, custody or financial verification.

The strongest remaining risk is treating the setting as an intake lifecycle.
Off must stop new missionary report acceptance without deleting accepted facts,
making already-posted money fail, or stranding real handling. Report, read,
correct, route and finance actions retain their independent current authority.
P15 remains the only owner; P28 adds no local donation row or replacement inbox.

## Important ordered schedules

1. **Disable wins:** read On → Off accepted → report acceptance checks current
   policy → terminal no-effect rejection. Re-enable does not execute that key.
2. **Report wins:** report/evidence/required intent/receipt accepted → reply lost
   → Off accepted → same-key recovery returns the accepted minimal result if
   currently disclosable. Finance continues the same intake.
3. **Old actual receipt, new intent:** check actually received while Off → a
   submission is rejected → organization enables reporting → Maya deliberately
   reviews current facts and submits a new key → P15 may accept the old receipt
   assertion now, preserving both times and the prior no-effect outcome.
4. **Correction wins:** material revision advances → delayed resolution names old
   revision → no false current correspondence; already-posted money persists.
5. **Resolution wins:** exact lineage accepted → material correction follows →
   preserve the recording event and route the disputed correspondence; no repost.
6. **Context changes:** accepted response is delayed → Tenant/actor/access changes
   → suppress stale private rendering and reauthorize recovery.

These are required outcome schedules, not executed concurrent transactions.
The narrow new model consumes owner facts and illustrates selected schedules;
it cannot qualify the actual P15 producer, RLS, locks, durable work delivery,
retention or browser behavior.

## Source anchors and limits

- [P15 D1](../../../../prds/sitestacker-parity/phase-15-offline-gift-batch-entry.md#d1-one-front-door-for-offline-money): one money commit path and the existing operational intake extension.
- [P27 intake contract](../../../../prds/sitestacker-parity/phase-27-donor-development/requests.md#gifts-awaiting-finance-exact-p15-owner-extension): independent physical/financial facts, honest unknowns, exact continuation and recovery.
- [P27 requirements F56–F74](../../../../prds/sitestacker-parity/phase-27-donor-development/requests.md#d25-requirement-contract): separate authority, source resolution, atomic local effects, retry, minimal protected data and release proof.
- [P27 D25 review](../../../donor-development/grill/phase27-d25-adversarial-review.md): attributed reported receipt is not a verified continuous custody audit; no photo, signature or routine second approver is introduced.

Most safeguards already belong to P15/P27; D33 must qualify the missionary
consumer and setting at those seams. Default-Off, terminal Off-rejection keys
and independent continuation while Off are the specific D33 temporal rules
recommended by the root review. This note selects no new table, universal
custody process, valuation, file upload, communication or financial power.
