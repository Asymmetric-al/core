## Independent source and model checks

The root freshly opened the official
[Reliant Check Giving FAQ](https://solomon.reliant.org/display/public/mtdmanual/Check%2BGiving%2BFAQ),
modified May 20, 2026. It confirms that missionaries can receive checks before
forwarding them to the organization and encourages direct delivery. This
corroborates the job, not a universal ministry policy. Its payee, handling,
currency and tax guidance is not imported into Core.

The root also opened [MPDX manual donation entry](https://help.mpdx.org/article/188-adding-donations-manually),
last updated December 22, 2020. It warns that manual entry alongside donation
synchronization produces duplicates. This is dated primary documentation of a
failure mode, not a current authenticated product test or a reason to copy its
donor-number/currency defaults. Core avoids the separate financial entry.

The root read the original and revised model, then independently executed only
the revised D33 script. [Reproduction](root-reproduction.json) is byte-identical:
**15 counterexample families, 5 controls and 91 outcome assertions**. Initial
script/result/readme hashes match the exact preserved copies. The model assumes
atomic source boundaries and qualified input proofs; it does not prove actual
transactions, RLS, clocks, providers, full duplicate canonicalization, retention,
browser behavior, upgrades, capacity or usability. See [model limits](model-readme.md).

Current narrative notes use repository formatting. The captured initial model
readme is deliberately excluded from formatting changes so its original bytes
and hash remain evidence; scripts and deterministic model JSON are likewise
preserved. Documentation verification checks those hashes without rerunning them.

## What remains a real qualification duty

No unresolved product question is hidden behind the simple setting. Engineering
must qualify the existing source/reporting/action/projection/finance/task seams,
actual policy/authority fences, old/new database mutations and all alternate paths,
source-shaped workloads, restore/migration and composed accessible user journeys.
Those gates are exact C01–C24/P01–P36, not permission to invent a local substitute.
No source runtime is established by this decision or model.

The statement that most tenants will not want the feature is the founder's
product rationale for Off. No fabricated survey, adoption rate or missionary
feedback is claimed. Numeric operating triggers inherit governing requirements
or are explicitly proposed; workload/latency ceilings require measured release
evidence. No irreversible application action, formal spec/ticket, live mutation,
external message, earlier verifier or prior-phase model was executed.
