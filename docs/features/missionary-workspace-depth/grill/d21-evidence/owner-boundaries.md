# D21 owner boundaries — explicit qualification without history-only attention

Research date: October 17, 2026. Founder answer recorded for October 17 in
Asia/Bangkok. **A is selected; the detailed amendments below are recommendations,
not separately ratified.** D19 and D20 are ratified. This is research only: no
formal owner, OpenSpec, application, schema, dependency, permission, ticket or
external service was changed. No Q22 is introduced.

## Finding and minimum permanent path

Accept A with the bounded clauses below. Its useful restriction is on the
**reason for creating automatic P28 unusual/special-gift attention**: a comparison
with earlier giving cannot alone establish that reason. It does not prohibit
history, source-derived facts, legitimate staff purposes or human judgment.
Required qualified first-support, special/above-commitment, fulfillment and
permitted recurring work remain. A does not itself finish qualification of the
remaining special-gift criteria.

Keep the existing P28 purpose producer, source-owner evidence and shared
Independent follow-up task. Do not add a detector, an intent registry, a second
task ledger, a universal no-history rule, a new tenant switch, or a classifier
approval queue. The strongest alternative is the rejected additional, explained
history-comparison review purpose: it might notice changes for supporters
without commitments, but its value and error rate have not been established.
Manual-only replacement is not an adequate alternative to already-required
native tasks.

### Manual follow-up and native work

The ordinary gift action should use existing task lookup and commands:

| Situation                                                                  | Smallest truthful behavior                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An authorized, compatible native follow-up already covers this gift/action | Offer its existing task or related action. Do not create another copy merely because the entry point says Add follow-up. Opening it creates neither an outcome nor a newly qualified member.                                                                                                                                                                                                                                                                         |
| No qualified native obligation exists                                      | A deliberate ordinary manual task may reference the permitted gift. Its creation records human intent, not special-gift qualification, a financial conclusion, native member admission or handled coverage.                                                                                                                                                                                                                                                          |
| Native qualification arrives while a compatible manual task is pending     | The source still proves eligibility. The existing task owner may reuse the task only when exact intended action, source, subject, current responsibility and completion authority are proved; attach the exact qualified membership through its ordinary authoritative command and retain the original human intent. Otherwise preserve both distinct obligations or route a genuine conflict through the qualified owner.                                           |
| A generic manual task was already completed                                | Neither its title, gift link nor Done status proves that the later native purpose was handled. Do not silently suppress the native obligation or blindly ask the user to redo an evidenced action. Any recognition of prior coverage needs a qualified current owner action with attributable evidence of exact intended gift/purpose/outcome, preserving original completion and later qualification/correction lineage. No backdated source admission is inferred. |
| The other task is inaccessible or incompatible                             | Do not reveal its existence or grant access through a duplicate diagnostic. Ordinary independently authorized manual work retains its meaning. The source owner resolves its own native responsibility/coverage without guessing that either task satisfies the other.                                                                                                                                                                                               |
| Native admission, manual creation or completion race                       | The existing source/task acceptance boundary serializes exact intent association and outcome coverage. One compatible intended obligation is not duplicated because commands used different entry points; a different deliberate human undertaking is not discarded because it references the same gift.                                                                                                                                                             |

These are logical conditions in existing owners, not a requirement for new tables
or a generic matching service. A free-text title, task type, same donor, gift
reference, temporal proximity or notification read cannot prove identical
purpose or completion. Where the ordinary command captures an exact deliberate
gift-related action, preserve that context through the existing task/source
contract; otherwise do not infer it later with text matching or AI.

Reuse does not expand the action's scope to every member of a D20 group. A human
reviewing only G1 cannot silently complete G2, later arrivals, a first-support
purpose, a receipt or an independently promised call. Existing D20 reviewed-set
and current-authority rules still govern.

## Corrected decision candidate

> A — Create automatic P28 special/above-commitment follow-up only when its
> qualified source criterion establishes that purpose. A change relative to a
> supporter's earlier giving is not, by itself, such a criterion. Keep permitted
> history useful as context and retain deliberate ordinary follow-up.
>
> This does not replace required native gift work, restrict special gifts to
> people with commitments, authorize a generic special flag, or prohibit source
> calculations and history needed by other qualified purposes. It creates no
> extra tenant toggle, financial rating or communication authority.
>
> Use the existing shared task and exact source-purpose coverage. Reuse compatible
> authorized existing work where its intended action is proved; manual creation
> or Done does not itself qualify a gift or silently consume a native obligation.
> Preserve deliberately accepted human undertakings and truthful history when an
> unsupported solely automatic reason is retired.

## Material concerns — eight dimensions each

Severity and likelihood are conditional design-risk judgments, not measured
incidents or predictions of fundraising outcomes.

### O01 — A becomes a ban on all history or required native work

- **What:** Interpret Explicit facts only as no derived facts, no history, no
  tasks for uncommitted supporters, or manual-only stewardship.
- **Why:** This discards required first-support completeness, legitimate source
  calculations and already-selected native workflows.
- **Severity:** High product/source correctness.
- **Likelihood:** Plausible because the shorthand is broader than the question.
- **Evidence:** S01–S02, S07–S09; the question concerns the comparison alone.
- **Answer impact:** Keep A; state the exact excluded purpose and preserved owners.
- **Permanent fix:** Admit existing qualified source purposes while rejecting the
  additional history-only attention reason; do not add a general history switch.
- **Exact proposed clause OC01:** “D21 SHALL prohibit automatic P28 unusual/special-
  gift attention whose sole qualifying reason is comparison with prior giving.
  It SHALL preserve authorized historical context, D19 history qualification,
  source-derived financial facts, P16 permitted suggestions/attention and other
  independently qualified purposes. It SHALL NOT mean commitments-only or
  substitute manual work for required native gift work.”

### O02 — A stored flag launders rejected inference into an explicit fact

- **What:** A worker, import, rule, staff field or AI writes Special, then a
  downstream producer treats that persisted value as independent evidence.
- **Why:** Persistence does not change the origin or authority of an inference;
  a label can hide the exact prohibited history-only trigger.
- **Severity:** High scope/integrity; potentially high privacy.
- **Likelihood:** Likely without an origin-aware source contract.
- **Evidence:** S01, S08–S10; source qualification and application authority are
  closed and versioned, not established by an arbitrary flag.
- **Answer impact:** Explicit means owner-qualified meaning and evidence, not raw
  versus derived or database-stored versus computed.
- **Permanent fix:** Validate the exact native criterion and provenance at source
  acceptance and every reached caller; distinguish human judgment from finance.
- **Exact proposed clause OC02:** “An explicit qualifier SHALL be a qualified
  source criterion with exact purpose and evidence, not an arbitrary stored flag,
  import tag, missing match, task label or model output. A history-only inference
  SHALL NOT become eligible by being persisted or relayed. Authoritative folds,
  recognition and exact commitment applications remain valid source facts; no
  new special-gift criterion, amount or staff-classification right is selected.”

### O03 — Manual Add follow-up duplicates existing native work

- **What:** Every gift-page click creates a second task, or a broad duplicate
  check blocks an independently meaningful manual undertaking.
- **Why:** The same intended action becomes repeated work, while deduplication by
  donor/gift alone can erase a different legitimate purpose.
- **Severity:** High work integrity; Medium friction.
- **Likelihood:** Likely with a generic create-only implementation.
- **Evidence:** S03–S05, S08; task links are pointer-grade and D20 identity is
  purpose-specific, not one task of any kind per supporter.
- **Answer impact:** Preserve the manual escape path but coordinate exact intent.
- **Permanent fix:** Reuse the existing task resolver/action for currently
  authorized compatible work; preserve distinct deliberate human purposes.
- **Exact proposed clause OC03:** “Gift-context Add follow-up SHALL first resolve
  and offer currently authorized existing work for the same proved intended
  action. It SHALL NOT create a duplicate solely because the entry point differs.
  Different intended undertakings SHALL remain distinct. Titles, task types,
  same donor, gift links or temporal proximity SHALL NOT alone establish semantic
  equivalence, completed coverage or rights to another task.”

### O04 — Manual creation/completion silently qualifies or suppresses native work

- **What:** Manual creation marks a gift special; a manual Done flag consumes
  future native coverage; or delayed native qualification blindly duplicates a
  still-pending compatible manual action.
- **Why:** Human planning, financial/source eligibility and task coverage are
  distinct. Either shortcut creates false evidence or redundant work.
- **Severity:** High durable integrity.
- **Likelihood:** Plausible during incremental native adoption or source delay.
- **Evidence:** S03, S05, S07–S09; D20 exact member/receipt rules and P27 evidenced
  multi-obligation outcomes.
- **Answer impact:** Manual work remains available without being a source bypass.
- **Permanent fix:** Existing source qualification followed by exact owner-bound
  association/reconciliation; no automatic retroactive inference from generic Done.
- **Exact proposed clause OC04:** “Ordinary manual follow-up SHALL record human
  intent without admitting native gift-purpose membership or consuming its
  coverage. Later source-qualified admission MAY reuse compatible pending work
  only through the existing task owner with proved exact intended action and
  current source/responsibility/completion authority. Prior manual handling SHALL
  be recognized as native coverage only through a qualified attributable owner
  action proving exact scope/outcome; never infer it from a link/status or backdate
  source admission. Retain original human and later source/correction lineage.”

### O05 — Reuse races or hidden-task checks leak data and alter reviewed scope

- **What:** Concurrent manual/native commands create copies, a hidden-task
  duplicate response leaks existence, or opening a group to follow up on G1
  silently covers other members.
- **Why:** Matching, visibility and completion are separate current checks. A
  helpful task shortcut cannot broaden actor rights or the reviewed gift set.
- **Severity:** Critical disclosure; High work integrity.
- **Likelihood:** Plausible with concurrent staff/source activity or role changes.
- **Evidence:** S03, S05, S08; D20 C06–C14/P16 and current replay limits.
- **Answer impact:** Keep one useful shared task without a per-viewer engine.
- **Permanent fix:** Resolve intent association/coverage at the existing qualified
  acceptance boundary; current filtered presentation and exact reviewed-set action.
- **Exact proposed clause OC05:** “Manual/native reuse and coverage acceptance
  SHALL re-prove current tenant, subject, purpose, source and actor authority
  within the existing owner's concurrency/idempotency boundary. No inaccessible
  task existence, member, count or outcome SHALL leak through duplicate handling.
  Reusing or opening a D20 task SHALL NOT expand the exact reviewed action scope
  or complete other gifts, independent promises or different purposes.”

### O06 — Retiring inferred work destroys a deliberate human undertaking

- **What:** A blanket deletion/Done conversion removes planned calls, completed
  history or P27 next-action coverage when an unsupported automatic reason ends.
- **Why:** An automatic reason can end while a person's separately accepted
  promise remains. Conversely, opening/commenting is not acceptance of a promise.
- **Severity:** High lost work/history.
- **Likelihood:** Plausible if retained data contains such work; not observed here.
- **Evidence:** S05–S08; P27 C27/C28 and D19 C11 explicitly separate these facts.
- **Answer impact:** A requires exact source retirement, not destructive cleanup.
- **Permanent fix:** Inventory source provenance; withdraw only the unsupported
  unresolved automatic reason and preserve lawful human intent/history.
- **Exact proposed clause OC06:** “If reached retained work was created solely
  by the rejected history-comparison purpose, its source SHALL fence further
  automatic admission/actions and withdraw only that unsupported unresolved
  reason with truthful No longer required history. Preserve actual completed
  outcomes and separately deliberately accepted calls/promises through the
  existing owner, on the same task where permitted, and reconcile P27 next-action
  duty to valid work or an owned exception. Read, claim, comment or reminder edit
  alone SHALL NOT create such an undertaking. Unknown provenance requires owned
  reconciliation, not title-based deletion, completion or mass conversion.”

### O07 — Optional workflows, ratings or AI recreate the rejected purpose

- **What:** Native UI hides the detector while a recipe, staff rating derivative,
  scheduled suggestion, notification or newsletter assistant still creates it.
- **Why:** Routing through a different caller does not change the P28 purpose or
  source restriction. Existing staff analysis and AI permissions are narrower.
- **Severity:** High authority/scope; potentially Critical protected-data egress.
- **Likelihood:** Plausible as optional consumers are integrated.
- **Evidence:** S06, S10–S12; D18's prose-only input and P27 missionary exclusion.
- **Answer impact:** Close alternate entry paths without canceling other owners.
- **Permanent fix:** Enforce the source-purpose restriction beneath callers and
  preserve existing P27/P35/AI scope and activation controls.
- **Exact proposed clause OC07:** “Every reached caller of the P28 special-gift
  purpose SHALL obey D21, including native jobs, optional workflows, AI, imports
  and notifications. No renamed suggestion, persisted anomaly or rating derivative
  may create the rejected attention. This SHALL NOT disable separately qualified
  staff analysis, P16 matching, ordinary reports or other source purposes. P27
  ratings grant no missionary projection; D18 newsletter assistance grants no
  financial retrieval, classification, audience selection, task or send authority.”

### O08 — Missing qualification becomes a quiet empty state or policy invention

- **What:** A is called implemented while its explicit native producer remains
  undefined, missing evidence means No special gift, or a default threshold is
  borrowed from posting risk/P35/vendor behavior.
- **Why:** Rejecting one trigger does not establish the remaining eligible cases;
  absence of accessible data is not negative source evidence.
- **Severity:** High missed work/source correctness.
- **Likelihood:** Likely unless qualification gates remain explicit.
- **Evidence:** S01–S02, S08–S10, S12; Q21 preserves the exact producer gate.
- **Answer impact:** Accept A's boundary now, qualify remaining producers before
  their activation without pretending all future phases are prerequisites.
- **Permanent fix:** Source-owned eligible/ineligible/unknown distinctions,
  current narrow owner gates and recoverable materialization/repair.
- **Exact proposed clause OC08:** “D21 SHALL NOT be treated as qualification of
  the required special/above-commitment producer. Before that producer activates,
  its owners SHALL establish exact criterion, source evidence, scope, currentness,
  correction and semantic effect rules. Unknown, denied or incomplete evidence
  SHALL NOT become ineligible, zero, no commitment or special. Manual work remains
  available under its own authority; it neither certifies nor replaces required
  native behavior. Existing E7/C-01 gates remain limited to affected operations.”

### O09 — The restriction adds a framework or gains false release proof

- **What:** Build a parallel intent registry/detection-disable service, scan all
  giving on every task action, or equate a synthetic no-task assertion with actual
  enforcement and usable recovery.
- **Why:** Additional systems add conflicting state without solving the exact
  owner contract; a negative result can hide lost required work.
- **Severity:** Medium maintainability/performance; High false qualification.
- **Likelihood:** Plausible in an overbroad implementation.
- **Evidence:** S03–S05, S08, S12; current/intended/runtime distinction.
- **Answer impact:** Keep the decision small and its proofs exact.
- **Permanent fix:** Existing source/task commands and indexed exact lookups,
  bounded retained-data reconciliation and actual positive/negative path tests.
- **Exact proposed clause OC09:** “Implement D21 through the existing qualified
  source-purpose and shared-task contracts, without a second task/intent registry,
  generic history classifier, new settings service or mandatory human report.
  Use bounded exact source/task lookups and existing repair/audit paths. Release
  proof SHALL cover both rejected history-only admission and preserved qualified
  native/manual work, including races, current access, retained-data retirement
  and truthful recovery. Research notes and isolated fixtures are supporting
  evidence only, not actual Core or user qualification.”

## Falsifiable qualification proofs

1. A larger gift versus prior giving, without another qualified criterion,
   creates zero additional P28 unusual/special attention through every reached
   native/optional entry point. Preserve authorized history display.
2. Persist the same inference as a flag/import tag/model result and replay it:
   no qualifying authority is gained. A genuinely qualified derived source fact
   still works; raw-versus-derived is not the test.
3. Qualified D19 first-support with complete history, explicit special work,
   P16 permitted attention/match suggestions and staff-only opted-in analysis
   remain independent. No missionary rating leakage or automatic donor message.
4. Gift Add follow-up finds an authorized compatible native task: one existing
   task/action, no duplicate, no new member or outcome merely from opening.
5. No native qualifier: create/retry ordinary manual work with exact human
   intent once; zero native qualification/coverage. Its Done is task-only.
6. Race manual creation with qualified native admission in both orders. Proved
   same pending purpose reuses one task; different intent survives separately.
   No title matching, blanket same-gift suppression or lost independent promise.
7. Native admission follows completed generic manual work: no automatic coverage
   inference. Qualified explicit coverage reconciliation, if admitted, preserves
   original outcome/time and later source lineage; unsupported claims conflict.
8. Actor can read the gift but not another task: no existence/count/status leak
   or access expansion. Later revocation, handoff and retry recheck current rights.
9. Reuse a D20 group containing G1/G2 for a G1 action: only exact reviewed
   coverage changes; G2/new arrival/hidden residue and separate obligations survive.
10. Retire a solely inferred open/claimed/commented task reason without marking
    it human-completed. Preserve a separately accepted call and completed history;
    reconcile P27 next-action duty and handle unknown provenance safely.
11. Replay, historical import/backfill, policy deployment and restore do not
    create prohibited historical tasks, repeat handled native effects or revive
    retired inference. Originally live source repair retains its distinct lineage.
12. Actual commands, source adapters, current P12 enforcement, old writers,
    migration/reconciliation, accessible mobile journey and bounded source/task
    lookup behavior prove the contract. No numeric limit, runtime, user benefit
    or test result is asserted by this owner research pass.

No source-controlled predecessor is reopened merely to repair an independent
human task. D20's qualified conditional correction remains its own contract.
No application, database, provider or intended-user experiment was executed here;
only documentary inspection and structural verification of this evidence note.
