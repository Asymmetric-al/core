# D21 evidence — explicit qualification without inferred attention

Research date: October 17, 2026 (Asia/Bangkok). This note pressure-tests the
selected **A — Explicit qualifying facts only** answer. It selects no monetary
threshold, history window, new flag, classifier, financial policy, task engine
or permission. It changes no formal owner document, application or dependency.

**Disposition: accept with required amendments.** Keep permitted giving history
useful. A comparison with previous giving does not, by itself, create proactive
special-gift attention. Required qualified native work and deliberate manual
follow-up continue through their existing owners. The important implementation
boundary is the basis of the effect, not whether the UI calls it a task, badge,
suggestion or “manual” action.

## Repository evidence and its limits

- The [Q21 frontier](../phase28-q21-history-based-gift-attention-research.md)
  asks whether historical comparison itself creates additional follow-up. It
  explicitly preserves qualified special/above-commitment work and does not
  equate “explicit” with a hypothetical staff checkbox. This note follows the
  founder's selection of A without claiming the recommendation amendments
  were separately ratified.
- The [founder brief](../phase28-founder-brief.md:165) requires source-qualified
  first/special/fulfillment/permitted-recurring work, preserved anonymity,
  source-purpose dedupe and truthful correction. D21 cannot satisfy that brief
  by quietly disabling all native gift work.
- Ratified [D19](../phase28-d19-first-support-follow-up-adversarial-review.md)
  requires complete owner-qualified recorded history to establish first support.
  D19 therefore uses historical facts legitimately. Ratified
  [D20](../phase28-d20-grouped-special-gift-follow-up-adversarial-review.md)
  covers exact reviewed source-qualified gift-purpose members while leaving
  special-gift criteria separate. Neither decision authorizes a historical
  anomaly classifier or supplies missing special-gift qualification.
- [P16 F.5](../../../../prds/sitestacker-parity/phase-16-pledges-recurring-commitments.md:1004)
  requires closed application-authority proofs; generic notes, source IDs,
  import flags or evidence strings cannot replace them. History and matching
  amounts may support source-owned matching suggestions, not application
  authority. That **separate staff commitment-matching purpose remains allowed**;
  D21 does not ban the owner's existing operational work.
- [P16 F.6](../../../../prds/sitestacker-parity/phase-16-pledges-recurring-commitments.md:1019)
  forbids inferred prepayment/debt/lifecycle changes. Its
  [M.3 reduction](../../../../prds/sitestacker-parity/phase-16-pledges-recurring-commitments.md:1393)
  can show **Applied above current commitment** without new money. That derived
  label is not a fresh special-gift occurrence.
- [P13 posting-risk review](../../../../prds/sitestacker-parity/phase-13-campaign-designation-contribution-ledger-giving-cart.md:979)
  is a finance risk purpose. Its large-gift threshold is not a stewardship
  criterion by analogy. [DON-03](../../../../prds/workflow-studio/07-core-workflow-catalog.md:1233)
  documents a later same-currency explicit-criteria recipe with unresolved exact
  source binding; it does not select P28's initial rule or prove a deployed
  producer.
- [IG-07](../../../../prds/program-roadmap/integration-guide.md:93) keeps permanent
  effect identity with the effect owner. [ADR-0183](../../../../adr/0183-source-owned-work-projects-into-one-shared-tasks-hub.md:622)
  preserves independent personal work and separate source authority.
- [D20 current-source evidence](../d20-evidence/current-source-and-ux.md) is a
  bounded static inspection of ordinary task and group mechanics, not an
  implemented special-gift qualification service. An existing chart, generic
  task type or an undeclared imported field cannot fill that evidence gap.

These are repository intent/source facts. None proves actual financial-owner
deployment, production permission enforcement, source completeness, user
comprehension or classifier quality. The Q21 note retains primary competitor
comparisons and their access dates/limits; no new competitor trial, interviews,
model calls, financial queries or provider operations were performed here.

## The exact counterfactual boundary

Hold current qualified source facts, original provenance, authority and genuine
user actions constant. Change only nonauthoritative historical comparisons or
context. **Automatic unusual/special-gift attention must not change.** This
includes creating or enrolling a task, adding an attention badge, changing
work priority/default attention ordering, sending a notification or presenting
a personalized “you should follow up” suggestion.

That is narrower and more useful than **history changes cause zero effects**.
An authorized chart can redraw. An explicit user sort can change a report's
order. Source operations may surface an actual integrity problem under their
own established purpose. A correction to owner-certified earlier support may
legitimately change D19 first-support eligibility and its pending work. None is
permission for an unusual-giving comparison to create the declined additional
stewardship attention.

## Exact proposed clauses

**DEC-01 — Declined inference boundary.** P28 SHALL NOT generate unusual/special-
gift follow-up solely from a comparison with the supporter's previous giving.
The prohibition covers task/admission/group membership, unsolicited personalized
follow-up suggestions, notification, attention badge and priority/default work
ordering changes whose qualifying basis is that comparison. Renaming the output
as a review, suggestion, insight, manual-action prompt or source flag SHALL NOT
change its meaning. No second scoring/classification product is introduced.

**DEC-02 — Qualified explicit source.** An explicit qualifier SHALL be an exact
current fact admitted through a qualified owning-domain contract, carrying its
purpose, scope, source occurrence, provenance and applicable rule/revision.
A boolean, tag, memo, import field, source-code label, report column, amount
comparison or user-authored workflow label SHALL NOT independently certify it.
An upstream flag derived solely from the declined historical comparison SHALL
NOT bypass DEC-01. D21 SHALL NOT introduce a generic “mark special” control or
invent a source rule to make an unavailable producer appear qualified.

**DEC-03 — Missing, unknown and known absent.** The current owning source SHALL
distinguish an unavailable/unknown commitment or history from a proved absence.
An empty missionary projection, unlinked payment or incomplete import SHALL NOT
establish **No commitment** or **First support**. Even a source-certified absence
of a commitment SHALL NOT become a zero expected amount that independently
classifies every positive gift as extra support. No-commitment supporters remain
eligible for other independently qualified native purposes and ordinary manual
follow-up under their existing rules.

**DEC-04 — Preserve established source purposes.** D21 SHALL preserve D19's
qualified first-support history, D20's reviewed grouping, required qualified
special/above-commitment/fulfillment/recurring work and source-owned corrections.
It SHALL NOT ban every history-dependent feature or make native tasks depend on
having a commitment. Existing finance review, commitment-matching suggestions,
source-integrity repair and staff-only rating purposes retain their own scope,
permissions and qualification; they SHALL NOT be copied into missionary
stewardship attention merely because they already exist elsewhere.

**DEC-05 — Context remains useful and truthful.** Authorized history, source
dates/amounts/currencies, charts and deliberate report filtering/sorting may
remain available as context. Unknown values SHALL remain unknown. History-only
context updates SHALL NOT silently change automatic special-gift attention under
DEC-01. A permitted historical chart SHALL NOT label a person unusually generous,
extra, lapsed or needing contact without its separately authorized exact purpose.
Plain ordinary **Add follow-up** stays available under existing permission without
an algorithmically selected donor recommendation.

**DEC-06 — Deliberate manual work.** A user may create an ordinary task after
looking at permitted history. That action records human task intent only; it
SHALL NOT certify a financial special-gift fact, native admission or gift-purpose
coverage. When exact qualified native work already exists and is accessible,
the source task command SHALL resolve/reuse that intended work instead of creating
a duplicate. The interface SHALL NOT reveal inaccessible work through duplicate
messages, counts or links.

**DEC-07 — Manual/native reconciliation.** A later qualified source arrival may
reuse compatible pending manual work only when the owning task contract proves
the same intended action, exact source scope, responsibility and current authority.
Similar title, date, supporter, gift link or generic manual Done SHALL NOT prove
native coverage. Recognizing prior handled scope requires explicit authorized
coverage reconciliation with retained lineage; it SHALL NOT backdate source
qualification or invent an interaction. Distinct authorized purposes stay
distinct. Current unresolved conflicts remain recoverable through the source
owner without creating a generic automatic task-merging engine.

**DEC-08 — Prospective policy and provenance.** Enabling or changing a source
policy, importing history, recomputing charts or changing a reporting definition
SHALL NOT turn historical evidence into a new live special-gift occurrence or
retrospective task flood. Preserve original occurrence provenance, activation
cohort and permanent source-purpose coverage. Originally live held work may
qualify after owner repair under the existing D19/D20 conditions; historical
repair does not become live merely because its processing time is current.
Existing source-qualified corrections may invalidate or repair affected pending
work while preserving performed work. A generic ban on all correction events
is not the implementation of this rule.

**DEC-09 — Qualification before activation.** Required explicit native producers
SHALL have exact source criteria, owner bindings, no-commitment behavior,
correction semantics, permission and acceptance evidence before their affected
profile activates. D21 neither supplies those missing criteria nor removes the
required native outcome. Unqualified cases fail closed with an authorized
source-repair path; independent qualified profiles and manual work remain useful.
Optional workflows SHALL honor the same purpose/source boundary and SHALL NOT
reintroduce the declined comparison through another producer name.

## Strongest permanent path forward

Record the narrow purpose decision and DEC-01/02/04 before using “explicit” in a
spec. Then bind the required source criteria under the financial/recognition/
commitment owners, preserve D19/D20 lifecycle and duplicate coverage, and qualify
the actual native producer. UI work should expose one ordinary manual follow-up
action and permitted history, using existing task ownership; no new inference
settings, donor score, historical alert toggle or “mark special” control is
needed for this answer.

Prove the boundary through source-qualified integration tests, not only by
counting newly inserted tasks. The acceptance matrix must observe task membership,
notifications, badges, priority and unsolicited suggestions. It must also prove
the positive retained cases: D19 first support, independently qualified special
gift, useful charts and manual work. A negative test that disables everything
would satisfy the wrong requirement.

No identified concern is deferred to monitoring instead of enforcement. A useful
residual invariant monitor is **any automatic P28 special/unusual-gift attention
whose only qualifying basis is historical comparison or unqualified metadata**:
threshold **one confirmed occurrence**; owner **P28 source-integration owner**;
response **pause the affected producer/surface, preserve audit evidence, remove
invalid unhandled attention through its owner and requalify all affected paths**.
The threshold is a proposed invariant policy, not an observed failure rate or
permission to launch a known bypass.

## Executed counterexamples and limits

Ran [counterexample-probe/probe.py](counterexample-probe/probe.py) with Python
3.12.14: **18/18 finite counterexamples reproduced**. Exact retained observations
are in [results.json](counterexample-probe/results.json).

The examples calculate contradictory outputs or show two worlds with identical
visible values but different authoritative meanings. Arbitrary ratios and
thresholds in D01/D16 are deliberately unsafe demonstration inputs, not proposed
rules or evidence-backed cutoffs. The flags/provenance cases demonstrate why
boolean equality is insufficient; they do not implement a qualifier or prove an
actual forged-source path exists in Core.

No runtime attention producer, Supabase/Postgres behavior, financial policy,
provider, model, user journey, accessibility or workload was tested. Zero-effect
requirements are proposed release obligations, not claimed production outcomes.
The probe does not certify the replacement solution merely because its finite
counterexamples pass. Real owner integration and independent positive/negative
journey evidence remain required.
