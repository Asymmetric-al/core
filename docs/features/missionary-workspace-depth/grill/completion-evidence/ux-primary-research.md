# Phase 28 completion — fresh primary research and joined UX evidence

Reviewed **October 18, 2026 (Asia/Bangkok)** against Core
`9cada8f3d8ab59db391d3fd20df77fcadeb09813` and its research working tree. This is a
new independent research note. It does not ratify reviewed amendments, publish a
formal specification, implement UI or establish that a production journey works.
Earlier evidence and verification programs were not modified or rerun.

## Finding

The selected direction can support a complete native missionary workspace without
another speculative feature choice. However, the existence of a decision for
each feature does not prove that the whole job is complete. The most material UX
work is now at the boundaries: finding useful work, recording what actually
happened once, seeing the resulting next step, recovering an interrupted action,
receiving an issue as a donor, changing the correct preference, and reviewing a
deliberately shared summary as a coach.

The [founder brief](../phase28-founder-brief.md) already requires these outcomes.
The [post-D41 synthesis](../phase28-post-d41-coverage-synthesis.md) identifies the
main selected capabilities and important owner gates. This fresh review adds
concrete joined journeys and falsifiable UX proof. It does **not** claim that
every seam below is absent from every decision packet. Several are well specified
individually, especially D7's sending and preference boundaries. Their composition
must remain visible in design, owner reconciliation and release evidence.

The strongest alternative is to ship a simpler disconnected combination of
contact list, task list and newsletter link, with staff training explaining the
handoffs. That reduces initial screen work but transfers reconciliation and
duplicate entry to missionaries and staff. The permanent path is to compose the
existing authoritative actions in context, with one truthful result and an
obvious next action. This does not require a workflow builder, a second CRM, a new
notification center or additional mandatory settings.

## A complete, simple experience

### 1. Staff configure a usable workspace

Keep configuration in the existing domain's settings and permission surfaces.
Each selected optional capability needs a clear name, current effective state,
who can change it, and a short explanation of what turning it Off changes. Show
the feature's actual prerequisites and current source qualification only where
they affect setup. A switch cannot pretend to activate an unqualified source.

Do not add a generic Phase 28 master switch, per-person exceptions where the
selected decision chose an organization-wide setting, or a settings page with
every dependency exposed. The combined-follow-up choice remains one
organization-wide choice. Missionary gift reporting retains its selected initial
Off state. Other features retain their own selected defaults and approval status.

Off is not one universal lifecycle operation. Existing intake must still reach
Finance; accepted sends and sent history retain their actual status; stopping
new sharing cannot silently erase required business history or restore revoked
access; turning off an optional guide does not block ordinary work. Each existing
owner specifies its exact behavior. Configuration help should explain only the
consequence relevant to that control.

Staff need an effective-permission view through the existing access-management
pattern, plus qualified preview where already available. Do not introduce
impersonation or expose Maya's private preparation to help an administrator
understand a setting.

### 2. Maya arrives and finds the next useful action

Use the existing workspace home and task surfaces. Put actual due work first,
with a short reason, responsible person, meaningful date and current permitted
action. Show informational financial changes as context, not fabricated tasks.
Preserve filters and place when returning from a record. Empty states distinguish
no work, no filter matches, unavailable data and unavailable access.

If the tenant offers a starting guide, it is a discoverable optional aid with
usable resource/action links. Maya can skip and return without losing access to
ordinary work. A guide must not be the only way to discover contacts, tasks,
appointments or newsletters. A resource that becomes unavailable needs truthful
feedback; it is not a failed compulsory lesson.

Possible contextual copy, subject to exact source state:

- **“No tasks match these filters.”** with the ordinary clear-filter action.
- **“You're up to date on this list.”** only when the list is actually complete;
  never substitute it for failed loading or withheld work.
- **“Starting guide”** with **“Use these suggestions whenever helpful.”** when the
  guide is offered; no mandatory progress gate.

### 3. Contact, referral and appointment become actual relationship work

Search and detail stay within current permitted scope. Maya can prepare, use a
permitted contact method, plan an appointment and return to the same contextual
work item. Native work remains usable without calendar or email connections.
An expired referral shows the already selected limited history and authorized
continuation route; a date change does not manufacture contact permission.

The crucial handoff is **intention → actual outcome → optional next step**.
Opening a dialer, copying an address, launching mail or checking a task is not a
conversation, sent message or donor reply. A compact contextual outcome action
can offer supported results and optional context, then an optional next action.
The source determines which results exist; this research does not prescribe a
new universal enum or mandatory log.

Examples of honest user language are **“Record outcome”**, **“Attempted contact”**,
**“Conversation completed”**, **“Reschedule”** and **“Add next step”** where those
meanings are supported. A normal task can be completed without falsely creating
an interaction. Cancellation and deferral retain their own meaning. An attempted
call must not advance a Request, fulfill a commitment or count as a completed
conversation.

When one deliberate action is allowed to record activity and satisfy a task,
show that combined consequence before acceptance and return one source-backed
result. The implementation must define its atomic boundary or explicit partial
result/recovery; the UI cannot imply both effects succeeded if only one did. A
new task is optional unless an existing source invariant requires next work or an
owned actionable exception. Do not force Maya to invent a date to dismiss a form.

### 4. A gift becomes appropriate stewardship once

Qualified gift/commitment facts appear in the existing follow-up context. Keep
the factual reason, applicable source, currentness and available action together.
The selected organization-wide compatible-grouping policy changes presentation
and handling, not the identity or completion evidence of each purpose.

One real interaction can satisfy multiple eligible purposes when the selected
rules allow it. The result explains which purposes were handled and which remain.
It must not imply a tax receipt, settled money, receipt by the donor or satisfaction
of another purpose. Refunds, attribution corrections, anonymity and changed
eligibility update the reason through its source rather than silently deleting
the actual historical interaction.

For D40's exact case, show the confirmed missed occurrence and currently scheduled
next occurrence with correct source context. **“Add follow-up”** is deliberate;
an informational notice does not become a completion obligation. Other qualifying
recurring conditions keep their independently required work. No added amount
threshold, urgency algorithm or automatic donor message is needed.

### 5. Maya sends an issue; the donor controls the right preference

The complete journey includes the recipient's experience, not just successful
composition. A permitted writer can draft, resume, review accessible media,
preview the issue, inspect permitted recipient/suppression results, deliberately
authorize that issue and understand its actual result. The native print path is
part of the selected job, with its own accepted output and truthful handling;
printing is not evidence that a letter was mailed.

D7 already distinguishes source acceptance, unresolved outcome, partial dispatch,
stopping remaining work and delivered-provider status. Compose these states in
the same issue detail. Preserve draft/recovery access only while it remains
authorized. A failed refresh after accepted sending must not invite a fresh send.

Recipient-facing language names the actual purpose and sender, for example
**“Stop newsletter emails from [approved ministry name]”** when that is the exact
withdrawal scope. It must not say **“Stop all emails”** if receipts, personal
communication or another independently selected purpose remain. A confirmation
can explain the applicable effect without showing a full email address in the
URL or exposing other subscriptions to an unauthenticated visitor.

Prove the valid combinations of public Page display, post notifications and
native newsletter preference required by D7. Do not add a fake daily/weekly
frequency selector to a deliberate-issue product. Known overlap must be explained
within existing purpose rules; it cannot be hidden by a new generic dedupe engine
or resolved by silently unsubscribing the donor from something else.

No account or donation is needed merely to complete the qualified exact
unsubscribe. Newsletter opt-out does not establish permission for a personal
solicitation; personal contact checks still apply. Conversely, independently
governed financial/transactional messages must not be described as a failure of
newsletter withdrawal.

### 6. Coaching remains a useful, bounded destination

Maya can choose eligible check-in context, selected targets or selected next-step
summaries, see the recipient and permitted period/scope, and share deliberately.
The invited coach's view is read-only and useful on its own: what was shared,
the period, currentness, any meaningful unavailable status, and the scope of a
next step. No donor drill-down, full task record, private message body or implied
finance access is introduced.

The same ordinary task remains Maya's update point. An approved coaching
description is not permission to publish later raw task edits. Questions remain
optional, and activity targets remain useful privately without a coach. A coach
being removed, a share ending or a source becoming ineligible changes current
access consistently; recovery must not reveal formerly permitted values.

The end-to-end proof must include Jordan's successful read and the loss of that
read after revocation. Showing Maya a successful Share button alone does not
prove the coaching job.

### 7. A phone interruption does not create a second effect

The ordinary responsive website must complete the job, including errors,
recipient review, preferences and recovery. Do not add an app-download dependency
or claim offline operation without a qualified design. A poor connection may
preserve an authorized draft, but must not automatically replay a send, sharing
grant, financial confirmation or contact correction.

Use distinct truthful feedback:

| Situation                                      | Useful behavior                                                                                                                                                                 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mutation definitely rejected before acceptance | Explain the correctable problem near the field/action; retain only authorized draft values.                                                                                     |
| Outcome not known after interruption           | **“Checking whether your changes were saved…”** or the action-specific equivalent; resolve the original operation, with an explicit unresolved state if checking cannot finish. |
| Source accepted; refresh failed                | Preserve accepted status and offer refresh; do not show a new-send or duplicate-create recovery as the primary action.                                                          |
| Access changed while editing                   | Reject the stale action, remove newly forbidden content and explain unavailability without disclosing hidden data.                                                              |
| Another actor changed the source               | Show the currently permitted conflict and review path; no silent overwrite.                                                                                                     |
| External account disconnected                  | Keep independent native work available; explain the affected integration action locally.                                                                                        |

Use shared Maia controls, restrained semantic status colors, readable spacing and
text labels. Preserve keyboard/focus behavior and programmatically announced
status. Core's mobile target guidance is 44px; do not misstate this as WCAG's
universal minimum. Verify 320 CSS-pixel reflow and equivalent zoom, not just a
device screenshot. Names, address order, phone formats, localized dates and time
zones follow qualified source representation, without Western-only mandatory
fields, guessed values or device-clock authority.

## Proof, prioritization and evidence limits

First preserve the selected decisions and reconcile the explicit approval-status
exceptions. Then resolve the source-owner conflicts already listed by the
synthesis; no amount of UI polish can supply missing financial, consent,
preparation or disclosure authority. Next produce a joined storyboard and
acceptance map using the journeys above, with each mutation/read assigned to its
actual owner. Finally exercise those journeys against qualified sources and
representative users before claiming release readiness. Safe unrelated native
work should remain usable while a particular effect is unqualified.

A proportionate formative study should ask an authorized missionary, tenant staff
member, invited coach and a newsletter recipient to complete their relevant jobs
and explain the outcome. Include a new user, a returning user and a mobile user
with an interrupted connection. These describe recruitment and tasks to verify,
not performed research or fabricated ministry needs. No claim is made that this
small study alone proves all tenant configurations or populations.

Record successful completion without assistance, mistaken outcome beliefs,
unnecessary repeated entry, navigation/time, abandoned steps and recovery success.
Set quantitative speed/navigation budgets from the representative baseline and
existing product targets; do not invent a universal number of clicks or completion
time. Any observed belief that an attempted call was completed, a checkbox sent a
message, newsletter withdrawal stopped every purpose, or a coach may inspect raw
donor records is a blocking interpretation defect for that journey. Any actual
unauthorized disclosure, duplicate durable effect or consent violation blocks the
affected release independently of usability scores.

These are release proof gates, not risks deferred to monitoring. Post-release
monitoring, if adopted by the root synthesis, needs its own named owner, signal,
threshold and response. This note does not substitute an unowned “watch usage”
recommendation for the proof above.

**Verified external facts** are the public documented behaviors in the table.
**Repository facts** are the selected scope, explicit source boundaries, UI rules
and proof obligations cited here. **Reasonable inference** is that explicit
outcomes, contextual next work and purpose-named preferences reduce opportunities
for confusion; their effectiveness in Asym remains to be observed. **Product
judgment** is to finish these handoffs with existing actions and controls instead
of adding another generic workflow layer. **Unresolved evidence** includes actual
qualified runtime behavior, representative usability results, measured performance
and the owner-policy rulings listed in the coverage synthesis.

No external example justifies reopening optional guide completion, automatic
future newsletter sending, general inbox synchronization, full-history migration
or an excluded contact feed merely to resemble another product. The concrete
impact of this research is a stronger definition of finished: the intended person
can enter, complete, understand and recover the whole permitted job, and each
receiving person sees exactly the authorized result.
