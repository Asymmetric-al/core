# D25 — Native coaching questions: owner boundaries and required amendments

Research date: **October 17, 2026 UTC**. Research only. The founder selected
**A — Optional organization-provided check-in questions**. This selection does
not itself ratify the detailed clauses below, establish a deployed service, or
authorize a formal PRD, ADR, OpenSpec, issue, schema or application change.
D24 and its amendments are ratified; its continuing numeric disclosure remains
separate from written check-ins.

This note inspects governing intent and reuses the clearly identified D24 static
census. It does not run a new application/runtime/database/provider test, inspect
hosted grants, interview users, or claim that a prompt/check-in service exists.
The earlier Q25 research preserves the question as it was asked; the parent's
current founder answer controls over that note's original unanswered status.

## Principal conclusions

1. **A is a bounded native P28 extension.** Qualitative check-ins already belong
   to the accepted coaching job. The newly chosen addition is organization
   management of optional questions, not a new reporting obligation or a new
   survey platform.
2. **Use one native P28 coaching source.** Propose explicit P28 ownership of
   question definitions/revisions and newly authored coaching check-in content,
   with existing P12 authority and P3/P10 classification. That is a required
   source amendment, not a claim that the command or storage already exists.
   A missionary-to-coach reflection is not automatically a P9 partnership
   interaction, P22 Ministry Update, P28 financial/activity Goal Version or
   P34 workflow submission.
3. **Prompt authors are not response readers.** Maintaining tenant questions
   permits reading/editing the question source. It does not permit listing
   respondents, drafts, answers, completion rates, response counts or historical
   disclosures. Independently qualified staff access, if any, remains independent;
   neither a role label nor prompt authorship manufactures it.
4. **The later roadmap already anticipates configurable coaching questions.**
   MPD-04 explicitly lists editable questions, but it is a disabled P34 configured
   automation with separate source binding gates. D25 brings a small native
   question capability into P28; it does not select the rest of MPD-04.
5. **Keep wording and answer meaning together.** A question's later edit,
   reorder or retirement cannot reinterpret an existing draft or accepted answer.
   Ordinary question retirement stops offering it to new drafts; it is not a
   response-deletion command or an authorization revocation.
6. **Question use is not narrative disclosure.** Saving a draft or choosing
   questions shares nothing. Existing D8 current audience/history controls still
   govern any deliberate narrative share. D24's standing selected-target scope
   and D11's duration create no standing narrative grant.

The one-current-set recommendation is a reversible scope simplification, not a
founder-confirmed cardinality. Plain writing must work without an active set and
without selecting an irrelevant financial goal or donor partnership. Exact limits,
draft/history retention and implemented commands remain source qualifications;
neither FORM-04's text lengths nor another D-number's TTL is inherited.

For the native narrative, the smallest complete proposed publication model is
**one private working revision and one current explicitly shared revision**. A
missionary can continue editing without replacing the coach's version; deliberate
Share/Update binds the exact reviewed revision to named, currently eligible
coaching episodes. This is a D25 design recommendation, not an entitlement
inherited from D24's changing numeric outputs. It creates no automatic future
check-in publication or coach revision-history browser. “Not shared with your
coaches” is truthful draft copy; “Only you” must not be promised when some
independent source-qualified access lawfully exists.

## Material concerns — eight dimensions each

Severity describes the consequence if implemented incorrectly; likelihood is a
qualitative review judgment about a naive implementation, not measured incidence.

### R01 — Prompt management becomes response access

1. **What:** A common “manage form” object or staff role unlocks drafts, respondent lists and answers.
2. **Why:** Administrators need to maintain questions without reading missionary narratives; metadata can itself reveal participation or confidential subject scope.
3. **Severity:** Critical for protected narrative disclosure.
4. **Likelihood:** High if a generic form-admin permission is copied.
5. **Evidence:** O02, O05, O09, O10, O14.
6. **Answer impact:** A is acceptable only with separate question and response admission; granting question administration is not a mandate for blanket staff access.
7. **Permanent fix:** Distinct source commands/projections through P12, including list/count/audit/recovery paths; exact grants and field classifications before release.
8. **Proposed clause:** **C02** — “Question-management authority SHALL confer no response, draft, respondent, participation or response-history access. Each requires independent current source-purpose authority.”

### R02 — Generic forms silently impose reporting or tasks

1. **What:** Required fields, due dates, missing-answer alerts or a next-action textbox turn optional check-ins into mandatory reporting or shared tasks.
2. **Why:** FORM-04 illustrates a required next action and MPD-04 describes due occurrences/reminders; neither is the chosen native product rule.
3. **Severity:** High, violating voluntary scope and operational truth.
4. **Likelihood:** High if the blueprint is treated as an implementation template.
5. **Evidence:** O01–O05, O07, O15–O18.
6. **Answer impact:** A remains optional for the organization and missionary; no obligation can be configured through this lane.
7. **Permanent fix:** Fixed optional text questions, useful free writing, no completeness metric; explicit separate owner action for actual work.
8. **Proposed clause:** **C03** — “All offered questions SHALL be skippable; no target, due date, missing response, required next action, task, notification or coaching enrollment SHALL follow from configuring, opening or skipping them.”

### R03 — Answers attach to the wrong source or subject

1. **What:** A check-in is saved as a CRM private note, exact-partnership interaction, financial Goal Version or generic workflow answer.
2. **Why:** Each source has a different audience, lifecycle and meaning; the shortcut can either disclose to staff or require a dummy donor/goal/workflow.
3. **Severity:** High for disclosure and durable data corruption.
4. **Likelihood:** High where only existing generic notes/forms are available.
5. **Evidence:** O01, O04–O08, O15–O20.
6. **Answer impact:** Native qualitative coaching is feasible, but its exact P28 producer must be explicitly qualified.
7. **Permanent fix:** One P28 coaching source with exact author/Tenant/canonical subject, using shared infrastructure and typed references to other owners.
8. **Proposed clause:** **C01** — “P28 SHALL own native question definitions and newly authored qualitative coaching records. Their source identity SHALL NOT be a substituted Party, interaction, Goal Version, Ministry Update or workflow occurrence.”

### R04 — A prompt edit changes what an old answer appears to mean

1. **What:** Responses join the latest question by array index, mutable label or current template head.
2. **Why:** Reordering, wording changes and retirement can make retained text answer a different question, destroy drafts or corrupt historical interpretation.
3. **Severity:** High for integrity, privacy expectations and useful coaching.
4. **Likelihood:** High with mutable JSON/index-based form rendering.
5. **Evidence:** O02, O16, O18, O20.
6. **Answer impact:** A adds real source revision obligations; these do not require a general versioning platform.
7. **Permanent fix:** Stable question identity and exact wording/order/version associated with draft/accepted content; CAS for question editing; no automatic migration of answers.
8. **Proposed clause:** **C04** — “An existing answer or draft SHALL retain its actual question meaning after edit, reorder or retirement. A current question-set revision SHALL affect new selection, not rewrite retained responses or require unrelated drafts to adopt new wording.”

### R05 — Numeric continuity or invitation acceptance publishes prose

1. **What:** The new narrative fields are added to the already shared activity target/module or made visible to every present/future coach.
2. **Why:** D24 selected recurring target periods, not future narrative contents; D8 exact history/current audience still applies.
3. **Severity:** Critical where narrative includes private context.
4. **Likelihood:** High if one broad coaching DTO/grant is reused.
5. **Evidence:** O01, O02, O05, O06, O09–O11.
6. **Answer impact:** Question selection does not settle automatic future check-in disclosure, old-history grants or response republication.
7. **Permanent fix:** Separate draft/content acceptance from deliberate narrative disclosure; exact authorized existing coaching recipient/subject and reviewed record revision; no implicit transfer from numeric grant.
8. **Proposed clause:** **C05** — “Choosing questions, saving text, D24 continuation, invitation acceptance or an access end date SHALL NOT share a narrative. Any narrative share SHALL independently satisfy D8's exact current audience, source, historical reach and reviewed content rules.”

### R06 — Prompt text or answers bypass classification

1. **What:** Tenant questions become arbitrary fields, instructions, hidden values or a route to copying restricted CRM/care/history into ordinary coaching.
2. **Why:** Editable wording cannot confer a new data purpose. A text field cannot truthfully promise semantic detection of every private detail a person types.
3. **Severity:** Critical for restricted-person/care disclosure.
4. **Likelihood:** Medium to High if a generic form engine or automatic context fill is added.
5. **Evidence:** O01, O05, O07, O10, O13, O16.
6. **Answer impact:** A is optional written guidance, not custom data modeling, assessment, AI assistance or imported history.
7. **Permanent fix:** Fixed classified fields, non-executable plain-text prompts, bounded input/rendering, explicit audience, no source-copy/autofill shortcut; enforce known source restrictions without claiming an NLP detector.
8. **Proposed clause:** **C06** — “Question wording SHALL NOT change field classification, source purpose or authorized audience. The feature SHALL NOT import, quote or summarize protected source history or supply a semantic-safety guarantee for arbitrary authored prose.”

### R07 — Template retirement is confused with response erasure or revocation

1. **What:** Removing a question deletes lawful answers, or preserving questions is treated as permission to keep serving answers after access ends.
2. **Why:** Source selection, retention and disclosure are independent. Ordinary administration must be reversible without silently destroying another person's work.
3. **Severity:** High for data loss or continuing disclosure.
4. **Likelihood:** Medium.
5. **Evidence:** O02, O05, O09, O16–O18.
6. **Answer impact:** A requires clear removal semantics, not an invented fixed retention duration or an exceptional reader.
7. **Permanent fix:** Retire from future offerings; preserve qualified existing draft/history under source retention/current rights; separate real safety withdrawal and permission revocation from routine edits.
8. **Proposed clause:** **C07** — “Ordinary question retirement SHALL remove future offering without deleting check-ins or ending their independent grants. Current source restrictions and lawful retention SHALL independently govern every retained draft, question reference and response.”

### R08 — Save/recovery uses stale authority or a different meaning

1. **What:** A late response crosses Tenant/hat/subject, retry creates duplicates, or a lost-response recovery serves a body after revocation.
2. **Why:** Check-ins contain private text and template edits are concurrent; authority at form-open is insufficient.
3. **Severity:** Critical for cross-context disclosure; High for lost/duplicate content.
4. **Likelihood:** Medium to High on mobile and multi-tab editing.
5. **Evidence:** O01, O05, O09, O14, O16, O20.
6. **Answer impact:** A's useful draft path must be qualified through actual source commands, not a UI-only mock.
7. **Permanent fix:** Trusted exact context, expected content/config revision, permanent same-operation recovery, current rights at acceptance/read, private caches cleared/fenced on context change.
8. **Proposed clause:** **C08** — “Each protected command and recovery SHALL preserve its exact Tenant, actor, subject, content/config revision and operation identity while rechecking current authority. A committed save remains committed; losing read authority never permits disclosure of its body.”

### R09 — Future P34 scope becomes a prerequisite or hidden expansion

1. **What:** Native questions depend on Studio or automatically inherit feedback writing, weekly occurrences, reminders, questionnaires, signatures or branching.
2. **Why:** Later MPD-04 has a broader workflow job; its symbolic source bindings/default clocks are not native qualification.
3. **Severity:** High for scope/authority drift; Medium for avoidable delivery complexity.
4. **Likelihood:** High if the existing blueprint is copied wholesale.
5. **Evidence:** O01–O05, O15–O21.
6. **Answer impact:** A selects the native question feature; future workflow scope remains separately bound and read-only coaching remains intact.
7. **Permanent fix:** P28 producer first, P34 exact consumer later; shared form controls without shared business grammar or duplicate response storage.
8. **Proposed clause:** **C09** — “Native check-ins SHALL function without P34. Later MPD-04 SHALL consume the qualified P28 source and existing effect owners; its questions, feedback, cadence and reminder examples SHALL NOT add unselected native powers or duplicate responses.”

### R10 — Every edit gets a new approval, or ordinary administration widens policy

1. **What:** ADR0211 is either omitted from real projection-policy expansion or applied to every question edit/check-in, adding unnecessary maker-checker friction.
2. **Why:** Editing permitted content and changing disclosure policy are different commands.
3. **Severity:** High for unauthorized widening; Medium for needless friction.
4. **Likelihood:** Medium.
5. **Evidence:** O05, O09–O11.
6. **Answer impact:** A can remain a short self-service journey under qualified existing policy.
7. **Permanent fix:** Explicit command distinction; ordinary authorized content edits are direct, while actual policy changes use existing policy governance.
8. **Proposed clause:** **C10** — “Ordinary question/check-in edits under qualified policy SHALL require no supervisory approval. Actual projection-policy widening SHALL retain ADR0211's distinct-human control; neither route shall substitute for the other.”

### R11 — Autosave publishes unfinished edits to coaches

1. **What:** Editing an already shared check-in changes its coach projection immediately, or a response revision is shown under an unreviewed recipient set.
2. **Why:** Narrative drafting and deliberate disclosure differ from D24's source-corrected numeric summaries; unfinished personal prose needs an intelligible save boundary.
3. **Severity:** High for accidental disclosure and loss of author control.
4. **Likelihood:** High if a single mutable response body serves both views.
5. **Evidence:** O01, O02, O05, O06, O09, O16; root's proposed D25 publication model.
6. **Answer impact:** A's prompt selection permits useful drafting; explicit publication behavior must be a visible review recommendation, not a claimed new founder answer.
7. **Permanent fix:** One working revision and one current shared revision in the same source; explicit Share/Update, exact recipient episodes/current eligibility, no automatic version-history entitlement or per-coach content fork.
8. **Proposed clause:** **C11** — “Autosave SHALL update only the private working revision. Explicit Share/Update SHALL publish the exact reviewed revision to its exact currently admitted coaching episodes; pending edits, new check-ins, new episodes and previous revisions SHALL gain no audience by implication.”

## Suggested exact decision wording

> Permit authorized organization staff to maintain optional reusable written
> questions for native coaching check-ins. A missionary can use any helpful
> questions, skip them and write their own context; ordinary free writing works
> without a configured set. Questions impose no reporting requirement, task,
> score or reminder. Managing questions grants no access to drafts or responses.
>
> Keep the question meaning attached to an answer: later edits, reordering or
> retirement do not rewrite existing drafts or history. Newly authored check-ins
> use one qualified P28 coaching source and current P12/P3/P10 authority. Saving
> text and sharing it are separate effects: changes remain in the private working
> revision until explicit Share/Update publishes the reviewed version. The
> recipient, source scope and historical reach must be deliberate and current.
> D24 numeric continuation does not disclose prose, and coaches remain read-only.
>
> Reuse existing settings, forms, permissions and shared infrastructure. This
> decision does not introduce a general form builder, new permission engine,
> imported private context, coach comments, automatic communications or a P34
> prerequisite.

This is candidate wording and source reconciliation, not a separately ratified
decision. A narrow explicit narrative acceptance/share contract must make the
native journey usable. If implementation proposes automatic sharing of future
check-ins or broader historical disclosure, that is a distinct product choice;
it must not be hidden in a question-template flag. Exact source symbols, safe
text handling, conflict recovery and retention implementation are engineering
qualification, not reasons to ask the founder to name tables or APIs.

## Formalization destinations and activation gates

Only a later authorized formalization may change these owners:

1. **P28 owner contract and its OpenSpec projection:** record question/check-in
   source ownership, optional native behavior, precise source identities,
   version/retirement semantics, disclosure boundary and positive journey.
2. **P12/P3/P10:** register/classify the exact native record fields and current
   author/admin/read/share/history commands; separate prompt management and
   response authority. Reconcile D8 Coach role intention with the fixed-role
   baseline rather than claiming the current role enum supplies the feature.
3. **P34 effective owner bindings/catalog:** bind MPD-04 and FORM-04 to the native
   P28 source once qualified; reconcile required-next-action/reminder/feedback
   examples with each later accepted source purpose. Preserve immutable original
   source assets. Do not rewrite them as if a native service shipped.
4. **Existing shared task/communication/export owners only if explicitly used:**
   typed independent actions retain their separate acceptance/effect identity.
   D25 alone creates no need for a new dispatch, task ledger or exporter.
