# Q26 frontier — selected next-step status in coaching

Research date: **October 17, 2026 UTC**. **Awaiting founder answer.**
D25's corrected decision and required amendments are explicitly ratified.
Neither Q26 option is selected. This is a researched product choice, not a
formal specification, new permission or implemented task-sharing service.

## The one choice

After a coaching conversation, Maya plans to **“Revise my support-raising
introduction by Friday.”** She keeps that next step in her ordinary task list.
Jordan would find it useful to know whether it is still planned, completed or
rescheduled before their next conversation. This is an illustrative scenario,
not a claim from an observed ministry interview.

**Should Maya be able to share a selected next step's current due date and status
with Jordan?**

- **A — Optional sharing of selected next steps (recommended).** When the
  organization permits it, Maya deliberately shares an eligible summary of a
  selected task. Jordan sees its approved description, due date and current
  status, read-only. Maya updates the ordinary task once; its permitted coaching
  summary stays current.
- **B — Describe next steps in check-ins.** Maya manages her ordinary tasks and
  describes progress in the check-ins she chooses to share. Coaching includes no
  linked task-status view in this release.

**Recommendation: A.** It helps both people prepare without asking Maya to
maintain a second checklist or repeatedly copy a task's status into prose.
Creating a task does not share it. Jordan cannot assign, edit or complete work.
New tasks and recipients are never added automatically, and supporter details,
private notes and source-record links are not included merely because the task
is selected.

Both options preserve voluntary coaching, current access, separately shared
written check-ins and normal task management. B keeps the complete qualitative
job; it does not remove agreed-next-step context or introduce a manually maintained
coaching task list.

The strongest alternative B is simpler: the already ratified written check-in
provides personal context and preserves deliberate publication. Its cost is that
the narrative may no longer describe the current task status; Maya may need to
write another update. That is an honest authored account, not a bug requiring
automatic narrative rewriting. A adds a small real source-projection/lifecycle
obligation and earns it by avoiding duplicate maintenance.

The generic roadmap “open decisions” is not a reason to repeat questions already
answered about resources, maps, connections, imports, writing assistance,
activity targets or questions. Direct recording of financial promises was also
considered as another frontier, but [P16](../../../prds/sitestacker-parity/phase-16-pledges-recurring-commitments.md:1209)
already explicitly restricts missionaries to read/request actions. This question
does not quietly reopen that financial-owner decision.

These are relevant pattern precedents, not proof that every ministry needs this
module or that Asym's live authorization is implemented. Core's source and privacy
contracts govern. A requires no new vendor, task engine or notification channel.

## Consequences to review after the answer

If A is selected, use a small **Next steps** area in the D8-defined coaching
context and a clear deliberate sharing action on eligible native work. Show what
the named coach will receive. Preserve one source of current due date/status.
Keep the full missionary task list separate from the selected coaching view.

The answer review must settle exact eligible task kinds and fields, safe summary
wording, what happens when task wording/scope changes, current status and
cancellation/reopen meaning, due-date/time-zone treatment, retention and removal,
current access and replay races. A selected summary must not acquire private
task descriptions, linked supporter identities or automatically changed narrative
scope. “Nothing shared,” “unavailable” and “completed” must remain distinct.
No extra task, manual shadow status, compulsory goal, activity credit or sending
effect follows. Existing P12/ADR0211 controls govern actual policy widening;
routine permitted task editing does not acquire a new approval step.

If B is selected, ordinary task management and authored next-step context remain
useful. Do not label narrative prose as a live task status or silently turn it
into a duplicate checklist. The linked summary module is absent, not an endlessly
loading or disabled promise in the coach UI.

Current-source evidence from the [D25 bounded census](d25-evidence/current-check-in-source.md)
is reused only within its original scope; it is not a new task-producer scan.
ADR0183 itself identifies existing generic task surfaces as migration inputs.
Neither an old task screen, a reference field nor a document establishes the
new coach-summary service. No runtime, database, provider, browser or load test
was needed or run to prepare this choice, and no prior probe was rerun.

The founder's one-question-at-a-time instruction remains in force. Q26 is
unanswered; this note does not select A, authorize a new module or broaden
coach permissions before the answer and its review.
