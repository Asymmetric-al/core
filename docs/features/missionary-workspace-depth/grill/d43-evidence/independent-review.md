## Remaining invariants checked

- **Consent and privacy:** exact original tenant/newsletter/destination authority
  survives only while current rules permit. Multiple pending links converge on
  one membership; withdrawal invalidates older uncompleted instructions; retry
  cannot be mistaken for fresh rejoin. Initial receipts and selector requests
  do not prove mailbox control or expose membership/suppression state. A
  verified capability still reveals only its currently qualified result scope.
- **Identity and permissions:** no login, CRM profile or tenant workforce
  membership is required for this native guest confirmation. No confirmation
  changes Supabase Auth email verification, grants content access or lets staff
  confirm on a reader's behalf. D42's separately qualified immediate Join path
  retains its own proof and authorization requirements.
- **Authority and implementation:** C10 calls for effective grants, old-row
  `USING`, resulting-row checks, tenant-aware relationships and privileged-path
  proof, rather than claiming RLS syntax alone is sufficient. Current code and
  research intent remain distinct; actual source transactions and release tests
  remain C14/P18–P26 obligations.
- **Evidence and operations:** the bounded model explicitly assumes atomic
  source operations and does not prove database concurrency, Auth, tokens,
  providers, CSRF, accessibility or production performance. Monitoring assigns
  signals, thresholds, accountable roles and responses without using monitoring
  to defer required correctness. Retention/restore must preserve the inability
  to revive expired or withdrawn authority.
- **Simplicity:** one Page entry control, the source capability stop under its
  existing settings/permission owner, one shared protected doorway and the
  existing delivery executor suffice. No pending dashboard, additional reminder
  product, identity engine or second outbox is justified by D43.
