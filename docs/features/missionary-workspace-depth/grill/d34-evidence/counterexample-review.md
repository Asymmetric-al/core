# D34 adversarial review: limited expired-referral history

**October 18, 2026 UTC.** D34 selects organization-permitted limited history.
This review proposes the narrow P9/P12 consumer contract; it selects no default
setting, expiry duration, retention period, renewal actor or new request queue.
It does not establish a deployed referral producer or permission grant.

The key boundary is a separately authorized projection of a referral occurrence.
It is not historical Party-list access. The source must prove an eligible
pre-expiry recipient in the exact work context, and current authority must still
permit this specific history purpose. That evidence may include a qualified
handoff recipient; it is not restricted by this review to the first recipient.
Creator, former membership, current assignment and original receipt alone are
insufficient. Reassignment does not automatically supply the historical proof.

## Concrete failures and minimal owner fixes

| Case | Unsafe alternative | Required bounded outcome |
| --- | --- | --- |
| A01 | An expired window still grants active referral access until a sweeper changes its status. | Evaluate ordinary effective expiry against current authoritative time/source facts at the actual disclosure boundary. A lagging display or job cannot extend active authority. |
| A02 | Any closed/revoked referral is called Expired and remains visible. | Ordinary window expiry is distinct from withdrawal, revoked source authority, invalidation and other dispositions. Only the qualified expired projection is admitted. |
| A03 | The history grant calls the ordinary Party serializer or includes private referral notes/referrer details. | Return only the current source-approved useful identifying label, Expired meaning and separately approved minimal references. Contact fields and private referral context are excluded from this entry. |
| A04 | Turning history Off removes independently authorized supporter contact access, or independent Party access reveals the old referral body. | Evaluate independent ordinary access through its own current purpose. Neither branch grants or cancels the other. Readability still does not imply contactability. |
| A05 | A creator, previous assignee, newly assigned missionary or matching email inherits every old referral. | Require canonical current actor/context plus exact source-proved eligible pre-expiry recipient evidence and current history permission. A legitimate historical handoff may qualify; reassignment alone cannot. |
| A06 | No safe name is available, so the UI returns “Private referral,” raw Party ID, hidden count or referrer hint. | Omit the entire entry from list/search/count/cursor when no useful identifying label is currently permitted. A separately approved safe alias can qualify; no unsafe fallback is inferred. |
| A07 | Search matches a private phone number or body, then returns a redacted label; a zero-versus-one result reveals the private match. | Search predicates, ordering, snippets and aggregate counts use only the authorized projection. Filtering after matching is insufficient. |
| A08 | A page cursor, total or has-more value is computed over all source rows before privacy filtering. | Page and count the permitted result set. Bind continuation to actor, Tenant, work context and history purpose; every continuation re-evaluates current source/privacy. Hidden insertions must not manufacture a public continuation. |
| A09 | A prepared row is delivered after Off, revocation, a context switch or source privacy change. | Reauthorize at disclosure and reject stale context/source/authority snapshots. Client rendering also rejects late previous-context responses; a cache entry is not a grant. |
| A10 | On→Off→On makes an old cached response valid again without current evaluation. | Re-enable permits a fresh current read when all gates pass. It does not revive a stale response, expired grant or revoked source proof. No new lifecycle epoch or receipt-time cohort policy is selected. |
| A11 | A Party merge or source identity repair transfers historical audience or discloses the survivor's name/contact details. | Resolve exact current source identity, privacy and label authority again. Preserve source provenance; do not infer recipient proof, duplicate entries or grant union from an alias/merge. |
| A12 | A legal hold, retained private body or old snapshot is treated as permission to show history after ordinary retention has ended. | Require current source-readable retention for this projection. Hold-only or erased data supplies no history read grant. D27/D28 preparation retention rules do not apply. |
| A13 | Opening history marks contact, restarts expiry, resets retention, revives tasks or sends a reminder. | Reading remains read-only. Continuation and any genuine interaction use their separate current owner commands; this decision grants none of them. |
| A14 | A renewed/active-again source remains in the Expired list, or hiding it deletes source history. | Re-evaluate the current source predicate. Remove it from this projection when active or withdrawn, while preserving the source's lawful history. This consumer neither renews nor deletes it. |
| A15 | Record denial, unknown expiry or a missing source returns a special row/count/error identifying a protected person. | Use the existing uniform unavailable/not-found disclosure contract. Unknown qualification is not evidence of “no referrals” or a license to expose an explanation tied to a hidden record. |

## Important schedules

1. **Expiry before sweeper:** active display snapshot → authoritative deadline
   passes → read under current time → active referral authority ends even though
   the display/job still says Active; independently qualified minimal history may
   now be read.
2. **Privacy before response:** prepare an allowed minimal row → source label or
   history authority is revoked → late disclosure → unavailable, with no cached
   label, count or existence hint.
3. **Off then re-enable:** prepare → Off → On → discard stale response; fresh
   evaluation may allow currently eligible history. Independent supporter access
   retains its own result throughout.
4. **Cursor after change:** first permitted page → hidden source changes or actor
   rights change → continuation re-evaluates only current permitted projections.
   Hidden-only changes do not create a public row, count or page.
5. **Qualified handoff:** source retains proof that a second recipient was eligible
   before expiry → current exact historical authority exists → that recipient may
   qualify. Replacing only the current assignee does not produce the proof.

A small finite model is useful for these observable differences, especially
private-field search and pagination metadata. Its qualified source inputs cannot
prove actual P9/P12 implementation, SQL/RLS, timing uniformity, cache invalidation,
retention, client rendering or concurrency. No previous model/probe is rerun.
