## The single choice

Maya is starting to raise support and wants help finding a useful first step.
This is an illustrative scenario, not a reported user interview or an assumption
that every new missionary needs the same guidance.

**Should her organization be able to offer a short getting-started guide inside
her workspace?**

- **A — Optional starting guide (recommended).** Authorized staff arrange a
  short set of suggested steps linking to approved resources and existing
  workspace actions. Maya can use it, skip it and return whenever helpful.
- **B — Resources and contextual help only.** Staff put starting advice in the
  existing resource library; Maya chooses her own starting point without a
  separate guided-start experience.

A means a small native starting path, not merely a PDF that D12 already permits.
B is the strongest simpler alternative: it uses the existing library and ordinary
help without adding a separately maintained starting presentation. Both keep
ordinary work available and preserve current source permissions. Neither turns
reading into completion, automatically creates tasks, assigns coaching, imports
a curriculum or requires a course before a missionary can work.

A is recommended for easier discovery: the organization can connect a few useful
first steps to the actual workspace. This is a product judgment, not a measured
retention, satisfaction or fundraising improvement. It must remain optional and
useful to someone returning for help, without permanent novice/veteran user types.

## Why this is a real unresolved choice

The founder explicitly requested consideration of contextual getting-started
help. D12 selected who curates the resource library; it did not select a guided
starting experience. Existing Phase 27 stage guidance explains a particular
stage and stays advisory. Neither necessarily provides orientation across the
missionary workspace. Asking whether to include a short native starting path
therefore changes launch scope, rather than re-asking whether staff may publish
an ordinary guide.

## Smallest coherent journey if A is selected

An optional **Getting started** entry leads to brief organization-approved
suggested steps. Each opens an existing permitted resource or action; it does not
perform that action just by being selected. Ordinary navigation remains usable.
Someone who has already done the work can ignore the guide, and someone returning
for help can find it again. No forced tour, takeover, mandatory questionnaire or
inferred “new missionary” classification is needed.

A small ordered list is a proposed presentation, not an accepted widget, schema,
step limit or saved checklist state. Do not add a percentage, overdue badge,
completion tracking or staff progress report merely to make the guide appear
richer. Source actions retain their own permission, validation, deliberate
acceptance and recovery. Guide links never grant action or content access.

Authorized staff prepare and maintain the approved guidance in the appropriate
organization context. If none is configured, ordinary work and the library still
work. The answer review would settle exact publication/withdrawal, placement,
tenant control, safe unavailable destinations, mobile/accessibility and recovery
through the existing design system and owners. These are not already ratified
A requirements or a new generic workflow/LMS dependency.

Under B, the same useful advice can be an ordinary library resource, with existing
contextual help retained. The cost is that Maya must find the relevant starting
material rather than receiving a connected starting path. B is not absence of
help, and it should not be described as an inferior or intentionally confusing UI.
