# D19 owner boundaries — first support for a ministry or project

Research date: October 16, 2026 UTC. Repository baseline:
`9cada8f3d8ab59db391d3fd20df77fcadeb09813`.

**Status:** the founder selected A: first-support follow-up concerns the particular
ministry/project, including a supporter who previously gave elsewhere in the
organization. The detailed recommendations here are unratified research. This
note changes no formal owner contract, application, task, grant or live service.

## Conclusion and minimum permanent path

Use one finite P28 first-support purpose on the existing shared task contracts.
P13/P14/P16 supply qualified financial/recognition/commitment facts; P28 owns the
follow-up meaning and admission; P9/shared Tasks Hub supplies the shared work
identity, links, authorized responsibility and presentation. P6/P17 remain the
only governed communication path. Optional P34/P35 callers reuse the same
source effect identity and cannot become prerequisites for native work.

**Do not automatically introduce a separate P28 review ledger before creating a
task.** ADR0183 explicitly distinguishes two existing contracts:

- A source-controlled assignment remains open while its exact source action is
  required. Generic Done cannot satisfy that action.
- An **Independent follow-up task** owns a human deliverable that can finish
  while its linked source remains open. Its authorized assignee can record
  **Done with my task**. Completion never changes the linked financial/source fact.

D19's personal thank-you deliverable fits the second contract as the simplest
recommended initial profile. It still needs source-qualified admission,
correction/applicability handling, stable business-effect identity and current
authority. If a particular admitted action instead requires a separate source
decision, use that source's closure contract for that action. Do not turn the
choice into a tenant completion-mode setting or permit callers to select it.

The required durable evidence is the bounded first-support admission basis,
source references/revisions, purpose/effect receipt and authoritative task and
outcome. This does not justify a generic gift-attention platform, new workflow
engine, notification ledger or copied financial history. A source obligation
and a shared task must not both independently own the same human Done fact.

### Human completion, held work and correction

**Mark done** should record only completion of the admitted human task. If the
missionary wants to record actual thanks or an encounter, offer the existing
qualified outcome/interaction action without requiring shared prose. Those facts
retain their separate source and truthful audience. “Mark done” must not silently
mean “Email sent,” “Conversation occurred,” or “Supporter replied.”

ADR0183's predecessor-never-reopened statement is in its **source-backed** closure
contract (`:74–107`); it is not a universal ban on correcting an accidental Done
for an Independent follow-up task (`:622–628`). Recommend ordinary conditional
**Undo completion** on the same task and purpose identity: current authority,
the exact latest completion receipt, no conflicting subsequent outcome, and
current source applicability. Append correction evidence; retain the original
completion and never undo or repeat a gift, communication or interaction.
This is an explicit D19/shared-task design recommendation, not a claim of current
runtime or an already specified independent-task Undo implementation.

The smallest recommended source/task lifecycle distinguishes:

1. **Before admission:** unknown/incomplete qualification is held. It is not a
   proved first gift, proved absence or consumed first-support effect.
2. **Admitted but temporarily unqualified:** keep the same unhandled task and
   admission identity while unavailable facts or current safety prevent action.
   Do not create a new generation merely for a transient hold.
3. **Proved no longer applicable:** withdraw the automatic requirement truthfully
   as No longer required, retaining its task/outcome and source cause.
4. **Qualified correction of that withdrawal:** a narrow explicit repair may
   restore the same independent task/effect identity only when the original live
   admission is proved, no intervening human Done/Not needed outcome exists,
   current source/recipient/safety checks pass, and a correction receipt retains
   the earlier withdrawal. This is a proposed correction of one erroneous
   disposition, not a fresh first-support occurrence, recurrence or historical
   catch-up. If the owner cannot prove these conditions, hold for qualified repair;
   do not improvise a successor engine or automatically rerun ended work.

Human Done/Not needed remains covered and cannot be restarted by financial
recalculation. A deliberate correction of the mistaken human disposition is
separate from automatic source repair. Shared-task ownership still controls the
human state; the financial source only supplies qualified applicability evidence.

## Corrected decision candidate

> Create source-qualified internal first-support follow-up for the actual
> ministry/project when a supporter first provides qualifying received support
> there, even if that supporter previously supported another ministry in the
> organization. A login, worker change, new year, new designation label, recurring
> instruction or first visible page of gifts does not establish a new beginning.
>
> Use one bounded P28 purpose and the existing shared task contract. Prefer the
> admitted independent human-follow-up profile for personal thanks: its completion
> records the human task outcome only and does not change a gift, commitment,
> relationship stage or communication fact. Required source decisions retain
> their own source-controlled completion. Current authorized responsibility and
> a discoverable qualified repair path keep work useful without guessed recipients.
>
> A task neither sends thanks nor grants contact or financial access. Actual
> outreach uses its qualified owner; an actual encounter may be recorded once
> through P9 under its proper audience. Native work, organization follow-up and
> optional workflows deduplicate the same intended purpose without collapsing
> genuinely distinct authorized communications. Preserve independently required
> work and completed history when facts or responsibility change.

The first paragraph records A's direction. The exact admitted first-support
source profile, task contract and operational safeguards below are recommendations
for ratification and later owner formalization, not additional founder-selected
recipient rights or implementation claims.

## Material concerns and exact candidate clauses

Likelihood describes a plausible unmitigated design failure, not production
incident evidence. Each concern has all eight requested dimensions.

### O01 — A new task framework or unnecessary source-review record

- **What:** Treat every gift-linked task as a source-controlled correction and
  build a P28 review lifecycle plus a separately completable task.
- **Why:** Two authorities can disagree about the same human work; a mandatory
  review hop burdens simple personal thanks and obscures actual completion.
- **Severity:** High for integrity; Medium for maintenance/friction.
- **Likelihood:** Plausible, because ADR0183's main source-backed discussion is
  easier to notice than its explicit independent-follow-up distinction.
- **Evidence:** S04–S06; ADR0183 `:622–628,697–711` expressly distinguishes these contracts.
- **Answer impact:** Preserve A; choose the smallest existing code-owned profile,
  rather than treating a new review framework as required architecture.
- **Permanent fix:** Register D19 purpose/admission/effect identity on shared
  work, keep one authoritative human outcome and use source-owned financial references.
- **Exact proposed clause OC01:** “D19 SHALL use one closed shared-task profile
  for its human follow-up deliverable. The initial recommended profile is
  Independent follow-up: authorized completion ends that deliverable only.
  Separate source-controlled actions SHALL retain their own source receipt;
  no second lifecycle may independently own the same Done fact. Completion mode
  is code-owned, not tenant- or caller-selectable.”

### O02 — First support is keyed to the viewer, login or mutable designation

- **What:** Worker replacement, ministry renaming, new calendar year, currency,
  provider event or related designation creates another “first” task.
- **Why:** It repeats personal work and may misdescribe financial history;
  hidden/partial history can falsely establish first support.
- **Severity:** High.
- **Likelihood:** Likely without an explicit qualified source identity.
- **Evidence:** S01–S03, S07; roadmap `:4843`; P27 canonical identities `:13–31`.
- **Answer impact:** A is scoped to the actual ministry/project, not every
  representation of it. Financial producer qualification is a release gate.
- **Permanent fix:** Bind the exact source-certified support subject, canonical
  ministry/project, Tenant/Legal Entity basis, qualifying source occurrence and
  named follow-up purpose; use complete history with explicit unknown states.
- **Exact proposed clause OC02:** “First-support qualification SHALL use the
  owning source's exact subject, canonical ministry/project scope, eligible
  occurrence and completeness evidence. A consumer-visible subset cannot prove
  absence. Actor, assignee, label, year, currency, transport, workflow run and
  credential changes SHALL NOT independently restart the first-support purpose.
  Unqualified mapping/history blocks that automatic admission with a truthful
  source-safe unavailable/repair state; ordinary authorized work remains usable.”

### O03 — Recognized humans become donors, contacts or automatic recipients

- **What:** One legal gift creates personal outreach tasks for every household
  member, DAF-related person, church member or organization contact in its context.
- **Why:** Recognition and relationship visibility are not recipient authority;
  this can expose a protected gift or solicit people who never consented.
- **Severity:** Critical for prohibited disclosure; High otherwise.
- **Likelihood:** Plausible when a broad supporter roster is reused as an audience.
- **Evidence:** S10; P14 J.1/J.2 `:1167–1177`; P27 C33 `:433–439`; S03 `:4845`.
- **Answer impact:** D19 selects ministry-relative meaning, not expansion of
  recognized-party contact rights or the separate mediated-member product.
- **Permanent fix:** Keep support qualification, legal donor, recognition subject,
  actual recipient and contact point distinct; qualify each admitted recognition
  profile and preserve anonymity in every derivative.
- **Exact proposed clause OC03:** “D19 SHALL NOT infer contactability, donor
  identity or a recipient from recognition, household/church membership or a
  shared mailbox. Via-church member attribution SHALL NOT create a member-facing
  thank-you affordance or member-outreach duty under this decision. A person's
  independently qualified direct support/contact authority remains separately
  usable without disclosing the protected church attribution. Anonymous or
  restricted facts SHALL NOT leak through task existence, title, counts or links.”

### O04 — Assignment is guessed, duplicated or silently transferred

- **What:** Every project member gets a task, the creator/admin becomes fallback,
  or Party reassignment silently transfers missionary follow-up and private history.
- **Why:** It produces duplicate accountability, access leakage or stranded work
  when a missionary leaves. No task recipient may gain rights by assignment.
- **Severity:** High.
- **Likelihood:** Likely without exact recipient/repair qualification.
- **Evidence:** S04 `:57–64,109–139`; S07 P05; S08 A07–A08.
- **Answer impact:** Preserve useful automatic work while qualifying the actual
  responsible actor; no new coordinator role or tenant routing engine is assumed.
- **Permanent fix:** Reuse source-authorized shared responsibility and exact
  current eligibility. Admit only proved eligible recipients; preserve source-safe
  discoverable needs-assignment work if none qualify. Revoke first, repair second.
- **Exact proposed clause OC04:** “Task responsibility SHALL be separately
  qualified from ministry participation, Party representation, cultivation lead
  and role label. An existing clear eligible responsible person may be used only
  under the admitted source profile. Missing/ambiguous/revoked resolution SHALL
  not broadcast or guess a fallback. Preserve the work through an independently
  authorized source recovery path. Handoff SHALL use the current shared/source
  command, preserve unrelated owners and history, and grant no new read/action right.”

### O05 — Done fabricates thanks, a conversation or compulsory shared reporting

- **What:** Generic task completion inserts “called/sent/thanked,” changes exchange
  recency, requires a shared note or opens a new pending-response obligation.
- **Why:** Personal work completion and actual communication evidence have
  different meanings; mandatory narrative undermines P27's voluntary history.
- **Severity:** High.
- **Likelihood:** Likely if task status is treated as interaction evidence.
- **Evidence:** S01; S05 independent task contract; S09 C01/C02/C10.
- **Answer impact:** Keep one short completion journey without inventing an
  interaction. The exact allowed task outcomes are a D19 owner profile, not the
  P27 rating-review “No change needed” profile borrowed by name.
- **Permanent fix:** Record an attributable task outcome. Offer an optional
  qualified encounter/outreach action when appropriate; reuse an actual existing
  communication source. No copied private body or compelled shared narrative.
- **Exact proposed clause OC05:** “Done with the first-support task SHALL mean
  completion of its admitted human deliverable only. An actual call, letter,
  message, response or encounter SHALL require its own truthful source evidence;
  opening a dialer, sending without reply, viewing a gift or checking Done cannot
  establish an exchange. One deliberate qualified command may record the actual
  outcome and satisfy the task without duplicate entry, but shared narrative
  remains voluntary. Non-success dispositions SHALL not be labeled Thanks sent.
  Qualified conditional Undo of an accidental independent-task completion SHALL
  correct that same task under current authority and expected outcome revision,
  preserving the original receipt and performing no communication, interaction
  or financial reversal/replay.”

### O06 — Task purpose bypasses Never Ask, suppression or P6/P17

- **What:** A first-gift flag is treated as consent, a task silently sends, or a
  worker routes around a blocked email through another channel/template.
- **Why:** Internal work is not communication authority. Conversely, collapsing
  every restriction into “no internal work” can hide legitimate repair duties.
- **Severity:** Critical for forbidden contact/disclosure; High for lost work.
- **Likelihood:** Plausible.
- **Evidence:** S01, S11 A8/A17, S12 truth boundaries; P27 P13 `:419–425`.
- **Answer impact:** Preserve A's internal task; no new channel, sender, newsletter
  consent, automatic thank-you key or restricted-contact exception.
- **Permanent fix:** Qualify the exact action/purpose/channel under the existing
  contactability owner at offer/acceptance/dispatch. Distinguish solicitation
  restrictions from other purpose-specific rules without consumer overrides.
- **Exact proposed clause OC06:** “A first-support task SHALL not authorize a
  message. Applicable Never Ask, do-not-contact, channel and purpose restrictions
  SHALL block prohibited suggestions and effects through their owning policy;
  D19 cannot relabel solicitation as thanks or invent channel fallback. Retain
  independently lawful internal review/repair with truthful permitted actions.
  Any actual send SHALL use its qualified source preparation and P6/P17 spine,
  with current recipient authority, consent and source-fence reproof.”

### O07 — Native and optional workflows duplicate or over-collapse effects

- **What:** Native task, staff workflow, replay and future P35 each create a thank-
  you; alternatively one receipt closes unrelated personal follow-up everywhere.
- **Why:** Transport deduplication expires and is not product identity. Different
  authorized communications may be useful but must not be silently equated.
- **Severity:** High.
- **Likelihood:** Likely without shared source-purpose identity.
- **Evidence:** S02, S03, S07 `:423`, S11, S15 `:99–107,179–187`.
- **Answer impact:** Preserve coordination without imposing one universal thank-you
  per gift, a second sender, or an optional-workflow dependency.
- **Permanent fix:** Owner-defined permanent identity and immutable request
  comparison at the source; share one authoritative outcome across native and
  workflow requests. Cover multiple obligations only with exact source evidence.
- **Exact proposed clause OC07:** “Native, staff and optional-workflow requests
  for the same admitted first-support purpose SHALL converge on one durable
  business effect and task. A changed payload under the same intent conflicts;
  a new run, provider ID or retry window does not create new meaning. An
  organizational receipt or unrelated acknowledgment SHALL not by itself complete
  this personal deliverable. One actual action may satisfy multiple obligations
  only when the owner records exactly which compatible obligations it addressed.”

### O08 — Corrections, imports, access loss or restore rewrite real work

- **What:** Refund/reattribution deletes completed thanks; a delayed gift or old
  import creates historical first-support work; source restoration reopens ended
  tasks; unavailable facts are treated as zero or proved invalidity.
- **Why:** Source truth changes, but completed human history does not become
  nonexistent. Read denial and no-longer-required work are different states.
- **Severity:** High.
- **Likelihood:** Plausible under ordinary finance correction and migration.
- **Evidence:** S01 `:173,181`; S04 typed ends; S07 `:165–191,423–425`; S09 C28;
  S15 `:199–207`.
- **Answer impact:** Preserve A, requiring explicit source correction/admission
  semantics rather than consumer regeneration. Source financial rulings remain gates.
- **Permanent fix:** Reconcile current applicability through source-qualified
  revisions; preserve historical receipts/outcomes, independent undertakings and
  body restrictions. Use prospective activation and effects-dark historical intake.
- **Exact proposed clause OC08:** “Qualified source correction SHALL reconcile
  unstarted automatic work without erasing completed outcomes or unrelated
  accepted follow-through. Source-proved withdrawal is No longer required, handoff
  is Reassigned, and access loss is neither completion nor proof of invalidity.
  Temporarily unknown qualification SHALL hold the same unhandled identity,
  not manufacture a terminal outcome. Replay, re-enable, imports, restored
  snapshots or mutable first-date recomputation SHALL not revive ended work.
  A qualified explicit correction of an erroneous automatic withdrawal may
  restore the same independent task only with proved original live admission,
  no intervening human resolution, current applicability/authority and retained
  correction evidence. Human dispositions require their own deliberate
  conditional correction. No recurrence/successor engine is introduced;
  historical backfill has no outreach/task effects by default.”

## Proof required before activation, rather than assumed by this note

1. First support for ministry B qualifies even after support for A; assignment,
   labels, currency, year, worker changes and retries do not restart B's purpose.
   Complete-history absence and merely hidden/partial history are distinguished.
2. Concurrent native and optional-workflow requests recover one task/effect;
   changed same-intent input conflicts. A distinct independently authorized
   organizational communication survives without falsely completing personal work.
3. Independent task Done does not mutate financial truth, create an exchange,
   publish a shared note or send. Source-controlled actions reject generic Done.
   Lost task/source responses reconcile their original accepted receipts.
   Conditional Undo corrects the same task once, rejects intervening conflicts,
   and does not undo or resend an actual communication.
4. Source-qualified named handoff/departure preserves work without granted access,
   duplicate assignees, invented fallback or silent historical disclosure. Zero
   and indeterminate recipient resolution remain distinct and repairable.
5. Church-member-only, independently direct-giving member, DAF advisor, household,
   shared mailbox, anonymous gift and restricted worker fixtures retain exact
   identity/purpose boundaries; no roster entry manufactures contactability.
6. Never Ask and applicable contact/channel restrictions fence prohibited effects
   at their actual owner boundary; legitimate source-safe internal work remains
   discoverable. Provider uncertainty cannot trigger another send.
7. Corrected/reversed/delayed/imported facts, completed work and independent
   follow-through retain truthful distinct outcomes. Mixed-version restore cannot
   recreate historical effects or revive ended access/work. Prove transient hold,
   automatic withdrawal and qualified correction of that withdrawal separately;
   no human-resolved work is silently reopened by source repair.
8. Verify actual task/source commands, current-role projections, authoritative
   old/new-row transitions, outbox/reconciliation and every reached direct path.
   A synthetic fixture or legacy `thank_you` enum alone proves none of these.

These are release requirements and bounded counterexamples, not tests run by
this research note. No runtime, database, provider, migration or real-user proof
was obtained here. No quantitative retention, response-time, deadline, reminder
or workload threshold is inherited or invented by this owner pass.
