## Initial findings

### IR1 — Membership-dependent solicitation is narrower than every linked message

**High severity; plausible likelihood if an appeal reference becomes a universal
cancellation key.** The initial communication section covers “deliberately
appeal-originated solicitation, including relevant follow-up” and separately
preserves independent duties. It should state exactly how those sets differ.
Otherwise an existing Request response/follow-through or source-required service
message might be stopped merely because it carries an appeal link.

**Exact fix:** “The continuing-inclusion predicate applies only to the exact
solicitation purpose whose qualified producer basis requires current appeal
working membership. Merely linking a Request or message to the appeal does not
make it dependent on membership. Required service/receipt/fulfillment work and
other independent duties retain their own source authority and applicability.”

**Meaningful proof:** Remove a supporter while membership-dependent solicitation
and an independently required linked service/follow-through are pending. Fence
only the former. Test both orders against the actual communication admission
boundary; preserve an already-in-flight or indeterminate outcome rather than
claiming recall. Return must not revive the ended solicitation occurrence.

This clarifies the selected cancellation scope without exempting the surviving
work from its own current consent, purpose, permission or source checks.

### IR2 — Advance the real validity fence; do not defer it as an intent

**Critical for unintended external effect; plausible with asynchronous outbox
reuse.** The communication section correctly says membership disposition and
producer-validity fence advance together. The initial database paragraph and R08
instead say “local work/fence intent” and “downstream/fence intent” are atomic.
A durable promise to advance a fence later is insufficient: dispatch could accept
old validity after removal has already been reported as accepted.

[P6 A17](../../../../prds/sitestacker-parity/phase-06-shared-communication-event-model.md:175)
and its [fence/API contract](../../../../prds/sitestacker-parity/phase-06-shared-communication-event-model.md:230)
require the exact producer invalidation in the invalidating domain transaction;
both dispatch and invalidation lock the same exact fence before the intent.

**Exact fix:** “Commit the accepted membership change, required local evidence,
receipt and actual required producer-fence advancement/supersession coherently
through the qualified owner transaction. Only secondary projections and other
permitted downstream effects may wait on durable intent. A fence-update outbox
message alone cannot establish successful prevention.”

**Meaningful proof:** With the projection worker unavailable, accept a membership
removal and attempt later dispatch admission. The actual old producer validity
must already be unusable. Inject failure of required local invalidation and show
that membership is not falsely reported as accepted with protection missing. The
reverse ordering preserves already-dispatching truth. AC10/AC14 should distinguish
this from an optional notification or projection failure after a valid commit.

This requires qualification of the existing P27/P32/P6 adapter, not a new global
transaction coordinator or P27 permission to mutate unrelated producers' fences.
An unqualified outward lane remains disabled; independent native planning works.

### IR3 — Do not combine two Blackbaud list features into one documented claim

**Low severity; plausible evidence overstatement.** The initial External fact
paragraph attributes “additions/exclusions” to Managed Lists. The
[practice appendix](practice.md) establishes managed membership and its changelog
from that article, while explicit manual inclusion/exclusion behavior is cited
from a separate filter-list article. Those sources do not establish all of D24's
chosen exclusion/removal/return precedence in one comparator.

**Exact fix:** Describe Managed Lists as “manual membership changes and change
history independent of later source-filter changes.” Keep D24's precise exclusion
and return policy attributed to the selected product judgment and source owners.

**Proof:** Read back the revised main claim against the separately scoped source
rows. No new runtime test or external fetch is needed, and this does not change A.

## Other substantive checks

- **Alternatives and scope:** B fairly retains actual history; it is not caricatured
  as deleting requests when a filter changes. The no-build alternative and reuse
  of P9 discovery are credible. One appeal-owned membership is neither a second
  stored portfolio nor a generic Groups feature.
- **Finite groups and recovery:** Selected identities survive paging/filter drift.
  Ordinary Add cannot reverse a removed/excluded disposition, including an exclusion
  recorded before inclusion. Historical receipts remain distinct from current state.
  A deliberate Return rechecks current state and does not resurrect effects.
- **Identity:** Same canonical Party can participate in distinct appeals. Church,
  pastor, household, advisor and shared address are not identity shortcuts. Merge
  preserves origins; currently conflicting intentions block only the affected
  membership. A superseded old removal is not an eternal exclusion. Undo must
  respect later decisions, restrictions and source provenance.
- **History and permissions:** Removed supporters' real requests, late responses,
  qualified gifts and independent obligations remain governed facts. Recording past
  facts requires no current inclusion. Current source disclosure controls history,
  candidate/result counts, caches and exports; a recorded list is no frozen directory
  or permanent permission. Unknown/withheld coverage is not zero.
- **UX:** One main list, contextual actions, optional concise reasons, explicit
  selection scope and durable partial outcomes are adequate. No extra approval,
  per-row task, mandatory essay or repeated acknowledgment is introduced. Shared
  controls still require actual pagination, keyboard, mobile and recovery proof.
- **Coverage and operations:** All 22 categories contain a concern, qualitative
  grade, evidence/limit, effect on A, permanent R clause and AC mapping. Monitoring
  follows preventive gates; the stated thresholds are proposed operating triggers,
  not measured service promises. Actual workload and user comprehension remain
  release evidence, with no invented empirical result or extra founder question.
