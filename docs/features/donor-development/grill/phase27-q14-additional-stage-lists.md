## Founder question — A selected

**Should an organization be able to create additional approved stage lists, or
only customize the lists Asym supplies?**

A stage list is the set of stage choices available for a particular kind of
partnership work. Imagine two ministry teams in the same missions organization
using genuinely different approaches to developing support. Customizing one
shared list might serve both; in other cases it could become a confusing combined
list. This is an illustrative design scenario, not a verified universal ministry
practice or a claim that each team needs its own list.

**A — Allow additional organization-approved lists when needed (recommended).**
An organization can keep the supplied lists, customize them, and add another for
a meaningfully different process. Each partnership still uses one applicable list,
with the same recorded stage wherever that partnership is viewed by authorized
people. This adds flexibility and some configuration/reporting responsibility.

**B — Customize the supplied lists only.** Organizations can add, retire, rename
and reorder stages within Asym's supplied lists, but cannot create additional
lists. This reduces administration, while different approaches may need to share
a broader list and use guidance/direct stage choice to accommodate their differences.

**Recommendation:** A, with shared lists as the ordinary starting point and
additional lists available for a real organizational need. Stage choice remains
straightforward for staff; flexibility should not become a personal pipeline for
every staff member, a duplicate partnership or a workflow builder. This is a
product judgment, not measured evidence that more lists improve ministry outcomes.

- No extra approval queue, arbitrary scripts, private user pipelines, new model

  answer. “Approved” means the existing organization-governed configuration

  optional initial assessment, direct changes and tenant-safe reads/writes. Stage
  names/ranks cannot become automatic cross-list report equivalences.
- The resulting choice affects administrator setup, the options staff see when
  starting work, later changes and report grouping. No formal specification,
  implementation or next founder answer is inferred from this choice.
