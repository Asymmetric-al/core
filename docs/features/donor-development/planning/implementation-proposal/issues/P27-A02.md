## What to build

Build one native settings draft and authorized impact preview using supported code-owned criteria, named role scope, eligible deterministic targets and explicit order. Save is inert. Preserve authorized dirty input when versions change, show Settings unavailable on read failure, and expose explicit non-drag ordering. Evaluate first proved true before checking target; unknown earlier input or ineligible selected target stops with a safe explanation, never falls through. Preview keeps current and proposed facts distinct, shows protected/unknown/no-match outcomes and honest complete/calculating coverage.

## Context and contracts

The existing Support Hub AssignmentRulesForm is a different inbox round-robin product and overwrites local drafts from settings changes. It is not a D30 rule builder or approved fallback. Current legacy CRM service loads all tenant rows before in-memory paging; do not copy that for policy previews.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.

## Acceptance criteria

- [ ] AC27-A02-01: Given ordered overlapping rules, including a known-false predicate, an unknown higher-priority predicate and a first-true rule whose target is ineligible; When the source evaluates each case against current authorized input; Then Ordered overlapping rules produce the first proved matching rule; unknown earlier predicates and ineligible selected targets do not silently fall through.
- [ ] AC27-A02-02: Given candidate staff differ in Tenant, role eligibility, current access and supported target-resolution basis; When staff search/select or a rule resolves a receiving person, including an ambiguous multi-candidate result; Then Target choices obey current staff/role/tenant/source eligibility and qualified deterministic resolution; multiple candidates are not resolved by database order.
- [ ] AC27-A01-04: Given an authorized edited settings draft and an independently changing saved policy; When a background refresh returns a newer version or settings retrieval fails; Then Concurrent settings refresh preserves an edited authorized draft and shows conflict; unreadable settings never render as the saved default or authorize Auto.
- [ ] AC27-A07-01: Given a current assignment that is eligible, or a separate case with missing or ineligible current responsibility; When evaluation finds no rule, an unavailable required input or a missing or ineligible selected target; Then No match or missing target preserves eligible current responsibility and exposes a permitted reason/repair action; missing current responsibility is not called healthy.

- [ ] At least one genuine source-qualified supported criterion and target is exercised end to end, including overlapping predicates. The implementation documents the bounded catalog and forbids output-dependent cycles rather than inventing a general rule language.
