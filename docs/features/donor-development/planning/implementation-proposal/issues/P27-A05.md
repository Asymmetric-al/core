## What to build

Connect the exact source-owned affected-work predicate to representative transfer and its repair UI. A partnership lead, Request/task owner, commitment and care responsibility do not automatically move. When lawful work ownership remains valid, transfer may proceed without fabricated handoff chores. Where work would lose eligible responsibility, require the source-approved disposition or durable owned handoff. Exact pre-transfer acceptance gates the commit; a separately subsequent acknowledgment stays outstanding after lawful assignment plus durable intent. Staff departure/revocation immediately denies access while authorized source repair continues.

## Context and contracts

Current Mission Control task creation inserts task, links and event separately and its assignment helper defaults to actor-and-queue. Neither supplies a qualified source-owned D30 handoff contract. Source actions and Tasks Hub projection must remain distinct; no generic task Done means acceptance.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.

## Scope and non-goals

- No universal second-person approval or handoff wizard, distributed transaction to complete every obligation, automatic work-owner transfer, guessed successor/primary/queue, donor message or invented Website return/coordination policy.
