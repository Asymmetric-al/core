## What to build

Compact current/proposed/saved stage UI with nearby optional guidance; no mandatory note, approval, acknowledgment, unrelated custom-field completion, regression warning or rank-derived success styling. Stage-only normalized commands exclude unrelated fields, use current exact binding/revision/eligibility, reject stale ABA changes, preserve source history and durable receipts, and treat same-value as an authorized no-op. Real X→Z creates no Y visit; Z→X is a distinct later occurrence, not lifetime-deduped. First null→stage records actual acceptance time without invented prior unassessed duration. On paused work expose ordinary stage actions with permitted review context; save leaves pause/review/time/owner intact. Reopening retains authoritative stage/absence rather than the editor snapshot. Preserve source-owned next work and independent gifts, participation, consent and lifecycle; optional Studio failure cannot gate native stage save. Minimize current/history/receipt/log disclosure.

## Context and contracts

Staff can set a first stage, skip or return directly using advisory guidance, with one deliberate save and history of actual accepted changes only.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.

## Scope and non-goals

- No sequential advancement engine, compulsory missionary reporting, stage-derived donor worth or money, broad generic donor-profile patch, or closed-work editing.
- Catalog retirement interleavings are completed in P27-P17; no promise that this slice alone qualifies full catalog activation.
