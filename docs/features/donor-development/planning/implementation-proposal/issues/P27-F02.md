## What to build

Extend the same Request form/source with qualified Legal Entity and ISO currency, checked integer minor-unit amount, cadence, duration/horizon and explicit unknown/absence semantics. Store nonfinancial and narrow noncash intent without a financial tuple or asserted valuation. Keep authorized unsaved values reversible when switching type; confirm saved semantic changes through history instead of deleting prior financial evidence. Display currency/precision explicitly and reject invalid precision, overflow and irrelevant hidden fields server-side.

## Context and contracts

The canonical money primitive already exists on current develop; reuse it rather than adding a substrate ticket. Qualified representability does not authorize provider transactability. Finance context must be owner resolved, not inferred from browser locale or tenant default.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.
