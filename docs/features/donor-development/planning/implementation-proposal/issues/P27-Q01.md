## What to build

Provide a reproducible cross-source release rehearsal and resulting candidate-bound evidence. Use retained production-shaped synthetic cases after the source slices have implemented their own migrations: unknown assignment provenance, role collisions, nullable assessment, private old notes, incomplete financial intake, pending jobs and accepted new-model writes. Exercise compatible forward readers/constraints, bounded idempotent backfill interruption/resume, incompatible writer fences, feature disable, compatible rollback/roll-forward and backup restore. Demonstrate that source history, manual protections, pending physical handling, independent obligations and current disclosure boundaries survive.

## Context and contracts

Q11 is the common deployment contract. Domain slices own and test each migration/kill switch; this ticket proves their interactions across the released candidate. D30 Auto disable immediately fences uncommitted old generations and reenable is prospective. Old private notes cannot become shared history, old ratings cannot become zero, unknown assignment provenance cannot become managed, and imported intake cannot become money. The checked current CI exercises Postgres 15 whereas local Supabase declares 17; release evidence must identify and test the admitted deployment version.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.

## Scope and non-goals

- Implement every domain migration in one ticket.
- Destructive downgrade of accepted data or repair by routine direct SQL.
- Change upstream finance correction/attribution policy.
- Activate production or claim full-phase activation merely because a rehearsal passes.

## Acceptance criteria

- [ ] AC27-Q11-01: interruption and repeated resumable migration map each retained source once or preserve an owned ambiguous exception with source counts/reference checks; no transfer, disclosure, duplicate effect or invented fact.
- [ ] AC27-Q11-02: after accepted new-version writes, disabling admission and executing old queued clients/jobs fences incompatible writes while current-authority history and lawful recovery remain accessible.
- [ ] AC27-A12-01: disable Auto, compatible rollback and restore preserve manual protections, source lineage/history and independent obligations; no queued generation resurrects old authority.
- [ ] Record source/build/schema/policy/fixture/provider versions, exact commands, expected versus actual source counts, failure injection, restore outcomes and limitations. A failed or unexecuted scenario stays a gate.

### AC27-A12-01

**Requirements:** REQ27-A12, REQ27-A17.

**Given** a bounded pilot has accepted new assignments and protected manual choices under the new model; **when** operators disable automatic acceptance, roll back compatible components and restore retained state; **then** Pilot disable/kill switch, mixed-version rollback and restore after new writes retain history/manual protections, fence stale work and preserve independent obligations.

### AC27-Q11-01

- **GIVEN** legacy rows contain unknown role provenance, unmapped scope and protected notes.
- **WHEN** migration resumes after a simulated crash.
- **THEN** each retained source maps once or remains an owned explicit exception with no transfer, disclosure, duplicate effect or invented fact.

### AC27-Q11-02

- **GIVEN** new-version writes have occurred.
- **WHEN** the feature is disabled and old jobs attempt execution.
- **THEN** incompatible writers are fenced, accepted history and handling obligations remain accessible through current authority and a tested safe recovery path exists.
