## What to build

Compose an on-screen structured brief through authoritative source readers, with dates/provenance, permitted links, coverage and explicit unavailable/unknown states. Keep legal giving, recognition, commitments, actual exchange, outreach, Requests and next work visibly distinct. Do not make full future document/AI services prerequisites for ordinary preparation. When qualified document/export actions are exposed, enforce exact current source/document/retention/export authority and expiry; never create a local upload store, public link or duplicated editable transcript. Honor shared-history audience and optional-rating Off/current financial permissions in any reached derivative.

## Context and contracts

Existing CRM detail service composes legacy donors/donations/activities and caps child arrays; it is useful layout/read-model prior art, not a complete source-qualified brief. Existing tests use a Supabase fixture. No inspected current service proves the new source combination or privacy across history/finance/documents.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.
