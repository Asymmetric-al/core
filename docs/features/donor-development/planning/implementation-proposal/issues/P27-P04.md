## What to build

Extend existing qualified assignment/shared-work owner with explicit partnership and review responsibility meaning. Preserve separately owned Party representative and child task/request owners. Revalidate named successor and expected responsibility head, deny revoked access first, keep eligible explicit review assignee when partnership lead changes, and expose owner-visible zero/indeterminate needs-assignment recovery. No invented queue or creator fallback.

## Context and contracts

Authorized staff can hand off an exact partnership responsibility and find a truthful repair path when no eligible recipient remains.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.

## Scope and non-goals

- No new CRM identity, authorization engine, task/notification platform or shadow finance ledger.
- No duplicate implementation of already owned request, encounter, Party merge or finance command.

## Acceptance criteria

- [ ] Changing Party representative or ministry people does not silently transfer partnership, asks or review assignee.
- [ ] Authorized expected-head handoff records one successor generation and preserves history; losing actor/recipient eligibility does not release payload.
- [ ] Current explicit review assignee remains unless separately changed; predecessor access is denied on revocation.
- [ ] Proved-zero/indeterminate resolver exposes authorized repair without guessed admin, queue, profile or recipient.
- [ ] Responsibility changes confer no content, history, support, finance or contact permission.
