## What to build

Extend qualified single admission into a finite sealed human-reviewed canonical member set. Distinguish page/all-results scope using exact permitted coverage, freeze intended action and original authenticated Tenant context, and execute bounded members via existing durable executor. Recheck each member current authority/eligibility/revisions; source receipt owns outcome and progress. Persist accepted/reused/unaccepted/unresolved results and cancellation for only unadmitted members. Measure and declare selection/payload/concurrency/pagination budgets before release.

## Context and contracts

Staff know exactly which selected relationships will start or reuse work and can recover partial progress without replaying accepted effects.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.

## Scope and non-goals

- No new CRM identity, authorization engine, task/notification platform or shadow finance ledger.
- No duplicate implementation of already owned request, encounter, Party merge or finance command.

## Acceptance criteria

- [ ] Reviewed A/B never expands to later matching C, stale filters or changed page cache; selection counts truthfully distinguish page and all matches.
- [ ] Partial failure preserves independent accepted members and leaves failed members without partial source state.
- [ ] Dropped first response and progress-write failure recover source receipts before retry; duplicate transport does not create extra task/ask.
- [ ] Cancellation versus acceptance works in both serialization orders and never deletes accepted history.
- [ ] Tenant switch/revocation/source retirement is re-proved without retargeting queued work; oversize selection visibly rejects or partitions without truncation.

Primary source cases are reproduced below so the implementer can distinguish one slice's first-demonstration ownership from later composed regression proof. An AC whose multi-step scenario crosses a later producer must have that producer as a genuine blocker or its primary acceptance transferred explicitly; a mocked internal owner does not satisfy it.

### AC27-P04-01

**Given** staff review A and B while C is outside the selection, **when** C later matches or staff edit the saved filter and pages are evicted, **then** only the finite reviewed A/B intent can execute; source eligibility is rechecked without substituting a different subject.

### AC27-P04-02

**Given** a supported page selection and all-results selection have different sizes, **when** staff review either action, **then** the scope and count are honest and inspectable; loaded rows are never represented as all matches.

### AC27-P04-03

**Given** one member commits and another member fails before source acceptance, **when** the group completes or is resumed, **then** the first success remains and the failed member has no partial accepted source state; remaining permitted outcomes can be recovered individually.

### AC27-P04-04

**Given** a worker commits source acceptance but loses its progress write or first client response, **when** the same intent is retried, **then** source receipt reconciliation recovers one accepted effect and does not duplicate its ask/task or manufacture failure.

### AC27-P04-05

**Given** cancellation and acceptance contend for the same unadmitted member, **when** each valid serialization order is exercised, **then** accepted work survives if acceptance wins; cancellation blocks later admission if cancellation wins; no accepted history is rolled back.

### AC27-P04-06

**Given** a Tenant switch, permission revocation, source retirement or material source change occurs after review, **when** a deferred member executes or its result arrives, **then** original context remains fixed and current constraints decide the member outcome; stale output cannot populate the new context.

### AC27-P04-07

**Given** a group exceeds a qualified numeric capacity boundary, **when** staff submit it, **then** the system explains a rejection or explicit partition; it neither truncates membership nor starts an unreviewed replacement operation.

### AC27-Q13-01

- **GIVEN** a command partially completes downstream or a batch has mixed results.
- **WHEN** an authorized operator investigates.
- **THEN** the operator can distinguish accepted source effects, pending/rejected work and safe next actions without reading private narrative logs.
