## What to build

Whole-list availability is separate from stage retirement. Current binding defines retained work; past use is not future attachment authority. No ordinary deletion, forced migration or stage event. Explicitly treat required dependencies; jointly supported matching-default removal commits atomically, other-owner dispositions must be completed and revalidated. Allow genuine zero new-use lists without breaking retained work. Admission-first versus withdrawal-first ordering determines retained acceptance versus rejection, including each finite group member and retries. Restore does not restore old default/grants/tasks or move work back. Retained assessed or unassessed work may choose currently active stages; qualified same-work pause/resume/reopen preserves source binding and current stage/absence with no revived children. Authorized settings/current filters/history/reports retain records and helpful restoration/zero-choice paths. Unknown or hidden dependencies never leak through success/rejection.

## Context and contracts

Configurators can stop and restore new use of a list while existing assessed, unassessed and returning partnership work continues on its retained binding.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.

## Scope and non-goals

- No global journey scan, mass assignment rewrite, migration task, donor notification, hard delete or silent default substitution.
- This does not implement saved list transfer or retroactive backdated exceptions.
