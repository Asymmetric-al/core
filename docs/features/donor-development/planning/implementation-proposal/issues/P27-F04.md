## What to build

Version meaningful presented and revised terms and staff forecast separately, preserving original attribution/time. A fresh authorized command can identify an older actually presented version for late evidence; stale editing of a replaced current head conflicts. Show which terms the answer addresses and what changed. Preserve day-only/unknown dates without DST fabrication. Serialize competing revise/respond/close/owner mutations and changed-intent retry; delayed acknowledgments never replace newer facts.

## Context and contracts

Expected-head control cannot prohibit truthful late history: reread current state then deliberately target the older presented version. The fixed review-field basis will consume term identities, not incidental Request revision.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.
