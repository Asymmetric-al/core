## What to build

Maintain zero/one usual reference in exact qualified scope, independently authorized from admission and list discovery/use. Preserve explicit selections and deliberate draft clearing through late defaults/refetch. Complete eligible coverage alone can prove sole choice. Hidden or failed default reads do not disclose a relation, imply absence or block an independently valid explicit/sole choice. Select no stage and create no work/effect from defaulting. Start uses concrete visible IDs; late usual changes cannot retarget submitted/group intent. Settings set/replace/clear commands preserve trusted history and durable idempotency; reject changed payload/stale revision; clear only current matching dependencies during later qualified withdrawal. Current UI explains prefilled choice, alternatives, no-stage option and pending/error/unconfirmed outcome without diagnostic IDs or claiming suitability.

## Context and contracts

Configurators may set or clear one optional usual list; new work visibly starts from established valid intent, a proved sole eligible list or a permitted usable usual list, and otherwise asks.

Current authority, tenant/field/history-safe read and write behavior, atomic source history/receipt/required intent, truthful lost-response recovery and applicable two-session concurrency proof accompany this slice. Base UI/base-maia/Zinc, keyboard/screen-reader/mobile/zoom behavior and slow/failing network recovery accompany every reached screen. These are in-slice delivery obligations under REQ27-Q01–Q14, not deferred to final qualification. Terminal Q tickets prove composition and release evidence.

## Scope and non-goals

- No app/role/name/rank/personal-history/AI default inference and no compulsory default.
- Whole-list withdrawal/default-removal race and non-revival are proved in P27-P19; no speculative cross-owner repair engine.
