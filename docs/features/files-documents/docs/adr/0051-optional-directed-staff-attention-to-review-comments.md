# ADR-0051: Optional directed staff attention to an exact review comment

Date:2026-10-25, Asia/Bangkok.

Status: **Fully ratified by Conrad on 2026-10-26, Asia/Bangkok: Q51 A with all required amendments and the Document Review Attention Request glossary term.** Reviewed disposition: **Accept with required amendments**; the complete package is adopted.

## Context and alternatives

Conrad selected optional directed staff attention and requested clear, easy UX, current primary research and the full adversarial review. Q45 allows exact source comments but no implicit notification. P17 owns a common staff center but defers generic mention producers; the current bell is a demo. Existing qualified review coordination is the strongest simpler alternative. The selected path uses one saved-comment action and one colleague, preserving unaddressed comments and avoiding a rich mention editor, task per comment or new inbox.

The native-only result can be required as one compatible source/P6/P17 database transaction, avoiding an independent delivery queue/provider and ambiguous partial notification. Actual compiler composition and native recipient identity remain qualification obligations. The [full review](../../grill/phase29-q51-adversarial-review.md) contains22 categories,20 clauses,44 proof groups,24 lifecycle cases,32 journeys,seven budget families and six operating controls, with all evidence and exact owner amendments.

## Ratified glossary addition

**Document Review Attention Request:** A source-owned staff request to bring an exact Document Review Comment revision to one eligible colleague’s attention. It is distinct from the comment, notification presentation, review responsibility, access permission and evidence acceptance.

The exact definition is adopted as the31st canonical glossary term; all30 earlier definitions remain unchanged.

Preserve all independently owned required notices, Q45 comment behavior and custody. Regenerate declared OpenSpec projections at authorized publication; the incorporated full clauses are normative, not only scenario summaries.

The native implementation must satisfy C01–C20/P01–P44 and all lifecycle, journey, budget and control requirements. No current helper, isolated model, source flag or visible UI establishes native behavior, permission, cost or accessibility. A same-transaction effect is a required outcome, not a claim that separate SDK calls are atomic. A minimal interface cannot waive source or role correctness.

## Consequences

Staff can deliberately bring a colleague to an exact comment without assigning review or publishing discussion to participants. One-person/per-revision uniqueness avoids duplicate noise and keeps the data model small. A later genuine revision can be explicitly notified; unchanged-repeat nudges use a meaningful follow-up or existing review coordination. No sender recall is offered; actual scoped privacy correction remains capable. Tenant/recipient optional Off stops old unread without On replay, while independently lawful recent history obeys its original ceiling.

The capability requires real implementation of the qualified shared native destination, identity and transaction protocol. It creates no external transport dependency, but reads/writes/history have measurable platform cost. Existing contract ownership is retained; no unchanged-bill promise is made.
