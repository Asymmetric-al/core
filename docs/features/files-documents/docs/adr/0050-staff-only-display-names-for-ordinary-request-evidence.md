# ADR-0050: Staff-only display names for ordinary request evidence

2026-10-25, Asia/Bangkok.

Status: **Fully ratified by Conrad on 2026-10-25, Asia/Bangkok: Q50 A with all required amendments.** Reviewed disposition: **Accept with required amendments**; the complete package is adopted. Its conclusion requires no new glossary term; all 30 definitions are preserved.

## Context and alternatives

The founder requires useful identity-preserving rename and discovery. Q50 chooses who sees an ordinary staff-authored descriptive name, not whether bytes can be renamed globally. A is one optional current value shared among source-authorized staff on the exact evidence use; B would deliberately publish the same name into the eligible participant projection. B can reduce naming mismatch, but makes routine edits participant-facing content. Current source context remains sufficient for already clear files and is never blocked on naming.

Primary Dropbox Sign, Adobe, Blackbaud, Contentful, CRM/record-attachment and W3C evidence supports the tradeoff and small interaction, not a universal audience rule or measured Asym outcome. ## Ratified decision and amendments

For ordinary Private Document Request evidence, allow one optional staff display name per exact admitted source contribution/use, shared among staff currently authorized to see that field. It is organizational metadata, not a personal alias, a Q42 tag, an item or request title, a universal asset name, or a new document identity. The ordinary source owns the authored value and its history. General resources, public Media, Support, financial evidence and official artifacts retain their existing owners; this decision grants no generic rename power over them. Renaming is optional and never a prerequisite for receiving, finding, reviewing or otherwise lawfully using evidence.

Keep the staff display name out of recipient, public, donor, missionary and Q41 external-reader projections when those are acting in their narrower purposes. A person who also has a staff role does not carry that staff disclosure into a participant session. Apply current source/P12 field disclosure before matching, rank, count, ordering, suggestions, display, caches, errors, accessible names, document/browser titles, print/export, generated material or delivery metadata. Do not serialize a hidden name and merely conceal it in the UI. Independently qualified staff exports and staff history may include the field only under their own current purpose and disclosure rules. Existing source-approved participant identification remains authoritative for that surface; A does not create another editable recipient name or an audience toggle.

Preserve exact use/version/byte identities, digest, received attribution and chronology, instructions, correction relationships, accepted basis, currentness, request obligations, access, retention and source status. A name edit changes none of those facts, embedded document metadata, storage locators, original bytes or sealed outputs. Keep the authored staff name distinct from retained received-name provenance and qualified delivery names. Retain and reveal a received filename only when its source permits; never reconstruct a discarded or restricted name from a provider key, header, manifest or another use. A safer display name is not redaction of the original or removal of a harmful prior disclosure. Q44 original-download/member-name/manifest rules and already sealed packages remain unchanged; no staff name is substituted into delivery by a generic fallback.

Treat a proved absent optional name, a present name, and a name unavailable through failure or current authorization as different facts. Display a source-approved fallback only under its own current field permission, using permitted file/item/receipt context where original-name disclosure is unavailable. A missing projection is not proof of absence, and denial is not an invitation to overwrite or clear unseen content. Ordinary editing requires current authority to inspect the exact naming basis as well as to change it. A source-designated privacy/records remedy may address otherwise restricted content through its own qualified powers; no blind generic naming or database-repair fallback is created. Preserve independently permitted reading and source work during an optional naming outage.

Offer deliberate Set/Edit and Clear through the same small edit flow. An absent staff value is an empty optional input, with the permitted fallback shown as context rather than prefilled as authored text. Empty or whitespace-only input after the documented server normalization means Clear; cancellation changes nothing. A valid same-value save is a no-op only after current eligibility and the expected naming basis have been checked. No-op and cancel create no name revision, business event, notice or workflow activity, while independently required security/access evidence remains governed. Same-use changes of business status preserve the name. A new Q03 correction, Q28 supplied/reused/replacement use, Q47 re-offer candidate or Q49 successor evidence use begins without an inherited staff name; matching bytes, names, item membership or a carried folder cannot copy it. Later deliberate naming remains available under that new use's own authority.

Derive actor, Tenant, environment, active staff context, source purpose, timestamps and attribution from trusted server context. Validate the selected exact use and proposed value under the ordinary source's current P12 action and field rules. Read, reviewer responsibility, uploader identity, folder membership, creator ownership or staff rank alone is neither edit nor disclosure authority. Tenants allocate the qualified capability through existing role controls within classification floors. Do not add a mandatory administrator gate, second approver, per-file ACL, bespoke audience switch or independent policy engine for this routine metadata act. Source rules may permit naming an admitted Checking, rejected, accepted, historical, withdrawn, fulfilled, canceled or retained use; those states do not themselves grant permission, and actual source freeze, disposition and privacy restrictions still govern.

Validate a bounded single-line plain-text value through one documented server/client contract. Use the field for concise identification permitted by the source, not as a care-note, body-text or workflow-status store. Define finite stored UTF-8-byte and user-visible text limits, normalization/comparison units and safe error behavior before activation; do not borrow a filesystem filename limit without justification. Preserve meaningful international text and case, support Unicode/RTL/IME, reject or safely handle prohibited control/spoofing characters with intelligible feedback, and render the result as text with appropriate direction isolation. Do not silently truncate, transliterate, translate, parse markup, execute content, derive a path/query or require a unique name. Duplicate display names are valid and need permitted source/item/version context. Qualified file type/icon and actual source status remain independent of an extension-like suffix or a word such as Approved.

Use one source-owned Set/Clear command with an exact relevant naming revision or equivalent opaque expected-state token and current source/authority checks at commitment. A string comparison alone is insufficient after an A-to-B-to-A change. Unrelated source edits must not cause universal stale-form failures, but a concurrent restriction or required freeze must still fence the act. Order competing Set/Clear commands so a stale writer cannot silently overwrite later work. Commit the admitted value or absence, new naming basis, required restricted history and durable operation result coherently; also commit required local projection follow-through or use a proved bounded reconciliation equivalent. Failure to record required source history cannot produce acknowledged success. Keep external services outside this local atomic effect; no provider call is needed to change the name.

Tie retry identity to the original durable naming effect and its validated actor/tenant/source/use/material intent, not a transient transport or provider window. Recover an already admitted operation before treating it as a new edit, subject to current result-disclosure authority. Reuse with changed material conflicts; an uncommitted stale expected basis is rejected before a same-value no-op. A lost response, reload, duplicate delivery or restored old request cannot create duplicate history or restore an earlier name over a newer edit. Recovery distinguishes the original outcome from the current authorized display; late UI responses cannot replace newer current state. Preserve minimal deduplication/result evidence under the actual retention contract, or reject an unverifiable stale replay after readable history expires. Reapply, correction and any offered Undo are new deliberate current-authorized edits, never rollback of source history.

Use the staff name consistently in currently authorized ordinary-source file lists, details and qualified review surfaces, with a compact permitted received-file reference and item context where useful. Source-approved names may participate in Q38 matching only when separately admitted to that search field set. Keep projections derived and rebuildable; update or reconcile them without making the search index, shared view or browser cache a write authority. Restrictive field/source changes fence subsequent serving before cleanup. Do not let historical names enter ordinary matching by default, widen the corpus to body text, or claim complete fresh results from incomplete coverage. Preserve lawful focus, selection and return context by exact use identity when a rename changes sorting/filter membership; disclose honest current, unavailable or recovery state without keeping forbidden data visible.

Qualify the actual storage and every read/write path before using any existing metadata seam. In particular, a generic assets metadata object, browser collection, CMS filename field or public serializer is not automatically an ordinary source-use field or a staff-private store. Enforce required non-null immutable scope and tenant-aware typed relationships, at most one current optional name per use, valid bounded value/absence representation, and server-owned history attribution. Do not impose global/name/digest uniqueness or cascade optional-name removal into evidence or required history. Inspect actual schema/table/function grants, RLS old-row USING and resulting-row WITH CHECK behavior, policy composition, SELECT/RETURNING/upsert, views, owners, triggers, workers, service roles, imports, restore and alternate APIs. Public tenant tables must follow the current ENABLE+FORCE and real-policy-or-reviewed-deny-by-default contract and applicable owner constraints. FORCE does not constrain superuser/BYPASSRLS or supply source authorization; an allowed metadata edit must not retarget tenant/use/version, recipient, author, approval or lifecycle. No finance/money schema changes are introduced.

Keep restricted attributable naming history separate from technical logs and from immutable receipt facts. Record the actual actor/context, exact use, time, ordered naming change and durable outcome required to explain or recover an edit; retain old/new values only under the source's applicable history purpose and retention rules. History readers require their own current permission. Do not convert changing a name into rewriting old receipts, messages or the evidentiary meaning of an earlier event. General logs, analytics, traces, error reports and crash capture exclude name text, received filenames, private associations and content; protected diagnostics can use governed opaque references. Apply owner-directed minimization, disposition/holds and current restrictions to current values, history, caches, indexes, exports and restored copies. Retention is neither perpetual readability nor permission to resurrect removed text.

Use Core's shared Base UI/base-maia controls and existing file-detail/row-action composition. The ordinary action is Edit staff display name; label the input Staff display name, mark it optional and explain that it is shared with authorized staff while recipients keep their source-approved name. Provide Save name and Cancel, and make clearing understandable as returning to the permitted default name. Keep a permitted received reference separate and readable where useful, without requiring a preview or an original-name disclosure. No mandatory reason, repeated confirmation, new approval workflow, dedicated naming screen or compulsory naming convention is introduced. The persistent edit action provides mistake recovery. This decision introduces no new naming-notification purpose; independently qualified existing effects keep their existing contracts and cannot use the private field as an unauthorized payload.

Make acknowledged saved, saving, failed, conflict and unknown-result states distinct. Preserve lawful input and return context on recoverable failures; do not silently dismiss an unsaved meaningful edit or present a canceled network request as proof that the server did not save. On conflict, retain the user's lawful proposed value, show only currently permitted current context and require a deliberate new edit against the fresh basis; do not overwrite automatically. Announce material status accessibly without unnecessary focus movement; a toast is not the only recovery path. Restore focus to the invoking control or a meaningful stable fallback if the row moved/disappeared. Support keyboard and single-pointer operation, touch, screen readers, speech input, 320-CSS-pixel form reflow, zoom, long names, RTL/IME and low-bandwidth interruptions. Full names and essential actions must not depend on hover. Localize controls and date/time presentation, not authored names automatically. Fence stale responses/private input on actor, tenant, purpose or authority changes; no silent offline mutation replay or new durable private browser store.

Implement the smallest source/API/metadata/query/UI change that satisfies these outcomes. Reuse compatible mechanics without importing their broader audience, mutable ownership or provider semantics. No new vendor, parser, OCR, AI naming, translation engine, alias-per-user system, naming template language, mandatory Realtime, byte-copy workflow or generic metadata-schema platform is required. Bound server input, result/history paging, queries/indexes, per-tenant work, retry/reconciliation and retained metadata. Measure realistic sparse/dense use cohorts, international names, updates and concurrent readers against existing approved infrastructure; declare finite budgets with units and accountable release owners before activation. Native metadata is not free, and this review claims neither a latency improvement nor unchanged Vercel/Supabase bills. Optional naming must not become a new dependency for lawful receipt or independent source work.

Roll out additively after a retained-data and consumer/writer census, exact ordinary-source mapping, native effective-role proof and compatible source reads/writes are qualified. Initialize no authored staff value unless an actual source-qualified existing fact justifies it; use the permitted fallback without duplicating filenames into a new authority. Do not infer private names or audiences from provider paths, freeform asset metadata, body content, shared bytes or specialist titles. Fence mixed-version generic serializers and direct writers before admitting private values. A scoped stop disables affected naming writes or unsafe projections while preserving admitted source facts, restricted history and lawful independent work; qualification failure does not justify adding broad grants or switching to an admin client. Restore applies later privacy/disposition/revocation facts before serving, and rollback must retain admitted metadata or use supported roll-forward repair rather than discard it.

Validate staff recognition and the staff-to-recipient identification journey using currently permitted references; comparator documentation is not measured Asym usability evidence. ## Consequences

Staff gain clearer organization through one optional field; recipients keep their source-approved identification. Separate permitted received references resolve naming mismatch. Clear is useful, not a validation error; missing/hidden is not absent. Original evidence, acceptance, byte version, shared links and sealed outputs stay stable. A correction/new use does not inherit a title automatically. Recovery uses current source commands and durable original outcomes; it never silently overwrites later work.

No new provider, naming engine, personal alias, audience switch, bulk transformation, notification purpose, automatic title generation or universal metadata schema is required. The small feature still needs real private projections, concurrency/replay and accessible recovery, with actual resource/retention budgets rather than a free-operation claim.
