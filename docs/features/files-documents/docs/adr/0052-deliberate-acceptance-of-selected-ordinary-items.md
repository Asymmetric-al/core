Date:2026-10-26, Asia/Bangkok.

## Context and alternatives

The [researched question](../../grill/phase29-q52-question.md) left optional selected-item acceptance versus individual acceptance only. Conrad selected A, emphasizing current practices, excellent UX and restraint. Q21/Q22/Q24 explicitly left bulk acceptance open. Grouping already-reviewed decisions can reduce repeated actions, while individual-only acceptance has simpler scope/conflict behavior. No measured Asym frequency or benefit is claimed.

The [full review](../../grill/phase29-q52-adversarial-review.md) contains all22 category outcomes, exact16-clause decision,36 proof groups,24 lifecycle distinctions,28 journeys,six budget families and five residual controls. Current adjacent task code/security gates do not qualify a native acceptance transaction. No new glossary term is needed; Document Request Item Acceptance already names the business fact.

## Ratified decision and amendments

**Q52-C01 — Scope.** Adopt Q52 A: currently authorized staff may deliberately Accept selected items within one eligible unfinished ordinary Private Document Request, while individual Q21 Accept remains available. Each selected Document Request Item receives its own exact source-owned acceptance. Several supporting files for one item remain one item decision. Ordinary items using independently qualified Q28 staff-supplied evidence remain eligible under their actual source rules; no source-origin conversion or additional staff evidence power follows. This is optional action grouping, not automatic acceptance, application/financial approval, publication, a new assignment, bulk Request changes/waiver/cancellation, cross-request approval or a generic batch platform. Existing tenant roles and actual source policies govern eligibility; do not add an admin-only gate, personal reviewer claim, compulsory second reviewer or separate settings matrix. No new glossary entity is needed.

**Q52-C02 — Explicit selection.** Start with no items selected. Use a nonempty finite explicit set of unique item identities and their reviewed relevant bases within one Tenant/environment, request and source purpose. Reject empty, duplicate, conflicting, malformed or over-limit submitted sets without business effects; cosmetic ordering does not change semantic intent. Preserve deliberate selection within the same request across sorting, filtering and paging, always with a visible total and reachable View selected summary. If a select-all control is offered, it selects only the eligible displayed rows at that instant; name its scope. Deselect shown affects that finite scope; Clear selection clears the whole local set. Never include all matches, unseen pages, future uploads or newly eligible rows implicitly. A changed or newly restricted member cannot be silently replaced or dropped to submit a smaller set; preserve only currently disclosable selection context and require deliberate repair.

**Q52-C03 — Real review.** Each new acceptance retains Q21's sufficient human inspection, complete source-relevant evidence set, current requirement/instructions, required technical safety/admissibility and source review basis. Selection is inclusion intent, not proof of review; receipt, a clean scan, filename, thumbnail, OCR/AI, preview opening, dwell or download telemetry are not substitutes. Do not add per-file approval, compulsory preview/download clicks, a blanket essay or routine second confirmation. Unsupported preview may use an actually sufficient, currently authorized qualified inspection path, including accessible content; controls alone do not make inaccessible documents reviewable. Required unknown or failed safety proof blocks acceptance. Q23 same-evidence reassessment remains possible with an actual per-item resolution of the earlier concern; no blanket comment may silently clear distinct unresolved concerns.

**Q52-C04 — Authority and identity.** For an action admitting any new decisions, the same actual staff actor must currently hold the source/P12 acceptance power for every selected member and all required source context. Read access, Q24 responsibility/team coverage, a task, folder, label, template, participant grant or role title alone is insufficient; do not union several humans' rights. Preserve actual specialist/separation-of-duties rules without inventing a universal one. Q25 original-issuance readiness is not a repeated gate for each review action. Resolve Tenant/environment, native staff principal and context, accepted-by, source time and audit attribution from trusted server authority, including qualified no-Party staff; no fabricated Party or email/name matching. Caller-supplied expected IDs/bases express intent, not authority. Re-prove required current policy and access dependencies at admission; unresolved proof fails closed. Exact result disclosure and fresh action authority remain distinct checks.

**Q52-C05 — Basis and ordering.** Bind each selected item's actual source, requirement/instruction, complete evidence, relevant review/clarification and continuing authority/admissibility dependencies. Preserve Q03 correction, Q23 Request changes/resolution, Q28 staff-evidence admission/removal when it changes the relevant evidence basis, Q30 clarification, Q33 No longer required, Q34 cancellation, Q36 published additions, Q37 revisions, Q45 source-relevant comment admission, correction, location change, withdrawal and Restore and Q47 withdrawal ordering. Expected relevant revisions detect intervening away-and-back changes; equal displayed content/bytes/status is insufficient. Use the owning structural review-context rule, not a new semantic-importance classifier. An unrelated name, folder, comment or other item change is not automatically an acceptance conflict, but real aggregate dependencies must participate. Correction/withdrawal first fences predecessor candidacy; acceptance first retains its existing source consequences. No stale proposal silently rebinds to a successor, waives a concern, revives evidence or reopens a terminal request.

**Q52-C06 — Existing decisions and no-op.** Partition the frozen selected set at the authoritative boundary into exact independently accepted, still-applicable items and items needing new decisions. Existing recognition requires the same complete selected meaning and a presently authoritative Q21 acceptance. Exempt only the review-head advance caused solely by that matching acceptance; changed evidence, instructions, relevant concerns or other dependencies still conflict. Historical rows or an Accepted badge alone cannot satisfy this check. Preserve original reviewer/time/basis. If all members already match, return a clearly no-new-work Already accepted reconciliation under current source/result disclosure, even if actual fulfillment has since occurred; create no acceptance, fulfillment transition, notification or reopening. If cancellation, an adverse source state or lost applicability prevents current recognition, show only the lawful closed/unavailable or historical outcome; never promote historical acceptance to present satisfaction. A permitted technical receipt is not a business decision. If a terminal source state wins while any new decision remains, admit none. Other prior accepted facts remain true even when this action fails. Reuse Q21's real current applicability/review identity; a permanent bytes-only or item-plus-digest key must not block a later source-qualified Q23 reassessment on unchanged bytes. Q52 adds no invalidation or Undo power.

**Q52-C07 — Coherent source command.** Admit the selected action through one qualified operational source command in packages/api. In one real enclosing database transaction commit all new selected item acceptances, required authoritative current-state changes, immutable attribution/history, durable original-operation result and required durable follow-through intent; otherwise commit none of those new facts. Do not implement best-effort per-item loops, hidden chunks, independently committed SDK calls, compensating unaccepts or an externally asynchronous batch-approval job. Coordinate the existing request aggregate and relevant item/policy dependencies with a proved protocol, stable lock order and bounded retry; never a whole-Tenant lock. Revalidate the intended bases after relevant waits and on every transaction retry without rebasing intent. Keep expensive inspection, file processing and providers outside locks. A transaction is necessary but its existence alone does not prove correct isolation or authority. Required intent is not provider delivery success.

**Q52-C08 — Original operation recovery.** A matching committed original operation is recovered under current disclosure before fresh-work lifecycle/eligibility checks, returning its original attributable outcome without new decisions or effects. Scope its identity to the trusted actor/context, Tenant/environment and source; reusing it with changed immutable selected meaning hard-conflicts. Different operation keys or overlapping reviewers cannot duplicate Q21 acceptance effects. After unknown commitment, reconcile that original operation before a reduced selection, successor basis or new-key submission; browser abort, timeout or navigation does not prove rollback. Bound transparent infrastructure retries to the same intent and re-prove current dependencies; never silently retry a business conflict against new evidence. Preserve minimal lawful replay evidence or explicitly reject unverifiable expired commands; retention, deployment and restore must not turn old work into fresh acceptance. A successful response followed by failed refresh remains known source success.

**Q52-C09 — Fulfillment and effects.** Q22 alone owns the complete authoritative fulfillment predicate, including relevant hidden, non-file, optional and remaining work. Evaluate or durably arrange its evaluation after the new item decisions through the same qualified source ordering; durable required follow-through is committed with those decisions. Item acceptance may be known while fulfillment follow-through remains unresolved, and recovery needs no new business approval. Do not infer fulfillment from selection count, filtered rows or an empty query, add a Complete button, backdate actual F or erase known acceptance when a projection fails. Explain the qualified possible end-of-work/access consequence inline before commitment, without a stale promise. Independently authorized staff review after participant expiry does not renew access. Existing Q27/Q40/Q48/Q51 and other qualified source effects retain their own purpose, current utility, stop and dedup rules; Q52 creates no new email, reminder, attention cue or task per accepted item and does not blanket-suppress existing required effects.

**Q52-C10 — Interaction and outcomes.** Use existing shared Base UI/base-maia components and semantic tokens. Keep contextual individual Accept direct. The collective path adds labeled selection, concise item/current-evidence context, View selected, Clear selection and Accept selected (N), without a compulsory new page or routine extra modal. Final activation expresses the staff decision for each selected item needing new acceptance; exact-existing acceptances are separately recognized without new attribution. Do not represent selection as review completion. Clearly distinguish locally selected, submitting, committed new decisions, existing exact decisions, known no-new-effect failure and unknown outcome. Known failure copy may say No new acceptances were saved by this action; never None are accepted when independent decisions exist. Mixed success readback reports newly accepted and already accepted separately under current disclosure. All-already says No new acceptances. Unknown says the result is still being checked and supplies original-operation recovery, not an ordinary new Submit action. Preserve lawful notes, reading position, focus and selection through recovery; prevent late responses crossing an actor/Tenant/request switch. After confirmed success, accepted items may leave active selection while persistent permitted results remain reachable; do not clear unknown work or jump to a guessed next item. Recovery must not unnecessarily freeze unrelated independently lawful work.

**Q52-C11 — Privacy and accessibility.** Apply current field/source/role restrictions to every row, name, count, selected-summary entry, reason, receipt, history, cache and export. A blocked batch must not reveal a newly hidden item's identity, membership or private review details; withhold exact counts when those would disclose forbidden facts. Do not weaken authority merely to explain the error. Clear protected client presentation on context/access loss and require current checks for readback; a saved result is not perpetual access to evidence or old private content. Participants see only independently authorized source status and remaining work, never staff selection, internal concerns or coordination. Qualify keyboard/screen-reader/speech/touch, mobile/reflow/zoom, long international names, RTL/IME and weak-network journeys, including actual inspectable document content. Checkbox Space and IME/suggestion Enter must not accidentally submit. Reflow the action controls and summary at 320 CSS pixels for vertically scrolling content; document/table layout exceptions do not justify clipping acceptance controls. Keep sticky actions from hiding focused controls and announce meaningful outcomes without flooding. No hover-only controls, color-only state, unexpected focus jump, unapproved offline queue/private device cache, new name/address/account step or implied translation/OCR support.

**Q52-C12 — Database invariants.** Use real same-Tenant/request/item/evidence relationships, non-null trusted scope and attribution where required, valid-state constraints, stable foreign keys and uniqueness for the existing source acceptance and original-operation meanings. Keep immutable historical decision fields protected from UPDATE/UPSERT/MERGE/delete replacement; preserve lawful deletion/anonymization/tombstones without cascades that erase other owners' history. Current applicability is distinct from historical truth and is maintained only through its owner. Prefer bounded references to existing evidence/revisions over copying bytes or private bodies into batch records. Derive counts from the exact set and use trusted source instants after relevant waits, not browser/upload time or a stale transaction-start clock. Verify table/column/schema and EXECUTE grants, default/inherited/PUBLIC privileges, USING/WITH CHECK composition, SELECT/RETURNING, views, function overloads/owners/search paths, triggers and real anon/authenticated/service/NHI/operator/guard/browser/CMS/GraphQL/worker/import/restore paths; enforce the same boundary or close the door. FORCE does not constrain superuser/BYPASSRLS; SECURITY DEFINER depends on its actual owner, and omitted WITH CHECK may inherit USING. Retain one fine-grained P12 policy authority with prescribed coarse Tenant RLS. No allowed mutation can move scope/actor/owner/basis to a forbidden state. This introduces no money amount or new precision requirement.

**Q52-C13 — Bounded resources.** Before activation bind numeric positive finite limits, units and evidence for selected count, command/result bytes, indexed proof-query work, statement/transaction/lock/retry budgets, aggregate follow-through/reconciliation age and retained operation/history storage. The full review’s finite release budget table defines what must be measured and enforced; no unset value, silent truncation or unbounded tenant-history scan is permitted. Preserve P12's existing exact protected-read/audit limits and exceptions; use bounded stable keyset pagination with a unique tie-breaker where results span pages. Prove boundary and production-shaped tenant/concurrency cases, including actual P12 policy cost, source aggregate reevaluation and no N-per-file byte fetch. Over-limit actions explain a deliberate smaller set or individual route; do not silently split one intent. Tenant fairness/rate controls reuse qualified platform controls. No new provider, per-click polling engine, broad realtime subscription, extra database instance or free-bill promise follows. Byte inspection remains separate from compact decision metadata, but cost still depends on actual workload.

**Q52-C14 — History and repair.** Preserve durable per-item actual actor/context, complete reviewed basis, decision instant, original operation grouping/outcome and required follow-through evidence. Existing accepted items retain their own attribution; the current batch caller does not become their reviewer. Source business history, security audit, technical traces, UI status and provider observations are distinct. General logs/metrics contain safe IDs/reason codes and bounded timings, not file/comment bodies, tokens, names or sensitive ministry/location data. Apply actual purpose retention, holds, authorized exports and backup/restore restrictions. A departed reviewer alone does not erase lawful decisions; actual continuing source dependencies still control applicability. Mistaken local selection can be cleared; committed mistakes use the existing source-qualified remediation and retained adverse history, never a universal Undo, fake new upload or direct database repair. The activated cohort must have an actual capable source/privacy remediation route with independently authorized and attributed operators; a powerless contact label is insufficient. Owned replay/reconciliation must handle delayed local follow-through without second approval.

**Q52-C15 — Rollout and stopping.** Roll out additive compatible source/schema/readback support before exposing the collective UI. Every admitted writer must use the qualified basis/currentness and aggregate protocol; old unsafe paths must be fenced, not left as a bypass. Qualify old/new client/schema combinations and actual upgrade/restore cases. Do not backfill human decisions from scan/task/legacy accepted flags or infer complete batches from old partial operations. A scoped kill switch may stop NEW batch admission while preserving disclosure-authorized original-result recovery, existing decisions and required follow-through; the individual route remains only where independently safe. Disabling UI is not rollback, and destructive schema rollback after decisions exist is forbidden. Roll forward or use a proved data-preserving downgrade; restore reconciles retained effects/restrictions rather than re-emitting them. Enforce current repository security gates plus actual source-specific SQL/concurrency/browser proof; passing a catalog/call-site gate cannot replace those tests. Use the actual approved source/guard path; do not add a new unrestricted service client or move code into an exempt directory to pass the gate.

**Q52-C16 — Owner adoption and proof.** Record Q52 A as fully ratified with the complete required amendment package adopted. Q01–Q52 are ratified; all31 glossary definitions remain unchanged. At authorized specification publication, narrowly replace Q21/Q22/Q24's bulk reservation for this within-request action, incorporate the exact Q52-C01–C16 and Q52-P01–P36 obligations into the ordinary source contract, then reconcile source/P12/P9/custody/Workflow bindings and declared OpenSpec projections together. Preserve every unrelated owner rule, specialist policy and existing stage boundary. Bind design/tasks/tickets/tests/release evidence to these identifiers; no generated-only amendment or task checkbox can prove native behavior. The package's decision, lifecycle, journeys, budget gates and monitored controls are one adoption unit. No new domain term is proposed: Document Request Item Acceptance already names the business fact; selection and operation grouping are interaction/recovery concepts.
