# ADR-0053: Staff uploads of new ordinary document evidence

Date: 2026-10-26, Asia/Bangkok.

Status: **Fully ratified by Conrad on 2026-10-26, Asia/Bangkok: Q53 A with all required amendments and the exact existing glossary refinement.** Reviewed disposition: **Accept with required amendments**; the complete package is adopted. Q01–Q53 and all 31 glossary definitions are ratified; only “existing” is removed from Staff-supplied Document Evidence, with all 30 other definitions preserved.

## Context and alternatives

Q28 admits eligible exact files already held in qualified custody. Conrad selected direct staff upload of new local files into eligible ordinary items, preserving flexibility and proportionate UX. The strongest alternative keeps all new-file intake recipient-led while staff reuse existing files. That has fewer intake writers but can require a repeated recipient transfer where legitimate staff assistance is sufficient. Personal source requirements remain under both alternatives. No measured Asym frequency, efficiency or cost benefit is asserted.

The [complete review](../../grill/phase29-q53-adversarial-review.md) contains the complete exact amendment/proof package, all 22 category outcomes, current source and primary comparisons, lifecycle/journey/operational requirements and independent reviews. ## Ratified decision and amendments

**Q53-C01 — Bounded staff supply.** Allow currently authorized staff to upload local files new to qualified Asym custody directly to an eligible Document Request Item in an issued unfinished ordinary Private Document Request as Staff-supplied Document Evidence. Explicitly extend Q28's ordinary staff-admission meaning to this new-byte cohort, retaining existing-file reuse and recipient intake. Source eligibility, actual tenant roles and qualified restrictions govern; do not add a universal admin-only gate, second reviewer, tenant settings matrix or new permission engine. Possession, reading, task assignment and reviewer status are not upload/admission authority. New to custody means neither fresh nor authentic. Preserve personal statements, signatures, consent, freshness and specialist duties as real independent requirements.

**Q53-C02 — Trusted identity and truthful provenance.** Derive Tenant/environment, native staff principal/context, source ownership, attribution and source occurrence from trusted authority, including qualified no-Party staff. Caller-selected target and expected bases express intent only. Bind the exact item/requirement/subject/purpose and immutable received version. Record the actual staff contribution and real durable request receipt; never fabricate a participant-attributed upload, Submission Confirmation, affirmation or approval. Verified private storage may exist before admission without being a request receipt. Use trusted source occurrence evidence sampled after relevant waits in the transaction that commits; do not require an unknowable future commit timestamp. Actual source receipt/admission time is not browser start, external email date or file metadata; do not backdate participant timeliness. Historical valid supply survives staff departure alone, while applicable continuing restrictions remain enforceable.

**Q53-C03 — One deliberate contextual action.** In the eligible item, offer Upload file beside Add existing file. Show currently disclosable recipient/item/instructions and selected-file identity before Upload and add. Use one deliberate action to authorize preparation, transfer and finalization of that exact intended addition; no routine second completion click, modal, essay or account. Local selection is removable without a business effect. A browser may stage only through an already qualified private purpose-bound session; it cannot imply source admission. Preserve meaningful existing draft/selection state only while lawful. If permitted metadata cannot safely distinguish the intended target/file, require a capable safe selection route; neither a blind add nor broader disclosure is acceptable. Changed target, bytes or relevant basis requires deliberate repair, not silent retargeting or acceptance of new terms.

**Q53-C04 — Private qualified intake.** Reuse the shared custody session bound to actor, Tenant/environment, source/item/purpose, immutable target, relevant revisions, finite type/byte/count profile, expiry and semantic operation identity. Record bounded technical attempt/generation identity before issuing provider effects; unknown grant issuance is reconciled and accounted for rather than reissued without limit. Clients cannot set authority, classification, readiness, visibility or overwrite policy. **Q53-C05 — Seal bytes and fence late writes.** Prove that admitted exact bytes cannot be overwritten or retargeted by the upload grant, another writer, retry or delayed completion. Source cancel/revocation, browser abort and token expiry are distinct from closure of all admitted in-flight writes. It must fence finalization/reference creation, preserve covered obligations, and establish closed write authority plus settled in-flight work before safe final disposal; no delete-on-catch, token-expiry-only deletion or empty-visible-use inference. A cleanup lease expiring does not reopen promotion while its physical delete may still finish; retain the exact delete-generation fence until the original outcome is safely reconciled. Use supported provider deletion for bytes, not SQL-only deletion of storage metadata. One qualified adapter can satisfy this; no compulsory second store/copy or global lifecycle engine follows.

**Q53-C06 — Coherent source admission.** After required verified receipt, one authoritative source command atomically commits the exact staff contribution, source membership and relevant evidence revision, required custody reference/retention protection, truthful receipt/attribution/history, original-operation result and durable required follow-through intent in the actual co-located database transaction. ## Ratified existing glossary refinement

**Staff-supplied Document Evidence**:
An exact file version deliberately supplied by authorized staff for a
Document Request Item, with attribution to that staff act. It is distinct from
a participant's submission or affirmation, item acceptance and permission for
other uses.
_Avoid_: submitted by the participant, copied approval, reused consent, file ownership

Exact delta: remove the single word **existing** from the current definition. Newly uploaded versus already-held intake is explained in C01–C09, not inserted as implementation detail into the glossary. Submission Confirmation already names durable exact source receipt and needs no new definition. The canonical glossary now adopts this exact single-word refinement; all 30 other definitions are preserved.
