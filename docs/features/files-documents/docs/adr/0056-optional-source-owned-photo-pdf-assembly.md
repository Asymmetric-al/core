# ADR-0056: Optional source-owned photo-to-PDF assembly

Reviewed 2026-10-26. **Fully ratified by Conrad on 2026-10-27, Asia/Bangkok: Q56 A+B with all required amendments and the complete glossary package.** Q01–Q56 and all 32 glossary terms are ratified grooming intent. Research and one Q57 question are authorized without inferring its answer or implementation.

## Context and trade-off

Direct photo/prepared-PDF intake is the simplest complete baseline. Conrad also chooses optional in-task composition. A retained exact original and its transformed output need different identities; receipt, correction, withdrawal, review and disposal must operate on a coherent source unit. Browser-only claimed lineage and an avatar cropper cannot establish this contract. No full scanner platform is needed.

## Ratified decision and amendments

**Q56-C01 — Combined choice and narrow scope.** Retain complete source-qualified camera/photo/file intake, including separate photos and an already-prepared PDF, and add optional Combine photos into a PDF for one eligible ordinary Document Request Item. A+B selects the additional composer and supersedes the researched A-only exclusion; it does not require composition for ordinary uploads. The actual recipient and Q53 staff-supply routes remain distinct. Existing source format, purpose, cardinality, personal-evidence, statements, access and acceptance restrictions still bind. No resource publication, official-document generation, general drive, cross-item merge, historical library editor, signature, OCR, automatic crop/enhancement, redaction or existing-PDF merger is selected. A source requiring unchanged images does not accept a PDF merely because Asym can create one. Availability follows the actual source capability and qualified processing profile; no new tenant scanner-policy builder or mandatory PDF default is needed.

**Q56-C02 — One understandable preparation journey.** Keep Upload files as the short ordinary route and provide the discoverable optional Combine photos into a PDF in the same item context. Offer Choose photos and, where supported, Take photo; camera/gallery differences must not block the qualified file route. Show the exact permitted target, ordered page list, Not submitted yet and a concise notice that the selected original photos are retained with the submission under its source policy. One deliberate Create PDF and submit, or staff Create PDF and add, may authorize preparation transfer, generation and final source admission for that exact intent and required statements. Do not auto-submit from selection, capture, blur, reordering, rotation or a processing callback. No routine second confirmation, forced opening of every photo or compulsory generated-PDF preview is required. An optional qualified preview may help inspection. Show known preparation/upload/finishing stages truthfully; source receipt is reported only after C07. Preserve safe list/item context and input on return/error without preserving stale authority. A device-prepared PDF follows ordinary file intake and has no invented custody of unseen original photographs.

**Q56-C03 — Small complete page controls.** Permit one or more valid still-image page occurrences within finite qualified limits; zero or any unresolved selected page prevents submission of the intended composition. Provide Add, Remove, Replace/Retake, Move up/Move down or equivalent accessible ordering, and clockwise quarter-turn rotation. Drag can supplement but never replace keyboard and single-pointer controls. Use stable page-occurrence identities and an explicit order, not filenames, language sorting or upload completion order. Distinct occurrences may deliberately refer to identical image bytes; never silently deduplicate. Reject duplicate occurrence identities or ambiguous positions. A canceled/failed retake preserves the prior local page until replacement succeeds. Normalize qualified intrinsic orientation once, then apply explicit rotation; four quarter turns normalize to the original intended orientation. Preserve full intended image coverage and aspect ratio without silent clipping, assumed A4/Letter cropping or automatic color enhancement. Do not silently omit failed pages, make an empty PDF, or substitute a smaller page set. Removing the last page returns an understandable empty preparation state.

**Q56-C04 — Qualified formats and fidelity.** Use one closed, versioned processing profile with actually supported still-image formats and finite input/output/page/pixel/frame limits. JPEG/PNG are practical candidates, not an untested all-variant guarantee; HEIC and other camera formats require actual decoder, orientation, safety, color and fidelity qualification before advertised support. Reject unsupported animated/multiframe inputs rather than silently taking one frame. File extension, caller MIME, image/\* and successful browser preview are insufficient validation. Qualified representation/compression must preserve source-required legibility, color and full content; originals remain unchanged, and neither smaller output nor lossless processing is promised without proof. State the actual source/profile limits before selection and give per-page repair. A format rejected by the composer may still use independently permitted direct intake through deliberate user choice. No public converter, forced cloud account, additional device or paid scanner is a required fallback. Where no suitable route exists, an actually capable authorized source/staff accommodation is required; a powerless Contact support handoff is failed journey qualification.

**Q56-C05 — One Document Assembly and truthful provenance.** A Document Assembly is one source-owned contribution binding the selected exact immutable image originals, the ordered page occurrences and declared transformation recipe/profile, and a separately identified exact immutable PDF output. Each selected input remains a Submitted Original where the participant submission contract applies; the generated output is labeled Assembled PDF, never Submitted Original. Staff inputs/output retain actual staff-supply origin. The assembler admits one contribution/candidate, not a new request item or an independent contribution for each internal page. P29 owns byte/version identity, integrity, processing custody and lawful disposition; the requesting source owns admission, current candidacy, correction/withdrawal, review and fulfillment; P4/P12 owns identity and current authority. Recipe/order and output are authoritative for that exact assembly only; thumbnails, client state, search and projections cannot rewrite them. Preserve the required original inputs, exact admitted output and lineage for their actual source obligations. This does not retain every abandoned retake or promise indefinite photo storage. The admitted PDF is evidence output, not a dispensable D32 preview: the preview's 24-hour rule cannot delete or silently regenerate it. A recipe alone is not backup of exact admitted bytes.

**Q56-C06 — Trusted bounded generation.** Produce the authoritative output through a qualified trusted processing boundary from verified immutable private input versions and the accepted ordered recipe. Before generation, independently verify actual stored input identity, completeness, content, size and integrity, with every write capability closed or fenced; a client callback or claimed digest is insufficient. Browser previews and proposed manifests are untrusted; a client-generated PDF plus claimed hashes cannot establish correspondence. Bind source/tenant/environment/operation, exact input IDs and verified digest/size, page-occurrence order/rotation, processing-profile/builder version and options, and the verified output identity/digest/size/page count. One output page represents each intended page occurrence in order. Do not require byte-identical PDF regeneration across software versions; recover one admitted immutable generation winner. Technical retries cannot overwrite a winner or turn a changed recipe into the original operation. Use the qualified existing processing/custody infrastructure where it satisfies these obligations; this decision selects no new vendor, SDK, storage platform or orchestration engine. PDF Studio/DocRaptor authority does not extend to private ordinary pages. The processor consumes exact permitted stored inputs, not caller-provided network URLs, paths or executable content. Produce an inert static PDF with no embedded scripts, active behaviors or remote references; syntax and claimed page count alone do not establish complete correspondence. A qualified trusted pipeline can establish that evidence without a compulsory second full decode or regeneration. Isolate untrusted decoding with least privilege, no ambient credentials and no network egress unless actually purpose-qualified, and bound the complete process tree according to the actual platform profile; never hold a source database transaction open across remote generation/upload. Optional local preview must agree with the declared recipe; authoritative success depends on actual output qualification.

Additional dispensable preview processing can remain separately unavailable after receipt; known receipt never becomes unreceived merely because preview or refresh fails. Receipt still does not establish authenticity, business acceptance, whole-request fulfillment or permission for another use. Required safety processing failure cannot be bypassed by merely calling the result Received.

## Ratified glossary amendments

Ratified new term:

**Document Assembly**:
A source-owned contribution that presents an ordered set of selected image originals as one assembled document. It preserves the identity of its originals and assembled output and is distinct from a Document Request Item, an original file, a preview and item acceptance.
_Avoid_: original file, preview, request item, accepted evidence, merged history

Ratified **Submission Confirmation** replacement:
The source's record that an exact file version or Document Assembly was durably received for a Private Document Request. It does not mean the received material is safe to preview or that the requested business evidence has been accepted.
Its existing Avoid list remains unchanged.

Ratified **Staff-supplied Document Evidence** replacement:
An exact file version or Document Assembly deliberately supplied by authorized staff for a Document Request Item, with attribution to that staff act. It is distinct from a participant's submission or affirmation, item acceptance and permission for other uses.
Its existing Avoid list remains unchanged.

Submitted Original and Document Review Comment need no change: the original remains exact received bytes, and a comment can already target the exact use/file version. Assembled PDF is a clear output label, not a second new glossary term. The canonical glossary now contains 32 ratified terms: Document Assembly is added, Submission Confirmation and Staff-supplied Document Evidence receive exactly the adopted refinements, and all 29 other definitions and both existing Avoid lists are preserved.
