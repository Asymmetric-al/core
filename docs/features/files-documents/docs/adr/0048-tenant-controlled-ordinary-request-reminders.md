# ADR-0048: Tenant-controlled ordinary request reminders

Date: 2026-10-25 (Asia/Bangkok)

Status: **Fully ratified by Conrad on 2026-10-25, Asia/Bangkok: Q48 A with all required amendments and the Document Request Reminder Plan glossary term.** Reviewed disposition: **Accept with required amendments**; the complete package is adopted.

## Context

The founder requires reminders and visible missing work; Q09/Q46 leave reminder initiation and timing unselected. Conrad chose tenant-controlled automatic reminders alongside deliberate staff reminders. That needs an actual source purpose rather than treating unfinished requests, task dates or an unrelated financial reminder implementation as authority. The alternative is a complete manual-only native reminder workflow, with lower autonomous complexity but continuing staff follow-up burden.

## Ratified decision and amendments

Adopt Q48 A for eligible ordinary Private Document Requests: support tenant-controlled automatic reminders alongside deliberate source-authorized staff reminders. The first cohort is optional external email through one exact ordinary-source/P17/P6 binding, not a new in-product bell, SMS, campaign, generic deadline key or copied permission Access-request/financial approval contract. The requesting source owns the actual remaining recipient action, exact recipient/purpose and current usefulness. An unfinished or overdue label, unaccepted evidence, scan state or staff-review backlog alone is insufficient. Received work awaiting checks or review must not be chased as unsubmitted; a genuine Request changes may create recipient work despite an existing file. Optional/nonblocking items do not become required demand or a fulfillment hold through reminders. Keep the request and lawful native work usable when optional mail is unavailable.

Adopt a deliberately bounded initial policy as new product judgments, not claimed empirical optima or inherited defaults. Tenant automatic reminders start Off. After authorized qualified enablement, new eligible issued requests inherit an automatic plan unless authorized staff chooses no automatic plan at issuance; never-issued drafts send nothing. Suggested defaults are an interval of 7 calendar days and a lifetime total of 3 automatic reminder occurrences per issued request. Tenant administrators may choose an integer interval from 1 through 30 calendar days, an integer total from 1 through 10, and a local minute-of-day with suggested 09:00 in an explicitly reviewed qualified IANA time zone. The platform ceiling is 10 automatic occurrences per issued request across all plan revisions; there is no unlimited value. These tenant fields are defaults copied into a plan, not mislabeled current hard ceilings for all earlier plans. Display their scope. Actual broader source/contact/operational limits remain live narrowing gates. No holiday calendar, arbitrary rule language, per-item schedule, per-request cadence editor or automatic escalation is added.

Tenant default/enablement management requires the actual source-policy capability and applicable automation:manage, declarative configuration, synthetic preview/non-authoritative test and activity-log activation gates. Preview/tests cannot create real communication intents, business events, business history or provider calls. Qualify the exact source contract, template/locales, recipient/contact/material/action, execution and recovery before enabling this cohort. A source-owned service executes an active plan under current tenant policy; it does not impersonate the human who enabled it or indefinitely borrow that person's session. Creator departure alone is not an automatic source-policy revocation. Define the currently accountable tenant/source administrator and real repair route. An unqualified automatic feature or optional mail problem must not block an otherwise lawful ordinary request by manufacturing a mandatory-notice dependency.

Capture the qualified tenant profile and revision in each request plan. Retain intervening stop generations even if no worker ran while Off. Do not backfill enrollment or send historical reminders.

Give eligible staff distinct bounded source actions to Start, Pause, Resume, use current tenant settings and Send reminder; read access, reviewer responsibility, task assignment or tenant rank alone grants none of them. Request-level Pause stops future automatic calls while preserving settings, history and count. Resume uses current authority and starts a full new waiting interval without resetting the budget or reviving an old occurrence. It cannot override tenant Off, recipient automatic-stop or broader source/contact restrictions. Deliberate manual reminders remain available under automatic Off/pause and after automatic limit exhaustion, subject to the same current purpose/privacy/contact rules, active-occurrence coordination and shared spacing. No forced reason essay or separate approver is added to a routine permitted action.

Explicitly add a narrow recipient capability to Stop automatic reminders for this request, and to deliberately allow them again, under the request's current qualified recipient/action proof. Stop affects only this automatic reminder purpose: it does not withdraw evidence, waive work, cancel the request, revoke reading, suppress independently lawful manual reminders or change other message preferences. Staff, tenant toggles, new work and profile adoption cannot clear the recipient's stop. Recipient resumption clears only their own stop; it cannot enroll an unconfigured request, clear staff/tenant stops or manufacture access. When it makes an already configured plan otherwise eligible again, it starts the same fresh full waiting interval as a permitted staff Resume; it never exposes an overdue pre-stop slot for immediate sending. All broader Phase 3 do-not-contact, do-not-email, purpose/consent and provider suppression rules govern manual and automatic alike. ## Ratified glossary addition

**Document Request Reminder Plan:** A source-owned, bounded arrangement governing whether and when automatic reminders may be issued for outstanding recipient work on one Document Request. It is distinct from a reminder message, a delivery attempt, the Requested by target and recipient access.

This exact definition is adopted as the 29th canonical glossary term; all 28 earlier definitions are preserved. The source arrangement is distinct from P17 delivery routing, individual messages/attempts, Requested by and recipient access.
