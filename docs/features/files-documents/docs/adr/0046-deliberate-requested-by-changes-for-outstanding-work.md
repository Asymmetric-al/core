# ADR-0046: Deliberate Requested by changes for outstanding work

Date: 2026-10-25 (Asia/Bangkok)

Status: **Fully ratified by Conrad on 2026-10-25, Asia/Bangkok: Q46 A with all required amendments.** Reviewed disposition: **Accept with required amendments**; the full package is adopted. Q01–Q46 are ratified, with all 27 glossary definitions unchanged.

## Context

Q09 selected a coordination target and immutable receipt applicability but did not select an issued-target editor. Conrad selected Q46 A after Q01–Q45 ratification. Keeping a stale ordinary target or cancelling/reissuing is weaker than a deliberate prospective source change while actual recipient work remains. The current task deadline handlers are not ordinary-source mutation authority.

## Ratified decision and amendments

Adopt Q46 A: allow authorized staff to deliberately change the source's Requested by target for actual outstanding recipient work on an eligible issued, unfinished ordinary Private Document Request. The source owns eligibility and exact target applicability; P12 supplies current authority. A staff title, reviewer assignment, file permission or generic task editor is not this capability. Use the existing request context and actual target scope; do not add per-item inheritance, bulk rescheduling, a new recipient/purpose, specialist hard-deadline editing or a general calendar platform. Date editing is available without opening submitted files or requiring recipient login when the source independently permits it.

Keep one authoritative current target and attributable target revisions within the ordinary source. A task, list, calendar, receipt label, notice or cached projection cannot become another writable target authority. Preserve the exact request, recipient/work applicability and source context; a target edit cannot change instructions, requirements, review responsibility, acceptance, No longer required, cancellation or fulfillment. An unfinished label alone is insufficient: material already received and awaiting staff checking/review is not outstanding recipient work merely because the source has not fulfilled the request. Current outstanding-work cues may change prospectively; historical receipt facts do not.

Support deliberate earlier or later values under the source's existing valid target rules, including an already-past requested date where genuinely permitted; do not invent a blanket future-only rule or backdate when the change occurred. Where the source explicitly supports an optional target and the actor has the applicable power, Set a target or Clear the target are explicit transitions; clearing means no current coordination target, not unlimited access or erasure of old terms. A required target cannot be cleared. Known absent, unresolved/unknown and malformed data are distinct. With known current source identity, expected revision, authority and declared target interpretation, a qualified new prospective value may replace an explicitly unresolved old target while preserving that unresolved history. Unknown command authority, ordering or target interpretation blocks the affected change; do not guess old data, optionality, defaults or a historical verdict to make a save succeed.

Preserve the source's closed declared target form and meaning. For a date-only target, bind the valid civil date to the request's source-declared IANA time zone; compare the trusted receipt's civil date in that zone, so the same requested date is not late and a later civil date is late. Do not encode that meaning as arbitrary UTC/browser midnight, twenty-four elapsed hours or a last-microsecond cutoff. An already-qualified instant target retains its declared precision and Q09's strictly-later/equality rule. This editor does not silently convert target kind, calendar, zone or precision. Current browser, organization-setting or display-format changes cannot rewrite saved target meaning. Preserve sufficient admission-time interpretation/comparison evidence to explain historical receipts after time-zone-rule upgrades without building a new time-zone service. Qualify one actual ordinary-source temporal profile before activation, with compatible server/database/client behavior and finite supported date range; users choose a useful date, not a calendar engine.

Requested by remains a coordination target, separate from actual intake cutoffs, original and fresh unfinished-access ends, completed access, proof/session validity, revocation, source closure and retention. Changing it cannot restart, extend, renew, reopen or authorize any of those. Under Q12 a target after access ends can be an honest timing mismatch, not a universal target-only rejection or implicit extension. Show the real availability separately; an otherwise permitted planning edit does not require manufacturing a fresh grant. Any later recipient action still needs its independently authorized access. Preserve specialized source limits and the existing fixed/fresh-access lineage, including ended periods and terminal stops.

Every received submission keeps its actual trusted source admission time, exact bytes/use/correction lineage and applicable target terms or explicit unresolved timing. Today's target must not recalculate an earlier receipt from late to timely or timely to late. Transfer start, browser clock, provider callback, scan completion, staff review or response arrival is not receipt time. New requirements, published instruction revisions and correction work keep their actual added/revised-at applicability; no unrelated retroactive lateness or automatic new interval follows. Genuine correction of an erroneous historical fact is a separate governed, attributed source act preserving prior evidence. Establishing new prospective terms does not repair or conceal unproved old terms.

Use one source-aware authoritative server command for the deliberate target change, with trusted actor, Active Tenant Assignment, Tenant/environment, actual source occurrence time, immutable intended target scope, reviewed proposed canonical meaning, expected relevant source/target revision and durable semantic operation identity. Current permission and eligibility are enforced at actual admission after relevant waits. Coherently commit the target successor, current pointer, required attribution/applicability history, durable outcome and genuinely required existing follow-through. No current target without its required history/result, no unadmitted history presented as a saved change, and no external provider/network call or human interaction under the source lock. One command does not imply one SQL statement or absence of required audit work.

Reconcile an already committed matching semantic operation under current result-disclosure rules before applying new-work eligibility, expected-revision or no-op logic. Recover its actual earlier outcome without reapplying it over a newer target, receipt or terminal state; changed intent under the same operation identity conflicts. Do not display an old recovered target as today's current target or let a late response overwrite a newer client projection. A genuinely new command requires current authority and the expected relevant basis even if the displayed date looks unchanged. After those checks, equality of the complete canonical target meaning yields an honest unchanged result without a fabricated business revision, history entry or downstream effect; required security/admission evidence still applies. An intervening change-and-change-back does not make a stale expected revision current. Keep minimum lawful replay evidence or reject unverifiable stale operations; expiry of a transport key or readable history cannot create a new effect.

Serialize target admission with genuinely relevant recipient/work applicability, receipt/correction, acceptance/removal, material instruction change, fulfillment/cancellation and authority changes through the actual source boundary. Require one explainable ordering in both race directions. If the final outstanding recipient work disappears or the source becomes ineligible first, a new target change cannot be admitted as ordinary outstanding work; if the edit is admitted first, preserve that real act even when later receipt or closure follows. Q09-compatible target-only changes may resolve at first submission admission without a new upload, intent or repeated confirmation; once admitted, replay preserves the original receipt/terms. Do not blanket-invalidate sessions, prepared unrelated work, accepted evidence or every review because a planning date changed. Relevant dependencies are structural and source-defined, not an AI relevance test or a whole-request revision guard unrelated to this act.

Make a mistaken target change recoverable through another deliberate currently authorized change on the same source, possibly back to the former value, while retaining the intervening history and actual new occurrence. A convenient recovery affordance invokes that same current command; it does not restore a snapshot, grant prior permissions or erase evidence. If current source eligibility has ended, the ordinary editor remains unavailable and any legitimate historical correction follows its separate owner procedure. Before activation, supported ended/no-recipient-work cases that require legitimate correction must have a real qualified source remediation route and an actor able to act; a powerless Contact admin link or ad hoc SQL is insufficient, and no generic reopen or historical-rewrite power is created. No mandatory reason essay, routine second approver, arbitrary edit timer, cancellation/reissue workaround or direct database repair is the normal recovery model.

Protect current targets, old/new values, dates, source associations, author/time attribution, counts, history, conflicts, operation receipts and error details through current source/P12 projections. Participant-visible change context is limited to the safe target/applicability information its source admits; internal actors, rationale, other items or audit history are not automatically disclosed. Known no target, unresolved timing, denied access and load failure must remain distinct without becoming an existence oracle. Fence late responses and private drafts/caches on user, Tenant, assignment, purpose or authority changes; never silently replay private offline edits. General logs, analytics, traces and session replay omit private target values, names, source URLs, credentials and sensitive context. Business history, security evidence and technical diagnostics retain their own minimal source schedules and governed restriction/disposal rules.

Publish the current target to actual authorized request/work projections without promising that a recipient has seen it. Existing messages and prepared work preserve their real pins, purposes and current usefulness rules; no raw task-date update, outbox retry or schedule recalculation becomes another authority. Q46 adds no notification default, generic deadline message key, automatic reminder cadence, escalation, acknowledgment requirement or blanket notifications-Off policy. It does not suppress independently qualified existing effects. Any required existing source follow-through has durable intent and owned recovery; an eventual view refresh or communication failure does not undo a committed target change or justify sending a duplicate. Prior delivered messages remain historical acts and are not rewritten.

Use the smallest typed source current-target/revision/operation records needed to preserve these facts, with native same-Tenant/environment/source/work relationships, unique revision and semantic-operation identities, immutable scope/actor/history attribution, coherent current pointer and expressible type/nullability/state constraints. Represent known absence separately from unknown interpretation; reject unsupported kinds, impossible/nonfinite dates, invalid zones and arbitrary provider/client expressions. Keep civil dates distinct from instants; a timestamptz does not retain its originally supplied named zone by itself. Cross-row current authority/eligibility belongs in the authoritative command rather than a CHECK that consults mutable external state. Parent/actor cleanup cannot cascade away required receipt/target evidence. No monetary facts/types, file copies, schema designer, event-sourcing framework or independent mutable task-date shadow is introduced.

P12 remains the one fine-grained PDP, with its prescribed coarse Tenant RLS using the same trusted context. Qualify effective grants, old-row USING and new-row WITH CHECK including defaults/composition, required SELECT/RETURNING, INSERT/UPDATE/DELETE/UPSERT/MERGE, function ownership/search path/EXECUTE, views, triggers, owner/BYPASSRLS/service roles and every browser/raw API/GraphQL/CMS/import/job/operator/restore path; qualify or close alternate writers and disclosure routes. A literal missing WITH CHECK or a SECURITY DEFINER label alone is not the effective-policy proof. Read the bounded current source and paginate authorized history with stable unique ordering; index actual scope/current revision/operation/history/FK paths and measure plans, contention, connection use and retention growth under real roles. Preserve P12 governed-read/audit budgets and actual exceptions without a policy query per item or full-history scan. No mandatory Realtime, perpetual polling, new provider or scheduler is needed for correctness, and no zero-cost or capacity claim is made.

Provide one contextual Change requested date action, showing the current value or honest absent/unresolved state, proposed value, affected work and separate actual access availability. Use a clear Save changes and Cancel flow; calendar selection, input blur, navigation or opening the editor never commits. Where qualified, Set/Clear has truthful wording and no ambiguous blank-field side effect. Use existing Core Base UI/base-maia shared components with a usable keyboard/text-entry alternative to the calendar, meaningful format/example/zone guidance, accessible validation and focus return, narrow-screen reflow, localized month/day presentation, long names, RTL and IME-safe submission. An earlier/past target or target/access mismatch receives useful contextual explanation without an extra confirmation ritual. Preserve lawful input during validation, stale-revision and recoverable network errors; distinguish pending, saved, unchanged, failed and unknown outcomes, reconciling an unknown save before clearing input or submitting again. Refresh must not overwrite the draft or pretend an older result is current.

Adopt prospectively through an actual source profile and retained-data census. Do not backfill historical timing from today's mutable task date, silently convert ambiguous legacy values or rewrite a source date into a different zone/kind. Old readers/writers must preserve or truthfully reject unfamiliar target meaning and revision state; new code must not assume an uninstalled schema. Before activation qualify finite target/input/history/query/retry/concurrency/retention profiles, server/database/client time-zone compatibility, real-role every-door authorization, both-order source races, source-safe recovery, intended-user/date-entry/AT/mobile proof and production-shaped workload. Bound projection repair and overload fairly without weakening current authority. Mixed application/database/cache/time-rule restores must apply current adverse history and never resurrect old targets, expired rights or effects. Disable the affected edit safely while preserving independently lawful intake, reading and review; use roll-forward when old code cannot interpret new admitted state. No native result, provider health or unchanged bill is claimed by source inspection or synthetic experiments.

Record Q46 A as fully ratified with the complete required amendment package adopted. The existing Document Request Due Date term remains sufficient; preserve all 27 glossary definitions. At the authorized formal publication stage, adopt the exact ordinary-source target mutation, temporal interpretation, applicability/history, P12/P3 rights, P9 task projections and relevant P6/P17/P34 interactions through canonical owners and regenerate their incorporated OpenSpec views. Trace the adopted clauses through design, tasks, authorized tickets, implementation, tests and release evidence. This ratification does not itself publish a formal specification, implement or activate a feature, mutate providers, send a message or select an answer to Q47. Research and one next question are authorized.

## Consequences

Authorized staff can keep the real ordinary request's plan current, with deliberate correction and historical integrity. Dates do not renew access or reclassify old receipts. The required persistence is a small source current/revision/operation model, not a general scheduler. Native current rights, both-order races, temporal meaning, bounded workload, accessible interaction and capable repair must qualify before activation.
