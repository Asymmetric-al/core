## Context and tradeoff

The founder requires reusable shared views. Conrad chose direct publication of eligible owned definitions by normally qualified ordinary authors, rather than an additional designated view-manager gate. Tenant control of actual source/P12 grants remains. B is credible for curated standard libraries, but adds a central handoff without removing privacy or lifecycle requirements.

One stable private definition becomes shared through explicit reviewed intent. A finite exact staff-assignment audience, each viewer's current rights, one current maintainer and scoped source administration provide the complete small lifecycle. Private copies are deliberate; no compulsory publishing duplicate or dynamic group engine is required. Metadata itself can be sensitive, and the existing personal gift-history defaults/writers/cascades cannot be reused unchanged after promotion.

## Ratified decision and amendments

Allow eligible staff to deliberately publish their own ordinary request-file saved views directly within the source/P12-granted authoring and publication scope, without a separate view-manager designation or routine second approver. This is an explicit ordinary-source amendment to P9/Q42's private-only starting scope; it does not activate reserved visibility values throughout CRM. Preserve all actual P3/P12 policy-widening, protected-grant, delegated-ceiling, self-benefit and separation-of-duties requirements. Reading files, holding a staff title, creating a private view or owning a definition alone cannot self-grant publication or a broader audience policy.

Use one stable saved-view identity, private by default. Share view deliberately promotes the exact reviewed owned definition to shared availability; do not create a mandatory duplicate private/shared pair or silently publish subsequent private experiments. Make the saved-versus-unsaved basis explicit; a combined Save and share may commit deliberately reviewed changes in one action. Bind its source, operative query meaning, schema/default basis, current maintainer and explicit audience in one coherent publication revision. No file bytes, result snapshots, evidence uses or folder placements are copied. The source owns the persisted definition/lifecycle; creator attribution remains historical, current maintenance authority is separate, and each execution uses the current viewer's source permissions.

The first audience is a finite explicitly selected set of eligible current staff Active Tenant Assignments in the same Tenant, environment and ordinary-request source envelope. Validate the actual assignments and definition-disclosure basis at commitment; do not substitute bare profile IDs, emails, Parties, demo teams, Support teams or a client-supplied context. Audience entries permit using a currently authorized definition, not editing, resharing, exporting or reading additional records. No Everyone, dynamic team/group audience, external recipient or automatic inclusion of future staff is selected. This delivers shared views without requiring a new directory/group engine. Later expansion to additional audience forms, such as dynamic teams or Everyone, needs explicit owner adoption and qualification; adding eligible named assignments within the existing envelope remains an ordinary deliberate Manage sharing action. Deduplicate exact assignment targets and reject a stale or partly invalid proposed audience without partial publication. An initial empty reader selection does not publish or silently save unsaved edits; preserve the private draft or perform only a separately explicit private Save. Removal of the last stored reader uses deliberate Stop sharing when a lawful current maintainer exists, or Remove/retire when one does not; never keep an empty shared publication. Temporary zero eligible readers with retained bindings does not itself privatize the view.

Authorize the view's existence, title, description, criteria, field/value references, maintainer attribution, audience information and history independently of the matching records. Then authorize source-approved fields and rows before they contribute to results, ordering, counts, facets, suggestions, pagination or subsequent actions. A publisher need not see every row that another properly authorized viewer may see; shared results need not be equal or complete for another person's work. A useful definition can have zero matching rows. Unknown required authority or coverage is not a successful zero. A definition whose protected meaning cannot currently be disclosed or executed for a viewer is safely unavailable; do not silently strip predicates, substitute defaults, conceal an unauthorized saved-view criterion while continuing to execute it or redirect into a broader list. Mandatory source/P12 authorization predicates remain enforced without exposing protected policy facts.

Use P9's typed, versioned query contract over Q38-approved ordinary-source metadata only. Bind the effective predicate/sort/group/source meaning and its schema/default resolution so unrelated tenant-default, schema or configuration changes cannot silently broaden or retarget a saved view. This does not require materializing results or a new version engine. Qualify supported viewer-relative values, date precision, locale/time-zone semantics and source current/historical selection explicitly; do not substitute the creator for the viewer or infer the newest file version. Unsupported/retired references and invalid definitions require safe repair or a deliberate newly validated save. Queries are data under an allowlisted contract, never arbitrary SQL/code or general document-body search.

A shared view has one accountable current maintainer, initially its publishing author, plus existing source-scoped administration for continuity. Viewing it grants no maintenance powers. Deliberate Save shared view, audience changes and maintainer transfer require their actual current source/P12 powers and the expected definition/audience/lifecycle revision. Transfer targets must be eligible exact current assignments; preserve creator and actual actor attribution, existing audience and source scope unless separately reviewed changes are explicitly committed. Departure or loss of publication power ends that actor's writes without automatically destroying independently valid shared work. Actual source restrictions and any applicable restricted named-grantor dependency still win. A scoped source administrator can transfer or retire an orphaned shared view through supported commands; this grants no blanket inspection or takeover of never-shared or later-private views.

Browsing, sorting and temporary filter experiments remain personal working state. Show when the working configuration differs from the saved definition, and require an explicit Save shared view to change what colleagues reuse. A stale private-save request from an old tab cannot mutate a view that has become shared. Save a personal copy, when currently authorized, creates a new private identity from the permitted reviewed definition, without copied audience or maintenance rights. A valid independent copy is not automatically recalled when its source view stops sharing, but its own current source/field/definition restrictions still govern. No background propagation synchronizes copies or author drafts. Hide for me, personal pins/defaults and shared-definition changes remain distinct; publication cannot force colleagues' defaults or tabs.

Provide deliberate add/remove audience, Stop sharing, Remove view and qualified recovery. Removing an audience entry blocks its future shared access; a later reassignment, matching email or recreated assignment must not restore that removed binding. Stop sharing clears the reader audience and leaves the definition private to its current authorized maintainer; it does not restore historical creator rights. If no lawful current maintainer exists, transfer to an eligible maintainer before Stop sharing or immediately Remove/retire to withdraw access; do not create an orphaned private state that requires general private-view takeover. Remove view withdraws the definition and audience from normal use without deleting files, source records or independent copies. Preserve only source-required restricted history and minimal replay evidence. Where lawful retained recovery is supported, restore as private under current authority with no old audience; any later sharing is a new reviewed operation. Urgent withdrawal does not wait for replacement ownership. Temporary technical or source-policy unavailability is distinct from explicit removal/withdrawal; only still-valid unchanged bindings may resume under their actual current rules. No old link, retry, default fallback, backup or name reuse revives a withdrawn publication.

All writes use one source-aware server command boundary, with trusted actor/Tenant/environment/context and exact view identity. Commit definition, audience, maintainer/lifecycle change, required restricted history and durable outcome coherently. Failure before initial Share preserves private state; failure before a shared update preserves the prior committed definition/audience subject to current denials. Compare relevant state and current authority at commitment; coordinate publish, edit, transfer, audience removal, withdrawal, source/policy change and execution admission so one lawful order wins. Reject stale edits with recoverable working input, not automatic merge or silent last-writer replacement. Recover an exact committed command before treating a retry as new work, under current result-disclosure rules; changed intent conflicts. Receipt expiry or restore cannot replay an old Share after Stop sharing. Retain minimum semantic deduplication/result evidence or reject unverifiable stale operations; this is not perpetual readable private history. Projection/refresh failures do not reverse committed truth or disable independently qualified source work.

Structurally enforce immutable Tenant/environment/source/view identity and creator attribution, typed same-scope maintainer/audience references, unique exact audience membership, valid private/shared/withdrawn combinations and concurrency revisions. Names are display values, not identity, ownership or global uniqueness proof; disambiguate legitimate duplicates using permitted source/maintainer context without exposing hidden-name collisions. P12 remains the fine-grained authority and RLS remains its prescribed coarse Tenant defense, with actual old-row USING/new-row WITH CHECK, grants, upsert and policy composition verified. Views, functions/RPCs, triggers, service-role jobs, browser collections, imports and raw APIs must preserve the same source/PDP boundary or be closed. No profile deletion cascade may destroy a published shared definition/history; old personal routes cannot bypass publication state, revision or current authority. Caller input cannot retarget scope, ownership, attribution or audience eligibility. This introduces no financial facts or money schema.

Use a compact Core Base UI/base-maia journey: private save, Share view, bounded searchable eligible-staff selection and one deliberate commit showing source scope and audience. For shared views show Shared and the permitted maintainer, with clear Save shared view, Save a personal copy, Manage sharing, Hide for me and consequence-aware removal as actual capabilities allow. Keep ordinary-request scope visible and separate definition unavailability from valid no matches. A Return to request files action must be deliberate and identify its broader scope. Preserve lawful drafts/selection and persistent acknowledged, pending, failed or unknown outcomes; a toast alone is insufficient. Keyboard, non-drag pointer, screen-reader, focus, mobile/zoom/reflow, long/international names, Unicode/RTL/IME, localized time and low-bandwidth recovery must work. No automatic email, new notification feed, approval queue or collaborator-presence system follows.

Preserve qualified ad-hoc query-context links independently of shared-library publication: they require current source/query disclosure; links to a saved definition also require that definition's current permission. URLs are not grants and must not expose protected predicates, names or tokens. Fence late responses and caches on actor, Tenant, exact assignment, definition/audience/lifecycle revision and relevant current governance changes. Apply actual source/P12 disclosure, metering, audit-before-serve and timing/error-uniformity rules; permission to inspect a view is not permission to inspect another viewer's results. Keep restricted business history distinct from technical telemetry, and omit private definitions, labels, predicates, audience identities and source material from ordinary logs, analytics, traces and crash reports. Do not persist restricted working state offline or silently replay queued sharing changes after reconnect.

Use the smallest native source/P9/P12/query/UI seams. A typed capability registry or visible team selector is not evidence of an implemented audience authority. Define finite source, definition, audience, query, catalog, concurrent-write and recovery budgets, measure actual plans/resource use and preserve P12's inherited governance-read and set-based projection budgets. Avoid full-directory/result loading, per-row policy loops, eager global counts, automatic expiry/cleanup engines and new vendors. Migrate additively with exact view/source/owner mapping, a retained-data census and fences for old personal writers/cascades before enabling shared writes. Preserve Q42 private definitions; do not mass-publish them. Disable affected shared serving/writes safely, preserve admitted source facts and lawful private work, and qualify roll-forward/restore against later restrictions. No unmeasured speed, capacity or unchanged-bill claim follows.

At authorized publication reconcile the scoped P9/Q42 shared-view amendment, actual source/P12 publication/administration/audience powers, query/default contract and all incorporated OpenSpec clauses through their canonical owners. Require real-role database and alternate-path proof, definition/result privacy, write/revocation/default races, exact replay, author-departure recovery, migration/restore, finite workload and composed accessible staff journeys before activation. Trace this decision into design/tasks, authorized tickets and release evidence. Q38 metadata scope, Q42 one-home/source independence, Q41 private document sharing and specialist owners remain intact. No new glossary term is necessary: existing saved-view and source language suffice. This is fully ratified grooming intent with all required amendments; it does not establish native implementation or formal specification publication.

## Consequences and glossary

Eligible authors can publish directly within actual source authority. Shared readers get reusable definitions, not rows, editing power, external sharing or a complete work queue. Local experiments remain personal; shared changes are deliberate. Current source administration can transfer or retire shared work after departure without a blanket right to read private views. Removal, replay and restore cannot silently recreate audiences or broaden filters.

The material first-cohort narrowing is finite explicitly selected current staff assignments, not automatic Everyone or dynamic teams. This satisfies the required shared-view outcome without building those additional systems. Existing Core query/context/UI seams remain the permanent path. No new provider, notification, approval queue, body search, file copy or glossary term is needed. All26 existing definitions remain unchanged.
