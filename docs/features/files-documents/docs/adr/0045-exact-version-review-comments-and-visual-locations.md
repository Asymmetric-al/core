Date: 2026-10-25, Asia/Bangkok.

## Context

Conrad selected exact-version comments with supported references and optional visual point/region markers on qualified PDFs/images. The founder requires useful exact-version review context. Current social comment and template-reader implementations do not prove this source-owned capability. P9 work ownership, P12 current authority, D32 qualified reading and its narrow authoring exclusion must be reconciled explicitly; Q45 ratifies that bounded extension without a new chat/editor product.

## Ratified decision and amendments

Adopt Q45 A+B as one ordinary staff review capability: exact-version Document Review Comments with supported location references, plus optional point or rectangular-region markers on qualified static PDF and image representations. A useful general comment needs no location or successful preview. The first source cohort is ordinary Private Document Request evidence contributions/uses, including Q28 evidence only within its origin and target restrictions. Existing source-specific specialist collaboration remains with its owners. This is a deliberate narrow addition to the shared reader's authoring interaction; D32's display of annotations already embedded in an original does not itself authorize creating new Core markers. Preserve every declared D32 reading lane and its coverage; marker support is required only for the separately qualified static PDF/image cohort, not automatically every Office rendition or file that happens to render into pixels.

Each comment has one immutable source use, exact original file version, business purpose, Tenant/environment and trusted original author context. The ordinary source owns its eligibility, current staff audience, content/history and retention; P12 owns current fine-grained authority and P29 the qualified reading/custody mechanics. Filename, equal bytes, folder/view membership, reviewer assignment, staff rank and a task link do not merge uses or confer comment or historical-file rights. Surface the same source-owned comments directly in existing evidence/request work and compatible task/reader context. Do not create a task for each comment, repurpose Party notes or post_comments, or create a universal cross-use thread. A flat comment collection with separately attributed same-version follow-ups is the complete initial conversation shape; no reply tree, Resolve/read-receipt requirement or new inbox is selected.

Require bounded nonblank plain-text content that communicates the feedback for every saved comment, including a visual marker, with at most one optional supported location in its current revision. Use a helpful prompt, not a required title/reason, minimum essay or semantic quality classifier; a concise observation such as Date unclear can suffice. That location may be a qualified page/slide/sheet/cell/line reference or one point/region on the qualified PDF/image surface. A plain explanatory description remains useful but must not masquerade as a verified jump target. Keep annotation text separate from original embedded annotations; preserve original bytes and signatures. No empty pin, attachment, screenshot/crop copy, executable selector, arbitrary HTML/SVG, freehand ink, rich document editor, redaction, OCR, AI interpretation, fuzzy text matching, body index, automatic link fetch or annotated export is introduced. Render untrusted text safely through existing shared components; typing an @name or URL is not an invitation, permission change or new notification purpose.

Bind any machine-resolvable location to the exact source use/version and the actual qualified representation semantics needed to interpret it. Distinguish source page identity from printed page label, preview pagination, original slide number, sheet/cell coordinates and literal text/CSV projection; browser wrapping, file extension and page-count equality are not stable coordinates. Derive trusted representation identity, geometry/profile/options/coverage basis and page/image bounds from the reader/source, not caller assertions or mutable provider paths. A location is a compact reference to that basis, not a new copy of document text or image bytes. A comment's identity and retention must not depend solely on an expiring technical generation or an on-delete cascade from it.

For a new or moved visual marker, use a currently qualified exact page/image mapping and one closed point/rectangle shape. Persist canonical, bounded, finite coordinates in a declared page/image coordinate space with precision and interpretation qualified for the actual reader. Validate type, dimensionality, range, nondegenerate rectangle and page/image membership before and after canonicalization/rounding; reject NaN, infinity, malformed, out-of-bounds, collapsed or unsupported values rather than silently relocating them. Screen pixels alone are insufficient: qualify zoom, rotation, crop/view box, device-pixel ratio, image orientation and resize transforms. Client movement is untrusted input; server validation against trusted geometry and native constraints remain necessary. No general spatial database, PostGIS dependency, SVG selector engine or annotation interchange platform is required for these bounded shapes.

Keep the comment and its target stable across corrections, renderer changes and preview expiry. A newer file version never inherits the old comment, location or approval. A regenerated representation may support navigation only after exact compatible location correspondence is proved under the current qualified source/profile/projection; do not guess placement from matching page numbers, dimensions, text or digests alone. If correspondence or required byte access is unavailable, retain only the independently lawful comment/context and show Location unavailable. Do not silently move or drop a saved anchor, extend a D32 deadline or retain every preview forever. Current technical generation and source retention remain separate. A text-only correction can retain its unchanged stored location without a fresh preview when current comment/source disclosure permits; new or moved geometry needs current qualification. Deliberate Remove location changes only that comment revision to general same-version feedback.

Authorize each action and disclosure through the actual source/P12 boundary: comment creation, reading, own editing, withdrawal, restoration, scoped administration, author attribution, counts, snippets, location facts, history, links and current source context. Comment access and original/representation access are distinct; permission to read a comment cannot fetch forbidden bytes, and permission to read a file cannot write or inspect every comment. Historical content remains subject to current source rules. Denied or unresolved authority does not become an empty list or a cached fallback. Revalidate the exact acting context and relevant source/policy state at actual command/read/navigation admission, fence late results and clear newly forbidden representations. Tenant controls are the existing source/P12 grants and qualified limits, not a new per-comment audience picker or permission engine. No participant or Q41 recipient automatically receives staff comments.

All mutations use one source-aware authoritative server command with trusted actor, assignment, Tenant/environment and time, immutable intended target, expected current comment/source basis and a durable semantic operation identity. Commit the current text/location/lifecycle revision, required attributable history, affected source-review basis and durable outcome coherently; no body-only success with a missing marker or orphan marker after failed text save. Post, Save changes, Withdraw and Restore are deliberate commands. Draft text, cursor positions, pointer movement, zoom, pan, hover and unsaved marker adjustments remain bounded local interaction state and cause no database writes. On a lost response, reconcile the same committed operation under current disclosure before new-work eligibility; identical deliberate retry recovers the original result, changed intent conflicts, and genuinely new follow-ups are not deduplicated merely because their text matches. After original-operation reconciliation and current authority/expected-revision checks, unchanged text and canonical location or already-current permitted maintenance state return an honest unchanged result without a fabricated Edited revision or advancing the review basis; stale expected revisions still conflict. Preserve minimal lawful deduplication evidence or reject unverifiable stale operations after readable history expires; restore cannot turn old commands into new effects.

Allow an author with current source permission to deliberately correct their own comment text or location on the same immutable target using an expected revision. Record the actual editor and edit time, keep the current presentation visibly Edited where applicable, and preserve source-required prior meaning/history under its own restricted disclosure and schedule. Do not overwrite concurrent changes, rewrite another person's authorship, reparent a comment to another use/version or silently merge conflicts. Preserve lawful working input for deliberate recovery. A wrong-version post can be withdrawn and followed by a new currently authorized comment on the correct target; it is not retargeted in place. A source-scoped operator may restrict/withdraw, perform separately authorized restoration or add a separately attributed correction, but cannot impersonate an author by rewriting their prose. No arbitrary edit timer or routine second approver is added.

Ordinary withdrawal removes a comment's active text and marker from normal presentation while retaining only the currently lawful withdrawal indicator and source-required history. It is not physical deletion, source-evidence disposal or a claim to recall what someone already read. Make accidental withdrawal recoverable through a deliberate current-authorized Restore of the exact currently withdrawn revision and latest lawfully retained text/location, recorded as a new attributed revision; an Undo affordance may invoke that same command. An unchanged location may restore as unavailable rather than being dropped or forcing a preview. Restoration cannot roll back to arbitrary older history, change target or authorship, bypass governed restrictions/redaction, reconstruct disposed content, restart source retention or revive ended source permission. Author departure does not erase required attribution/history; separately scoped source administration provides lawful continuity. No new Trash platform, universal recovery period or irreversible-delete shortcut is selected.

Comments inform source review but do not accept evidence, issue Request changes, waive requirements, revise instructions or fulfill a request. The ordinary source explicitly declares the structural dependency between exact review context and comments; admission, correction, location change, withdrawal and restoration in an affected basis advance it so an uncommitted prepared review cannot silently ignore newly changed relevant context. Use exact structural scope, not an AI or semantic classifier, and require deliberate source revalidation only where that basis changed. Unrelated historical comments do not globally invalidate work. A committed decision is not undone by a later comment, and Q22 deferred fulfillment gains no new completion predicate merely because discussion changed. No reply, Resolve flag, comment-reading ceremony or automatic repeat review is required. Participant-facing communication remains a new deliberate qualified Q23/Q30 act, never a visibility toggle or automatic forwarding of internal content.

Keep source-owned current comment data, attributed revision/withdrawal/restore history, security/access evidence, technical diagnostics and disposable reader state distinct. Retain body versions only where their actual source schedule, relied-on review evidence or hold requires them; minimal accountability is not indefinite readable raw text. D32 technical expiry does not delete the comment or grant old-byte access, and comment retention does not hold its preview automatically. Governed restriction/redaction/disposal acts apply consistently to current views, lawful history, caches, exports/backups and restore suppression under their owners. Logs, metrics, traces, replay tools and crash reports omit private comment text, quotes, location descriptions, geometry payloads, names and raw source/credential URLs. Operators get purpose-scoped safe diagnostics, not blanket comment/body access. Record actual admission, revision, recovery and access facts; viewing a marker or posting a comment proves no inspection, approval or human reading.

Use a small source-owned relational record and compact optional typed-location data, not a whole-file JSON array of comments, duplicated document/page bytes, independent competing annotation truth or an event-sourced collaboration platform. Enforce native same-scope relationships to exact source use/version and comment revisions; immutable original author/target attribution; unique operation and revision identities; one coherent current revision; at most one current location; valid active/withdrawn combinations; and bounded nonempty text and finite valid coordinates. Use exact declared types/nullability/defaults and trusted timestamp semantics; reject unsupported location discriminators instead of dropping their fields. Cross-row current eligibility and geometry/source compatibility are enforced by the single command, not a CHECK constraint that queries mutable external rows. Parent/user/rendition deletion cannot cascade away required comment/review history. No global digest/name key merges comments, no broad nullable owner pointer weakens tenant relations, and no money facts or financial types are introduced.

Keep database work bounded and proportional to the requested source/version and visible reader context. Fetch permitted comment pages with stable keyset ordering and a unique tie-breaker, using an opaque or validated scope/query-bound continuation; edits do not silently reorder creation history or make equal-time rows disappear. Fetch needed page markers and permitted author/context metadata in bounded batches, not one query or authorization/ledger call per pin or per row. Index actual equality/range/order/FK predicates and verify plans under real roles and production-shaped distributions; use selective indexes rather than speculative indexing or generic JSON/spatial search. Do not load all tenant comments, all versions, every page or complete histories to render one view. Show incomplete/loading/unavailable coverage truthfully; a partial page is not all comments or proof of none. Preserve P12's actual logical governed-read budget, set-based projection, tiered audit and stated exceptions. No guaranteed constant-time query, capacity multiplier, zero-cost or unchanged-bill claim follows from this design.

P12 remains the sole fine-grained PDP and RLS its prescribed coarse Tenant defense using the unified trusted Tenant context. Qualify effective grants, SELECT requirements, old-row USING/new-row WITH CHECK including inherited behavior, composed policies, INSERT/UPDATE/DELETE/UPSERT/MERGE, views, RPCs, triggers, security-definer/owner/service roles, storage/reader paths, raw API/GraphQL/CMS, browser collections and every job/operator/restore writer; qualify or close each alternate door. Do not reuse public post-comment policies, existing Realtime publication or default-enabled collection subscriptions for private review data. Correctness uses current authoritative commands and bounded authorized refresh, not broadcast arrival or optimistic rows. No new mandatory Realtime, presence, cursor broadcast or CRDT is introduced. Any existing qualified invalidation transport is an advisory, currently authorized minimal hint followed by protected refetch; coarse RLS alone cannot publish private bodies, history or geometry outside the PDP. Never use raw DELETE/old-row payloads as permission-safe notification or revocation proof.

Compose one normal comment list/composer with optional location in the existing Core Base UI/base-maia reader and source work surface. Show the exact file/version and internal source context before Post; offer a general comment, a supported location reference, or an explicit Comment here action that pre-fills qualified context. A new visual marker remains visibly provisional until the same Post commits its meaningful text and location. Selecting a region, switching tools, scrolling or closing a preview does not post. Use explicit placement mode so normal touch pan/zoom and text selection do not accidentally create markers. Save changes and Cancel are clear; preserve lawful drafts/positions on recoverable errors and conflicts without silently persisting private drafts offline or replaying them after context changes. Unknown save is reconciled before clearing input or repeating work. New activity can be refreshed through bounded existing policy without stealing focus, moving the reader, overwriting a draft or automatically choosing a different version.

Provide a readable semantic list and meaningful text/location labels for every marker, with synchronized explicit selection between list and reader. Point/region creation, adjustment, removal and navigation must work with keyboard, assistive technology and an equivalent single-pointer non-drag path; for regions a two-corner interaction or equivalent precise controls can complement dragging. A less precise whole-page note is not an equivalent replacement for selected region functionality. Do not expose coordinate numbers as a mandatory ordinary user task. Keep controls usable at 320 CSS pixels, zoom and touch, with stable focus/return, sufficient hit areas, non-color-only meaning, restrained announcements and reduced motion. ## Ratified glossary addition

**Document Review Comment:** A source-owned staff observation about an exact document use and file version, optionally associated with a supported location. It is distinct from comments embedded in the original, a participant message and a review decision.
