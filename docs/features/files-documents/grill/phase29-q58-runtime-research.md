# Q58 runtime research — qualified staff readership and resource publication continuity

Research date: 27 October 2026. Q01–Q57 are ratified; Q58 has no selected answer. This is read-only question research, not implementation, deployment, database, provider, or capacity proof. Only this task-local note is authored by this pass.

## Result and practical fork

A general staff-reference library cannot be justified by the existing staff role, Mission Control shell, resource curator capability, or shared storage. P28 currently defines the ordinary missionary reader and explicit staff curation; it does not make every staff member a reader of every publication. There is also an existing, narrower Support-owned Internal Staff guides source: Q58 must preserve it rather than claim that all internal staff guidance lacks an owner.

The useful remaining question is publication continuity for the same approved resource across qualified staff and missionary audiences. A practical A would allow one deliberately reviewed resource publication to serve both exact qualified audiences when the same content version, purpose, rights and maintenance meaning are appropriate. B would require separate audience-specific publications, each independently authorized, while permitting separately lawful reuse of an exact held version. These are choices about publication responsibility and audience scope, not one-versus-two catalogs, storage systems, CMSs, or global permission architecture. Both must actually provide the founder-required internal resource experience, rather than using the absence of a native implementation as a no-library alternative.

I favor optional shared publication for genuinely common guidance, with independent publications where audience-specific guidance or lifecycle differs. This avoids mandatory duplicate publication maintenance without claiming measured demand, guaranteed lower cost, automatic audience expansion or compatible shared rights. B remains credible when teams need independent wording, review timing, replacement or withdrawal. Staff-only and missionary-only publications remain useful under either option. The concrete labels and final source amendment belong to the researched question and any later selected-answer review.

## SQL/Auth interpretation and primary technical evidence

They support testing effective grants and policy composition, not merely an RLS flag. Permissive policies combine with OR; restrictive policies add constraints. ## Cost, engineering scope and evidence limits

Shared publication can reduce duplicated curator actions when one piece of guidance truly serves both audiences; this is a qualitative workflow argument, not measured workload or a billing guarantee. Both options require actual source-qualified staff reads, bounded search/listing, safe current retrieval and maintenance. Separate publication rows need not duplicate file bytes, and sharing one row does not make authorization free. Database indexes/query plans, response size, storage/reference accounting, cache isolation and read costs need measured qualification.
