## Conclusion and evidence limits

The selected behavior can remain small: an exact source-owned publication has an optional, explicitly known next-review target; authorized reads derive its current due status; deliberate curator actions record actual review, rescheduling or factual correction with their own attributable history. A passed review date alone does not withdraw independently lawful guidance. There is no need for a recurring review engine, a sticky overdue cycle, a database write when midnight passes, or an extra permission system.

The principal risk is borrowing authority from adjacent code. Current Core authentication, membership lookup, table RLS posture and service wrappers are useful foundations, but none demonstrates the complete P28 review command. In particular, an authenticated profile role, a default Tenant, a successful `getUser`, a `SECURITY DEFINER` declaration or `FORCE ROW LEVEL SECURITY` is not, individually, proof that this caller can review this publication in this active Tenant. Every proposed route must qualify the actual current P12 decision and source context. Existing broad assets metadata must not receive protected review/history fields merely because it is convenient.

### Current primary technical verification

Context7 was used for current Supabase Auth and PostgreSQL policy/date semantics, with primary documentation read directly where needed. These are technical constraints, not native tests:

- [Supabase server-side Auth guidance](https://supabase.com/docs/guides/auth/server-side/advanced-guide): `getClaims` validates JWT signature/expiry, while `getUser` contacts Auth and can detect server-side session termination; `getSession` alone is not trusted server identity. Current Core already uses `getUser`. Neither call grants the source action or guarantees that a later mutation still has the same assignment/capability.
- [Supabase RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security): grants and RLS compose; user-editable metadata cannot be an authorization source; JWT claims can be stale until refresh. A signed JWT is not proof that current resource membership or publication rights still exist.
- [PostgreSQL 17 CREATE POLICY](https://www.postgresql.org/docs/17/sql-createpolicy.html): `USING` governs eligible existing rows; `WITH CHECK` governs resulting rows where applicable. For UPDATE/ALL, omitted `WITH CHECK` can inherit `USING`; absence is **not automatically an unrestricted-write bug**. Effective permissive policies OR together, restrictive policies AND with the permissive result. INSERT/UPDATE/DELETE, `ON CONFLICT`, MERGE, required SELECT/RETURNING access and BEFORE-trigger effects need operation-specific proof.
- [PostgreSQL row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html) and [CREATE FUNCTION](https://www.postgresql.org/docs/17/sql-createfunction.html): examine actual role inheritance, object owner, ENABLE/FORCE, superuser/BYPASSRLS, view/function security, search path, table/function/schema grants and default/named EXECUTE. A definer uses its owner's privileges; it does not universally bypass RLS. Table ownership ordinarily bypasses unless appropriately forced, while superuser/BYPASSRLS still bypass. Definer and privileged worker paths must be scoped deliberately.
- [PostgreSQL date/time functions](https://www.postgresql.org/docs/17/functions-datetime.html): CURRENT_DATE/CURRENT_TIMESTAMP/now use transaction-start semantics; statement time and actual clock time differ. Review occurrence and new-target validity after relevant waits cannot simply assume transaction-start is current. `AT TIME ZONE` distinguishes a civil date in a declared zone from a browser-parsed UTC instant. This does not prescribe a particular SQL function or an unknowable future commit timestamp.

## Exact proposed amendments

These clauses express required behavior and proof, not a fixed schema, table count, service split or new general engine. Their scope is the ordinary P28 resource publication; stricter actual owner policies remain binding.

**C01 — Advisory availability and truthful status.** A known passed review target produces advisory due status and authorized curator maintenance. It does not itself withdraw, expire, hide or deny an otherwise independently lawful publication, guide reference or source use. Current rights, safety, classification, publication, audience, retention/access and custody rules still govern. Due is not proof of danger; not due is not proof of accuracy. Do not label a reschedule Fresh, Verified or Reviewed.

**C02 — Small explicit target profile.** The ordinary next-review target is optional: a known absence is **No review scheduled**, distinct from unknown/corrupt/unavailable facts. An actual source policy requiring a target cannot be bypassed by this optional ordinary default. A target comprises a valid civil date and the captured, qualified source IANA zone. A newly set plan uses today or a future source civil date at actual validation. Viewer/browser zone and later Tenant default-zone changes do not silently reinterpret it. No automatic cadence, global interval, grace period or hidden rollover is adopted.

**C03 — Current due projection and rescheduling.** For a known target D, due means trusted server time expressed in the captured source zone has a local date strictly later than D. The whole chosen day is not overdue. Authorized prospective rescheduling or clearing where optional may change current due status; preserve the attributed old/new target and occurrence evidence. Last reviewed and what was true historically remain unchanged. There is no sticky overdue obligation, second active target or background latch. Time passing alone need not write a business row. An unknown target/zone does not become absent or a false clean status.

**C04 — Actual review with an explicit next plan.** Record review requires actual source-qualified review of the exact current publication/content basis and current authority. Record the actual actor and trusted occurrence time after relevant ordering/waits in the transaction that commits; do not backdate it to click, transaction start, old upload or publication time. In the same authoritative operation explicitly choose a qualifying next target or known None where optional. A still-valid future target may be explicitly confirmed unchanged; an old past target is not silently rolled forward. The current review fact, target choice, attributable history and durable result either commit coherently or do not claim success. A publish-plus-review action is allowed only when it explicitly expresses an actual qualified review; publishing or changing a date alone does not attest review. Transport/viewer failure does not necessarily require repeated review when actual current source evidence already establishes the completed review; absent actual authority or review evidence is not a technical delay.

**C05 — Corrections distinguish facts from plans.** A prospective reschedule is not a factual correction. Correct a misrecorded historical date/review fact only when the source can establish the error, under actual correction authority and exact current relevant basis. Preserve the original actor/time/value/evidence; append a linked attributable correction/invalidating fact. For an erroneous actual-review record, derive the current review projection from remaining applicable evidence and explicitly choose the current target coherently. Do not edit history in place, pretend a missed review happened, blindly restore an older target, invalidate a newer review, change content/publication identity, or undo a later withdrawal. Ordinary mistake recovery must be available through a concrete authorized source route; raw SQL is not the user journey. Governed disposal/redaction remains a separate owner action.

**C06 — Current identity, Tenant and source powers.** Obtain verified native identity, current validated Active Tenant Assignment and exact P12/source action authority from trusted context. Distinguish reader, date planner, actual reviewer, factual-correction operator, publisher and withdrawer as the existing source permits; a role label does not grant every action. Do not infer powers from caller-supplied Tenant/user/actor, profile-role fallback, super-admin demo/default Tenant, signed JWT app_metadata alone, arbitrary service-key possession or a Party/donor record. Do not fabricate a Party. Current source state and relevant permission revision are checked at the actual act; an actor's later departure cannot rewrite their genuine historical attribution. Current result disclosure remains separately qualified.

**C07 — Relevant ordering and coherent authority.** Authoritative mutation must bind the reviewed publication/version, current review/plan basis and only the relevant authority/policy generation. Serialize or otherwise prove equivalent ordering with review, reschedule, correction, replacement, withdrawal, audience/source restriction and actor revocation. Relevant invalidation before admission defeats the stale act; mutation first preserves its actual history while later restrictions still govern reads and later acts. An unrelated global edit should not force needless conflicts. Pending drafts are not business facts. Multiple Supabase SDK calls, audit wrappers or a generic callback are not assumed atomic; qualify the actual transaction/source fence.

**C08 — Original replay, no-op and stale intent.** Reconcile a matching committed operation before new-command eligibility, returning only what current result-disclosure authority permits. A lost response after success must not create another review, reset the target, resurrect a resource or overwrite a newer UI projection. Reusing an operation identity with changed immutable intent conflicts. A different command still needs current authority and expected relevant basis. A genuine unchanged canonical plan is a no-op: no new business revision, target/history fact or review attestation, while required security auditing remains. An unchanged stored date that is now past is not rejected solely because a newly set date would need to be today/future. A stale expected revision, including A→B→A, is not a no-op shortcut. A deliberate new actual review is a new attributed act, not a value-only no-op; double-submit/retry of that same act remains one result.

**C09 — Minimal durable relationships.** Keep authoritative Tenant/environment, source publication, exact content/version/use basis, actor and stable operation/correction references immutable after admission. Enforce mandatory identifiers, lawful nullable optional target state, valid canonical date/zone profile, referential consistency and source-scoped operation uniqueness through appropriate structural constraints and trusted transitions. Do not allow UPDATE/UPSERT/MERGE to retarget a row to another Tenant/publication/version/actor. A source-derived current projection must not become a mutable substitute for history. Do not use a CHECK constraint as a substitute for cross-row current permission or lifecycle concurrency. No arbitrary new table, universal date platform or digest-based review identity is prescribed.

**C10 — Effective database and alternate doors.** Qualify the effective combination of schema/table/column/sequence/function grants, PUBLIC and named/default EXECUTE, row-policy roles and composition, actual invoker/definer owners, search path, role inheritance, ENABLE/FORCE, superuser/BYPASSRLS and view/RPC security. Exercise old-row eligibility and resulting-row validity for actual SELECT/INSERT/UPDATE/DELETE, UPSERT/MERGE, required SELECT/RETURNING and BEFORE/AFTER trigger effects. Audit browser Data API/GraphQL, server actions/routes, collections, direct permitted SQL, functions/views, service-role/NHI/operator jobs, imports/backfills and any storage/reader path. Each must preserve the exact source/P12 contract or be closed. RLS flags and one wrapper do not qualify an alternate writer or public metadata exposure.

**C11 — One PDP and the actual coarse Tenant backstop.** P12 owns fine-grained capability/source decisions and current revocation. Database defense follows its prescribed coarse Tenant boundary and the actual qualified execution model, not a second membership/capability PDP in per-row RLS joins. The current JWT-based helper and partial tenant-guard allowlist do not prove the intended unified request-GUC/current-context contract. Qualify necessary native paths before activation, including fail-closed missing/mismatched context, pooled-connection reset, caller inability to forge the source context and scoped privileged paths. Set-wise authorization and bounded resource queries must respect actual P12 logical governance budgets without turning every resource card into another permission query.

**C12 — Disclosure, current reads and independent uses.** Review dates, reviewer identity, old values, correction rationale and hidden publication existence are source data with actual audiences. A reader's access to a resource is not automatic access to curator history. Safe due status can be shown without leaking restricted reasons. All list/search/filter/count/detail/guide/cache/export/byte/preview/thumbnail/range/conditional/HEAD paths apply their actual current metadata/content rights; an old signed URL or a cached safe-looking date is not continuing permission. Unknown review quality may be displayed honestly while independently proven lawful content remains available; unknown access authority fails closed. This does not create a global read lock or recall already received copies. A review-date action does not delete bytes or rewrite another lawful use's status. P28's safe independent guide advice and unsafe dependent-link distinction remains.

**C13 — Bounded read and cache behavior.** Use bounded server-side metadata queries, applicable indexes and stable continuation with a unique tie-breaker for lists/maintenance/history; avoid all-row browser filtering, per-card permission or body fetches, offset-only unbounded scans, polling every file or a query per date badge. Current due projection uses a coherent trusted as-of time and explicit per-target zone. Define how cache/list continuation/open-screen refresh observes a source date boundary or changed plan without granting authority from stale cached decisions. Date passage may change a derived result without a business revision. Do not index an assumed immutable `today()` predicate or claim an index/query plan without native evidence. No automatic Realtime subscription or cron/notification engine is required.

**C14 — Honest failure and practical recovery.** Distinguish no mutation, committed mutation with failed readback and unknown outcome. Preserve local input on safe conflicts; reconcile the original operation before offering a new act. A committed review/plan is not Failed merely because the resource list failed to refresh. Keep current versus historical result separate. Source-proved repair can address malformed/unknown legacy facts without inventing their old value or review; missing authority cannot be repaired by a default. Curator succession uses actual current source rights, preserving the original reviewer rather than impersonating them. A failed optional due projection does not withdraw independently lawful material, but an unavailable authoritative access check cannot be treated as permission.

**C15 — Rollout, restore and retention.** Migrate prospectively with real old/new reader/writer compatibility, effective grants, explicit unknown legacy provenance and bounded backfill. Do not infer historical review from updatedAt, access logs, task completion, scan success or file modification. Restore must reconcile current source revocation/withdrawal/version/actor state and operation uniqueness rather than revive stale publication or replay old corrections. Readable history and minimum operation/revocation evidence have separately governed finite retention; shortening UI history must not reopen old semantic operations. If old identity is no longer safely verifiable, reject unverifiable stale replay instead of treating it as new. Disabling new Q55 mutations must not remove independently lawful resource reading or truthful retained history. No universal retention days are selected.

**C16 — Proportionate scope and qualification.** This adds no recurring interval, reminder/email/native-notice purpose, task per due date, acknowledgment/unread/Resolve obligation, mandatory second curator or automatic review. Independently qualified existing effects retain their own rules. Ordinary controls are the actual target and explicit source acts; stricter source policies remain stricter. Required native qualification covers real roles, constraints/transactions, current readers, accessible maintenance, finite performance/cost and recovery/restore at the actual release head. No mock, logical model, static source read or included database feature proves deployment, healthy capacity or zero bill increase.
