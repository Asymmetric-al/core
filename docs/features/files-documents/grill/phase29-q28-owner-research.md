## Recommended genuine next decision

For a new ordinary request/item whose source permits existing evidence to be reused, **may authorized staff deliberately supply an eligible exact file already held in Asym, or must the intended participant freshly affirm its use for this request before it can count as submitted evidence?**

| Option                                                                  | Practical behavior                                                                                                                                                                                                                                                                | Benefit                                                                                                                                                                                                                         | Cost and boundary                                                                                                                                                                                                                         |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A — Allow deliberate staff-supplied existing evidence (recommended)** | An authorized staff member selects the exact eligible version in the destination request/item and deliberately adds it as staff-supplied evidence. Record the real staff act and source lineage. Fresh participant affirmation is needed only when the actual source requires it. | Avoids asking a person to repeat an administrative step when Asym already holds suitable evidence and staff have the actual authority to use it. Gives the File Manager/embedded reuse promise a useful, attributable workflow. | Staff can choose stale or wrong material, or incorrectly assume suitability/freshness. Clear provenance and a current target-specific review are essential; mere read access and prior acceptance elsewhere do not authorize the new use. |
| **B — Require fresh participant affirmation for this request**          | Staff may propose an eligible exact existing version, but the intended participant must explicitly affirm that version for this target purpose before it counts as their supplied evidence. Both routes avoid physical download/reupload.                                         | Gives the participant a fresh opportunity to identify outdated/wrong material and confirm intended use.                                                                                                                         | Adds a participant interaction and can delay ordinary work. The exact proposal needs its own safe current presentation; a link or mailbox check alone is not affirmation, and it must not grant access to an old-request file library.    |

Recommend A as a **source-bounded product judgment**, not a statement that all document reuse is appropriate or that participant confirmation never matters. Source-required certification, signature, current declaration, freshness, representation or confirmation remains mandatory. Those owner requirements can require B-like behavior for a particular request under either default. No legal/consent rule is invented by this research.

The action is staff supply of evidence, **not an automatic acceptance**. A new request/item still needs Q21's exact current staff review and every source prerequisite; Q22 alone owns actual fulfillment. Adding a reference must not transfer approval, claim the person submitted it, manufacture a fresh declaration or imply the participant saw it. Existing exact same-basis decision reuse remains allowed under Q21; acceptance in a different request/item is not that case. No universal second reviewer or unnecessary click ceremony follows: preserve whatever actual review/SoD the source requires.

## Why this fork is open and worth asking

The broad existence of reuse is already promised. Founder brief15 requires embedded work without repeated download/reupload;139/153 permits separately admitted typed uses through source commands; Q02 ADR29–39 ratifies those distinctions. Asking “reuse or always reupload” would re-ask settled intent. The open question is **who may supply the new-purpose evidence and whether this ordinary new target requires a fresh participant act**.

Q13 ADR59–61 deliberately permits a new authorized submission to reuse exact qualified custody only under its source contract, with truthful receipt/review lineage. That clause prevents stale commands from borrowing new authority; it does not select staff versus participant authorship. Q21's acceptance policy likewise requires actual target-specific review but does not determine who may supply a new ordinary candidate. The current Private Document Request glossary says the recipient is asked to supply documents; A would need a narrow explicit staff-assistance/source-admission amendment, not a silent relabeling of staff behavior as recipient submission.

This moves beyond notification defaults into a real File Manager and embedded-control journey. The next question should not reopen P23 Media curation, P28 resource publishing or broad central File Manager scope. I considered those alternatives: the roadmap explicitly retains the common File Manager, and P28 C38–C40 already require explicit staff curation, intentional publication and no extra routine moderator. A remaining general staff-resource owner mapping is real future work, but asking the founder to choose record/domain names would be an engineering question. Additional version-comparison product scope is also genuinely open in brief203, but staff-originating reuse is a more immediate admission/provenance boundary for the already-requested shared file foundation.

## Concrete ordinary journey

Illustrative example only: a new ordinary document request asks Nora for a document that authorized staff already hold in an eligible existing source. Elena opens the destination item and chooses **Use an existing file**, sees only the source-approved candidate information, selects the exact version and checks the target and provenance.

- With A, Elena deliberately supplies that version. The target truth says staff supplied existing evidence, retaining real actor/time/origin and new-use lineage. It becomes available for the target's required review, not automatically accepted or “submitted by Nora.”
- With B, Elena proposes that exact version. Nora's current, purpose-bound affirmation is required before the evidence can count as her supplied evidence. She does not need to upload the same bytes again. If she cannot lawfully inspect the proposed version, the system cannot solve the problem by exposing the old source; it must use the source's qualified alternative/help.
- Both remain in the destination's existing workflow. There is no personal Drive, blanket “reuse any file I can read,” global scan that leaks protected matches, copy-to-public shortcut or new permission engine.

This need not force a new specialized picker design. The actor policy is the founder decision; source-qualified destination-aware selection, exact versions, current authorization and truthful result are required implementation consequences.

## Constraints shared by A and B

1. **Current target permission, not an expiry shortcut.** The target must currently permit this new staff-originating evidence proposal/admission. No accepted/frozen/closed item mutation, source-intake prohibition or genuine hard deadline is bypassed. Conversely, the participant's upload/access expiry alone is not a universal prohibition on independently authorized staff source work. Q28 does not revive participant rights, create a fresh grant, extend retention or qualify a completed-read admission that never existed.
2. **Read is not reuse.** Check source release/reuse rights, current target admission/purpose, intended subject/recipient, exact version, classification/rights/safety/profile and any other applicable owner requirements. An attachment to a broader record does not enlarge the original permitted audience. Same bytes/name/person or a hash match does not establish suitability, permission or equivalent evidence.
3. **Truthful acts and current review.** Retain original origin/version/custody, actual staff proposer/supplier, target admission time and new-use linkage. Never rewrite the earlier submitter/time, fabricate the intended participant's affirmation/signature/declaration, or label old evidence as newly obtained. New target review and source-required fresh acts remain. Existing actual SoD applies; generic ordinary support does not add a universal second reviewer.
4. **No automatic new readback rights.** A staff-supplied file is not automatically the participant's own Q02/Q04/Q05 submission. Its appearance in recipient metadata, preview, original download or history needs exact source authority, and cannot expose the originating request's other documents/details. B also needs separately authorized exact candidate presentation before meaningful affirmation; it does not grant old-library browsing or every prior version.
5. **A new use is not a new physical file or a merge.** Reuse the qualified immutable byte identity with independently admitted target source meaning, review/currentness, access and retention. Re-scan/reprocess where target/current profile actually requires it; never transfer stale safety/acceptance by content equality. Unlink/withdraw one use cannot dispose of another use, hold or original evidence.
6. **A deliberate action with accurate outcomes.** Preserve destination item and exact selected version, current checks after waits, durable semantic identity and source/custody race protection. Unknown admission is recovered, not repeated as another submission. A stale picker cannot silently substitute the latest version or expand a recipient set. Reuse failure should preserve existing evidence and permitted work rather than force upload or weaken permission.
7. **Existing messages/work only through their owners.** Adding staff evidence can change the target's pending review under its actual source contract; it does not automatically email the participant, perform Q26 Request changes, create a staff assignment or copy historical Q27 notices. Native source event qualification governs any resulting work/notice. No new notification default is selected by this question.
