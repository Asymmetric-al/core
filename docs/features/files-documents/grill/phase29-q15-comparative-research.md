# Phase 29 Q15 — another continuation after an earlier continuation expires

Research date: **21 October 2026, Asia/Bangkok**. The parent reports Conrad ratified Q14 A and its full amendments. **Q01–Q14 are the accepted baseline; no Q15 answer is selected.**

This is public-document comparative research and proposed product framing. Only this note was written. No canonical document, product, account, permission, provider, dependency or UI was changed. No live competitor, native source, browser, assistive-technology or intended-user test was performed.

## Recommended next single decision

Ask whether **the same still-unfinished source request may receive another separately reviewed, prospective thirty-day access admission after an earlier fresh admission has ordinarily expired**.

Recommend **A: allow individually reviewed sequential admissions, without adding a preset repeat-count cap**, subject to the existing real purpose, original eligible requirement lineage, current source/issuer/recipient authority and genuine limits. Keep B, **one fresh admission only**, as a credible tighter alternative. Neither recommendation follows from a universal vendor standard or empirical Asym demand study.

This is a valuable single question because Q13 established the capability and Q14 resolved each admission's timing, while repetition remained deliberately open. It can resolve repeat eligibility and the coherent sequential boundary together without adding a duration menu, first-entry model, reminder policy or generic renewal platform. A third numerical limit would be arbitrary without a real owner reason; it need not be manufactured merely to offer three choices.

The central tradeoff must be explicit: **finite individual admissions do not create a finite cumulative request-access lifetime when there is no repeat-count or independent overall cap.** A therefore permits a potentially long sequence of separately justified admissions. It does not authorize an always-active grant, automatic renewal, uninterrupted access, recipient entitlement to approval, overlapping admissions, queued future periods or ignored hard limits. B instead makes the first fresh admission a final ordinary opportunity for that request, even when legitimate work still remains.

## What is already settled

- Q13's Fresh Unfinished Request Access is tied to the same eligible source purpose, recipient, original requirement lineage and current source permission. It is not access to arbitrary files or a general library.
- The original expired admission and each subsequent source effect remain historical facts. New access never rewrites an old end, adverse action, receipt, correction or acceptance.
- Q14 establishes each newly admitted standard period at its own qualified source issuance G plus **720 elapsed hours**, clipped only by genuinely applicable scoped limits. The end also bounds never-entered access. No reset on entry, resend, retry, activity or proof refresh exists.
- A same-effect retry recovers its original result; a new period requires a genuinely new deliberate source act. An unknown previous outcome is not permission to try a new admission.
- Exact source authority controls reading, uploading and pending-item correction separately. Earlier accepted/frozen work is not reopened just because access is granted again. Old unadmitted commands cannot borrow a newer admission; reuse of retained qualified custody, where permitted, requires the existing new deliberate admission rules rather than needless byte upload.
- Eligible source fulfillment during valid fresh authority may admit the separately scoped Q07/Q13 completed view, with its own fulfillment anchor and genuine caps. Fulfillment in an access gap cannot be made eligible retroactively. Q08 further fresh-read eligibility is not expanded by Q15.
- Requested-by targets, intake cutoffs, session/proof expiry, source authority, retained custody and device copies remain different things. A new access period does not alter the target or convert review delay into recipient lateness.

These are baseline requirements, not proof that the native implementation already enforces them. Q15 should inherit them, not restate them as another implementation framework.

### Why A is recommended, and when B would be preferable

A better preserves Asym's already-selected purpose-bound workflow and received evidence when a still-valid request needs more time. The recommendation is about continuity and source judgment, not a claim that recipients usually need repeated periods or that every correction is small. The same honest justification applies to never-entered prior access, prior technical difficulty or staff review delay only if a new admission is currently useful and lawful; none is automatically entitled to another period.

B is preferable if Conrad wants an express finality rule even when an otherwise-eligible request remains unfinished, or if the owning source cannot govern repeated decisions without routine rubber-stamping. It should not be sold as “simpler but worse,” nor should it be undermined with an automatic duplicate-request escape. Conversely, A is not equivalent to Dropbox-style indefinite storage: every admission remains a specific permission to work within the original authorized purpose and scope, and every expiry creates a real gap unless a later prospective decision succeeds.

Selecting A must acknowledge no new preset cumulative bound. Requiring a current, meaningful source purpose mitigates drift but does not mathematically bound total elapsed history. Existing independent hard caps still win. If evidence later shows chronic repetition or unsuitable source cohorts, that requires an explicit policy/product decision, not quietly stretching grants or inventing an unapproved cap.

[GOV.UK Check answers](https://design-system.service.gov.uk/patterns/check-answers/) supports a meaningful opportunity to review what will be submitted. Its example email/PDF is not a requirement for Asym. Both current pages were rechecked on 21 October 2026; no stable update date is relied upon.

[WCAG 2.2 SC 4.1.3, Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), **Level AA**, requires qualifying status messages to be programmatically available without taking focus. Announce the relevant grant/recovery outcome, not every repeated poll or ticking second. ## Boundaries the question should state plainly

1. **Sequential, not evergreen.** A new admission is considered only after the previous relevant fresh unfinished authority has genuinely ordinarily expired. A still-active grant, unresolved prior result or merely expired proof does not qualify. No overlap or scheduled automatic successor is selected.
2. **Same real work, not a renamed library.** The original eligible requirement lineage and current source scope remain the boundary. Changing a title, copying the request, adding new unrelated requirements or changing the recipient cannot launder another period. A truly new purpose uses its own separately authorized source process; this question does not define it.
3. **No retroactive repair.** Each qualified new issuance has its own G and actual U. Gaps remain gaps. Prior receipts, adverse restrictions, late corrections and completion facts are not rewritten; late observation recovers historical truth before deciding whether new access is needed.
4. **Permission must be current at the actual act.** Prior issuer authority or recipient familiarity is not enough. Two staff actions cannot create overlapping new admissions through a race. Same-effect retry and competing new intents must obey Q13's source serialization/current checks, not an added UI-only lock.
5. **A new grant is not evidence acceptance.** It cannot unfreeze accepted work, widen read scope, revive unsafe versions, accept a stale correction, or reset Requested by. The recipient need not repeat received usable work simply because an access period changed.
6. **No guaranteed further completed view.** Each eligible fresh admission retains Q13/Q14's conditional source-fulfillment transition and declared read scope. Neither actual late fulfillment nor a future promised grant backfills an expired period. Q08 remains separate.
7. **No hidden count or support escape.** A means no new preset count cap; B means one fresh admission, not “one unless support clones it.” Genuine existing caps still bind both. Automatic reminders, notification channels, date editors, approval escalation, cooldowns and a new total duration are not selected.

These are the smallest necessary meanings of the fork. Detailed proof remains inherited from Q13/Q14; a new general-purpose renewal engine is not warranted.

## Suggested founder-facing question

**If a thirty-day continuation expires and the same request is still legitimately unfinished, may authorized staff grant another continuation?**

- **A — Allow another reviewed continuation (recommended).** Only after the prior period has ordinarily ended, and only while the same purpose, recipient, work and current authority remain valid. Each approval creates a new prospective period of up to thirty elapsed days. No automatic renewal, overlap or preset repeat-count cap. This preserves continuity, but allows cumulative access to continue through separately justified approvals.
- **B — One continuation only.** If that fresh period ends while the request is still unfinished, this ordinary unfinished-access route is final for the request. Staff retain independent source work and governed help; they cannot clone the request merely to reset the limit. This provides a stronger count limit but can end access while legitimate work remains.

Recommendation rationale: choose A if continued legitimate work should be judged on its current purpose and authority rather than a fixed historical count. Choose B if one final continuation is itself an intended product restriction. The decision is not whether to keep one grant open forever; both preserve real ends and the existing source safeguards.
