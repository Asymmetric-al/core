## Outcome and material amendments

Keep A: the ordinary source supplies its applicable approved policy and the existing request review shows a readable summary. The normal deliberate **Issue** action can apply that valid binding. The issuer does not need a routine policy checkbox, records quiz, second approver or extra confirmation dialog. A source-required individual determination remains a real choice; missing or ambiguous policy is not a choice the UI can invent.

The important amendments are concrete:

1. Show safe scope and actual trigger as ordinary readable text, not a policy name alone or essential hover-only information. Keep Access ends separate, and do not promise all-copy deletion on one date.
2. Distinguish known approved default, required authorized choice, missing applicability facts, no applicable approved policy and temporary inability to check. Each needs an honest result and a usable next action.
3. Policy admission applies before earlier durable preparation/allocation/expensive processing as required by Q02. Later Issue cannot authorize already-collected bytes retroactively. Preserve only independently lawful preparation.
4. Recheck the exact relevant source/purpose/policy/actor basis at admission. Preserve current valid choices and draft input; do not silently replace them when a default changes. Unchanged effective meaning should not create another approval ritual, but a stale authoritative basis is not validated by an identical displayed name.
5. A wrong admitted assignment needs a small actual source-owned **Correct policy assignment** remedy under separate records/source authority. It must preserve the old assignment and append the corrected current applicability, including the actual affected-class/trigger evaluation. It is not a free-form timer editor, hold release, object deletion or ordinary issuer override.
6. Preserve original result recovery, privacy of policy/hold facts, truthful pending states and current-result disclosure. A lost response is not a failed issue or permission to issue a second request.
7. Make missing-policy repair demonstrably capable. The actor must be able to reach the authorized source/records owner, preserve lawful work, and return to refreshed review after repair. Repair does not issue automatically. No new global governance console or ticket per request is necessary.

These are product and source-contract recommendations. Actual policy substance remains R-POL-ordinary work; native authorization, custody, disposal and real-user evaluation remain evidence gates. No frequency, compliance rate, time saving or ministry workflow has been measured.

## Concrete minimal experience and copy

The existing request composition/review remains the primary screen. A quiet **Retention policy** section shows the current approved name, safe covered purpose and actual trigger. **View retention details** is secondary. **Change retention policy** appears only when the source permits another compatible selection; a genuine selection-required case has an explicitly labelled choice with no guessed answer. ### Small permanent recovery paths

**Before admission:** edit permitted facts/choices inline; cancel or return without changing admitted records. A known valid selection stays selected while its basis remains valid. A new default does not silently overwrite it. When it is no longer valid, explain the changed condition and show current allowed choices. Retain independently lawful draft information; do not create an offline persistence feature by calling it draft preservation.

**No policy or unresolved conflict:** the supported source must have an actual named responsible authority and usable existing route for that authority to establish or correct the approved binding. The handoff contains only allowed minimal request/source references. The issuer can return to the same lawful draft, refresh the summary and deliberately issue. There is no automatic issue after an admin fix, no policy ticket per request by default, no unqualified direct editing of the approved catalog and no forced user attestation to bypass absence.

**After admission:** adopt the narrow proposed source-owned Correct policy assignment act for a proven mistake. The currently authorized records/source actor reviews the exact original binding and current intended approved result, supplies concise factual basis where the source requires it, and deliberately commits an attributed correction. Trusted context can provide a routine cause; no blanket extra essay or second approver is introduced. The original assignment, actor, version and trigger facts remain historically attributable. The current corrected applicability and impact on actual retained classes are explicit; required source/custody work has an owned result/recovery, not an unlabeled success. A genuine source-proved trigger correction is allowed by that source's exact authority; arbitrary timer reset is not.

**Urgent restriction or disposal concern:** use the actual independently authorized source/privacy/records action without waiting for unrelated draft validity or completion of a new assignment. Do not invent a universal hold, assume indefinite retention is safer, or perform irreversible cleanup while required authority/coverage is unknown. Actual floor/ceiling conflicts require their qualified owner; Q62 cannot choose a generic winner.

**Mistaken correction:** another deliberate current source correction of the erroneous finding/assignment, preserving both histories and current independent restrictions. No old snapshot restoration, old trigger replay, new read grant or automatic revival of disposed bytes. If bytes are no longer lawfully recoverable, say so and use the actual source remedy; no fictitious universal Undo.

## Strongest alternative and simplicity conclusion

B remains a credible design: deliberate policy application in the existing review can highlight real differences where an issuer supplies material context. Its weakness is asking again even when the source already knows the only valid answer. A is preferable for that ordinary resolved case, provided required individual choices remain explicit and the summary is useful. The choice is not between safety and speed; both still need actual authority and correct policy content. No empirical time/error advantage is claimed.

No new settings matrix is required. Actual source-supported policies/choices remain records-owner concerns; ordinary staff see only applicable behavior. No generic catalog, workflow engine, approval queue, per-file wizard, AI classifier, policy-specific inbox, new email or branded governance center is justified. The narrowly proposed correction act closes a real error path and must not be widened into ad hoc retention administration.

## Seven founder checks

### What could go wrong with this answer?

An approved-looking default may conceal an incorrect purpose, stale revision or incomplete copy scope; a correction may be mistaken for deletion. The exact source basis, readable scope/trigger, original-result recovery, protected history and actual records remedy address those risks. Missing policy content still blocks the affected capability.

### What hidden assumptions are we making?

Actual ordinary policy schedules, allowed choices, operator qualification, workload, user comprehension and deployed command behavior are not proved. The default assumes only that a particular supported source can establish its applicable approved rule. It cannot infer missing jurisdiction or classification facts, and the note contains no invented ministry observations.

### How does this affect the whole product?

It adds a bounded ordinary assignment interaction and required error recovery, preserving all specialist/public/source/copy owners. It does not transfer P18/P21/P23 meanings into ordinary files, collapse used-in references or rewrite access, submission, review, notification or disposition contracts.

### How does this affect the end-user experience?

The issuer sees a concise governing summary and ordinarily issues once. Real choices, missing facts and repairs remain usable. Participants retain their current upload/access/help journeys and receive only authorized explanation. Records operators can correct a proven wrong assignment with history and actual impact visible, rather than raw SQL or a powerless help instruction.

### Does this follow modern best practices?

Current primary docs support visible governed defaults and manual choices, while GOV.UK directly warns against pre-answering real questions. W3C adds concrete accessible behavior. The recommended synthesis is a source-resolved fact plus explicit real exceptions, not a universal industry rule, legal period, user study or native conformance claim.

It fits only through the actual source/P12, Q02 preparation, Q25 issue/recovery and Q39 default boundaries, with existing shared UI. The runtime reviewer reports adjacent native changes, not a current ordinary policy catalog or qualified path. Real policy, legacy, native writer/reader/custody and restore proof remain explicit.

Keep selected A with U01–U18. Adopt the minimal attributed correction/repair route and prove the exact lifecycle rather than adding ceremony or returning to a broader feature vote.
