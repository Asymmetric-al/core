# Q65 — Preserve collection evidence and allow optional ongoing partner reference

2026-10-28, Asia/Bangkok. **Fully ratified by Conrad on 2026-10-29: Q65 A+B and all required amendments.** Reviewed disposition: Accept with required amendments; the complete corrected decision is adopted.

Support both purposes: keep the collection/review/handoff record under its existing rules, and let authorized staff deliberately admit suitable accepted evidence for ongoing partner work when needed. The additional use is optional, independently governed and tied to exact evidence. It does not make every accepted document available to every partner-record reader.

The simple product shape is **Use for partner reference**, a contextual reference entry with truthful availability, **Replace reference**, and **End reference**. The reference reuses qualified held evidence; it does not require another upload, another storage system, a legal-agreement register or a new workflow engine. These labels express outcomes, not a mandatory new top-level screen or schema.

The [ratified ADR0065](../docs/adr/0065-optional-source-owned-partner-document-reference.md) carries the identical corrected decision. Partner Document Reference is adopted in the Files glossary. Existing Q01–Q64, 62 prior ratified feature ADRs, all 33 prior Files terms and the entire root glossary remain unchanged.

## The smallest complete user journey

1. **Finish the ordinary document work normally.** The collection record, receipt, processing, exact staff acceptance and request fulfillment retain their existing meanings. No reference checkbox is required to finish collection.
2. **Choose Use for partner reference when useful.** Offer the contextual action for eligible accepted evidence. Use the known qualified partner context; show a bounded authorized choice only when the destination is genuinely ambiguous. No general file picker exposes unrelated records. Preparing the choice is inert.
3. **Review the actual consequence briefly.** Show the exact evidence/version or complete accepted unit, destination partner and concise ongoing-purpose/policy summary that the actor may see. One deliberate command admits the use. No forced preview, second approval queue, routine reason essay or repeated legal questionnaire is introduced.
4. **Return from the partner context.** Eligible staff see the admitted reference and its exact material, safe provenance and present availability. Access does not require browsing the original request conversation. It also does not reveal that conversation, internal review history or other uses by implication.
5. **Handle changes truthfully.** A newer upload does not replace the reference. Use Replace reference to deliberately adopt another qualifying accepted basis. If earlier acceptance is corrected, show only permitted current source consequences and stop affected reliance until resolved; lawful repair/history reading may remain.
6. **End the use when it is no longer needed.** End reference stops this operational use. The source record states what ended and preserves required history; it does not say the document was deleted. A continuing or newly arising lawful need—including repair of an accidental End—can admit a fresh use after current qualification, with linkage to prior history rather than revival of the old one.

Suggested concise copy: “Available for partner reference”; “This reference uses the version shown”; “Reference ended. Collection history is unchanged.” These are comprehension targets, not legal-currentness claims or a new global status enum. Source-restricted information must not appear in copy merely to explain a denial.

## Ratified decision and amendments

**Q65-C01 — Support A+B without compulsory expansion.** Preserve the complete collection/review/handoff record under its existing policy and allow optional, independently admitted Partner Document References for ongoing work with a particular partner. A remains a fully usable baseline; B is available when its real purpose and current authority qualify. No automatic reference follows from upload, acceptance, request fulfillment, a partner relationship or workflow completion. Preserve all Q01–Q64, other source families and legitimate existing uses.

**Q65-C02 — Name the narrow write authority.** The ordinary partner-document-reference source owns each reference's admission, exact adopted evidence basis, current lifecycle, ending/replacement, business history and records-policy binding, using a qualified Phase9 partner context. This declares the narrow source contract to implement/qualify, not an assertion that a native service already exists. Phase9 retains partner identity/relationship truth; the ordinary request source retains receipt, acceptance/correction and fulfillment; Phase29 owns shared custody/copies; Phase12 owns authorization decisions; GEN-05/Workflow coordinates only qualified source receipts. No new agreement-validity, signature, organizational-representation, membership, giving or partner-approval authority is created.

**Q65-C03 — Deliberate, contextual admission.** Provide a source-context Use for partner reference action after the exact relevant evidence has a qualifying source acceptance, at the supported handoff point or later. Do not require whole-request or partner-process completion unless the actual reference-purpose contract requires it; do not allow acceptance to be assumed from a partial workflow node. Optional preparation selects only permitted current evidence and a qualified target and creates no operative reference or custody authority. The normal command clearly identifies the additional use; do not silently bundle it with Accept or add a mandatory combined approval flow. Actual capability/policy and eligible destinations constrain tenant/staff choices. Q66 supplies separate tenant-controlled ordinary policy authoring; reference admission itself remains a simple contextual act and requires no policy editor or governance form.

**Q65-C04 — Exact evidence and acceptance basis.** Bind the admitted unit to immutable version/assembly/input-output identities and its actual source item/requirement revision, contribution/provenance and relevant acceptance basis. Q21 may accept a multi-file set and Q56 may admit an indivisible assembly; preserve that actual unit and coverage. A component cannot be presented as independently accepted or a complete agreement merely because it belongs to an accepted set. A source-qualified sufficient subset may be admitted when its actual acceptance basis and required dependencies remain intact; it is not a new per-file acceptance. A narrower representation is allowed only where the source expressly qualifies its meaning and disclosed coverage. Keep original participant versus staff-supplied acts truthful. Byte/digest/name equality is not equivalent purpose, acceptance or rights; a later acceptance of identical bytes is a different basis when its source facts differ.

**Q65-C05 — Separate admission, reading and management powers.** Admission requires current source permission to reuse the exact material for this destination purpose and current target authority to admit it, plus actual policy/custody eligibility. Reading an admitted reference requires current target-purpose read/field authority and applicable continuing source restrictions; it does not require original request-browsing permission, inherit the original participant's access window or grant the original transcript/internal review/other-use history. Management actions such as End may use sufficient permitted metadata without body-read/reuse eligibility where the source authorizes them. Relationship lead, original reviewer, partner record access, folder membership, URL and service key are not substitutes for these separate powers.

**Q65-C06 — Trusted context and current source facts.** Derive tenant/environment, actor, author, policy/approval attribution and trusted execution context from native validated identity and current source/P12 facts. Caller IDs are validated selectors, not authority. Preserve qualified limited/no-Party paths where applicable; do not fabricate a profile, membership or demo Tenant. Current staff or system/NHI authority, including actual owner ceilings/revocation where relevant, applies at each action and result disclosure. Recheck relevant facts after waits at the owning boundary; stale JWT claims, browser state, user metadata, cached acceptance or a queued role alias cannot authorize an effect.

**Q65-C07 — Coherent admission and custody protection.** Admit the exact source use, required copy/reference protection, trusted history and recoverable original result coherently before making it available for operational reliance. Order admission with current source restrictions/acceptance corrections and custody's hold/use/writer/disposition boundary; deletion-claimed or unresolved possibly-deleting material cannot gain a favorable new use. Preserve all required components of an accepted unit. Use a real short transaction or proved durable fence at the actual source/custody seam; multiple SDK calls or a withTenant callback are not one transaction. No long SQL transaction across provider IO, transient list count or asynchronous best-effort link is acceptable proof. Safe incomplete work is not an available reference.

**Q65-C08 — Flexible identity and duplicate handling.** Distinct source-legitimate documents, versions, periods or needs may coexist; impose no universal one-agreement-per-partner or one-active-reference-per-origin-lineage rule. Prevent duplicate equivalent active uses under the actual target, admitted purpose/need and exact evidence basis using source-defined semantics and enforceable uniqueness or equivalent serialized admission. Do not use a permanent digest/target uniqueness rule that blocks a fresh authorized admission after End, including for a continuing lawful need. An equivalent successful replay/no-op preserves original attribution and time; a different legitimate reference is not merged merely because bytes match. No slot graph, arbitrary caller purpose string or configurable cardinality engine is introduced.

**Q65-C09 — Use lifecycle and truthful availability.** Distinguish inert preparation, durably admitted use, current permitted/restricted/temporarily unknown availability, and deliberately ended/replaced history. Availability is derived from current source rules, not a second legal-validity or acceptance flag. Temporary permission/technical uncertainty can clear under the same still-admitted basis when actual current proof permits; it is not a terminal end. Explicitly ended or replaced uses never revive from restored access, background replay, cache refresh or database restore. Seeing retained history never itself authorizes ongoing operational reliance.

**Q65-C10 — Deliberate replacement.** Replace reference acts on one exact selected current use/generation and a separately qualifying candidate evidence basis for the same admitted target/purpose. Preserve the old use and its actual history while preparation occurs; commit the qualified successor and old use's operational end with coherent custody protection and original-result evidence. If replacement fails, do not claim it succeeded or remove a still-lawful predecessor; an already unsafe/restricted predecessor does not become a fallback just because replacement failed. Do not silently follow latest uploads, reaccept evidence or mutate the original use's historical target/basis. Identical bytes with a genuinely different accepted basis are not a semantic no-op. Actual equivalent existing-reference reconciliation must not create duplicate active effects.

**Q65-C11 — End and fresh use again.** End reference deliberately ends only the selected ongoing use under current source management authority and expected basis. It does not delete collection evidence, end unrelated uses, erase original acceptance/F/history or certify physical disposal. End must remain usable through sufficient permitted source metadata when bytes or reuse eligibility are unavailable. End remains independently usable when unrelated replacement or other preparation is invalid or unsaved; urgent authorized containment does not wait for a replacement. An explicit wrong-target correction ends the mistaken use and, only with fresh destination/source authority, admits the intended new use; never reparent history in place. A continuing or newly arising lawful need, including correction of an accidental End, may create a fresh distinct admission linked to prior history under current authority once any operative end cause is resolved; no forced reupload or invented different business need is required. A replay returns its original committed result with any separately qualified current state; it cannot reactivate the ended use or rekey around restrictions, unresolved effects or an operative end cause. No generic Undo or permanent ban on all future lawful uses is selected.

**Q65-C12 — Acceptance correction and changing source restrictions.** Register this use as an affected consumer of the relevant source acceptance/restriction facts. Q60 findings, source withdrawals/restrictions, policy changes and other relevant adverse facts must prevent unsupported current reliance through current source/custody checks, even before an async badge or projection catches up. Preserve the reference's actual admission and original source history; do not automatically erase or universally terminate it. Independently allowed repair/history/body inspection may continue under its exact purpose. Clearing an erroneous blocker can restore eligibility of the same still-admitted exact basis only under current proof and remaining restrictions. A genuinely new acceptance/basis requires deliberate adoption through replacement or fresh admission; identical bytes do not silently retarget old reference history. No stale “accepted/current” presentation may hide the current source consequence.

**Q65-C13 — Atomic effects, idempotency and original-result recovery.** Each admission, replacement, End and fresh re-admission binds tenant/environment/source purpose, target/use generation, exact intent/basis and a durable semantic effect identity. Commit authoritative facts, required history, reference protection and original outcome coherently; durably admit required follow-through. A matching committed operation recovers before new eligibility under current result-disclosure rights. Changed intent under the same identity conflicts; complete semantic no-op, stale ABA basis, genuine equal-display correction and expired unverifiable intent remain distinct. Repeated transport keys, events, workers or native/optional Workflow callers cannot duplicate use or revive ended work. Reconcile unknown source outcomes before new work; notification/projection failure is not rollback of a committed use or permission for another effect.

**Q65-C14 — Actual independent records obligations.** Bind approved policy for the collection record and the ongoing use, including actual class/applicability/authority/version, typed trigger/date precision, preservation/privacy bounds, hold/conflict powers, mode and lawful correction/recovery. Preserve historical assignments while applying qualified current successors. Do not infer a period or clock from “agreement,” handoff, relationship end, reference addition, last read or changed default. A new reference must have a legitimate admitted purpose and cannot manufacture retention to evade privacy/disposal duties. One use ending is not all-copy deletion; another actual required use remains protected. Q62/Q63 current coverage, finite dispatch, possible-effect fences, Stop and physical-outcome/restore rules remain fully binding. Missing/unknown is not none, retain-forever or a guessed default.

**Q65-C15 — Structural and database safety.** Enforce mandatory tenant/environment/source/target/use/generation/evidence/policy relationships with typed same-scope keys or proved equivalents, null-complete references, source-appropriate uniqueness, state/time constraints and indexed access. Platform-owned global capability or specialist-source definitions may remain global. Q66 ordinary tenant business-policy definitions and versions are tenant-owned while all assignments/effects stay scoped. Prevent general updates from reparenting uses, swapping immutable evidence, forging actors/policies or rewriting received/accepted/end history; reject unsafe partner/account/document cascades. Verify effective named/PUBLIC/default/inherited schema/table/column/sequence/EXECUTE grants, actual function owners/overloads/search paths, ENABLE/FORCE/BYPASS/service behavior, policies, trigger-adjusted rows, SELECT/RETURNING/INSERT/UPDATE old-and-resulting/DELETE/UPSERT/MERGE, views/materializations, REST/GraphQL/RPC/Storage and worker/import/legacy/operator paths. Preserve one source/P12 decision layer plus coarse Tenant RLS and coherent app/database context with pooled success/error/cancel/retry reset. Zero affected rows is not success; keywords alone are not security proof. No money, currency or posted financial facts change.

**Q65-C16 — Small, complete contextual UI.** Use existing source/request and Phase9 Files context with shared Base UI/base-maia components. Present Use for partner reference, exact current entries, deliberate Replace and End with concise permitted impact and truthful result. Explain that End stops this use while collection history remains. Show exact selected version/unit and sufficient safe provenance; never label a reference “legally valid,” “current agreement” or “partner approved” by inference. ## Ratified glossary term

**Partner Document Reference**:
An independently admitted, source-owned use of specified document evidence for ongoing work with a particular partner. It is distinct from the original collection record, a sharing permission, and a determination that an agreement is valid or current.
_Avoid_: reference letter, bookmark, active agreement

Adopted placement: Files and Documents CONTEXT.md beside File Purpose. This domain term distinguishes the admitted business use from a navigation link or Private Document Share; it does not name a new custody store or general contract-management product.
