# Phase 29 Q54 — Deliberate reuse with optional existing-file suggestions

2026-10-26, Asia/Bangkok. **Fully ratified by Conrad: Q54 A+B with the complete required amendment package.** Reviewed disposition: **Accept with required amendments**; all amendments are adopted. The combined decision retains deliberate Add existing file and adds narrow optional pre-intent suggestions. Q01–Q54 are ratified; all31 glossary definitions remain unchanged. The ratification used A and mentioned a glossary refinement; this is recorded as adoption of the actual reviewed A+B/no-glossary-change package, not a reversion to manual-only or an invented term edit. Research and one Q55 question are authorized; its answer, implementation and formal publication are not inferred.

## Decision and strongest alternative

Allow an eligible staff member choosing a local file for an ordinary request item to receive a quiet suggestion that an independently discoverable and reusable existing version may match. Keep Upload and add and Add existing file useful. The suggestion creates no source evidence and never selects a file automatically. It is assistance before a source action, not duplicate cleanup or a new review stage.

Manual-only A remains the strongest simpler alternative: fewer processing and privacy paths, with the real cost of missed reuse under unfamiliar names. B has a documented discovery benefit and the founder has chosen to include it. That resolves the product scope; implementation must still demonstrate useful pre-intent behavior, safe current permissions and bounded resource use. No observed Asym task frequency, time saving, user preference or invoice saving is asserted. An on-demand matching button adds the same matching authority plus another action and is not the selected compromise. Mandatory matching, automatic reuse, post-upload interruption and global deduplication are rejected.

## Complete staff and recipient journey

The illustration is hypothetical: Nora supplies a local inventory for Elena's ordinary item. An eligible version is already held with another approved name. It is not a claimed observed ministry workflow.

1. **Enter the actual item.** Show permitted recipient/item/instruction context and the existing **Upload file** and **Add existing file** actions. Hide actions not currently allowed. Staff who already know the file can go straight to the existing picker; no local file is required for manual reuse.
2. **Choose a local file.** Show its recognizable name/type/size and actual intake limits. Native file selection remains available beside any drop zone. Required upload checks retain their meaning. Optional matching may begin only within its qualified cohort; it does not disable **Upload and add**, consume a source slot or claim upload progress.
3. **No useful suggestion.** Show no routine warning, check-success banner or repeated spinner. Disabled, unsupported, bounded-out, empty, failed and still-running lookup are distinguishable internally. Absence of a hint never means unique or fully searched. If a previously opened candidate view fails, show a local actionable error without treating the upload as failed.
4. **Timely permitted suggestion.** Display one quiet inline cue associated with the selected file: **An existing file may match** with approved identifying metadata. A single safely distinguishable eligible candidate can offer **Use existing file** directly; **Review existing file** is optional. Multiple or ambiguous candidates use the existing picker for a deliberate exact choice. Dismiss hides assistance for that current selection through repeated results/refreshes; changing the selected file starts a new comparison context. Do not reannounce the same hint or use warning colors to imply the new contribution is wrong.
5. **Review by choice.** Open the existing source-aware picker/detail composition, with a bounded list of permitted exact-version candidates when necessary. Safely distinguish candidate name, type, version/source context and date only as allowed. No hidden total, arbitrary authoritative winner or automatic preview. Preview/original/history remain separately qualified; sufficient metadata can support lawful reuse without forcing a broader read.
6. **Return without an effect.** Back/close returns focus and the still-lawful local selection. Review alone neither adds evidence nor cancels preparation. A reload cannot promise restoration of a browser File object; explain necessary reselection without inventing an offline file store. Restored query state must not resurrect old authority or dismissed hints.
7. **Choose one source action.** In the inline cue or candidate context use **Use existing file** with the explicit target; this is the one Q28 add action, not a second preparatory selection that demands a redundant final confirmation. Or return and choose **Upload and add**. Once either command may have begun for this intended addition, fence the other path and late hints, show the true source-operation state, and recover the original outcome before changing routes.
8. **Handle changed facts.** An obsolete candidate or changed target can reject new admission. Explain **This file is no longer available for this item** only when safe, preserve lawful context, and offer deliberate return/selection. Do not auto-upload the local file, choose another version, reopen the request or broaden permissions.
9. **Finish truthfully.** A Q28 contribution has its actual new staff-use history and original file provenance; Q53 has its truthful new staff-upload receipt. Checking/inspection/review/fulfillment remain separate. A failed screen refresh after known success keeps the known success and retries refresh; an unknown command result says **Checking whether the file was added…**, not **Upload failed—try again**.
10. **Preserve downstream simplicity.** Recipients, donors and missionaries see only their existing authorized status and work. They get no matching UI, staff directory, new file-read grant, notice, affirmation or forced action. Actual source-required participant work remains. Administrators may disable the helper without disabling the two baseline routes or undoing committed evidence.

On small screens use the same sequence with a single-column candidate list and existing responsive picker/detail surface. Long international names wrap without relying on tooltip-only identity. Bidirectional text is safely isolated; dates use the existing locale/time-zone contract and never rank authoritative currentness by formatted labels. Controls retain keyboard order, non-drag operation, usable targets, reflow, IME input and visible focus. Announce a new actionable hint once politely; reading a list need not announce all candidates. New content must not shift the primary action under a pointer. No motion, hover, color, thumbnail or full side-by-side view is necessary to understand the choice.

## Ratified decision and amendments

**Q54-C01 — Selected combined scope.** Preserve Q28 Add existing file and Q53 Upload and add, and admit optional existing-file suggestions only for eligible staff preparing a local file for an eligible outstanding ordinary Document Request Item. This explicitly replaces A's no-matcher exclusion and narrowly extends Q28/Q53's prior exclusions. It is a separately qualified source purpose under Q38, not general document-body search. No participant matcher, visual/semantic similarity, OCR, AI, bulk all-matches action, physical deduplication or generic duplicate-management product follows.

**Q54-C02 — Current authority before disclosure.** Trusted server context determines tenant/environment, native human principal including qualified no-Party staff, source/item/subject/purpose and current matching/discovery authority. Return only exact held-version/use candidates independently permitted for disclosure and current target reuse. Upload, read, assignment, custody possession and a claimed fingerprint grant none of those powers. Apply field/source restrictions before presence, rank, count, pagination, thumbnail, timing-dependent signal or serialization; one visible use never exposes another. Independent preview/read/history and final admission reauthorize through their actual owners. Current source/P12 is the single permission authority.

**Q54-C03 — Untrusted query, trusted held facts.** A bounded local fingerprint is discovery input, not proof of uploaded bytes, custody, authenticity, ownership, freshness or intent. Qualify a collision-resistant full-original fingerprint contract with compatible algorithm/version/byte coverage; trusted held facts bind the actual immutable original and verification lineage. Never substitute a filename, MIME, size, unqualified ETag, thumbnail, rendition, normalized output or sampled resume fingerprint. Do not trust caller metadata or promote a query into the held catalog. Use possible-match wording; an eligible candidate may be lawfully returned before any incoming transfer, but the browser value never certifies equality. No new upload is required just to discover an independently permitted held candidate.

**Q54-C04 — Useful quiet assistance.** Begin bounded optional work only in the current selected-file context before source intent. Keep the ordinary Upload and add action available during helper work; never wait on the helper, add a routine check modal or demand another completion click. Show a cue only for a currently permitted useful candidate, using An existing file may match. One safely distinguishable candidate may offer Use existing file directly with its permitted identity and explicit target; Review existing file is optional. No default-selection, scary duplicate badge, routine successful-zero banner, repeated announcement, per-file email or later cleanup prompt. Failed or incomplete checking is not global absence and does not relax Q53 safety checks.

**Q54-C05 — Deliberate exact source choice.** Candidate review has no source effect. Show sufficient permitted context to choose the exact existing use/version and target, with independent preview only when allowed. A safely identified single candidate needs only one deliberate Use existing file action; do not require opening details first. Multiple or insufficiently distinguished candidates use the qualified picker without preselection. Use existing file performs the existing Q28 addition with actual source cardinality, restrictions and staff attribution; it creates no fresh original receipt or inherited acceptance. Keep a lawful route back to local upload. Multiple eligible candidates need bounded deliberate selection, not an arbitrary first match, merged provenance or permission union. An identifier without safely distinguishable context cannot justify blind addition. If the intended exact contribution is already current in the target, preserve Q28's truthful existing-membership/no-op and original-attribution rules; do not manufacture a new contribution or cancel the local upload automatically.

**Q54-C06 — One intended addition across routes.** Bind either source act to the same current intended addition and immutable chosen route/payload through the existing source operation boundary, with a server-enforced winner. UI disabling alone is insufficient. Once either Q28 or Q53 may have begun, fence alternative commands and late hints; recover a matching original outcome under current disclosure before interpreting new eligibility or changing intent. Changed immutable intent conflicts. Do not automatically fall back from failed reuse to upload or vice versa. A definitively unstarted/failed or canceled act can be deliberately repaired under current source rules; an indeterminate act cannot be assumed absent. Distinct later intentional eligible contributions remain possible even with equal bytes. No global digest uniqueness or new durable chooser business entity is required.

**Q54-C07 — Currentness and pure lookup.** Bind responses to actor/context, exact target/relevant basis, selected-file generation and query generation, not a digest alone. File replacement/removal, dismissal, context/authority change, helper disable, expiry and source-operation start invalidate relevant pending results. Recheck at the current serving and Q28 admission boundaries; no globally locked lookup snapshot is promised. Pure comparison creates no source receipt, operation/effect slot, evidence revision, retention reference/hold, acceptance, reservation or completion hold. Required protected access/security audit remains allowed. Lookup retry is a newly authorized bounded read, not permanent replay of an old disclosure grant. Candidate/catalog projection lag, source change and independently permitted post-delivery changes retain honest consistency limits; late events or restored caches cannot revive restrictions or old choices.

**Q54-C08 — Tracked preparation and cancellation.** A lookup needs no incoming storage session. If qualified preparation already exists, choosing reuse only retires that intended local preparation through Q53's supported cancellation/recovery path. Local Remove, worker cancellation, lease/token expiry and physical deletion remain distinct. Account for live grants and in-flight writes, original unknown admission/deletion outcomes, retention, holds and every reference before any cleanup. Never delete on match, route switch or catch. A canceled helper neither cancels a committed source operation nor erases history; Q28/Q53's actual removal/remediation remains available independently.

**Q54-C09 — Preserve independent domain meanings.** Equal bytes do not merge documents, subjects, source uses, origin, rights, consent, retention, acceptance or currentness. Personal participant requirements remain real. Q21/Q22/Q23/Q52 review and fulfillment are unchanged. Actual new Q28/Q53 admission retains Q24/Q27's controlled source-actionability effects; query/hint/dismissal creates no task, notice, reminder reset, Q51 attention or access clock. Participant reading/history/status follows existing authority. New independent uses do not copy folder/labels/Q50 names/comments; actual already-qualified replacement keeps only its exact existing exception. Official documents, private specialist evidence and Media retain their owners.

**Q54-C10 — Limited tenant and staff controls.** Provide one tenant-governed helper enable/disable control within the established configuration ownership, without a standalone settings product or per-role/per-channel matrix. Default it enabled only as part of explicit qualification/activation of the declared cohort; do not silently activate existing tenants through a schema/backfill default. Staff can dismiss assistance for the current selection without repeated reappearance, including inspection return or an Off-to-On cycle. Re-enable permits a fresh currently authorized lookup for a still-applicable nondismissed selection, never replay of old results or revival of a dismissed generation. Off stops new helper work and fences pending hints; it does not remove manual reuse/upload, cancel a started source operation or revoke independently lawful Q28 selection/read/admission. No fingerprint retention or search entitlement is created by enabling it. Unresolved helper policy means no hint, not proof that the helper is Off or that no eligible file exists. Activation and configuration changes are attributable; ordinary matching does not need a persistent personal preference system.

**Q54-C11 — Protected query state.** Fingerprints, queries, filenames, candidate identifiers and metadata are protected purpose data even if no result is shown. Keep raw values out of URLs, generic logs/analytics, public/shared caches and unapproved durable browser storage; include request capture, error reporting and session replay in proof. Use only the minimum qualified transient state and retained technical metadata with actual owner retention. A digest is not anonymization. Current context changes clear protected presentation and fence late results, without claiming to erase information already lawfully delivered. Qualified internal diagnostics must not become another searchable private corpus.

**Q54-C12 — Small native architecture and database guarantees.** Sensitive lookup and source mutations belong in packages/api, using the current source/P12 and custody seams. Clients cannot retarget scope, actor, version, provenance or trusted verification. Prove actual grants/default/inherited privileges, RLS USING/WITH CHECK/SELECT/RETURNING, view/function/RPC owners/search paths and every direct/browser/service/operator/import/restore/storage path. Allowed updates cannot transform permitted rows into forbidden facts. Coarse tenant RLS remains prescribed defense; no duplicate permission store. No new money field, raw-file/base64 column or unbounded JSON history is introduced.

**Q54-C13 — Bounded resources and fair failure.** Before activation declare and measure B01–B06 for actual supported devices, file/corpus sizes, concurrent users and tenant skew. Browser whole-input hashing must fit measured memory/CPU and responsiveness limits; unsupported/oversized/slow work skips the helper without reducing independently qualified upload limits. Cancel/release obsolete workers, buffers and object URLs with proved finite settlement; do not promise instant abort. Validate query data/algorithm/length and bound rate, candidate work, pages, concurrency, retries, cache and backfill. Apply fair server limits independently of a client flag. No external matcher, mandatory Realtime, unbounded backfill, extra provider or processing platform is required. **Q54-C14 — Accessible Core interaction.** Reuse shared Base UI/base-maia and suitable inspected ReUI file selection/status/list composition, replacing unlimited/default and simulated state with actual qualified bounds and source facts. Preserve stable primary actions, selected-file context, target identity, return focus/scroll, logical reading order and safe localized names/dates. **Q54-C15 — History and diagnostics.** Q28/Q53 continue to record the actual source act, actor, exact use/version, occurrence, original result and required downstream intent. A hint is not a durable business event and does not need a permanent per-query history. Store only necessary protected operational correlation, qualified failure classes, resource measurements and configuration audit. M01–M06 have named owners and responses; monitoring never substitutes for permission or concurrency guarantees.

## Adversarial check

### What could go wrong with this answer?

Hints can reveal protected existence, mislead about equality, race two source additions or slow the normal task. Current pre-cue authorization, honest possible-match wording, one source-operation winner and measured finite optional work address those specific risks.

### What hidden assumptions are we making?

The example assumes an eligible, independently disclosable held version and useful pre-intent timing. Demand, device performance, actual digest coverage and cost are unmeasured. They are qualification inputs, not claims that the feature already works or that every selected file gets a hint.

### How does this affect the whole product?

It adds one ordinary staff-discovery purpose while preserving manual reuse, upload, review, messages, participant rights, public Media and specialized document identities. Custody facts do not become operational approval, and no new global file object or permission store follows.

### How does this affect the end-user experience?

Known-file users go straight to Add existing. Unknown-file users may get a quiet useful candidate. Everyone can continue the original upload without waiting. Review is reversible; actual source commitment is deliberate and recovered reliably. Recipient flows stay focused on their actual work.

### Does this follow modern best practices?

Yes as a proportionate design direction: official CRM/DAM guidance supports explicit reuse and optional assistance, W3C supports predictable asynchronous feedback, and native technical guidance requires bounded work. Vendor defaults, hidden cues, MD5 certainty and cleanup ceremonies conflict with Core and are explicitly rejected. No empirical superiority is asserted.

### Does this fit Asym’s existing repo and product direction?

Yes with the explicit narrow owner amendments and real native qualification. Current assets/public Media/specialist hashing are evidence to inspect, not ready-made private authorization. Packages/API and exact shared Base UI/base-maia remain binding; general search and other domains keep their meanings.

### Should we adjust the recommendation?

Accept the selected A+B with the complete required amendments. Keep the implementation small and the interaction optional; do not revert to manual-only against the founder's choice or create a generic duplicate platform. Release qualification must resolve actual authorization, races, workloads and user outcomes before activation.
