## Conclusion and strongest alternative

A is a sound product direction when a named outsider needs limited, authorized
document access. Compulsory donor, missionary or staff enrollment is the wrong
prerequisite for that need. The permanent solution is a small source-owned share
through Core's native identity, authorization, private serving and communication
owners. It is not a new guest workspace or a public storage link.

The important amendments are substantive: name the first actual source cohort;
separate mailbox proof, native identity and disclosure permission; stop automatic
donor/tenant creation; make the exact reading scope and end explicit; and prove
current authorization through every retrieval route. Optional signup must not
mean optional authorization. A future staff setting cannot make restricted
material ordinary or downgrade the owning source's assurance.

**B remains the strongest alternative:** serve only people with an existing
qualified Asym context and source rights. It is a credible long-term fit for
recurring readers and avoids another admission/recovery path. It excludes an
otherwise eligible occasional outsider. We prefer A because it meets that
bounded need without unrelated onboarding, while acknowledging real engineering,
support and resource cost. No observed Asym demand, conversion lift, time saving
or cost neutrality is claimed. Copying an attachment into email, a transferable
anyone-link, forcing a donor profile or inventing an ownerless File Manager
permission are not compatible simpler substitutes.

## Ratified corrected decision

> Allow a named recipient to obtain source-authorized private document reading access without compulsory enrollment as a donor, missionary, staff member or organization member. The first concrete Q41 cohort is exact currently eligible evidence durably received from the participant or supplied by staff under Q28 and held by the ordinary Private Document Request source. That source owns a distinct outbound disclosure/read admission for its continuing lawful purpose; P29 supplies custody and the shared file experience. An issued unfinished or fulfilled request may qualify; fulfillment alone neither grants nor ends outbound access. Actual cancellation or an applicable adverse source restriction blocks new shares and affected future reads. Retention, acceptance, staff file access and a source reference alone do not establish disclosure authority. No new ordinary share admits historical/superseded material by inference or widens an existing specialist source lane.
>
> Each new Private Document Share binds one exact tenant/environment, source/request/use, immutable selected evidence version, intended recipient/address revision, stated source purpose, explicitly permitted reading actions and a finite end. The staff actor must have the current source/P12 authority to administer that exact disclosure within its assignable ceiling; being able to read is not equivalent. That single source command may designate the named recipient under its qualified rules; no pre-created Party, guest directory entry or routine second approval is required. Q28 material carries all applicable restrictions of its supplied use, including any required origin permission for onward disclosure. Equal bytes and other independent uses neither confer nor automatically merge rights. The new Q41 lane pins the selected version and does not follow later uploads; independently qualified other-source current-version rules remain unchanged. A later correction or supersession never retargets the share and ends affected reads wherever the source ends eligibility. Declare P12 owner-transfer and grantor dependencies explicitly, including restricted-grantor departure; current qualified source administrators can manage the share without depending on its original issuer's continued availability.
>
> Provide a qualified reading rendition for the actual permitted material. Original download is a separate explicit source-permitted action, never a preview-failure fallback. Do not issue a purportedly usable share with no qualified reading path: prepare/recover the rendition through the existing bounded owner process before issuance, or truthfully leave the share unissued. This is a source/custody readiness check, not mandatory grantor body inspection or a guarantee of continuous transport availability. Staff see the actual recipient, material/version, permitted actions and end in the existing source-context Share review. An owner-qualified finite default may populate the end; otherwise staff choose it there within the exact source's finite maximum and earlier limits. ## Ratified glossary definition

**Private Document Share**:
A source-authorized, finite permission for a named recipient to read specified
private document material for a stated purpose through explicitly permitted
actions. It is distinct from an invitation, recipient confirmation, a collection
request, retention and permission to alter or reshare the material.
_Avoid_: anyone link, file ownership, folder membership, request-only access, proof of reading

This is a domain concept, not a proposed table or a broad guest role. Existing
Request-only Access remains collection-specific. Conrad ratified the exact
definition with the full amendment package. Private Document Share is now the
26th glossary term; the prior 25 definitions are byte-preserved.

## User journeys and UI contract

The coherent staff journey is **source context → review share → issue with
truthful invitation outcome → manage access**. Known authoritative context is
supplied, not re-entered into a governance form. A source-authorized grant
administrator need not download/read the body as a prerequisite if permitted
scope facts suffice for lawful administration. Copy link is a reference to the
existing protected entry, never a public-access toggle.

The recipient journey is **safe entry → required confirmation when needed →
the specific document**, with a readable scope/end and supported recovery.
Selecting a recipient or changing a staff Share-review field must not issue a
share, send email or navigate. Only the deliberate final staff action does so.
There is no new dashboard or browsing entitlement. Show **Email confirmed**
when that is the actual proof, not **Identity verified**. After reading, a
shared-device user can end the session. No required read-acknowledgment button,
marketing opt-in, account completion task or animated onboarding is added.
