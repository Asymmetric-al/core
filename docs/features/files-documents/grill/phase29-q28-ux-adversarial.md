# Phase 29 Q28 — Independent UX and comparative adversarial review

**Reviewed:** 2026-10-22, Asia/Bangkok. **Disposition: Accept with required amendments.** Conrad selected A, allowing authorized staff to add existing evidence. Q01–Q27 are ratified; the complete Q28 amendment package is not yet ratified. This is an independent research and design review, not product qualification.

A is useful when the source genuinely allows staff assistance and no fresh participant act is required. The appropriate ordinary flow is **Add existing file → choose the exact eligible version → Add to this item → normal review**. A mistaken unaccepted staff addition needs a real **Remove from this item** action. A participant should understand the permitted status and any actual remaining action without being credited with an act they did not perform.

## Strongest alternative and necessity

**B is strongest where current endorsement matters:** staff prepare the exact eligible candidate, then the participant affirms its use before review. This gives the participant an opportunity to catch stale or inappropriate material. It also depends on their availability and on a sufficiently informative, authorized and accessible presentation. A blind confirmation is not meaningful endorsement, and a click cannot authorize a prohibited disclosure or substitute for an actual required signature.

A avoids making that response a universal prerequisite for ordinary assistance. Its advantage is the removed response dependency, not a demonstrated universal speed or safety benefit. Source-required declarations, currentness, consent, signatures and specialist rules still apply. A must not silently grow into authority for staff to change a participant's statements.

The useful implementation remains narrow. Existing role/source controls determine who can add. The contextual picker discloses only eligible authorized information. One deliberate add records the actual staff act. Normal item acceptance remains separate. Removal repairs a pending mistake without deleting shared bytes. No universal consent wizard, general drive, global policy matrix, second reviewer, new account, mandatory essay, compulsory preview click or notification framework is justified by this decision.

## Practical journey checks

Examples are illustrative tests, not claims about observed ministry practice.

| Journey                                                         | What a usable, truthful experience requires                                                                                                                                                                              |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tenant administrator enables an ordinary role                   | Existing source/P12 settings explain the admitted action and preserve separate review powers. No new general reuse matrix or all-admin fallback.                                                                         |
| Elena adds Nora's existing certificate                          | Stay within Nora's target item; expose sufficient permitted person/version/date context, add once and show staff origin plus current review state. No byte download/re-upload round trip.                                |
| The request already contains supporting evidence                | Preserve participant and other staff members. A single-candidate requirement produces a safe conflict; it never silently replaces the evidence set.                                                                      |
| The same current membership is selected again                   | Recover the existing permitted result with original attribution. Equivalence follows the source's role/version/purpose/lineage identity, not a digest-only guess.                                                        |
| Elena or another authorized human reviews                       | One deliberate Q21 acceptance of the actual current basis; no automatic approval and no universal second person. A team route does not confer private content access on every member.                                    |
| Nora views progress                                             | Where authorized, state that staff added evidence and whether Nora has actual remaining work. Avoid false “Submitted by you,” “Approved file” or duplicate-upload demands.                                               |
| Nora cannot see the private origin or file                      | Show safe target status and a usable help route. Withhold protected bytes/notes/origin relationships; do not widen access merely to make a confirmation button work.                                                     |
| A fresh declaration or current document is needed               | Keep that substantive requirement visible. Reused supporting material cannot fabricate an up-to-date statement, consent or signature.                                                                                    |
| The reviewer finds a staff-selection mistake                    | Route the actual correction to authorized staff removal/replacement. Ask Nora only for genuinely source-authorized new work, never an unavailable own-submission edit.                                                   |
| Elena notices the mistake before acceptance                     | Cancel before add; after add, use Remove from this item. Explain remaining item work without implying deletion of the original or other uses.                                                                            |
| An accepted or closed mistake is discovered                     | Show the real state and qualified source remediation. Do not promise generic undo, reopen or an invisible swap; a support label must have an owner able to act.                                                          |
| A replacement fails during admission or afterward               | Before commitment, preserve the predecessor if admission fails. After a qualified Checking commitment, show the actual committed successor and later technical failure, without pretending the predecessor was restored. |
| A scan or preview is unavailable                                | Distinguish technical failure from business rejection. Use only a sufficient authorized inspection alternative; do not invent Request changes or force an upload to repair a viewer.                                     |
| Nora's participant access has expired                           | Authorized staff work may continue where the source allows. Do not renew Nora's access, fabricate completed-view eligibility or reset an access clock.                                                                   |
| Two people act, or the network response is lost                 | Preserve valid concurrent members, fence stale decisions and recover the original operation. Do not claim success without proof or treat a lost response as permission for another admission.                            |
| The user switches tenant, item or purpose                       | Discard delayed private results from the previous context and clear material whose disclosure ended. Retain only still-permitted working context.                                                                        |
| A reviewer uses keyboard, AT, a small screen or slow connection | The selection, real document content, status, conflict and recovery path remain understandable and operable. Long international names and localized dates cannot conceal identity/version distinctions.                  |
| The original staff member leaves or cleanup runs                | The independent lawful target use is not erased merely by the old actor's role loss. Actual continuing restrictions still apply, and target references protect required bytes from disposal.                             |

These journeys are covered by the root package's seventeen grouped journeys and P01–P24. Several examples above split a grouped journey for clarity; they do not add scope or claim tests were executed.

## Final root-draft material check

The root draft addresses both essential initial UX findings: a qualified pending **Remove from this item** action, and a truthful participant projection that does not borrow own-submission rights. Its strongest-B account is fair and its primary-source claims remain appropriately limited.

One final clarification was raised: negative feedback on staff-supplied evidence must not send a participant to correction controls they cannot use. The final C06 explicitly names the authorized next actor/action, and P15 tests that failure. **This finding is closed.**

The later runtime amendments were also checked for user-visible consistency: C03 defines current contribution equivalence beyond byte equality; C08 preserves trusted actual source time after waits; C07/P12 distinguish failed replacement admission from later check failure after commitment. The corrected decision now preserves committed replacement lineage without automatic prior-version revival. These changes improve recovery truth without adding interface ceremony.

**No further material UX or comparative-evidence defect remains in the consolidated draft reviewed here.** This means the amendment package is coherent enough to present for ratification; it does not mean that the user has ratified it or the native feature is qualified. Real source authorization, browser/AT inspection, intended-user journeys, low-bandwidth and recovery proofs remain release obligations.

Only this independent note was written. No canonical document, product code, schema, permission, provider/account state, message, private file content or UI was changed. No new prototype, authenticated comparator test, runtime test or usability study was performed.
