## Conclusion

**Keep A, but make it a useful source-owned result rather than an unexplained negative badge or a permanent block.** A recipient should be able to identify the exact item/member needing attention, understand a permitted next step and use the existing correction path while eligible. The review must also support a qualified resolution when staff were mistaken or the existing evidence proves sufficient, without forcing invented replacement bytes. Preserve the earlier record; do not silently delete feedback or pretend it was never issued.

This is a small behavior in the existing staff review and participant request view. It needs one deliberate Request changes action and actionable current guidance, not a new case-management system, per-issue workflow builder, mandatory essay, universal checklist, additional reviewer or new chat product. Useful guidance is an outcome requirement: it may use concise safe text or already-sufficient source instructions. A character count, empty “Rejected” banner or checkbox saying “I explained it” is not proof of usefulness.

The source must distinguish receipt, a review request for changes, a newly received correction, current unresolved work, technical readiness, acceptance and whole-request fulfillment. A correction alone does not prove all requested changes are addressed. Conversely, a historical request for changes cannot remain an unexplained permanent barrier after the source lawfully resolves it. These distinctions preserve Q03/Q21/Q22 rather than creating another decision engine.
