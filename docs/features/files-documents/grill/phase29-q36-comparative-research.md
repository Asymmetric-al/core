## One meaningful decision

**When staff discover another ordinary document is needed for the same continuing
purpose and recipient, may they add a requested item to the existing issued,
unfinished request, or should the additional work use a separately qualified
new request?**

Recommend **A — Allow a bounded addition to the same eligible unfinished
request**. Keeping closely related collection in one place can let the participant
see the additional work alongside preserved progress, and let staff review the
whole continuing demand without creating another request simply because an item
was omitted. This is a reasoned product judgment, not an observed Asym workflow
or measured reduction in work.

| Option                                                                             | Everyday experience                                                                                                                                                                                                                                                              | Strong benefit                                                                                                                                                                                                                               | Real cost or risk                                                                                                                                                                                                                                |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **A — Add a requested item to the same eligible unfinished request (recommended)** | Source-authorized staff deliberately add a new ordinary item for the same continuing purpose and recipient. The current permitted view identifies the added work; existing files, review decisions and history remain intact.                                                    | Keeps related work together and avoids another request for a modest omission discovered during collection.                                                                                                                                   | The participant's task grows after issue; completion/progress may change. Requires exact authority, source/access-scope adoption, clear addition history and ordering against fulfillment/cancellation. Existing access must not silently widen. |
| **B — Use a separate qualified request for additional items**                      | No same-request addition is introduced. Where ordinary original-issuance authority is independently qualified, staff prepare/review/issue a separate request for the added need, preserving the old request. Other capable existing source resolution retains its own authority. | Keeps additional requirements out of the original request so it can fulfill independently, and gives new work a distinct review/access/collection boundary; useful for materially different purposes, sensitive additions or concluded work. | Can fragment one continuing collection and require the participant/staff to distinguish and track two requests. A new request is not free of authority/access work, and there is no assumed generic reissue button.                              |

These are two practical alternatives. No artificial third option, three-mode
tenant system, general request editor, revision engine or notification default
belongs in this question. A does not remove the independently authorized option
of a new request when it is the clearer or only lawful route.

Illustrative scenario, not an observed ministry workflow: Elena has issued Nora
an ordinary request for two documents. One is accepted and the other awaits
review. Elena discovers a third document is genuinely necessary for the same
continuing purpose. Under A she adds that item, and Nora can see what was added
without losing credit or history for the first two. Under B Elena uses the
separately authorized ordinary issuance path for the third document. Neither
option makes the third document implicitly accepted or grants an extra access
period merely because the additional demand exists.

B does not freeze every aspect of an issued request: ratified Q33 removal and
source correction, Q34 cancellation and all other existing boundaries remain.
It simply does not add the new same-request addition capability.

## What the one decision includes, and what it must not silently change

The proposed action is **Add requested item**, for a new ordinary requirement
on an eligible issued unfinished request with the same continuing purpose and
recipient. It is not draft authoring, correction of an existing item's wording,
replacement of evidence, Changes requested feedback, reactivation of No longer
required, a generic specialist waiver, whole-request cancellation or reopening.
Choosing A would newly authorize this bounded source capability; a UI label or
the existence of a reviewer role cannot confer it by itself.

The source must establish the exact new item's lawful need, recipient scope,
participant-visible description and competent handling/review route. Review
responsibility and permission to inspect an uploaded file do not automatically
permit imposing a new demand. Existing Q24/Q25 source/work boundaries still
govern; do not create a review task or staff notice merely because an empty
requested item exists if the owning actionable-work rule has not occurred.

**Access scope requires explicit prospective adoption.** The parallel owner audit
identifies Q13/Q15's restrictions against adding requirements through a fresh-access
operation. A cannot bypass those restrictions by editing rows and trusting the
old invitation. The adopted source/access contract would need to authorize this
new item and its same-recipient current view while preserving exact identity,
privacy, proof, expiry and other caps. It cannot automatically widen an old grant,
renew its end, change the recipient or turn a private title into a public cue.
Existing current proof may be reused where the actual owners permit; do not force
another challenge solely because the source change was legitimate. The active
period may be a valid original or already-qualified fresh period; its end/caps
remain unchanged. Expired or revoked access does not silently become valid.
A separate qualified fresh admission would have to explicitly include the newly
approved lineage under Q36's prospective reconciliation of Q13/Q15; without that
authority, do not enlarge it by implication. Ordinary new issuance remains a
separate independently qualified route.

**Progress and historical truth are preserved.** Existing received files,
acceptance/Changes requested decisions, optional reusable evidence and item
history stay attached to their exact original meanings. Do not reset all items,
copy an earlier acceptance onto the new item or silently repurpose an old item.
If the count grows, show the new outstanding item so a smaller completion fraction
does not look like lost work. The new item begins according to its genuine
qualified source state; any Q28 reusable evidence still needs its exact permitted
use and review rather than an automatic acceptance.

**Terminal order remains real.** An addition is meaningful while the actual
source remains unfinished. It must be ordered with Q22 fulfillment and Q34
cancellation, not merely a stale task badge or client screen. Addition first
changes the relevant requirements for any later completion evaluation; actual
fulfillment/cancellation first prevents this ordinary addition. A final review
click or deferred completion worker is not, by itself, proof that source
fulfillment already occurred. An uncommitted addition draft or staff intention
cannot hold fulfillment open. A's committed unsatisfied item changes this same
aggregate's completion requirement; B lets the original fulfill independently.
No completed or canceled request is reopened by A.

**Awareness is necessary, but this question adds no email purpose.** The current
authorized request view must make newly added work understandable. A concise
addition cue and retained source history can do that without a new read/unread
system or arbitrary New-label timer. A participant who is away may not see the
addition promptly; this is a real limitation, not evidence of daily portal use.
Use only a genuinely approved existing source outreach route if needed. Do not
manufacture a Q30 reply, Q26 rejection, Q20 access event or another ratified
notice as a transport for a new requirement. Q36 does not select a new notification
default, reminder sequence, bulk send or communication composer.

## Simple staff and participant experience

On the existing ordinary request, authorized staff choose **Add requested item**,
enter the minimum clear participant-facing requirement and any already-required
source facts, and deliberately commit the addition. The action makes clear which
request and recipient it affects. Preserve a simple reviewable action; do not
require an essay, new approver, request-wide editing mode or multi-stage revision
workflow for a single bounded addition.

The current permitted participant view keeps existing work in context and makes
the addition visible, for example through **Added [date]** plus the new item and
its actual status. That wording is illustrative; a durable source history entry
is preferable to inventing read tracking. A truthful short explanation can say
that an additional document is needed without suggesting earlier uploads failed.
Any newly created participant-facing text obeys the same privacy and access
boundaries as the source request. Do not prefill sensitive internal rationale.

A staff member who notices a mistake after adding must use the applicable
ratified Q33/source correction path while eligible; there is no new universal
Undo or hard deletion of history. If actual fulfillment or cancellation wins,
show that state and the real qualified source resolution, including ordinary
new issuance only where independently authorized. A disabled button or help
label alone is not a capable replacement workflow.

Use existing base-maia/Base UI interaction patterns. The new item, updated count,
errors and result must be clear to keyboard, screen-reader, mobile/zoom and
low-bandwidth users. Do not let an unrelated participant upload disappear when
a concurrent addition refreshes the page, automatically submit on field change,
or require the participant to repeat already valid work. The engineering protocol
for safe concurrency remains an implementation qualification question, not a
new product mode to ask here.

## Why the recommendation remains bounded A

The useful case is a modest ordinary addition while one continuing collection is
still open. Requiring a separate request for every such discovery can divide a
single task unnecessarily. Keeping the source's existing work together is a
practical reason to support A, provided staff can legitimately impose and expose
the new requirement and the participant can tell what changed.

B is strongest when the original promise of a stable item set matters, when
staff frequently add work near completion, when additions require different
purpose/recipient/access authority, or when new work ought to have a separate
collection boundary. TaxDome's client-request restriction is evidence that
limiting post-start edits is a real product choice, not an obviously bad design.
Submittable's connected Additional Form makes B a coherent workflow, not merely
a refusal to support more documents. Core cannot assume either workflow is
available simply because a vendor provides it.

No current Asym data establishes how often omissions occur, how often new items
change scope, how participants interpret growing progress totals, whether existing
outreach reaches them, or how much separate requests cost. These uncertainties
should be explicit. If A is chosen, its adversarial review should test those
journeys and the exact source/access/terminal ordering before activation rather
than claim a universal best-practice improvement from comparative documentation.
