## 1. Recommendation and evidence boundaries

Keep the selected A: allow one exact suitable organization-resource publication to serve independently qualified staff and missionary readers, with separate publications whenever their substantive wording, authored language, rights, review meaning or release/withdrawal needs differ. Add an explicit staff-reader purpose to the existing P28 resource owner and adopt the compatible Q55 and Q57 staff journeys under their own action rights. Do not make staff become curators, obtain Support-read rights or impersonate missionaries merely to read a P28 resource.

The smallest complete curator experience is an **Audiences** section in ordinary publication preparation and an explicit **Change audiences** action for an existing publication. Show the current permitted audience, the proposed result and the shared effect. A deliberate **Publish** or **Save audience changes** admits the exact reviewed source change. Editing a checkbox does not publish. Removing the final audience is not an implicit withdrawal or a Published-with-no-audience state: preserve the local selection and offer the ordinary **Withdraw publication** act with its actual whole-publication consequence. There is no need for a second routine moderator, consent checkbox, reason essay or confirmation modal.

For divergence, use existing ordinary source preparation of a separate publication, with permitted exact-file/reference reuse and independently reviewed metadata, audience and publication. Do not add a generic Clone/Sync/Split engine, automatic report transfer, copied approval or atomic cross-publication promise. Preparing a separate edition changes no live availability. Publish it when qualified; deliberately narrow the common publication where appropriate. If the old audience disclosure is unsafe now, the actual restriction/withdrawal remedy must be usable independently of replacement readiness.

**Strong alternative B remains real.** Mandatory separate audience publications give independent editorial control from the outset and reduce the chance that a curator forgets a shared change's reach. They can use the same lawful custody without re-upload. A is preferred because it allows that same separation when needed while avoiding mandatory duplicate publication decisions for genuinely common guidance. This is reasoned product judgment. There is no measured Asym/ministry content overlap, update frequency, staff demand, error rate, time saving or cost saving in this research.

## 3. Complete small experience and proposed copy

**Illustration only:** Elena curates an equipment-handling guide. Nora is an authorized staff reader; Maya is an authorized missionary reader. The same approved instructions fit both. Later, Nora's team needs an internal procedure that Maya should not receive. This illustrates the fork; it is not a recorded ministry workflow.

### Staff and missionary reading

Use **Resources** in each actual existing shell, showing the current organization/context and only admitted publications. Staff reading is a real new source purpose, not a route to curator preview. Reading rights, Open, Download, review-information disclosure, Report a problem and own-report return each use their actual compatible grants. A person can legitimately have multiple contexts without their powers being unioned. A shared publication appears once in one current authorized result, not once for every matching audience membership.

Keep text-first title/description, actual language, format and known size; **Open**, **Download** and honest external destination behavior retain their existing source meaning. No forced preview, whole-file prefetch, new tool account or mandatory acknowledgment. Return preserves lawful search/filter/position while rechecking access. **No resources available**, **No matching resources**, **We couldn't load resources. Retry**, and **This resource is unavailable** describe different states; failed authorization evaluation is not a successful complete zero. Do not reveal hidden editions, audience membership, restricted places or private draft titles through explanation text.

Q55 remains visibly truthful: actual **Last reviewed**, **Review due**, **Review planned [date]**, **No review scheduled**, or qualified unknown states follow the adopted semantics. Adding staff to an unchanged publication does not mark it reviewed, reset its target or promise that it is factually accurate. Q55 actual review binds the audience, purpose and exact content basis: retain earlier review evidence, but reevaluate whether it applies to the current publication basis after adding or removing an audience. Do not display an earlier review as covering a newly widened or otherwise changed basis. When no current-applicable review is proved, distinguish known absence from unavailable information; any historical review display must be clearly scoped and currently authorized. A current review act is deliberate, never fabricated by Save/Publish. The existing review plan may remain unchanged where qualified; audience change alone creates neither a review nor a new Review due event. **Report a problem** and **Your reports** reuse Q57 only after explicit staff-cohort adoption. A report is private source work, not a comment on a public article.

Preserve Support **Staff guides** under D27-C for actual Support-read consultation without a ticket. Q58 does not remove that source, copy its internal text, turn its users into P28 curators, force Support access for P28 reading or extend body search across sources. Consistent navigation can make the two useful entries understandable while each source authorizes its own journey.

### Curator preparation, addition and removal

Use the existing resource preparation surface with an **Audiences** fieldset. Show only discoverable, source-qualified scope choices; labels such as **Staff readers** and **Missionary readers** must state any material allowed organization/scope restriction and must not imply every staff member or missionary. Do not create a new group directory, arbitrary individual picker, region-based grant or universal Both permission. Existing explicit audience intent is preserved; new staff readership is never silently added to an old publication or by rollout.

For a shared selection, a concise adjacent consequence can say: **This publication has one version and review plan for these audiences.** For an audience change, show the actual current and proposed set, for example **Add: Staff readers** or **Remove: Missionary readers**, only where those facts are authorized. A stable **Save audience changes** action submits the reviewed effect. No mandatory second dialog, reason essay, per-audience checkbox acknowledgment or forced document-opening ceremony. Actual source safety/rights approvals remain required where applicable.

For an unpublished draft, no audience may remain as ordinary incomplete preparation; it cannot publish until the intended admitted audience is nonempty and qualified. For a published resource, if the local proposed set is empty, say **Choose an audience, or withdraw this publication to stop offering it.** Keep existing publication state unchanged until a deliberate authorized action. Offer **Withdraw publication**, with **Stops new resource access for every audience of this publication. Files already received cannot be recalled.** The visible final act must actually be withdrawal; do not silently reinterpret Save as withdrawal. If the actor lacks the needed right, provide the actual scoped capable source route without inventing it or revealing hidden scope.

Removing one audience while another remains is an explicit current source narrowing, not global withdrawal, byte deletion or a change to another publication. Adding/re-adding an audience is a fresh current admission, not restoration of old grants. A full-set edit cannot drop an undisclosed current audience or convert unknown state to empty. If the source provides a narrower authorized restriction command, it can be used under its own scope without falsely requiring power over every unaffected audience. This must not become a guessed client-side patch to permissions.

### Shared content changes and divergence

A replacement/review-date/actual-review/whole-withdraw action clearly shows its shared permitted impact in the same ordinary flow. Content change remains exact immutable publication replacement under P28. A staff-only paragraph cannot be hidden from missionaries inside the same shared body. Different authored languages or independent review/release needs use separately qualified publications. An existing qualified accessible rendition is not automatically a different editorial edition.

A separate publication uses current ordinary preparation and permitted exact-file/reference reuse. Safe reusable metadata may be carried only under current field/source rights and explicit reviewed intent; do not transfer reports, review approvals, audience grants, private notes or successor history. Preparation is inert. When the separate edition is ready, deliberately publish it and deliberately narrow the original where intended. These are actual independently ordered source actions; this proposal promises neither an atomic Split command nor a gapless cutover. Where both temporarily remain lawful, show their distinct source identity/currentness without confusing them as one updated edition. Where the old disclosure is unsafe, stop it first using actual restriction/withdrawal, then complete safe replacement without reopening old access. A missing capable divergence/remediation route blocks the affected cohort's activation; **Contact support** alone is not such a route.

## Adversarial check

### What could go wrong with this answer?

A curator can mistake a shared audience control for display-only targeting, expose staff-only content, or believe a shared replacement/withdrawal affects one surface. A private report or stale title can leak even if the file itself is blocked. Require exact current admission, a legible shared consequence, independent report-purpose disclosure and stage-correct restriction/recovery. Unchecking the last audience must not silently withdraw.

### What hidden assumptions are we making?

Some guidance may genuinely fit both cohorts, and authorized stewards may be able to approve its shared lifecycle. Neither frequency nor measured benefit is known. We do not assume all staff have P28 reader rights, that curator preview is reader access, that Support guides are ownerless, or that a previously accepted review certifies different wording/audiences. Actual source/path/user proof remains missing.

### How does this affect the whole product?

It completes the narrow P28 staff-reader extension and gives one publication a deliberately shared readership where appropriate. P12 current identity/action/field policy and P29 custody remain distinct. Support D27-C, specialized artifacts, private evidence and public CMS keep their owners. Q55/Q57 staff cohort adoption is explicit; no notification, LMS, office editor, public sharing, group engine or cloned knowledge platform is added.

### How does this affect the end-user experience?

Readers get a clear Resources path, current guidance and safe return without management powers. Curators can maintain one shared edition and see the impact of changes. When needs diverge, they can prepare and publish a separate edition through real existing source work, with honest handoff rather than a magical split. Persistent correction and original-result recovery make mistakes survivable without routine extra confirmation or forced preview.

### Does this follow modern best practices?

Current official knowledge/CRM/nonprofit-resource documentation supports explicit audiences and separate reader/manager powers. It also exposes dangerous defaults, inherited access and targeting-only behavior that Core must reject. Document360's independent unpublished clone illustrates separate editorial truth, but does not require a clone engine. W3C guidance supports predictable input, understandable status and reflow. None proves a universal best option or actual Core accessibility.

### Does this fit Asym's existing repo and product direction?

Yes as an explicit P28 purpose/command/cohort adoption under existing owners, shared native identity, static field projection and Base UI/base-maia. Current shell/demo components are not implementation proof. Parent/runtime must reconcile the new f8ef44f head and actual native grants/paths; this note does not claim that audit. Preserve D27-C's already-owned Staff guides rather than force one source to replace another.

### Should we adjust the recommendation?

Keep selected A with the eighteen amendments: one suitable publication, explicit current audience change, final-audience withdrawal as a named act, real independent editions when meaning/lifecycle differs, compatible staff Q55/Q57 adoption and complete recovery. The strongest B remains appropriate when independent editions are preferred; A already permits that without making it mandatory. Do not add a sync engine or extra approval ritual.
