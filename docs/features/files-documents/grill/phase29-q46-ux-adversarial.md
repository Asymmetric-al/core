# Phase 29 Q46 A — Independent UX adversarial review

2026-10-25, Asia/Bangkok. Conrad selected **A: deliberate authorized changes to the Requested by target for outstanding recipient work in an eligible unfinished ordinary Private Document Request**. Q01–Q45 and 27 glossary definitions remain ratified. Q46's full amendment package is pending review and ratification. This note is independent research and acceptance judgment, not canonical publication, implementation, a native test or authority to create Q47. Only this assigned note is authored.

## Disposition and smallest complete experience

**Accept with required amendments.** One contextual **Change Requested by** action, a clear existing/proposed target and **Save changes / Cancel** are enough for the routine flow. Keep **Requested by** visibly distinct from actual **Access ends**, and distinguish recipient work from staff checking/review. Do not make a calendar selection itself a source mutation. A save must preserve the history of the earlier target and the timing that actually applied to received evidence.

The strongest alternative B remains credible: a fixed issued target gives one stable planned baseline and fewer edit states. It avoids the temptation to hide delay by continually moving a date. Its cost is that an authorized later plan may live in communication while the request still displays the original target. A improves current-plan clarity; immutable receipt applicability and attributed target history protect historical truth. No measured Asym frequency, support savings, completion gain or universally superior nonprofit default is claimed.

Illustration only: Jordan requested Elena's remaining inventory documents by 10 November. They now plan for 17 November. A lets Jordan save that current target without cloning the request or asking Elena to upload again. If her access ends on 15 November, the interface still shows that limit: the requested plan can be recorded where lawful, but this action supplies no access on 16–17 November. A separate current source admission is necessary if later participant action needs it. The planning edit must not be universally rejected or forced into a new access grant merely because of that mismatch.

## Fourteen exact proposed UX/source amendments

Severity below is prospective impact if the boundary is missed. Likelihood is qualitative exposure in an ordinary workflow, not an observed incident rate. H = high, M = medium, L = low. No Critical claim or deployed vulnerability is inferred from a research gap.

### U01 — One current ordinary-source action (H / plausible)

Add deliberate target revision only for the actual source's current target scope, with outstanding recipient submission/correction work in an eligible unfinished ordinary request. Current source/P12 authority governs the actor and exact Tenant/environment/assignment/purpose. A task date, staff role, author/reviewer label or shared view is not alternate write authority. This command changes neither recipient, purpose, instructions, requiredness, evidence acceptance, staff review responsibility nor any specialist binding deadline. A queued fulfillment evaluation is not actual fulfillment; order against the real source transition.

### U02 — Current plan and received history are different (H / plausible)

Record an attributed prospective target change and retain its preceding applicable terms and trusted occurrence. Earlier durable receipts keep their actual admission time and captured target basis or explicitly unresolved timing. A later target must not make an earlier late receipt on time; an earlier target must not make an earlier timely receipt late. Current outstanding work may legitimately cease being overdue or become currently overdue after a qualified rescheduling. That current projection is not a rewrite of historical receipt facts. Do not require a new midnight event ledger or full-history scan merely to display the current target.

### U03 — Preserve the source's declared temporal form (H / plausible)

Use the declared target kind already qualified for this source. A date-only target is a valid civil date in the captured source IANA time zone; compare the trusted receipt's local civil date in that zone, with a receipt on the same day not late. An already-qualified precise instant retains Q09's strict-later rule, supported precision and exact comparison. Do not silently convert date-only to UTC/browser midnight, add an end-of-day timestamp, drop precision or change kind/zone when saving. Current organization or browser-zone changes do not reinterpret an admitted target or old receipt. This is no user-facing zone/kind editor or new calendar engine. Reject impossible/ambiguous unsupported input with usable feedback rather than normalizing it into another date.

### U04 — Earlier, later, past and optional states remain honest (M–H / plausible)

Support source-permitted earlier/later values without a universal future-only validator. A past value may make current outstanding work immediately past its requested target; show that consequence without inventing historical lateness or a hard cutoff. Set/Clear transitions are available only where the actual source proves the target optional and authorizes that transition. Unknown/missing interpretation is not an optional empty value; a required target cannot be cleared. If current source identity, expected basis, authority and declared temporal interpretation are known, a qualified new prospective value may replace an explicitly unresolved old target while retaining that unresolved history. Unknown old history is not a blanket ban on fixing today's plan; unknown command authority, ordering or target interpretation still blocks the affected change. No new mandatory-date, target hierarchy, per-item inheritance, clearing policy or default date follows. A genuinely different target scope is not silently created by editing this field.

### U05 — Requested by is not Access ends (H / plausible)

Show the actual requested target and current access availability/end separately. A target after the current access end is a mismatch to explain, not a universal target-only rejection, forced new grant or hidden extension. An authorized planning edit may proceed while recipient access is expired if the source otherwise permits it; later participant action still needs independently current authority. Do not renew proof, restart original/fresh periods, clear revocation, reopen completion/cancellation or pretend a date edit makes documents available. The absent/unknown-access state must not be rendered as unlimited access or fabricated expiry. Preserve partial currently lawful actions and capable actual source help.

### U06 — Show whose work remains (H / plausible)

Derive outstanding recipient work from the actual source requirement and receipt/review state. All-received material awaiting scan or staff review is not recipient-overdue merely because fulfillment has not occurred. Do not expose this ordinary target editor as a staff-review deadline editor or encourage moving dates to hide a backlog. Q03 corrections and Q36/Q37 added/revised work retain their own applicable terms; no unrelated prior target or automatic fresh interval is inherited. Preserve exact current evidence, acceptance and requiredness; source restriction remains independent of the displayed requested date.

### U07 — A compact deliberate editor (M / likely without explicit design)

In the existing request context, show **Requested by**, the currently applicable value, the proposed value and enough authorized work context to understand what changes. Keep **Access ends** separately visible when relevant. Use **Save changes** and **Cancel**. A calendar selection, text change, blur, month navigation, closing a popup, reopening the page or context refresh does not commit/send/navigate. No routine reason essay, extra approver, recipient acknowledgment or repeated confirmation is required. Explain known material consequences inline, including an earlier/past date or access mismatch, without a second wizard. Preserve lawful input on validation failure and keep unrelated work intact.

### U08 — Accessible date entry and presentation (M–H / likely for affected users)

Provide useful labeled direct entry plus an optional shared calendar where appropriate; do not make a pointer-only or JavaScript-only calendar the sole route. Show an unambiguous display such as **17 November 2026**, with relevant source zone for its actual meaning; local display cannot change the stored meaning. Support qualified localized month-name/numeric entry without ambiguous month/day guessing. Preserve keyboard navigation, readable day/month/year labels, selected-date and error feedback, focus return, 320-CSS-pixel reflow, zoom and touch targets. Handle RTL, Unicode, long names, leap days and IME without accidental submit. Announce material status without reading every month navigation twice or taking focus away from the field. Reuse Core Base UI/base-maia, not an imported design system.

### U09 — Coherent save, no-op and concurrent recovery (H / plausible)

One authoritative source command validates current actor, exact target scope, expected relevant basis and proposed typed value, then coherently records admitted target/history/outcome and required owned follow-through. No mutation on keystrokes or calendar navigation. Reconcile a lost original response under current disclosure before applying new intent. Identical operation retry returns the original result; changed intent conflicts. An unchanged value on a matching current basis returns honest unchanged without a fake business revision, timestamp or communication. A stale expected basis still conflicts even when the displayed value equals the current one after intervening changes. Preserve lawful proposed input alongside the newly current value for deliberate recovery, not silent last-write-wins or merge.

### U10 — Submission/edit ordering preserves work (H / plausible)

Keep Q09 first-admission semantics: a compatible target-only change can resolve at actual first source admission without forcing reupload, a new intent or needless identity confirmation. Once admitted, replay preserves the original receipt/time/terms or unresolved timing. Transfer start is not durable receipt. Order target change against receipt/correction, actual fulfillment/cancellation, source requiredness/acceptance and relevant revocation under the owning source; recheck actual time after waits. No global lock spanning human editing/upload or blanket invalidation of every request view is justified. Material non-target changes retain their own currentness requirements.

### U11 — Repair mistakes through a new lawful edit (M–H / plausible)

Before Save, Cancel discards the local proposed value. After an admitted mistaken target change, while the source is still eligible with outstanding recipient work, repair through a new deliberate currently authorized edit with current expected basis; staff may select the previous value as a new present decision. Do not roll back history, restore an old grant, erase a receipt, backdate the repair or replay the original operation as another change. After terminal/no-recipient-work state, ordinary editing is unavailable: actual governed fact correction/source remediation remains with its owner. Do not fabricate outstanding work, clone a request or expose a fake Undo to make repair appear possible. Operators need an actual supported current source route rather than routine SQL.

### U12 — Awareness is not a hidden notification decision (H / plausible)

Current authorized request and staff views reflect the actual target; participant return must not falsely display a stale date as authoritative. Permitted concise change context can explain the current plan without exposing internal history or another actor's private facts. A display or refresh proves neither human reading nor agreement. Q46 creates no new email, cadence, reminder, escalation, acknowledgment or mandatory subscription. It also does not set all notifications Off: independently qualified existing effects retain their original purposes and current usefulness/dispatch contracts. A prepared message must not assert obsolete facts or be silently rewritten to a different event. Any need to coordinate outside the product uses an actually qualified source route; no guaranteed away-from-product awareness is claimed.

### U13 — Privacy and honest uncertainty across projections (H / plausible)

Current date, affected work, historical terms, attribution, source association, count/filter, errors, URLs and task projections remain source-protected facts. Revalidate actual current source/acting context at write/read admission and fence late results/cache/drafts after tenant/assignment/purpose changes. Do not expose a requested date to an unauthorized recipient merely to explain access failure. No raw historical/private target narrative, recipient name or credential URL enters general diagnostics/session replay. Date interpretation unknown is different from absent target; permission unknown blocks the affected action, while target-only timing uncertainty preserves independently authorized intake as Q09 permits. Retention or a cached old display is not current disclosure authority.

### U14 — Lean bounded qualification and accurate stage (M–H / plausible)

Use existing source commands, shared projections, native temporal data and immutable attribution; no new scheduler, calendar platform, event-sourced history engine, file copy/processing, provider or third-party date service is selected. Keep current reads and bounded history proportional to one source scope, with measured list/index/query/concurrency limits and no per-row full-history recomputation. Qualify native real-role/all-writer policy, temporal validation, races/replay/no-op, mixed clients/restore and intended-device journeys. Old clients must preserve or truthfully reject unsupported target semantics, not drop zones or overwrite new revision state. No new term is needed; current Document Request Due Date and access terms suffice. Current code, a date picker, vendor documentation or synthetic date arithmetic is not full native proof.
