# Phase 29 Q36 — runtime research for adding an ordinary item after issuance

2026-10-23, Asia/Bangkok. Conrad fully ratified Q35 and all amendments; root records that ratification. Q36 is a researched question, not a selected answer. Only this work note is authored. No canonical, runtime, schema, provider, credential or private-data mutation is authorized or performed.

## Recommendation and the open product choice

Recommend **A — allow appropriately authorized source staff to add an ordinary requested item to the same eligible issued, unfinished request, for its same continuing purpose and intended recipient**. The useful case is a missing ordinary supporting document discovered while the existing collection is still underway. Keep one coherent request context and preserve everything already received or accepted. This is a new prospective requirement and participant-scope amendment, not generic checklist CRUD.

**B — use a separate independently qualified new request for the additional need.** The existing request keeps its admitted requirements and history, subject to already ratified Q33/Q34 actions. B gives the new request explicit original issuance, recipient/purpose qualification, review readiness and its own legitimate finite access terms. It costs another request context and potentially another entry journey; qualified Q01 proof reuse and Q28 evidence reuse may reduce that friction, without copying grants or acceptance. B is a real product alternative, not a claim that a qualified native create-request runtime already exists.

A is preferable for continuity where the need genuinely belongs to the same still-open purpose, but it has a real cost: the source must support an exact prospective requirement/scope amendment and truthful current remaining work. Keeping items fixed and using B is simpler to reason about. No measured Asym usage establishes the optimal choice. Do not add a third artificial option or combine this with editing old instructions, changing recipient/purpose, reopening closed work, bulk template propagation or a new notice default.

## Complete participant authority under A

A must mean a usable additional requested item, not merely a staff-only draft row or a new demand the participant can never lawfully see. The simplest complete owner model is:

1. **Prospective exact scope amendment.** The source records the added ordinary requirement with stable item identity, explicit instructions/requirement basis, relevant revision and exact recipient/purpose relationship. Qualify requirement-addition authority separately from evidence review, assignment, generic edit and recipient-access administration. Source and P12 remain the single authority path.
2. **Current original or fresh period.** An independently valid period may admit the new item only through an explicitly qualified amendment to that current participant scope. Retain the same already established end and all earlier caps/current restrictions; keep original admitted facts immutable. An existing token/session does not automatically widen, and changing an array of item IDs is not sufficient proof.
3. **Already expired participant access.** Adding a requirement never revives expired rights. Participation requires a separately authorized fresh unfinished admission whose approved amended requirement lineage is explicitly reconciled with Q13/Q15. Existing duration, ordinary-expiry eligibility, no-overlap and repetition rules remain unchanged. Otherwise the source uses B. Never turn revoked purpose, wrong recipient or an independent prohibition into ordinary expiry.
4. **Proof is separate from authority.** Reuse existing Q01 mailbox proof only when its exact current contract qualifies for this amended request context. Do not assume global verified-email permission; do not force a new account, email proof or credential merely because an item was appended where qualified reuse is valid. Every protected use remains current-authority checked.
5. **Review path for the added work.** Explicitly qualify current usable review coverage for this newly declared work using the source's existing Q24 route. An unchanged qualified team can suffice without reassigning every old item. This is the proposed addition prerequisite, not a claim that Q25 already supplies an ongoing gate or permission to inspect nonexistent future files.

The question can state these boundaries without choosing a new grant table, separate permission engine, universal scope-version platform or routine second approval. The selected answer's adversarial review must make the exact owner amendment and recovery concrete before activation. Unknown required authority blocks the dependent new admission; it must not arbitrarily disable independently lawful old-item work.
