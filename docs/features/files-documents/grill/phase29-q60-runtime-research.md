## Agreed Q60 research subject — correction of mistaken acceptance

The parent/owner census has now identified a genuine product consequence, so the next researched question should compare:

- **A — Correct the mistaken acceptance within the same eligible unfinished request (recommended).** A deliberate authorized corrective source decision ends the exact erroneous acceptance's current applicability, preserves the actual earlier acceptance and attribution, and returns only affected work to the proper current review state. It must not erase history, silently change submitted evidence or reopen a request whose fulfillment already committed.
- **B — Use separately reviewed corrective work for every such mistake.** Keep the original acceptance/fulfillment history, record the qualified error/current-reliance restriction, and use an actual source-authorized corrective request/process. For an eligible unfinished ordinary request, a proposed complete route is a deliberate coherent termination/supersession of the old collection plus separately reviewed same-recipient corrective issuance for still-needed work. For actual already-fulfilled/otherwise closed work, preserve terminal history and use the separately qualified remedy. This route is an explicit proposed narrow source adoption, not existing Q49 authority or a generic Help link.

A avoids making staff and participants repeat the entire collection merely to correct one still-live staff mistake. B gives the correction a clean separate work boundary but can cost another request and require more explicit handoff/reuse work. Neither option should promise that the existing native runtime implements it, force fresh bytes where retained evidence can be lawfully used, or treat an acceptance error as proof that every other item is invalid. No measured mistake rate or workflow frequency is asserted.
