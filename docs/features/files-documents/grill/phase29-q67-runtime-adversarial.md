## Recommendation and material runtime findings

Accept the new optional human input route with exact source admission and recovery. An authorized actor records an **already-defined supported external occurrence for an exact source subject**. The source owns its accepted fact and current interpretation; a browser form, policy editor, Workflow receipt or general event ledger cannot supply that authority.

Keep two identities distinct: the caller's original business operation and the source's real occurrence. Manual/native/integration inputs can refer to one occurrence. Exact duplicates must not create another clock or falsely attribute another actor's result; contradictory dates or evidence require actual source reconciliation. A permanent subject+type or date-only key is unsafe for legitimately recurring events. No universal evidence graph, event registry or new workflow engine is needed.

Correction/retraction must target the exact accepted recording/evidence basis. Retracting a mistaken staff input cannot erase independently valid native/integration support for the same occurrence. Nor does retraction prove the event never happened or automatically restore a not-yet-triggered state. Relevant current adverse impact must be fenced before deferred recomputation; Q63's possible physical effects remain truthful. These requirements are the strongest material additions to a simple Record event form.

Current code has useful Auth, dispatch and stored-event precedents, but they are not a qualified Q67 implementation. The actual workflow ledger's duplicate-key lookup does not compare complete semantic intent; dispatch and outcome recording are separate calls. Its envelope validates shape and suspicious key names, not complete purpose/field disclosure. The general operation wrapper supplies an admin client after Auth/optional role checks, not the source PDP or a transaction. These are limitations on proposed reuse, not claims of an observed deployed Q67 vulnerability.

- [PostgreSQL CREATE POLICY](https://www.postgresql.org/docs/17/sql-createpolicy.html): USING governs old rows; resulting-row checks apply after BEFORE triggers. UPDATE/ALL can reuse USING when WITH CHECK is omitted. Permissive/restrictive composition matters. Literal omission is not by itself an exploit.
- [PostgreSQL row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html) and [functions](https://www.postgresql.org/docs/17/sql-createfunction.html): actual owner, FORCE/BYPASS and effective ACL/search_path govern. DEFINER is not universal bypass; public placement is not proof every role retains EXECUTE. Context7's generated “invoker is now default/breaking change” label is rejected; that default is not a newly established change.
- [Constraints](https://www.postgresql.org/docs/17/ddl-constraints.html) and [isolation](https://www.postgresql.org/docs/17/transaction-iso.html): null-complete keys/checks and correct cross-row transaction boundaries matter. A CHECK that calls mutable current data cannot enforce lasting current authority. Native concurrency proof cannot be replaced by an in-memory serial example or multiple SDK calls.
- [Date/time](https://www.postgresql.org/docs/17/functions-datetime.html): date-only, timestamp, source zone and calendar/elapsed units differ; implicit date-to-midnight conversion can change meaning. Transaction-start timestamps cannot represent a new fact recorded after a long wait without qualification.
- [Supabase server Auth](https://supabase.com/docs/guides/auth/server-side/advanced-guide): getClaims verifies token identity/signature/expiry, not every current session/source membership; getUser provides fresh Auth lookup where required. getSession's embedded user is not trusted authorization. User-editable metadata is not authority; even server-controlled JWT claims may be stale. No example's auth.uid ownership policy replaces Core's source/PDP architecture.
- Supabase SSR suggestions for route `dynamic` config are not adopted: Core's Cache Components/backend contract uses its qualified request-private boundary and forbids those route-segment exports. Request-bound clients and scoped current caches remain essential; a module-shared authenticated client cannot mix actors.
- [Storage schema](https://supabase.com/docs/guides/storage/schema/design) and [backups](https://supabase.com/docs/guides/platform/backups), read directly/through Context7 in the same-day Q66 pass: metadata SQL is not physical deletion, and DB backups do not restore missing objects. Correcting an occurrence cannot undo removed bytes.

## Twenty exact proposed clauses

**C01 — One optional owning-source input route.** Q67 admits deliberate recording of an already-defined supported ordinary external occurrence by a currently authorized actor, alongside existing qualified native/integration producers. The actual event/profile/source/subject/allowed evidence and consequences must qualify before exposure. No arbitrary event registry, policy-form override, file metadata authority or whole Workflow installation is required. Existing native F/receipt/acceptance/cancellation, signature, grant/financial and other specialist owners cannot be impersonated by this route.

**C02 — Trusted identity and exact powers.** Derive actor, Tenant/environment, active assignment/context and source scope from validated native identity. Recheck record/correct/retract/reaffirm/history/evidence/projection powers separately through the one P12 PDP and owning source; generic admin, policy-edit, authorship, row ownership, Drive access, service key or an old JWT claim is insufficient. No fabricated Party/profile/membership or demo Tenant. Human submitter, original producer and system processor are truthful separate attribution. NHI current owner ceiling/epoch and operator purpose/expiry remain applicable.

**C03 — Precise subject and meaning.** Record against the exact existing source subject and compatible event meaning/schema revision, with current relevant expected basis and allowed record/use obligation scope. Blank, unknown or denied scope is never all files with a label. Policy definition does not establish occurrence. A completed/ended collection or elapsed participant access does not universally forbid a later actual business fact; independent current source recording rights decide. No original issuer/body-preview requirement or broad history grant follows.

**C04 — Proportionate admitted evidence.** Use sufficient existing permitted references or concise evidence genuinely required by the source. Do not require new upload, essay, second approver or legal conclusion universally. Evidence/reference permission, source fact authority and underlying byte read are distinct. Any new persistent draft/evidence material needs actual purpose/intake authority; Q67 adds no new attachment/capture route by implication. Protected text is data, not instructions; no arbitrary external-URL fetch, secret-bearing payload or unsafe rendering follows from a reference.

**C05 — Time is a source fact.** Preserve actual occurred date/time, declared precision and source calendar/zone independently of actual server recording/admission time and actor. A truthful late record may refer to a past occurrence. Planned future, unknown, approximate and not-yet states require actual supported semantics; this completed-occurrence command cannot invent exactness or silently use today/midnight/file-modified/import time. Dates that only look different after canonicalization are compared under the exact profile. Use current server time after waits, not backdated transaction-start time; no claim of knowing a future exact commit timestamp inside a transaction.

**C06 — One occurrence, multiple possible inputs.** The owning source defines occurrence identity/cardinality and semantic uniqueness, including legitimate recurrence. Do not permanently lock all future events by subject+type, key by date alone or use upload digest/transport ID as business identity. Authenticated manual/native/integration inputs for the same real occurrence reconcile through that source. Matching accepted evidence reuses the fact safely; it does not generate another clock or reattribute the first recorder's result. Conflicting date/evidence is not automatically a second occurrence or a last-writer-wins overwrite. Only authentic, current material conflict can trigger scoped adverse handling; arbitrary/stale payloads cannot create a global denial-of-service fence.

**C07 — Minimal coherent admission.** At the actual source transaction or proved equivalent fence, admit the current occurrence/evidence interpretation, attribution/history, immutable original operation result and any immediately required current control/impact fence coherently. Necessary deferred follow-through is durably recorded in that commitment; it may reuse existing source work/outbox machinery. No new generic event/outbox platform is required, and entirely local synchronous work need not be artificially queued. A dispatch ledger record, external event acceptance, callback of SDK calls or generic task completion is not the authoritative source transaction. No short DB lock is held across provider I/O to pretend a distributed commit.

**C08 — Semantic operation recovery.** Bind caller operation identity to actual Tenant/source/actor/action/target, full canonical intended effect and relevant expected basis. Recover matching committed original results first under current disclosure before new eligibility. Different intent under the same identity conflicts. Cross-command/cross-actor business duplicates return only safe existing-source outcome without stealing another actor's attribution or minting another effect. Original recorded result and separately qualified current corrected/retracted state remain distinct. Unknown commit stays unknown until reconciled; failed projection refresh does not undo a known commit. Finite result/control expiry must reject unverifiable stale requests rather than treat them as fresh.

**C09 — Current no-op and races.** A true no-op requires current authority, current expected relevant basis and full semantic equality; equal date/text is insufficient when evidence, precision, scope or accepted interpretation differs. It creates no new occurrence/revision/recording date/impact while retaining required security audit. Original replay never advances state. Stale ABA basis rejects despite equal displayed values. Order concurrent manual/native admission, correction/retraction/reaffirmation, policy change, subject transition and permission loss after waits; unrelated metadata changes need not cause a global conflict. Do not automatically rebase an uncommitted human act onto a materially changed fact.

**C10 — Correct an admitted recording.** A real current-authorized Correct recording route targets the exact accepted recording/evidence basis with expected revision and sufficient truthful correction context. Append attributable replacement interpretation/date/evidence while preserving original occurrence/recording facts. It does not change Tenant, subject, event type or producer attribution in place. Wrong subject/type is handled by retracting the wrong recording as authorized and independently recording/reconciling the correct target. The correction may be material even if computed retention date is unchanged. Correction cannot silently alter native business truth owned elsewhere or manufacture another occurrence.

**C11 — Retract mistaken reliance without erasing other proof.** A current-authorized Retract recording action removes reliance on the identified mistaken accepted recording/evidence basis and preserves its history. It is not deletion of the real-world event, a statement that it never happened or automatic restoration of not-yet status. Independently valid native/integration/other source evidence for the same occurrence remains evaluated under the actual source rule; retracting one input cannot erase it. Provide safe current consequences and capable reconciliation. Do not infer a producer-priority rule or build a generic evidence graph.

**C12 — Repair a mistaken retraction.** Where the actual source permits, a deliberate current-authorized reaffirmation/correction of the exact retained recording can create a fresh attributed accepted revision with current evidence, authority and impact review. It does not revive old commands or overwrite newer accepted interpretation, reparent identity, undo governed erasure or release independent adverse controls. Genuine later repeated occurrences use their actual new source identity; a mistaken retraction is not a new external event. No separate Trash/Restore platform or universal button name is prescribed.

**C13 — Current impact before unsafe consequences.** Recording/correcting/retracting/reaffirming a fact and applying it to dependent policy bindings are distinct outcomes. Establish the necessary governing result or restrictive pending-impact fence before affected irreversible work proceeds. Then perform finite scoped resumable reconciliation with truthful pending/partial/blocked outcomes; no giant all-record transaction or silent scope expansion. A later lawful record/use binding to an existing event follows current profile/coverage and accepted fact; it does not require manufacturing another occurrence or resetting every old record. Unknown/denied coverage is not zero or permission to skip required scope as success.

**C14 — Preserve Q63 physical boundaries.** Every actual destructive attempt still needs current disposition authority, retention eligibility and complete registered use/reference/hold/processor/writer/copy coverage at the last-preventable source/custody gate. A correction/Stop/hold winning before that gate prevents the new affected call; after a request may have escaped, no event correction promises recall or survival. Preserve finite permit/current worker generation, original possible-effect fences, fresh destructive-retry authorization and late physical-fact reconciliation even when new policy/Stop forbids further deletion. Lease expiry, rekey, new version or event retraction cannot erase the earlier possible effect. Loss requires only lawful qualified recovery, else truthful incident/source remediation.

**C15 — Minimal structural database integrity.** Use actual existing owner records where equivalent; otherwise only the minimum typed relations for occurrence identity, accepted recording/revision/provenance, scope, operation result and necessary impact. Enforce non-null/valid-state/date/precision fields, null-complete composite scope relationships, immutable original subject/type/actor/provenance and source-appropriate semantic uniqueness. Current policy/authority/coverage needs owning transactional checks rather than a mutable cross-row CHECK. Prevent allowed-row update from reparenting or forging resulting scope; safe disposition must not cascade away required source history/control. No arbitrary new table names, permanent date key or generic epoch graph is selected.

**C16 — Actual Auth/RLS/every-door proof.** Preserve one source/P12 business decision layer and prescribed coarse Tenant RLS. App/database Tenant Authorization Context must be unforgeable and agree; missing/mismatch fails closed; pooled success/error/cancel/retry resets. Prove actual SELECT/INSERT/UPDATE/DELETE/UPSERT/MERGE/RETURNING and trigger-result rows; required SELECT; schema/table/column/sequence/default/inherited/PUBLIC/named privileges; function overload/search_path and real INVOKER/DEFINER owner/FORCE/BYPASS/service composition; views/materializations/REST/GraphQL/RPC/collections/workers/import/operator/restore doors. Close bypass paths rather than trusting a handler role check, literal SQL keyword or zero affected rows. Q67 does not copy the tutorial per-row capability policy into RLS.

**C17 — Safe current projections and UI.** Source facts, evidence references, counts, impact samples, history and original results use existing static field classification/subtract-only projection and current disclosure. Recording rights do not grant agreement body/history/hidden hold access. Safe source summaries or capable restricted review permit useful action without blind overwrite. Request-bound Auth clients, private correctly scoped caches and stale-response fencing prevent cross-account/Tenant leakage. Context, known values, draft/focus and truthful recorded/impact/unknown statuses survive recoverable errors; passive GET/render/prefetch/blur/IME is inert, deliberate commands use existing origin/CSRF protection. No raw event payload to public cache/realtime/email and no new notification purpose.

**C18 — Finite resources and operations.** Qualify bounded evidence/payload/occurrence/revision/page cardinality, impact targets/copy fanout, query/lock/transaction/retry, worker concurrency, latency/backlog and result/control retention with actual workload units. Use indexed set-wise current projection, stable unique keyset pagination and current per-page/chunk checks; no N+1 PDP or full history scan per form. Preserve P12 R6 logical≤1 governance-row SELECT+≤1 ledger UPDATE per governed read, written physical-shard carve-out, restricted unstriped conditional pre-egress hard-deny/zero denial and uniformity priority. This is not all SQL in a mutation. No borrowed workflow/Stripe/Eve quotas, speed, capacity or free-cost claim.

**C19 — Compatibility, privacy retention and restore.** Pin semantic source/event/representation versions; new code cannot reinterpret old occurrence precision or policy meaning. Unknown versions deny fresh effects while preserving current fences, original results and capable recovery. Inventory actual old writers/readers/data; guard before new writes and qualify mixed-version behavior. Governing record/evidence/history retention and privacy repair are distinct from minimal dedup/Stop/possible-effect controls; no infinite append-only plaintext archive. Restore reapplies current restrictions, retractions/corrections, dedup and physical outcomes before serving or dispatch. Database backup alone is not object recovery; rollback cannot revive an expired producer or bypassing writer.

**C20 — Complete source remedy and evidence stage.** Record/correct/retract/reaffirm/reconcile must have actual eligible source operators and useful bounded recovery, including departed original actor and lost source access. No blanket original-author-only gate, powerless queue, routine direct SQL or provider-console repair. A disabled human route does not invalidate existing legitimate native facts; unsupported profiles remain safely unavailable with actual duty handling, not retain forever. Prove intended-user/native/custody/operational outcomes before affected activation. Q67 selection does not supply a legal trigger, live GF Tenant, actual occurrence, financial scope, period, provider or implementation/ratification. No model or benchmark is claimed by this review.
