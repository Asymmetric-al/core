## The genuine remaining choice

The founder already requires recipient-change recovery, and Q01 already requires any such change to be source-owned, versioned and safe. The open choice is the **continuity procedure when an issued ordinary request was directed to a different intended person**, not whether staff can fix mistakes and not whether an email address field should be editable.

Recommend **A: a guided, linked replacement request for a different intended person**, preserving the old request and its history and qualifying the new recipient through an independently reviewed original issuance. The alternative **B** adds a tightly bounded same-request successor only where the source proves there has never been an admitted participant-origin **or staff-supplied** contribution, adopted evidence or participant clarification, and no prior transcript is transferred; otherwise it uses the same guided replacement route. This is a product judgment about a simpler, understandable permanent boundary, not evidence that recipient mistakes are common or that B cannot be implemented safely.

An illustrative situation: a request intended for Maya was issued to Jordan. Staff should be able to correct that mistake through one coherent source workflow without copying private evidence, taking over Jordan's identity or leaving unclear whether Jordan can still use the old request. A keeps the old and replacement request identities explicit. B preserves the request identity in a proved early, unused case, at the cost of an additional source eligibility/authority handoff and race to qualify. Neither option means rebuilding every definition by hand, quietly leaving the old grant live or treating the new draft as already issued.

**Same person's corrected address or lost-mailbox recovery is a separate identity/contact case.** It must use its actual current source/identity qualification. Email equality, normalization, a profile edit or staff saying “same person” cannot prove that case; conversely, this question must not force a different-person replacement procedure on an independently qualified same-person recovery. This distinction is necessary to keep Q49 one concrete product choice.

## Boundaries the question should preserve

1. **Correct the source recipient, not global identity.** A new intended person is not a typo fix to an Auth user, CRM person, donor profile, Party or contact record. The source must establish that person's legitimate role in the exact request purpose. Do not infer representation, delegation or sameness from name/address equality.
2. **Keep original facts immutable.** Preserve request/item definitions, real receipt attribution, accepted evidence, participant assertions, source conversation, issued grants, original audience and transport history. A replacement link is not a transfer of those rights or a relabeling of who supplied evidence.
3. **Define B's negative eligibility from authority, not a screen.** A durable participant file receipt or Q30 response is a response even if scanning is incomplete, no preview exists or the viewer cannot see it. Any ever-admitted staff-supplied contribution also disqualifies the pristine shortcut, whether accepted, unaccepted, later withdrawn or superseded. Transfer progress is not receipt. Missing/filtered/unknown history cannot prove never-responded. Adopted evidence and incompatible current commitments must be checked through their real source.
4. **Serialize the actual handoff.** Recheck source authority, expected recipient/context and relevant work/adoption state at commitment. If receipt/clarification/adoption wins first, a stale early-successor action must conflict and offer the actual replacement path; it cannot discard the new fact. If the authority-ending transition wins first, late operations cannot borrow the new recipient's scope. Already received lawful work and protected retention remain governed independently.
5. **Preparation is not old-authority termination.** Creating a replacement draft, copying definitions or changing a UI recipient field does not revoke the old person's active grant, cancel the old request or issue the new one. A guided flow must expose the actual old-authority and new-issuance results, including partial/unknown recovery, through capable qualified source operations. It must not claim the correction is complete while leaving a previously active recipient unknowingly authorized.
6. **Reuse only permitted definitions.** A deliberate definition transfer can avoid typing the same requirements again, but must be source-qualified for this journey. Q39 does not authorize cloning an issued instance or hidden personal text. Review actual reused instructions; keep evidence, transcripts, assertions, grants/proofs, clock ends, recipient bindings, reviewer instances and message plans out of an automatic copy. Resolve valid new defaults from the new current source context.
7. **New recipient, exact new proof/action context.** No unnecessary full Asym enrollment or fake Party. Preserve Q01's fixed source-approved recipient/address revision and stronger source assurance; qualified proof reuse is permitted only for the exact new context. Old sessions/links do not silently retarget. A safe old landing must not disclose the new person's identity or private new request.
8. **Messages and reminders preserve their own occurrence truth.** Fence affected old recipient-bound intents through the actual P17/P6/source rules. No rerouting sealed mail, false recall, duplicate fresh key or optional notice dependency that rolls back lawful native work. Q35 cannot notify a wrong address merely because the old request ends. Q48 counts/stops/history cannot be reset to evade limits; a genuinely independent new request is reviewed for its own legitimate purpose, not created as a noise workaround.
9. **Current disclosure applies to the link and history.** Staff may need an authorized correction/replacement relationship; the recipient does not automatically see the predecessor, its files or transcript. Search, counts, titles, old responses, audit and result recovery must not reveal another person or source. Seeing one relationship does not expose all linked uses.
10. **Ordinary first scope and capable recovery.** Preserve specialized source owners, terminal/accepted facts and same-person identity recovery. Wrong recipient, response during correction, denied authority, no safe address, old-access uncertainty and new-issuance failure need real source repair. The permanent path must not require raw SQL, provider-console edits, blind confirmation, forced duplicate upload or pretending a draft is active.
