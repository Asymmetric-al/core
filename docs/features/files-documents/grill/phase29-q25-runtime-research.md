# Phase 29 Q25 runtime research — review responsibility at original issuance

2026-10-22, Asia/Bangkok. Q01–Q24 and their complete amendments are ratified. Q25 is unselected. This is bounded next-question research, not a selected-answer adversarial review, implementation or native qualification.

## Recommendation and the genuinely open choice

The candidate is a meaningful next decision: **must an ordinary request have a known usable Q24 person/team review route when its original recipient collection access is first issued, or may otherwise-authorized collection start in an explicitly supported, accountable assignment-needed source state?**

Q24 deliberately chose responsibility shape at the review-action boundary and left collection-before-resolution open. Requiring a supported source contract, authorized issuer, safe private custody and capable recovery before product activation is already settled. Requiring a currently resolved review destination on each original issuance is a different possible product prerequisite. Do not re-ask whether unauthorized review, an unqualified source lane or unknown protected authority may proceed: they cannot under either option.

I lean **A — establish a known usable qualified review route before original issuance**. Q24 already permits a team, so this need not mean selecting a named person, requiring anyone online or getting another approval. Reuse an existing qualified source responsibility/default; only a genuine gap needs staff attention before asking the recipient to submit private evidence. That gives the ordinary flow a clear path to the required Q21 review and Q23 resolution without starting a recipient's fixed access period while staff still need to establish that route.

The strongest B is not “collect with nobody responsible.” It is **allow collection in a real source-owned assignment-needed lane**, with the issuer's permission, recipient/purpose terms, custody, current intake authority and capable staff resolution all established. Specific review responsibility can then be resolved before review actions. This avoids delaying otherwise legitimate collection when recipient availability and reviewer assignment need not coincide, but adds an unresolved-work obligation and risks a review backlog while the already-fixed source clock runs.

This recommendation is product judgment, not measured ministry staffing evidence. Current availability cannot be guaranteed for the whole access period under A; later staff changes still use Q24. B cannot claim that a generic task flag already supplies accountable recovery. Neither alternative should silently become a new ongoing-intake stop after lawful issuance or a fresh-access policy for Q13–Q19.

## Practical implications the final question should make clear

1. **Scope the decision to new original issuance.** Draft creation and editing are separate; no retrospective invalidation of lawful already-issued requests is inferred. Later staffing loss remains Q24's current source/eligibility problem. Reissuing credentials, resending messages and fresh source access are different events, not ways to evade the selected prerequisite.
2. **A is current qualification, not guaranteed future attention.** A known eligible person or usable qualified team may be offline; a team label alone is insufficient. Do not introduce availability calendars, synchronous acceptance of assignment, another named reviewer or a new review SLA.
3. **B requires a known supported condition, not a fail-open fallback.** The source must deliberately support collection while review assignment is pending and retain capable owned repair. A failed authorization query, unresolved issuer/recipient scope, missing contract or unsafe custody remains blocked. If the system cannot establish whether the issue is only an allowed assignment gap, B cannot guess.
4. **Clock semantics stay fixed.** A starts the original access period only at actual source issuance after its selected precondition. B starts it normally even while assignment is pending. No timer pause, automatic extension, altered due target, new sixty-day restart or extra completed-access stage follows.
5. **Protect recipient expectations.** The permitted request view should distinguish received/checking/awaiting review and actual available help without exposing staff rosters or internal assignment failure details. Do not promise a reviewer has started or that collection is accepted merely because a task exists.
6. **Preserve exact operation recovery.** If qualification races with issuance or the response is lost, recover the actual original admission before treating the work as a new issue attempt. Neither a new staffing check nor a delivery retry can rewrite original source terms. Full concurrency/failure proof belongs in the selected answer's adversarial review, not a guessed new algorithm now.
7. **Do not widen the cohort.** Stricter application, care, financial or specialist source preconditions remain. Ordinary native policy does not automatically generalize to public intake, anonymous upload, all GEN-06 recipes or freshly restored records.

## Is another question simpler or higher value?

Default algorithm details, personal claiming, workload balancing or assignment notifications would be premature: Q24 intentionally accepts source-qualified existing mechanics, and none of those is needed to state the next boundary. Keep one fair fork. If the owner reconciliation were to find an exact existing ordinary-source requirement already deciding original issuance readiness, apply that contract instead of reasking; the current inspected sources and Q24's explicit deferral do not establish such a decision.
