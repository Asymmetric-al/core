# Phase 29 Q42 — One home folder, with labels and saved views

**Status:** Fully ratified by Conrad, 2026-10-25, Asia/Bangkok: Q42 A and every
required amendment. The reviewed disposition was **Accept with required
amendments**. The exact fourteen-paragraph decision and full clause/proof,
category, lifecycle, journey, budget and operating-control package are adopted
without substantive change. Q01–Q42 are ratified; all 26 glossary definitions
remain unchanged. This is grooming intent, not a formal PRD, implementation,
native qualification, release or activation.

## Conclusion and strongest alternative

Keep A. One optional home gives ordinary request evidence a predictable location;
labels, source context and saved views supply other routes without duplicate
folder references. This is appropriate for source-owned operational evidence,
where staff need to find and use material without changing its business meaning.
It is not a claim that folders are universally superior or that users must file
every receipt. **Unfiled is a useful normal state.**

The strongest alternative remains one home plus explicit non-owning references
in other folders. Google demonstrates that model; it need not copy bytes or
grant access. It would better serve teams that repeatedly navigate several
hand-curated folder structures. Its extra home/reference/removal/unavailable-
target distinctions are not justified by measured Asym need here. A uses already
required labels and views. No-build source navigation alone is simpler, but it
does not satisfy the founder's explicit organization outcome. A universal drive,
automatic taxonomy or new search vendor is unnecessary.

The material amendments are: exact source-use cardinality and namespace;
one-time **home-only** continuity for qualified corrections; protected
organization metadata; empty-only folder removal with finite Move first;
non-authoritative labels and fail-safe saved predicates; and real transaction,
permission, recovery and rollout proof. These make A concrete without adding
another workflow or permission platform.

## Ratified corrected decision

> For ordinary Private Document Request evidence, provide one optional home folder per exact admitted contribution/use in the Tenant × environment × ordinary-request filing namespace. An entry may remain Unfiled. Labels, authorized source navigation, search and saved views provide other discovery routes; appearing in those routes is not another placement. The identity is the source's exact evidence use, not an entire multi-file item, filename, byte digest, provider object, person or universal Logical Document. Different uses of the same bytes retain independent filing and authority. Existing Page/Article and Media folder contracts remain separate and unchanged.
>
> Filing is optional staff organization. Receiving, inspecting, reviewing and otherwise lawfully using evidence must work without a folder or label and through a recoverable organization outage. The source may permit organization of a durably admitted use while Checking, rejected, historical, fulfilled, canceled or retained; none of these states independently grants organization or byte access, and participant access expiry is not a blanket staff-filing prohibition. A move, label or view does not change the source, evidence version, current candidate, acceptance, fulfillment, publication, permissions, share terms, retention or disposition. It does not move provider bytes, rewrite an immutable original, alter source-event chronology or create review work or participant/staff notices. Organization has its own attributable restricted business history, separate from redacted operational telemetry. Ordinary logs, analytics, traces and crash reports must exclude private names, paths, labels, view predicates, content and hidden associations.
>
> New independent participant contributions and Q28 staff-supplied uses start Unfiled without copied labels. For an actual Q03 correction, or an explicitly qualified Q28 replacement with an exact predecessor, the ordinary source performs a one-time home-only carry-forward at admission when the predecessor and successor belong to the same Tenant, environment, request and item and the current destination and source maintenance authority qualify. Bind the ordered predecessor-home and destination basis to that admission. Do not copy labels, acceptance, rights, shares or history access; do not infer lineage from equal bytes, names or a whole item. An unavailable, incompatible or conflicting optional filing basis leaves the lawful new receipt Unfiled rather than blocking receipt. This fallback applies only after independently valid source admission: unknown or invalid Q03/Q28 authority, custody or required evidence conditions must still block that admission. Record the original carry-or-Unfiled outcome; no later worker or retry copies a then-current home. Subsequent filing is independent, and non-byte changes to the same use preserve its existing home and labels.
>
> Current source/P12 authority governs organization commands and each disclosed fact. Permission to inspect evidence, responsibility for review, folder visibility and staff rank are not filing or folder-management authority. Resolve actor, Tenant, environment and source scope on the server; validate selected entry and destination against that context. Folder, label and view metadata are protected independently of evidence contents. No per-folder ACL, permission inheritance, participant folder rights, cross-source relocation, shared public folder or second policy engine follows. Existing narrower source/classification restrictions continue to apply inside the filing namespace.
>
> Apply current authorization before names, paths, labels, view definitions, result ordering, counts, facets, suggestions, pagination and errors are disclosed. A visible folder grants no entry visibility, and a visible entry grants no hidden path or other-use disclosure. Source-approved metadata remains discoverable independently of preview readiness. A hidden filing location is not falsely presented as Unfiled; render a neutral unavailable location only where that fact itself is permitted. Unknown authorization or incomplete coverage is not a successful empty result or proof of an empty folder. Q38's approved-metadata-only search boundary and Q41's exact share scope remain intact.
>
> Offer create, rename and move for authorized folders and Move to folder or Remove from folder for eligible entries; the latter sets only that entry's home to Unfiled. Folder identity remains stable across rename and reparent. Parents and placements remain in the same namespace; the hierarchy cannot contain cycles or ambiguous normalized sibling names. Removing a folder is an empty-only operation: current authoritative state must prove no directly filed entries or child folders, including those absent from the caller's filtered display. First offer the existing finite Move flow for entries or child folders, then a separate deliberate Remove folder. Never recursively delete evidence, silently rehome hidden contents or invoke provider folder deletion. A currently authorized source/organization operator resolves inaccessible memberships through permitted exact membership facts and the same Move or Unfile commands. Source-owned reconciliation may clear only proven-stale organization references while preserving source evidence and required history. Neither broad body-read grants, hidden-count disclosure nor routine database repair is that remedy.
>
> Labels are optional, nonauthorizing organizational metadata, not source review or workflow states. A label such as Reviewed must remain visually and behaviorally distinct from actual source acceptance. Preserve original display values, use stable identities, and qualify name normalization without silently merging different entries, folders or labels. Saved views store validated query/display definitions, not frozen results, membership or permissions. Renaming a referenced folder or label preserves its identity; removing or losing access to a referenced criterion must not silently discard that predicate and widen results. Show a safely repairable unavailable view and require deliberate changes. Initially use actor-owned private ordinary saved-view definitions and existing qualified system/source views. This decision does not activate P9's reserved team/everyone visibility or erase the promised shared-view outcome, which requires its separate owner-qualified audience decision.
>
> Use one source-aware server command boundary for all organization writes and finite bulk actions. Compare the relevant current placement, folder/parent, label/view and authority dependencies; revalidate at commitment. One submitted finite bulk Move is all-or-none, with the exact selected eligible identities and expected state, never a fresh all-matching query on retry. Coordinate competing moves, hierarchy changes, empty-folder removal and correction-home initialization so one lawful order wins. Persist the effect and required history/receipt coherently. Recover an exact committed operation before evaluating it as a new move, under current result-disclosure authority; an old retry must not move an entry back after a later successful move. Changed material conflicts. Readable receipts/history follow source retention; expiry or restore must not turn an old semantic operation into a new command. Retain the minimum required deduplication/result evidence or reject unverifiable stale operations, without perpetual readable private history. Recovery is a newly authorized forward action, not blind rollback.
>
> Enforce one-home cardinality, immutable scope/source relationships, same-scope typed references, unique label assignments and valid parentage structurally where the database can express them; enforce cross-row graph and source rules through the single serialized mutation boundary. Use explicit nullable placement for Unfiled or a proved equivalent; absence of a failed projection must not mean Unfiled. Qualify actual grants, RLS old-row USING and new-row WITH CHECK behavior, policy composition, upserts, views, functions/RPCs, service-role paths, workers, imports, trigger-initiated writes and alternate APIs. Root folders with null parents must obey the same normalized sibling-uniqueness rule as nested folders. Caller input cannot retarget tenant, source use, attribution or approval fields. Organization deletion cannot cascade into source evidence, custody, audit or retained facts. No finance or money schema is introduced.
>
> Keep the ordinary interaction small: All request files within an always-visible ordinary-request scope, Unfiled, visible filters and permitted source context; a clear current location; and an accessible searchable Move picker with one deliberate commit. This folder lists direct entries; All request files covers the currently authorized ordinary-source cohort. Any separately supported descendant-inclusive mode must be explicitly labeled and bounded; do not silently recurse or imply complete cross-product coverage. Preserve lawful selection, query and return context. Report acknowledged success, conflict, failure and unknown result honestly, with persistent recovery beyond a transient toast. Undo, if offered, is a newly validated move that cannot overwrite later work. Do not require filing, tagging, explanations, a second approver or a notification for routine organization. Participants, external Q41 readers, donors, missionaries and public users retain their focused source experience and receive no staff tree through this feature.
>
> Use shared Core Base UI/base-maia controls and meaningful text labels, with keyboard and non-drag single-pointer operation, correct focus restoration and restrained status announcements. Support narrow-screen reflow, zoom, touch, assistive technology, long and international names, Unicode/RTL/IME input, locale-aware dates and explicit time zones where relevant. A slow connection or lost response must preserve safe recoverability. Fence obsolete responses and private cached state on actor, Tenant, purpose or authority changes. Do not persist restricted content or queue unapproved mutations for silent offline replay.
>
> Keep implementation to the existing source, API, metadata, query/view and UI boundaries. Reuse compatible mechanics without importing CMS permission, recursive removal, version or storage semantics. No general hierarchy engine, shortcut layer, automatic classification, body-text extraction, sync service, new provider or speculative closure table is selected. Bound and measure server-side list/picker queries, hierarchy traversal, label joins, view evaluation, bulk size and concurrency on the actual supported workload. Define finite operational budgets and authority-safe failure behavior before activation; no unmeasured speed, capacity or unchanged-bill claim follows from this decision.
>
> Migrate additively with a retained-data census and exact source-use mapping. Do not infer filing from provider keys, legacy paths, filenames, uploader identity or equal bytes, and do not mass-rewrite source facts to initialize Unfiled. Qualify old/new readers, writers, jobs and adapters before enabling mutations. Preserve stable identities and history in export/restore; apply current restrictions before serving restored data. A kill switch stops affected organization writes or derived serving without reversing source receipts or disabling independently qualified source work. Roll forward with supported repair; rollback must preserve organization data already written and must not revive removed access.
>
> Before activation, prove the exact source/P12 mapping, database and privileged paths, races and replay, correction carry-forward, empty-folder removal and recovery, private metadata, saved-view failure semantics, migration/restore, finite workload and composed accessible user journeys. Reconcile Q42 through the owning source documents and full incorporated OpenSpec at authorized publication, then design, tasks, authorized tickets and release evidence. Until those proofs exist, this is reviewed grooming intent, not a native implementation or activation claim. Q01–Q41 remain unchanged except for the expressly proposed ordinary-source organization initialization added here.

## Adversarial check

### What could go wrong with this answer?

Staff may assume a folder shares or owns evidence; a correction can inherit a
misleading label; removal can delete material; a stale retry can reverse later
work. C01–C09 make these invalid rather than relying on training.

### What hidden assumptions are we making?

We have not observed real staff filing frequency or measured capacity. Labels
may not suit every team. Exact source identity and usable operator recovery
still require native proof. Competitor screenshots and adjacent code establish
neither. The strongest B alternative remains documented.

### How does this affect the whole product?

It provides ordinary staff organization while preserving source evidence,
P12 authority, P23 specialized folders, Q38 search and Q41 sharing. Donor,
missionary, public, finance, care, resource and official-document owners gain
no new permission or lifecycle from a folder.

### How does this affect the end-user experience?

Staff can work without filing, use one clear Move action and find evidence in
several authorized ways. Exact corrections retain a qualified home without
inheriting labels or acceptance. Removing a folder requires moving its contents
first, using bounded bulk actions; this is the deliberate simplicity tradeoff.

### Does this follow modern best practices?

Yes as a context-specific product judgment: source context, optional metadata,
saved queries, stable identities, current authority and accessible non-drag
actions have strong primary precedents. Neither multi-location shortcuts nor
folder-plus-tags is a universal winner. Vendor disclosure/deletion/automation
defaults that conflict with Core are explicitly excluded.

Yes with the ratified amendments. It keeps the operational source, custody,
CMS, source views, policy and shared UI owners distinct. It does not mistake
current public Media or gift-history code for an ordinary private organizer.
It preserves the required File Manager outcome without creating a general drive.

### Should we adjust the recommendation?

Keep A, with C01–C14 and P01–P30. The final disposition is **Accept with required
amendments**. Do not record unamended A as final or call this native qualification.
