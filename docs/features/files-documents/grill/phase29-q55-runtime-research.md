## Recommended genuine choice

**Recommend A: a passed review date creates honest review-due status and curator maintenance, while an otherwise safe, authorized publication remains available.** B makes that review date an automatic library-availability cutoff until a deliberate qualified rereview. This is an effect of the resource's review date, not a choice about whether to build the required library or who already owns it.

| Option                             | Reader and curator outcome                                                                                                                                                                                                                                                  | Real benefit and tradeoff                                                                                                                                                                                                                                                                       |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A — Advisory review date           | The reader can still open an independently valid published resource, with truthful review-due information where permitted. The curator sees due maintenance and can actually review the exact publication, correct/replace or withdraw it.                                  | Avoids removing useful guidance solely because a maintenance date passed. It requires honest status and an accountable maintenance journey; readers may still rely on material whose scheduled review has not happened. It is not a claim that overdue material is accurate or safe.            |
| B — Review date stops availability | Once the qualified review-date boundary passes, the library stops new discovery/retrieval through that publication until the source records an actual currently authorized rereview and restores availability lawfully. Curators retain their separate maintenance context. | Stronger protection against continued routine use of guidance past a chosen review deadline. It can remove still-useful guidance because a curator is unavailable or late and requires dependable cutoff/recovery across all delivery paths. A missing scheduler run cannot silently extend it. |

Both options retain actual rights, safety, classification, access and source-validity stops. A does not weaken them; B does not turn ordinary retention into permission or make expired rights reviewable by a generic curator. Neither selection grants a mandatory reading/acknowledgment program, automatic reminder/email, recurring cadence, new task per date or a new general resource engine.

## Practical implementation consequences without a new date platform

**A can be a small current projection.** Given a currently admitted exact publication, its actual review evidence, an authorized review date and the source's declared date/zone meaning, calculate due status when serving authorized list/detail/maintenance views. The passage of time need not write a new business row, issue a notification or run a scheduler. Use appropriate existing bounded/indexed list filters for curator maintenance rather than polling every file or building an automated campaign. Caching and open-screen refresh must keep displayed status honest; they cannot become continuing permission. An absent/unknown date or actual-review record must be represented honestly, not fabricated as “Reviewed” or “Overdue.”

**B needs a real source eligibility boundary.** It may still be a time predicate, not a cron engine: every new library metadata/content admission must apply the actual review cutoff along with current source/P12 rules. A delayed background job must not leave a supposedly expired resource discoverable or readable. The source must define what happens at the exact boundary, including list/search/thumbnail/detail/original/preview/range/conditional and cached/indirect guide paths. A late result, old URL or restored record cannot bypass it. Stopping this publication does not delete the original, stop unrelated lawful uses or recall downloaded bytes/external destinations. Lifting the review-based block must be a real current source review of the intended exact version, not a cosmetic date change or retry that defeats an independent withdrawal.

Both require a modest correct date contract. A civil date is not automatically a UTC timestamp created by `new Date('YYYY-MM-DD')`; reader locale is presentation, not source authority. Use the existing qualified source calendar/time-zone convention or explicitly adopt a small one before activation. Define “date passed,” equality and the due-day boundary, DST/zone changes, unknown values and exact comparison semantics. This question should not invent universal days, review frequencies, grace periods, date caps or source clocks. The selected-answer review can settle the concrete temporal contract once the effect is chosen.

Context7 resolved `/websites/postgresql_17` and returned the official [PostgreSQL date/time documentation](https://www.postgresql.org/docs/17/functions-datetime.html): `CURRENT_DATE`/`CURRENT_TIMESTAMP`/`now()` use transaction-start semantics; statement and actual clock functions differ. This matters if an authorization transaction waits across a cutoff. It does not prescribe one function or prove a deployed source path. For a hard B boundary, native tests must exercise the actual effective admission time after relevant waits rather than assume an old transaction timestamp is always current.
