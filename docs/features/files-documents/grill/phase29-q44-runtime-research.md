## Recommended product fork

For a finite staff-selected set of eligible ordinary request-evidence originals, recommend **A: prepare one bounded private ZIP download with its manifest and integrity/outcome record**. B is **a prepared list of individual exact-original downloads with the same manifest/outcome record**. Both implement required authorized bulk handling; neither is “build bulk downloads versus do nothing.”

| Option                            | User experience                                                                                                                                                                                                                 | Fair tradeoff                                                                                                                                                                                                                                                                                         |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A — One bounded private ZIP       | Review the actual selected set; prepare a package; download one archive containing the eligible exact originals and an understandable manifest. Partial/unavailable members are identified only as source/privacy rules permit. | Convenient for collecting several files and keeping their manifest together. Requires a qualified archive-building/staging/retrieval lifecycle, safe entry names and truthful package completeness. It creates a temporary derived byte artifact and does not prove files reached a safe destination. |
| B — Prepared individual downloads | Review the same finite set and receive a stable prepared list, manifest and per-member outcomes. Deliberately retrieve each permitted original through its current authorized route.                                            | Avoids building an archive and lets staff retrieve only what they need or retry one file. More download interactions and local file/manifest organization; the browser must not be assumed to permit an automatic burst of downloads.                                                                 |

A is a product judgment, not measured Asym task performance, a ZIP-library selection, proof of lower infrastructure cost or a promise that every selection fits one archive. The supported selection/byte/runtime limits belong to engineering qualification. A should preserve a clear smaller-selection or other actually qualified recovery path when a request exceeds those bounds; it must not silently add a multipart archive platform. B must remain a complete deliberate browser workflow, not a loop that calls click() repeatedly and labels every requested file Downloaded.

The first cohort is **staff download/export of exact admitted ordinary Private Document Request evidence uses**, whether participant receipt or eligible Q28 staff supply, with current source permission for the exact original. Q04's participant download grant, Q41 external-recipient scope, Q43 view access or Q42 folder placement does not supply this staff bulk authority. Current source classification/origin restrictions continue to apply, including restrictions that cover reused Q28 material.

Vercel's current Function limits page documents request/response payload, duration, memory and descriptor constraints. Its linked official knowledge-base article explicitly distinguishes streaming responses: streaming can avoid the ordinary response-size limit. Therefore **4.5 MB is not a justified universal Core ZIP cap, nor proof A is impossible**. Streaming still consumes the configured execution duration and actual resources; route/runtime/plan support must be measured at the chosen deployment. No payload/runtime setting was changed. [Function limits](https://vercel.com/docs/functions/limitations), [official response-size guidance](https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions).

A signed URL with a short TTL is not a fresh source/P12 decision on each later request. ## Minimum boundaries for either choice

1. **Current source authority for each selected original.** Prove staff download/export authority for each exact admitted use and original version, including applicable Q28 origin restrictions, classification, safety and retention/access distinction. Mere discovery, review, preview, acceptance, shared-view membership or participant access is insufficient. Not every accepted file is universally downloadable; not every unaccepted file is universally forbidden. The source decides.

2. **Freeze a finite reviewed selection.** Bind exact source-use/version identities and expected relevant basis from the actual user selection, not a folder, digest union, provider prefix or later “all matching” query. Equal bytes in two source uses do not erase their separate purpose/outcome facts. A correction or new version cannot silently replace the selected original.

3. **Manifest and outcome are protected source data.** Preserve an understandable mapping from the prepared output to the requested exact selection, permitted source/version identity, byte/integrity facts and truthful included/unavailable/failed/not-started/unknown outcomes. Authorized omissions must not disclose newly restricted titles, associations or hidden counts. An incomplete library query does not create a complete selection manifest.

4. **Preparation, availability and retrieval are distinct.** Requested, building/preparing, ready, expired, blocked, failed, partially available and observed delivery outcomes must reflect actual durable facts. Do not call provider upload success, a generated URL or a clicked browser anchor “downloaded and safely stored.” Neither A nor B certifies human reading, verified destination custody, source completeness, legal sufficiency or source deletion.

5. **A has an additional immutable derived artifact.** A package binds the exact admitted members/output and source-approved manifest; safe archive entry names cannot traverse paths, collide silently or execute content. Original file bytes are not rewritten/rendered as replacements. An uploaded original that is itself an archive is not recursively unpacked merely to build the outer ZIP. File names, manifest text and hashes require their actual disclosure rights.

6. **B is an explicit prepared download list.** Preserve the same selection/outcome across separate retrievals; each actual file request still rechecks current eligibility. Do not rely on automatic multi-download browser permission, a downloaded count inferred from clicks or access to the user's local folder. Make manifest retrieval and failed-member recovery usable.

7. **Currentness survives preparation.** Private package bytes and manifests remain subject to applicable current source/P12 retrieval rules, including resumed/range/conditional requests where supported. A prepared archive containing a now-forbidden member must not be served merely because it was safe at build time. The selected-answer review must close whole-package blocking/repreparation and truthful partial-output behavior without mutating a sealed old result or leaking forbidden members. Revocation does not recall bytes already lawfully received.

8. **Recover the original operation.** Retry a lost preparation/retrieval response against the exact recorded selection/result; do not rebuild from a changed view or create new arbitrary duplicates. Preserve source history and minimal result identity as qualified. Byte-stream delivery and multiple downloads are not made atomic by Q42's all-or-none metadata Move rule.

9. **Short-lived staging is not source disposition.** Protect staged originals/copies/package/manifest with the actual permitted lifecycle, private retrieval and cleanup/hold/currentness fences. Expired or deleted staging never deletes the originals, revokes independent source uses, ends a hold or certifies offboarding. Cleanup/recovery must handle crashed preparation without public fallback or destructive source rollback.

10. **Bound actual work and keep the native route usable.** Qualify finite member/byte/name/manifest sizes, total input/output/compression work, memory, stream buffers, duration, retries, concurrent tenant work and staging lifetime. One large request cannot starve intake/review. For A, “one package” means one supported bounded package, not unbounded all-history or hidden multipart complexity. For both, unsupported/oversize selection needs an honest smaller-selection or actually qualified alternative, not an unexplained failed Download.

11. **Preserve unrelated owners and controls.** No P21 official records export, P31 destination connector, participant bulk grant, share-recipient expansion, public asset rule, email attachment, new notification, automatic export schedule or source deletion is added. Use the existing shared UI, current permission brain and qualified custody workers; no general export/drive engine is selected.
