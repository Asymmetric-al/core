## The question

**For an issued ordinary Private Document Request with outstanding recipient work, should authorized staff be able to change its Requested by target while the request remains eligible and unfinished?**

- **A — Allow deliberate Requested by changes for outstanding work. Recommended.** Authorized staff can revise the source's current requested target in the existing request context. Show the intended change, save it deliberately and preserve attribution and prior applicable terms. The current plan can change without resubmitting files or creating another request. This adds a small source-owned correction/rescheduling action with current authorization, revision checks and truthful recovery.
- **B — Keep issued Requested by targets fixed.** The original target remains the recorded target after issuance. This is simpler and keeps one stable baseline; later coordination uses an independently permitted source communication rather than changing this target. Its cost is a stale-looking requested-by date and possible manual explanation when plans change. Actual governed correction of erroneous source facts remains distinct from ordinary rescheduling and is not a workaround permission.

**Recommendation: A.** Q09 already made this date a planning target rather than an automatic lockout. Allowing a deliberate current-plan change is consistent with that meaning and the selected ability to add work and revise instructions. The complexity belongs in preserving source history and current authority, not an approval queue, new calendar service or repeated recipient submission. No measured time-saving or Asym frequency is claimed.

## Boundaries preserved under both options

1. **Target versus access:** Requested by remains Q09's soft coordination target. The original/fresh unfinished end, completed access, actual binding cutoff, revocation and source closure keep their independent rules. Show actual access limits; never suggest that changing a target extends access. Q12 does not impose a universal target-only rejection merely because a target falls after access ends. If renewed access is needed, only its separately authorized source action can provide it; do not make an otherwise source-permitted planning edit itself an access grant or silently require a new one.
2. **Current work versus history:** A change applies prospectively to its qualified current target scope. It does not backdate its occurrence, erase receipt/target evidence, relabel previously received material using today's date or shift a staff-review backlog onto the recipient. Governed erroneous-fact correction is distinct.
3. **Exact eligibility and scope:** A is for actual outstanding recipient work on an eligible unfinished ordinary request, using source/P12 powers. It creates no permission for a participant, reviewer label, task owner or broad administrator by implication. Specialized hard-deadline sources remain outside this ordinary choice. Do not introduce per-item inheritance, bulk edits, new target levels or a different recipient/purpose through this question.
4. **Existing date semantics:** Earlier/later edits use actual source rules and preserve qualified date/instant precision, zone/calendar and optionality. No universal mandatory-date, future-only, date-removal or missing-date-default rule is selected here. Unknown target data is distinct from no target. Do not convert every date-only value to browser-local or UTC midnight by accident.
5. **Deliberate coherent save:** Under A, show the current and intended target and use an explicit Save changes/Cancel action. No extra routine approver, mandatory explanation, automatic submission or repeated confirmation is justified. Preserve safe input on conflict/error; expected revisions and durable operation recovery prevent stale overwrites or duplicate effects. An unchanged save should not manufacture a new revision.
6. **Submission races and source work:** Q09's actual first-admission terms govern a concurrent target edit/submission. A compatible target-only change must not force reupload or alter an already admitted receipt; material instruction/evidence/source changes retain their own guards. Fulfillment/cancellation/revocation cannot be undone by a stale save or backup.
7. **Communication and current views:** The authorized request page and staff work projections show truthful current terms. No new notification default, cadence or automatic reminder rescheduling is chosen. Independently qualified existing effects must use their actual current source/dispatch rules; old prepared messages cannot assert obsolete work or grant rights.
8. **Small implementation and honest evidence:** Reuse the current source mutation boundary, trusted attribution, native scope/revision constraints and existing date controls. No cron or full-history scan is needed to decide current authority. Real-role grants/RLS/all-writer, concurrency, migration, locale/date and browser/AT proof remain necessary. Research and document validation are not native passing tests.
