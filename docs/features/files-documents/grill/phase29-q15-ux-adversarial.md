# Phase 29 Q15 — reviewed repeat access without a renewal product

Research/review date: **21 October 2026, Asia/Bangkok**. The parent reports Conrad selected **Q15 A: further individually approved sequential fresh periods after ordinary expiry**, and again asked to avoid overengineering. Q01–Q14 and their complete amendments are ratified. **Q15's full amendment package remains unratified.** This note proposes refinements, not another founder choice or a Q16 decision.

Only this research note was written. No canonical record, UI, product, permission, provider, dependency or private account was changed or exercised. The question, Q14 UX review and same-day primary comparative research were read; this is not a native source, browser, assistive-technology or intended-user test.

## Disposition

**Keep A with focused refinements.** The user-facing flow remains the existing request, meaningful current context, **Grant access to continue**, and the actual new end. Q13 and Q14 already supply the authority, exact timing, effect recovery, private serving, completion and accessibility contracts. Q15 should specialize repeat eligibility and its presentation, not create a renewal center, configurable quota, grant-calendar product or parallel state framework.

The most important incremental UX distinction is **a historical successful grant versus access that is usable now**. Recovering an old result must neither display a fresh success celebration nor replace the current valid end with its old end. The other central distinction is **real continued recipient need versus merely unfinished staff work**: another grant is available for legitimate current use, not automatically required whenever a request is still unfinished.

## Preserve the strongest alternative and the honest cost

B, one successful fresh admission only, has a real benefit: a final count boundary and fewer future authorization decisions. It can be reasonable even when a request remains unfinished. Its cost is ending this recipient route while legitimate work remains, without promising another channel or allowing a cloned request to reset the limit. A is not justified merely because some file-request products permit reopening.

A instead allows a potentially long sequence, including years if each source decision truly qualifies and no independent cap ends the purpose. **An individually finite end does not provide a finite aggregate lifetime.** Current-purpose review mitigates drift but does not mathematically impose a cumulative cap. Do not describe A as a guaranteed finite overall exposure window.

No positive cooldown follows from sequential admission. Each prior authority must genuinely be ordinarily ended at the actual new source act, but Q15 creates neither a mandatory waiting gap nor a promise of uninterrupted access. It also creates no queued next grant, pre-expiry extension, automatic trigger or renewal entitlement. A new exact source act can only use the current lawful state; inherited qualified ordering still governs boundary cases.

The simplest alternative in many individual cases is **no new grant**: staff continue independently authorized review or resolution. A does not require another recipient visit, upload or approval merely because only staff work remains. Conversely, a legitimate current recipient readback purpose during review can support access even when no new upload is needed. Neither an unfinished flag alone nor a mandatory pending-upload count captures that judgment.

## Complete supported journeys with minimal copy

All text below is proposed wording, not tested-user copy. Private details are conditional on current disclosure authority; there is no public expiry/history badge for an unqualified link.

### 1. Staff considers whether access is needed at all

Use the existing request page. Show the intended recipient, the immediately relevant prior outcome and current source work/read purpose. Preserve the distinction between recipient action, file checks and staff review. A grant administrator need not receive file-body access just to make the decision; source-authorized metadata can be enough.

If independently permitted staff review is all that is needed, do that work without requiring another grant or telling the recipient to upload again. If recipient access still has a genuine current purpose, use the existing meaningful review and **Grant access to continue** action. No new mandatory written reason or approval ladder is introduced. Repetition itself does not justify a modal warning on every use.

Safe prior context might say **Previous access ended [date, time and zone]**. It must refer to the actual relevant predecessor, not any convenient old expiry. An authorized concise history may provide deeper context, but loading every historical row or viewing every old file is not an extra user prerequisite. A required source-lineage proof failure is different from a nonauthorizing history-display failure.

### 2. Staff grants and sees the actual result

Before the source occurrence, show Q14's fixed rule and known caps; any proposed date is an estimate. After the source successfully records the admission, show **Access granted. Unfinished access ends [actual date, time and zone].** This is a new prospective period, not an edit to the old period.

The deliberate contextual action is sufficient. Material scope/recipient/limit/lineage changes need refreshed source review; ordinary time advancing under unchanged terms does not require a second confirmation. A previous narrow selected subset is not automatically a permanent universal cap, but any different subset needs its own current meaningful review within the original boundary. Do not union all historical permissions.

Two staff actors working from an old ended result must not create two overlapping admissions. The losing or stale action returns the real current state or a safe conflict; it does not secretly schedule itself for the next expiry. Do not turn this into a new UI lock manager or quota display.

### 3. A response is lost, a prior result is replayed, or notification fails

| Proven state                                                                  | Copy/action direction                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admission is proved not to have committed                                     | Say the action did not grant access, using the actual safe reason/recovery. Do not record an apparent new period or use a success toast.                                                                                        |
| Commitment is genuinely unknown                                               | **We couldn’t confirm whether access was granted.** Reconcile the same deliberate source effect. Do not label it denied/expired or offer a new grant as the retry.                                                              |
| Admission committed; response was lost                                        | Recover its original G/end and current status. A recovering observer does not issue another thirty days.                                                                                                                        |
| Recovered admission is now ended                                              | In authorized history, **Access was granted on [date] and ended [date].** The main task state must reflect current authority, not a fresh success message. If a newer valid period exists, its current end is shown separately. |
| Current admission is proved active; a separately authorized invitation failed | **Access was granted, but the invitation could not be sent.** Repair only the supported communication. Neither automatic retry policy nor a new notification channel is selected here.                                          |
| Source commitment known, but current authority cannot be established          | Distinguish the historical act from current uncertainty. Affected protected use remains closed until current authority is established; do not convert that uncertainty to a new expiry or new grant.                            |

The current source decides what is current; the browser must not choose the maximum timestamp or treat whichever transport response arrives last as authoritative. Preserve source facts even if the notification, status rendering, audit projection or browser subsequently fails. Required source evidence still must be durable under Q13; this does not excuse an admitted result without required provenance.

### 4. Recipient returns before or after a repeat grant

Before a new admission, preserve the existing safe ended/help experience and Q01 entry requirements. Help can explain the available source process but cannot promise approval or expose private request metadata. An old bookmarked link or a familiar email address is not a grant.

After current qualified use is established, show the existing task and **Access while this request is unfinished ends [actual date, time and zone]**. Show the next permitted action and current received work. A delayed visit has only the actual remainder. Proof refresh, another device, resend and activity do not alter G/end.

Do not make the recipient create an account again, press Activate, acknowledge another timer, download a receipt, or remember how many periods have existed. No new recipient self-service approval request or help queue is selected. Current private history may be useful, but the user does not need a grant-administration UI.

### 5. Recipient resumes an upload or pending correction

The source must distinguish unadmitted old operations from a new deliberate use of current authority. Keep Q13's qualified retained-custody reuse where allowed, so a legitimate new submission need not retransmit the same usable bytes merely because its permission context changed. Never backdate its receipt or let a stale old command borrow the new grant.

Q03 still applies to the exact pending member: successful successor admission fences the old candidate while checks may remain pending; a failed check does not automatically revive the old file. Other supporting files remain intact. Previously accepted/frozen work is not reopened by another access period.

Upload progress is not receipt. If a response is lost, recover the actual same-effect outcome and safe current actions. Closing a dialog, cancelling after dispatch or losing connectivity is not proof that the source did not admit the file. The access end is not reserved by starting a transfer.

### 6. Reviewer acts while the recipient period changes

**Received — awaiting review** remains true when the file is received and review is outstanding. Granting another period neither resets that receipt nor means the evidence has been accepted. The recipient is not overdue solely because staff review remains, and the Requested by target stays separate.

Reviewers use the actual current file/correction lineage and their independent authority, not a stale recipient-grant screen. A new period does not validate an old candidate, widen body access or require the recipient to be online. If a source-permitted decision completes the request while no recipient authority exists, the business outcome can stand without inventing a completed recipient admission.

### 7. Source completes, restrictions change, or another period ends

The unfinished lane stays terminal at source completion. Eligible normal fulfillment during valid fresh authority follows Q13/Q14's declared completed-read scope and F-based maximum; it is not guaranteed extra thirty days. A timely durable completion learned late recovers its original outcome. Do not issue another unfinished period merely because its projection had still looked expired or unfinished.

Current adverse restrictions, true hard ends and genuine purpose changes cannot be removed by selecting an older ordinarily expired predecessor. A source-specific barrier remains a barrier; another positive grant action is not an override workflow.

After another real ordinary expiry, A allows consideration under the same current test, not automatic renewal. No new cooldown or extra reviewer is implied. If repetition reflects no remaining legitimate recipient need, use the actual owning source's supported resolution; do not fabricate fulfillment or cancel legitimate work merely to stop a counter.

### 8. Support diagnoses the right problem

Support distinguishes proof failure, notification failure, current-view outage, unknown admission, obsolete historical output, genuine ordinary expiry and a real adverse restriction. Each has its own existing owner/recovery route; support familiarity alone does not confer the issuer capability or private body access.

No ordinary repair resets a valid end. If a prior period has actually ended and another admission is justified, that is a new deliberate source decision. A support-only clone, manual date edit, unprotected email attachment, hidden role assignment or reclassified purpose is not an equivalent repair.

Do not treat deletion or absence of a required historical record as evidence that no prior grant existed. Reconstruct only through the permitted trustworthy source process; if required lineage cannot be proved, explain the safe inability to continue instead of fabricating an unused opportunity. None of this selects indefinite retention or another archive.

## Lean accessibility and presentation

Keep Base UI/base-maia and existing source components. Place current status, actual date/time/zone, next actor and relevant action in ordinary main content; older outcomes belong in clearly labeled concise history. Do not rely on color, hover, a countdown or a toast to communicate whether access is current. Mark old results as historical even when they were successfully recovered today.

Keep keyboard and touch actions predictable, allow reflow/zoom and long localized labels, and preserve focus after a recoverable failure. Announce one meaningful outcome rather than every poll or history refresh. Existing accessible proof mechanisms remain available; a repeated grant is no reason to require manual code transcription or disable paste.

Slow or interrupted networks must not produce duplicate source decisions or false success. When only a nonauthorizing history/preview subview fails, preserve independently verified current work with a truthful local error. When current authority itself is unknown, close affected protected actions until it is established. Do not display an empty list as a successful history load or declare the whole request ended because one file rendition failed.

Exact date precision/exclusive boundaries and relevant short-timer assessment remain inherited from Q14. A long business period is not an accessibility certification for short proof/session/upload timeouts. Browser/AT testing must exercise the composed screen; existing primitives and a polished screenshot do not prove it.

## Bounded follow-through

The parent can keep a small incremental set of repeat-specific acceptance outcomes: a legitimate second admission; no-grant staff review; prior-active/adverse/unknown cases; stale/replayed result versus current live status; competing issuers; delivery failure after commit; late completion; retained received work; and the same accessible request experience. All inherited Q13/Q14 source, RLS/current-use, immutable history, custody, serving and durable recovery proofs remain required. No new broad test harness, scheduler or renewal analytics product is needed.

Use existing source/security/product diagnostics. Any confirmed unauthorized repeat, overlap, wrong current end, scope growth, duplicate effect or misleading historical-success presentation is an actionable correctness defect for the owning source/product path. A reproduced critical accessibility or unsupported cohort journey requires fixing or gating that affected path. Repeated staff grants alone are not evidence of abuse or an invented quota breach; they can inform an explicit later product review without silently changing A.

The selected direction remains A. These proposed amendments and proof outcomes await ratification through the parent's review. No canonical record, runtime feature, new policy choice or Q16 decision is made here.
