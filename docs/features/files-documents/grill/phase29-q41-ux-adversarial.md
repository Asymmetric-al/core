# Phase 29 Q41 — Independent UX and comparative adversarial review

2026-10-24, Asia/Bangkok. Conrad selected **A: named-recipient access without
compulsory full Asym signup** and requested deep adversarial review. Disposition:
**Accept with required amendments.** This note proposes the bounded complete
journey below for ratification; Q01–Q40 and twenty-five current glossary terms
remain unchanged. Only this assigned note is authored. No implementation,
account/provider change, real invitation, private document access or formal
owner/OpenSpec publication is performed.

## Conclusion and meaningful counterargument

A should provide a real authenticated native recipient context that leads
directly to a source-authorized document. It must not become anonymous viewing,
a donor-profile creation shortcut, general guest membership or another login
platform. Authentication establishes the appropriate subject/proof; the source
still authorizes this exact disclosure and every reading action.

B remains credible for recurring readers who already have suitable authenticated
contexts and established recovery. It has a smaller admission surface to support,
while leaving an otherwise permitted occasional outsider without this lightweight
route. There is no measured Asym enrollment burden, share frequency, completion
benefit, cost neutrality or universally superior proof method.

The concrete first cohort agreed with root/owner is **ordinary Private Document
Request evidence**, comprising an exact participant receipt or Q28 staff-supplied
version, with an independently authorized outbound disclosure/read purpose.
This is a proposed ordinary-source command, not a general File Manager export
power. Q28 reuse cannot launder stronger origin restrictions. A fulfilled request
may qualify through an actual continuing lawful outbound purpose, not retention
alone. Cancellation or a relevant adverse restriction denies new shares and
current affected serving as an explicit Q41 amendment. Original request
participants cannot use this new lane to bypass their ratified access/recovery
or completed-scope limits.

For this first cohort, propose one named intended recipient and one selected
exact version, a qualified reading representation, original download only where
separately expressly granted, and an actual finite end reviewed before issuance.
Use a current source-qualified end default if one exists; otherwise staff choose
within the source's qualified bounds in the same review. No universal number,
rolling renewal, follow-latest rule or hidden download grant is selected. These
are **explicit additional amendments**, not facts already decided by Q41 A.

not prove that method meets a source's stronger assurance policy. Conversely,

representation, legal identity, document acceptance or a signature.

## Exact proposed amendments

H/M/L describes impact; exposure is a qualitative prospective judgment, not an
observed incident rate. The clauses state product/source outcomes, not a required
physical schema or a new orchestration platform.

### U01 — A real first source, with distinct outward authority

**H / plausible:** any readable stored file becomes shareable, or existing
request/collection access is used to evade source restrictions.

Initially admit only a currently eligible ordinary Private Document Request
source's exact participant-received or Q28 staff-supplied evidence, under a
deliberate separately qualified outbound disclosure/read purpose for one named
recipient. Require actual current authority to create this use, not mere read,
upload, review, storage-admin, folder, staff rank or custody ownership. Preserve
all applicable origin/privacy/specialist restrictions; Q28 reuse, byte equality
or acceptance does not permit an otherwise forbidden external disclosure.
Grant administration is its own current P12 capability: body Read is neither
necessary nor sufficient. The single qualified source command may designate
the recipient without a prior Party record or a routine second approval.

Keep financial/generated, expense, Support/care, restricted/public media and
resource lanes with their actual owners; no relabeling them as ordinary. The
new source command may supply this narrow capability when formally adopted,
but a button or generic JSON permission cannot. Do not use Q41 to regrant the
original request recipient's expired/closed or excluded historical material.
Other future document-source families need their own explicit qualification.
Proof: P01/P02/P21/P24.

### U02 — Native identity without product enrollment

**H / plausible:** normal signup creates a donor/tenant role, or an isolated
guest-token path bypasses the shared authorization system.

Qualify a limited native recipient principal/session through the shared identity
owner and P12's sole authorization decision point. A durable scoped identity
record may exist; no mandatory donor/missionary/staff profile, broad membership,
fifth general role, synthetic Party or second login service follows. Preserve
the person's independently existing identities and memberships. A native user
without a product profile must not be declared unauthenticated merely to force
enrollment, and changing the general signup trigger must not damage other lanes.

Return a successfully established correct context to the intended source
document rather than a role-home dashboard. Keep the continuation server-bound,
non-authorizing and restricted to the intended flow; an arbitrary next URL must
not redirect out of the trusted application or grant access. A wrong-account
switch preserves safe context without revealing private metadata to that account.
Proof: P03/P04/P10/P23.

### U03 — Current recipient proof, accurately described

**H / plausible:** a global verified-email flag, old collection proof or a
second person using the same address is treated as the named reader.

Bind the subject, source-designated intended recipient and required assurance
to this exact share. Reuse current signed-in/recipient proof only when the
identity/source owner admits the exact mapping, freshness, audience and proof
strength. No challenge solely for ceremony, but no email-string match, tenant
membership or old successful login as a substitute for actual share rights.

Where the ordinary source explicitly permits mailbox confirmation, use the
qualified shared proof mechanism and accurately describe its limited assurance.
Do not claim MFA/AAL/phishing resistance or legal identity. Shared, delegated,
reassigned or aliased mailboxes require the actual source's designation/assurance;
staff cannot waive stronger policy because the reader lacks a full account.
Changing the approved contact requires qualified source/identity correction,
not caller-supplied retargeting. Proof/session/credential validity remains
separate from the share's actual finite permission.
Proof: P04/P05/P07/P10.

### U04 — Pin the promised document, actions and finite end

**H / plausible:** a new version changes what was shared, view becomes original
download, or proof recovery creates indefinite access.

For the first cohort, bind one exact selected immutable evidence version/use,
not an ambient latest pointer or all request files. Require a qualified reading
representation and show its actual limitations. Original download requires a
separate explicit source-admitted action; read-only adds no upload/edit/comment/
review/accept/reshare, original request history, folder or other-use access.
Copying a reference link cannot widen the audience. A later version is not
automatically selected, accepted or substituted by a correction/replay.

Require a real future finite end within the current source-approved bounds,
reviewed at issuance. Reuse a qualified default if one exists; otherwise staff
choose the end in that same flow. Before activation the source must have a
qualified finite maximum and exact timing rule, not let an unconstrained date
field invent policy. No new universal day count, rolling renewal, first-view
restart or Q05–Q20 duration inheritance. Reissue/proof/message repair cannot
move the issued end. Source restrictions may shorten actual permissible use.

A known missing, unsupported/unsafe or inaccessible reading route is not a
usable share promise. Complete qualified bounded rendition preparation before
issuance, or preserve an honest unissued preparation state. This source/custody
readiness check does not require the grant administrator to inspect the body.
An already issued share with a qualified reading route may survive a recoverable
technical read delay without resetting time; no continuous-availability promise
or automatic original/public/external-viewer fallback follows.
Proof: P06–P08/P11/P15.

### U05 — One meaningful issuance and a real entry path

**H / plausible:** staff think a grant exists when only email was queued, or
grant creation is repeated to repair a lost invitation.

Use the existing source/document review to show the safe actual intended
recipient, selected version, reading actions, finite end and external effect.
Reuse source facts instead of asking for a governance essay, duplicate fields,
approval tier or another wizard. The final act deliberately admits the share;
an invitation/proof message, prepared token, provider callback or first visit
does not itself constitute that source act.

Coherently retain the admitted terms, actor/time, current authority basis,
permanent semantic identity and required entry/handoff/recovery facts. An actual
qualified entry path must exist; a stranded grant with no capable recipient
route cannot be called complete. Known material changes before admission get
inline revalidation and preserved lawful input, not an invented new destination.
Keep grant result, invitation state, proof state and actual retrieval distinct.

Any invitation or on-demand proof message needs its own exact source/P17/P6
contract, actual recipient and minimal content. Do not relabel Q20/Q31/Q35/Q40
or silently introduce a recurring reminder/default-notice policy. Qualified
message retries/credential repairs retain the source grant and its end. If a
qualified communication is delayed or blocked after source issuance, preserve
known grant truth and actual supported recovery rather than issuing again.
Communication-only suppression is not read revocation; invalid recipient/proof
or actual source restriction still denies access. A necessary fresh challenge
cannot bypass a prohibited delivery path.
Proof: P09/P10/P15/P16/P19.

### U06 — Current access on every private door and lifecycle transition

**H / plausible:** an initial successful confirmation admits later unauthorized
metadata, ranges, cached content or restored access.

The existing scanner-safe doorway remains inert before qualified proof and
deliberate use. Link possession, automated GET, email preview, session cookie
or an opaque storage key is not a new read grant. Every protected metadata,
preview/rendition, original action if authorized, range/conditional response,
print/export, result recovery and alternate reader path applies current exact
source/recipient/action/version authority. Bound stream/read admission and
continuation under the actual source contract; no unlimited post-revocation
lease or public/direct-storage bypass. Already received bytes cannot be recalled.

As an explicit Q41 rule for this first cohort, request cancellation or an adverse
source restriction stops new share admission and current affected serving.
Fulfillment alone does not stop an independently lawful continuing outbound
purpose. Retention alone never supplies that purpose. Q33 No longer required,
later evidence correction/supersession or unrelated work changes do not
automatically retarget or revoke a pinned share; the actual current owner read
fences and continuing outbound purpose govern. Source cancellation does not
create a third-party analogue of Q34's limited original-recipient status view.

Order issue/revoke/restrict/cancel, proof completion, version/read admission and
replay through qualified source boundaries. State entered and left between
worker polls cannot resurrect a revoked/ended grant. Unknown rights fail safely
without fabricated success or permanent denial facts. Any new grant requires
an independent current source decision and cannot bypass an adverse restriction.
Proof: P11/P12/P14/P15/P21/P23.

### U07 — Recovery repairs the actual problem

**H / plausible:** inaccessible email or a wrong recipient is repaired by
silently changing identity, resending authority or extending access.

Before issuance, allow lawful edit/discard. Issued recipient/address revision,
material/actions and end are immutable. Correct a wrong recipient, changed
approved contact, wrong version or end by revoking the affected share and,
where still independently lawful, deliberately issuing a separately reviewed
new share. Prove same-person mapping through the current identity/source
contract without retargeting old grants, proofs or history. A genuinely different
recipient likewise needs a new decision. No universal Undo, silent migration of
old tokens or recall promise.

Expired proof with a still-valid share can re-establish only the required proof;
an expired/revoked/source-ended share cannot be repaired by sending another code.
A temporary proof, authorization or technical block may clear through its actual
owner repair only while the share remains live under unchanged terms and all
current gates; a failed/unknown read does not itself revoke the share. Keep a safe
wrong-account switch, bounded credential retry and capable source contact route
for inaccessible mailbox/unsupported assurance. Before authority is established,
errors cannot disclose whether a private share/person/file exists. After adequate
proof, explain the specific permitted issue and useful next step. No arbitrary
address box, public link, download-and-email workaround or powerless help link.
Proof: P05/P07/P10/P13/P14/P19.

### U08 — Stable outcomes, data and original-result replay

**H / plausible:** double-clicks or response loss create extra grants, a later
version is substituted, or privileged code bypasses source identity.

Preserve exact original source/use/version/recipient/actions/end/proof profile
and stable semantic effect identity. Reconcile a matching already committed
issuance/revocation result before treating a retry as a new act, under current
result-disclosure rights; later expiry or cancellation cannot erase history.
Changed material conflicts rather than modifying the old grant. Network retry,
credential replacement and a new message key are not new share decisions.

Use trusted same-tenant/source/actor/subject relationships, typed IDs/times and
valid transitions; qualify null/default/unique/check/reference/delete rules.
Prove effective grants/RLS old/new-state checks, upserts, views/functions/storage
and service/admin/import/worker paths. Current read permission is not write/share
authority, and allowed updates cannot retarget a record's source, person, version
or end. Provider I/O remains outside source locks; exact qualified communication
reconciliation supplies evidence without changing the source grant.
Proof: P09/P15/P16/P21/P23.

### U09 — Minimized identity, metadata and access evidence

**H / plausible:** a safe-looking landing, subject, autocomplete or audit table
reveals a protected person/case/file or retained reading history.

Minimize recipient identity records to justified native identity/source facts,
with their actual retention/erasure duties. No automatic CRM enrichment or new
general contact directory. Current discovery authorization applies before
recipient suggestions, source/file titles, thumbnails, counts, share lists,
status, history, exports and cached results. A pre-proof landing may show only
the source-qualified safe cue, not document details because the URL is valid.

Keep exact permitted access evidence: source admission, required proof, allowed/
denied retrieval and transport outcome are distinct from delivery and human
reading. No read receipt, signature or mandatory acknowledgement is invented.
Do not copy document bodies, secrets, raw token-bearing URLs or sensitive contact
facts into logs, analytics, general histories, referrers or offline state.
Preserve actual qualified transport envelopes/protected-entry carriers under
their narrow contracts; this is not a blanket prohibition on necessary carriers.
No public external viewer, tracking fetch or new document-body search corpus.
Proof: P10/P17/P18/P21/P23.

### U10 — Simple accessible staff and recipient composition

**M / probable exposure:** recipients are forced through onboarding or another
dashboard, lose context switching apps, or cannot enter the required proof.

Staff get one clear **Share with a named person** review with readable current
recipient/version/actions/end. Selecting a recipient or changing a field does
not issue, email or navigate automatically. The recipient reaches the intended
document after qualified proof, with actual access end and available actions
clear. Do not make them enter unrelated names/profile data or confirm facts
already proved by an accepted current context.

Support keyboard/AT/voice/touch, meaningful label/state/focus/error/status,
contrast, reflow/zoom, RTL, long/international names and addresses, IME and
localized end/time zone. Use one logical labeled code input supporting leading
zeros, whole-code paste/autofill and password-manager
assistance; no manual-transcription-only segmented code or inaccessible CAPTCHA
as the only recovery. Preserve a safe continuation across mobile email/browser
switching and slow/lost responses. Plain-text/images-off message content keeps
safe entry meaning without private metadata, attachments or required downloads.
Provide a clear way to end the reader's session on a shared device without
deleting their independent identity or memberships.

Use honest available/preparing/limited/unavailable/revoked/expired states only
where disclosure permits; protect current reading context on technical failure.
The document representation itself must satisfy its actual accessibility/coverage
contract, not just the surrounding control. Qualified original download may be
a separate permitted action; never silently use it as accessibility repair.
Proof: P08/P10/P19/P20.

### U11 — Bounded operation, noise and compatible rollout

**H / plausible:** code requests become mail spam, expired/old links regain
rights after restore, or limited admission breaks existing signup.

Reuse existing identity, source, custody, protected-action and communication
owners. Bound proof attempts, credential/message requests, session/credential
lifetimes, source/read/stream workload, preparation, recovery and retained
material. Resetting a code cannot erase attempt limits or become a mail-flood
tool. Choose numeric security/workload parameters through actual qualification,
not vendor examples or a founder checkbox. No new reminder/digest/noise engine.

Measure complete staff/recipient task success and recoverability, source latency
separately from message/processing latency, realistic format/network/tenant skew,
and relevant resource cost. No free-feature or physical exactly-once claim.
Provide supported operations to stop new issuance/affected reads, reconcile
original results and fix identity/recipient mistakes without routine SQL.

Roll out prospectively with native identity/signup/callback compatibility,
old-writer/read-door fences and restrictions-first restore. Preserve existing
memberships and all normal enrollment flows. No synthetic donor/tenant backfill,
historical grants or revived revoked shares; repair must retain original scope
and occurrence. Whole future Workflow/Workspace products are not prerequisites.
Proof: P03/P10/P16/P22/P23/P24.

### U12 — Explicit adoption, not a disguised further policy choice

**H / plausible:** selected no-signup intent is recorded as implemented while
its actual owner, proof, private-reading path or finite source cap is missing.

Adopt the concrete ordinary-request outbound source command, shared limited
identity context, sole P12 authorization, P17 doorway and any exact P6 messaging
contracts explicitly. Preserve the first-cohort/source exclusions, pinned exact
version, qualified rendition/separate download and reviewed finite end as the
proposed Q41 amendments. Do not represent universal periods, follow-latest,
email-notice defaults or a global MFA choice as already ratified.

At least one actual complete native source/identity/reading route, capable
recovery, finite source/proof/material limits and accountable owner must be
qualified before Live. A mock guest screen or a token that works outside P12
does not meet that gate. Trace every clause/proof through canonical source
authors, declared OpenSpec projections and later design/tasks/tests/release.
Propose the single term below if root adopts it; do not change current glossary
or infer a wider external-user role from it.
Proof: P01–P24.

## Proposed domain term

**Private Document Share**:
A source-authorized, finite permission for a named recipient to read specified
private document material for a stated purpose through explicitly permitted
actions. It is distinct from an invitation, recipient confirmation, a collection
request, retention and permission to alter or reshare the material.
_Avoid_: anyone link, file ownership, folder membership, request-only access, proof of reading

or erase stronger source-specific language. The current twenty-five terms remain
unchanged until explicit ratification.
