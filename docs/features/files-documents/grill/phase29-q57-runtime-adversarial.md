## Current primary technical research and relevant changelog

- [PostgreSQL 17 CREATE POLICY](https://www.postgresql.org/docs/17/sql-createpolicy.html) distinguishes existing-row USING and resulting-row WITH CHECK. UPDATE/ALL can inherit USING when CHECK is omitted; permissive policies OR and restrictive ones AND. MERGE/ON CONFLICT, SELECT/RETURNING and BEFORE-trigger changes need actual command-specific proof. An omitted clause is not automatically a vulnerability; a visible row is not permission to mutate arbitrary columns.
- [PostgreSQL 17 function security](https://www.postgresql.org/docs/17/sql-createfunction.html) executes a definer function with its actual owner's privileges; schema/search-path/overload and effective EXECUTE grants matter. New functions ordinarily grant PUBLIC execute unless restricted. The existing named-grant lockdown is relevant, not a universal certificate for future functions.
- [PostgreSQL 17 isolation](https://www.postgresql.org/docs/17/transaction-iso.html) permits different statement snapshots under Read Committed and rechecks predicates after waits. An atomic transaction still needs correct source/revision/authorization ordering; a mock callback or two independent SDK calls do not prove that ordering. Serializable strategies may require whole-transaction retry and do not justify a generic retry engine.
- [PostgreSQL time functions](https://www.postgresql.org/docs/17/functions-datetime.html) distinguish transaction-start time from the actual clock. Record source occurrence and check time-bounded authority at the qualified admission point after relevant waits; do not backdate to a browser click or assume that an earlier transaction timestamp establishes still-current permission.
- [Supabase sessions](https://supabase.com/docs/guides/auth/sessions) and [JWT documentation](https://supabase.com/docs/guides/auth/jwts) distinguish token verification from live session facts. Strict sign-out guarantees can require current session evidence; authorization claims are not a replacement for the P12 current source/member checks. Do not add arbitrary per-card Auth requests or a second identity store to solve that distinction.

## Exact proposed amendments

These are independent enforceable requirements for the selected answer. They define behavior and constraints without prescribing a new table family, policy engine, vendor or universal quota.

**C01 — One explicit source purpose.** Adopt contextual resource-problem reports under the exact P28 resource-publication owner for the governed missionary-reader/qualified-curator cohort. Reading, reporting, own report maintenance, handling, handling correction, privacy repair and resource publication remain distinct source actions. No role label, library read, report authorship or row visibility grants all of them. General staff-reference readership, comments, ratings, attachments, task-per-report, email, conversation and automatic resource action are outside this addition.

**C02 — Strict current new admission.** A new report binds one exact reviewed current organization/publication/version or approved external-reference basis, trusted reporter/context and a bounded nonempty plain-text note. Safe source metadata and actual report authority suffice when body/preview/download fails; successful byte delivery is not a prerequisite. Missing/unknown/denied source or target authority fails closed. A relevant publication/audience/context change before admission requires refreshed deliberate intent while preserving safe draft text; never silently retarget a report or fetch an arbitrary URL to discover its source.

**C03 — Small report lifecycle and separate privacy state.** An admitted report has Open, Handled or Withdrawn business state with a monotonic current revision or equivalent unambiguous expected-basis mechanism. Its Tenant/environment/source/organization, exact target, original reporter/context and original receipt are immutable. Text changes produce attributable successor content revisions. Handling is bound to the exact reviewed report revision and records the actual handler, time and truthful outcome. Privacy restriction/redaction/disposal is independently governed, not a fourth business state that any handler can toggle to bypass access or retention.

**C04 — Independent current report rights.** After admission, the reporter's current own-report rights may permit the latest lawfully retained text needed for an eligible Edit/Restore and a minimal source-local Your reports receipt/handling projection independently of current resource publication or byte permission. Require the verified native principal, current validated same-Tenant context and exact reporter/source-purpose relation under current P12 restrictions, applicable retention and disclosure. Ownership, past access, a receipt, a JWT or retained rows alone confer no continuing permission. Resource withdrawal/replacement is not automatically report erasure; report access never grants old resource titles, internal notes, other reporters' reports or historical bytes. Loss of context/membership or actual report-purpose restriction denies affected access; a temporary failed evaluation does not falsely declare the report permanently destroyed.

**C05 — Own text correction, withdrawal and restoration.** An authorized reporter may Edit the current eligible Open report's text or Withdraw it through its expected current basis; these actions cannot change the target or original actor/time. Ordinary withdrawal stops that report's open handling but is not erasure or recall of earlier read copies and does not cancel independently mandatory safety action. A deliberate Restore of the current Withdrawn report is a new attributed transition to Open using the latest lawfully retained body, exact immutable target, current report-restore/disclosure authority and a capable handling route. It neither replays the original submit nor rewinds newer content/handling nor overrides redaction, disposal or prohibited source use. The actor must be able to lawfully review/authorize the proposed retained content; unknown hidden text is not silently treated as empty or safe to restore. A different observed version or independently new concern uses a new report, not target editing.

**C06 — Curator handling and permanent correction.** A currently qualified curator may Handle the exact Open report revision with a truthful, appropriately disclosed outcome. Handled does not imply Fixed, Reviewed or published. Reopen of current Handled state is a deliberate current-authorized new Open transition, preserving the actual earlier handling fact. An authorized correction of a Handled outcome is a new attributed correction of that exact report/handling basis; no operator impersonates the original handler or rewrites their historical action. Current handling eligibility includes the retained content's current audience/privacy restrictions. Curators cannot rewrite the reporter's words as their own ordinary edit or restore an author-withdrawn report merely by using handling permission. Separate scoped operator privacy repair remains available.

**C07 — Durable handling without a queue platform.** At new admission and Restore, qualify the source-owned destination/stewardship so a durably received report cannot be stranded without a capable handling route. This does not require a particular person to be online, immediate human reading, a new global inbox or an email delivery. Record the actual handling ownership/reference and mandatory history with the report/result. Departure or loss of individual curator scope must have a supported transfer/takeover under current source authority; ordinary staff do not automatically inherit the report. Source-local management/list projections may recover from technical delay without claiming the source admission failed or asking the reporter to submit again.

**C08 — Original operation identity before new-act logic.** Bind a stable source-recognized submit/mutation intent to immutable actor/Tenant/purpose/target/payload and expected relevant basis. Matching committed replay recovers its original outcome before evaluating new-action eligibility, state or no-op; current result disclosure still governs returned fields. Changed meaning under the same operation identity conflicts. Different transport correlation keys, callbacks or response loss cannot duplicate one admitted intent. A deliberately new report is not permanently prohibited by equal text, reporter/resource identity or a previous Handled outcome. The UI must reconcile an unknown original attempt before presenting a fresh Send as a retry. An original receipt is labeled as the original outcome; a separately authorized current projection may differ, and a late replay response cannot overwrite newer report state. Equal-content transport recovery and a new business act are different.

**C09 — Exact ordering, no-op and truthful time.** Qualify coherent transaction/source fences for new submission, own Edit/Withdraw/Restore, Handle/Reopen/outcome correction, privacy actions, context/revocation, publication replacement/withdrawal and relevant handling ownership. Fresh commands check the reviewed relevant state/content/context revision; Open→Handled→Open or Withdrawn→Open does not make an old expected revision current again. After original replay handling, a fresh current canonical unchanged edit is a no-op: no new content/state revision, false handling, timestamp/history reset or duplicate work; required security auditing is independent. Do not invalidate for unrelated global content edits. Required source facts, current state, immutable references, history and authoritative command result commit coherently; audit/logger construction and multiple SDK calls are not assumed atomic. Sample trusted actual source time and check expiry after relevant waits, without pretending to know a future commit timestamp.

**C10 — Minimum structural data invariants.** Enforce non-null stable Tenant/environment/source/report identity, tenant-consistent exact target/report/revision/handling relationships, immutable original attribution, valid business states, positive monotonic revisions, finite validated text, valid handling-to-content references and scoped operation uniqueness. Prevent reparenting, scope widening, replacing actor/receipt, dangling handling history and lost required outcomes through any writer. A nullable field must represent a proved legitimate absence rather than unknown authority. Immutable relationships need constraints or equally effective checked command/database enforcement; a row policy alone does not make columns immutable. No globally unique visible name or content digest is a report identity or permitted existence oracle.

**C11 — One PDP and unified context.** All actions and read projections use P12's single fine-grained PDP and the source PEP with the current validated Tenant Authorization Context appropriate to the principal class. For these member actions, the current Active Tenant Assignment and its actual source/report powers must qualify; selected-Tenant/profile/default/demo shortcuts are forbidden. Qualify application/database Tenant source agreement, context unforgeability, missing/mismatched context denial and transaction/pool cleanup. Database RLS remains the prescribed coarse Tenant defense, not a second per-row membership/capability engine. R6's ≤1 governance SELECT plus ≤1 ledger UPDATE is its logical governed-read bound with the existing physical-sharding exception; it does not mean every business action contains only one query. No Party, donor or staff membership is fabricated to fit report routing.

**C12 — Effective native roles and every door.** Inspect and test actual schema/table/column/sequence/function grants, PUBLIC and named/default/inherited EXECUTE, function overload/owner/search_path, invoker/definer views, ENABLE/FORCE and superuser/BYPASS composition. Exercise actual SELECT/INSERT/UPDATE/DELETE, UPSERT/ON CONFLICT, MERGE, SELECT/RETURNING and BEFORE/AFTER trigger-transformed writes against old and resulting states. Browser Data API/GraphQL, collections, route/action handlers, RPC/views, service/NHI/operator jobs, imports/backfills, exports, caches and any storage-linked reader must preserve the same source contract or be closed. Broad Support/asset policies and role checks cannot be inherited merely by adding a narrow policy. Omitted WITH CHECK may inherit USING; prove effective behavior instead of asserting a text-pattern myth.

**C13 — Protected content and capable privacy repair.** Render report/outcome text as bounded inert plain text; no HTML execution, automatic link fetching, quoted file body, attachment, remote preview or new body-search corpus. Classification/current permitted handling audience applies to text, reporter details, target metadata, counts, search/sort, history and response—not just the main row. Minimize reporter-return fields and withhold protected historical titles/reasons/internal notes. Do not send report bodies/private URLs/tokens/queries to telemetry, analytics, session replay, shared caches or broad audit logs. Scoped source/privacy operators must be able to restrict or redact mistaken sensitive text and required historic copies through governed correction/disposition while retaining only permitted minimal attributable facts. Ordinary curators cannot impersonate the reporter; append-only audit does not require forbidden bodies to remain generally readable. Legal/security holds, actual deletion rights and report-purpose access are separate; preserve independently qualified protected carriers under their own contracts rather than logging them.

**C14 — Bounded retention, replay and restore.** Set finite actual classification-owned readable body/history/receipt retention and minimal uniqueness/replay evidence before activation, without borrowing Q51/Q48 or preview durations. Retain adequate minimal opaque outcome/tombstone proof or reject unverifiable stale intent; no new-key shortcut silently recreates the old act. Restore/backfill/reindex must replay later restrictions, state revisions and erasure/disposition fences before disclosure. A report record cannot preserve or revive resource byte permission. Required history is not accidentally deleted by member/profile/resource cascades; actual approved disposition and protected evidence policy govern.

**C15 — Honest UI and existing-effect independence.** Keep one concise note and explicit Send, normal reading independent, and input local until deliberate submission; typing, blur, Enter during IME, navigation and transient edits cause no unintended send/handling. Preserve safe draft text on failures and clear unsafe context on tenant/actor switch; make no offline durable-save promise. Show Received only after known admission and unknown outcomes as recoverable unknowns. Your reports must offer the permitted return path even when a resource is withdrawn, with Handled distinct from Fixed and minimal current disclosure. New reports/edits/handling do not make Q55 review/date facts, publish/withdraw resources, create task/notification/survey/reader metrics or close other reports. Independently qualified existing source effects retain their actual contracts; no blanket communications-Off policy is created.

**C16 — Finite native performance and cost.** Before activation qualify finite note/outcome/payload sizes, per-principal/Tenant admission and active-operation bounds, list/history page size, stable unique keyset continuation, query/lock/wait/retry/result-retention bounds and aggregate tested workload. Unknown legacy report/resource provenance is not guessed into an admitted report; migrations and old/new writers must preserve attribution/history/privacy. If old software cannot represent the accepted state, use a safe forward correction rather than destructive rollback. Operators need actual scoped tools for orphan handling, privacy mistakes, contradictory outcomes and restore repair; routine raw SQL is not the permanent product path.

**C18 — Traceability and evidence.** Carry the selected exact report/handling contracts into P28 and consumed P12/P29/operational projections, preserving prior ordinary-request and Q55/Q56 semantics. Qualify the actual native producer, real roles, source-currentness/races, all-door disclosure, retention/restore and representative reader/curator mobile/AT tasks before activation.
