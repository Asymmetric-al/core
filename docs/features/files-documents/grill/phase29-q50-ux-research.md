# Phase 29 Q50 — Ordinary evidence display-name audience

2026-10-25, Asia/Bangkok. Independent UX and primary-product research. Q01–Q49 are fully ratified; Q50 is an unselected question. This note recommends an audience contract for an already-required identity-preserving rename capability. It does not ratify an answer, create an ADR, change canonical terms, or prove native implementation.

## Recommendation and the meaningful fork

**Recommend A: one optional descriptive display name for the exact ordinary evidence use, shared among currently authorized staff.** Keep the recipient's existing source-approved representation separate. This is not a personal alias and not a name on a universal asset shared across every use of the same bytes.

**B is credible:** one current display name shown both to authorized staff and the currently authorized participant can make support conversations and recipient navigation easier. Under B, changing that name is deliberately participant-facing content, with actual disclosure authority and clear audience guidance. It cannot be an internal label that happens to escape through a generic serializer.

The choice matters because the visible words can carry internal context or change what a participant recognizes. It is not a choice about storage keys, whether rename exists, whether staff can change bytes, or whether metadata always belongs to everyone who can read the file. Founder §7–§8 already require stable identity, protected names and useful discovery. Q42 fixes the ordinary exact contribution/use as the organization target. A universal cross-use rename would reopen settled boundaries.

| Option                                        | Best practical case                                                                                                            | Actual cost                                                                                                                                                                                                      |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A — Shared authorized-staff display name      | Staff can organize an unhelpfully named contribution using local business context without changing its recipient presentation. | Two naming contexts remain. Staff need a compact permitted original reference and item context to identify the same contribution with the recipient.                                                             |
| B — Same current name for staff and recipient | Staff curate a clearer name that both sides can use, reducing conversational name mismatch and improving recipient navigation. | Each rename also changes external presentation. Staff must know that audience, and current source permission must authorize the value; earlier receipt facts and already delivered material cannot be rewritten. |

Neither requires a name on every file. Both retain exact source/use/version identity, authoritative type/status, original receipt provenance under its owner, independent uses, and current permissions. B does not mean public visibility, participant editing, new read rights or a rename email. A does not mean that every staff member may view or edit every name.

The recommendation is a product judgment: staff organization is the narrower established need, while the relative importance of shared participant vocabulary is not measured. If the founder's intended outcome is specifically to curate names for recipients, B is a reasonable answer. Do not add a per-file audience toggle, a second editable recipient title, personal aliases or a naming engine merely to defer this decision.

## Evidence limits and recommendation test

A's weakest assumption is that staff can reliably identify a contribution with the recipient through the permitted original reference and item context. Test that composed support journey; if persistent confusion is demonstrated or participant-side naming is the actual intended outcome, B deserves selection. B's strongest value is not merely cosmetic consistency: a readable common name can help both sides recognize the same work. Its disclosure responsibility is also real and should be visible before save rather than delegated to a warning after publication.

Neither comparator documentation nor repository source demonstrates actual ministry frequency, reduced errors, satisfaction, latency, current native accessibility, database isolation or operating cost. No provider/private-account tests, uploads, messages, UI implementation, SQL changes, commits or external publication were performed. No new glossary term is presently necessary to ask the audience question.
