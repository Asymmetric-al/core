### Primary technical facts

PostgreSQL17 documents old-row `USING` and proposed-row `WITH CHECK`; an omitted check can inherit the using expression. UPDATE/UPSERT also interact with SELECT policies. Multiple permissive policies combine by OR and restrictive policies by AND; owners/BYPASSRLS and some privileged paths require separate treatment. Integrity checks can leak existence through constraint failures. [CREATE POLICY](https://www.postgresql.org/docs/17/sql-createpolicy.html), [row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html).

Foreign keys/unique constraints, including deliberate NULL semantics, should enforce relationships expressible that way. A CHECK referencing changing other rows is not a valid durable cross-row invariant. [PostgreSQL constraints](https://www.postgresql.org/docs/17/ddl-constraints.html).

Supabase distinguishes grants from RLS, warns that service role bypasses RLS, and documents invoker-security views. Its performance guidance supports indexed authorization/filter columns and measured representative queries. These facts guide native proof; they do not certify Q42 or make new queries free. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [view security](https://supabase.com/docs/guides/database/views).

## Required amendments

### C01 — Exact first source, namespace and side-effect boundary

Admit only the ordinary Private Document Request source's actual stable evidence-entry reference: one durably admitted participant file contribution or Q28 staff-supplied use for a specific request/item. Qualify a concrete Tenant/environment ordinary staff-organization namespace and current organization powers before activation; its label is not a CRM organization Party, profile or tenant replacement. Preserve source-owned exact/current/version/history interpretation and separate identities for distinct uses of equal bytes.

One eligible entry has one home folder or Unfiled. A source/list/search/view appearance is not another placement. No shortcut, equal owning parents or additional folder-reference feature is admitted. Filing changes no evidence membership, receipt, acceptance, requirement, request outcome, participant access, Q41 share terms, source ownership, byte location, provider copy, publication, retention or disposition. Foldering requires organization authority, not automatically body-read permission, where the actual source permits metadata-only filing.

### C02 — Concrete new-entry and correction behavior

An independent new contribution/use, including Q28 reuse of the same bytes, begins Unfiled with no inherited labels. A status/review/instruction change on the same source entry preserves its existing home and labels subject to current restrictions; do not create a new entry from every review transition or adopt a new file by moving one.

For an exact Q03 correction, explicitly permit a **single admission-time copy of the predecessor's home only** when the source proves same Tenant/environment/request/item, the declared exact correction relationship, current source-maintenance authority, compatible current classification/organization policy and a valid destination. No labels, approval, sharing/history rights or other metadata are copied. This authority belongs to the trusted source operation, not to the participant's filing permissions.

Determine that copy in the source's actual ordered correction admission, with an effective fence against predecessor home change, destination removal and relevant policy changes. If the copy basis is unknown, incompatible, unavailable or conflicts, the lawful correction is admitted Unfiled. Persist the copy-or-Unfiled outcome with the source entry or equivalent source-owned recovery fact. An optional organization outage cannot block lawful source receipt or leave a hidden deferred instruction to copy a later then-current home. Later moves/labels never propagate between occurrences. Receipt replay reconciles the original outcome; it does not rerun initialization. Required Q03 custody/authority/history/receipt conditions still apply independently.

### C03 — Current source powers and confidential organization metadata

Use server-authenticated actor/context and actual current source organization capability for entry moves; separately qualify folder/label/shared-view management and any source-maintenance copy. Staff rank, uploader, reviewer assignment, Party linkage, folder visibility, retained bytes or a valid Q41 read share alone grants none of these powers.

Authorize each disclosed folder label, breadcrumb, entry title, label association, view definition, suggestion, count, ordering key and error before serialization. A container does not reveal protected targets or other uses. Shared view creation does not share matching records; results use the viewer's current source permissions. Deny unknown authority without fabricating a global absence. Restriction-first denies affected new writes and subsequent disclosures; a valid earlier filing fact can remain retained without granting current visibility. Issuer/author departure alone does not delete otherwise lawful shared organization.

### C04 — Database relationships, immutable attribution and one home

Native schema must identify a single ordinary organization scope and source-entry key, with immutable tenant/environment/source/request/item/use attribution. Structurally enforce one current placement per entry; NULL-backed Unfiled or a proven equivalent must not allow duplicate “unfiled” rows. Same-scope entry→placement→folder and folder→parent relationships must be enforced with effective composite keys/foreign keys or an equivalently proved native constraint, not unrelated UUID foreign keys or browser predicates alone.

Folders have stable opaque IDs and one same-scope parent. Enforce normalized sibling/root label collision rules, no self-parent/cycles and the qualified depth bound under concurrency; ordinary NULL uniqueness must not allow duplicate root names. Protect immutable attribution on UPDATE, UPSERT, trigger/service/import paths and restore. Cascades must never delete source uses/bytes/history or silently rehome them. Do not use a CHECK that consults mutable rows as the only cross-row safeguard. This clause specifies invariants, not a mandatory new generic schema/engine.

### C05 — Effective grants, RLS and privileged doors

Inventory actual schema/default grants, API exposure, roles, column grants, all applicable policies, functions, views, triggers and direct writers. For each SELECT/INSERT/UPDATE/UPSERT/DELETE path prove old-row visibility and permitted proposed state; test composed permissive/restrictive policies and SELECT requirements. Missing literal WITH CHECK is not by itself a finding: evaluate inherited behavior and the complete effective policy. Explicitly test ownership/source/tenant reparent attempts even when both old and new tenants are accessible to the actor.

A service-role API, SECURITY DEFINER function, owner/BYPASSRLS connection, Payload Local API and privileged worker each need their actual trusted command boundary and source predicates; do not call them RLS-protected merely because a table has RLS. Restrict EXECUTE, untrusted search paths and direct raw mutations; qualify view security, REST/GraphQL, browser collections, RPCs, jobs, migration/backfill and trigger-initiated writes. Same server command semantics must hold through every exposed door. Safe errors must not turn uniqueness/FK conflicts into hidden-target enumeration.

### C06 — Coherent commands, ordering and durable replay

Create/rename/reparent folder, move entry, label/view edits and removal bind exact actor/scope/target, expected relevant state and deliberate intent. A successful command coherently commits the complete authorized organization mutation, required safe history and durable semantic result. No partial successful placement with missing required history, nor success inferred from an optimistic list or HTTP timeout.

Reconcile a matching committed semantic operation **before new-command eligibility/no-op checks**, under current result-disclosure rules. The original receipt cannot reapply a move after later moves, correction, deletion or permission loss. Changed payload under the same identity conflicts; new deliberate work has new identity/current validation. Retain enough owner-governed opaque uniqueness/result evidence for supported retry/restore, distinct from finite readable history. A same-current-state deliberate no-op creates no artificial source business revision.

Order relevant placement/folder/source policy writes with short native locks/CAS or proved equivalent and deterministic lock ordering; handle deadlock/serialization retries as retries of that exact operation. Revalidate the authoritative relevant basis rather than stale UI. Coordinate restriction/correction/removal without a global document read lock, provider call inside a transaction or blanket invalidation of unaffected source work.

### C07 — Empty-only folder removal and safe correction races

Initial **Remove folder** deletes only the exact authoritatively empty folder: no direct entry placements and no child folders. Staff first deliberately move entries to another eligible folder/Unfiled and reparent child folders through their own qualified commands. No automatic rehome, recursive delete, source unlink, byte purge or provider-folder removal is bundled into removal.

Visible zero, filtered current rows, missing historical-read rights or a failed query do not prove emptiness. Inspect actual organizational membership under the qualified maintenance boundary, without leaking hidden identities/counts to an unauthorized caller. Retained historical/withdrawn entry placements count until their own lawful organization change removes them.

The emptiness decision and removal fence must serialize with entry moves/correction home copies/child insertions. Copy or move first makes the folder nonempty so removal cannot win as empty; removal first prevents new references and makes the optional correction initialize Unfiled. An unsupported/unknown basis blocks removal safely, not the independent source receipt. IDs are never reused to turn a stale destination into a different folder.

### C08 — Finite all-or-none Move batches

For the initial bounded bulk Move within one qualified namespace, admit a finite exact set of unique entry identities, expected placement/source bases and one reviewed destination. Freeze the authorized selection; distinguish selected rows from “all matching.” Reject duplicates, foreign-scope entries, unsupported/over-limit or incomplete selection before commitment. Do not silently replace it with the current result of a view.

Recheck every member and destination at the transaction boundary. Commit all selected moves and required receipts/history or none. A valid entry already at the destination can be an explicitly recorded unchanged member under the same semantics. Show committed/unchanged or blocked/conflicting/not-committed accurately; an unknown commit requires reconciliation, not a promise that nothing happened. Never retry a failed batch by silently dropping blocked members or adding newly matching rows. A deliberate revised selection is new work. Folder removal remains a separate action. No broad export/deletion automation is added.

### C09 — Bounded labels and saved definitions, not authority snapshots

Use source-qualified simple organization labels and allowlisted saved view definitions over Q38-approved metadata/source context. Labels never encode authoritative Accepted, Required, Reviewed or access/retention state; actual status remains source-owned. Do not use arbitrary JSON paths, executable predicates, freeform schema definitions, body extraction, previews or AI ranking to evade Q38.

Bind personal/shared definitions to exact owner/scope and current management/disclosure powers; viewer-result authorization stays independent. Concurrent edits use expected definition state; exact replay cannot overwrite a newer definition. Changing/deleting a view or label changes only organization metadata/association as explicitly qualified, never evidence or home placement. Define practical deletion/conflict handling without treating a view's empty result as no underlying evidence. This is a small definition capability using qualified shared patterns, not a requirement to create a generic view platform.

### C10 — Usable source work, truthful read models and caches

New receipt, review, lawful source access and independent Q41 sharing must remain usable when optional folder projection or UI is delayed. Authoritative Unfiled is different from an unavailable/unknown placement lookup. Show refresh/retry/reconcile with retained context; do not relabel unknown metadata as Unfiled or complete empty output. If the source durably initialized Unfiled, that fact is not a failed projection awaiting automatic home copy.

Q38 coverage/source-version/current-access rules apply to folder-filtered search, counts, breadcrumbs, labels and saved views. Cache keys and invalidation must include actual scope/view/source authorization dependencies; session or tenant changes cannot reuse protected results. Current server mutation checks remain necessary even with optimistic UI. Recheck read-return authorization at the actual serving boundary; no global read lock or promise to recall information already lawfully displayed.

### C11 — Small finite implementation and honest operations

Set explicit measured launch limits for folder depth/count, label/view definition size/count, page size, ancestor traversal, exact batch size, transaction duration/lock retries and safe history/receipt retention before activation. Use the existing stack and indexed scope/entry/folder/source authorization access paths; avoid full-library/tree loading and per-result remote authorization/provider calls. Costs are bounded by real workload, not zero because metadata is small or Postgres already exists. No new storage vendor, copies, extraction, scheduler, distributed transaction or tenant-wide workflow engine is needed merely for filing.

Record safe operation identity/actor/source scope, expected/resulting organizational state, timing, success/unchanged/conflict/blocked/unknown outcomes and recovery correlation. Do not log private filenames/labels/view predicates/bodies, raw keys or hidden record sets by default. Record correction home-copy versus Unfiled without exposing its confidential reason to the participant. Existing evidence/review/mail statuses remain separate; no new notice or automatic approval is created.

### C12 — Prospective migration, affected-path activation and restore

Qualify one concrete ordinary source cohort, effective native schema/role boundary and accessible end-to-end filing journey before exposing it. Existing eligible entries start Unfiled unless an independently reviewed deterministic source-backed migration says otherwise; provider paths, filenames/digests, prior uploader folders and guessed source relationships cannot assign homes. Do not fabricate missing source entries. Preserve P23 Media/Page/Article folders and their contracts.

Deploy additively with constraints/access closed before any new writer is enabled. Census and fence old writers/readers/importers that could bypass single-home/source/currentness rules; handle concurrent backfill and new admission without overwriting deliberate moves. Gate only affected capability paths; independent source work remains usable. Rollback disables incompatible organization writes without dropping receipts/history/placements or restoring unsafe access. Restore must reestablish current source denials and identity/uniqueness before serving; stale snapshots must not revive deleted folders, old move effects or expired/revoked Q41 shares. Use supported source repair, not unreviewed direct SQL.
