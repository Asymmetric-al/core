# Phase 29 Q39 — UX and comparative adversarial review

2026-10-23, Asia/Bangkok. Conrad selected **A — optional reusable ordinary item
templates for independent new request drafts**. Q01–Q38 and twenty-four glossary
definitions remain ratified. This review proposes the complete safeguards and
one possible new term for later ratification; selection is not implementation,
formal owner/OpenSpec publication or activation. Only this assigned note is edited.

## Conclusion

**Accept A with required amendments.** Keep the everyday experience small:
**Start from scratch / Use template → review and adapt an independent draft →
normal qualified request issuance**. An eligible template saves repeated item
assembly; it must not carry prior-person data, portable authority or live links
that later change other requests.

The material hazards are concrete: sensitive facts inside otherwise allowed
instruction fields; half-edited shared content becoming reusable; overwriting
staff draft edits; applying a silently newer template; duplicate or stale copies
after a lost response; template retirement being mistaken for request cancellation;
and reuse being treated as readiness to issue. These can be resolved by the
ordinary source's bounded save/copy/retire actions and actual current issuance
checks, without a general workflow, schema, approval or version-management engine.

The strongest B remains individual contextual authoring without a new template
catalog. It has less upkeep where requests are infrequent or bespoke. A's value
depends on recurring similar ordinary work; no Asym frequency, time saving,
error reduction or vendor-account test establishes those benefits here. Under A,
ad-hoc work must remain quick and templates optional. Do not request an item
merely because a familiar template contains it.

## Exact amendments

H = high impact; M = medium impact. Likelihood is qualitative if the failure is
introduced, not a measured incident rate. P references are future proof duties.

### U01 — A bounded source object, optional use

**H / plausible scope expansion; M / probable friction if compulsory.** The
ordinary request source owns a reusable set of supported ordinary item definitions,
not a clone of a request or an executable form/workflow. Restrict it to actual
eligible fields and item types; do not accept arbitrary JSON, schema, scripts,
variables, automatic scheduling, attachments or specialist policy because an
editor can store them. Existing independently qualified instruction/reference
handling remains governed by its source, not new fetching or attachment powers.

Start from scratch stays immediately usable. Preserve current qualified defaults
through their own owners; template use adds neither extra approval nor manual
reentry of information the source already knows. P17 email templates, P23 pages,
P34 workflow publications and GEN-06 remain different contracts. **P01, P02, P20.**

### U02 — Distinct current powers and explicit reusable sharing

**H / plausible.** Discovery/read, use, create/edit/retire, sharing and request
draft/issuance/review are separate current source capabilities. Generic admin,
reviewer, uploader, creator, tenant membership or known template ID is not enough.
The source resolves actual tenant/context and permitted reusable audience; no
new parallel permission engine or implicit all-staff catalog is created.

When saving reusable content, make the effective scope clear in ordinary language.
Using a template cannot disclose other source uses or give the maintainer the
recipient's private request/evidence. A person who can prepare a draft may still
lack issuance power. **P03, P04, P17.**

### U03 — Definitions only, including deliberate prose review

**H / plausible.** Save as template selects the actual reusable definition fields
and shows the saved name/content and effective audience. Copy no recipient/source
record, evidence, response, acceptance, prior review, clarification history,
participant assertion, access/proof/credential, due/access clock or communication
occurrence. A closed field allowlist is necessary but not sufficient: instructions
can contain Nora's name, case facts, example answers or identifying locations.
Staff must be able to remove/generalize such material deliberately before making
it reusable; no AI/classifier or generic sanitizer can certify contextual privacy.

No compulsory essay, second approver or always-on warning ritual is needed. A
clear reusable-content editor and meaningful Save are sufficient where current
source policy permits. Protected past data must not be made reusable by renaming
it instructions. **P02, P04, P05, P17.**

### U04 — One coherent Save, then exact selected use

**H / plausible.** Separate an editor's working changes from the reusable basis
offered to another staff member. One deliberate **Save template** commits a
validated usable nonempty ordinary set and attributable content basis. Private
working autosave may protect input but must not quietly expose half-written shared
content. No additional Publish, approval stage or workflow is required.

Preview/use binds the exact selected saved definition basis and actual target
draft. Material template change, retirement or lost permission before a new
copy is admitted produces a truthful current result/conflict, preserving lawful
work; never substitute latest content or mix revisions. Copy-first yields an
independent draft. The recorded basis supports attribution, not an unlimited
historical-template-body archive or permanent read entitlement. **P06, P07, P08.**

### U05 — Apply only to an actually unissued new-request draft

**H / plausible.** Use a template only for a genuinely never-issued request draft
through current ordinary authoring rights. An issued, fulfilled, canceled or
unknown-issuance request is not made eligible by a UI Draft label. Application
creates independent item identities/content and no source demand, task, grant,
clock, notification, acceptance or fulfillment hold. Current Q25 readiness is
required at actual issuance, not prematurely as a condition of lawful preparation.

The participant need not be online, enrolled, acknowledged or already proven
merely for staff to prepare a draft. Actual protected issuance/use still obeys
Q01–Q19 and the source's current recipient/purpose/access/review rules. A template
contains no portable reviewer-ready flag. **P09, P10, P11.**

### U06 — Preserve staff input with a concrete small application flow

**H / plausible loss; M / probable confusion.** Prefer choosing a starter before
entering items. If the existing new draft already has lawful work, preserve it;
show what applying will do and let staff keep their work or deliberately make a
reviewable, correctable change. No silent replacement, automatic similarity merge,
unexplained dropped fields or extra items from a double click. Do not add a generic
merge engine or a mandatory dialog for every empty-draft use.

Applying a set must leave a coherent known result or no acknowledged successful
copy. If it cannot complete, retain lawful staff input and a capable retry/edit
path. Template-loaded values remain editable under current ordinary draft rules;
they are not mandatory specialist requirements or a reason to ask for unnecessary
documents. **P07, P09, P12, P18.**

### U07 — Copies stay independent; current restrictions still apply

**H / plausible.** Editing a draft never edits its source template. Later template
edits or ordinary retirement never rewrite/delete already-copied drafts or issued
requests, their item/receipt/instruction history, evidence, acceptance or access.
A copied draft does not need a permanently active template to exist or be issued;
its own current content/source authority must qualify.

Distinguish ordinary template availability from independent privacy/safety/source
restrictions. A real restrictive rule may govern retained content or future
issuance even after copying; independence is not a grandfathered entitlement.
Do not automatically refresh a draft from a new template version or apply Q36/Q37
through catalog edits. Later issued changes use their actual source command and
history. **P08, P10, P13, P14.**

### U08 — Retire future use and correct mistakes at the actual stage

**H / plausible irreversible wrong effect; M / plausible upkeep burden.** Provide
a simple **Retire template** operation that stops future selection/application
under the source's availability rules while retaining required attribution and
independently lawful copies. Explain that it does not cancel existing requests.
Retirement-first blocks a stale new use; committed-copy-first preserves that
copy, subject to current independent restrictions.

Before Save/apply, staff may correct/discard lawful working changes. After a
mistaken template edit, a current authorized corrective Save creates a new
coherent basis; it does not roll back already-copied work. A mistaken retirement
has a capable current make-available route over still-lawful content with current
rights, not an unconditional restore of a past permission snapshot. After an
incorrect draft application, ordinary current draft editing/correction is the
remedy; after issuance use the actually eligible Q33/Q34/Q36/Q37/source remedy.
No universal Undo, hidden reopen, replacement receipt or recall is promised.
Making a template available again establishes current availability; it does not
automatically revive a stopped or uncommitted application against its retired
basis. A matching committed effect still reconciles first under current result
disclosure, without applying again.
**P08, P13, P14, P15.**

### U09 — Original result recovery before new-effect eligibility

**H / plausible.** Save/apply/retire retry identities bind the actual actor/context,
operation, target and reviewed material. Recover a matching committed original
effect under current result-disclosure authority before evaluating whether a
new save/copy/retire would now be allowed. A request may have since issued, a
template retired or the draft edited; the retry must not copy again, overwrite
newer work, report a different latest result, or claim the original never happened.

Changed material is new/conflicting intent, not replay. Unknown commitment is
reconciled rather than guessed to be failure; known source commit survives
optional list/render/audit-projection delay where the required audit is already
admitted. Required source state, exact copy/basis and durable follow-through are
coherent. No dependence on a short transport-key lifetime or new provider call is
introduced. **P07, P08, P12, P16.**

### U10 — Private content and existing search boundary

**H / plausible.** Template title, summary, instructions, selected-item preview,
history, use associations and query text can be sensitive. Current tenant/source
authorization applies before lists, counts, suggestions, reads, previews,
exports and result recovery. Retention/provenance is not permission to show old
bodies. Safe display of an unavailable template must not reveal its hidden text
or existence, and preserve independently lawful draft content when that is allowed.

Q38 remains metadata-only for the general File Manager. Reading a qualified
template in its authoring context does not grant general body indexing. Do not
fetch external links, execute rich-text content or expose source secrets in
URLs/logs/analytics/cache. Apply current privacy/retention/disposition to reusable
and working copies without inventing a permanent scratch or history archive.
**P03, P04, P05, P17, P20.**

### U11 — Accessible, low-friction and international composition

**M / probable without actual proof.** Use existing base-maia/Base UI and ordinary
request authoring. **Use template**, **Start from scratch**, **Save template**,
**Retire template** and the actual final issuance action need distinct visible
and programmatic names. Show a useful named item list and relevant source context;
participants should not choose templates or learn catalog terminology.

Preserve lawful input, focus and return context across selection, validation,
retry and permission changes. Expose meaningful saved/applied/retired/conflict/
unknown statuses without focus theft or false success. Support keyboard/AT/voice,
touch/zoom/reflow, long text, RTL, Unicode and IME. If item reordering is offered,
provide keyboard operation and a non-drag pointer alternative; keyboard support
alone is insufficient for the pointer criterion. No mandatory download, popup
chain, extra confirmation, second approver or full-account setup is warranted.
**P18, P19, P20.**

### U12 — Proportionate operations, rollout and proof

**H / plausible stale authority; M / plausible resource growth.** Reuse compatible
source/API/editor mechanisms with bounded item/content/catalog/page/concurrency
and recovery workloads. Qualify native relational/effective-role/alternate-path
behavior, not a JSON-copy demo. Old readers/writers/imports/restore cannot bless
unknown provenance, widen sharing, resurrect retired/restricted material or turn
an old source draft into a new template automatically.

Operators need safe current recovery/containment without routine manual SQL or
an unlimited template-analysis platform. Record meaningful minimized attribution,
coherent basis and known outcomes, not private prose in telemetry. No numeric
capacity, savings or zero-provider-cost claim is invented. Existing source work
survives optional catalog/projection failure. The prior Q38 body-search cost
condition is not a new universal zero-cost requirement for templates. **P20–P22.**
