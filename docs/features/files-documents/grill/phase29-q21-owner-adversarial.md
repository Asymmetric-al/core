## Corrected meaning

For the ordinary native request's file-evidence path, require a deliberate, lawfully admitted staff decision on the exact current requested item evidence before that evidence counts toward satisfying the item. Staff acceptance is **necessary, not a bypass or a sufficient condition for every downstream outcome**: all applicable current source requirements, technical qualification and restrictions still govern. The item may involve several supporting members. Preserve existing authorized non-file/waived/not-required source outcomes and specialist policies.

Record acceptance as a source-owned decision with exact evidence/requirement basis and trusted approving actor. It is not a generic file flag, preview success, role label, task checkbox, AI judgment or a global approval attached to matching bytes. Keep historical acceptance distinct from its current applicability. Reuse a proved existing exact acceptance where the current source legitimately recognizes it; do not demand a redundant click or transfer approval to different evidence, requirements or uses.

Q21 chooses no collection-only profile, review routing/pool, bulk acceptance, extra approver, negative-outcome taxonomy, final whole-request Complete action, reminder or acceptance email. Source fulfillment and the ratified recipient clocks remain separate. Use existing source/P12/custody/tasks/communications and shared UI mechanisms, not a generic review engine.

The strongest alternative is the previously described explicit upfront collection-only profile with honest collected-not-reviewed meaning. It can remove ceremonial review where collection alone is sufficient, but adds distinct source meaning and earlier correction/fulfillment consequences. It is not selected and cannot be a fallback for backlog, missing reviewer, renderer failure or an inaccessible file. Actual Asym workload evidence remains absent.

## Key consequences and counterexamples

- **Necessary, not sufficient:** an authorized staff click cannot turn quarantined evidence into eligible evidence, waive an unprovided required member or validate a signature/financial fact. Conversely, staff acceptance is not an artificial extra step for an already-authorized non-file/waived route.
- **Partial versus complete evidence:** if the item needs two files, accepting the shown one is not acceptance of a hidden/missing sibling. Source requirements may legitimately change the required set through their own commands; this decision provides no waiver editor or caller-selected shortcut.
- **Rendition limitations matter:** a DOCX view omits comments/revision details; an XLSX view has saved values rather than recalculation. A review requiring information outside that qualified coverage cannot infer that omitted material is absent. The source needs a permitted adequate inspection path, not an automatic download or another vendor upload.
- **No duplicate ceremony:** a retry of a proved current acceptance returns that outcome. Merely reopening the item does not require acceptance again. Reusing a prior decision from a different request/purpose is not authorized just because bytes match; any exact source-recognized reuse must prove its current applicability rather than manufacture a new reviewer act.
- **Races:** local file selection does not freeze staff review. A durably admitted correction does. Acceptance of the old member cannot win after that source fence, even if its old preview remains open. Independent item work should not conflict unless the actual source decision depends on both.
- **After acceptance:** reviewer departure is not evidence that the earlier act never occurred. A later malware finding or changed requirement can still affect current serving/satisfaction under source policy. Preserve both the historical decision and the current qualified outcome; do not silently reopen a completed request or revive the corrected predecessor.
- **Staff and recipient lifetimes:** recipient access can expire while staff reviews already-admitted work. Staff authority and source work are independently evaluated; late review neither blames the recipient nor automatically creates completed-view access. Q21 does not solve delay by changing the selected clocks.

## Glossary recommendation

Recommend **one** new term when the parent records the reviewed package. This names a stable business decision used by future review, source satisfaction and audit work; existing Item/Submission Confirmation definitions distinguish it but do not define it. It is not terminology added merely to number Q21.

**Document Request Item Acceptance**: The source's recorded decision by authorized staff that specified submitted evidence is suitable for an ordinary Private Document Request item. It is distinct from technical file checks, the source's determination that the item is currently satisfied, and fulfillment of the whole request.

_Avoid_: uploaded, scan passed, preview Ready, request complete, file approval everywhere.

No schema, event/table name, status enum or new review engine follows from the term. No glossary edit was made by this agent. If the integrated review chooses existing prose instead, retain the same three-way distinction explicitly; correctness does not require introducing a new software type.
