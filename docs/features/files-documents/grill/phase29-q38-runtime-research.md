# Phase 29 Q38 — runtime research for File Manager search depth

2026-10-23, Asia/Bangkok. Conrad fully ratified Q37 and its amendments/new term; root records that adoption. Q38 is researched, not selected. This note examines the new staff File Manager discovery surface, not whether search exists at all. Only this work note is authored; no canonical/runtime/schema/provider/private-data changes or tests occur.

## Recommendation and fair alternatives

Recommend **A — search names and explicitly approved source metadata in the initial staff File Manager, with ordinary filters and source-context navigation, without cross-file document-body search**. Eligible fields may include a safe source-provided file title/name, type, approved labels and source relationship where their exact owners permit indexing and disclosure. These are examples to qualify, not a blanket all-metadata grant. Preserve useful open/preview/source actions and already-qualified Find within an individual representation.

**B — also provide bounded, purpose-qualified search inside eligible documents' text.** B helps staff find a document from a phrase, reference or other clue they remember from its contents but not its name. It must operate on explicitly admitted source/version/text profiles with a complete handling path and current restrictions, rather than every retained file. This need not mean AI, semantic answers, embeddings, OCR, all formats, an external search provider or a whole new platform; those are separate powers, not implied by text matching.

A is recommended because it supplies useful cross-source discovery while avoiding a new private text-derivative/index lifecycle across heterogeneous owners as a prerequisite for the first File Manager. It fits Q02's admitted-purpose boundary and the current source evidence. The cost is real: a clue that exists only inside a document will not find that file through A. A safe filename/filter workflow or opening likely files one by one is not equivalent to content search, and Find is not universally available or complete for every format. Do not oversell metadata quality or claim staff always know the name.

B is a credible product choice when body-only retrieval matters enough to justify source qualification, extraction coverage, index consistency/privacy and user recovery. Current native absence is not evidence that B is unsuitable. No measured Asym search frequency, metadata quality, time saving or corpus size establishes the optimal choice. The proposed fork selects search depth, not a universal implementation engine or a permanent ban on future compatible capability.

## What A must still get right

A is smaller than B, not automatically safe or trivial. Names, labels, source relationships, identifiers and dates can be sensitive, and a file's existence is itself a disclosure.

- Define a source-qualified field allowlist and exact authorized file/use population. Use a permitted safe display name where original filenames were discarded, restricted or never retained. Neither provider key, raw metadata JSON, a folder label nor a tenant-admin role provides admission.
- A field named summary/description/metadata is not automatically outside content search. Do not smuggle extracted document text, generated summaries, embeddings or copied private bodies into supposedly metadata-only fields. Existing source-authored descriptions have only their actual separately qualified purpose/visibility.
- Preserve typed source/use and immutable version identity. One shared byte object can have multiple independently authorized uses; permission through one use must not reveal another source, its relationships, historical versions or hidden use count. File grouping/deduplication must not union their rights.
- Apply current source/field/classification/search eligibility before hits, counts, facets, ordering, snippets and pagination, then reauthorize open/preview/source navigation. A filtered display after broad retrieval is not automatically sufficient; privilege and cached metadata need actual source checks.
- Match and filter semantics must be truthful and supported, including international names, punctuation and filenames. Do not copy CRM's stripping of `%(),`, memory's websearch grammar, D22's exact literal/phrase contract or its numerical caps by analogy. The eventual implementation must qualify its actual simple query contract.
- Distinguish a complete no-match result from a failed, stale, incomplete or unsupported source projection. Declare that this search covers names/details, so a body-only clue is not falsely represented as having been searched. Avoid an inaccessible-content count or denial-specific result that leaks hidden files.
- Keep source-private query terms and results out of ordinary URLs/referrers/telemetry/recent-query archives unless the exact owner contract permits that representation. Search terms can contain sensitive names or identifiers even without body indexing.
- Reuse admitted source metadata, one qualified source-facing API/projection and existing UI patterns; no arbitrary new search service, CMS copy or workflow engine is inherent. Bounded currentness, pagination, stale-query cancellation, usable empty states and relevant saved-filter/context behavior still require proof.

A preserves existing source search and in-document Find under their own contracts. It does not disable Support's approved conversation text, public CMS text search, CRM notes, resource titles or the qualified per-document reader. Conversely, current-source body search somewhere else is not permission for the new File Manager to aggregate those bodies.

## The additional obligations and real benefit of B

B can find a file when only its contents contain the remembered clue. To make that meaningful rather than a nominal switch, at least an exact useful source/profile cohort must actually qualify; a feature with every profile perpetually unadmitted is not a delivered B.

1. **Search-purpose admission beyond readability.** Identify which source/use/version and textual representation may be extracted, indexed and served for this purpose. Reading/previewing/downloading or being the uploader does not automatically grant corpus eligibility. Existing Support restricted-tier, care/finance-provenance, raw-source, draft/Recent-copy and other owner exclusions remain unless their owners explicitly adopt compatible amendments.
2. **Exact extraction scope and honest completeness.** Pin immutable byte/version, source restriction generation, extractor/profile/options and coverage. Digitally present text can be in unsupported or encrypted files; scanned pages have no guaranteed extractable text. Headers/footers, comments, tracked changes, hidden slides/sheets, cached formulas, images and linked resources have distinct coverage. A text-bearing preview alone neither proves whole-original extraction nor authorizes its persistence.
3. **No OCR/AI implication.** A bounded literal/keyword text path may be selected without OCR, embeddings, generated answers, semantic ranking, translation or new providers. If broader processing is proposed, it needs its own explicit source/technical qualification. Do not make B artificially equal an expensive universal AI platform to favor A.
4. **Private derivative lifecycle.** Extracted text, tokens/chunks, snippets, match coordinates, query caches and exports remain derived private material with exact provenance and finite source-owned retention/destruction. D32's Ready 24h and parser limits are preview-only contracts, not permission to retain an index forever or a copied File Manager budget. Reuse mechanics only where compatible qualification proves them.
5. **Immediate current serving gates.** Revocation, redaction, source reclassification, withdrawal, recipient changes and governed destruction must stop affected matches/counts/snippets before asynchronous physical cleanup completes. Backups/restore/index rebuild cannot resurrect forbidden content. An old index hit is not current permission or current source evidence.
6. **Coverage is broader than returned candidates.** A subset of parsed documents cannot claim no body matches across eligible files it never covered. Pending extraction, unsafe/unsupported profiles, quotas/timeouts and partial scopes need understandable states without disclosing hidden source existence. Safe source navigation/current reading can remain available independently.
7. **Traceable results and action separation.** A match identifies the exact permitted source/use/version and matching representation. A filename hit must not cause a byte download; a body hit does not mean acceptance, signature/authenticity, relevance to every source or permission to expose adjacent pages/versions. Open/Find navigation rechecks current rights and represented coverage.
8. **Coherent source/index recovery and finite cost.** Required projection intent or provable discoverable gaps follow original source changes durably. Index availability must not block otherwise authorized evidence receipt or business work. Rebuild/update jobs stay idempotent and revision-ordered with body-free events; stale generations cannot overwrite current restrictions. Measure supported corpus/input/concurrency, query/recovery/purge latency and tenant fairness before claiming capacity.

These requirements justify B's cost without assuming a specific vendor, schema or full shared-AI service. They are intended-source qualification, not facts already supplied by current code.

## Practical scenarios and later proof

| Scenario                                                             | Honest A outcome / additional B obligation                                                                                                                                  |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Staff knows filename, safe title or source record                    | A should find the permitted matching metadata and open the actual source; B preserves that simple route.                                                                    |
| Staff remembers a phrase only inside a PDF                           | A does not search that text and must not imply otherwise. B can find it only for an admitted exact text/profile/source; scanned or unsupported content may still not match. |
| Two files share a name, or one byte version has several uses         | Preserve exact source/use/version context and current rights; no auto-merge or leaked hidden relationship.                                                                  |
| Preview supports only declared visible content                       | Find searches only that qualified representation with disclosed omissions; neither option may claim it searched all original or other files.                                |
| File remains readable but indexing is forbidden                      | A uses only independently allowed metadata; B cannot direct-scan body to evade the source prohibition.                                                                      |
| A source denies name/body or becomes restricted after a query starts | Stop the affected result/count/snippet/navigation under current authority; discard delayed stale-context responses.                                                         |
| Index/source lookup fails or is rebuilding                           | Loading/incomplete/unavailable is distinct from no matches. Preserve independently lawful browse/source actions without a public fallback.                                  |
| Staff changes tenant, purpose context, filters or page               | Cancel/discard stale results, preserve deliberate permitted controls and never broaden context automatically to obtain a match.                                             |
| A user pastes a private identifier into search                       | Treat query handling as private data, parameterize and avoid ordinary diagnostic/body/query logging; do not infer identity from the string.                                 |
| A retained historical version or disposed/redacted derivative exists | Retention is not search/read permission; current exact owner scope and cleanup/restore rules control both options.                                                          |
