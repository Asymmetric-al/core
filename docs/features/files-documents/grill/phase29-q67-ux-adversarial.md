# Q67 — Source-authorized external-event recording: independent UX review

2026-10-29, Asia/Bangkok. **A selected; required amendments and full ratification pending.** This review covers an optional narrow source route for recording an already-defined event that actually occurred outside Asym. It preserves Q01–Q66 and the prior Q67 research note. Only this file changes. No event, legal period, actual GF policy, native command, implementation or hosted effect is established.

## Recommendation

Accept A with the complete current-authority, correction and recovery amendments below. Use one contextual **Record [defined event]** action where the exact source supports it. Keep subject/event context already known; ask for the occurrence in the source's declared precision and only the necessary factual basis. Show meaningful consequences before one deliberate final action. Do not create a generic event administration product, force a witness statement or upload, add a second approver by default, or require staff to edit a policy to represent an occurrence.

The strongest alternative remains B: consume only events already authoritatively recorded by their business source/integration. B avoids a new human fact-entry path and is stronger where that source is complete and reliable. It may still involve a human performing the source's normal business action. A is justified as an additional supported route when the fact happens elsewhere; it must not compete with existing authoritative facts or silently become a privileged timestamp override. No measured ministry demand, time saving or error reduction is asserted.

The essential distinction is between **recording an event**, **correcting the same recording**, and **retracting a mistaken recording**. Retraction ends reliance on this recording; it is not proof the event never happened. Another valid source may still establish the event. Mistaken retraction has a fresh qualified recovery path using permitted retained basis and linked history; it must not revive old operational authority through an unconditional Restore button.

## Small complete intended flow and copy

The default surface is the exact source record's existing Records/detail context. It shows enough current permitted subject/event information to avoid a blind action. Do not ask the actor to reselect a known subject or known single supported event. If there are several genuinely eligible events, make the actual choice explicit without a first-row default or global catalog. Entering from a broader list must still resolve the exact source context before commitment.

The form contains only the source's declared occurrence value and genuinely required basis/reference. For a known date-only fact, show a civil date and the source's relevant calendar/zone meaning; do not request a time merely because storage uses a timestamp. An instant-based source needs actual time/zone/offset precision; an ambiguous or nonexistent local time cannot silently use browser interpretation. Unknown/partial dates follow only an explicitly supported source type and route. A planned future milestone is not a completed occurrence. Server recording time and actual actor are never editable.

Show the exact event/subject, occurrence value, allowed evidence and meaningful records consequence immediately before the final action, in the same small form where feasible. No mandatory second modal or checkbox is needed. A field edit is local preparation; **Record [event]** is a consequential source command. Draft persistence, if any, must already be lawful and accurately described; do not add a new persistent draft platform or write business facts on every keystroke.

## Eighteen exact required UX amendments

**U01 — Narrow optional producer.** Permit initial staff recording only for an actual supported external event whose source owns the fact and its records-purpose use. Keep qualified native/integration facts and existing human business actions authoritative; do not require re-entry. This is neither a general event registry nor a policy-editor timestamp override. No new legal trigger, retention period, source domain or observed GF workflow is inferred.

**U02 — Qualified source profile.** Before offering the route, define exact event/subject/occurrence identity, allowed producer, sufficient evidence, date type/precision/calendar/zone, admissible scope, current impact and correction/retraction/recovery. Selecting a policy event label does not provide these. If the profile cannot safely represent a legitimate fact, identify that affected source limitation and competent route rather than invent a default or make all unrelated work unavailable.

**U03 — Actual actor powers and dual roles.** Initial record, read, correct, retract, recover, policy edit and disposal powers are distinct current source/P12 capabilities under trusted actor/Tenant/environment context. A qualified person may hold several powers without a universal second approver; actual source-required separation remains. Neither author-only correction nor generic administrator superiority is assumed. A source operator can act on another staff recording only under real scoped authority with their own truthful attribution. Preserve supported no-Party actors and existing memberships.

**U04 — Known context and exact reviewed scope.** Use the known source subject and supported event; ask only a real unresolved choice. Safe sufficient identity and consequences must precede one deliberate act. Missing/ambiguous/denied scope is not a wildcard or verified empty list. Revalidate material changes since review; no silent expansion, cross-tenant impact or inaccessible body requirement to identify the target. Current source rules govern any finite group; no unrestricted bulk-event feature is introduced.

**U05 — Temporal truth.** Preserve actual occurrence value/precision separately from trusted recorded time/actor and later correction times. Date-only civil dates use the source calendar/zone; instants use qualified precision and timezone/offset. Do not convert unknown time to midnight, date-only to arbitrary UTC or partial date to a guessed day. Late actual reporting may be valid; a future plan is not happened. Unknown, disputed, not-yet, inaccessible and temporarily unverified are distinct. The user cannot change the source date type or record time to manufacture eligibility.

**U06 — Evidence only as necessary.** Reuse sufficient permitted source facts/references and concise required input. No universal personal-witness oath, document upload, preview, reason essay or additional approval. Actual mandatory evidence remains mandatory; absent/contradictory evidence cannot be legalized by checking a box. When a body/restricted source must be consulted, route to someone with actual authority without granting the recorder unrelated access. Sensitive causes and evidence have their own source purpose/retention.

**U07 — Proportionate final action.** Keep local input changes, validation, inspection and Cancel distinct from source admission. Review meaningful event/date/subject/scope/consequence in the existing form, then one deliberate Record/Correct/Retract action. Do not force a second modal merely because the action is important; add confirmation only where actual consequences cannot otherwise be understood. No business mutation or private durable draft on every key/blur, no auto-record after repair, no optimistic committed status. Lawful draft save remains separately identified if supported.

**U08 — Coherent source and current impact.** Admit exact occurrence/recording basis, necessary history, original result and current restrictive impact/follow-through coherently through the owning source. A reported past date may make rules due; establish current governing constraints before a permissive disposer acts. Show source recording committed separately from required impact pending/blocked/completed and physical outcomes. No UI success, task completion or notification is a substitute for the actual source result.

**U09 — One occurrence across producers.** Reuse authoritative existing facts. Equivalent duplicate human/native/integration input must not create another occurrence, clock, history claim or automatic side effect. Conflicts use source identity/revision/priority/evidence rules and capable resolution, never arbitrary last writer. Correction/retraction of one recording must account for independently valid remaining evidence. A source UI may state that another source establishes the event only where that fact is currently disclosable.

**U10 — Unknown results, stale intent and no-op.** Preserve exact original business intent/expected basis and reconcile matching committed results under current disclosure before treating a retry as new work. Mismatched/stale intent conflicts; unknown remains unknown. Same visible date is not proof of same occurrence/evidence/authority or a no-op. A genuine complete no-op creates no new effective occurrence/date/impact, while required security evidence remains. A successful old command can now be corrected/retracted/superseded; show original and current truths separately. No offline automatic command queue or rekey to escape uncertainty.

**U11 — Correct the same recording.** Provide actual source-authorized Correct recording for an allowed date/evidence correction of the same actual occurrence/subject/type, with current expected basis, safe before/after impact and actual cause/reference only as needed. Preserve original values/attribution and current correction/result. A wrong correction is itself corrected currently; no history rollback, date reset to now, restored acceptance/access or altered policy. Subject/type changes require the appropriate separate route rather than hidden reparenting.

**U12 — Retract mistaken reliance.** Provide source-authorized Retract mistaken recording with safe effect review and attributed factual cause. It withdraws reliance on that recording, not the real-world event and not all independently established evidence. Current source evaluation must determine remaining established/unknown/conflicting basis and actual records consequences; do not automatically mark not-yet or clear a clock. Necessary source restrictions/holds remain, history is preserved under actual policy, and the action is not Delete event or recall of dispatched effects.

**U13 — Permanent humane recovery.** Wrong subject/type uses retract-wrong plus fresh correct-target acceptance, preserving both identities and restrictions; no copy of approval/authority. Mistaken retraction must have a usable fresh current acceptance path with linked history and the same actual occurrence identity where the source proves it, using lawful retained evidence/context rather than needless upload or retyping. It cannot revive the old operational intent, clear other blockers or force duplication when another valid source already establishes the event. No universal Restore window or Trash subsystem is required.

**U14 — Real irreversible limits and competent operation.** Preserve Q62/Q63/Q66 current policy, hold/use/writer/copy coverage, Stop, finite dispatch permission and possible-effect reconciliation. Event recording/correction/retraction grants no disposal, hold release, contract termination, money effect or physical restoration. Late facts get actual current handling, not invented grace or blanket indefinite retention. If a wrong fact enabled possible deletion, stop what remains preventable, preserve physical evidence, perform only lawful qualified recovery or record actual loss/incident. The actual capable source/operator route must exist before this cohort activates; no powerless Contact support or routine SQL repair.

**U15 — Privacy, purpose and current context.** Apply existing static field classification and subtract-only current projection to event/subject names, dates, basis, other-source hints, history, counts, impact, results, exports, logs and caches. Event capability is not body/transcript/other-tenant access. Reject late responses on actor/Tenant/environment/source change and invalidate unsafe cached context. Do not put evidence/credentials/private policy text in URLs/telemetry or unauthorized device storage. Participants and ordinary issuers gain no new legal form, consent duty, source action or notice.

**U16 — Existing Core accessible UI.** Preserve exact base-maia, Base UI1.9.0-compatible shared components and semantic tokens; no new primitive/style stack. Use labeled date/evidence controls, source-specific hints, contextual errors and meaningful status; keyboard/touch/AT, 320-CSS-pixel ordinary reflow, zoom, RTL/long Unicode labels and actual locale/date semantics must work. Focus is visible/unobscured, retained through validation and restored on return/close. Announce meaningful pending/partial/error/result changes without focus theft or per-keystroke chatter. Passive selection/blur/IME/navigation/prefetch cannot Record/Correct/Retract; deliberate focused Enter/Space/click/tap works with current origin/CSRF protection.

**U17 — Bounded proof and operations.** Reuse the source command/history/current-impact/custody paths and existing qualified work views, not a separate event bus or approval platform. Qualify finite source choices/evidence summaries/history/impact pages, stable unique paging, bounded set-wise current checks and continuation/retry/control retention with tenant fairness and actual P12 limits. Normal repair must be usable by authorized tenant actors. No guessed latency, batch size, legal period or indefinite missing-fact queue. Actual native/role/race/fault/restore and intended-user proofs are mandatory, not monitoring substitutes.

**U18 — Scope and evidence stage.** Preserve Q01–Q66 and all specialist owners. This selection adds only a supported initial input route plus its required correction/retraction/recovery. Existing source event/recording terminology should be reused unless the owner demonstrates a distinct business term; no new glossary entity is assumed here. GF/operator/legal/native facts remain unestablished where not supplied. Formal source/OpenSpec/tickets, implementation, provider testing and release qualification stay separate. This note does not close the consolidated root-package review.

## Seven founder checks

### What could go wrong with this answer?

A convenient date field could impersonate business authority, broaden scope, reset clocks or conceal a false occurrence. Correction/retraction could erase valid independent evidence or claim deleted bytes returned. Exact source admission, truthful time/provenance/current reliance and real recovery prevent those outcomes; warning text alone does not.

### What hidden assumptions are we making?

That a supported ordinary profile may need a fact occurring elsewhere, with an actual capable actor and sufficient evidence. No GF occurrence, period, legal termination or native producer is established. Actual source profile/legacy/custody/user proof remains required, not replaced by the selected product capability.

### How does this affect the whole product?

It adds a narrow initial producer and its complete factual recovery while retaining existing native/integration sources. Policy authoring, business event execution, current record applicability and disposal keep their owners. No new event platform, notification purpose or general agreement/grant/finance authority follows.

### How does this affect the end-user experience?

The actor sees known context, a source-appropriate date, only necessary evidence and one meaningful final action. Existing facts are reused. Corrections and retractions have honest durable results, and mistaken retraction can be repaired without reuploading lawful retained evidence. Ordinary participants/issuers do not become records-policy experts.

### Does this follow modern best practices?

Primary systems document human external-event recording and automated producers, while their broad-scope/date/disposition restrictions expose real pitfalls. Accessibility guidance and current Core components support a small clear form. These are evidence-informed design choices, not a universal vendor consensus, user study or accessibility certification.

### Does this fit Asym’s existing repo and product direction?

Yes through actual source/P12/current-impact/custody commands and exact base-maia components. Current source reads prove the design-system foundation, not an implemented event feature. Core form conventions and existing state primitives should be reused without copying a vendor's roles or architecture.

### Should we adjust the recommendation?

Accept A with the precise amendments and tests above. Keep B's authoritative existing producers; allow human capture only where the source supports it. Keep Record, Correct and Retract understandable and separate, with permanent qualified recovery rather than a blanket Undo or additional form/approval platform.
