## Historical question and alternatives

**Must a new ordinary document request have a qualified person/team review
responsibility before its first recipient access is issued, or may collection
begin while that review responsibility remains unresolved?**

| Option                                                                    | Practical behavior                                                                                                                                                                                                                                                                                                                       | Benefits                                                                                                                                                                  | Costs and boundaries                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A — Resolve review responsibility before first issuance (recommended)** | Reuse a valid source-qualified person/team route and establish its currently eligible review path for the declared request purpose before first issuing recipient authority. If that readiness is missing, invalid or cannot be established, preserve authorized draft/preparation and provide a real way to resolve it before issuance. | Avoids starting a recipient's finite collection period with a known review gap. With a valid default or shared team, it adds no picker, personal claim or extra approval. | Staffing resolution or a required qualification-check outage can delay a new request. Readiness now does not guarantee future staffing, workload capacity or turnaround. It is not an online-presence requirement.                                                                  |
| **B — Allow collection with review assignment pending**                   | A source with an explicitly qualified assignment-needed collection path may issue otherwise-valid recipient access while review responsibility is unresolved. That pending work must have a capable source-owned response; substantive Q21/Q23 review still waits for actual current qualification.                                      | Allows collection to begin while staff organize later review. Useful where collection and review intentionally occur at different stages.                                 | The original access clock starts at issuance and continues during the wait. Requires honest pending-review status and real recovery; a silent empty queue is insufficient. Unknown issuer/recipient/purpose authority or unsupported source/custody is never permission to proceed. |

**Recommend A.** For the ordinary native request, reuse the person/team
responsibility that Q24 already permits, then issue access. A team can satisfy
this without choosing a particular person to claim every request. Where a valid
default already resolves, the staff journey remains one deliberate issue action.
This is a small readiness condition, not another approval workflow.

B is a credible staged-collection policy, not an unsafe straw man. It preserves
the source's accountable intake/recovery owner while deferring instance-level
review responsibility. Its cost is knowingly starting recipient effort and the
fixed access period before a usable review path is resolved. We have no direct
Asym user evidence establishing that this tradeoff is routinely needed for the
ordinary profile. A is a product recommendation, not industry consensus or a
claim that all nonprofit programs should require reviewers before intake.

## Concrete example

Illustrative scenario, not a claimed ministry workflow: Elena prepares a private
request for Nora. The source normally routes review to Document Review Team.

- If the team is qualified and has an eligible review path for the declared work,
  **both options** allow first issuance without naming an individual reviewer,
  waiting for anyone to be online, or asking the team to approve sending.
- If no qualified review responsibility can presently be resolved, **A** retains
  the preparation and explains the exact staff-owned gap. An authorized person
  can select an eligible destination or use the source's capable repair route.
  Nora's original access period has not begun merely because a draft exists.
- Under **B**, collection can begin if its independent authority and qualified
  assignment-needed source path are established. Nora may submit while staff
  resolve responsibility. Receipt is still not acceptance. The original access
  period runs from actual issuance; later assignment does not restart it.

The difference is a **known unresolved review path at initial issuance**, not
whether the team is online, whether an invitation email arrived, or whether the
ultimate reviewer has personally claimed the work.

## Scope and existing decisions

“First issuance” means ratified **Document Request Access Issuance**: the
source-owned act first making original purpose-bound access available to the
intended recipient under approved terms, still subject to required confirmation
and current permission. It is not draft/task creation, credential generation,
email delivery, first sign-in or first upload. Do not implement this policy only
in a Send email button while another issuance path bypasses its actual terms.

This question concerns **first original ordinary issuance only**. It does not
silently change already-issued intake, invitation resends, Q08 completed-read
recovery, Q13/Q15 fresh unfinished periods or any previously ratified access
deadline. Existing qualified source rules continue to govern those operations.
Neither choice creates a fresh-admission gate by implication.

Both options preserve the following:

- **Real authority first.** Exact issuer, tenant/environment, recipient, purpose,
  source scope, supported entry/custody and all independently required facts
  must be qualified. B separates review readiness only where that source
  explicitly supports the separation. It does not treat unknown authorization,
  missing source implementation or unsafe storage as an allowed exception.
- **Responsibility is not permission.** Q24 still separates routing authority,
  destination qualification, actual human review and participant contact. No
  administrative role, queue label or team membership grants private access.
- **Readiness is scoped.** A checks the current person/team review path for the
  declared work. It is not a promise to accept future evidence, cover every
  unanticipated sensitivity change, deliver a review SLA or maintain an online
  reviewer. Existing specialist and stronger source rules remain authoritative.
- **Clocks stay fixed.** Q11/Q12's original up-to-60-elapsed-day period begins at
  actual first source issuance, subject to earlier limits. B does not pause it
  while assignment is pending. A cannot reset it by pretending a committed but
  unacknowledged issuance is still an unissued draft.
- **Later staffing loss uses existing recovery.** Neither choice retroactively
  erases issuance, automatically suspends all independent recipient intake,
  renews access, demands new bytes or undoes earlier lawful acceptance. Current
  protected operations still enforce actual applicable source restrictions.
- **Completion remains Q22's source fact.** Independently authorized staff may
  finish received work after recipient access expires. A later completion does
  not automatically create completed access after the relevant admission ended.
  Missing staffing is not a new completion predicate once all actual conditions
  have been lawfully satisfied.
- **No extra system.** No new claim, online-status service, calendar, second
  reviewer, timer pause, routing algorithm, per-request bypass switch, automatic
  email, extra confirmation or whole-Workflow-Studio prerequisite is selected.

Known unresolved/invalid responsibility, known lack of an eligible actor and an
unavailable eligibility check need different truthful states. Under A each can
prevent its readiness-dependent initial issuance. Under B an unavailable review
check must not be mislabeled as an empty team; independently established
issuance may proceed only under the explicitly supported source separation.
Neither option permits guessing authority or claiming nonexistent readiness.

## UX and decision safeguards

With A, show the resolved responsibility compactly and reuse it automatically
when valid. Only a genuine readiness problem needs staff action. Explain that
problem beside the issue action, retain authorized preparation and expose the
existing permitted repair route. Do not make every sender reselect a reviewer
or treat an unavailable lookup as proof no reviewer exists.

With B, pending assignment is explicit staff-owned work with a capable response,
not an empty inbox or a recipient error. Show receipt and actual review status
truthfully without exposing staffing details. Do not promise readiness,
acceptance, renewed access or another completed-view period merely because
documents were received. Both paths need accessible labels, predictable focus
and safe retry/unknown-result recovery in the existing design system.

For either selected answer, its full adversarial review must test the first-
issuance boundary, changing eligibility during issuance, lost acknowledgment,
defaults versus actual source qualification, current disclosure and real
staff/participant recovery. Existing Q11 effects/clocks must be recovered before
treating a retry as new issuance. No additional state machine or SQL design is
selected by this question.
