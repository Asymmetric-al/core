# Phase 29 Q33 — Comparative research: an item is no longer required

Research checked 2026-10-22, Asia/Bangkok. Q01–Q32 and twenty-two definitions
are ratified grooming intent; Q33 has no selected answer. This note supports
one product decision, not implementation, activation or formal publication.
Only this file was written. No private data, real messages or provider actions
were involved.

## One decision and recommendation

**If an outstanding ordinary requested item was included by mistake or is no
longer applicable, should source-authorized staff be able to mark it No longer
required within the unfinished request?**

Recommend **A — Allow the source-authorized No longer required action** for
the outstanding, unaccepted item within an eligible unfinished ordinary request.
It gives staff a direct way to stop an unnecessary demand without pretending
that missing or unsuitable evidence was accepted, erasing submitted files, or
making the participant create a meaningless replacement upload.

| Option                                                         | Practical experience                                                                                                                                                                                                           | Benefit                                                                                                                                                                     | Cost and boundary                                                                                                                                                                           |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A — Allow No longer required (recommended)**                 | Authorized staff record that this particular outstanding item is no longer required by its actual source. The participant sees that no more submission is needed for it, while evidence and history retain their real meaning. | Resolves a mistaken or inapplicable demand where staff and the participant already see it. Avoids fake acceptance, deletion or needless file production.                    | Requires a real source-authorized requirement change and clear consequences. It must not become a generic way to waive a still-binding specialist, consent, financial or legal requirement. |
| **B — Keep resolution in the existing qualified source route** | Add no ordinary-item action. Staff use the source's already-qualified correction/resolution route, and the request reflects the resulting authoritative facts.                                                                 | Keeps requirement changes inside established source procedures and avoids another way to initiate them from the request UI. Strong when those procedures already work well. | May require a handoff or leaving the item context. The route must actually be capable and discoverable; B cannot mean an endless request or an invented cancel/reissue workaround.          |

There is no useful third option merely to create a three-column choice. B does
not remove already-authorized source powers or require cancellation/reissue.
A does not grant this power to every reviewer, participant or tenant admin.
The difference is a narrow ordinary-request action initiated through the actual
source authority, not competing owners of the requirement.

Illustrative example, not a ministry observation: Elena requested a certificate
from Nora, then establishes through the source's actual rules that this item was
included by mistake. With A, Elena marks that item No longer required. Nora no
longer sees an outstanding demand for that certificate. An earlier uploaded file
remains a received file with its true review status; it is not retrospectively
accepted or deleted. With B, Elena uses the existing qualified source-resolution
route to achieve the lawful outcome. Neither asks Nora to upload a blank PDF.

The strongest objection to A is that an easy-looking action could bypass a
meaningful source decision. A is acceptable only as that source decision's
qualified entry point. The UI cannot itself confer requirement-change authority.
A may authorize a new bounded ordinary-source capability with qualification,
or expose an existing safe source command; it does not enlarge specialist powers.
No evidence here establishes how often Asym staff encounter unnecessary items,
how much time this saves, or a universal preference for A.

## Meaning that must stay clear

| Similar-looking action                                  | Why it is different                                                                                                                                                                       |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Participant says Not applicable / I cannot provide it   | Information for the source. It does not establish that a still-binding requirement is waived or satisfied. Q30 clarification can carry it.                                                |
| Staff accepts existing evidence                         | Q21 deliberate evidence acceptance. If an eligible existing file still satisfies a required item, use Q28 supply/Q21 review rather than hide the requirement to avoid review.             |
| Request changes / reject / decline                      | A review outcome or broader source decision, not a statement that the request item was unnecessary. Q23's recoverable ordinary review remains intact.                                     |
| Delete a field, item or file                            | Can erase structure or data; the proposed No longer required records an authoritative change while preserving real evidence/history under their owners.                                   |
| Make a template field optional or hide it conditionally | A definition/configuration operation whose scope may affect other people or future requests. Q33 is one source-qualified item in one current request, not silent global template editing. |
| Remove staff-supplied evidence                          | Q28 withdraws one eligible unaccepted staff-added contribution; it does not remove the underlying requirement or alter other submissions.                                                 |
| Cancel the whole request                                | A different whole-request outcome, not Q22 successful fulfillment and not selected here.                                                                                                  |
| Reopen or restore a required item                       | A separate source change/remediation with its own authority. No toggle-back, generic Undo or restoration of old access follows from Q33.                                                  |

## Existing Core authority and the real open boundary

The founder brief requires a bounded request definition and exact revision
(line 221), only source-owned commands/evidence to satisfy a requirement
(line 227), and preserved versioned instructions during edits (line 229).

Feature ADR-0022:37–40 preserves existing qualified requiredness and waived/
not-required outcomes but explicitly adds no new waiver. Lines 46 and 59 keep
canceled requests distinct from fulfillment and make genuine requirement changes
part of source re-evaluation. Feature ADR-0023:59–60 says feedback cannot change
requiredness; lines 113–117 require a capable route for mistaken/non-remediable
requests while adding no generic terminal/cancel/waiver action. Feature
ADR-0028:62–69 permits narrow staff-evidence removal, not requirement removal.
The current decision log through Q32 does not select Q33 by analogy.

Thus A is a new narrow source-authorized ordinary-item act requiring explicit
qualification; it is not a file-state flag or a pre-existing reviewer entitlement.
Outstanding unaccepted items are in scope. Accepted/closed outcomes, specialist
requirements, consent, signatures, financial evidence and higher-level application
decisions retain their owners. Normal access, retention, holds and original
submission/review attribution remain independent.

## Simple interaction and consequences

Use a deliberate item action such as **Mark no longer required**, displayed only
under the source's qualified capability. Staff should understand that this changes
what is being requested, not whether submitted evidence was accepted. Possible
short explanation: **This item will no longer be requested. Existing submissions
and history are kept.** Exact copy remains subject to actual retention/disclosure
and intended-user proof; it must not imply indefinite raw-content retention.

For the participant, use an understandable **No longer required** status and
safe text such as **You do not need to submit anything else for this item** when
that is the source's true outcome. Preserve permitted status/history rather than
making the item vanish or presenting an Accepted badge. Show remaining work and
the actual request result independently.

If the change would currently satisfy the full Q22 predicate, make that consequence
clear in the existing interaction. Do not promise completion from a stale screen
or ask for a second routine approval. A source-required reason or judgment must
be recorded, but this choice does not mandate a long essay, a new reason-code
designer, a second reviewer or an unconditional confirmation modal. The actual
source may impose stronger requirements for its own meaning.

No new email/SMS/bell, automatic explanatory message, reminder, cancellation,
bulk-waiver feature or workflow mode follows. Existing messages keep their exact
meanings: this source change is not Q26 Request changes, Q27 evidence-actionable,
Q31 a deliberately shared staff clarification, or Q32 a received participant
message merely because some text/status changed. A genuinely separate permitted
clarification remains possible without manufacturing it as the item-change audit.

## Required evidence later

Test that representative staff distinguish No longer required from acceptance,
rejection, deletion and binding-domain waiver. Test that participants understand
what remains and do not continue an unnecessary upload. Include already-received
files, prior requested changes, last/all-item cases, non-file obligations, denied
authority, stale changes, upload/review/closure races and lost-response recovery.
Measure task success and understanding without claiming an unobserved reduction
in support time. Native source/authorization/concurrency and accessibility proof
must qualify the real capability; documentation and a button mock do not.

No authenticated competitor workflow, browser/AT/intended-user study, source
runtime, SQL/RLS, provider or concurrency test was performed. Primary research
is deliberately narrower than a claim of universal industry practice.

## Independent question review closure

Read the full `work/phase29-q33-question.md` on 2026-10-22 after the coordinator's
source, recovery and ratified Changes requested wording refinements. No material
UX or comparative-evidence issue remains in the researched question. A and B
present one meaningful choice and give the existing-source alternative its
strongest practical case. The question distinguishes a newly qualified ordinary
capability from a UI inventing authority or a competing File Manager mutation.

The complete journey review covers received evidence, denied authority, last/all
items, the complete Q22 predicate, concurrent upload/review/clarification,
uncertain outcomes, mistaken decisions and accessible persistent results. The
question correctly leaves concrete correction qualification for the selected
answer's review rather than promising universal Undo, reopening or a cancel/reissue
fallback. It adds no mandatory reason essay, second approval or notification.

The public-source claims match the examined primary pages, including TaxDome's
US scope and separately marked Beta behavior, Content Snare's review/edit
permission distinction, Submittable's whole-form lifecycle, and GOV.UK's clear
status/remaining-work guidance. They do not establish an exact equivalent Core
action or measured ministry benefit. The example is explicitly illustrative.
This closure verifies the question's reasoning and recording, not native runtime,
permissions, concurrency, accessibility or intended-user qualification.
