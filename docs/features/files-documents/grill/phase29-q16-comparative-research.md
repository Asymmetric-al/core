# Phase 29 Q16 — completed-read recovery after a continuation

Research date: **21 October 2026, Asia/Bangkok**. The parent reports Q15 and its full amendments ratified. **Q01–Q15 are the accepted baseline; no Q16 answer is selected.** This note researches the next scope decision. It does not resolve Q08's still-unselected timing or repetition policy.

Only this research note was written. The Q08 decision/question, Q13/Q15 decision context and current official public documentation were inspected. No canonical document, UI, runtime, permission, private account or provider state was changed. No competitor, native grant, browser/AT or representative-user test was performed.

## Recommended single question

**Should Q08's staff-approved fresh read-access capability also cover a valid completed view reached after fresh unfinished access, or remain limited to completion under the original ordinary access?**

Recommend **A: include both qualifying completed-view origins**, while keeping the **actual source-created completed-view admission at fulfillment** as the governing historical scope ceiling for each case. Current source authority, legitimate purpose, intended recipient, current eligible own-submission members and genuine restrictions still control the proposed new read grant. The old admission stays ended; completed work stays completed.

This is a coherent scope decision before choosing Q08's fresh timing profile. It answers who may be considered under the already-ratified read-recovery capability, not how long that later permission lasts. It prevents the clock discussion from silently inheriting two different eligibility rules. The recommendation is a product consistency judgment; no reviewed competitor proves that this exact provenance distinction must be treated the same.

The strongest alternative is **B: retain original-ordinary-only eligibility**. That is an explicit narrower capability, not a failure to provide help. A valid completed view produced by a continuation would keep its existing Q07/Q13 access until its own end; once it ordinarily expires, Q08 recovery would not apply to that origin. Independently authorized source assistance remains possible on its own terms, and might not be able to supply another copy.

## Why this is still unresolved

Q08 was ratified for a proven original ordinary completed-view admission followed by eligible ordinary expiry. It bounds later read scope by that original completed admission and current eligibility. It did not admit a recipient who never had a lawful completed view, and it did not make actual prior viewing a prerequisite.

Q13 later allowed a different lawful path: eligible source fulfillment during a valid fresh unfinished admission can create a completed-read admission within its separately declared read scope. Q14 sets each fresh unfinished period; Q15 permits individually reviewed sequential unfinished periods. All three explicitly leave Q08 broadening unresolved. The fact that the resulting screen looks similar cannot itself grant this new power.

Q16 therefore needs an express prospective successor rule if A is selected. It can recognize either valid fulfillment-created completed-view origin as the historical root for Q08 consideration. It must not use a generic request status, an old unfinished grant, a record of file receipt or retained bytes as an equivalent root.

The governing root is the **actual source-created completed-view admission at fulfillment**, not simply the last screen the recipient used. A prior click, preview or download is neither necessary nor sufficient to prove that admission.

### The scope ceiling must not drift

Hypothetical example, not an asserted ministry workflow: the original request involved files A and B. A fresh unfinished admission declared a completed-read scope containing only A, and its qualifying fulfillment actually admitted only A. Under proposed option A, a later Q08 grant can review only that completed admission's allowed scope intersected with current eligibility. It cannot retrieve B merely because B was once in the original request or remains stored.

An individual later fresh-read grant's narrower selected subset alone does not redefine that historical completed root into a new global ceiling; Q08's existing rule already distinguishes a deliberate subset from a genuine binding restriction. This does not decide whether a further fresh-read grant is allowed, because completed-read repetition remains open. Never union historical grant scopes or use the most recent grant as a replacement for the fulfillment-created root.

## Q08 timing is a real dependency, not a reason to merge decisions

Q08 still requires an explicitly adopted finite timing/activation/unused-admission profile and a repetition/overlap policy before activation. Q16 can resolve **which completed origins may be considered** first. Both branches of A should then use the same adopted standard Q08 policy unless the source explicitly defines a real scoped difference; neither origin inherits another lane's policy by name.

- Q07's up-to-thirty-day completed view is the period that has already expired, not an automatic fresh read period.
- Q14's thirty days from fresh issuance governs **unfinished** continuation. It does not choose a Q08 read-recovery duration or anchor.
- Q15's sequential repeats without a preset aggregate ceiling govern **unfinished** continuation. They do not authorize repeated completed-read recovery, select nonoverlap semantics for Q08, or remove a future read-recovery count cap.
- A does not choose first entry, issue time, a calendar date, reminder cadence, notification channel, a grace interval, or new account/session behavior.
- Q08's actual source/capability mapping, timing, repetition, current serving and user-journey qualification remain activation gates for both origins. Q16 selection is not implementation permission or proof of readiness.

This avoids silently selecting a clock merely to make the proposed scope operational today. The source needs usable finite terms before it can issue a real new permission, but the founder can decide the cohort boundary without being forced to choose the remaining terms in the same answer.

## Keep the staff and recipient experience familiar

The recipient should not need to identify whether a past grant was original, a first continuation or a later continuation. Those are source proof facts. The staff actor reviews the relevant completed admission, intended recipient, current legitimate read purpose, allowed files/actions and true limits in the existing context. No new lineage picker, body-read escalation, taxonomy lesson or approval chain follows.

Copy can remain short: **This request is complete. Access to this view has ended.** is suitable only where those facts are currently disclosable. The help action should name the actual established route, not promise a new grant. After current usable read permission exists, **Read-only access ends [actual date, time and zone]** is clearer than explaining the historical path to completion.

No new reason essay, date picker, timer activation, recipient account, mandatory second confirmation, export feature, email attachment fallback or general file archive is needed. Existing Q01/Q04/Q05/Q08 accessibility and disclosure boundaries remain. Helpful return behavior does not imply perpetual rights.

## Proposed founder-facing wording

**When a lawful completed view later expires, should staff be able to consider the same limited read-access recovery even if the request was completed during a continuation?**

- **A — Apply it to either valid completed-view origin (recommended).** The source must prove that the completed view was lawfully admitted, then apply Q08's current-purpose, recipient and scope checks. It stays read-only and cannot recover files outside that actual completed admission. This gives a consistent help route without treating all completed requests as eligible.
- **B — Keep recovery for original ordinary completion only.** A completed view reached during a continuation keeps its admitted access, but once that expires it is not eligible for this recovery route. Existing governed help remains; reopening or cloning the request cannot bypass the boundary.

Recommendation: A better matches the existing promise of a purposeful completed view without making the recipient's recovery depend solely on the path taken to lawful completion. B is the honest narrower choice if that path is itself intended to determine finality. Neither selects the new read period's length, anchor, repetition or notification policy.

## Limits and follow-through

No reviewed official source settles this exact fork; no Asym demand study measures either branch's burden or benefit. Consistency is not proof that permissions can be unified without preserving their provenance. The question should present that limitation plainly rather than call A an industry default or an accessibility requirement.

If A is chosen, the subsequent adversarial review can focus on the two valid roots, an unvisited valid completed view, no-view gap/cap cases, current adverse restrictions, a narrower actual completed scope, observed-late completion, old replay versus live access, and shared user-facing behavior. The source must retain an exact proof link to the fulfillment-created admission; it cannot reconstruct rights from filenames, emails, view logs or a completed flag. Existing Q08 source/data/serving/rollout proofs remain required.

The next scope answer remains open. This note selects no Q16 policy, new clock, repetition limit, runtime behavior or canonical record.
