## Current research and alternatives

Official [Box annotation guidance](https://support.box.com/hc/en-us/articles/360048016153-Annotating-Documents) supports contextual comments, navigation, version distinction and overlays that leave original bytes unchanged. [Dropbox specific-part comments](https://help.dropbox.com/view-edit/comment-specific-part) support bounded image/PDF area feedback, while its [comment guide](https://help.dropbox.com/view-edit/commenting) describes limits on repositioning. That limitation strengthens the case for deliberate correction in Core; competitor roles, permanent deletion, mentions and email behavior are not adopted.

[Adobe's web review guide](https://helpx.adobe.com/acrobat/web/share-review-and-export/review-pdfs/add-manage-comments.html), updated August31,2026, uses a comments pane and deliberate Post, with own edits visibly indicated. Its replies, reactions, auto-mentions and permanent-delete behavior are optional vendor choices, not requirements here. [Mobile review guidance](https://helpx.adobe.com/acrobat/mobile/review-files/review-documents.html) supports evaluating touch journeys; it does not certify Core's UX. [Submittable's staff-note guidance](https://submittable.help/en/articles/923669-how-do-i-attach-a-note-to-a-submission-who-will-be-able-to-see-it) is a relevant grant-review precedent for keeping internal notes distinct from submitter communication. It does not establish exact-version spatial behavior or Core staff audiences.

[WCAG keyboard guidance](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) and [Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) require separate keyboard and single-pointer non-drag consideration. A page-level text fallback is not equivalent access to region placement. [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) applies to the surrounding list/composer even when the document legitimately needs a two-dimensional surface. [Status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) support truthful save feedback. Reduced-motion behavior is sound product judgment; the animation-from-interactions criterion is AAA, not an invented AA rule.

[Mozilla's PDF examples](https://mozilla.github.io/pdf.js/examples/) distinguish viewport transformation and output scale. [W3C's annotation model](https://www.w3.org/TR/annotation-model/) distinguishes target/state/selector concepts. These support a stable location basis without selecting PDF.js, JSON-LD, every selector type or a general annotation framework.

[PostgreSQL policy semantics](https://www.postgresql.org/docs/17/sql-createpolicy.html) require effective old/new-row behavior, including inherited WITH CHECK defaults, not a keyword audit. [Function security](https://www.postgresql.org/docs/17/sql-createfunction.html#SQL-CREATEFUNCTION-SECURITY) depends on owner privileges, grants and safe name resolution. [Pagination](https://www.postgresql.org/docs/17/queries-limit.html) needs unique ordering; [index usefulness](https://www.postgresql.org/docs/17/indexes-multicolumn.html) depends on actual predicates. [Supabase Postgres Changes](https://supabase.com/docs/guides/realtime/postgres-changes#scaling-postgres-changes) adds per-subscriber authorization work; it is not free fanout or a substitute for P12. Current changelog compatibility notices were checked; no environment upgrade or extension is selected.

**Strongest alternative: A only.** General and supported page/cell references would remove spatial mapping and interaction work. It is credible but makes staff describe visual details manually. A+B is worth selecting when limited to the qualified static cohort and one optional anchor. A generic annotation/chat/editor suite is a substantially weaker fit: extra lifecycle, privacy, dependency and operational burden without evidence of need. Existing task navigation is useful; forcing one task per comment or off-platform messages does not meet exact-version in-context review. No-build/copy-paste lacks reliable current attribution and context. These are product judgments, not measured comparative outcomes.

## Minimal data and Supabase work plan

Use a source-owned relational comment identity with immutable scope/author and a guarded current revision. Store source-required revision/history records under their actual retention. The current revision contains bounded plain text and zero or one compact discriminated location. A point or rectangle needs a small fixed coordinate shape and an exact trusted location basis; it does not need PostGIS, screenshots, copied PDF content or a second annotation truth. Physical table/column names and numeric precision remain design choices to qualify, not arbitrary frozen schema here.

The source owns authoritative scope, lifecycle, eligibility and review relevance; the original-file/version owner owns immutable evidence; the qualified reader owns representation geometry/coverage; P12 owns authority. Location controls and cache entries are disposable projections. A persisted marker does not grant byte access or own preview retention. Author selection, approval, Tenant, assignment and timestamps are server-derived, not editable payload fields.

Native PK/unique/FK/check/default/nullability/delete contracts must enforce expressible invariants. Composite scope relationships prevent cross-Tenant/use/version pointers; one guarded current revision and operation identity prevent conflicting duplicate effects. Closed types and finite bounds reject malformed shapes. Current cross-row eligibility belongs in the authoritative command, not a mutable cross-table CHECK. Required historical attribution cannot disappear through an author/rendition cascade. Large bodies do not belong in every index; no money columns or precision migration is introduced.

The ordinary workload is **one bounded deliberate command**, **one bounded source/version list page**, and **needed page-marker/author batches**. This is not a promise of one SQL statement: required history, current authority and accounting still run. Zero writes are caused by typing, dragging, pan, zoom or hover. Unchanged saves avoid needless revisions. Stable creation-order keysets use a unique tie-breaker and a context-bound continuation; edits do not reorder history. P12 projection is set-wise before pagination/count disclosure. Do not repeatedly resolve/audit per pin, rewrite whole task JSON or load every version/history/page.

Index the actual scope/version/filter/order/foreign-key and cleanup paths, then inspect real-role plans and measured lock/connection/WAL growth under skew. P12 R6's logical ≤1 governance-row SELECT + ≤1 ledger UPDATE and its actual physical carve-outs apply; this is not a one-total-query rule. Preserve restricted-tier audit and safety even when it costs more. Do not use isolated keyset examples as O(1) or provider capacity evidence.

Fine-grained rights stay in P12; coarse Tenant RLS is defense in depth under the same trusted context. Inspect effective policies and grants, USING/new-row CHECK defaults/composition, required SELECT, RETURNING/errors, MERGE/UPSERT, owner/BYPASSRLS/service sessions, function search_path/EXECUTE, views and trigger side writes. Qualify or close browser collections, raw Data API/GraphQL/CMS, imports/jobs/operator/restore and reader/storage doors. The absence of the literal WITH CHECK is not itself a vulnerability; SECURITY DEFINER is not universally synonymous with bypassing every policy.

No mandatory Realtime/presence/CRDT or always-on poller. Current command responses, deliberate refresh and bounded current-context revalidation can provide this workflow. Existing qualified invalidation may be a minimal advisory signal followed by protected refetch, including restricted-tier silence. Public post subscriptions, old-row/DELETE payloads and coarse RLS alone cannot safely distribute private review content. Actual deployed version/configuration and latency/storage/egress/accounting are release evidence, not conclusions of this review.

## User journeys and UX acceptance

The smallest complete flow is: open the exact permitted evidence version → Add comment or deliberate Comment here → write a concise observation and optionally choose a supported location → Post comment. A qualified point/region stays provisional until the same Post succeeds. The list and marker select each other deliberately. Edit uses Save changes/Cancel; Withdraw has qualified Restore/Undo. There is no required title, reason essay, routine second approver, compulsory reply or resolution ceremony.

On mobile, deliberate placement mode preserves ordinary pan/pinch. Regions support a usable two-corner/non-drag path and equivalent keyboard controls; exact numeric coordinates are not mandatory user input. Unknown save is not success or failure: show Checking whether your comment was posted only while actual reconciliation runs. Location unavailable describes mapping/access reality without saying the comment vanished. No automatic external viewer/download is recovery.

Elena's inventory review in the UX note is an illustration, not evidence of an actual ministry process. Donors, missionaries and Q41/public recipients receive no new internal-comment audience merely from their other role; staff may themselves also be missionaries, so the actual current acting assignment/source permission matters. International addresses are not collected by this feature; names, Unicode, RTL, IME, time zones and long labels still require proof. Original source content is not auto-translated or rewritten.
