## Recommendation after the whole-scope check

The next useful question is **how to remedy a substantively mistaken acceptance of ordinary requested evidence**, not another optional resource feature. Recommend **A — a deliberate attributed source correction of the exact mistaken acceptance while the ordinary request is still eligible and unfinished**. The strong alternative is **B — use separately reviewed corrective work for every such mistake, instead of returning that accepted item to ordinary review in the same request**.

Both options must record the mistake and its current reliance consequences truthfully. Preserving the original historical acceptance must not mean that a known-invalid acceptance continues to satisfy the current source requirement. Neither option silently edits the original reviewer/time, resurrects predecessor evidence, automatically sends messages, renews participant access, reopens a fulfilled request or makes source correction a file-state toggle. Both need an actual capable route for completed/closed cases using fresh independently authorized corrective work and preserved fulfillment/history.

A preserves continuity for normal errors while other work is still outstanding: correct the actual current acceptance, retain the original act and evidence, then use the existing current review/Request changes/submission-correction paths where their source prerequisites hold. This does not automatically assert that the participant owes another upload; staff may only need to reassess the same retained evidence. A new source-correction power and relevant aggregate ordering are required. This is product judgment, not a measured estimate of mistake frequency.

B must be executable rather than a Help label. For an unfinished ordinary request, the concrete separate-work shape is a deliberate source-qualified end/supersession of the old collection using actual Q34 cancellation semantics, with a separately reviewed corrective request for **only legitimate remaining work**, independently qualified Q25 original issuance, current recipient/access terms, and permitted Q28 evidence reuse where suitable. This is an explicit proposed Q60 same-recipient corrective-remedy adoption, not permission already supplied by Q49's different-person replacement. Old unrelated accepted facts/history remain; they do not need to be requested again merely to populate a new checklist. An already committed protective stop or cancellation remains effective if the new preparation/issuance fails, and the actual source remedy must permit truthful resumption of the remaining authorized work. If actual source constraints forbid cancel/supersede, the corresponding existing domain remedy must be named and capable before that cohort can use B; a vague operator promise is insufficient.

For already fulfilled or otherwise terminal work, neither A nor B cancels/reopens the old record through an unfinished-request command. Record the error/current reliance restriction through actual source authority and conduct any legitimate further work under a separately reviewed new source act/request. Preserve the real original F and access-history rules; no new thirty-day/sixty-day period is inferred. Pure attribution/date-recording typos and privacy/safety containment are different from a substantive decision that wrongly counted evidence as satisfactory. Do not automatically recollect documents or cancel a request merely to correct a factual record or restrict unsafe bytes.
