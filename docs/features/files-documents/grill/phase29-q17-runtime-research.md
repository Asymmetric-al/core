## Recommendation and next dependency

**Recommend a fresh completed-read period whose finite end is resolved at its own qualified source issuance.** This reuses the intended source-issued clock shape already chosen for fresh unfinished access, while retaining Q08's distinct purpose, exact completed ceiling and still-unselected numerical policy. It avoids an extra business activation transition and gives staff and the recipient one actual end to understand.

The strongest credible alternative is **a finite latest qualified entry, followed by one finite reading interval from that first entry**. It preserves usable reading time when the person returns late, but introduces a pending-entry state, its own finite expiry, one-time activation identity, concurrent-entry handling and a later possible final end. It must not be watered down to an indefinite unused grant or first successful file download.

This clock/profile choice has greater dependency value than deciding repeated fresh-read count first. Repetition must later apply to a fully defined admission/expiry model. Neither A nor B may activate until Q08's separate repetition/overlap/cumulative and authority qualification gates are resolved.

For a lean founder question, compare complete understandable profiles if the parent can justify the numbers as product judgment; that avoids another shape-only round followed by a number-only round. The two models must remain visible, however. Choosing “30 days” without its anchor and unused bounds is incomplete. Reusing Q14's thirty-day value could be proposed for consistency, but would be a new explicit Q08 decision, not an existing default or empirical optimum. Current code does not establish a better 7-, 14- or 30-day value. Do not infer such a count from a provider/session/official-document constant.

Final sequencing reconciliation: the parent's prepared Q17 question chooses the clock model alone, with one complete numerical profile explicitly next. That is also coherent and avoids pairing unresearched counts with the anchor tradeoff. The paragraph above records an optional leaner question format, not a technical requirement or a selected count; this note's recommendation for the source-issued model is unchanged.

## Exact clock alternatives

The following symbols are explanatory notation only, not new glossary terms or prescribed schema: `R` = this new fresh completed-read source issuance, `D` = the eventual finite reading duration, `W` = an eventual finite latest-entry interval, `T` = first qualified source entry, `E` = this fresh period's end. All formulas below illustrate an elapsed-duration profile **only if that calculation and its units are later selected**. Q17 chooses the clock model, not arithmetic, units, a count or the complete calculation profile. All alternatives remain subject to actual applicable current source/purpose/action limits.

| Model                             | Complete semantic shape                                                                                                                                                                                                                                                             | Tradeoff and qualification                                                                                                                                                                                                                                                                      |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A — Source-issued fixed end       | Source issuance R resolves and preserves one finite E under the subsequently selected calculation profile. Illustratively, if an elapsed-duration profile is later selected, nominal E = R + D; applicable earlier limits retain their real scope. The same E bounds unused access. | One end; no entry activation, pause, resend extension or sliding expiry. Delivery/proof delay and recipient absence consume time. Source issuance is not a preliminary approval, button click, notification, authentication callback or first view.                                             |
| B — Bounded first qualified entry | At R, source terms declare finite latest-entry L = R + W and the finite read-interval rule. Exactly one qualifying T strictly before L can resolve nominal E = T + D under current eligibility/true caps. No qualifying entry by L means no later activation.                       | A timely late entrant can retain D reading time, and the nominal final end can approach but remains strictly before R + W + D. R creates the explicitly bounded conditional source permission; T is not an ungoverned login event. Issuance/activation/usability must be distinct and truthful. |
| Hard-outer variant of B           | Source additionally declares a genuine fixed overall read ceiling H at R, and E is clipped to H.                                                                                                                                                                                    | This is a different promise: late entry can leave less than D. Do not hide this variant inside B or relabel an already-binding end as entry-only. It is unnecessary as an extra founder option unless that tradeoff is wanted.                                                                  |

B requires the source to define the protected entry/activation semantics prospectively. No unqualified private reading may precede the required entry checks. Any minimal entry/help information remains under its existing source/identity policy. An approval that has not issued source rights is a different state; it cannot be called active access or used to smuggle in an indefinite pending period.

Compared with Q14's old first-entry alternative, this lane has no unfinished-to-completed business transition: the request is already completed. No pre-entry fulfillment calculation or new F is needed. Do not carry the unfinished completion-stage rules into the fresh read interval. Q07's actual F and prior completed end remain historical facts; each authorized Q08 fresh period gets its own adopted clock, not a replacement F.

The expired prior ordinary read end is not required to remain valid or automatically become the new end's cap—Q08 expressly authorizes consideration after eligible expiry. Genuine source/purpose/content-use/retention-disposition restrictions retain their actual scope and may forbid or shorten new reading. Repeated narrower grants are not a new global ceiling; the fixed Q16 completed baseline/current intersection still limits scope.

## Boundary conditions the question must preserve

1. **One actual new source occurrence.** If A is selected, R is the qualified source occurrence whose effect durably commits after relevant current checks; not original I/F, browser time or preliminary review. A delayed observation recovers the same R/E. Internal SQL timestamp capture is not itself proof of a physical commit boundary.
2. **No special first-use loophole.** If B is selected, T must be one source-qualified deliberate entry bound to this exact issued effect, recipient and current Q01/P12/source checks. It is not a GET/HEAD, prefetch, link scanner, generic login/token refresh, verifier success alone, email open, rendered preview or first byte. Status-only access can qualify entry without a file body. Compatible current proof may be reused; no extra account or routine timer-start modal is implied.
3. **Exact timing and current scope.** Before/at/after applicable end/entry boundary must have a defined exclusive rule. Preserve actual earlier limits and current restrictions after waits. Neither reads nor reauthentication slide the period. Different transport attempts and concurrent first entries cannot each get a fresh end. If B's original entry committed but reply was lost, recover its original T/E rather than activate at retry time.
4. **Stable reviewed intent versus outputs.** Bind exact baseline, recipient, action/member scope and adopted timing policy. Source-generated R/T/E are original effect outputs, not freshly recomputed retry intent. Material changes need the existing renewed review/conflict handling. Unknown result is not absence, closing after dispatch is not cancellation, and missing policy/history is not a new default interval.
5. **Grant is not usability or notification.** Under A, the time may be running while recipient proof, representation or separately authorized delivery is unavailable. Under B, issued conditional terms and activated interval must be shown distinctly. Source restrictions and applicable continuing issuer/delegation dependencies still apply; a current read check cannot simply trust a successfully activated flag. No automatic email or resend program follows.
6. **Expiry is authority, not a scheduled deletion.** Enforce at source/private serving with existing Q04 stream/range/conditional/cache and Q05 metadata rules. A worker, client countdown or TTL cleanup is not the authoritative end. Expiry never deletes or reissues documents, changes F/acceptance/correction truth, changes retention, or permits copying to a new request.
7. **No implicit repetition.** Ordinary expiry may lead to truthful help. Whether a further fresh completed-read period may be issued, overlap or cumulatively continue remains Q08's separate unresolved policy. Q15's sequential/no-fixed-quota rule is about unfinished access only.

## Current official technical checks and proof limits

The PostgreSQL 17 documentation checked during this same Q16/Q17 review explains that NOW/CURRENT_TIMESTAMP use transaction start; clock_timestamp changes during execution. None is a guarantee of physical commit time. Source occurrence, after-wait currentness and durable outcome need the already-owned qualification, not a new universal timestamp function. [PostgreSQL date/time](https://www.postgresql.org/docs/17/functions-datetime.html)

READ COMMITTED row rechecks do not make a multi-row authorization/activation predicate atomic. Row locks protect retrieved rows, not an absent activation record. Source-owned uniqueness/serialization and replay handling would be required for concurrent first entry; a generic worker lease or per-transport key does not establish that invariant. [PostgreSQL isolation](https://www.postgresql.org/docs/17/transaction-iso.html), [locking](https://www.postgresql.org/docs/17/explicit-locking.html)

No database/runtime experiment or unit test was needed to decide this product fork. Prior clock/projection/workflow tests remain adjacent historical evidence, not proof of either native Q17 model. No hosted PostgreSQL version, applied migration state, actual grant policy, provider session behavior or representative-user outcome is asserted.

The fixed source-issued model is the simplest recommendation. The first-qualified-entry model has a real user benefit and a real additional state/qualification cost; current evidence does not make it unsafe by definition. The founder should choose the complete intended experience with those tradeoffs visible, without an inferred count, new arbitrary staff deadline editor or automatic renewal.
