## Whole-product adversarial check

### What could go wrong with this answer?

A source return could become an irreversible negative flag, force identical
reuploads, expose confidential reasoning or be replayed after acceptance. Another
reviewer could accept a stale basis without seeing the current requested change.
The source needs exact current review state and historical decisions, with safe
recipient guidance and monotonic projection recovery—not a general comment engine.

### What hidden assumptions are we making?

That ordinary defects are often repairable, that source-approved guidance can
be understandable, and that non-remediable cases have an accountable resolution
path. These are a product choice and qualification obligations; no ministry
frequency or staffing capacity was measured. Same-evidence reassessment must be
lawful and substantive, not a bypass for real unmet criteria.

### How does this affect the whole product?

It defines the recoverable ordinary negative outcome while preserving source
final dispositions, Q03 corrections, Q21 acceptance and Q22 fulfillment. A current
safe participant projection is required, but old feedback/audit history and new
communication channels do not follow. No second authority lives in Tasks or custody.

### How does this affect the end-user experience?

The recipient sees the affected item, what needs attention and a permitted next
step. Staff retain valid work and can correct mistaken review through an attributable
new decision. Neither party needs a new request for a routine correction; technical
outages and staff delay are not disguised as recipient mistakes.

### Does this follow modern best practices?

Close collection products support targeted recoverable review. Stronger final
decisions exist in broader source processes. The chosen scope is sensible because
the ordinary surface remains small and explicit, not because finality is always
bad. Accessibility and security guidance supports clear feedback and current
authorization, not extra mandatory fields or imported workflow machinery.

### Does this fit Asym's existing repo and product direction?

Yes, with an explicit ordinary source outcome and safe participant projection
qualified at the existing owners. Adjacent finance reject semantics are not the
native contract. Full incorporated OpenSpec sections and canonical authors remain
authoritative. Specialist decline/waiver/cancellation and future reviewer routing
are not generalized into this button.

### Should we adjust the recommendation?

Keep A with eight clauses below. Make recovery possible through valid current
correction or substantive reassessment; preserve receipts/history and the actual
source/access rule. Require an accountable path for impossible work rather than
an arbitrary attempt cap, forced duplicate bytes or a hidden terminal outcome.

## Ratified corrected decision

For an ordinary native Document Request Item, use **Request changes** as the
recoverable negative-review outcome on exact currently unaccepted submitted
evidence. The requesting source records the authorized staff decision, its
current requirement/evidence/review basis and recipient-safe actionable guidance.
The item remains unsatisfied; the outcome does not itself correct a submission,
accept evidence, waive a requirement or create a terminal item rejection.

The recipient may use the existing Q03 correction path only while currently
authorized. A staff Request changes action is not a prerequisite for existing
self-correction and is not a new grant, extension or reopening. Preserve valid
supporting material, independent accepted items and prior received acts. New
submissions still require applicable technical checks and Q21 staff review.

Recovery SHALL not require meaningless new bytes. When the same current evidence
actually meets the current requirement, a fresh authorized exact-basis review
may accept it under Q21 and record how the earlier requested change is resolved.
Preserve the earlier review as history; no delete, generic Undo, automatic
resolution or acceptance override is introduced. A real requirement change must
use its own authorized source command/revision, not be smuggled into guidance.

The source SHALL order Request changes, correction admission, acceptance,
requirement changes and closure coherently, preserving one current authoritative
outcome and durable history/effect identity. Old retries and delayed projections
cannot reinstate a resolved change request or attach predecessor findings to new
evidence. Unknown outcomes require reconciliation; known source success survives
secondary task or communication failure.

Use the existing request review and participant context with a clear affected
item, sufficient safe guidance, truthful current status and real next action/help.
Genuinely non-remediable work must have an accountable qualified source resolution
path before activation; recoverable does not mean indefinite access or an endless
upload loop. Preserve existing specialist final dispositions and all Q06–Q22
access/fulfillment rules. No generic terminal item action, message default,
reviewer-routing engine, mandatory essay or whole Workflow Studio dependency
is added. Q23-C01–C08 and Q23-P01–P20 are required parts of this decision.

## Ownership, invariants and lifecycle

These are business distinctions, not a required new enum or workflow engine.
The source owns the review outcome/current applicability and permitted instruction;
custody owns byte/safety facts; P12 owns authority; P9 and communication owners
consume qualified source results. Prior decisions are history, not current commands.

| Situation                                        | Required meaning and transition                                                                                                                                                      |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Received but not yet sufficiently inspectable    | Technical recovery/checks remain separate; no fabricated business return or acceptance.                                                                                              |
| Eligible exact unaccepted evidence reviewed      | Authorized staff can accept under Q21 or record Request changes under this policy, using current source rules.                                                                       |
| Current changes requested                        | Item remains unsatisfied; show source-approved current guidance/available action. Existing recipient self-correction is not newly granted or restricted by needing staff initiation. |
| More than one concern or reviewer                | One coherent current source outcome/instruction, with currentness and retained history; no silent overwrite or stale contradictory demands.                                          |
| Same evidence later proves sufficient            | Fresh current authorized review may resolve the concern and accept; preserve prior decision and resolution evidence, without fabricated bytes or generic Undo.                       |
| Correction durably admitted                      | Q03 predecessor fence applies; older review remains attached to its actual basis. New evidence needs current checks/review; receipt is not acceptance.                               |
| Acceptance wins before return                    | Stale ordinary return cannot unaccept/reopen. Later remediation remains a separate source process.                                                                                   |
| Relevant source requirement or recipient changes | Apply actual source command/version/current disclosure; do not reinterpret earlier submission through a note or leak old guidance to a new recipient.                                |
| Optional nonblocking item or request closure     | Q22's complete predicate governs. A negative optional label alone cannot hold the request open; closure ends ordinary correction promises.                                           |
| Recipient access expires or is revoked           | Independently authorized staff work may continue; participant action/disclosure remains denied where required, with neutral owned help. No new clock/grant.                          |
| Replay, delayed consumer or restored state       | Recover original effect/history without restoring obsolete actionable status, changing actor/time or duplicating outward work; current restrictions remain.                          |
