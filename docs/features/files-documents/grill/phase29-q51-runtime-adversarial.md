## Outcome and the smallest complete path

Adopt **Notify a colleague on an already posted, currently active Q45 comment**, whether newly posted or older. One deliberate act selects one currently eligible staff person other than its actor. It produces one optional informational cue in the governed active-Tenant P17 staff center, not a task, assignment, mention parser, email, read receipt or obligation. Posting and editing comments remain Q45 acts and never implicitly notify.

The strongest simplification is **one synchronous source-owned transaction**. It validates current source/comment, actor, target and controls; occupies the source business slot; invokes the actual transaction-scoped complete one-member P6 compiler; releases that parent; creates the local P6 `available` event and P17 projection; and commits the source history and operation result together. Parent release precedes local materialization within this transaction. No private-child bypass or independently committed compiler transaction is allowed. A fault rolls back the entire attention act; Q45's already committed comment remains. Lost response after commit recovers that original result. A background notification queue, pending-cue TTL, provider attempts, lease worker or external outbox is unnecessary for this local-only slice.

This is a proposed compatible specialization, **not a claim the native compiler or reader exists or is already transaction-composable**. P6 §E allows the local available event without a provider call, while requiring its complete parent release. Proving that exact composition is an activation gate. If it cannot be implemented within its governed transaction boundary, do not quietly substitute an asynchronous partial-success path or claim that a queued intent is an available cue.

The once-only source slot is the exact Tenant/environment/source-owned comment and **current active Q45 visible revision + stable intended staff person + Q51 purpose**. Separate original assignment/role/access-revision pins govern presentation. Two requesters or transport keys cannot create two cues for that slot. Later genuine Q45 active revisions, including lawful Restore, can be explicitly notified; mutation alone never sends. The cost of this simple repeat rule is intentional: an unchanged comment cannot create another cue merely because it was read, archived, expired or the person's access returned. A genuine follow-up or existing qualified source coordination handles a new nudge. Technical recovery never requires reposting or fabricating a comment revision.

## Current primary technical checks

Context7 was queried for PostgreSQL 17 policy semantics and current Supabase role/function guidance; current primary pages were opened directly. [CREATE POLICY](https://www.postgresql.org/docs/17/sql-createpolicy.html) governs old-row USING versus new-row WITH CHECK, inheritance when the latter is omitted, combined permissive/restrictive policies, command-dependent SELECT/RETURNING, ON CONFLICT and MERGE checks. [Row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html) distinguishes grants, default deny, table owner, FORCE and bypass privileges. [CREATE FUNCTION](https://www.postgresql.org/docs/17/sql-createfunction.html) governs actual owner execution, safe search_path and explicit function privilege handling. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) separately documents client authentication and service-role behavior. These are semantics, not proof of Core's effective deployed policies.

For Q51, constraints must encode expressible identity/relation/uniqueness invariants; current capabilities belong to the single PDP/source enforcement path. Do not put an independently evolving second capability resolver inside RLS. Real-role tests must inspect the effective session, table/column/schema/function grants, inherited roles, owner/BYPASSRLS and policy composition. SQL and HTTP denial need not look identical internally, but application responses must not reveal protected existence through error details or counts.

## Fourteen exact proposed clauses

**C01 — Source act and scope.** Notify a colleague is a separate deliberate action on an already posted active Q45 comment, new or old. Resolve the immutable Tenant/environment/source/request/item/use/version/comment and current Q45 visible revision server-side. It never posts/edits a comment, follows a different file version, grants permission, assigns work or schedules another effect. One explicit other staff person per command; no self, groups, bulk, watchers, @ parsing or implicit composer effect. Notify may target the comment author when a different eligible actor invokes it.

**C02 — Real authority and recipient selection.** The actor needs current source-qualified create-comment authority and exact current comment read, within the one P12 context. The target needs the exact compatible active staff assignment and current comment/destination read for this purpose; no recipient-create capability or file-byte/preview right is imposed by association. Resolve a real stable native staff identity, not an email, display name, supplied profile or new identity-merging heuristic. Picker results are bounded, currently authorized and existence-safe; a picked row is rechecked on commit. No Party fabrication, donor enrolment, default Tenant, borrowed Support agent or direct address route. The exact P6/P17 staff no-Party branch must be explicitly qualified end to end where applicable.

**C03 — Atomic local success.** The entire attention admission, permanent source slot, complete one-member P6 parent release, local available event, P17 projection, protected source history and operation result commit once in a single actual source transaction. The compiler remains the sole producer entrance and its private child cannot commit independently. No event or projection is externally visible before release/commit; exactly one admitted local member is expected. Missing Live binding, unavailable required publication, unknown target/authority or incompatible destination rejects without a cue. Failure after any provisional write rolls everything back. Success means available in the qualified native channel, not seen/read. Post is independent. This specialization introduces no durable pending state, external prepared material, email profile, provider request or background send worker.

**C04 — Two identities and original replay.** A trusted operation identity binds its actor and immutable reviewed intent. Recover a matching committed operation before new-command eligibility/current revision checks, while independently limiting result disclosure now; changed input under that operation conflicts. Separately enforce the permanent business slot for exact Q45 revision + stable intended person + purpose within immutable source/Tenant/environment. A different currently authorized command/requester for that slot returns a safe already-requested outcome and no new event; do not feed changed requester input into the old P6 immutable envelope and call it a retry. Do not reveal the original requester, engagement or hidden assignment through this response. Current projection is separately read; late original responses cannot overwrite newer current state.

**C05 — Relevant concurrency and retries.** Validate the exact reviewed current comment revision, target assignment/access basis, relevant source/privacy context, applicable control basis and actual current authority in the serialized admission. Order these against Q45 edit/withdraw/Restore, real access/assignment loss and purpose Off. No blanket unrelated request revision, token/session reset or whole-Tenant content lock. Notify-first records the original revision and later end/restriction rules; edit/withdraw-first makes the stale command conflict/reject. A no-op Q45 save leaves its revision unchanged and cannot buy a new slot. A genuine later active revision, including lawful Restore, is eligible only for a fresh deliberate command. Database deadlock/serialization retry must rerun the exact bounded command/current checks, not mint another semantic identity.

**C06 — Information policy and exact clocks.** Explicitly select `presentation.information_30d_then_recent_90d@1` for this Q51 key: All only, never Needs attention. Actual committed availability starts both immutable UTC clocks. Unread ends at the earliest current-policy read/archive, correction/supersession, Q51 optional-purpose stop, or exactly available+30 days. Authorized recent presentation ends at exactly available+90 days even with late purge. Archive/restore and engagement never extend either boundary or create another cue. Event available status remains true historical local availability; read/archive/click is not source acknowledgement, assignment, acceptance, completion or a read receipt exposed to the sender.

**C07 — Optional controls and durable stops.** The qualified Q51 native purpose is On initially; this creates no automatic notices. Existing qualified Tenant and recipient optional-purpose controls may narrow it. A known Off before ordered admission rejects without consuming the business slot; unresolved effective policy fails closed. Since available commits in the same transaction, Off ordered before commit prevents that act; Off ordered after availability ends unread without fabricating read/archive, preserving only currently authorized minimal recent evidence to the original 90-day end. A durable intervening Off must be respected even if a worker/browser missed Off→On. On never revives unread or resets an occupied slot. Temporary inability to evaluate policy hides/fails closed, not a guessed known Off or fabricated terminal record. No global email suppression or cadence is adopted.

**C08 — Access loss, supersession and recovery.** Actual loss of the original bound assignment/access revision removes both active and recent presentation permanently for that occurrence. Current unknown/transient authorization failure hides it without asserting that loss. Later access or context changes never transfer or revive it, and the same-revision business slot remains occupied. A later genuine Q45 active revision can be explicitly notified under its new exact binding. Correction/supersession ends old unread but permits only lawful minimal recent context; a typed destination may show the current same comment with a Changed explanation, not another use/version or a historical body grant. Comment withdrawal/restriction/disposal obeys its actual Q45 disclosure policy. No source-status-only cancellation or completion rule overrides that policy. Source/recipient privacy repair may restrict a cue; no sender Recall/Undo is introduced. A wrong but eligible target does not require withdrawing the whole comment: notify the correct colleague separately, while the original recipient has normal engagement and applicable privacy repair.

**C09 — Safe content and every door.** Keep the event/header and local cue minimal, typed and source-owned. Do not copy private comment body, anchor geometry, filenames, staff labels, email/address, raw tokens or arbitrary URLs into a generic notice/telemetry envelope by convenience. Show only the exact currently permitted identity/context/preview fields; no field is safe solely because the target can read some row. Resolve destinations server-side through current Q45/P12 gates. Apply the same policy to picker, list, unread count, search, pagination, rendering, names/ARIA, mutation, direct API/DB/RPC, repair/support, exports, realtime invalidation and click. Never derive hidden rank/count/snippet from protected data. Identifiers in invalidation still require a lawful audience. No global browser/cache persistence, shared URL state or public-cache alias for protected context.

**C10 — Structural database and effective roles.** Use immutable, non-null same-scope relationships for the source comment/revision, stable recipient, original assignment/access binding, purpose, plan/event/projection and source result. Tenant attribution cannot be retargeted by update/upsert. Expressible unique/FK/check constraints enforce one source slot and one event/projection result; current eligibility stays in one PDP/source command, not in a fake cross-row CHECK. Keep required source history/result coherent and avoid cascades that erase retained dedup evidence. Enforce the current repository ENABLE/FORCE/owner/exception baseline and P12 coarse Tenant defense; neither proves fine-grained source access. Inspect effective anon/authenticated/service/guard/operator/owner/NHI routes, USING+WITH CHECK including inheritance, permissive/restrictive composition, SELECT/RETURNING, INSERT/UPDATE/DELETE/UPSERT/MERGE, triggers, views and direct/RPC/repair/bulk writers. Function safety includes PUBLIC and every direct/inherited EXECUTE grant, overload/schema access, owner/BYPASSRLS, current request context and fixed search_path. Unsafe doors must preserve the same boundary or remain closed.

**C11 — Read-model health and finite work.** One explicit target and one local transaction do not justify a platform queue or Realtime dependency. Bound picker input/result size, list pages, keyset cursors with a unique tie-breaker, preview/payload size, transaction/lock/deadlock retry, history and cleanup batches. Enforce current source/role/purpose set-wise within indexed queries rather than per-row network/PDP loops. Avoid per-keystroke writes, one query per badge/pin, full-center reloads or global count scans. Cache keys include actual Tenant/principal/assignment/context/purpose epochs; unknown currentness fails closed. Poll/refresh/cursor recovery can be sufficient; optional invalidation is not authority. Qualify actual workload/row bytes/index/CPU/egress and release budgets, not invented vendor-free or constant-time claims.

**C12 — Retention, restore and migration.** Separately govern short-lived role-safe preview/search/engagement and minimal permanent or owner-retained source-slot/replay evidence. P17's 90-day preview ceiling is not permission to delete the uniqueness evidence and resend. If old identity cannot be safely verified after disposal or restore, reject that stale replay rather than manufacture new work. Preserve compatible hash/token schema aliases through deployment/rollback; no namespace/version rekey. Restore preserves stops, original times, occupied slots, restrictions and current authority; it never creates unread from old comments/@text/queue rows. Cutover is future-only with one qualified writer and reader, bounded non-visible comparison if needed, no dual projection writer. Do not leak new fields through old SELECT \* readers. Source history remains independently governed; no unlimited private body retention is added.

**C13 — Honest recovery and audit.** Retain a safe operation reference and actual stage: no admission/rolled back, original available, already requested, current unavailable, or conflict. An unknown network result is not proof of failure or permission to rekey. Preserve selector/draft context where lawful on precommit failure; after commit, reconcile the original occurrence without another notice. Record actual actor, exact source revision, recipient binding, applicable policy basis, commit time, source/event/result IDs and reason-safe lifecycle evidence under protected audit. Operational logs contain bounded opaque correlation/reason codes, not body/address/filename/target-list data. Read-only/source repair owns invariant failures; operators cannot force-release, retarget, erase dedup or bypass access to clear an alert. No sender read-tracking surface is selected.

**C14 — Qualification and practical scope.** Before Live, prove the exact Q45 source action, stable-person resolver, no-Party branch where needed, P6 complete local plan, P17 information destination/control/end rules, one P12 enforcement path, real effective SQL roles, atomic crash/replay behavior and current viewer journey. Keep ordinary comment posting/read usable when this new optional capability is unqualified, and state why Notify is unavailable truthfully. No task/CRM-note universal thread, follower engine, multi-recipient composer, new role, provider channel, scheduler, cooldown graph or deployment-wide all-producer prerequisite is selected. The native source slice must be complete; mock UI or this model cannot qualify it.

## Isolated reference model — code prepared for one execution

The following stdlib model makes only serial source transitions and atomic-copy assumptions explicit. It is not the implementation, an actual compiler, SQL isolation/role proof, throughput test or provider exercise. Tenant/source/purpose are constants in the fixture; identity and policy decisions are booleans/tuples, not a PDP. It models the selected synchronous local path, so there is no durable pending state. The modeled availability integer is an assumed commit time. It does not prove real commit-clock integration, input normalization, sender/recipient UI, P6 hashes or all lifetime/retention mechanics.

```python
from copy import deepcopy

DAY = 86400

class Model:
    def __init__(self):
        self.rev = 1
        self.active = True
        self.on = True
        self.policy = 1
        self.access = {"bob": (1, 1, True), "cara": (2, 1, True)}
        self.slots = {}
        self.ops = {}
        self.cues = []

    def basis(self, person="bob"):
        return (self.rev, self.policy, self.access[person][:2])

    def notify(self, actor, op, person, basis, now, rights=True,
               disclose=True, fault=None):
        key = (actor, op)
        intent = (person, basis)
        if key in self.ops:
            old_intent, cue_id = self.ops[key]
            if old_intent != intent:
                return ("conflict", None)
            return ("replay", cue_id if disclose else None)
        if not rights or not self.active or actor == person:
            return ("denied", None)
        if basis != self.basis(person):
            return ("stale", None)
        if not self.on or not self.access[person][2]:
            return ("denied", None)
        slot = (self.rev, person, "q51")
        if slot in self.slots:
            return ("already_requested", None)
        staged = deepcopy((self.slots, self.ops, self.cues))
        slots, ops, cues = staged
        cue_id = len(cues)
        slots[slot] = cue_id
        if fault == "source":
            return ("rolled_back", None)
        # Assume the actual shared compiler would release exactly one member.
        if fault == "release":
            return ("rolled_back", None)
        cues.append({"id": cue_id, "rev": self.rev, "person": person,
                     "binding": self.access[person][:2], "available": now,
                     "unread_end": None, "access_lost": False})
        if fault == "projection":
            return ("rolled_back", None)
        ops[key] = (intent, cue_id)
        if fault == "result":
            return ("rolled_back", None)
        self.slots, self.ops, self.cues = staged
        return ("available", cue_id)

    def end_unread(self, now):
        for cue in self.cues:
            if cue["unread_end"] is None:
                cue["unread_end"] = now

    def control(self, on, now):
        if on == self.on:
            return
        self.policy += 1
        self.on = on
        if not on:
            self.end_unread(now)

    def change(self, now, active=True, material=True):
        if not material:
            return
        self.rev += 1
        self.active = active
        self.end_unread(now)

    def revoke(self, person):
        assignment, generation, _ = self.access[person]
        self.access[person] = (assignment, generation, False)
        for cue in self.cues:
            if cue["person"] == person:
                cue["access_lost"] = True

    def regrant(self, person):
        assignment, generation, _ = self.access[person]
        self.access[person] = (assignment, generation + 1, True)

    def view(self, cue_id, now, evaluation_known=True):
        cue = self.cues[cue_id]
        current = self.access[cue["person"]]
        if not evaluation_known:
            return "hidden_unknown"
        if (cue["access_lost"] or not current[2]
                or current[:2] != cue["binding"]
                or now >= cue["available"] + 90 * DAY):
            return "not_presentable"
        if cue["unread_end"] is not None or now >= cue["available"] + 30 * DAY:
            return "recent"
        return "unread"

checks = []

for first, second in (("alice", "dana"), ("dana", "alice")):
    m = Model(); b = m.basis()
    assert m.notify(first, "a", "bob", b, 100) == ("available", 0)
    assert m.notify(second, "b", "bob", b, 101) == ("already_requested", None)
    assert len(m.cues) == len(m.slots) == 1
checks.append("two requester orders: one business cue")

for first in ("notify", "edit"):

    if first == "notify":
        assert m.notify("alice", "a", "bob", b, 100)[0] == "available"
        m.change(101)
        assert m.view(0, 102) == "recent"
    else:
        m.change(100)
        assert m.notify("alice", "a", "bob", b, 101)[0] == "stale"
        assert not m.cues
checks.append("notify/edit orders: old revision never gains new unread")

for first in ("notify", "off"):

    else:

assert len(m.cues) == 1
assert m.notify("dana", "c", "bob", m.basis(), 107)[0] == "available"

checks.append("unknown evaluation versus actual access loss; explicit later Restore revision")
```
