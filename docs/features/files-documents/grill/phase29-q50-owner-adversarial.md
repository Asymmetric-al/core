## Judgment

**Accept with required amendments.** A is a small useful source-metadata capability when it preserves the difference between the current staff name, received provenance, evidence identity and delivery names. It is not a new source-wide document identity, a private alias per employee or a hidden participant-facing edit.

The strongest B remains a single current name shared with the authorized participant, which can improve conversation and recognition. That benefit does not justify silently selecting it after A. A instead needs enough permitted original/source context for staff to identify the same file with the participant, without exposing a denied original name or requiring another upload. Actual frequency and comparative user outcomes remain unmeasured.

Key prospective findings, calibrated to omission or naive implementation rather than alleged deployed defects:

- **High / likely if omitted:** a generic metadata serializer or delivery-name helper can disclose the internal name to participants, Q41 readers, public consumers, email or sealed exports. Treat this as a protected source field with explicit output purposes, not a harmless filename.
- **High / plausible:** equal bytes, a whole item, a correction or re-offer can accidentally inherit a stale or sensitive name. Preserve exact-use identity; newly admitted uses start without automatic name copying. Same-use lifecycle changes retain their name subject to current restrictions.
- **High / plausible:** an allowed text patch can mutate source scope, actor, version or approval through a broad update path; FORCE RLS alone does not prevent this. Use a closed current source action and exact resulting-state checks.
- **High / plausible:** denied or unavailable current-name lookup can be treated as empty, letting an actor blindly overwrite hidden content or leak its existence. Absence, denied disclosure and failed evaluation are different facts.
- **Medium / likely if omitted:** a lost response, stale expected revision or unchanged-looking value can replay an older name over a later correction. Permanent semantic recovery precedes new-action eligibility and canonical no-op; stale basis still conflicts.
- **Medium / plausible:** requiring preview, a received raw filename or unaccepted status for every edit would block useful lawful organization. The source controls eligibility independently; no blanket freeze or body-inspection ritual is justified.
- **High / plausible:** ordinary Clear or Undo can be mistaken for erasure of historical private text. Source-required history and privacy remediation remain separate; neither indefinite readable name history nor instant recall is selected.

## Exact proposed amendments

### O-C01 — One source-owned current staff name

Provide one optional plain-text current staff display name on an exact admitted ordinary Private Document Request evidence contribution/use, whether participant-origin or independently qualified staff-supplied. Share that field only with staff whose current source projection permits it. The name is not per-viewer, a whole item's title, a tag, a global blob name, a provider key or a universal Logical Document. Different source uses of equal bytes remain independent. Specialist sources retain their actual naming/discard/official-identity rules.

### O-C02 — Meaning and lifecycle stay separate

Setting, changing or clearing the name changes only this metadata and its required history/result. Preserve immutable use/version/recipient/receipt/actor identities, exact bytes and digest, received provenance, source instructions/currentness, acceptance and fulfillment, shares, retention and disposition. A name such as Approved or an extension-like suffix is not source status, actual MIME or a successful safety check. Mere naming does not advance evidence/review/instruction basis, reset proof or create recipient work. Independently governed existing effects retain their own actual contracts; add no naming-notification purpose.

### O-C03 — Same use persists; new use starts independently

A non-byte or lifecycle change to the same exact use preserves its current name unless a lawful source/privacy action changes or suppresses it. A newly admitted independent contribution, Q03 correction, Q28 reuse/replacement or Q47 re-offer candidate starts without an automatically copied staff name. Equal bytes, an item, a predecessor name/folder or replay cannot establish name inheritance. This is the explicit small ordinary default, not an inferred global law. It does not block lawful receipt or alter Q42 home-only initialization. Naming a successor later is a separate currently authorized metadata act.

### O-C04 — Real current read/edit powers and permissible states

Adopt an explicit ordinary source/P12 metadata-maintenance action, separate from evidence Read, review responsibility, folder/view visibility, creator identity and role labels. A current qualified staff actor may maintain the field without the original editor's live session; no generic private-record takeover follows. The actual source may permit an admitted Checking, rejected, accepted, historical, withdrawn, fulfilled, canceled or retained use to be named. No status alone allows or forbids it; a real source freeze, privacy restriction, disposition or missing current authority still wins. Do not require preview or original download merely to edit safely identifiable metadata. Actual policy/classification widening retains P3/P12's approval rules; ordinary within-policy editing gains no routine second approver.

### O-C05 — Explicit absence and a safe fallback

Distinguish a source-proved unset name from a denied field, unknown authorization and failed lookup. Use only the current source-approved fallback identifier and context when the name is unset or its disclosure is not permitted, and only where that fallback is itself lawful. Do not reveal a hidden-name indicator, infer no evidence, leak the hidden text through sorting or revive discarded/raw provider filenames. Original received-name facts are independently retained and disclosed under source policy, not guaranteed public provenance. Source/item/version context can disambiguate permitted same-name entries without viewing bytes. If current authorized facts cannot safely identify the edit target/basis, give capable source recovery; do not enable a blind overwrite or Clear against a fabricated empty value.

### O-C06 — Small deliberate Set/Edit/Clear

Use one single-line plain-text edit, with clear staff-only audience guidance, Save and Cancel and a visible way to clear the optional name. A canonically empty value after the declared whitespace handling means deliberate Clear, not mandatory naming or loss of evidence. Cancel has no source effect. Preserve significant Unicode/international display text; use a declared bounded validation/counting contract, reject unsupported controls or over-limit input clearly and never silently truncate or coerce the label into a filesystem path. Names need not be unique; no collision-driven merge, automatic suffix or extension/type rewrite is needed. No essay, approval ceremony, editor, bulk rename, template, translation or semantic classifier is required.

### O-C07 — Coherent current mutation and recovery

Derive actor, Tenant/environment and immutable source/use context on the server. Commit current name/revision, trusted attribution, required restricted history and semantic outcome coherently through one source command. Bind current expected name basis and relevant source/authority dependencies; do not use unrelated whole-request revisions to force pointless reconfirmation. Recover matching committed intent under current safe result disclosure before new eligibility/no-op evaluation. Changed material intent conflicts. For a new command, current authority and expected basis precede canonical no-op; an intervening change away and back is not the reviewed revision. No-op creates no business change event/revision/history/count, while independently required access/security evidence remains. Lost response recovery never repeats an old rename over a newer one. Undo, if offered, is a newly reviewed eligible forward edit, not a history rollback.

### O-C08 — Staff-only at every output

Do not make this field a generic replacement for `filename`, `name`, title or accessible-label serialization. Under A it is excluded from participant/public/Q41-reader projections and their payloads, suggestions, captions, accessible names, filenames/headers, notifications, manifests, URLs and caches. ### O-C09 — Search and shared views consume current authority

Admit the staff display name to Q38 matching/display only through an explicit approved-field mapping and current source/field authority, preserving the body-search boundary. Safe plain text does not authorize copying private care notes or document bodies into general discovery. Apply actual source restrictions before rank, facets, counts, ordering and predicates. Relevant new restrictions fence serving before cleanup. Preserve exact selected row identity and lawful focus/return state when name sorting/filtering removes or moves a row.
