## Disposition and smallest complete model

**Accept with required amendments.** A is viable without a new sharing engine. Use the same stable owned saved-view identity: explicit **Share view** promotes the exact reviewed private definition and finite audience in one coherent operation. Local filter experiments remain local; later persistent edits use an explicit **Save shared view** action. **Save personal copy**, if offered, deliberately allocates a new private identity with no inherited audience or management grants. There is no concrete integrity reason to mandate a separate published copy for every Share.

This refines an earlier conservative research preference for preserving an independent private copy. The question promised private-by-default and deliberate sharing, not an automatic permanent duplicate. Same-ID promotion is simpler if its state/command boundary is real: stale private PUT/DELETE requests, autosave, profile cascades and old code must not treat the shared object as still personal.

The first reader audience is a finite explicitly selected set of currently eligible same-Tenant/environment staff **Active Tenant Assignments**, within the publisher's actual ordinary-source audience envelope. No raw profiles, emails, Parties, demo teams, Support teams, automatic Everyone or unqualified group model. This does not grant membership, role/capability, field/row access, export, download or Q41 share authority.

The shared definition becomes source-owned for lifecycle/history, with immutable creator attribution and a separately current maintainer. **Unshare** clears the reader audience and leaves the retained definition owner-private under current maintenance/source authority. Deliberate reshare is a new qualified act, never replay of an old Share. A scoped source administrator has a concrete transfer/withdraw remedy when the maintainer leaves. Author departure alone does not erase independently valid current viewer access; actual continuing definition/source restrictions and applicable P12 dependencies still apply.

## Exact proposed amendments

### C01 — Scope and actual meaning of A

Within the Tenant × environment × ordinary-request finder, ordinary view-authoring scope may include deliberate sharing of an eligible owned view to an explicit audience inside the actor's current source/P12 publication envelope, without separate manager designation. It does not confer the underlying capability or widen that envelope. Any actual grant, protected permission/audience-policy expansion, self-benefit or separation-of-duties event follows existing P12/P3 governance.

The audience is a finite reviewed set of exact eligible same-scope staff Active Tenant Assignments, resolved on the server. No automatic future staff, groups/Everyone, email/profile/Party fallback or alternate hat union is introduced. No external/participant view library, row/data permission, folder placement, evidence state, notification, export or Q41 grant changes.

### C02 — Same stable identity and explicit persistent intent

Private views remain private until explicit Share of their exact reviewed current definition. Share atomically promotes that stable view identity with its reviewed audience and current maintenance/source basis. Keep immutable creator attribution; publishing does not grant readers editing rights.

After promotion, transient filters/sort/columns remain a local working state. Persistent global changes require explicit Save shared view with expected definition/publication state. A stale private-save/delete request, autosave, default-reset or old client cannot mutate the now-shared object as personal. If offered, Save personal copy is deliberate, creates a new private ID from an exact currently readable/authorable definition and carries no audience, other-person default, grants or authorship falsification. Copying does not copy files or source authority.

### C03 — Finite current audience and protected definition

At Share and audience update, prove current actor authority, exact current definition disclosure compatibility, every selected assignment's same-scope identity/eligibility and the permitted audience envelope. Commit the complete reviewed set or none; duplicate/cross-scope/missing/over-limit/unknown members must not silently produce a partially shared view. Finite explicit selection does not require preexisting permission to read every future matched row.

At list/open/use, independently prove the viewer's current active assignment, membership in the view's retained selected audience or legitimate current maintenance-read authority, and current definition/source restrictions. The maintainer's management read grants no access to other people's result rows. Never identify audience by bare person/email or retarget an ended/recreated assignment to a newer one.

This is a live query definition, not an email delivery cohort. Temporary inability to prove current access may clear through the actual owner-qualified repair for the same retained assignment and unchanged view terms. Do not permanently burn an audience entry merely because of a temporary denial. Explicit audience removal, Unshare, deletion or actual source termination is not undone by later role recovery; adding/re-sharing is a new deliberate qualified act. New staff are never added automatically.

### C04 — Exact query/schema/default meaning and safe invalidity

Use the actual approved P9/source typed definition schema and Q38 field/operator/sort/column allowlists. Validate the entire versioned definition and relevant references before publication, save, copy and execution. Unknown versions, fields/operators, malformed nested groups, obsolete/private criteria or missing required source/default basis cannot be dropped, coerced or replaced with “all.” This includes definitions restored from storage, not only new request payloads.

Compile admitted typed predicates through the qualified parameterized query boundary. Stored definitions contain no raw SQL/JavaScript, arbitrary expression, unqualified JSON-field path or caller-provided execution authority. Bound the parsed tree before query execution; a syntactically valid oversized definition is not an admitted workload.

Bind the reviewed operative query meaning and its schema/default basis. P9's delta storage need not be replaced, but a tenant/system default or schema change must not silently broaden a shared predicate, retarget a field/reference or mutate the author's meaning. Qualified compatible migrations may preserve exact meaning; material incompatible change becomes safely invalid/repairable and requires deliberate correction. Stable folder/label IDs survive rename; deleted/denied criteria remain safe invalidity, not broader fallback.

Viewer-relative predicates, if actually supported, resolve in the viewer's current context with explicit meaning; no hidden author-as-viewer substitution. A view is a live query lens, not static membership, a review queue, SLA or complete audit of pending work.

Typed relative-date/time predicates must also declare their clock/time-zone meaning and execution/continuation basis. Share, Save shared and execution revalidate the actual schema/default basis; browser locale, server time zone or an unrelated default change cannot silently rewrite that meaning. This is precise query interpretation, not a new scheduling engine.

### C05 — Separate definition disclosure, per-viewer results and result actions

Protect titles, descriptions, criteria/values, labels/folders, audience information, revision/history, suggestions, counts and error output as data in their own right. A visible container or zero visible rows does not authorize a protected criterion. Render only current permitted facts; unknown permission/coverage is unavailable/incomplete, not a proved empty view. No filtering-after-serialization, hidden counts or author-result cache.

Execute the exact valid view revision against each viewer's current Q38/source permission and coverage. Authorized metadata need not wait for file preview, and query access grants no history/bytes by itself. Pagination/continuation binds the actual query revision/scope; a material definition change cannot silently continue an old cursor as a different query.

Any supported row action, finite copy/export/download/share or bulk operation must reprove its own source/action authority and bind its exact admitted selection/query basis. Removing a view never turns an action into “all records.” Already-admitted independent source actions follow their own qualified recovery/currentness contract; Q43 neither recalls lawful prior disclosure nor invents an export feature or a new global cancellation rule.

### C06 — Small permanent maintenance, Unshare and departure recovery

Current maintainer/source powers separately govern Save shared, audience changes, Unshare, transfer and deletion. Creator is provenance, not perpetual permission. Author departure or loss of publishing rights ends their affected writes; it does not by itself delete a valid shared definition or act as an invented universal creator-read ceiling. Actual current definition/source eligibility and any applicable P12 grantor/restriction dependency still control.

Unshare clears the reader audience and retains the definition owner-private under its current lawful maintainer/source authority; private original identity is not duplicated automatically. Deliberate reshare requires a new reviewed command, current definition and audience proof. Scoped source administration can transfer maintenance to an eligible exact assignment or withdraw a stranded view without broad record-read grants, forced IAM bypass or routine SQL. Transfer does not change creator/history, audience, filters or row rights, and the candidate maintainer must qualify independently.

Delete/retire removes the view from ordinary use while preserving required audit/semantic identity under owner retention; it deletes no files, folders, source uses or personal copies already independently admitted. Personal Hide/unpin is not global deletion. Temporary invalid/unavailable source or proof state is distinct from actual Unshare/deletion; only proper current repair may restore availability, never old replay. No mandatory second maintainer or approval queue is added.

Where the source retains a retired definition for supported recovery, a qualified current maintainer/steward restores it only as private after current validation; no former audience is restored. Publishing it again requires a new deliberate Share. Read-only audience membership never confers edit, transfer or recovery power; these remain with the current maintainer and explicitly scoped source stewards.

### C07 — One coherent command and exact permanent replay

Share/Save shared/audience update/Unshare/transfer/delete bind immutable view/scope/actor identity, expected definition/publication/audience/maintainer state and reviewed material. Revalidate current source/P12 facts at commitment. Coherently commit the full effect, required restricted history and durable operation result. Failures before commitment leave prior facts intact; unknown acknowledgement reconciles the original operation.

Recover a matching committed semantic operation before new-command eligibility/no-op checks, under current result-disclosure authority. Old Share must not republish after Unshare; old update cannot overwrite a later revision or transfer; old delete cannot target a replacement. Changed payload under one identity conflicts. New deliberate operations use new identities and current expected state. Preserve minimum semantic/result evidence or reject unverifiable stale operations after readable-history expiry/restore; do not require perpetual readable private history.

An exact no-change save is truthfully unchanged, not a new source event. A wrapper request ID, provider transport key, timestamp alone or current projection is not durable semantic identity.

### C08 — Precise concurrent ordering without a global lock

Use the existing native transactional/source/policy boundaries to order overlapping writes. Prove Share versus private edit/delete; definition edit versus audience change; two concurrent edits; maintainer transfer versus old-author write; Unshare/delete versus Share/read/copy; selected-assignment end/restriction versus publication/read; and default/schema/reference change versus publication/query. Relevant scope/current policy facts must be fenced at actual admission, not merely checked before a network call.

Readers receive one coherent valid definition/audience/maintenance basis, not new public metadata with an old predicate or a half-updated audience. Apply current disclosure at the serving boundary and suppress obsolete responses. Do not lock an entire tenant library for a reader, hold provider calls in transactions or promise recall of previously valid output. Deadlock/serialization retry repeats the same intent within finite bounds.

### C09 — Structural SQL and every real authorization door

Native rows must structurally bind immutable Tenant/environment/source namespace, stable view identity, definition/publication version, creator provenance, current maintainer and typed audience-assignment references. Enforce same-scope relationships and unique audience membership/one current head with native keys/constraints, plus command-level current eligibility. Separate immutable attribution from the one explicitly authorized maintainer change. A profile FK cascade must not own deletion of a shared source record.

Preserve P12's single-PDP design: database RLS supplies its actual coarse Tenant defense, while the verified PDP/source enforcement boundary owns fine-grained definition, audience, field and result decisions. Do not duplicate the membership/capability resolver inside RLS. A raw database/API door must preserve that verified decision/projection boundary or be closed; coarse same-Tenant RLS alone cannot expose all private/shared definitions. View identity is an opaque ID, not its name; do not introduce global name uniqueness or hidden-name collision errors as an existence oracle.

Inventory actual grants/default grants/API exposure, role inheritance, all applicable permissive/restrictive policies, views, functions, triggers and direct writers. Test SELECT, INSERT, UPDATE, UPSERT and DELETE old-row and proposed-row behavior, including mutation responses; an omitted WITH CHECK may inherit USING, so evaluate the actual effective rule. Protect against retargeting tenant/source/creator/audience/approval fields even when an actor can access both targets.

Service-role/owner/BYPASSRLS and SECURITY DEFINER paths need the real trusted source command and current predicates; RLS enabled does not cover them automatically. Restrict raw personal APIs against shared rows, function EXECUTE/search paths, CMS/REST/GraphQL/browser collections/jobs/imports/backfill/trigger writes, and invoker-view behavior. A client boolean or a typed but unverified context is not source authority. Normalize errors to avoid hidden view/assignment/reference enumeration.

### C10 — Personal defaults and focused experience stay independent

Availability in the shared library does not replace another user's default, pinned order, local filters or active work. Existing tenant/system defaults and policy management stay separate. A removed/invalid active shared view is visibly unavailable with safe recovery; never silently fall through to a broad tenant/system query while labeling it as that view.

Use one clear Share review with exact intended audience and meaningful consequence, and explicit Save shared/Unshare versus local/private actions. Preserve unsaved working state safely during validation/conflict/network failure; no mandatory email, routine reason, extra approver or full audience directory loading. Show known success, conflict, unavailable and unknown result accurately; a refresh failure after commit does not claim rollback. Mobile/keyboard/non-drag pointer/screen-reader flows use shared Base UI/base-maia controls.

### C11 — Private delivery, finite work and useful audit

Do not put protected title/filter/audience values or content in public URLs, metadata/social previews, public caches, analytics, logs, crash output or unprivileged error strings. Qualified direct query-context links remain supported through safe source-owned references or a proved non-sensitive representation; possession is never a bearer grant. Do not persist private definitions/results offline or queue unreviewed mutations for later silent replay.

Scope client/server caches and in-flight response fencing to the actual actor/assignment/Tenant/environment/purpose, source/policy, view revision and audience dependencies. Existing signout/user-switch cleanup is useful but insufficient evidence for same-user assignment/audience changes. No cache should return another viewer's results or author counts.

Set measured finite launch bounds for explicit audience size, catalog/page results, definition bytes/nesting/predicates/sorts/columns, query/reference checks, transaction/lock retries, response size, cache lifetime and history/recovery retention. Use indexed server-side current authorization, no full membership expansion or per-result remote calls. Retain restricted safe business history separately from redacted operational metrics. No new vendor, body index, sync/event platform, notification engine or “free because Postgres” claim is needed.

### C12 — Prospective migration and affected-door release

Keep all existing personal views private unless their owners later perform the newly qualified Share command. Do not infer audience from a default/delegate list, team, author role, profile or historical sharing URL. Reconcile actual ordinary source/P9/P12 schema and capability authorities before activation; the prepared capability files alone cannot authorize requests.

Deploy additively with effective constraints/current authorization before writers. Fence old personal commands, cascade behavior, imports and old tabs before same-ID promotion is possible. Rehearse mixed old/new readers/writers, unknown schema versions and existing private/default data preservation. Do not enable public enum values by migration default or convert tenant default settings into published definitions.

Disable only affected shared operations/derived serving on failure while qualified personal/source work remains usable. Preserve shared identity/history and current denials on rollback/restore. Never restore a prior audience, maintainer, deleted ID or old Share operation as current authority. Supported qualified forward repair replaces ad hoc SQL. Release requires real role/source/transaction/race/privacy/query/load/user proof, not mocked services or document parity.
