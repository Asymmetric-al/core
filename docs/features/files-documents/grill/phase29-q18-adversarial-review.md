## Adversarial check

### What could go wrong with this answer?

“Thirty days” could become a month, local calendar addition, a reset on retry,
a guaranteed minimum, or a single oversized timer. State the exact interval
and preserve the original source result under scoped current restrictions.

### What hidden assumptions are we making?

That intended recipients have a useful chance to return within this fixed
period and that the future native source implements the qualified contract.
Comparable defaults and correct multiplication prove neither assumption.

### How does this affect the whole product?

It supplies one standard Q08 interval for both Q16 origins without changing
completion, original files, evidence acceptance, custody or another domain's
time policy. Equal numbers must not create shared ownership accidentally.

### How does this affect the end-user experience?

Use the same action and one actual date/time/zone. Late arrival has the real
remainder; unused access ends normally. Current proof or preview trouble needs
truthful recovery, not a new activation step or hidden deadline extension.

### Does this follow modern best practices?

Finite thirty-day windows are documented in comparable products. The choice
is reasonable, not empirically optimal. Exact instants, immutable retry results,
current authorization and accessible status make it a coherent Core profile.

### Does this fit Asym’s existing repo and product direction?

Yes through a scoped numerical successor to Q08/Q17 and preservation of Q16.
It does not turn Asym into a personal file store or import specialist newsletter,
coaching, official-document or transfer-product permissions.

### Should we adjust the recommendation?

Keep A with exact elapsed arithmetic, safe finite bounds, real scope/expiry
semantics, preserved effects and lean UX. The implementation should reuse
existing owner mechanisms; a dedicated countdown/renewal platform is unwarranted.

## Quantities, ownership and invariants

Let G be this new qualified source occurrence and N the nominal end, solely as
explanatory notation: **N = G + 2,592,000 seconds**. The admitted grant end may
be earlier under real grant-wide limits. This review does not prescribe extra
columns, a second grant table or a new clock authority. Record enough trusted
policy/limit evidence to preserve and explain the actual source result.

The source owns G, actual end, material policy/limit evidence and semantic
effect; P12/Auth owns exact current issuance administration and recipient use;
custody owns originals/renditions/disposition; communication owns its separately
authorized outcomes. Display, cache, scheduler, lease and provider TTL are not
authoritative permission facts. One grant end is not a promise that every
member remains usable to that date.

Source data must enforce exact tenant/environment/recipient/request/admission/
member/effect relationships, semantic uniqueness, required finite values,
valid transitions and trusted actor/owner/approval/audit attribution. Validate
units, supported precision/range and conversion/rounding without silently
changing an end. Expressing the duration in whole seconds does not permit
truncating the source occurrence. A nullable CHECK can pass an unknown result,
timestamp types can represent infinity, and a CHECK is not rerun just because
time passes; qualify required finite values and current enforcement separately.
An allowed update/upsert/parent change cannot retarget the
scope, alter original timing or widen rights. Preserve later adverse facts;
delete behavior, migrations and backfills must not erase replay/audit truth or
create a new access basis. No money precision change is introduced.

Qualify effective grants and SELECT/INSERT/UPDATE/DELETE, old-row USING and
resulting-row WITH CHECK, policy composition, column rights, view/function/RPC/
definer/service/job/storage behavior. A literal missing WITH CHECK is not alone
a defect because applicable policies can inherit USING. RLS and same-tenant
foreign keys alone do not establish the exact recipient/action boundary;
privileged paths need the source/P12 checks. Current local SQL is adjacent
evidence, not a deployed native grant policy certified by this review.

Q17's lifecycle remains: not dispatched, known no effect, unknown commitment,
committed with a resolved end, currently usable or scoped unavailable, ended/
revoked, and protected historical recovery. Q18 adds no first-use state or
further fulfillment transition. Current restrictions/authority and deadline
races still need source-qualified ordering and checks after waits. Expiry
does not require a stored status update at the exact millisecond to be true.
