## Recommended next genuine choice

**Should authorized source staff be able to add an additional ordinary requested item to the same eligible issued unfinished request for its continuing purpose and intended recipient, or should that additional work use a separately authorized new request?**

Recommend **A — Allow a deliberate same-request addition.** Keep genuinely related unfinished work together, show that the item was added and what remains, and preserve previous submissions/decisions. This is an exact source amendment with a current qualified participant scope; it is not an Add row shortcut that silently widens an old grant, resets time or edits earlier requirements.

**B — Request the additional item separately.** Use independently authorized normal original issuance for the new need, with its own scope, readiness and actual admission. Preserve the original request and let it fulfill under its own complete rule. This gives a clearer fixed boundary to issued scope and avoids same-request amendment complexity, but can split one piece of work across requests. B does not require another account, needless re-confirmation or duplicate upload when Q01 proof/Q28 exact evidence reuse is independently permitted. It neither cancels nor automatically clones/reissues the original request.

No artificial third option is needed. The question is about **adding a new ordinary item**, not changing an existing item's meaning, replacing its requested type, changing recipient/purpose, editing a template, reopening fulfillment/cancellation or choosing another email default. It is a more substantive frontier choice than mechanically following Q35 with another notification setting.

A is useful when staff discover a genuine omission while related work is still underway. For example, Elena's ordinary equipment-handover request to Nora includes the inventory and a condition report, but omits a packing list. A adds the packing-list item to that same still-unfinished request, visibly and under current permission. B sends a separate qualified request for the packing list and leaves the original's completion independent. Avoid application/consent/finance/care examples that imply an ordinary document action owns a specialist requirement.

The practical cost of A is also meaningful: a newly required item can keep the same request unfinished. Staff must see that consequence, and the participant must not be told earlier work was late, rejected or insufficient merely because staff added a new demand later. B's original request can finish independently, at the cost of another request context. No measured Asym frequency, preference or time-saving evidence establishes either choice as universally best.

## The scope amendment A would need

A must be a complete useful addition, not a source draft that no intended participant can ever use. The source deliberately defines the new item and its current ordinary requiredness/instructions/review basis, retains the original request and amendment history, and explicitly admits the newly added scope for the same eligible intended recipient and continuing purpose where authorized.

For an original or already-qualified fresh unfinished period that is currently valid, the addition needs an explicit prospective scope decision preserving that period's exact end and every earlier cap/current restriction. An existing credential/proof may be reused only through its qualified owner rule; an unchanged email or an old request token cannot automatically confer the new item's rights. Preserve unaffected old-item work rather than invalidating everything just because an aggregate revision number changed.

If participant access already expired, the source cannot revive it by adding an item. Useful participation requires separately authorized fresh unfinished admission under the existing timing/repetition rules, with Q36 explicitly reconciling Q13-C06/Q15 to include the legitimate newly approved requirement lineage where allowed. Otherwise the new need uses B. This is a proposed necessary dependency of A, not a currently ratified grant expansion, automatic renewal, new duration or promise that every expired source remains eligible.

The historical original grant/requirement set remains true; the new authority belongs to an attributable prospective amendment, not a rewritten original admission. New recipient/purpose, materially different assurance or specialist scope must not slip through “same request.” Exact source policies may require stronger proof/current action permissions, and those requirements remain. Q08/Q16 completed-reading scope must not expand merely because a source row now contains another item. Once actual fulfillment or cancellation wins, A cannot reopen the record; use the independently qualified new-request/source remedy.

This access consequence is significant enough to state in the question. It is not necessary to select physical grant tables, token shapes or a new permission taxonomy before the founder chooses A/B, but it is necessary to avoid implying that old grants already permit the added work. The selected-answer review must close the exact original/fresh/expired/completed mappings before activation.
