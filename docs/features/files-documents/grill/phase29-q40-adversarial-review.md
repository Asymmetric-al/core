## Conclusion and alternatives

Keep the optional email in the existing Add item/Update instructions review,
initially On when qualified. Give the tenant real availability/default controls
and staff a clear per-publication choice. This helps a recipient learn about an
actual published update without having to discover it on a later visit.

The strongest B is the same integrated capability initially Off: it better
guards deliberate communication when changes are frequent or staff already
coordinate directly. Native on-return guidance plus an existing qualified manual
contact route is a smaller no-build alternative, with additional remembered
follow-up. No Asym frequency, missed-update, fatigue or conversion data establishes
the magnitude of those tradeoffs. A is a bounded product judgment, not a universal
best practice or measured ministry need.

The important refinements are practical: a notice must not manufacture work or
access; a disabled or superseded notice must not wake up later; mail failure must
not repeat the source update; and a combined fresh-access action must not silently
request two similar emails. The solution uses existing source/P17/P6 mechanisms,
not a new notification platform, digest, scheduler or configurable rules engine.
