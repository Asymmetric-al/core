## Primary technical verification and authority

Context7 was not exposed in the current inventory. Current direct official documentation was consulted:

- [PostgreSQL 17 CREATE POLICY](https://www.postgresql.org/docs/17/sql-createpolicy.html): command-specific old-row USING/resulting-row checks; UPDATE/ALL can inherit USING without explicit CHECK. Permissive OR/restrictive AND, SELECT/RETURNING, UPSERT/MERGE and trigger transformations require effective proof. Omission alone is not a vulnerability.
- [CREATE FUNCTION](https://www.postgresql.org/docs/17/sql-createfunction.html): invoker uses caller privileges, definer actual owner privileges. Inspect owner/search_path/overloads and PUBLIC/named/default grants. Definer is not a universal bypass label.
- [Transaction isolation](https://www.postgresql.org/docs/17/transaction-iso.html): successive statements can see different facts. Require coherent source ordering/constraints/bounded retries, not an SDK-atomicity or isolation-name assumption.
- [Supabase sessions](https://supabase.com/docs/guides/auth/sessions): token/session lifetime is distinct from source membership/grant currentness. No generic token duration becomes resource policy.
- [Changelog](https://supabase.com/changelog.md) and relevant linked pages read: [new-table Data API grants](https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically) require explicit new-table grants while existing grants survive; [TLS](https://supabase.com/changelog/cbc-tls-ciphers-deprecated) removes an older project HTTP cipher subset from 10 November at earliest; [15.19/17.11](https://supabase.com/changelog/postgres-15-19-17-11-breaking-changes) has conditional extension/operator upgrade implications. These require applicable release compatibility, not new extensions/upgrades or a claim of deployed settings.
