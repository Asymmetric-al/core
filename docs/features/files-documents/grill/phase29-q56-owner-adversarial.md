## Finding and permanent product recommendation

The useful increment is one optional way to prepare an ordered document for one existing ordinary request item. It must not create a mutable bundle whose individual pages accidentally acquire different acceptance, withdrawal or correction states. A single source-owned contribution should bind the exact selected image originals, their ordered page recipe and one immutable Assembled PDF. Originals and output remain separately identifiable files, with distinct provenance and current action rights.

The strongest A-only alternative remains sound: deliver direct camera/photo/multifile and prepared-PDF intake well, using suitable device tools where independently permitted. It avoids the assembly processor and input/output lifecycle. The user has now deliberately chosen B's in-task continuity as well; this review preserves that benefit without claiming measured demand, lower bills, fidelity, authenticity or universal accessible-PDF output. No additional scanner/editor/OCR product is necessary.

The material amendments are: an ordinary composition unit and actual current creator authority; trusted generation rather than trusting a browser PDF manifest; whole-unit admission before Q03 predecessor fencing; exact original/output readback; whole-unit correction/withdrawal/re-offer with narrow own-input reuse; truthful staff origin; explicit derived-output consumers; and source retention distinct from D32's dispensable preview clock. All are concrete product/source decisions, not implementation details to leave unnamed.

## Proposed vocabulary — pending ratification only

**Document Assembly:** A source-owned contribution that presents an ordered set of selected image originals as one assembled document. It preserves the identity of its originals and assembled output and is distinct from a Document Request Item, an original file, a preview and item acceptance.

Suggested Avoid: merged files, original PDF, preview, accepted evidence.

Two existing definitions need minimal widening for the actual whole-unit source fact, with their Avoid lists unchanged:

**Submission Confirmation:** The source's record that an exact file version or Document Assembly was durably received for a Private Document Request. It does not mean the received material is safe to preview or that the requested business evidence has been accepted.

**Staff-supplied Document Evidence:** An exact file version or Document Assembly deliberately supplied by authorized staff for a Document Request Item, with attribution to that staff act. It is distinct from a participant's submission or affirmation, item acceptance and permission for other uses.

Submitted Original stays unchanged; Assembled PDF is a useful output label, not a second domain entity. Document Review Comment already binds an exact use/file version; qualifying the output cohort does not require changing that definition. All31 canonical terms remain untouched pending full-package ratification; this proposal would yield32 terms with two precise refinements, not an engineering schema glossary.

## Adversarial check

### What could go wrong with this answer?

The output can omit or change evidence, an input page can be independently withdrawn from an accepted group, or D32 cleanup can erase the exact reviewed PDF. The exact whole-unit, trusted profile and source-retention amendments prevent those distinct failures; a visual demo cannot prove them.

### What hidden assumptions are we making?

We assume an eligible ordinary item accepts this representation and actual current participant/staff powers exist. We have no measured device mix, paper volume, billing benefit or complete renderer proof. Browser manifests and camera permissions are not trusted provenance.

### How does this affect the whole product?

This adds a narrow source composition/derived-output contract atop existing custody. It must explicitly reach correction, withdrawal, review, current reads, export/comment/name consumers and restore. It adds no general editor, official-document authority, financial acceptance or broader resource audience.

### How does this affect the end-user experience?

Users keep direct uploads and gain optional ordered assembly with one deliberate source intent, non-drag controls and recoverable whole-unit mistakes. Own-input reuse avoids repeated transfer. Exact original/output labels and genuine capable assistance matter more than an extra confirmation ritual.

### Does this follow modern best practices?

It uses documented layered hostile-file handling, non-drag accessibility and truthful image-PDF limitations. Comparator tools demonstrate workflows, not the proper source authority or retention rule. The selected convenience remains a product judgment requiring actual native qualification.

### Does this fit Asym's existing repo and product direction?

Yes, with explicit ordinary-source and shared-custody adoption and one P12 authority. The current avatar/crop or template-PDF seams are unsuitable as implicit evidence contracts. Existing D32 reading can be reused without inheriting its dispensable-output retention or broadening Support authority.

Accept A+B with these required amendments. Retain the simpler A-only alternative as the rejected scope choice, not an automatic fallback that changes selected product.
