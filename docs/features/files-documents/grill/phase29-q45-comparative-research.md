## The genuine open choice

The founder's §10 already requires useful staff review comments tied to the intended version, page/location where supported, and business purpose. Q29 provides paired exact-version reading without generic automated difference claims. Q30 explicitly preserves mandatory staff version comments while selecting a separate participant item-question/reply path. Therefore comments versus no comments is not a fair question, and participant conversation is not the unresolved frontier.

The remaining choice is **how precisely a staff comment can point within its exact file version**:

| Option                                                                                  | Actual experience                                                                                                                                                                                                                                                              | Strongest advantage                                                                                                                                                | Cost or limitation                                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A — Exact-version text comments with optional page/location references; recommended** | Staff write a comment about an exact source use/version. They can identify a page, sheet or other meaningful location when supported, with a useful page/location jump only where the qualified reader can resolve it. A general comment remains available without a location. | Useful across more file types, readable in a normal comment list and practical even when visual preview is unavailable. Keeps authoring and recovery small.        | Staff must describe a detail and colleagues may need to locate it manually. A page reference can still be too broad for a dense image, table or diagram. It does not pinpoint an area visually.                               |
| **B — A plus optional visual point/region markers on qualified PDF/image readers**      | Keep A's text/comment list and supported references. For qualified static PDF/image representations, staff may point to a spot or mark an area and attach the comment to that exact representation/version.                                                                    | Makes the intended visual detail more precise and can reduce ambiguity when several similar details share a page. Useful for pictures, diagrams and dense layouts. | Adds marker authoring, rendering, accessible equivalents, zoom/rotation and rendition/version-mapping work. It remains unavailable for unsupported formats or unavailable previews; no all-format annotation promise follows. |

**Recommend A now.** A delivers the required version-specific comments and practical location context without making every review depend on a visual annotation layer. It accepts a real cost: more descriptive effort and manual locating within complex pages. This is a permanent bounded initial product choice, not a promise to auto-enable B later or a claim that simple text is universally superior.

**B is a strong alternative, not frivolous editing.** A visual marker can identify the exact serial-number plate in a photograph or a particular line in a dense scanned table more clearly than a page number. Current document products demonstrate that value. B need not become an office suite: one optional point/region interaction with a readable text equivalent can stay bounded. Even that small increment needs real source/representation anchoring and accessible control behavior. Its value for Asym cannot be established from vendor marketing alone.

A strict whole-version-only option that deliberately refuses every supported page/location reference would underdeliver the founder's requirement. We therefore fold useful supported page/context references into A, while keeping general comments optional and simple. There is no third tenant mode or per-tenant annotation-policy product implied by these alternatives.

## Illustrative reviewer journey

Elena reviews an exact inventory PDF and an accompanying equipment photograph from an ordinary request. She wants Rui, an independently authorized colleague, to inspect one unclear entry. This is illustrative, not a claimed ministry practice or measured demand.

With A, Elena can write a comment on the PDF version with the readable location **Page 3, serial-number table**, or on the photograph version with **Serial-number plate at the lower right**. If the qualified reader has a meaningful page identity, Rui can use the page reference to reach that page, then locate the described detail. The interface identifies the exact file version and source context; the note is not a generic request-wide instruction.

With B, Elena could also place a marker on the specific table cell or plate in a qualified static representation. Rui sees the text in the comment list and can use its qualified visual target. The marker does not alter original bytes and does not itself request a replacement, resolve a review concern or share the note with the participant.

If a correction arrives, the comment still belongs to the version Elena actually reviewed. It must not slide to the same page number or screen coordinates in the new file. The source may allow current access to the older comment/context, require a new deliberate comment on the newer version, or restrict the old content. Neither the retained note nor its marker grants a historical archive entitlement.

## Common safeguards that preserve the one decision

1. **Exact target remains visible.** Source/use/version identify the comment; filename, digest equality, newest version and currently focused pane do not select a different target silently. A current correction can change source eligibility without changing what the old comment referred to.
2. **General comments stay useful.** Location is optional. Source-authorized staff can record useful inspection/review context such as a preview problem without being forced to invent a page or first load a successful preview. Actual current source rules still decide comment and byte-reading permissions separately.
3. **Page/location wording is honest.** A typed description is not automatically a machine-validated anchor. A clickable page/location action is shown only when its actual current qualified representation resolves it. Otherwise preserve the permitted description and say the target cannot currently be opened; do not jump to a misleading nearby/newest location.
4. **Representations do not rewrite evidence.** Both A and B preserve originals and independent acceptance/currentness. Optional markers are source-owned overlay/reference data, not edits burned into a submitted PDF/image or a new file version by default.
5. **Permissions cover text and location.** A comment can contain sensitive copied content or context even if the file name is safe. Author, current reader, draft, location, preview, count and history disclosure follow the source/P12 purpose; file Read alone and mentions do not enlarge the audience. No public/participant/staff-everyone default is inferred.
6. **Current readers are not granted history.** Existing comments on old versions remain attributable but current authorized reveal is independent of retention. Denied original access, expired rendition or changed source restrictions must not be bypassed by saved text excerpts, region thumbnails or cached annotations.
7. **No automatic cross-version carry or retention coupling.** Replacement, correction, rendition regeneration, crop/rotation/profile change and byte-identical reuse need exact owner-defined mapping. A lost visual anchor does not erase the permitted source comment; it also does not get guessed onto the new file. Comment retention/disposition is owned independently from D32's disposable rendition lifetime. A deliberate new comment on a new target is distinct.
8. **Posting is deliberate and recoverable.** Show the intended version and internal context before Post. Lost acknowledgments/repeated clicks reconcile the same comment, not duplicates. Preserve only lawful draft/context after technical failure or scope changes. The chosen-answer review must settle concrete edit/correction/removal and source-admin repair without rewriting past business decisions.
9. **Comments do not create a workflow.** No mandatory Resolve/read receipt/acknowledgment, per-file review ceremony, independent review assignment, new notification, subscription, mention-based invitation or general Support inbox is selected. Actual Q21/Q23 source work and Q30 outward messages remain separate.
10. **B must be accessible and bounded if chosen.** A meaningful comment list/text location remains primary usable context. Point/region creation and navigation need keyboard and non-drag single-pointer equivalents, clear focus, zoom/reflow behavior and no color-only meaning. Pin placement must not become a prerequisite for review or acceptance.
11. **Both options need practical failure states.** Distinguish missing preview, unsupported anchor, expired technical rendition, inaccessible old version, unknown current authority and ordinary temporary network failure. Use current qualified retry/help; no automatic original download, external office viewer, private screenshot upload or permanently retained preview solely to keep a comment clickable.
12. **Keep platform impact small and explicit.** Use the source, current P12, qualified reader and shared Core UI. No provider/account change, annotation license purchase, custom renderer, generic chat service, body extraction/AI, dynamic audience engine, offline sync or assumption of free implementation follows. Native workload/accessibility/rights/replay proofs remain required.
