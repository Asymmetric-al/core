## One decision

**Should authorized staff be able to deliberately notify a specific eligible colleague about an exact document-review comment, or should comments remain unaddressed while staff use existing qualified review coordination?**

| Option                                                  | Practical experience                                                                                                                                                                                                                                        | Benefit                                                                                                                      | Cost or limit                                                                                                                                                                         |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A — Optional directed staff attention (recommended)** | Select a currently eligible colleague for a particular comment. A protected informational cue in the governed staff notification center opens that exact comment under current permissions. Ordinary comments can still be posted without notifying anyone. | Keeps the observation and the request for attention together, without creating a separate task for every comment.            | Requires a real source-owned attention occurrence, current recipient qualification, safe contextual navigation and retry/noise controls. The current demo bell does not implement it. |
| **B — Keep comments unaddressed**                       | Keep Q45 comments in the authorized evidence/review context. When someone else needs attention, use an actual qualified source-review or task-coordination route separately.                                                                                | Less new notification behavior; sufficient where existing review responsibility already brings the right people to the work. | A targeted colleague handoff needs a separate coordination step. Neither the comment nor a task link proves that the person noticed it or grants access.                              |

**Recommend A, narrowly.** Offer deliberate colleague attention as a convenience alongside ordinary unaddressed comments. Use the already-governed staff center, with no new inbox, mandatory task, follower list or automatic all-comment broadcast. This recommendation selects an in-product informational outcome; it does not silently choose email, SMS or push defaults.

Illustrative situation, not an observed ministry workflow: Elena leaves a comment about an unclear serial number on page2 of an ordinary submitted inventory. Ravi is already eligible to read that exact internal comment and context. With A, Elena can bring Ravi directly to the observation. With B, she uses an existing qualified review-coordination route to point him there. Neither changes who owns review, gives Ravi additional file access, or sends the discussion to the request participant.

## Why this question is open

The founder's confidentiality requirement covers comments, annotations, mentions and notifications and expressly says mention must not grant access. It does not establish a notification producer or transport. [Q45](../docs/adr/0045-exact-version-review-comments-and-visual-locations.md) chooses flat source-owned comments on one immutable use/version/purpose, with optional qualified locations. It explicitly leaves `@name` text non-authorizing and selects no task per comment, new inbox, read receipt, Reply/Resolve workflow or new notification purpose.

P17 likewise defers generic assignment/@mention keys until their producing source fixes typed meaning and destination. P9's CRM-note/task discussion rules do not supply ordinary document-comment authority. Q27's source-review notice, Q32's clarification notice, Q40's participant update and Q48's recipient reminders have different occurrences and recipients. Q51 resolves the specific colleague-attention capability; it does not activate every mention or inherit another notification's defaults.

The strongest alternative is B's existing review coordination, not removing comments or forcing screenshots/private-email workarounds. There is no measured Asym missed-comment rate, interruption volume or staff preference result proving that A is necessary. A is a proportionate product judgment for a specific colleague handoff. If normal assigned review is sufficient, B is genuinely simpler.

## Proposed experience and bounded requirements

A's intended journey is **exact comment → deliberately choose colleague → explicit final action → truthful result → colleague's staff-center cue → exact authorized comment**. It should also work when a staff member decides to direct attention after the comment was already posted. Whether the smallest implementation is a saved-comment action, an optional composition affordance, or both is design work within that outcome, not a requirement to install a rich editor.

The following are proposed boundaries for A's selected-answer review, not a recorded Q51 answer:

1. **One exact source context.** Bind the act to an admitted Q45 ordinary-source comment/use/version/purpose and meaningful current comment basis. Equal bytes, file identity, an enclosing task or a newer upload cannot substitute. Specialist sources remain separately owned.
2. **Separate powers.** The actor needs the actual source permission to direct attention; the colleague independently needs current qualification for that exact comment/context. Staff rank, reviewer assignment, read alone or a typed name grants neither power. Comment access does not require unrelated preview success or automatically grant original-file access.
3. **Safe target discovery.** Reveal only permitted staff identities in the validated Tenant/context and select actual eligible identities. Disambiguate same-name people with permitted context. No arbitrary address field, group broadcast, automatically selected first suggestion or exposure of hidden ineligibility details. Qualify the actual no-Party staff branch.
4. **Explicit act and honest recovery.** Typing/pasting `@name`, opening/selecting a picker, blur, draft autosave, IME confirmation, viewing, ordinary edits and canceled choices have no attention effect. The final act durably admits its exact intent and result. An invalid choice before admission must not silently redirect or claim success; preserve lawful input and offer a deliberate valid path. A later cue failure must not erase a valid comment or require reposting it to recover.
5. **Concrete shared destination.** The result is an informational item under the compatible P17 policy in the active-tenant staff center, opening the exact authorized comment. Use the existing Phase6 event/plan/recipient evidence and P12 authority through their canonical owners. Do not create another inbox, event ledger, task per comment or full Workflow prerequisite.
6. **No new work obligation.** The cue neither assigns review nor requires a reply, deadline, Resolve state or read receipt. Q24 responsibility, Q22 fulfillment, acceptance, Request changes and participant clarification remain separate source acts. Reading/archiving is not completion.
7. **Current usefulness and privacy.** Revalidate actual authorization/source applicability at admission, projection/dispatch, serving and navigation. Every badge, name, preview, search result, history and error must respect current role/field rights. No participant/Q41 reader inherits staff discussion, and the same human's staff role is not unioned into a participant session. Minimal cue content must still identify the permitted work usefully; no generic copying of private comment bodies, Q50 names or location details into broader channels/logs.
8. **No accidental repeats.** A durable occurrence and original recipient basis make retries recover the original result, not create another cue or substitute today's roster. Edits, withdrawal, Restore, source completion/correction, later access and re-import cannot automatically re-alert or revive old presentation. The selected review must close finite recipient/repeat/self-target and correction/end behavior without introducing followers or reminders.
9. **Flexible within existing control authority.** Tenant capability/optional-presentation controls and recipient preferences apply in P17's governed order where this exact purpose permits them. Preserve required source/safety notices. No new permission engine, per-comment audience setting or tenant configuration matrix. A creates no email/SMS/push default; another channel requires explicit source/P17/P6 qualification and current disclosure, not analogy to Q27, Support or finance.
10. **Small accessible interaction.** Reuse shared Base UI/base-maia components and ordinary plain-text comments. Use clear target/audience/action labels, keyboard/speech/touch operation, stable focus,320CSSpx reflow, localized time and international/RTL/IME names. Loading, no permitted matches, failure, stale choice and unknown result are distinct without revealing forbidden records. Preserve lawful input during recovery; no hover-only action or automatic original download.
11. **Minimal persistence, real bounds.** Store source-owned attention facts and required evidence, not duplicated file content or a universal mention graph. Derive tenant/actor/recipient attribution from trusted context. Qualify all actual database grants/RLS/policies/RPC/service/browser/import/restore paths and immutable tenant-aware relationships. Use finite picker/list/recipient/fanout/query/recovery/retention budgets and actual workload/cost proof before activation. No new provider, mandatory Realtime or claim of unchanged Supabase/Vercel bills.
12. **Safe rollout and repair.** Adopt the exact producer, identity and destination through canonical owners before native activation; preserve the existing comment route. Use one qualified writer, future occurrences, compatible readers and bounded source-scoped recovery. No replay of historical `@text`, generic queue migration, fake engagement history or access widening to repair a broken cue. No need to implement all future notification producers to deliver the narrow slice.

## Adversarial check

### What could go wrong with this answer?

An attractive @mention control could expose a staff directory, grant access, notify before posting, duplicate alerts, or point to the wrong version. The current Support callback and demo bell demonstrate why UI similarity is insufficient. A needs the exact source-owned act and native destination; B avoids this new effect.

### What hidden assumptions are we making?

We infer that some review observations benefit from a specific colleague's attention; we have no measured Asym need/frequency. We do not assume daily bell visits, a response SLA, universal staff Party records, generic source-task implementation or free compute. Intended-user and workload qualification remain necessary; the example is illustrative.

### How does this affect the whole product?

It adds one explicitly adopted ordinary-comment producer to P6/P17 and the compatible source/P12 staff identity path. It does not activate generic CRM mentions, alter responsibility, expose participant comments or duplicate the shared center. Existing independent notices and safety requirements remain governed.

### How does this affect the end-user experience?

The author can ask a particular colleague to look without creating a task or copying context. The colleague returns to the exact comment and may continue normal authorized work. Unaddressed comments stay low-friction; participants see no internal discussion. The useful outcome depends on honest in-product delivery and recovery, not an @ chip or a promise of response.

### Does this follow modern best practices?

Primary document/CRM examples support explicit targeted attention, contextual navigation, current permissions and noise controls. They disagree on grants, subscriptions and channels. Core should use the compatible pattern and explicitly reject HubSpot-style access grants and automatic subscriber/assignment behavior; no universal vendor consensus is claimed.

### Does this fit Asym's existing repo and product direction?

Yes as an explicit new source contract using the already-governed shared staff center. Q45 intentionally left the act open, and P17 explicitly requires typed producer meaning/destination first. Actual staff/no-Party compatibility and native wiring remain requirements, so neither source import nor a sample dropdown is presented as proof.

### Should we adjust the recommendation?

Keep A, narrowed to optional deliberate colleague attention with an informational native cue. Keep B available as the simpler coordination model. Do not expand A into subscriptions, assignment, access sharing or automatic email to make it seem more powerful. No Q51 answer or glossary term is recorded until the founder responds and the selected answer is reviewed.
