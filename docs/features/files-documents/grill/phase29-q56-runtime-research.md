**Recommended A — Upload photos or a prepared PDF.** Preserve qualified camera/photo input, ordinary file selection and permitted several-file evidence on one item; a user may supply a PDF already prepared through their chosen lawful device/tool. Do not add an Asym page-assembly feature in this first scope.

It is not an editor for already received evidence, a retroactive merge of contributions or a general scanner/drive.

This is a real optional product increment. A does not remove required camera sources, multiple files where the item permits them, or ordinary prepared-PDF upload. B's strongest advantage is continuity: a person with several paper pages can complete the work in the same request context without switching tools and locating a newly created file. It can make intended page grouping/order easier to inspect. That benefit is plausible, not measured Asym usage or proof of fewer mistakes. A avoids an additional capture/order/derivation/recovery surface and its fidelity/device costs; it can require a tool switch when one PDF is needed. Neither answer excuses an unusable baseline camera/file-intake journey.

## Minimal practical consequences, without freezing architecture

**A remains complete ordinary intake.** If the item accepts several image contributions, show their individual selected/received states and source grouping; the source can review the exact meaningful set under Q21. If its actual requirement needs one supported PDF, a prepared PDF can be selected and submitted through the ordinary lane. Do not pretend a source that accepts only PDF can always accept separate photos, or require a person to use an unqualified outside service. The source needs its real capable alternative/help where supported device/file choices cannot meet the requirement.

**B adds a local preparation concept, not automatic admission.** A bounded set of permitted still images can be arranged with clear page count/order and deliberate removal/retake/reorder, then converted into the chosen PDF output and passed through actual qualified intake. A custom always-on camera, automatic edge detector, crop enhancer, OCR, text recognition, signature check or external processor is not necessary merely to assemble pages. The selected-answer review would make the exact supported edit/rotation/fidelity and recovery behavior concrete; this question must not silently choose a full scanner/editor.

Preserve selected originals where the actual source requires fidelity and identify transformations/assembled output separately. This does **not** mean retaining every rejected shot or retake indefinitely. If the browser supplies only an assembled PDF and the source accepts it as an incoming user-produced file, do not claim the server possesses/verified every input image or proved page completeness. If source-qualified input lineage/original preservation is required, the actual input custody/verification must support it. Browser-generated hashes/manifests are untrusted assertions until the server verifies the relevant material. Client-side generation never bypasses server checks on the incoming PDF or current source admission. The source must not call a transformed image signed/unchanged evidence.

Working locally may avoid an additional server rendering step, but decoded images, canvases, thumbnails, compressed buffers and output PDF can coexist in memory. Main-thread responsiveness, CPU/battery, memory, supported dimensions/pages and cancellation on modest phones need measurement. A worker may help responsiveness but does not remove total resource bounds or supply authorization. Server generation can add transfer, storage, processing/egress and cleanup costs. Browser versus server location, libraries and numeric caps are engineering qualification decisions, not implicit promises of this fork. No option has measured cost neutrality or capacity.

Retained browser state is not reliable durable custody. Browser process termination, navigation, device permission changes and context switching can lose a draft. Avoid silent persistence of sensitive photos in broad local storage, logs, analytics or session replay. Explain local-only/unsaved state and recover only what is actually retained under qualified rules. If preparation is transferred privately, it needs its source-owned staging/disposition/hold/reference accounting. Cancel is not safe-delete authority while writes/finalization or references may still win. Camera permission and source admission are separate, and ending access does not automatically prove physical cleanup safe.
