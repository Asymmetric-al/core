# Phase 29 Q34 — Comparative research: cancel an unfinished ordinary request

Research checked 2026-10-23, Asia/Bangkok. Conrad fully ratified Q33 and all
amendments; Q01–Q33 and twenty-two definitions remain settled. Q34 has no
selected answer. This note supports one new product choice, not implementation,

## One decision and recommendation

**Should source-authorized staff be able to cancel an eligible unfinished
ordinary Document Request when the whole request was issued by mistake or its
legitimate collection purpose has ended?**

Recommend **A — Provide a deliberate source-authorized Cancel request action**.
It gives staff a truthful way to stop an obsolete whole request without falsely
fulfilling it, deleting received evidence, or pretending that each item was
independently no longer required. Its cost is a real aggregate source decision,
with clear consequences, current authority and capable mistaken-action recovery.

| Option                                                                                                 | Practical experience                                                                                                                                                                                                                                                                 | Benefit                                                                                                                                                          | Cost and boundary                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **A — Allow authorized cancellation of an eligible unfinished ordinary request (recommended)**         | Staff end that exact request's ongoing collection purpose in context; the source records Canceled rather than Fulfilled. Prior receipts, decisions and independent duties retain their meaning. The participant gets a truthful terminal experience wherever current access permits. | Resolves the whole-request dead end without dummy submissions, fake acceptance/completion or loss of history. The remaining work for other requests stays clear. | Requires actual cancellation authority, aggregate ordering, safe terminal presentation and a capable remedy for mistakes. Cannot cancel an application, financial, consent or other specialist obligation by changing an ordinary file-request status. |
| **B — Add no ordinary cancellation action; use an existing qualified capable source resolution route** | Staff use the real source's supported resolution process. The request reflects the resulting authoritative facts; no new ordinary cancellation power is added.                                                                                                                       | Avoids duplicate commands where the source already handles withdrawal/resolution well, and keeps established domain judgments in their existing route.           | May require a handoff or leaving the request. The path must actually end/resolve the obsolete demand; a decorative help link, imagined cancel/reissue sequence or indefinitely open request is not an adequate substitute.                             |

These are product alternatives, not tenant modes. There is no useful artificial
third option. A should reuse an existing qualified command where it supplies
the exact behavior; where absent, it would authorize a bounded ordinary-source
capability. UI, File Manager, tasks and custody do not become competing owners.
B neither strips existing domain powers nor promises an unsupported fallback.

Illustrative example, not a ministry observation: Elena sends Nora a duplicate
ordinary request for supporting materials. The first request is still the valid
collection route. Elena discovers that the second request was issued in error.
Canceling the duplicate should end its demand without marking its missing files
Accepted or claiming successful fulfillment. Any file already received through
the duplicate remains a historical receipt under its real protection/retention
rules; reuse through the valid request still needs its own qualified action.

## Why this is the next meaningful question

Q33 specifically changes one mistaken/no-longer-applicable demand inside an
eligible unfinished request. Its fully ratified package says an ended whole
purpose cannot be converted into successful fulfillment through repeated item
removals. Q22 also keeps canceled/withdrawn outcomes separate from fulfillment.
Thus Q34 is a distinct aggregate lifecycle decision, not a reopening of Q33.

The prior frontier census explicitly reserved whole-request cancellation,
participant refusal and broader sent-request revision. Post-issuance instruction
or required-item revision remains meaningful but broader: adding new demands,
changing instructions or recipients affects the participant's expectation and
the exact evidence/review basis. It should not be smuggled into cancellation.
Generic “can staff author requests?” is currently a weaker question: useful
ordinary issuance is already required and Q25 settles readiness. A later
authoring question needs a specific unresolved tradeoff rather than another
permission-by-role question or a blank workflow-builder design.

The strongest objection to A is legitimate: a convenient Cancel control can
be used to abandon difficult but still-required work or duplicate a good source
route. The response is a narrow current source capability and real purpose
decision, not universal staff cancellation or a mandatory approval bureaucracy.
No evidence establishes Asym's cancellation frequency, staffing cost or a
universal preference for A. The recommendation is a product judgment grounded
in the selected request/review model and current comparators.

## Meaning and consequences that must stay separate

| Similar-looking action                       | Q34 distinction                                                                                                                                                                                |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q33 No longer required                       | Ends one exact demand while the request can remain eligible and progress under Q22. Cancellation addresses the whole collection purpose ending; it is not repeated item removal.               |
| Fulfilled / Complete                         | Q22's successful source outcome, not the result of abandoning a mistaken/obsolete whole request. Preserve any earlier true acceptance but do not fabricate aggregate success.                  |
| Archive / hide from a list                   | A presentation/organization choice unless its source contract defines more. Moving a row cannot be the authoritative cancellation act.                                                         |
| Revoke a participant grant                   | Removes that access; it does not by itself establish that the business no longer requires the request or that other participants/staff work should end.                                        |
| Expired access or overdue due date           | A clock result, not a staff purpose decision or automatic cancellation. Current access rules remain; do not reset them.                                                                        |
| Delete request or file                       | Data disposition with separate retention/hold/use rules. Cancellation must not delete receipts, evidence, decisions or independently used bytes.                                               |
| Participant declines/cannot provide evidence | Information or a different source decision. Q30 clarification does not confer cancellation authority.                                                                                          |
| Reject evidence or request changes           | Review meaning. Cancellation must not relabel received files as rejected/accepted or continue obsolete correction demands.                                                                     |
| Cancel a domain process                      | Application, finance, care, consent, employment or another consuming domain retains its own semantics and powers. Canceling an ordinary collection request does not cancel that domain record. |
| Undo / reactivate / reissue                  | A separate current source recovery operation, not a free inverse that revives deadlines, grants, messages or fulfilled history. Q34's answer review must make the supported remedy concrete.   |

An unfinished request can contain already accepted individual items. That is
different from Q33's not-currently-accepted target item: cancellation must
preserve each true earlier receipt and acceptance while ending the remaining
ordinary aggregate demand. A fully fulfilled request is a different lifecycle;
Q34 should not retroactively turn its true fulfillment into cancellation.

## Keep the interaction small, but the consequences concrete

Use an action such as **Cancel request** in its current request context, with
the exact permitted request identity and a short statement of consequence.
Candidate wording to test: **This ends this request for documents. Previously
received files and decisions are not changed by cancellation.** Retention,
disclosure and independent duties remain governed; this copy must not promise
perpetual raw-file availability.

The meaningful action should state that this is the whole request. The UI must
not conflate its own **Back/Keep request** choice with the business **Cancel
request** action. A participant-safe **Request canceled** status with **You do
not need to send more files for this request** is useful only where those facts
may be disclosed to the current viewer. The parent task/application may still
have other requirements; do not say **Everything is complete**.

Staff need a concise accountable cause/basis. Existing trusted source facts
can supply it; concise entry is appropriate where otherwise missing. A universal
essay, configurable reason-code system or routine second approver is not
justified. Internal rationale and participant-facing guidance are distinct.

The [GOV.UK button guidance](https://design-system.service.gov.uk/components/button/)
supports action-specific labels and sparing use of destructive warning buttons.
[W3C error-prevention guidance](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-all.html)
supports checking, review/correction or reversal; that cited broader criterion
is AAA, not a new blanket Core conformance obligation. These pages were read in
the same 2026-10-23 research session. Apply the principles without prescribing a
universal modal, second approval or new component system.

## Terminal access and mistaken cancellation need explicit review

Ending the collection demand is essential to cancellation. The exact remaining
participant status/history/help surface is not established merely by copying
a competitor's Archive/Rescinded behavior. Preserve Q06–Q19's existing access
limits, Q22's fulfillment distinction, Q30's admission/closure rules and current
source authority. A cancellation does not earn a fulfilled-request history
window, restart a deadline or grant access. Staff's lawful historical access
and independent duties may remain. The selected-answer review must bind the
actual canceled-entry and clarification behavior, including what a currently
authorized participant can see and what an expired/invalid link cannot reveal.

Mistaken cancellation is a necessary journey, but Q34 must not secretly choose
a generic reopen policy. Existing capable source remediation is the starting
point. Separately reviewed normal original issuance, where independently
authorized and appropriate, is one possible concrete remedy; it is not an
automatic clone/reissue or an inferred inverse for this newly proposed terminal
act. Preserve permitted Q01 proof and Q28 evidence reuse under their own exact
rules rather than forcing repeated proof/uploads solely to repair state. The
selected-answer review must name and qualify the actual remedy and retain the
cancellation history. A contact-only placeholder or direct data repair is not
a complete product path.

No new cancellation email/default, bell, SMS, reminder, participant refusal,
bulk action, arbitrary request revision or new tenant mode follows from asking
this question. Existing Q26/Q27/Q31/Q32 messages retain their exact meanings;
cancellation status or audit text is not one of those events. A separate lawful
clarification or issuance action remains subject to its own existing contract.
