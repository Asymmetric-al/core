## Judgment and main findings

**Accept with required amendments.** A is coherent with Q01's already-required source correction and Q34's prepare-and-issue remedy. It should be one practical correction flow rather than manual reconstruction, an email-field mutation or a draft presented as success. The strongest B is a same-request versioned successor only for a source-proved pristine request; that would preserve an early request reference but require a separate eligibility, recipient-lineage and clock model. A deliberately chooses one consistent replacement shape.

The largest prospective risks are High, not Critical; no catastrophic deployed incident is established by this research.

1. **High / likely if omitted — draft versus real handoff.** Inert preparation, an independently ended old request and an actually issued successor are different facts. The normal path must coherently commit actual Q34 cancellation and actual Q25-qualified original issuance, not leave two active recipients or call a draft the replacement.
2. **High / likely — urgent-stop dead end.** Requiring the old request to remain unfinished at every later step would strand a legitimate correction after its old authority was safely canceled. Preserve an exact already-canceled remedy branch without reopening old access or treating every terminal record as cloneable.
3. **High / plausible — duplicate successor.** Transport keys, separate staff drafts or retry after lost response can issue two requests. One active preparation and one ever-issued direct successor per predecessor need source-owned uniqueness and original-outcome recovery.
4. **High / likely — implicit transfer.** Old receipt, acceptance, transcript, evidence use, proof, clock, notification or preference must not become the new person's state. Source-approved definition reuse is a narrow new operation beyond Q39, and free prose still needs disclosure review.
5. **High / plausible — false reminder reset.** A genuinely new person can have a new original request under current Q48 policy, while old count/stops/unknowns remain. Nominal identity edits, aliases or recreation cannot be used to evade a person's existing restriction or refill an old allowance.
6. **High / plausible — wrong-recipient cancellation email.** Q35 expressly forbids notifying a known-wrong former recipient. A formerly legitimate recipient whose responsibility changed is a different case and may independently qualify for a minimal factual cancellation notice. Neither blanket sending nor blanket suppression is correct.
7. **Medium / plausible — blanket past-date ban.** New terms require explicit current review, but Q46 permits a source-valid past Requested by value. Do not convert “no blind copying/backdating” into a new future-only rule or universal Q12 target-after-access rejection.
8. **High / plausible — permission transplant.** Draft authoring, origin definition read, cancellation, responsibility administration, new issuance, link disclosure and repair are distinct current powers. The new named-function grant lockdown is useful foundation evidence, not an ordinary replacement permission.
