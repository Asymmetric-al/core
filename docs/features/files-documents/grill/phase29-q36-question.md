## Historical question and alternatives

**When another ordinary document is legitimately needed for the same continuing
purpose and intended recipient, may authorized staff add an item to the existing
issued unfinished request, or must they issue a separate request for it?**

This is a genuine scope decision. Q33 allows an unnecessary existing item to be
marked No longer required and corrected on its same lineage; it does not permit
new items. Q01 binds access to the relevant request/recipient/purpose revision.
Q13 and Q15 expressly keep fresh unfinished scope within original admitted
requirements. Q22 can evaluate authorized requirement changes but does not
authorize them. A therefore needs an explicit prospective source/access-scope
amendment; it is not a cosmetic Add button on already granted authority.

| Option                                                                                        | Everyday experience                                                                                                                                                                                                         | Benefit                                                                                                                               | Tradeoff                                                                                                                                                                                                        |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A — Allow authorized staff to add an ordinary item to an unfinished request (recommended)** | Staff deliberately add the new item to the same eligible request and qualify its recipient scope. Existing submissions, acceptance and history stay intact; the new required item joins that request's completion criteria. | Keeps one coherent checklist and avoids a second request for an omitted or newly established need within the same legitimate purpose. | Changes what finishing that request requires. Needs clear added-work presentation, exact prospective authorization and ordering against fulfillment.                                                            |
| **B — Use a separately authorized request for additional items**                              | Staff issue a new request containing the additional need through the normal qualified issuance path. The original request continues under its existing requirements and completion rules.                                   | Keeps the original collection scope stable and avoids this new live-scope amendment capability.                                       | Staff and participant manage another request and its independent access/history; work may become fragmented. Existing qualified proof/evidence reuse can still prevent unnecessary re-verification or reupload. |

**Recommend A**, limited to the same eligible unfinished ordinary source,
continuing legitimate purpose and intended recipient. Keep added work clear,
preserve completed effort and require real prospective scope authorization.
Use B for a different purpose/recipient, a terminal request, specialist rules
that prohibit amendment, or a source that cannot qualify the amendment path.
These are product alternatives, not two new tenant modes.

A does not authorize rewriting existing item requirements, silently editing
accepted evidence, altering templates for other requests, general reopening,
new recipient audiences, automatic email or longer access periods. Those are
different decisions. It also does not mean staff can indefinitely avoid
fulfillment by leaving planned draft items as hidden completion blockers.

## Concrete example and user journeys

Illustrative scenario, not an observed ministry workflow: Elena requested
ordinary equipment-handover documents from Nora. Nora has supplied the inventory
and handover record. Elena establishes that an omitted packing list is also
needed for that same handover purpose while the request is still unfinished.

Under A, Elena deliberately adds Packing list through the source's authorized
amendment path. Nora sees the newly added requirement alongside the preserved
earlier work when current access permits. Under B, Elena issues a separate
packing-list request; the original can complete independently. Neither option
asks Nora to repeat the inventory or rewrites its earlier acceptance.

## Current primary research and strongest alternative

- [Content Snare: editing requests after sending](https://contentsnare.com/help/knowledge-base/editing-requests-after-sending/)
  documents adding fields to sent requests, visible on the client's next opening.
  It also warns that deletion can remove answers. This supports continuity and
  preserving prior work; Core should not import unrestricted autosaved live
  edits, destructive deletion or automatic timing changes.
- [FileInvite: sending an Invite Follow-Up](https://help.fileinvite.com/articles/sending-an-invite-follow-up)
  explicitly adds new requests to the existing Invite. The word Follow-Up does
  not mean a separate new Invite. Its notification, SMS and multi-contact
  features are separate vendor behavior, not Q36 scope.
- [TaxDome: actions with client requests](https://help.taxdome.com/article/actions-with-client-requests)
  permits edits only before the client starts responding. This is substantive
  counterevidence to broad live editing. Its separately editable checklist and
  Beta missing-document request feature must not be conflated with this rule.
- [Submittable: sending an Additional Form](https://submittable.help/en/articles/2691276-how-can-i-send-an-additional-form)
  provides staged additional collection connected to a submission. It supports
  a separately bounded follow-up approach, not an automatic Core request-scope
  change or permission to reopen an application's completed history.

The [comparative research](phase29-q36-comparative-research.md) records verified
edition/feature differences, additional evidence and limits. B's stable-scope
advantage is real. A is recommended as a bounded ordinary continuity feature,
not because every comparable product permits editing or because all ministry
needs evolve in the same way. No observed Asym amendment frequency, completion
improvement, staff preference or reduced support burden has been measured.
Intended-user proof must test surprise new work, preserved progress, terminal
races, expired access and separate-request clarity before benefit claims.

## Repository reconciliation and scope boundaries

The [owner research](phase29-q36-owner-research.md) and
[runtime research](phase29-q36-runtime-research.md) retain exact anchors and full
consumed governing contracts.

1. **Actual new source power.** Adding a requirement is distinct from reviewing
   evidence, supplying an existing version, removing an unnecessary demand,
   changing task text, refreshing access or editing a global template. Require
   actual same-tenant current source/P12 authority and legitimate ordinary scope.
   Neither a generic staff role nor Q22's reevaluation machinery grants it.
2. **Explicit scope successor, not old-grant widening.** Q01-C08's versioned
   successor/fencing rules constrain changes; Q13-C06/Q15 currently exclude new
   requirements from fresh scope. A must explicitly reconcile that limitation
   prospectively for the approved added-item lineage while preserving old
   admissions, deadlines, adverse facts and unrelated restrictions. A valid
   original or fresh period may carry the new item only through qualified scope
   amendment, retaining its exact end/caps. Expired access needs independently
   authorized fresh admission for the amended lineage, otherwise use B. No
   automatic grant extension, union of expired rights or new duration policy.
3. **Identity proof remains separate.** Q01 proof reuse must qualify against the
   amended exact request/purpose/recipient revision. Safe reuse can avoid needless
   challenges; old proof/token/address alone cannot admit newly added work.
   Source scope change and identity confirmation are not interchangeable.
4. **Historical integrity and current completion.** New item identity and its
   authoritative admission must be attributable and current. Existing submission,
   correction, acceptance, questions and history remain on their original basis.
   Serialize relevant requirements, admission and actual Q22 terminal results.
   A required added item belongs to the same completion predicate; B's new
   request is independently fulfilled. Draft plans are not hidden obligations.
   Preserve source-certified nonblocking optional work as nonblocking; this
   question does not turn every added row into a new completion hold.
5. **Qualified review work without a new staffing platform.** Q24 flexible
   person/team responsibility and Q25's genuine source-edit coverage rules
   support reusing valid paths. Explicitly establish coverage for newly added
   declared work; do not treat Q25's first-original gate as a standing universal
   restriction, demand private roster disclosure or combine reviewer powers.
6. **Useful timing and recovery.** Q09 targets and Q10–Q19 finite admission
   terms remain separate. No timer reset, new repetition rule or automatic
   reissue follows. Preserve original addition identity across lost responses,
   current disclosure and relevant source changes. A's full selected-answer
   review must supply a usable participant path, not only a staff-added draft.
7. **Existing related capabilities keep their owners.** Q28 may provide exact
   existing evidence under current source/target authority without copied
   acceptance or participant assertions. Q33 may end a mistaken new demand
   under its actual eligibility. Q30 clarification does not edit requirements.
   Q34/35 cancellation and mail remain separate. No new added-item email,
   reminders, channel, global notice policy or completed-request reopening is
   bundled; existing approved source outreach remains only where actually lawful.
8. **Prospective qualification and trace.** If A is selected, reconcile exact
   source/P12/Q01/Q13/Q15/Q22/Q24/Q25 ownership and full OpenSpec requirements;
   amend canonical authors and regenerate declared projections together. Native
   source/recipient operations, structural authorization, relevant races,
   idempotency, safe mixed versions/restore and composed UX need actual proof.
   No new generalized permission/workflow engine or whole future Studio gate.
