## Conclusion and delegated condition

**Accept A with required amendments. Do not add general document-body search in
this package.** The delegated exception has not been established. The current
runtime review reports a native text-search primitive in another purpose, but no
qualified reusable general document-text producer or measured account/workload
delta proving both low complexity and an unchanged bill. That does not prove B
is impossible, unaffordable or always complex. It is sufficient to make the
current product scope explicit rather than leave a hidden conditional feature.

No new search-vendor subscription, an included database primitive, or unused
allowance is by itself evidence that extraction, index persistence/updates,
authorization, query work and delivery add nothing to the existing bill. Exact
provider pricing, capacity and native-source findings belong to the runtime
adversarial note. This UX review does not claim to have inspected billing accounts
or run a cost benchmark. Nor does it promise that the required A metadata search
itself has zero operating cost.
The relevant comparison is the optional body-search addition against the same
approved metadata baseline and supported workload on each provider's bill;
offsetting an increase at one provider with a saving elsewhere is not the stated
condition. The runtime note records that current account/plan discovery did not
establish actual usage/headroom or a successful Vercel billing read.

The proposed corrected product decision is:

> General staff File Manager search matches and ranks only explicitly approved
> source metadata and source context. Provide useful names, relevant source/type/
> date/label filters, recent work, saved views and return navigation where each is
> qualified. Do not inspect document bodies to select, rank or explain these
> results through an index, direct scan, preview fallback or a field renamed as
> metadata. Existing independently qualified source search and Find within an
> authorized document representation retain their own scope. Document-text search
> is not selected in Q38 because its delegated cost/complexity conditions were
> not established; there is no dormant automatic enablement or unusable toggle.
> A later explicit evidence-backed scope decision may add a bounded capability.

The strongest B alternative remains useful, source-qualified keyword/phrase
search over a declared text-bearing cohort, without OCR, AI, embeddings or a
new vendor requirement. Someone who remembers **annual calibration** only from
inside a file cannot locate that file from those words under A unless they also
occur in its approved metadata. A may require narrowing and opening candidates.
Find within one representation is not equivalent to cross-document discovery,
is not available for every format, and cannot search omitted content. Do not
present A as universally superior or claim that source metadata always suffices.

## Exact proposed amendments

Severity/likelihood describe plausible impact if the named failure is introduced,
not measured incident rates. H = high, M = medium, L = low. Required proofs below
are future obligations, not tests reported as passing.

### U01 — One explicit scope and cost conclusion

**H / plausible expectation breach.** Record A now and the delegated B condition
as not established. No latent automatic body-search activation, ambiguous
sometimes-searches-contents behavior, tenant toggle with no useful cohort, or
unqualified no-bill-increase promise. Preserve the practical body-only retrieval
cost and strongest feasible B alternative. Existing source search stays intact;
no perpetual body-search prohibition follows. **P01, P02, P21.**

### U02 — A finite approved field and matching contract

**H / plausible disclosure; M / probable confusion.** For each admitted source
use, name the fields allowed for discovery and the exact operations/representations
that may use them. A safe display name, type, date, source reference, label or
catalog description is an example to qualify, not an all-metadata permission.
Preserve already source-approved catalog descriptions; do not mine a document's
body, request clarification, private note or preview into a substitute field.

Declare useful bounded term/phrase/prefix and Unicode/punctuation/date behavior.
Do not silently inherit a CRM helper's stripped punctuation, interpret arbitrary
user input as SQL/operator authority, truncate a meaningful query into a different
one, or require a query-language course. Explain invalid/over-limit input and
allow correction. No new synonyms, fuzzy ranking, semantic model or schema designer
is required merely for this decision. **P03, P04, P05.**

### U03 — Current authority before every result surface

**H / plausible.** Trusted actor/tenant/source/purpose and exact field-disclosure
rules govern matching, ranking, suggestion, facet, count, pagination and serialized
results. Same tenant, staff rank, uploader identity, known ID, a shared saved view
or permitted byte read is insufficient. Search must not expose existence through
a zero/nonzero count or ranking influenced by forbidden fields. Body text cannot
influence A's matches/ranking even if no excerpt is shown.

Keep metadata discovery, preview, original read/download, source navigation and
actions separately qualified. A result is not a grant to read every occurrence,
accept evidence or expose related uses. Recheck actual current authority when
opening/acting; no delayed cache/index cleanup as the sole revocation mechanism.
**P06, P07, P08, P17.**

### U04 — Useful source context and sparse-metadata recovery

**M / probable if only a filename box ships.** Deliver a coherent finder with
actual source/type/date/recent context, understandable removable filters and
permitted source labels; preserve the promised organizational tools. Staff should
not have to rename every original or copy sensitive prose into tags just to find
ordinary files. Approved context may be available even when names are neutral,
discarded or sparse. If the source cannot disclose a field, use only genuinely
permitted cues rather than fabricate a meaningful label.

Useful source navigation is a real path, not a dead Contact support placeholder.
The metadata/source route must remain usable where its source permits discovery
despite an unsupported/unavailable preview. Do not turn byte processing Ready into
a universal metadata eligibility rule. **P05, P09, P10, P20.**

### U05 — Honest result scope, coverage and failure

**H / plausible false assurance; M / probable friction.** Distinguish a completed
query with no matches in its declared current search universe from initial state,
loading, invalid query, unavailable source, capped candidates, incomplete paging,
stale projection or failed query. A complete zero is relative to stated metadata
scope, not proof no matching document/body exists. An unavailable or indeterminate
required authorization evaluation cannot silently become a successful complete
zero. Definitely unauthorized objects remain undisclosed; this rule does not
require revealing their existence or reporting each ordinary policy exclusion.

Result limits must support honest continuation or explain the bounded view without
claiming all results were searched. Do not search a first capped candidate set,
postfilter it and report total completeness. Coverage explanations may describe
only what the current reader is allowed to know; no hidden source/document counts.
Keep known independently lawful partial results if the contract supports that,
clearly mark their limits, and provide actual retry/refinement/source navigation.
**P11, P12, P13.**

### U06 — Source currentness, versions and ongoing restrictions

**H / plausible.** Results bind to exact source use and the version/status meaning
selected by that source. Latest storage upload is not automatically accepted,
canonical or discoverable. A corrected candidate must not inherit an earlier
acceptance, and old result rows must not silently change target after selection.
History discovery remains separately qualified; it cannot broaden Q05/Q06–Q19
participant scope or expose Q37 historical instruction bodies.

Rename/move/provider-key changes preserve identity. Restriction/withdrawal,
quarantine or disposition follows the source's exact field/discovery consequences;
it does not automatically erase all separately permitted metadata or imply byte
availability. Source updates remain true if their search projection fails. Stop
forbidden future results while recovering the replaceable projection; keep actual
history and safe independently permitted work. **P08, P10, P14, P18.**

### U07 — Saved views, return state and sensitive queries

**H / plausible disclosure; M / probable lost-work friction.** Preserve lawful
query/filter/sort/position and return-to-source context when staff inspect a
result. A saved view records a query/scope, not a list of permanently shared rights
or frozen answers. Current permission applies each time. Missing/retired fields,
changed source scope and incompatible saved filters cannot silently drop a
restriction or broaden a view; explain the actual repair/refinement required.

Query terms, filter values, history and view names can themselves contain sensitive
people/location/case facts. Apply their declared purpose, visibility and retention;
no raw query in broad analytics, logs, reusable links, browser history or persistent
shared-device storage by default. A safe opaque saved-view reference can carry
navigation without embedding sensitive text where the actual contract permits it.
Saving a personal view is not automatic sharing. No new general history product
or per-query approval ritual is needed. **P15, P16, P17.**

### U08 — Bounded, predictable asynchronous search

**M / probable; H / plausible cross-context harm.** Preserve exact current query
and context across request/response, page continuation and retry. An older response
must not overwrite a newer query, appear after tenant/user/source change, restore
revoked content, or cause surprising navigation. Retry the read under current
authority; do not manufacture source work, tasks, messages or grants.

Finite query/page/concurrency budgets and appropriate request scheduling prevent
unbounded every-keystroke work. An explicit Search action is acceptable and can
support low bandwidth; instant suggestions are not required. Preserve lawful
input/focus during loading or recoverable failure and show truthful status. No
offline private corpus or background content download is implied. **P12, P17, P19.**

### U09 — Accessible, international and mobile composition

**M / probable exclusion without actual checks.** Use existing base-maia/Base UI
with visible/programmatic names and relationships. Keyboard, screen reader,
voice and touch must operate the query, filter chips, sort, continuation and
result actions. Status messages should announce meaningful search progress or
completion without stealing focus or reading the entire result list at every
keystroke. Preserve lawful return focus and no hover/color-only result meaning.

Prove reflow/zoom, long neutral/international names, RTL, mixed scripts, diacritics,
IME composition and localized date boundaries. Do not auto-submit a half-composed
IME value or silently remove punctuation that is part of a reference. A failed
search with a foreign-script query is not proof the file is absent. Date filters
must say which source date they use and follow actual timezone semantics.
**P04, P05, P19, P20.**

### U10 — Search does not choose consequential actions

**H / plausible.** Result relevance, row selection, current page and all matches
are distinct. Existing source commands/current item permission govern every
preview/download/share/review/move/unlink/disposition operation. Preserve finite
selection, impact review where required and honest per-item partial outcomes;
search/pagination cannot create an atomic bulk-action promise. A clicked result
must preserve its exact identity and lawful context, not secretly resolve to a
newer candidate or another source use. No new workflow action is selected by Q38.
**P07, P14, P17.**

### U11 — Useful operations and proportionate cost control

**H / plausible missing recovery; M / probable resource growth.** Metadata search
still needs measured supported workload and an actual operator capable of fixing
eligible projection failures without manual SQL as the normal user remedy.
Separate source truth from index/projection work. A stop or restricted-mode action
must suppress the affected unsafe result path without falsifying source records or
disabling independent qualified search elsewhere.

Measure query latency/failure and safe coverage, bounded projection backlog and
cost-relevant work without storing private query/body content. Declare budgets
from actual workloads and environment; do not invent numerical quotas, cheapness
percentages or guaranteed bills. A future B evaluation needs an explicit useful
cohort and actual incremental cost/complexity evidence, not a zero-field fixture or
all-disabled production path. **P02, P12, P18, P21, P22.**

### U12 — Compatible rollout and simple terminology

**H / plausible stale disclosure or scope creep.** Old clients/jobs/imports,
alternate APIs, caches and restore must preserve exact source/field eligibility
and current restrictions. No legacy all-file access, guessed field entitlement,
automatic body backfill, preview-derived index or restored revoked query result.
Unknown legacy eligibility stays unknown and receives a capable source-qualified
repair rather than a false searchable/not-found claim.

Reuse existing native/source authorization and metadata/view seams where qualified;
one ordinary search flow is enough. Do not introduce a second permission engine,
query builder, AI, OCR, new provider, tenant mode, obligatory tags or a whole future
Studio gate. Existing terms suffice; no new glossary term is proposed. Preserve
Q01–Q37 and their separate participant/notice/access/review meanings. **P01, P03,
P18, P21, P22.**

Suggested concise copy to validate with representative users:

- **Search files** with nearby **Search names and file details** explains A's scope.
- **No matches in this search** with visible filters avoids implying document
  contents were checked. A safe next step can be **Clear filters** or return to
  the current source; it must not silently broaden the query.
