## Recommendation and genuine alternative

Recommend **A: allow appropriately authorized source staff to mark an outstanding, unaccepted ordinary requested item No longer required within an otherwise eligible unfinished request**, when the item was requested by mistake or genuinely ceases to apply. Preserve its evidence and history; show the requirement outcome distinctly from Accepted. This is a real new ordinary-source power, rather than an inference from existing file, task or reviewer permissions.

**B: add no ordinary item action, and resolve the mistaken requirement through an already-qualified capable source correction or resolution route.** B is coherent where the organization deliberately controls requirement changes elsewhere. It carries navigation and handoff costs and must identify a capable accountable source owner. Neither a generic contact label nor an unimplemented cancellation/reissue workflow makes it a working alternative. No artificial third option is necessary.

The practical case is an unnecessary duplicate ordinary request item, not a legally mandated document. Inadequate evidence still needs Q23 Request changes; sufficient current evidence can be accepted under Q21. A participant saying that they cannot supply something is relevant information, not automatic permission to remove the requirement. No longer required says that this particular demand no longer applies; it does not say evidence was received, accepted, legally waived or destroyed.

## Final item and all-items cases

Q22 deliberately rejects both an automatic zero-count success and an invented universal minimum-one-file rule. Apply that exact distinction:

1. Removing an unnecessary item while other genuine obligations remain leaves those obligations intact.
2. If this was the last outstanding item, reevaluate the complete current authoritative source predicate and lifecycle. A lawful explicit rule may permit completion with accepted evidence plus this removed demand, or with a complete genuinely eligible empty/non-file requirement set.
3. All items marked No longer required is not automatically Fulfilled and not automatically Canceled. The source must explicitly allow its actual complete remaining set and purpose. Missing definitions, partial/filtered queries, failed reads and drafts are not a qualified empty set.
4. A request whose entire purpose ended must not be laundered into successful fulfillment by removing its items one at a time. Cancellation/withdrawal, where actually supported, remains a distinct source outcome with its own consequences; Q33 adds no such whole-request action.
5. The ordinary-source release must define and qualify this boundary before enabling A. It must not leave staff with a misleading zero-outstanding screen or fabricate success while source evaluation is unresolved.
6. If item removal committed but aggregate follow-through is unresolved, retain that item success and recover Q22 separately. No repeat click, second business approval, fresh access clock or backdated fulfillment is justified by response loss.

The interface should truthfully explain the currently qualified possible completion consequence before the meaningful action. It must not guarantee completion from a stale count or add a routine final Complete request button. Q22's actual occurrence and existing access clocks remain unchanged, including no revival when participant access already expired.
