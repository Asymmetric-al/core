# Phase 29 Q53 — Staff uploads as staff-supplied evidence

2026-10-26, Asia/Bangkok. **Fully ratified by Conrad: Q53 A — Allow staff uploads as staff-supplied evidence, with all required amendments and the exact glossary refinement.** Reviewed disposition: **Accept with required amendments**; the complete package is adopted. ## Decision in plain language

An authorized staff member who already possesses a needed file may add it directly to an eligible ordinary request item under their own identity. Keep the existing recipient-upload and Add existing file routes. A staff upload is a truthful staff contribution, not a recipient statement, proof of authenticity or approval. Normal private intake, technical checks and substantive review still apply.

The useful experience is **Upload file → choose file → Upload and add → truthful status** in the current item. The original deliberate action authorizes completion of that same intended upload and addition; do not make the user press another routine finalization button. An uncertain result needs recovery of that original action, not another blind upload. Existing-file reuse remains the faster route when qualified bytes already exist.

Illustration only, not observed ministry feedback: Nora has a lawful local copy of Elena's requested inventory. Nora sees the correct item and instructions, selects the file and adds it as Nora. Elena is not falsely recorded as uploading or affirming it. A source-required personal declaration still needs Elena's real participation. The reviewer can distinguish received evidence from evidence that has passed checks and been accepted.

Source eligibility, actual tenant roles and qualified restrictions govern; do not add a universal admin-only gate, second reviewer, tenant settings matrix or new permission engine. Possession, reading, task assignment and reviewer status are not upload/admission authority. New to custody means neither fresh nor authentic. Actual source receipt/admission time is not browser start, external email date or file metadata; do not backdate participant timeliness. **Q53-C03 — One deliberate contextual action.** In the eligible item, offer Upload file beside Add existing file. **Q53-C04 — Private qualified intake.** Reuse the shared custody session bound to actor, Tenant/environment, source/item/purpose, immutable target, relevant revisions, finite type/byte/count profile, expiry and semantic operation identity.
