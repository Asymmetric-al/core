# Phase 29 Q54 — Combined manual reuse and optional possible-file suggestions: independent UX review

2026-10-26, Asia/Bangkok. **Q54 A+B is selected, pending full adversarial review and ratification.** Q01–Q53 are ratified. The selected outcome preserves deliberate Q28 Add existing file and Q53 Upload and add, and adds a narrowly qualified optional hint before the upload intent. This note writes only its assigned work file. It does not ratify Q54, change canonical documents, implement a screen, upload a file, contact a provider or create a new notification. The 31 canonical terms remain unchanged.

## Recommendation and evidence limits

Deliver this as quiet assistance beside two complete existing actions. After an eligible staff member selects a local file, the interface may asynchronously offer an independently authorized held version under **An existing file may match**. One safely distinguishable candidate may have a direct **Use existing file** button that is the deliberate Q28 action; preview is optional. Several candidates use the existing qualified picker, with no automatic choice. **Upload and add** remains available without waiting for matching. Once either source action begins, the helper must not offer a competing action for that same original intent.

The user selected both approaches after the earlier research recommended the smaller manual baseline. This review honors that selection rather than repeating the question. The strongest manual-only alternative remains credible: it avoids new fingerprint computation, disclosure checks, asynchronous state and distraction, while retaining real reuse. Its cost is missed eligible files that staff do not know to search for. The selected helper can address that discovery gap, but no measured Asym frequency, task-time saving, lower bill, duplicate reduction or ministry workflow establishes its benefit here. Those are unmeasured hypotheses, not acceptance evidence.

The parent accepted one bounded tenant control for the convenience, with the initial enabled setting effective only after deliberate qualification and rollout of the applicable cohort. Existing tenants are not silently activated by data backfill. Staff can dismiss suggestions for their current selected file without repeated reappearance. This is a reasonable flexibility choice, not a claim that all modern products use this default. The leaner alternative is source-qualified availability without a dedicated tenant switch; the selected control is justified only as a way to stop this optional work and noise without changing ordinary upload/reuse powers. No per-user preference matrix, per-item matching policy, new settings page, reminder setting or channel choice is required.

An illustrative journey: Nora selects `inventory-final.pdf` for Elena's eligible request item. An independently discoverable and reusable held version is named “Equipment inventory — October.” Nora may not know that name. The hint can make that exact held version available for deliberate reuse. It must not imply that the local file has been received, that the two files are authoritatively identical, that the evidence is current for this purpose, or that Elena supplied it. Nora may instead upload her selected file. This example is invented to explain the choice, not observed usage.

## The smallest complete user experience

Keep the selected local file and the normal **Upload and add** action stable. A suggestion must not appear under a pointer, change the main button's meaning, steal focus, replace the file selection or turn routine upload into a duplicate-resolution task. A quiet inline area is enough. No helper spinner is necessary on every file; if a material check state is exposed, explain that upload can continue and announce it once, not on each hash chunk.

For a single candidate, show only permitted distinguishing context: a safe current label and, where authorized and useful, source/version information. A raw received filename, a thumbnail, private request title or original body is not mandatory. The button **Use existing file** is already a meaningful final action in the target item and may directly invoke Q28. It does not need a separate “Are you sure?” or a preview read. If safe metadata cannot distinguish the exact choice, provide an already-qualified picker/context route that can; otherwise withhold the shortcut and leave the manual paths usable.

For several candidates, **Choose existing file** opens the existing permitted picker with a bounded candidate context. It must not silently select a “best” copy because its bytes, date or name look alike. Different source uses of identical bytes may have different rights and meanings. The picker may offer **View file** only under independent read rights and **Use existing file** only under current Q28 authority. Returning from inspection restores the local selection and the prior focus position where safe; it must not restart the upload or repeat a dismissed hint.

No candidate is preselected. Selecting a picker row is not adding it. Choosing or changing a local file can initiate the qualified helper query, but never creates a request receipt, review, notification or source admission. The final source action must be unambiguous. We do not promise that file selection entails no network traffic: the selected feature specifically permits the narrowly authorized lookup.

## Lifecycle and resource restraint

The helper's useful lifecycle is small: not applicable/disabled; preparing local file; optional computation/query; timely permitted candidates; no usable cue; dismissed; and closed by selection/context/source-intent change. These are interface/technical states, not a new business aggregate or required durable workflow. Once a deliberate Q28/Q53 act exists, use that owner's pending, committed, failed or unknown-result lifecycle. Do not create a second queued “reuse requested” object with different truth.

An aborted optional query is not a failed source contribution. A source contribution committed after a lost response is not canceled by closing the dialog. A candidate list frozen on screen does not freeze eligibility. An independently lawful ordinary Q28 selection is not revoked by helper Off. An unchanged source result does not acquire a new admission time because matching reruns. These distinctions are the minimum complete flow, not extra user-facing jargon.

Finite qualification is needed for six resource groups: browser file bytes/working memory/CPU/concurrency; authorized candidate query work and page/result size; helper request/response lifetime and stale-context handling; sensitive query/client-state retention; tenant/global service fairness; and any unused Q53 preparation's current disposition/retention/reference handling. Actual numbers belong in the qualified release profile. This note does not invent a maximum file size, all-device guarantee, arbitrary candidate cap or cost-free index. A bounded unsupported file simply receives no helper while its independently qualified baseline path continues.

Operational controls can remain in existing surfaces: the helper-only tenant switch; current-file dismissal; source permission/restriction enforcement; source result recovery; existing source/custody privacy/disposition remedies; and bounded protected observability. None is a new approval queue, duplicate inbox, cleanup task or notification channel. Required security evidence is preserved under its own contract; minimizing generic logs does not mean disabling real audit.

## Glossary and stage judgment

No new domain term is needed. “Possible existing file” is explanatory interface language for a derived candidate, not a new durable business identity. Exact versions, source uses, Staff-supplied Document Evidence and existing Q28/Q53 actions already describe the authoritative outcome. Do not rename a possible hint “Duplicate Document” or “Verified Copy” and accidentally confer identity/equality. Canonical terms remain 31 pending any separate actual term decision.

The selected combined answer is defensible with these amendments. It is narrower than a duplicate-management product and more honest than a guaranteed same-file detector. Its real value is discovering an allowed existing version before a staff member commits upload; its real cost is optional client/query work and additional current-disclosure states. The complete manual route remains the strongest alternative and the reliable path when no timely hint appears.
