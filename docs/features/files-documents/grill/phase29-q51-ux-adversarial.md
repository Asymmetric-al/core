# Phase 29 Q51 — Directed review-comment attention: independent UX adversarial review

2026-10-25, Asia/Bangkok. **Q51 A selected, pending ratification.** This review proposes the complete small interaction and source-compatible safeguards for deliberate staff attention from an exact Q45 comment. Q01–Q50 and the current 30 glossary definitions remain ratified. Only this assigned work note is authored; no native implementation, contact, provider, private-account, SQL or external publication action was performed.

**Disposition: accept A with required amendments.** Use a saved-comment **Notify a colleague** action, one deliberately selected eligible colleague, and one informational native notification under the existing governed staff center. Keep comment Post, correction, withdrawal and Restore under Q45. A typed `@name` remains plain text. No composer notification field, rich-text mention parser, group fan-out, follower system, task, reply obligation or email lane is required for this first slice.

## Recommended permanent journey

1. Staff post a normal comment through Q45. After the comment is durably admitted, **Notify a colleague** is available on that saved comment immediately and later. The action is also available on another author's comment to an actor with the current ordinary source's qualified comment-create and exact-comment read powers, as explicitly adopted for this act; it is not author-only and does not invent a new broad role. A pending/unknown Post must first recover its original comment result.
2. A small contextual surface identifies the actual saved comment and offers one labeled **Colleague** picker. Use current permitted author/time/source context and the already authorized comment where useful; do not require a new explanation, title, file preview or body copy. The picker has no default target, no self target, groups or arbitrary email address. Selection is local until **Notify**. **Cancel** has no source effect.
3. **Notify** is the one deliberate final action. Validate the actual current comment revision, actor/target identity and access, optional-purpose controls and duplicate basis. If something changed, preserve the lawful selection and provide a deliberate correction path; do not redirect to another person or silently notify a different revision. No second confirmation ritual is needed.
4. Show **Notifying…** only while the deliberate command is in flight. One atomic local command commits the source attention occurrence, complete one-member Phase 6 plan release, local availability event/P17 projection, required source history and durable result together. **Notification added** requires that proved committed availability. A known failure rolls back the whole notification effect; an unknown result is checked against the original operation before fresh work. There is no durable accepted-but-queued notification state, worker or provider lane. Added never means read, seen, emailed, assigned or answered. The saved comment is never reposted to repair an attention failure.
5. The colleague receives the informational item in the active-tenant staff notification center's **All** presentation. It has a minimal qualified cue and a typed **View comment** action. It does not enter required **Needs attention** work. Opening it returns to the exact comment/use/version context under current rights; a marker jump is secondary and available only with a qualified exact mapping.
6. Ordinary notification read/archive controls remain engagement only. A correct but unnecessary cue can be archived by its recipient. A mistaken eligible colleague does not create work debt: notify the correct different colleague through the same action, without withdrawing the comment or manufacturing a new one. There is no sender recall/Undo after admission. Actual privacy problems use the source's separately qualified restriction/disposition remedy.

This adds one extra deliberate action after posting compared with an inline composer selector. That is an honest cost. The benefit is a single understandable saved target, no combined Post-and-notify failure ceremony, and support for existing comments without a second interface. A later composer shortcut could be assessed separately if real use demonstrates a need; it is not quietly included now. The saved-comment path should be readily discoverable beside ordinary comment actions, not hidden in a distant notification settings page or offered only in a transient toast.

The per-revision rule is a compromise worth stating plainly. Once-per-comment forever would be quieter, but could force a new comment just to draw attention to a legitimate correction. Per-click resend would be flexible but noisy and harder to distinguish from retry. Existing visible revisions plus explicit action offer useful flexibility without a new cooldown or semantic-content classifier. It does not prevent deliberate misuse through repeated real edits; actual bounded source rates and operational abuse controls remain necessary, without claiming an invented user-behavior result.

## Sixteen exact required UX/source amendments

These assess prospective omission risks, not existing production vulnerabilities. Severity is High for material confidentiality/authority/integrity or unrecoverable outcomes; Medium for substantial friction/noise. Likelihood is qualitative and unmeasured.

### U01 — Saved, exact and optional action (Medium / likely for affected users)

Provide **Notify a colleague** on a durably admitted active Q45 comment, immediately after known Post and on later access. Keep Post and notification as separate deliberate commands; no inline-composer attention field or rich-text parser is needed. The actor needs the explicitly adopted ordinary source's current comment-create capability and exact-comment read authority, not necessarily original authorship. Plain `@text`, typing, selecting, blur, preview, comment edits and canceled local choices have no attention effect. Ordinary comments remain useful without any notification. **Proof: P01–P03/P25.**

### U02 — One explicit eligible colleague and safe discovery (High / plausible)

Select one specific currently eligible colleague with a trusted stable staff identity and actual admitted assignment/access context. Exclude the actor's self target, groups and arbitrary addresses; do not default to the first suggestion. Candidate identity/disambiguation fields require current disclosure to the actor and target qualification for this exact internal context. A visible file, parent task, email match, roster or generic staff rank is insufficient. No directory existence, sensitive denial reason or profile linkage may leak through counts, loading, errors or autocomplete. **Proof: P04–P07.**

### U03 — Native staff identity without account fiction (High / plausible)

Explicitly adopt the compatible source/P12/P6/P17 staff branch, including supported no-Party staff, using trusted current Tenant/environment/identity/assignment rather than a fabricated Party or raw address. Stable duplicate identity across requesters does not transfer the original cue, unread state or history into another role/assignment. Same-human participant sessions and other tenants remain separate purposes. No full enrollment, new role platform or automatic access grant follows. **Proof: P05/P07–P09.**

### U04 — Exact revision and one semantic occurrence (High / plausible)

Admit at most one occurrence per actual current active Q45 comment revision and stable target staff identity, across requesters and transport keys. Use Q45's actual visible revision, not a new content graph or semantic classifier. A genuine later active revision, including lawful Restore, may be explicitly notified under current rights; no-op edits create no slot. Read, archive, expiry, access return, another requester or operation key cannot reset a spent slot. Original presentation remains bound to its admitted assignment/access basis. **Proof: P10–P13.**

### U05 — Current coherent admission and durable recovery (High / plausible)

At the authoritative boundary, validate exact actor/target/source/comment basis, controls, duplicate identity and useful destination. One atomic local command SHALL commit the source attention occurrence, complete one-member Phase 6 plan release, local availability event/P17 projection, required source history and durable result together. Failure rolls back the entire notification effect; the pre-existing saved comment is unaffected. No normal accepted-but-unavailable queue, worker or provider stage is introduced. Replay the original result under current disclosure before creating fresh work. Unknown response is not failure; changed recipient/comment intent conflicts rather than rewriting an old operation. A valid comment is never deleted, reposted or replaced to repair notification. Known ineligibility/Off before commitment produces no cue or semantic slot; a later deliberate eligible act is new current intent, not automatic old-command revival. **Proof: P06/P10/P14–P17.**

### U06 — Informational native outcome, never work debt (High / plausible)

Use the existing active-tenant P17 staff center and typed exact-comment destination under the compatible informational policy. No new inbox, required Needs attention item, task, reviewer reassignment, deadline, response/Resolve/read-receipt gate or new email/push/SMS lane is introduced. Distinguish in-flight client status, known rolled-back failure, unknown result, proved committed availability, later read/archive and underlying source state. “Notification added” requires the actual qualified availability committed with the source effect; it does not imply the colleague saw it. **Proof: P17–P20/P26.**

### U07 — Optional controls with no catch-up surprise (High / plausible)

After qualified activation, the exact optional native purpose is initially On under existing tenant/recipient controls in the governed order. Known Off before the atomic command commits has no effect/slot. Off after committed availability ends unread treatment without fabricating Read/Archive; authorized recent history retains its original 90-day ceiling. Later On never replays old work, creates unread debt or resets duplicate identity. There is no pending-admission queue to drain on enable. This is a narrow explicit Q51 informational-end amendment, not a new settings system or a rule for unrelated required notices. Private preference reasons remain private unless independently disclosable. **Proof: P06/P18/P21–P22.**

### U08 — Source applicability and access loss are precise (High / plausible)

Qualify the current exact comment/context purpose at every admission, projection, list/count/preview/history and navigation boundary. Actual bound-access-revision loss removes active/recent presentation; later authority cannot revive it. Temporary authorization-evaluation failure only fails closed for current serving and does not prove permanent loss. Acceptance, fulfillment or request status alone is not necessarily comment irrelevance; actual source purpose and restrictions decide. A comment revision change, supersession or withdrawal before the atomic availability commit prevents admission on the old basis. After that commit, it ends the old cue's unread treatment and leaves only currently authorized minimal recent/current-state navigation until the original 90-day end. Explain updated/unavailable context rather than show stale body or pretend current text is the originally notified revision. Restore never revives an old cue, though its real new active Q45 revision may be explicitly notified. **Proof: P07/P12/P19/P23–P24.**

### U09 — Useful exact navigation without extra byte rights (Medium–High / plausible)

The cue returns to the exact comment/use/original-version context through a typed server-resolved destination. Preserve current permission for comment and metadata independently of preview/original bytes. If a rendition expired or mapping is unavailable, retain lawful comment context with honest location-unavailable behavior; never jump to newer bytes, force download, re-upload, renewal or an external viewer. Minimal cue content must identify the work usefully without generic copying of private bodies, filenames, Q50 staff names or restricted location/identity metadata into a broader surface. **Proof: P08–P09/P19/P23–P24/P27.**

### U10 — Clear choice and permanent mistake recovery (Medium / likely for affected users)

Show the saved comment context, one Colleague field, **Notify** and **Cancel**. No new message body, reason essay, custom title or second confirmation is needed. Before admission, selection/cancel is local. After admission there is no sender recall/Undo; notify the correct different eligible colleague without reposting, while the original recipient uses ordinary read/archive. Actual sensitive-content or authority errors require a capable separately scoped source/privacy remedy, not broad grants, fabricated follow-ups or forced withdrawal of a lawful comment. **Proof: P02/P06/P25/P28.**

### U11 — Honest result and duplicate copy (Medium / likely for affected users)

Keep in-flight, added, already requested, known no-effect and unknown distinct; a later ended/hidden presentation is not proof that the original atomic command failed. Recover the original semantic outcome rather than issue a new key as retry. An existing occurrence can be reported only with currently disclosable facts; do not expose who previously requested it or the target's read/archive/preference state by default. An unavailable/no-match picker is not proof no eligible person exists. Preserve lawful target/input on recoverable errors; tenant/purpose/authority changes fence stale candidates and responses. **Proof: P04/P14–P18/P21/P29.**

### U12 — Accessible interaction and source-context return (Medium–High / likely for affected users)

Reuse `@asym/ui` Base UI/base-maia. Provide visible labels, matching accessible names, keyboard/speech/touch operation, meaningful initial/restored focus, 320-CSS-pixel form reflow, zoom, RTL/IME and understandable localized time. Popup focus/selection and composition-confirming Enter do not submit Notify. Announce material pending/error/outcome without focus theft or per-keystroke chatter. Full target/context identification and actions cannot rely on hover, color or toast alone. No automatic open/download, forced preview or durable private offline store. **Proof: P25/P27/P29–P30.**

### U13 — Existing owners and effects remain separate (High / plausible)

Q45 comment meaning, review basis and source mutation remain intact. Q24 responsibility, Q22 fulfillment, Q23 changes requested, Q30 participant discussion and other communication/reminder purposes are neither triggered nor suppressed by generic Q51 activity. No direct attention to participants or Q41 external readers is created. Existing native preference/presentation semantics apply only through explicit qualified adoption; Support, finance, contribution or vendor defaults do not confer authority. **Proof: P01/P08–P09/P20/P26/P31.**

### U14 — Bounded native data and all-path privacy (High / plausible)

Bind trusted immutable scope, comment revision, target identity/context, complete event/plan/step membership, meaningful transition and semantic operation result with actual native constraints and current source/P12 checks. Qualify effective grants/RLS, functions/views/triggers/services/imports/browser/caches/repair/restore and all count/serialization doors. No raw public post_comments, generic queue or demo bell becomes the source. Bound candidate queries, list/fanout, command/result recovery, retained metadata and source rates; measure actual resource cost without new provider/Realtime requirements or a free-operation claim. **Proof: P04/P05/P15/P31–P33.**

### U15 — Future-only rollout and capable recovery (High / plausible)

Adopt the exact typed producer, staff identity, native destination, current applicability/end rules and compatible writers/readers before activation. No historical @text backfill, duplicate projection writer, inherited engagement, suppressed-cue catch-up or broad permission fallback. Preserve admitted comments and required body-free evidence during scoped stops. A source operator can reconcile actual unknown results or an invariant incident under current rights; restore applies later restrictions before serving. This is not a normal queued-delivery product state. No SQL-only routine recovery or automatic old-intent reissue. **Proof: P14–P17/P21/P28/P32–P34.**

### U16 — Evidence, alternatives and stage discipline (Medium / certain if only A is recorded)

Maintain exact U/J/P and owner trace. Distinguish source intent, static implementation, isolated tests, native real-role behavior, intended-user/AT tests, provider state and workload measurement. Vendor docs are not user studies; no ministry behavior, missed-comment rate or response SLA is known. Keep unaddressed comments and actual existing coordination usable. Record current decisions pending ratification; do not add a new term, channel or subsystem just because a notification button exists. **Proof: P30–P34.**
