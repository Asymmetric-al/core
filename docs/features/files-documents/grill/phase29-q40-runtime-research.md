## Recommended bounded choice

Recommend **A — an eligible optional participant email, initially On with a visible staff choice to decline, for a deliberately published ordinary item addition or material instruction revision**. Native on-return cues are already required by Q36/Q37, but a participant may continue preparing old work without reopening the request. A small factual cue can draw attention to the change. It is not proof the person read/understood it, a new requirement, an access grant or acceptance.

**B — the same qualified optional capability with the per-act choice initially Off** is credible when amendments are frequent, staff already spoke with the person or most changes need no out-of-product cue. Keep its initial tenant capability offering the same if comparing only On versus Off. **C — no dedicated email capability**, using native changed-work context plus an already-qualified capable source contact route where lawful, is a real smaller alternative; manual contact costs navigation/consistency and must not be invented as a generic email-any-address escape.

Authorized tenant controls should remain bounded to this exact optional purpose within P17, with actual availability distinct from the initial per-act choice. The exact configuration/default and pending-work stop semantics belong in the selected-answer review. Prior Q35 controls are a useful precedent, not automatic new-purpose authority. Missing or ambiguous legacy choice is not On. Preserve an already reviewed explicit choice when a default changes.

This recommendation is product judgment. No observed Asym amendment frequency, response rate, benefit or notification-fatigue measurement exists. No new digest, scheduler, reminder, channel, inbox or general settings engine is selected by proposing A.
