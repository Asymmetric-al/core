The requesting source's attributed record that a specified earlier Document Request Item Acceptance was made in error, together with its current source consequences. It preserves the original decision and is distinct from Submission Correction, Request changes, deletion and request reopening.
_Avoid_: unaccept toggle, undo acceptance, Submission Correction, request reopening, deleted evidence

## Complete UX and lifecycle

An authorized reviewer notices that an item was accepted on a mistaken basis. In the item's existing review surface, Correct acceptance shows the exact decision and consequence. The reviewer records the intelligible basis and submits once. On known success the item says Needs staff review; the received files and original decision remain visible to their qualified readers. Continue review uses that retained evidence. Only a fresh actual Request changes decision asks the recipient for anything. This is a prospective design journey, not observed ministry behavior or a tested interface.
