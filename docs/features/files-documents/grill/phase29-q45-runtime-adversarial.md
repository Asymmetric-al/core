## Disposition and the small complete model

Accept A+B with the boundaries below. Use a source-owned exact-version comment with **at most one optional closed typed location/anchor**, a current revision and source-governed history. Keep text composition, pointer movement, zoom and unfinished marker selection local until deliberate Post/Save. One source command atomically admits text, exact target, optional anchor, attribution/revision, required history and recoverable operation result. Read the comment list and relevant page markers in bounded authorized batches. A marker is metadata over an unchanged qualified representation, not a new file or screenshot.

Flat independent follow-up comments are sufficient for this first scope. Current-authorized authors may correct their own text/location on the same target through an attributable successor revision, withdraw current presentation under source retention, or deliberately Restore an ordinary withdrawn comment under the exact current-state rules below. A scoped source operator may restrict/withdraw or repair qualified attribution/location issues after departure without writing another author's words; operator Restore requires its own actual authority. Do not inherit post moderators, hard-delete cascades or a Reply/Resolve/unread/Trash engine. The root/owner synthesis will make these exact lifecycle choices binding in its proposed decision.

Supabase health is achieved through bounded work and a correct data boundary, not a promise that comments are cheap. No per-pointer write, per-pin query, whole-history JSON rewrite, broad collection subscription, CRDT, presence or mandatory Realtime is needed. One explicit write still needs safe conflict/replay, and one bounded read still needs P12 source projection. Measure actual query plans, rows examined, locks, WAL/index growth, API payloads and active-user load before release. A synthetic loop is not a hosted database benchmark.

## Current primary technical research

- PostgreSQL distinguishes old-row visibility from new-row acceptance, including UPDATE/ALL default WITH CHECK behavior and permissive/restrictive composition. Effective privileges, functions, views and triggers must be examined together. [CREATE POLICY](https://www.postgresql.org/docs/17/sql-createpolicy.html), [row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html).
- Definer functions run with owner privileges and need safe name resolution and deliberate EXECUTE grants; invoker alone is not proof a privileged service caller lacks access. [CREATE FUNCTION](https://www.postgresql.org/docs/17/sql-createfunction.html#SQL-CREATEFUNCTION-SECURITY).
- Stable pagination needs a unique order, and large OFFSET still computes skipped rows. Composite-index usefulness depends on query predicates and leading columns, not a universal speed multiplier. [LIMIT/OFFSET](https://www.postgresql.org/docs/17/queries-limit.html), [multicolumn indexes](https://www.postgresql.org/docs/17/indexes-multicolumn.html).
- Keys/checks/FKs express structural invariants; actual plans and rows examined establish performance. EXPLAIN ANALYZE executes its statement, so future measurement must use a qualified safe test database/transaction rather than casual hosted mutations. [Constraints](https://www.postgresql.org/docs/17/ddl-constraints.html), [Using EXPLAIN](https://www.postgresql.org/docs/17/using-explain.html).
- Supabase Postgres Changes performs authorization work per event/subscriber and preserves order through single-thread processing. Built-in subscriptions therefore are not free fanout; filters do not satisfy Core's confidentiality floor. Context7 `/supabase/supabase` corroborated the current primary page. This does not select Broadcast or a provider threshold for Q45. [Postgres Changes scaling](https://supabase.com/docs/guides/realtime/postgres-changes#scaling-postgres-changes), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).
- Current Mozilla documentation shows PDF viewport scale/rotation/origin/HiDPI transforms; W3C distinguishes a target/state from a selector. These support explicit representation/coordinate provenance, not adopting PDF.js, JSON-LD or every annotation type. [PDF.js examples](https://mozilla.github.io/pdf.js/examples/), [Web Annotation Data Model](https://www.w3.org/TR/annotation-model/).

Root separately checked current Supabase changelog compatibility notices; no upgrade/extension/type/provider mutation follows from research. ## Exact proposed amendments

### C01 — One ordinary source purpose, independent rights, no new inbox

The initial scope is internal staff review comments for an actual ordinary request evidence contribution/use and its exact original version. Tenant/environment, source, request/item/use/version and business purpose are immutable scope. Equal bytes, a file title, Q28 reuse or a global document identifier do not union comments or audiences. Preserve applicable originating-use restrictions. No automatic Party note, Support conversation, task, notification, mention grant, participant reply, public share, original annotation/export or Q44 ZIP inclusion follows.

Current source/P12 comment read, create, author correction, withdrawal and operator repair are distinct from original-byte read/download. Byte/preview unavailability alone does not remove an otherwise lawful comment path; current confidentiality restrictions still apply to text/author/location/version metadata under their actual source projection. A comment containing protected context cannot be used to bypass a source restriction merely because it is text. No new universal accepted/unfinished/request-open predicate is imposed; use the actual staff source rule.

### C02 — Exact target and minimal typed location

Use one source-owned comment with at most one optional closed typed location: no location, supported page/slide/sheet-cell/literal reference, or a qualified static PDF/image point/bounded region. The display label, original page ordinal/printed page label, slide index, sheet identity/cell address and text/CSV location are not interchangeable. A human explanation is not machine-verified navigation. Reject unknown kinds/fields and incompatible target/format combinations; no arbitrary selector script, SVG, DOM path, URL, screenshot or copied body is required.

Bind a spatial anchor to exact source use/version and qualified representation/geometry semantics, including page/image identity, relevant profile/projection/rotation/orientation/view box and mapping revision. Retain the actual creation basis for history. A technical generation may establish that basis but is not the comment's sole identity or retention owner. Never silently bind a Post to latest, the focused pane, filename, digest-global content or another use. A deliberate new target is new authoring intent, not an in-place retarget of admitted history.

### C03 — Local composition and one deliberate durable act

Keep keystrokes, pointer movement, tentative region, pan/zoom, hover and focus local to the current draft. They generate no comment write, row per point, presence event or subscriber fanout. Post/Save performs one bounded authoritative command, not separate save-text/save-anchor calls. Freeze the user-reviewed exact target and anchor basis for that command. Keyboard/IME composition and input changes never trigger submission.

The server derives actor/Tenant/current assignment and source references; it accepts no caller-declared authority, owner, version promotion, profile version, access token or provider path as truth. Atomically commit accepted text, target, optional validated anchor, current revision, original operation result and required attributable history/audit. Return that authoritative result. Optional UI invalidation failure does not make the comment uncommitted. A demo/local optimistic row must be labeled pending and cannot masquerade as saved.

### C04 — Finite geometry, safe canonicalization and explicit failed-anchor recovery

Validate numeric types, finite values, dimensions, coordinate bounds and compatible point/region shape against trusted actual page/image geometry. Reject NaN/infinities, booleans/numeric strings, out-of-bounds or reversed/degenerate regions and impossible page/sheet references; do not silently clamp them into a different intended location. Qualify a finite precision/canonicalization profile and validate its resulting stored geometry, not just pre-rounding input. Define minimum usable region/point interaction in the actual reader, not a guessed schema constant.

Transform through the reader's declared page/image geometry, rotation, view/crop box, user unit, orientation, CSS zoom/pan and device scale. Never persist raw viewport pixels and hope future screens match. For a newly selected or changed anchor, if current placement authority/geometry cannot be proved before admission, retain the lawful draft and explain the affected location. Offer deliberate retry/reselection or explicit removal of the anchor and Post as a general exact-version comment where permitted; never silently downgrade a reviewed anchored Post. A text-only edit retaining an unchanged admitted anchor may keep its exact existing basis with Location unavailable when current comment/source rules allow but current preview mapping is absent; it neither requires regeneration nor drops the anchor. No successful preview is needed merely to post a lawful general comment such as an inspection difficulty.

### C05 — Current rendering and exact compatible regeneration

Read/show/navigate a marker only when the current actor may see its comment/location and the current exact representation. The list can show only permitted comment information when original/preview access is separately unavailable; location navigation must not fetch forbidden bytes. Missing text/OCR is not an error that authorizes extraction or external viewing.

New source versions never inherit anchors or approval. A new rendition generation for the same original may display the old anchor only through a positively qualified compatible geometry/location mapping; same source digest, page count or profile name alone is insufficient. Missing, changed, expired or uncertain mapping produces an honest unavailable location. Do not guess, fuzzy-match, automatically move the anchor or keep an expired generation alive. Coordinate placement is optional presentation capability, not a new grant or source review fact.

### C06 — Exact replay and expected-revision correction

For an authenticated caller with safe reconciliation authority, recognize a matching committed semantic operation before applying new-command eligibility; compare its original normalized input and reconcile the original result under current disclosure. Reusing an identity with different text/target/anchor conflicts. Unknown acknowledgement is neither definite failure nor permission for a new Post. Preserve draft and same-operation recovery until known; repeated clicks/callbacks do not create duplicates.

Editing text/location on the same immutable target requires the expected current comment revision and actual current author authority, producing an attributable successor revision. Concurrent edit/withdrawal must have one ordered winner; stale Save retains the lawful local edit and offers review of the current state, not last-write-wins. Ordinary withdrawal hides current presentation under source rules while required history remains restricted; no routine hard-delete/child cascade. Do not recreate a withdrawn comment through old Post or Save replay. Retain minimal opaque dedup/result-or-reject evidence separately from readable history, or reject unverifiable stale operations after expiry/restore.

### C07 — Small permanent correction and source-review ordering

Allow current-authorized authors to correct their own text/location on the same exact source target or withdraw the comment's ordinary presentation. The actor and revision history remain truthful. Author departure does not transfer authorship or automatically delete source history. A scoped source operator may withdraw/restrict or repair an attributable location/metadata problem under actual authority, never impersonate another author or silently rewrite their words. A wrong-version comment is withdrawn/corrected through a new deliberate correct-target comment, not moved retroactively.

Ordinary withdrawal is reversible through deliberate Restore of the exact current withdrawn record, using its expected revision and latest lawfully retained body/anchor. Restore creates a new attributed revision on the unchanged source/use/version/purpose; it is not old Post replay, history-version overwrite or target movement. The current-authorized author, or an operator with separately scoped Restore authority, must pass current disclosure and source rules. Preserve original authorship and actual restorer attribution. Governed restriction/redaction/disposal or source-ended content cannot be revived through this action. An unchanged retained anchor may remain Location unavailable when the comment is lawful but mapping is absent; Restore neither silently drops it nor forces preview regeneration. No general Trash, restore-any-history or undelete platform is introduced.

Use flat independent follow-up comments; no new nested replies, Resolve/unread/seen gate, task completion requirement or discussion inbox is necessary. Structurally relevant new/edited/withdrawn/restored comments invalidate only the affected uncommitted human review basis as explicitly qualified by the ordinary source. No language-model relevance classifier, all-request blanket invalidation, mandatory reading/replying/resolving or undo of an already committed acceptance/review result follows. Preserve already admitted participant receipts and all prior review outcomes; re-review remains its owning command.

### C08 — One PDP, coarse Tenant RLS and all disclosure doors

Use P12's sole fine-grained resolver and exact validated Tenant Authorization Context, assignment, source/purpose/field floor, epoch and expiry at each actual create/edit/withdraw/read/recover/navigation door. P12-prescribed coarse Tenant RLS uses the same trusted Tenant source; no second membership/capability/anchor-privacy engine is embedded in RLS. Prepared capability helpers, role/profile strings, copied memberships, service credentials or an old client permission snapshot are not authority.

Comment/list/count/author/location/history projections are independently governed; a user who can read one file is not automatically permitted to read every comment or author. Check source disclosure before returning hidden-target distinctions, foreign IDs, counts, snippets or cursor metadata. Protect private caches and late responses by actor/context/Tenant/purpose/source/version and current relevant policy. Listing does not download originals or open a PDF. Location navigation uses the existing current private reader; no raw provider URL, direct Storage listing, public fallback or external office viewer is introduced.

### C09 — Native relational invariants and effective SQL permissions

Enforce non-null immutable same-Tenant/environment/source/use/version/purpose attribution; compatible composite relationships for comment, current revision/history, author context and optional location basis. Unique semantic operation identity and guarded current revision prevent duplicate writes. The anchor kind and payload are closed and bounded, with native checks for expressible shape/numeric/state constraints. Current cross-row eligibility stays in the one trusted source boundary. Do not use an arbitrary unvalidated JSONB document as identity, global digest/name uniqueness or a generic foreign target union that cannot prove scope.

Inspect actual effective grants and RLS enable/force state, old/new-row semantics, permissive/restrictive composition, required SELECT policies, INSERT/UPDATE/DELETE/UPSERT/MERGE and RETURNING/error paths. This is qualification of the prescribed boundary and actual privileges, not a blanket new FORCE RLS configuration decision. Include views, inherited roles, owners, BYPASSRLS/service roles, invoker/definer functions, safe search_path/EXECUTE, trigger side writes and all raw Data API/GraphQL/CMS/import/job/repair/restore paths. Missing explicit WITH CHECK is judged by effective default behavior, not keyword absence. Default PUBLIC function execution must be deliberately closed where inappropriate. Actor/source/version keys and authorship cannot be reassigned through privileged shortcuts. Do not cascade author/source cleanup into losing required comment/replay history or retaining forbidden body text indefinitely.

### C10 — Bounded reads and explicit lightweight freshness

Read one bounded source/version comment page with a stable unique keyset order, using an immutable server order key plus ID tie-breaker and a context-bound cursor. Apply current source/security projection before pagination and return only allowed fields. Cursor possession grants no access. Qualify deep history, equal timestamps, inserts/withdrawals between pages and sparse visibility; keyset is not a universal constant-time guarantee. Do not label a loaded slice as all comments or a failed/filtered lookup as zero.

Fetch marker metadata for the currently requested qualified page/image in bounded batches, reusing the permitted comment projection and batched author metadata. Never perform one remote policy query, one file fetch or one request per pin. More comments/markers than the qualified view budget require explicit pagination/partial-coverage behavior, not silent missing pins. Do not load every comment revision, page or full document merely to draw the current page or badge. Avoid unneeded exact global counts and hot parent-row counters.

Use the ordinary successful-command response, explicit refresh and bounded current-context revalidation on reopen/return to keep the view usable. This feature does not depend on raw postgres_changes, Realtime presence, live cursors, CRDT or an always-on poller. Any already-qualified shared signal remains signal-only, subject to P12 restricted-tier silence, current context and coalesced refetch; it cannot transport comment text or become necessary for correctness. Stale-write protection lives at the server even when another user's comment has not yet refreshed.

### C11 — Supabase health, indexes and actual measurement

Qualify finite text bytes, location-payload size/precision, list size, marker batch/density, history retrieval, concurrent writers, refresh/retry rates and source/Tenant workload. Keep blobs, screenshots, originals and cached rendition bytes out of comment rows. A Post/Save updates a small comment/revision set plus required history/audit; do not rewrite a whole document/task JSON or append every pointer move. Index actual source/version/scope filters and unique order keys, and necessary referencing/cleanup paths. Covering indexes are chosen from measured plans; do not stuff large text into every index or add a GIN/full-text/spatial extension without an actual query need.

Preserve P12 R6's logical ≤1 governance-row SELECT + ≤1 ledger UPDATE per governed read, its physical carve-outs and restricted safety priority. This is not one total data query and not one resolver per row. Use set-wise/index-backed projection and bounded transaction locks; no lock during human typing or network preview generation. Future safe test qualification must capture EXPLAIN/ANALYZE/BUFFERS and real-role row counts/plans, latency/lock waits, connection use, API bytes, WAL/index/table growth, repeated edits and skewed source distributions. Measure write amplification and retention cleanup, not only median first-page read.

No current invoice neutrality, capacity, database health pass, 10x gain or O(1) claim is made. Existing indexes, managed compute, connection pools and extensions must be inspected on the actual authorized release environment. Prefer existing APIs/queries and small native fields over a new service or policy engine. On overload, bound admissions/refresh and show useful retry while preserving unrelated intake/review; do not bypass authorization or switch to a public collection.

Match exact current admission time and expected revisions; stale UI/client clocks and deferred callbacks are not authority. Denied/unknown current use prevents affected admission or disclosure, not an invented permanent burn of an otherwise lawful comment. Governed terminal restriction/disposal and old operation identities cannot be undone by a stale replay. No comment body, selected text, marker label, document excerpt, private route/URL, provider token or raw SQL parameters enters general logs, analytics, traces, replay recording or errors. Observe safe rates of conflicts, failed mapping, unknown writes, retries, row/payload bounds, query/lock pressure and expired-generation navigation without creating a cross-Tenant content oracle. Support can diagnose with scoped source facts; repair authority does not imply original-file or unrestricted comment reading. Keep a readable semantic comment list with exact version/purpose and supported location description. Text/IME input and local marker adjustment must not generate server effects.

Show pending/unknown/saved/conflict/withdrawn/unavailable-location states truthfully and preserve lawful draft/focus across transient failure. Material changed target/anchor before Post is explained inline with deliberate retry/reselection or comment-without-location; no silent downgrade. If comment access is lost, clear the affected protected result; if only byte/preview authority is absent, show whatever comment projection remains lawful and disable navigation without implying missing source content. No forced download, compulsory extra confirmation, auto email, new task or unread/Resolve obligation is added.

Executed once through stdin using Python **3.12.3**, entirely in memory. No PDF library, browser, file write, database, network, private data, installation or runtime feature was involved. This verifies only a small mathematical model and a cursor counterexample. The normalized coordinate convention and six-decimal example are illustrative, **not selected production schema/precision or native mapping proof**.

Results: 96 synthetic point round-trips across four rotations, three zooms, two device-pixel ratios and four points had maximum error `5.551115123125783e-17`; seven malformed/nonfinite/type/out-of-bounds/degenerate regions were rejected. ```python
import math, json, sys

def rotate(u, v, r):
    return {0:(u,v),90:(1-v,u),180:(1-u,1-v),270:(v,1-u)}[r]
def inverse(a, b, r):
    return {0:(a,b),90:(b,1-a),180:(1-a,1-b),270:(1-b,a)}[r]
def display(u, v, r, scale, dpr):
    a,b=rotate(u,v,r)
    w,h=((600,800) if r in (0,180) else (800,600))
    return ((23+a*w*scale)*dpr, (47+b*h*scale)*dpr)
def recover(x, y, r, scale, dpr):
    w,h=((600,800) if r in (0,180) else (800,600))
    return inverse((x/dpr-23)/(w*scale),(y/dpr-47)/(h*scale),r)
def finite_number(v):
    return type(v) in (int,float) and math.isfinite(v)
def valid_region(values):
    if len(values)!=4 or not all(map(finite_number, values)): return False
    x,y,w,h=values
    return 0<=x<=1 and 0<=y<=1 and w>0 and h>0 and x+w<=1 and y+h<=1

errors=[]
for r in (0,90,180,270):

                a,b=recover(x,y,r,scale,dpr)

rounded=tuple(round(n,6) for n in tiny)

naive=[r for r in rows if r[0]>first[-1][0]][:2]
