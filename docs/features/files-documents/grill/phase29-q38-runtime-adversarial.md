## Decision

**Choose A now, with the amendments below. Do not include general cross-file document-body search in Q38.** Built-in PostgreSQL full-text search is a credible component, but the inspected system has not established a qualified reusable document-text producer, exact useful searchable cohort, full derivative lifecycle or measured incremental workload. Current account discovery also does not establish bill neutrality. Neither low complexity nor no higher provider bill is proved. This closes the delegated conditional assessment for this decision; it is not a latent feature flag or permission for automatic later activation.

A remains useful source-qualified names/details/context discovery with filters, recent work, saved views and contextual source opening. It misses a clue that appears only inside a document. Qualified per-document Find and independently governed existing source text search remain intact; neither substitutes for cross-document body search. A is not declared free, already implemented, complete for every source or universally preferable. A future explicit body-search decision may reuse better evidence without repeating settled metadata authority.

## Finite limits and operational response

A needs bounded implementation, not numbers invented during grooming. Before activation, the actual selected route must declare and qualify the following applicable limits against its real workload:

1. Query representation and complexity: Unicode/byte size, supported operators if any, field/filter/sort allowlists and malformed-input response.

5. Data handling: exact field/index/cache/diagnostic retention and disposition/restore barriers under source rules. A query log must not become retained document history.
6. Operations: measurable latency/resource/error/incomplete-coverage signals, cause-aware recovery, stop of affected serving and actual accountable ownership. Do not recover through broad public access or manual production SQL as the ordinary user path.
