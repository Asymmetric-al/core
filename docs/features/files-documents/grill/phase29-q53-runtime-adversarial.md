## Principal findings

The useful capability is one truthful staff supply act in an existing ordinary request item. Its hardest boundary is not a file picker: **source admission, actual writable storage authority, verified immutable bytes and physical cleanup have different completion conditions**. A closed source, canceled UI, expired application session or expired cleanup lease cannot be treated as proof that no late write/delete can still happen.

Four material safeguards dominate this review:

1. Qualify the actual source/P12 staff power, exact target and relevant current basis at source admission. A native staff-attributed durable receipt is real; a participant-attributed receipt, affirmation or acceptance is not.
2. Verify a fixed immutable physical object/version before admitting the contribution, then prevent outstanding upload authority from overwriting it. Track any later physical write after cancellation/deletion; retired keys never become new input authority.
3. Recover the original source result before cleanup or fresh-attempt checks. Finalization and deletion claims must have one owner-ordered winner, including uncertain physical deletions after a worker lease expires.
4. Prove the actual database/storage/worker doors and complete transaction. Existing assets/public image/Eve mechanics and current guard gates do not establish the new source command.

These are plausible integration hazards, not claims that deployed Q53 data is exposed or that a new Q53 command already exists. A remains preferable for permitted staff assistance; B is a simpler valid alternative where new intake remains participant-led. No Asym usage frequency, cost neutrality or performance benefit is measured.

## Eighteen exact proposed runtime amendments

**C01 — Narrow source act and truthful receipt.** Adopt direct staff local-file supply only for an eligible ordinary request item under actual source/P12 power. Use the real actor/context and record actual durable staff receipt and actual later source admission distinctly. Do not invent participant upload/Submission Confirmation, assent, signature, external received date, authenticity or approval. A real staff-attributed receipt is not prohibited by Q28's reuse-only no-new-original-receipt rule. Existing personal/specialist/separation requirements remain. No general uploader role, global drive, fabricated Party or cross-person permission union.

**C02 — Deliberate immutable intake identity.** Bind one logical intake to trusted Tenant/environment/source/request/item/purpose, actual staff actor, relevant requirement/evidence basis, declared file intent and a server-controlled immutable physical target/attempt lineage. Different transport/request IDs for the same admitted intake cannot create another contribution. Matching committed intent recovers its original result first under current disclosure; changed immutable intent under its admitted identity conflicts. Byte equality alone is not business identity: a deliberately new independently eligible upload of the same bytes may be a different contribution. Do not automatically match/reuse, copy approval, retarget to another item or use filename as identity.

**C03 — Bounded preparation before transfer.** Qualify current source permission and code-owned purpose profile before allocating storage/grants or expensive processing. The server owns target key, privacy/classification, permissible methods, type/count/size, lifetime, concurrency and retry bounds. Client/protocol metadata is input to validate, not authority. Record a bounded technical generation before issuing effects that may outlive the request. Unknown issuance cannot justify unlimited reissuance. No broad bucket/list/read/delete/update/overwrite grant is implied by upload. Grant expiry/activity does not extend participant access or alter requested-by dates.

**C04 — Real grant closure, not UI cancellation.** Track the actual provider credential/session and any admitted in-flight writes separately from source eligibility and client progress. Cancellation/revocation/expiry denies future source promotion as required even if a bounded transfer still arrives; it does not falsely claim physical abort or deletion. Qualify the adapter's expiry, revocation, abort, resumable and generation behavior. No accepted byte/version may be modified by a still-valid write credential, upsert, replay, resume, late callback or competing transfer. Retired physical keys are never reused. After a canceled/expired generation, any permitted fresh retry must be independently current, explicitly bound and superseding for promotion without making old physical attempts untracked. Source-terminated work cannot revive through it.

**C05 — Verified immutable received object.** Independently establish complete durable custody of the exact fixed object/generation with actual bounded length, allowed content/type, integrity evidence and required safety/admissibility. Stream and bound verification; do not read unlimited bodies into database transactions. Browser file metadata, extension, client digest, ETag, provider URL, object name, callback or 100% progress alone is insufficient. Only use provider checksums whose algorithm and scope are actually qualified; no universal ETag-as-content-hash assumption. Detect a changed/truncated/missing object between proof and admission, and prevent later mutation rather than repeatedly trusting a mutable key. Do not silently transform originals or treat an output rendition as the original.

**C06 — Separate receipt, admission and processing.** A verified durable staff receipt can truthfully exist while source admission is unresolved/denied; a received-but-not-added file is not a successful item contribution. Current final source authority and relevant basis are re-proved at admission after waits. Only an explicit bounded intake profile may defer particular processing until after admission in Checking. Unknown authority/custody, forbidden content or required failed safety proof cannot be deferred as harmless Checking. Once admitted, independently authorized source workers may continue without an indefinitely open browser session; current worker/source restrictions still apply. Receipt, inspection readiness, Q21/Q23/Q52 acceptance and Q22 fulfillment remain different facts.

**C07 — Coherent local finalization.** In one actual qualified source transaction after verified receipt, commit the new contribution/use, immutable object reference and retention/reference protection, current evidence basis, actual attribution/times, mandatory history, original-operation result and required durable follow-through; otherwise commit none of these new source facts. Provider transfer/scanning/deletion stays outside locks. Neither withOperation, a tenant-guard callback, several RPCs nor Promise.all is an enclosing transaction. Bind the verification to a still-protected exact object/generation and coordinate custody claims with this transaction through a proved protocol; a transaction alone does not prevent external byte races. No silent best-effort attachment or compensation that deletes possibly admitted evidence.

**C08 — Source currentness and aggregate order.** Order admission against actual actor/source restrictions, request/item cardinality, Q03/Q47 correction/withdrawal, Q28 additions/removals, Q30 clarification, Q33 removal, Q34 cancellation, Q36 additions, Q37 instructions, relevant Q45 comments, Q49 replacement and Q21/Q52 acceptance/Q22 actual F. Relevant ABA changes conflict even if display text/bytes return to a prior value. Only relevant source changes participate; no whole-Tenant lock or incidental folder/name conflict. Pending transfer is not received evidence or a completion hold. A winning terminal/frozen/incompatible source state denies admission without substituting another target. Existing independently admitted facts remain; Q22's complete predicate is never a visible-count shortcut.

**C09 — Original-operation recovery and clocks.** Recover committed original meaning before new lifecycle/permission-to-act gates, subject to current result disclosure. Distinguish known rollback, still-unknown commitment, known admission with failed projection and actual source rejection. A timeout/navigation/cancel request is not rollback. Reconcile before rekeying, retransferring or destructive cleanup; exact transport retries are bounded and cannot rebase a business conflict. Use trusted actual receipt/admission/decision instants after relevant waits, not device file dates, client clock, byte-transfer start or a stale transaction-start clock. Preserve original receipt and admission history across retries; technical generation changes do not backdate a new act or create another receipt effect by inference.

**C10 — Finalization versus cleanup has one winner.** Register every tentative copy/generation before I/O and track its disposition owner. A deletion claim fences admission/promotion; admitted/currently protected references fence staging cleanup. Before a destructive call prove source eligibility for disposal, complete relevant references/holds and that no still-usable grant or already-admitted write can recreate/modify the exact key, or use a separately qualified adapter mechanism that enforces the same invariant. A filtered/failed list, ended request, abandoned UI or elapsed age is not absence proof. Late objects remain restricted and tracked for bounded reconciliation; never acknowledge complete cleanup while a possible write remains unaccounted for. Use the supported Storage API for physical bytes, not direct deletion of storage metadata in SQL.

**C11 — Unknown deletion remains fenced.** A physical deletion already admitted can finish after its worker lease or application timeout. Lease expiry alone must not reopen admission/promotion, reuse the key or allow another generation to be deleted by the stale worker. Bind deletion to exact object identity and owner claim; reconcile unknown outcomes, late acknowledgments and post-delete recreation before marking actual erasure. Holds/required retention may keep bytes; count them and preserve access restrictions rather than falsely recording deletion or dropping their record to satisfy a budget. No source received/accepted object is disposable merely because a cleanup callback lost its response.

**C12 — Actual authorizations and relational invariants.** Use one fine-grained source/P12 authority with prescribed coarse Tenant RLS, not a second permission engine in storage paths or UI labels. Enforce required nonnull scope, same-scope source/item/intake/object/use/actor relations, valid bounded sizes/digests, immutable authority-bearing fields, operation/effect uniqueness and valid state transitions with actual constraints/privileges. A composite FK is reference validity, not protection from a permitted retarget; nullable MATCH SIMPLE and cascades need explicit treatment. Keep history protected from UPDATE/UPSERT/MERGE/delete replacement. Cross-row current policy and provider state are not fictitious CHECK constraints. Caller cannot set trusted actor/time/Ready/accepted/classification/source.

**C13 — Every database and storage door.** Verify actual named/PUBLIC/default/inherited table/column/schema/function EXECUTE grants, required SELECT/RETURNING, effective permissive OR/restrictive AND, old/new-row USING/WITH CHECK including inheritance, INSERT/UPDATE/DELETE/UPSERT/MERGE and trigger-transformed values. Inspect function invoker/definer owner/search_path/overloads, ENABLE/FORCE/BYPASS and the actual anon/authenticated/staff/NHI/service/guard/operator roles. API, direct browser/table/view/RPC, storage upload/sign/resume/HEAD/info/list/read/move/copy/update/delete, CMS/GraphQL, workers/import/restore must preserve the boundary or be closed. Current catalog/service-client gates are necessary checks, not row/source proof. Never copy a broad image-assets policy or add a bare service client/exempt-directory workaround.

**C14 — Current disclosure and secret handling.** Staff upload does not grant participant own-submission reading/history, original download, previous-use discovery or permanent uploader access. Each metadata/status/receipt/preview/original/range/conditional response and cached result obeys current source/field rights; no public URL or external viewer fallback. Keep short-lived upload credentials, raw filenames/body, source/provider URLs and private associations out of ordinary telemetry, error responses and unapproved local persistence. Resume records are scoped to the actual actor/Tenant/intake/attempt and protected against cross-context reuse. Clear protected UI and fence late responses on context loss without erasing durable source facts. Required restricted audit and actual protocol carriers remain allowed under their own controls; logging everything is not recovery.

**C15 — Existing staff-evidence lifecycle and effects.** New admission is additive within actual cardinality, never implicit replacement of a participant contribution, accepted/frozen material or another use. Explicitly extend the relevant Q28 staff-origin removal and actual recovery meaning to this path; local cancel is not withdrawal and withdrawal is not physical erase. Any qualified replacement has its own source command/lineage; later Checking failure cannot revive a predecessor. Actual source/privacy operators need a usable remedy without routine SQL. Separately qualified review remains necessary. Reconcile genuinely source-actionable admitted staff evidence with Q24/Q28/Q27 work/notice meaning and original controls; no callback-created notice, new recipient email, task per file, Q48 reset or Q51 cue. Existing required effects are not blanket-disabled.

**C16 — Small usable interaction and finite operation.** Keep the task within the item with safe target/instructions, Upload file/Add existing, explicit staff attribution, deliberate add and truthful per-file progress/known/unknown results. No routine second confirmation/approver, required essay, inferred consent, forced participant re-upload or new global settings panel. Multiple files, if qualified, remain independently reported intakes; no physical atomic batch promise or silent failure hiding. Actual keyboard/non-drag/AT/touch/reflow/RTL/IME/weak-link journeys must work. Enforce measured finite purpose-profile, in-flight/staging, parser, query/lock/retry, cleanup and retention budgets before activation; no imported 5MB image/preview/Eve duration or free-cost claim.

**C17 — Prospective rollout and durable non-revival.** Qualify compatible schema/readers/writers and source/custody adapters before exposing the UI. Do not backfill private/provenance/safety/receipt/acceptance truth from old assets/public URLs/local chips. All old admission/cleanup writers must respect current generations/references or be fenced. A scoped stop denies new preparations/admissions while preserving lawful original-result recovery, already admitted processing and safe cleanup/reconciliation. Outstanding grants/in-flight writes/deletes still need accounting after disable/rollback. Keep minimal lawful intent/tombstone evidence or reject unverifiable old commands; restore/hash/namespace changes cannot reissue old work or reveal disposed content. Roll forward or prove a data-preserving downgrade; do not drop active source references because a feature flag is off.

**C18 — Proof and evidence separation.** Before activation prove the actual ordinary staff source command, exact current roles, real immutable custody and all supported transfer methods, finalization/cleanup races, current reads, source review/fulfillment and source-owned operator repair under measured native load. Specification, upstream examples, existing tests, static gates and any logical model are not this proof. Bind requirements/design/tasks/tests/releases to the final clause/proof IDs and reconcile owner/OpenSpec publications together at the authorized stage. This note performs research only and does not approve a provider, declare a deployment secure or select new global numeric limits.
