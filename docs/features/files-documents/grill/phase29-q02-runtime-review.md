## Findings that matter for this decision

1. **No qualified uploaded-PDF/Office own-submission preview pipeline was found.** Current Support attachment UI displays filename chips. PDF Studio creates authoring HTML from structured template JSON; it is not a parser/viewer for submitted PDFs or Office files. Existing image resizing works for configured public image formats but does not qualify confidential general-document previews.
2. **Preview is a private read capability.** A submitted-file owner needs a current source/request/submission permission, not just a storage URL or a matching uploader/profile ID. Preview renditions must bind the exact submitted bytes, processor version and source purpose; they do not confer source acceptance, official-document status, publication or global reuse.
3. **Purpose admission belongs before storage allocation and expensive processing.** The Phase18 purpose-catalog admission pattern is a useful fail-closed precedent, explicitly allocating no artifact or identity. It is only a Generated Document contract and does not presently gate generic uploads. A freeform `purpose` string, folder or filename is not an authorized Asym use.
4. **Public CMS delivery cannot be reused as private delivery.** Installed Payload Blob adapter defaults public access and one-year public caching, explicitly supports range/ETag/304 responses, and its client upload path sets `access:'public'`. The current public-media policy intentionally permits public file bytes. This is compatible with its existing public purpose; it is not a bug to fix globally or a private-preview foundation.
5. **Eve private artifact custody is useful but specialized.** It records UUID/hash/private object/expiry and authorizes tenant+owner before issuing a60-second signed URL. No own-submission rendition, per-source grant, access-range evidence, strict post-issuance revocation or generic file-manager admission follows from that code.

## Permanent seam recommendation

Preserve Q02 A. Add a source-qualified **preview-own-submission** capability to the Q01 participant grant, bounded to the submitted occurrence/version. The request interface shows that participant's authorized submission, processing state, supported reading rendition and clear next action. It does not become a personal drive, expose other recipients/requests, or infer an entitlement to original download, source acceptance, reuse or delete. Whether the accepted product already permits original download should remain explicit; do not add or remove it as incidental preview hardening.

Use shared custody for immutable byte identity, private intake, processing state, rendition lineage and authorized serving. Reuse existing exact-source/context serializer discipline, caller-scoped identity, domain command/outbox and hold/deletion patterns. Keep a single delivery authorization gate for every representation; isolate the viewer/processor as required by the format. Keep CMS public media delivery separate and use its source owner to activate public generations. Do not create a second Media catalog or a freeform upload warehouse.

Implement Asym scope as a **source/purpose admission contract**, not file-extension or folder policy. The Phase18 fail-closed admission approach is a helpful pattern, but its generated-document purpose list is not the list for every Phase29 family. Admit only required/currently intended Asym workflows and narrow resource purposes approved by their owners; preserve staged work, retention and migration obligations even before files are linked or future feature consumers launch.

## Required targeted implementation proof

1. Correct participant previews exactly their submitted version; unrelated participant/tenant/request, staff without source capability, guessed opaque ID and same-byte duplicate all fail before metadata/bytes.
2. Upload pending/quarantined/unsupported/encrypted/malformed/partial files never produce unsafe inline fallback. A supported image/PDF/Office family passes its actual renderer safety/coverage/accessibility proof before admission promises preview.
3. Preview metadata, thumbnail, all pages/tiles, original-download if separately allowed, HEAD/range/conditional responses and cached navigation all obey grant revision/revocation and private response policy.
4. Replacement, cancellation, recipient revocation, processor retry, response loss and late callback preserve exact-version lineage and cannot resurrect access or overwrite an accepted artifact.
5. Processor has no unintended network/local-secret access; external relationships/macros/embedded payloads/active content remain inert. Real memory/deadline/output limits and failure recovery are demonstrated with harmless hostile fixtures in isolation.
6. Preview fidelity/coverage is understandable: truncated/unsupported material is reported, not silently omitted; safe accessible reading is tested with keyboard/screen reader/mobile and realistic file families.
7. Admission rejects unrelated arbitrary storage without inventing a source link, while genuine Asym resources/staged work remain usable under a named owner; source removal, holds and retention cannot become immediate generic delete.
8. Reuse/link commands do not broaden audience, alter official receipt/currentness, expose other uses or convert source evidence into publication. Real database roles, policy composition and trusted worker authorization are tested separately from service-only mocks.
