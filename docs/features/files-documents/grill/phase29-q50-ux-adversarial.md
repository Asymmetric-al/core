# Phase 29 Q50 — Staff display names: independent UX adversarial review

2026-10-25, Asia/Bangkok. Conrad selected **A — Staff display name only** and requested a full adversarial review. **Selected, pending ratification.** Q01–Q49 and the current 30 glossary definitions remain ratified; this note creates no Q51 choice or new term. Only this assigned work note is authored. No native UI, provider, SQL, account, production or GitHub mutation was performed.

**Disposition: accept A with the exact amendments below.** One optional, source-owned current display name shared among field-authorized staff is useful and proportionate. Its confidentiality must be real across projections, not merely a hidden recipient field. The principal usability cost remains two naming contexts; permitted original/item/receipt context must make that manageable without exposing forbidden provenance or forcing another upload.

## Recommended permanent experience

Use a small contextual editor in the existing request/evidence details or File Manager surface. The action can be **Edit staff name**; the field is **Staff display name (optional)**. Suggested concise guidance: **Shown to authorized staff. Recipients keep the existing name.** This is proposed copy for intended-user validation, not a claim of tested wording. A staff name is shared with eligible colleagues, not personal to its author or automatically visible to every employee.

Show the currently permitted received reference separately where useful, for example **Received as: scan_004.pdf**, plus existing source item/context. Do not manufacture this line if the original filename is restricted, discarded or unknown. A readable permitted fallback must still identify the exact use; a failed preview does not by itself prevent metadata organization. If current safe metadata cannot identify the intended target, provide actual source recovery rather than blind naming.

An absent staff name starts as an empty optional field, with the default display context separate. Do not prefill the fallback as if it were a previously authored staff name. An unavailable or unauthorized current staff name is **not absent** and must not enable blind overwrite or Clear. A currently permitted source fallback may still display independently.

**Save name** commits one qualified source edit. **Cancel** leaves naming unchanged. Removing the input and saving deliberately clears the optional staff value; whitespace-only canonical input may mean the same Clear. A Clear control, if useful, can simply empty the local field before Save. It does not delete the file. An unchanged save creates no naming business effect. No reason essay, second approver, extra confirmation modal, preview attendance, file download, re-upload, naming template or notification choice belongs in this routine edit.

After success, keep the same exact use selected even if its row moves in name order. If the renamed row no longer matches the current filter, provide a truthful result and safe return/focus rather than silently selecting another file. If no stable row remains visible, return focus to the actual existing list/filter context with a concise outcome. Implementation may use the current shared detail surface; no new navigation framework is needed.

Mistakes are repaired through the persistent current **Edit staff name** capability. Selecting a prior value is a new authorized edit, not history rollback. A convenience Undo is optional and can only invoke that same current command against an eligible current basis; it cannot overwrite later edits or revive restricted history. Sensitive text already disclosed to lawful staff is not recalled by renaming. Actual source privacy restriction/disposition remains the remedy where ordinary correction alone is insufficient.

## Evidence layers and alternatives

- **Governing product intent:** founder §7–§8 and Q02/Q04/Q05/Q38/Q42/Q44/Q45 preserve source/use identity, protected metadata, meaningful current file context, independent uses, exact comments and original delivery. Owner confirmation distinguishes absent/denied/unknown name, optional Clear, same-use continuity and no automatic name inheritance onto new Q03/Q28/Q47 uses.
- **Fresh primary documentation:** verified below on 2026-10-25. It supports concrete patterns and counterpatterns; it does not establish Asym demand, user-study outcomes, native permissions, performance or legal guarantees.
- **Current runtime evidence:** root reports the current remote review baseline beginning `2838` is unchanged. Exact Git/SQL/public-Media findings remain in the root/runtime evidence; this UX note does not claim an independent complete live SQL audit. Earlier question-stage `8c8f…` facts are not relabeled as the latest head. No native tests were executed here.
- **Design judgment:** A is the narrower fit for staff organization. The empirical frequency of poor filenames, label adoption and staff/recipient confusion is unknown. A read-only source view, source context and existing names remain a good no-extra-edit baseline for files that already work; neither the founder nor A makes renaming a required workflow step. Omitting the already-required rename capability altogether is not a newly available third answer.
- **Strong B:** a shared participant-visible current name can improve recognition and common vocabulary, especially when the participant presentation is unclear. Its benefit is real enough to test, but it requires deliberate participant-disclosure authority. A does not prove B unsafe or universally inferior. Do not secretly add B through a share toggle, second recipient-title editor or generic serializer.

## Sixteen exact required amendments

Severity/likelihood below assess plausible omission or naive implementation, not discovered production vulnerabilities. **High** means a material disclosure, authority, evidence-integrity or unrecoverable outcome; **Medium** means significant confusion or repeated work. Likelihood is qualitative, not measured incidence.

### U01 — One optional shared staff field, with precise absence (High / plausible)

The ordinary source SHALL own at most one current optional staff display-name value for each exact admitted evidence contribution/use in its actual Tenant/environment/request/item scope. It is shared only with currently field-authorized staff, not personal to its author, global to equal bytes, a requested-item name, Q42 tag or official document identifier. Definite absence, current unreadability/denial, unresolved state and an unavailable projection SHALL remain distinguishable. Only proved absence may initialize an empty editable field; an unavailable or undisclosed current name SHALL NOT authorize blind Clear or overwrite. An independently permitted source fallback may still be displayed. **Proof: P01–P03.**

### U02 — Actual source powers and proportionate tenant flexibility (High / plausible)

Derive actor and scope from trusted context and authorize current name-read and name-edit separately through the actual source/P12 contract. Reviewer assignment, uploader identity, folder access, byte read, generic staff rank or the name author's identity alone is insufficient. Existing qualified tenant role/capability controls may assign or remove this bounded maintenance power; no new per-file ACL, universal naming switch or approval queue is required. Another currently qualified staff operator can maintain the source field without impersonating the prior author. **Proof: P02–P04/P26.**

### U03 — Enforce the selected audience through every output (High / plausible)

Under A, the staff display value SHALL NOT enter recipient/public/Q41-share projections, generic filenames/headers, messages, thumbnails, accessible labels, error payloads, manifest/export fields or shared caches merely because it exists on the source row. Current field authority applies before matching, rank, ordering, counts, suggestions, pagination and serialization. Independently qualified staff projections/exports retain only their actual permitted fields; do not impose a blanket ban on lawful staff use. The value is confidential input, not an unrestricted notes field, search language, template or HTML. **Proof: P03–P07/P24.**

### U04 — Identity, provenance and lifecycle continuity stay distinct (High / plausible)

Name edits SHALL preserve bytes, digest, custody keys, exact use/version references, original receipt attribution, source instructions, review decisions, comments/locations, required work, grants and clocks. Retain/reveal original filename and historical names only under their actual source retention/disclosure rules; never reconstruct deliberately discarded provenance. The same exact use retains its name through non-byte lifecycle changes unless its owner lawfully restricts or disposes of that metadata. A new Q03 correction, Q28 contribution or Q47 re-offer use starts without automatic title copy; matching names/bytes/items and Q42 home-only carry are not inheritance authority. **Proof: P01/P08–P10/P24.**

### U05 — Keep one deliberate optional edit, including Clear (Medium / likely for affected users)

Provide a visible optional field, concise staff-audience guidance and Save name/Cancel through the existing shared UI. A known absent name stays empty; display the permitted fallback separately rather than prefill it as authored data. Deliberate blank or whitespace-only canonical input may clear the optional name. Clear affects neither bytes nor receipt history and returns to the current permitted fallback, which need not be the raw original filename. Editing/clearing local input alone SHALL NOT commit, navigate, download, send or reset work. No mandatory reason, extra approver, second confirmation, body preview or upload is required. **Proof: P03/P11–P13.**

### U06 — Safe, predictable plain text without naming bureaucracy (Medium / likely for affected users)

Declare a bounded plain-text normalization/validation contract that preserves meaningful Unicode, combining text, punctuation, RTL and IME input; reject unsupported controls safely rather than treating names as markup or paths. Length units and errors must be understandable and consistent between UI and server. Do not silently truncate stored text, transliterate, translate, autocorrect meaning, strip arbitrary meaningful characters or require unique display names. Type/icon and business status remain source facts even if the name contains an extension-like suffix or “Approved.” Do not add an AI semantic classifier, naming template language or document extraction for this field. **Proof: P14–P16.**

### U07 — Coherent source write, current expected basis and no-op (High / plausible)

One authoritative mutation SHALL coherently record the admitted name change, current revision/result and required attributed history or equivalent durable source evidence. Qualify exact scope, canonical intent and the relevant expected name basis. Canonical no-op after original-operation reconciliation creates no new naming revision, business effect or artificial activity; required protected-read/security evidence remains governed. A stale expected revision conflicts even when the visible name has returned to an earlier value. Unrelated source changes need not force needless retyping when actual name authority/basis remains valid. **Proof: P11/P17–P19.**

### U08 — Recover lost responses without replaying old intent (High / plausible)

Bind durable semantic operation identity to the exact action/material intent and source scope. Reconcile an original admitted result before treating a retry as a new edit; never reinterpret its old payload under a later default or current value. A lost response does not imply failure. Recover the original fact under current disclosure and show the actual current name separately where permitted; an old replay cannot restore an earlier name over another staff member's later edit. Concurrent genuine edits require one ordered result and a usable conflict path, not blind overwrite or a merge engine. **Proof: P17–P20.**

### U09 — Permanent correction and source privacy recovery (High / plausible)

Keep a current authorized Edit/Clear path available wherever the source permits this metadata maintenance, including qualified retained evidence. Before save, cancel/edit the local proposal. After save, repair a mistake through a new current edit; a prior value may be deliberately chosen only where lawfully available. A transient Undo is not the sole remedy and cannot roll back source history, overwrite a newer revision or revive discarded/restricted text. If sensitive wording requires more than a display correction, an actual capable source operator must apply the relevant metadata/history restriction or governed disposition, with attribution and current permission. Do not promise recall of already seen text, original-file redaction or a universal restore window. **Proof: P12/P20–P22/P26.**

### U10 — Identify the contribution without requiring forbidden provenance (Medium–High / plausible)

Provide current authorized staff with a compact distinction between their staff name and the source-approved received/item/receipt reference where useful. Preserve the recipient's approved representation under A. If raw original naming is unavailable, use an actually permitted source reference and capable help; do not force preview, byte access, an original filename or participant re-upload as a naming prerequisite. Do not imply a new recipient description editor or participant rename power. Test a staff/participant conversation that identifies the same exact contribution despite different names. **Proof: P05/P08/P13/P23.**

### U11 — Derived discovery and focus follow source identity (Medium–High / plausible)

The current source field is authoritative. Qualified Q38 search/sort/filter projections are derived, scope-bound and rebuildable; stale restrictions fence serving before cleanup. A projection delay cannot undo a lawful source save or become a false complete no-match result. Preserve safe query/filter/scroll/selection return state by exact identity. A moved or filtered-out row must not silently retarget focus, selection or a pending action to another item. No metadata edit creates a body-search corpus or an obligation to rename files before finding them. **Proof: P06–P07/P23/P25.**

### U12 — Existing effects and delivery remain under their owners (High / plausible)

Q50 SHALL authorize no new naming notification, message payload expansion, access grant, request instruction, review decision, timer, reminder reset or source business outcome. Independently qualified existing effects retain their actual purpose/currentness contracts; no blanket notification-Off policy follows. Q44 original downloads, sealed member names and manifests remain unchanged. Q41 external disclosure and Q45 exact-version comments are not retargeted by a name. Sensitive display strings do not become new URL slugs, proof material or provider object keys. **Proof: P08–P10/P24.**

### U13 — Accessible, international and weak-network completion (Medium–High / likely for affected users)

Qualify keyboard, touch, screen reader, speech, zoom/reflow, RTL/IME and slow-network editing in the existing shared component stack. The visible label and accessible name must agree; full names and essential actions cannot rely solely on hover. Prevent composition-confirming Enter from accidentally saving while preserving normal deliberate keyboard submission. Associate text errors with the field, retain lawful input for correction, and announce saving/result/conflict without unnecessary focus theft. Keep focus meaningful after Save/Cancel, list reordering and filtered removal. Respect current private-state limits on tenant switches, revocation and navigation; no durable offline draft store or silent background replay is selected. **Proof: P14–P16/P18–P20/P25/P27.**

### U14 — Native invariants and all alternate doors (High / plausible)

Qualify actual native relations and effective grants/RLS plus source/P12 authority under supported roles, not UI visibility alone. An allowed name mutation cannot retarget Tenant/environment/source/use/version, provenance, actor, recipient, review or lifecycle. Prove permitted and forbidden old-row selection and resulting-row paths for SELECT/INSERT/UPDATE/DELETE/RETURNING/upsert as applicable, plus API/RPC/view/service/import/job/function/trigger doors. No optional naming metadata may cascade-delete evidence or required history. No blanket database configuration is selected beyond the actual governing owner contract. **Proof: P04/P28–P29.**

### U15 — Bounded rollout, history and operational recovery (Medium–High / plausible)

Census all fields/readers/writers before activation; initialize absence/fallback from proved source mappings, not generic provider paths, same-byte matches, body extraction or specialist titles. Define finite input/history/query/concurrency/retry/recovery budgets and measure actual query/index/resource behavior. Preserve lawfully admitted names/evidence during recoverable projection failures; use source-approved operator repair rather than routine SQL. Restore reconciles later restrictions before serving; stopping affected new writes does not erase source facts or disable independent lawful work. History bodies and operational diagnostics follow their separate retention/disclosure contracts; no perpetual name archive is invented. **Proof: P22/P26/P28–P31.**

### U16 — Exact qualification and stage honesty (Medium / certain if only A is recorded)

Record complete source/amendment/proof/journey trace. Separate product intent, static code, isolated tests, real role/database proof, browser/assistive technology checks, intended-user validation, hosted state and measured cost. Do not call vendor documentation a user study or a shared component an accessibility certificate. Monitor only after naming the signal, threshold, owner and response; monitoring cannot substitute for a closed authority or privacy boundary. No new glossary term, provider, UI stack, realtime service, naming engine or broad metadata platform is justified by this decision. **Proof: P30–P32.**
