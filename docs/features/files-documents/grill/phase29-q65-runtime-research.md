## Candidate and recommendation

The genuine remaining distinction is **whether the first partner-document reference is only collection/review/handoff evidence, or is also intended for ongoing partner-reference work after that collection ends**. This is business-purpose scope. It is not a choice of byte location, Files tab, generic relationship schema, legal validity or retention number.

**Recommend the narrower first profile: collection/review/handoff evidence.** It records what was requested, received and reviewed for that purpose, with the already-governed permitted history and staff follow-through. It does not automatically establish an ongoing partner-reference use. All independently lawful existing source uses and deliberate qualified reuse remain possible; this choice must not prohibit them, remove required history or mean delete at fulfillment.

**Strong alternative: explicitly add ongoing partner-reference use to the reference workflow.** Staff may need the document later when doing continuing partner work. If that is an intended product outcome, state it and qualify the additional source purpose, current eligible audience/actions, exact version/use relationship, correction/end behavior and records obligations. Use the same immutable bytes where qualified; no second store, automatic copy, contract-management engine or public library is implied.

The alternative has a real benefit when continuing reference is needed: staff can rely on a source-qualified continuing use rather than stretch collection history into unspecified business authority. It also adds actual source lifecycle/permission/coverage work. The inspected documentation does not establish that this ongoing use is required or already selected. Neither choice declares a document legally valid, signed by an authorized representative, the current governing agreement, or evidence that partnership/onboarding is approved.

This should be asked only as purpose clarification for the ratified reference. Merely asking whether staff can still open permitted history would repeat settled protections; merely asking whether to light up P9's Files tab would repeat required product scope.
