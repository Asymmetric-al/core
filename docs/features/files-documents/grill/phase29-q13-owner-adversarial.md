## 1. Disposition and strongest challenge

**Accept with required amendments.** The capability can resolve a legitimate still-unfinished request without duplicating received work. It must be a newly authorized finite admission, not an edit to an expired end, a cleared restriction, a revived token or a new ID that hides the same old effect.

The strongest alternative remains keeping expiry final for that same request. It avoids a new grant command and repeated-access risk, but legitimate unfinished work then needs another genuinely authorized resolution. Neither alternative permits serial cloning, backdating, implicit new source work or private attachments as a workaround. No observed ministry need or support rate establishes A as empirically superior.

The most consequential refinement is that **fresh write scope and fresh read scope are different**. Granting correction of one pending requirement must not reopen other accepted items or turn later completion into a grant over every request file. Conversely, freezing fresh scope to old file IDs would prevent the new submissions that the selected capability exists to admit. Bound the original requirement/purpose lineage and current reviewed actions, then qualify exact current own-file reads independently.

Severity below is the impact if a design error is implemented; likelihood is qualitative plausibility, not a measured production incident rate. No native Q13 exploit or completed implementation is claimed.

## 3. Material findings and exact amendment proposals

### O01 — Ordinary expiry must be positively proved, not inferred from Expired

**High impact; highly plausible.** An Expired badge may conceal revocation, earlier binding shortening, a purpose end, missing proof, a stale projection or a still-valid completed transition. Once a cause disappears, a new fresh grant can otherwise launder the adverse history.

**Evidence:** Q13 question:56–77; Q08:19–39; Q07:29–40; Q10:46–64; Q12:23–41.

**Required clause:** “Prove the original lawful admission, its exact scope, ordinary unfinished expiry and retained adverse history. A generic status, missing cookie, failed lookup or elapsed nominal date is insufficient. Evaluate a new source authorization without requiring the ended grant to pass its old live-use predicate. Do not reclassify genuine adverse shortening/revocation/purpose expiry as ordinary expiry because its cause was removed; unresolved required evidence blocks the affected issuance.”

Temporary representation/proof failure is not automatically permanent revocation. Preserve its actual owner semantics without using a new grant to hide the unresolved state.

**Proof:** ordinary time expiry; removed genuine shortening cause; stale expiry after timely completion; proof outage; missing original evidence; pure credential expiry; independent intake-only cutoff. Each produces its actual route.

### O02 — The original scope ceiling cannot be replaced by the latest request shape

**High impact; highly plausible.** A request may have later added requirements, changed recipient/purpose, accepted some items or widened its file categories. Resolving “all current requirements” at grant time could create authority never present in the original admission.

**Evidence:** Q13 question:63–69; Q03:18–33; Q11:19–40; Q05:24–34.

**Required clause:** “Each fresh admission SHALL be bounded by the original admitted request/requirement-purpose lineage, current source eligibility and its explicitly reviewed subset/actions. Current revision alone cannot widen that ceiling. Newly received files/corrections for those eligible requirements are permitted only through ordinary current admission rules; neither old-file-ID freezing nor whole-request reopening is correct.”

Use exact source occurrence/revision lineage rather than text, filename, mailbox or digest matching. Legitimate source revisions retain their owner procedure; Q13 itself grants no new requirement, recipient or purpose. A narrow fresh grant does not erase unrelated historical source facts or create a permanent global restriction on other independently authorized future decisions.

**Proof:** original A/B requirements with C added later; narrow grant for B; accepted A; new own submission for B; same filename under C; legitimate source instruction revision; recipient changed through an unrelated UI. Preserve allowed subset without extra rights.

### O03 — Separate pending writes, current reads and the declared completed-read scope

**High impact; highly plausible.** A single “request open” permission can allow accepted-item correction or original download where only upload was approved. The opposite implementation can wrongly hide independently permitted accepted own files.

**Evidence:** Q03:18–33,44–49; Q04:19–30; Q05:19–34; Q13 question:63–86.

**Required clause:** “Review and enforce eligible submission/correction actions separately from current own-file metadata/preview/original/history rights. Only exact source-open unaccepted occurrences may receive those writes. Accepted/frozen own files can remain readable only where independently qualified; this never reopens writes. Source-approved completed-read scope SHALL be declared within the fresh admission's reviewed bounds, not inferred from write permission or request membership.”

A current request-safe status may be visible while particular requirements/files remain concealed. Do not require an issuer to read private contents merely to administer a scope they are permitted to grant.

**Proof:** grant upload to one requirement but no original download; accepted own file with permitted read; another person's file; restricted original with preview only; staff-only evidence; original unsafe file whose metadata also requires suppression.

### O04 — Completion must not widen a narrow fresh admission

**Critical impact; plausible.** Normal whole-request fulfillment can tempt a resolver to create the usual full completed view by unioning old expired grants or all current request files. A fresh grant for one remaining requirement then becomes a broader read entitlement.

**Evidence:** Q10:25–38; Q07:42–47; Q08:27–38; Q13 question:78–107.

**Required clause:** “At eligible fulfillment, resolve the continuation-created completed view only from the fresh admission's eligible declared read scope, original requirement/purpose ceiling, current source permission and exact current own-submission lineage. Do not union ended admissions, add unrelated request members or infer read authority from write/correction capability. Preserve the admitted completed scope and provenance; later serving still rechecks current permission and representation eligibility.”

This can include newly received own submissions legitimately admitted under the fresh requirement scope and independently permitted accepted own files within its declared read scope. It does not create a previous-version archive. Later authorized rendition repair of the same admitted version is not a new source member.

**Proof:** fresh B-only grant when expired original covered A/B; source fulfills entire request; resulting view cannot acquire A unless A was independently included in eligible declared fresh read scope. Test superseded, later-added and other-recipient files; metadata/counts as well as bytes.

### O05 — Issuer authority and continuing dependencies are not role labels

**High impact; highly plausible.** Reviewer/read/support powers, original sender status or a privileged database client can be mistaken for the ability to issue external authority. Alternatively, every staff departure may revoke grants unnecessarily, or the original issuer snapshot may permit stale authority indefinitely.

**Evidence:** P12:1542–1548,1552–1568,1670–1672; Q08:22–25; Q11:39–43; native identity active change:34–51.

**Required clause:** “The deliberate fresh decision SHALL require the exact current source issuance capability and applicable P12 administrative scope/live assignable ceiling. Preserve the approving actor and source-approved intent; worker dispatch/recovery uses its own current service authority and cannot invent another approval. The actual grant/type mapping SHALL declare continuing issuer/delegation dependencies. Apply those dependencies exactly rather than a blanket survive/revoke rule.”

Use the existing required source/P12 mutation fence. No unconditional original-grantor-only rule or named new staff role is selected. A service-role connection is never a substitute for capability.

**Proof:** file reader, assigned reviewer, support actor, original sender with lost capability, authorized delegate, narrowed live ceiling during a wait, NHI owner loss and a committed grant whose actual dependency has or has not ended.

### O06 — Fresh authority must exist at the causal fulfillment point

**High impact; highly plausible at races.** Staff may open a grant dialog while source review completes, then commit using the old unfinished state. A later fresh approval could be backdated to give the earlier fulfillment completed eligibility.

**Evidence:** Q10:25–51; Q11:45–64; Q13 question:78–93,122–123.

**Required clause:** “Completed admission under this successor requires actually eligible fresh unfinished authority under its adopted activation policy at the qualified normal-fulfillment occurrence. Approval, proposed future activation, a click or observer timestamp alone is insufficient. Serialize relevant fresh issuance/activation, source completion, evidence-set, recipient and adverse-authority changes. Completion-first may remain a valid source outcome but cannot receive retroactive recipient admission.”

Lawful atomic fresh admission plus fulfillment remains possible where the exact source predicates permit it. Require causal proof and a durable effect, not an arbitrary strict inequality between equal-precision timestamps. Qualify after-wait checks and a transaction spanning a boundary, including rollback and unknown commit. No provider I/O under source locks.

**Proof:** completion before command, while dialog is open, before lock, during a later wait, after valid fresh admission, and in a lawful atomic operation. A proposed delayed-activation policy must define whether any pre-entry authority actually exists; this review does not choose that policy.

### O07 — Completion uses one exact fulfillment and bounded actual authority

**High impact; plausible.** Fresh approval may start the completed clock prematurely; repeated completion events may restart it; an old ordinary expiry job may terminate valid new authority; a new expiry job may delete evidence.

**Evidence:** Q07:22–47; Q10:33–64; Q12:30–48; Q13 question:78–86.

**Required clause:** “A valid continuation-to-completed effect SHALL close ordinary writes and resolve its completed end at no later than the actual qualified fulfillment plus 720 elapsed hours, clipped by genuine applicable independent caps and preserved later shortening. The fresh unfinished-only end is not also a completed cap. No `max` with the old end, approval/observation anchor, completed-cycle reset or ordinary-original ninety-day fallback is permitted.”

The count/anchor for fresh unfinished authority remains unselected. At fulfillment, an actual finite applicable authority boundary and its historical eligibility must nevertheless be provable under the eventual qualified policy. Delayed consumers recover that original completed effect/end while honoring current restrictions; actual late fulfillment does not create it. Source work can complete independently without participant admission.

**Proof:** early completion yielding an earlier final read date; near-end completion; exact/after fresh exclusive end; duplicate observations; delayed observation after either old end; genuine overall cap; unknown historical state; stale ordinary/fresh expiry worker after valid stage transition.

### O08 — An old unadmitted upload cannot silently borrow the new grant

**High impact; highly plausible with request-level auth lookups.** An upload session or correction command began under expired original authority, then finalizes after fresh access is granted. Looking up “any current grant for this request” could attach old bytes/intent to the fresh authority while preserving a false earlier receipt.

**Evidence:** Q01:49–56; Q03:18–33,50–51; Q11:32–49; Q13 question:56–62.

**Required clause:** “Preserve the authority provenance and semantic intent of prior admitted and unadmitted work. Fresh access SHALL NOT automatically validate an expired upload session, stale correction intent, old token/URL or prior unadmitted action. Recover already-admitted effects under their original lineage and current disclosure. Any new admission of previously unadmitted work requires an explicit currently authorized submission decision under the fresh scope, with truthful new admission time and current target/review-set checks.”

Qualified custody reuse may avoid an unnecessary retransmission, but it cannot transfer expired authority, reuse an old acceptance/safety result without qualification, rewrite receipt time or silently switch the actor/purpose. Do not require re-upload merely to learn that an earlier effect already committed.

**Proof:** old transfer started before expiry but not admitted; original finalization committed with lost reply; fresh grant narrowed to another item; old idempotency key replay; custody bytes still present versus purged; current correction target changed; fresh user deliberately submits the reusable bytes through a qualified path.

### O09 — Same fresh intent and separate fresh requests require different handling

**High impact; highly plausible.** New HTTP keys, changed output times, two staff or expired provider dedupe can produce duplicate grants. Conversely, a universal one-active-grant constraint could silently decide the still-open repeat/overlap policy.

**Evidence:** Q08:48–55,71–73; Q11:32–37; Workflow runtime:45–51; Q13 question:87–100.

**Required clause:** “One deliberate fresh intent SHALL converge on one attributable source effect with immutable approved inputs and recoverable resolved outputs. Lookup of an existing effect precedes new timing calculations. Conflicting material reuse fails; unknown outcome is reconciled before replacement. Separately intentional requests require the adopted repeat/overlap/history checks in the same relevant source order; no unlimited repetition, one-shot count or one-active cardinality is inferred.”

No source-complete transition may reopen the same request for another cycle. Creation/recipient/item end states still govern each new request. A narrower individual grant is not automatically a new global scope restriction, while genuine adverse restrictions cannot be escaped through another intent.

**Proof:** identical intent from concurrent callers, same key changed scope, new key same source intent, two independent approvals with conflicting overlap, committed response lost, server-calculated end changes on retry, later scope restriction, namespace/version and provider-key expiry.

### O10 — Current recipient proof and host succession remain separate from fresh authority

**High impact; plausible.** A fresh grant might turn an old expired link into an authorizing link, treat a changed email as the same recipient, require a needless account, or move the action to a platform host after a tenant-domain failure.

**Evidence:** Q01:25–47,66–87; ADR0025:35–50,74–92,125–130; Q13 question:63–77,120,136–155.

**Required clause:** “Recipient use SHALL bind the same intended recipient through the current source-authorized identity/contact revision and Q01 assurance. Compatible current proof is reusable only under the qualified exact scope; an old verified-email flag or mailbox match is insufficient. Old expired credentials remain expired. Each new protected action keeps its issuer-qualified frozen tenant host and separate credential/message identity; a legitimate newly proved host requires its existing owner-approved successor issuance, never an arbitrary fallback.”

Do not freeze a new action to a no-longer-qualified historical host when the owner already permits a correctly issued successor, and do not treat host succession as authority to widen the source grant. Fresh commit alone is not present usability when the timing/activation policy or proof remains unresolved.

**Proof:** compatible versus stale proof, changed mailbox revision, shared mailbox, wrong account, expired old selector/verifier, tenant host lost/newly qualified, new message identity, signed URL/cookie outliving its old admission and cross-surface handoff.

### O11 — This continuation does not silently broaden Q08

**High impact; plausible.** A continuation-created completed view can be mislabeled an original ordinary completed admission, then used to obtain repeated Q08 read access or a union of historical scope.

**Evidence:** Q08:19–39,71–76; Q13 question:102–107; Q11:58–64.

**Required clause:** “Record the actual continuation-created completed admission and its lineage distinctly enough to enforce its source contract. Q13 SHALL NOT broaden Q08's currently ratified eligibility by label or inference. Any future admission of this lineage to Q08 requires an explicit compatible owner decision and its own current scope/timing/repetition qualification. An already-completed request with no valid completed-view admission remains outside this unfinished lane and Q08 as currently adopted.”

This does not reopen the already-selected 720-hour continuation-completed consequence. It preserves a different unresolved capability: further fresh reading after that period ends. No Q08 grant occurs automatically at completion.

**Proof:** source completed in the access gap; valid completed view from Q13; attempt to pass either as original Q08 eligibility; historical eligibility unknown; later files added; ordinary Q08 source whose original qualification remains unchanged.

### O12 — Finite timing must remain unresolved honestly, not defaulted into existence

**High impact; highly plausible.** Implementers may reuse 60 days, start on approval by default, leave never-entered approvals unbounded or promise an exact end before a future activation rule resolves it.

**Evidence:** Q13 question:94–107,120,136–144; Q08:41–45,71–75; Q12:17–28,56–61.

**Required clause:** “Before activation, explicitly adopt the fresh duration/anchor, unused-admission bounds, repeat/overlap policy and exact source type/dependency mapping. Required current authority must always have a provable finite applicable bound; missing policy is not forever. Review approved timing terms and known controlling limits, show the exact end where resolved, and never describe a committed approval as presently usable authority solely because it exists.”

No old grant is edited and no count is borrowed from Q12/Q07/Workflow. The original source's true hard limits still apply. Merely delayed proof does not establish a business activation event; the eventual owner policy must say what does.

**Proof:** approved but not usable, never entered, unknown activation outcome, first-use races if that future model is chosen, no timing policy, immediate earlier hard end and repeated grant attempts. Numerical values remain a later founder choice, not a test fixture that accidentally becomes product policy.

### O13 — Existing source work, retention and help do not depend on new recipient permission

**Medium/high impact; plausible.** Staff may force fresh approval just to review already received evidence, request duplicate uploads, or create a grant as the only way to show a support agent private content. Custody may delete bytes when the old grant ends.

**Evidence:** Q01:49–56; Q03:27–33; Q05:36–45; Q10:30–31,59–64; Q12:71–76.

**Required clause:** “Independent source scanning/review/fulfillment/retention and qualified technical work SHALL retain their own current authority. No new recipient grant is required merely for staff processing. Fresh access needs a legitimate recipient use within the selected scope; receipts and prior evidence remain true regardless of the decision. Source-approved help creates no new content-disclosure, impersonation, restoration or attachment exception.”

Existing separately authorized support/source rights are preserved, not globally prohibited. Holds preserve records rather than grant access. A missing or disposed object can make a representation unavailable without fabricating whole-request expiry; do not mint permission to promise unavailable contents.

**Proof:** all uploads received but review pending, no remaining recipient action, legitimate read/status need, quarantined evidence, hold after expiry, independent shared-byte use, lawful disposal, temporary preview/history outage and help actor with only administration evidence permission.

### O14 — Prospective adoption must name the narrow owner successor

**High impact; plausible.** A broad “renew” function may mutate old `expires_at`, revive legacy grants or bypass Q01/P12 integration. A migration may backfill fresh authority from help messages or infer consent from a prior upload.

**Evidence:** Q01:60–87; Q10:18–31; Q11:39–75; Q12:56–61; Workflow owner gates:68–85.

**Required clause:** “Adopt a narrowly identified fresh-unfinished source command and its declared continuation-to-completed rule through the canonical source/P4/P12/communication contracts and declared OpenSpec projections. Preserve ordinary Q10 behavior, Q08 eligibility and existing specialized sources. Rollout/restore must retain original ended admissions, genuine adverse history, fresh effect/activation state and completed lineage; no guessed backfill or old-code fallback.”

Keep existing coarse tenant RLS, sole PDP, exact grant mutation fence, tiered egress/audit and scoped R6 budgets. Permission decisions cannot be implemented as a nullable date field or broad service-role bypass. No new permission platform or global serialization beyond owner-required fences is justified.

**Proof:** old/new writer overlap, restore after revocation/fresh completion, legacy expired record without provenance, unknown fresh outcome, task/email history without source admission, rollback to code unaware of narrow read scope and actual SQL/RPC/service/storage attempts to mutate valid old rows into forbidden new authority.

## 4. Exact corrected meaning proposed

Permit a specifically authorized staff decision to issue a separate finite admission for the same intended recipient and genuinely still-unfinished ordinary request after proved ordinary access expiry. Prove original admission/scope and retained adverse history, then decide fresh authority from current source/P12 administrative permission without pretending the old grant is current. Preserve old deadlines and all source facts; the gap remains unauthorized.

Bound each fresh decision by original requirement/purpose lineage, current eligibility and its reviewed actions. Distinguish pending write/correction scope from independently allowed current own-file reading and the declared completed-read scope. New uploads/corrections may serve those same eligible requirements; accepted/frozen work is not reopened and no other-person, staff, superseded or unrelated-file archive appears.

Under the explicit prospective Q10 successor, exact normal fulfillment while actually eligible fresh authority exists closes ordinary writes and may admit a completed view bounded by that fresh admission's eligible declared read scope, current own-submissions and source permission. Resolve its end from that original fulfillment at no more than 720 elapsed hours under true applicable caps. Lawful atomic admission/fulfillment and delayed recovery are supported through proved causal order; completion-first, inactive approval or later processing cannot fabricate prior authority. Further Q08 eligibility remains separately undecided.

Separate this effect from credentials, messages, proof, prior upload attempts, source processing and retention. Recover same-intent outputs rather than minting another grant; old unadmitted operations cannot silently borrow fresh authority. True adverse restrictions remain binding, while qualified temporary recovery does not automatically become permanent revocation. Finite fresh timing/activation/unused bounds and repeat/overlap policy remain explicit founder decisions and activation gates, with no renewed 60 days or one-shot/unlimited default.

Use one existing source/PDP/native participant/communication/custody path with truthful current state and accessible meaningful review. No deadline editor, automatic message, new recipient picker, second universal approval, forced account, historical backfill or general override follows. Qualify actual source/state/role/race/private-serving and recipient/reviewer/help outcomes before activation.

## 7. Glossary proposal and remaining scope

A distinct term is warranted because this is neither original issuance nor Q08's read-only fresh completed access:

**Fresh Unfinished Request Access:** A separately authorized, finite admission that lets the same intended recipient continue currently permitted work within the original scope of a still-unfinished Private Document Request after ordinary access expired. It leaves ended admissions unchanged and neither reopens completed work nor supplies a duration, repeat entitlement or broader purpose.

The detailed prospective completed-read consequence belongs in the ADR/clauses rather than overloading the two-sentence glossary definition. This definition is proposed only; no canonical glossary edit was made.

Unselected: fresh duration/anchor and unused bounds, repetition/overlap/cumulative policy, further Q08 eligibility for this lineage, reminder/notification behavior and any pre-expiry extension or deadline editor. Exact source/P12 type/command and continuing dependency are required owner integration, not optional implementation guesses. All these must be correctly separated from implementation and release evidence.

The research is bounded to the cited ordinary/new continuation scope. It does not re-audit every specialized Phase18/21/26 purpose end to end, inspect production state or claim native behavior. Existing specialized owners remain preserved. The parent synthesis should record selected capability versus pending full-amendment ratification, then trace later authorized canonical/OpenSpec adoption and qualification.
