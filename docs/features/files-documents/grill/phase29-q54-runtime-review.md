## Primary technical checks and instruction reconciliation

I read the repository's API, backend, Supabase and Postgres skill instructions. This is research, so their implementation-test or schema-mutation steps do not authorize database changes here. Context7 resolved `/websites/postgresql_17` and `/mdn/content`; two topic queries returned current official policy and browser-digest/abort documentation. The earlier Q54 direct MDN/index/RLS reads remain relevant and are not native evidence.

- [PostgreSQL 17 CREATE POLICY](https://www.postgresql.org/docs/17/sql-createpolicy.html) specifies old-row USING and proposed-row WITH CHECK; omitted UPDATE/ALL WITH CHECK can inherit USING. Required SELECT/RETURNING and UPSERT/MERGE combinations depend on the actual command. The skill's blanket omitted-WITH-CHECK warning is therefore insufficient.
- [PostgreSQL 17 row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html) explains permissive OR/restrictive AND composition, role inheritance and owner/FORCE/superuser/BYPASS behavior. A narrowly added permissive policy cannot be assumed to narrow an existing permissive `true` policy.
- [PostgreSQL 17 CREATE FUNCTION](https://www.postgresql.org/docs/17/sql-createfunction.html) is the authority for actual invoker/definer ownership, search path and execution privileges. A definer is not universally a bypass role; inspect its real owner and named/PUBLIC/default/inherited grants. A private schema name alone is not an access proof.
- [MDN SubtleCrypto.digest](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest), also returned by Context7, supports SHA-256 but requires whole input in memory and accepts no streaming input. Worker availability does not eliminate memory/CPU cost. [AbortController.abort](https://developer.mozilla.org/en-US/docs/Web/API/AbortController/abort) aborts supported client operations; it does not provide a business rollback contract. Thus stale-result fencing and original-source recovery remain necessary even when abort is requested.
- [PostgreSQL 17 multicolumn indexes](https://www.postgresql.org/docs/17/indexes-multicolumn.html) supports investigating a scoped equality lookup. It does not establish this schema, query plan, authorization cost or throughput. Measure actual eligible and worst-case sparse/hidden-candidate distributions; no skill O(1)/10x or free-capacity assertion is adopted.

The current Supabase changelog index was fetched; a first output was truncated, so the relevant current sections were reread in bounded form and linked notices opened. [TLS changes](https://supabase.com/changelog/cbc-tls-ciphers-deprecated) start November 10, 2026 at the earliest for old project-HTTP cipher clients; [PostgreSQL 15.19/17.11 guidance](https://supabase.com/changelog/postgres-15-19-17-11-breaking-changes) identifies specific extension/operator compatibility checks. Neither notice selects a new extension, host upgrade, client support promise or provider mutation. Exact deployed versions and compatible plans remain release evidence.

**C02 — Trusted context before discovery.** Derive actual Tenant/environment/native staff identity and current source context through the source/P12 boundary, including a qualified no-Party context without fabricated Party/membership. Validate the chosen request/item/purpose and current capability for this matching context. Before any candidate contributes to a response, count, order, grouping, thumbnail, error distinction or other cue, prove its exact existence/metadata disclosure and current target reuse eligibility. Possession, digest knowledge, read permission, rank or Q53 upload power alone is insufficient. Manual Q28 and Q53 capabilities remain independently qualified; no new source power follows from using the picker.

**C03 — Untrusted full-file query, trusted exact original facts.** The browser may compute a bounded fingerprint of the selected full original and send it only as untrusted lookup input. Declare the compatible algorithm, encoding and byte coverage; validate fixed shape and supported profile before work. The held-side digest must be a trusted fact bound to the exact immutable original version and verification provenance. Do not substitute sampled resume fingerprints, filenames/size, provider ETags of unknown meaning, thumbnails, normalized output or rendition hashes. A claim can be spoofed and matching hashes are not mathematical certainty, authenticity, rights, freshness, participant intent or received-byte proof. Missing compatible trusted facts cannot be fabricated from client metadata. Q53 independently verifies any actual upload; Q28 independently qualifies the held version that is deliberately chosen.

**C04 — Small protected data seam.** Reuse compatible owner-qualified custody/source facts and a bounded lookup; do not create a global content corpus or duplicate authority store. Required same-Tenant/environment/source/use/version relationships, digest/profile validity and immutable attribution must be enforced by actual keys/constraints/privileges where expressible. A composite FK does not prevent an otherwise permitted retarget; nullable links, cascade behavior and UPDATE/UPSERT/MERGE require deliberate treatment. No digest-only unique constraint may merge lawful independent uses or prohibit distinct equal-byte contributions. A derived lookup projection is rebuildable and never authoritative for rights, currentness or physical custody. Do not place private fingerprints/use references into public assets metadata by convenience.

**C05 — Exact candidate meaning and minimal disclosure.** A candidate names one exact held version through its currently permitted source-use/reuse basis, not a global asset, provider key, arbitrary same-byte use or union of every use's rights. Several eligible candidates remain distinguishable using only allowed metadata; no arbitrary winner or authority ranking is inferred from equality. A source-qualified grouping, if used, must not expose hidden uses/counts or erase the selected origin basis. Preview, original reading, history and downstream actions are separately authorized; no mandatory preview ritual or blind confirmation. If metadata cannot safely distinguish a choice, omit the unsafe action and retain a capable manual route.

**C06 — Read-only bounded lookup lifecycle.** Pure matching creates no contribution, request receipt, source-operation slot, evidence revision, retention reference/hold, task, review blocker or reserved reuse grant. Required security/access audit and bounded operational counters remain under their owners. Do not allocate storage or transfer a new file solely to answer this lookup. Use bounded server retrieval and set-wise current authorization under one P12 authority; do not download candidate bodies, fetch the tenant corpus for browser filtering or issue unbounded per-candidate provider/PDP requests. Query retry is a bounded fresh read, not permanent semantic replay of an old authorized result. No read lock over an entire tenant or provider/hash work inside a business transaction.

**C07 — Honest outcomes and incomplete coverage.** Distinguish a returned eligible candidate, a completed scoped lookup without an eligible suggestion, an unsupported/missing-fingerprint cohort, a bounded incomplete lookup and failed/unknown required authorization or query evaluation. Definite policy exclusions stay undisclosed and need not reveal an error or hidden count. Unknown coverage/authority must not become a definitive zero or successful exhaustive statement. Any pagination has a finite cap, declared consistency and stable unique tie-breaker, with current authorization at each page. Safe refinement/continuation or manual search is preferable to silently widening scope. Failure leaves independent Q28/Q53 routes usable.

**C08 — Local generation and pre-intent timing.** Bind asynchronous work/results to the current local selection generation, actual target/context and supported fingerprint profile; same name/size/hash is not sufficient to reattach an old response. File replacement, reselection, target/purpose/tenant/actor changes, clear, navigation, unmount or final source action invalidate its presentation. Hashing/checking cannot disable Upload and add, force a wait/modal, steal focus or add a second routine completion click. A changed branch under an admitted identity conflicts or reconciles its original meaning.
