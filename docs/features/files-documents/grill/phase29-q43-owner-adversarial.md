## Disposition and smallest complete product

Keep A. Ordinary staff with the actual ordinary-source authoring/publication power may deliberately publish an owned eligible saved definition within their allowed staff audience. A separate designated view-manager gate is not required for that act. This is an explicit source/P12 adoption, not permission inferred from Read, staff rank, a preference API or view ownership. B remains sensible for a deliberately curated library, but it imposes coordination on routine shared working arrangements.

The smallest complete path uses the **same stable saved-view identity**, an exact reviewed saved definition and a finite set of selected current staff Active Tenant Assignments. Share promotes the private definition deliberately; there is no compulsory duplicate private/shared pair or automatic propagation between copies. Later global changes use deliberate **Save shared view**. Ordinary browsing/filter experiments remain local, and **Save personal copy** is an explicit new private definition when wanted. This better preserves an understandable single view than mandatory duplicate definitions, while retaining private-by-default behavior.

The ordinary source owns publication and current eligibility. Immutable creator attribution is separate from the current maintainer. Current scoped source administrators can transfer a shared view to an eligible maintainer or withdraw/retire it without needing the departed author's cooperation. Definition disclosure, audience membership, current viewer authorization and the source query are independent gates. No new workflow, group directory, routine second approver, public audience or notice is selected.

## Exact proposed owner amendments

### C01 — Ordinary publication power and policy boundary

Adopt publication of an owned eligible ordinary request-file saved view as part of the normal source-qualified staff view-authoring/publish scope, without a separate designated-manager gate. The source/P12 authority must be current and bounded by its actual definition and audience envelope; private ownership, Read, staff rank or a capability-shaped string alone is insufficient. Administration of another person's definition, transfer, permission grants and policy changes remain distinct powers. Publication inside this envelope grants no role, group membership, field permission, source-record right or power to widen the envelope. Actual P3 projection-policy widening, protected grants, self-benefit and SoD retain their existing approval requirements. No generic approval queue or second PDP follows.

### C02 — Concrete first audience and independent viewer rights

The first ordinary shared-view audience is an explicit finite selection of current staff-eligible Active Tenant Assignments in the same Tenant/environment and ordinary request source. Resolve identity/eligibility through the authoritative source/P12 directory and current context, not email, bare profile, Party, Support team or demo group. Recheck the exact reviewed recipients and publisher's audience envelope at commit; an ineligible or indeterminate selected target cannot be silently omitted from a purportedly complete publication. No audience is automatically selected. Teams/groups/Everyone are not required for this first usable cohort and are not implicitly enabled; this does not remove the founder's shared-view outcome. Each read rechecks the exact assignment/audience binding plus current definition and source rights. Deleted/recreated assignment identities do not inherit old membership. Removal from the audience is not undone by later membership reactivation; any still-admitted temporarily blocked binding resumes only under its actual current P12/source rule.

### C03 — Definition disclosure is its own protected operation

Classify and authorize the title, description, typed filters, field/column names, sort criteria, folder/label references, predicate values and attribution before publishing and before each definition/list/read/execution result. Author permission to use a private definition does not prove permission to disclose it to the audience. The source must qualify the actual record family and field rules before offering publication. Each viewer executes against their own current source projection; never execute as the creator, union rights or require all viewers to see identical rows. A useful definition may have zero current matches, and the author need not be able to read every record another eligible viewer may independently see. Unauthorized user-saved or invalid criteria cause a safe unavailable/repair state, never predicate dropping, creator fallback or a claimed complete zero. Mandatory source/P12 row, field and purpose predicates remain enforced without disclosing protected governance facts. Actor-relative/date operands use only an already-declared typed source meaning; no silent creator/current-viewer substitution or new macro language is introduced.

### C04 — Same identity, explicit shared edits and personal copies

Share deliberately promotes the exact reviewed saved owned-private definition under the same stable view ID and a new coherent definition/audience state. Bind the saved revision, name, source scope and explicit audience to that operation. Canceling/preparing the review changes nothing. Do not require a duplicate private/shared pair or silently publish unreviewed browser experiments. An explicit combined Save and share may atomically commit the deliberately reviewed working definition and complete audience; no preliminary private Save is mandatory. Mark a shared definition clearly and require deliberate Save shared view for global edits, revalidating the expected definition and current audience disclosure. Browsing/filter/sort experiments and personal pin/hide preferences do not autosave shared state. Save personal copy is an explicit currently authorized new private definition with no inherited audience, maintenance grant, privileged fields or result snapshot. Later edits to either identity never propagate automatically.

### C05 — Source ownership, maintainer and departure

Preserve immutable creator attribution and a current maintainer distinct from source ownership. An eligible ordinary maintainer can edit, adjust permitted audience and stop sharing their view within current powers. Scoped ordinary-source administrators can manage/transfer shared definitions to an eligible current maintainer or retire them, with exact current administrative authority and expected state. This is not permission to inspect or take over every private view. Ordinary creator departure or loss of publishing capability ends that actor's writes; it does not itself end independent viewer rights to an otherwise current source-owned shared definition. Actual source/classification loss and applicable P12 restricted named-grant/grantor dependencies still end affected access. Declare the ordinary source's survive-transfer rule explicitly and preserve stricter actual dependencies. Never query as a departed author, keep their session alive, or require their approval for supported source stewardship.

### C06 — Remove readers, stop sharing and safe removal

An authorized audience change removes exact reader bindings immediately at the source admission boundary; future reads and stale responses must honor it. Stop sharing clears the shared reader audience and retains the saved definition only under a currently lawful maintainer's private rights. If none exists, scoped source administration transfers to an eligible maintainer before privatization or immediately removes/retires the shared definition; urgent withdrawal never waits for succession. It does not restore the historical creator or make any other private draft readable. Share again is a fresh deliberate current-authorized review/operation; no restored session, role, default or backup recreates removed readers. To preserve a shared resource when its maintainer is unavailable, a current scoped source administrator can transfer it while shared before optional privatization, or withdraw/retire it. Urgent withdrawal cannot wait for a replacement maintainer. Remove view retires the definition from active use and withdraws its audience, preserving only the required restricted history and replay evidence; it deletes no source evidence. Any supported recovery of that definition returns only an independently authorized private state before a fresh Share, never the old audience. A viewer's Hide/unpin is personal presentation and cannot remove the shared definition for others. Required repair is a real source command, not routine SQL or a generic permission grant.

### C07 — Current criteria and exact source independence

Preserve Q38 approved metadata-only discovery and Q42 source-use/one-home semantics. A view is neither a source queue nor a finite bulk selection; current live results can differ by viewer/time. Folder/label renames preserve stable reference identity; removal, restriction or schema incompatibility cannot silently broaden a query. Current restrictive changes fence serving before asynchronous cleanup. A temporary inability to resolve criteria or authorization is unavailable, not a proven terminal withdrawal or permission to revive historical settings. Legitimate current source fixes may restore an otherwise still-admitted definition within unchanged audience terms. Publication and maintenance do not move files, accept/reject, create source work, extend shares, alter retention, send notices or overwrite another user's defaults. Existing independently qualified filtered links remain available without requiring access to an unrelated private saved-view record; protected query material must stay out of unsafe URLs.

### C08 — Coherent publication, exact ordering and durable replay

Commit the authoritative saved definition/revision, exact audience, current maintainer and required history/operation result coherently, after complete candidate validation. Use exact intent and permanent semantic operation identity. Matching committed replay is reconciled before new-command eligibility, with current result-disclosure checks; a changed payload/key conflicts. No stale Share retry can restore an audience after unshare, undo transfer or replace a later definition. Distinguish uncommitted local edits, accepted publication and failed refresh. Order publication/update/transfer/withdrawal against assignment, source, predicate and policy changes at the actual source boundary; no success from an obsolete precheck. Keep minimum replay/result identity or reject unverifiable stale operations after readable history expires, without retaining private plaintext forever. A correction is a newly validated forward act; a failed response is not permission to publish a fresh wider copy.

### C09 — Native state and every path

Use exact tenant/environment/source/view relationships, current owner/audience assignment references, revision/state checks, unique exact audience membership and durable operation identity with appropriate indexes. Actor, scope, source binding and attribution are server-derived; updates cannot reparent them or mutate creator history. Same-scope constraints and current source/graph checks cover all read/write paths. Prove effective grants, RLS old/new-row checks and combined policies, SELECT/INSERT/UPDATE/DELETE/UPSERT, views/RPCs/functions, triggers, service roles, workers/imports and alternate routes. Protected publisher/recipient metadata must not be exposed by direct tables, broad directory pickers or diagnostics. Definition/audience deletion cannot cascade into evidence, source obligations or required history. Do not claim prepared capability code is already a wired PDP or use legacy preference/default permissions as the new grant.

### C10 — Usable publication and maintenance

Use the existing source-scoped saved-view context: named private/shared state, readable audience review, one deliberate Share/Save shared view, clear current maintainer and a direct Manage sharing/Stop sharing path when permitted. Avoid required essays, unrelated enrollment, forced full-directory loading, extra routine approver or automatic notification. Explain that recipients see their own permitted matches. Preserve local experiments, current selection and safe return after conflict or poor connectivity. A stale editor gets a clear current-state conflict and can deliberately rebase or save an authorized personal copy; no silent overwrite. Keyboard, non-drag pointer, mobile, focus, screen reader/status, reflow, Unicode/RTL/IME and long-name journeys must work through selection, publication, withdrawal and recovery. No action occurs merely from selecting an audience option.

### C11 — Minimal protected evidence, bounded work and operational repair

Record actual actor/context, exact definition/audience revision, maintainer changes, publish/update/withdraw/retire and recovery outcome in restricted source business history under its retention rules. Separate source-readable history from access/security evidence and redacted telemetry. Do not put private names, filter values, recipient rosters or content in ordinary logs, URLs, analytics or metrics. Bound definitions, predicates, audiences, pages/pickers, query work, active operations, concurrency and recovery/retention with actual owner units/thresholds before Live; no arbitrary audience/depth/day numbers or free-cost claim. Keep P12 set-wise query/audit budgets and source classifications. Current scoped stewardship can diagnose safe causes and repair exact supported state without raw SQL, broad read grants, contact-list exports or another incident product.

### C12 — Adoption, migration and proof before activation

At authorized publication reconcile the ordinary source's publish/read/maintain/audience/transfer/withdrawal powers through P9/P12, P3 classification where consumed, the exact current capability registry and full incorporated OpenSpec. Preserve Q38/Q41/Q42 and specialized owners. Qualify actual directory assignments, source metadata and all paths before enabling the first bounded cohort; no entire future teams/permissions product is a prerequisite. Legacy private views remain private; tenant defaults/reserved visibility and pasted links create no migrated audience. Mixed-version readers/writers, restored data and caches must honor current withdrawal and policy facts. Disable affected publication/derived serving without erasing personal work or independently lawful source use. Native role/race/replay/restore/retention/query/AT/staff proof is required; documentation review alone proves none of it.
