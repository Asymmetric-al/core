## Conclusion, alternative and precise new amendments

A is a useful bounded model when one ordinary evidence contribution needs a
clear staff filing location. It remains discoverable through its source and
other authorized views; filing and labels are optional. The model must not
turn a folder into a storage path, access grant, evidence status or new owner.

**B remains the strongest alternative:** additional explicit non-owning folder
references fit staff who repeatedly navigate different curated folder paths.
They need not copy bytes or grant rights. A's cost is real: another grouping
uses a label/view instead, and a label-based view will not automatically include
an unlabeled correction. No staff study, measured speed/cost improvement,
universal simplicity result or observed ministry frequency proves A superior.

The coordinated proposal makes three previously open seams concrete for this
amendment package, rather than pretending the original selection settled them:

1. One **Tenant × environment × ordinary-request-source staff filing namespace**,
   with current source/P12 rules for each fact/action and no folder ACL builder.
   It does not mean every staff member can see every folder, path or entry.
2. A genuinely new contribution/use is independent. A proven source correction
   may **copy its exact predecessor's currently qualified home once at admission**
   in the same scope. It does **not copy optional labels**, review decisions,
   permission or retained-history entitlement. Ordinary new contributions start
   Unfiled. Same-use non-byte instruction/status changes retain that use's home
   and labels. This is an explicit source-owned convenience rule, not identity
   merging or a universal successor rule.
3. **Remove folder is empty-only**, after an authoritative check for both direct
   entries and child folders. Use the existing accessible finite Move operation
   to clear contents first. Removing a placement to Unfiled, moving a folder and
   deleting source evidence are distinct operations. No recursive evidence
   deletion or compound hidden-content unfiling follows.

These are proposed exact outcomes pending the root's complete review and founder
ratification. No global folder platform, personal/shared audience toggle,
automatic label classifier, correction wizard or additional approval is needed.

## Exact proposed UX and source-facing amendments

H/M/L describes impact if wrong; exposure is qualitative design reasoning, not
an observed incident rate. U01–U12 refer to this note, not published owner clauses.

### U01 — One source-owned entry and one real filing scope

**H / plausible:** a folder operation mutates an entire multi-file item, merges
equal bytes across uses or grants general file ownership.

Adopt the ordinary staff filing namespace described above. The target is one
admitted participant receipt or Q28 supplied contribution/use for one request/
item, with an exact stable source reference. Keep one home or no home; no extra
folder references. Names, byte digests, provider keys and request-item IDs alone
are not this identity. Distinct uses remain distinct even when bytes match.
The source/P12 supplies current organization powers; body Read, upload/review
ability and staff rank are neither a substitute nor a universal prerequisite.
Use permitted metadata for organization without forcing body inspection.
Proof: P01/P02/P03/P18/P22.

### U02 — Optional filing with direct, truthful actions

**M / likely if desktop-file conventions are copied:** staff must file every
receipt, fear Delete will erase evidence, or lose an entry after a move.

Keep **Unfiled**, source navigation and current authorized lists usable. A missing
home is not missing source ownership. Use an always-visible ordinary-request
scope and **All request files** for that authorized cohort. **This folder** means
direct entries; any independently supported descendants mode must be explicit
and bounded, never an implied complete cross-product list. Provide a clear
**Move to folder** action, visible current location and a permitted destination
chooser. **Remove from
folder** means move this entry to Unfiled, with wording such as “The evidence
stays in its request”; display only currently permitted source context. Choosing
a destination prepares intent; the deliberate **Move** action commits it. Do
not issue on focus/change, require a reason essay or add another approval.
After success show the actual location and a safe route to it. A corrective Move
is available under current rights; a fleeting Undo toast is not the only repair.
Proof: P04/P05/P11/P14/P19.

### U03 — Correction continuity copies home only, once

**H / plausible:** a new correction inherits Reviewed/accepted/permission facts,
or a failed optional filing lookup blocks a lawful participant receipt.

For an actual Q03 correction or explicitly qualified Q28 replacement with an
exact predecessor, the source may carry only the exact
predecessor's current qualified home at admission, once, within the same tenant,
environment, request/item and filing namespace. Require current exact lineage,
destination existence and assignment authority. No name/digest matching,
cross-source placement, automatic copying of labels or live propagation follows.
Preserve both use identities and the original placement/history. If no qualified
home is available, the new contribution is Unfiled without copied labels. This
optional convenience must not prevent otherwise lawful source receipt. Report
the actual filing outcome; no false carried-home claim or delayed hidden catch-up.
The fallback applies only after independently valid source admission. Unknown
or invalid receipt/custody/required evidence authority still blocks admission;
Unfiled is not a bypass for those mandatory conditions.

Non-byte instruction, review or status changes to the **same use** preserve its
home/labels unless its actual owner restricts them. Later moves of either old or
new use are independent. Current review status remains authoritative. Staff see
the correction/new contribution and its actual filing; participants receive no
new folder disclosure. A label view can omit the unlabeled correction, so the
current home/source route must remain useful rather than promising every view
includes it. Proof: P06/P07/P08/P12/P17.

### U04 — Empty-only folder removal with a usable clearing path

**H / plausible:** a familiar Delete recursively destroys retained evidence,
or a filtered zero tricks staff into removing a nonempty folder.

**Remove folder** succeeds only after authoritative emptiness of both direct
entries and children is proved at the commit boundary. Otherwise leave it intact
and offer the actual finite Move flow for permitted entries/child folders to an
eligible parent/location or Unfiled as applicable. A child folder cannot itself
become an evidence entry in Unfiled; its supported destination remains a folder
tree/root location. Then staff can deliberately remove the empty folder. No
recursive delete, automatic hidden-item unfiling or multi-stage approval ritual.

Visible results and counts include only permitted facts. “No items you can
access” is not authoritative empty. If the actor lacks required scope, provide
safe source/admin help without revealing hidden item counts or reasons. The
qualified operator uses permitted exact membership facts and the same Move or
Unfile command. Source-owned reconciliation clears only proven-stale references,
preserving evidence/history; no body-reading grant or routine SQL is required.
Races with new entries/children make removal conflict safely; incomplete clearing
never silently removes the remainder. Proof: P09/P10/P11/P13/P18.

### U05 — Stable names, tree identity and meaningful context

**H / plausible:** moving a folder changes source identity, silently transfers
rights or creates an unbounded/cyclic path.

Folder rename/move changes organizational structure, never source association,
provider bytes, entry identity, permission, retention or evidence currentness.
Use stable folder/label identifiers; labels and paths are presentation, not keys.
Prove same-scope parents, no cycles/self-parenting, declared finite depth/size,
safe name normalization and collisions. Show enough permitted destination/path
context to distinguish identically named folders; do not expose hidden ancestors.
Preserve international/RTL names and input; render names as data. A valid rename
must not break saved criteria or existing source references. No five-level cap,
automatic root repair or owner-specific reparenting rule is inherited from Media.
Proof: P03/P10/P12/P16/P18/P20.

### U06 — Optional labels are not business decisions

**H / plausible:** a Reviewed label is read as actual acceptance or copied to
a correction without the underlying review.

Keep organizational labels visibly separate from source review/status fields.
Applying/removing/renaming a label cannot accept, reject, resolve, fulfill,
cancel, share, retain, publish or notify. No automatic rule engine or semantic
label classifier follows. Do not style an arbitrary label as an authoritative
status. Keep exact version/current source status readable when permitted.
Labels are optional; no classification task may block intake or ordinary use.
New contributions, including corrections, have no automatically copied labels.
Staff may deliberately apply current permitted labels through a source-qualified
action. Renaming a label does not rewrite historical evidence or create a new
source state. Proof: P07/P12/P15/P17/P19.

### U07 — Saved views are current queries, not copied audiences

**H / plausible:** saving/sharing a view freezes private results or silently
drops a missing criterion and returns a wider set.

Initially provide actor-owned private ordinary saved-view definitions and
qualified system/source views. Preserve the promised shared-view outcome for
its actual owner-qualified audience decision; do not activate P9's reserved
team/everyone visibility or imply that this folder choice settles it. Views
store qualified criteria/presentation, not a source grant or recipient list.
Apply each viewer's current source/field authority before results, counts, rank,
grouping or export. Preserve current Q38 sparse/unknown/incomplete distinctions.
If a folder/label/field criterion is deleted, unauthorized or unsupported, show
a safe invalid/unavailable criterion and a deliberate repair path. Do not
silently discard it, retarget by the same label text, broaden the query or claim
a complete no-match result. Clearing a filter is an explicit user action.
Proof: P12/P14/P15/P16/P19/P22.

### U08 — Current authority before every organizational disclosure

**H / plausible:** a folder path, count, source association or stale picker
reveals protected work despite a safe-looking entry list.

Authorize folder/label names, ancestors, entry identity, chosen destination,
source context, counts, suggestions, pagination, error details, history and
recovered results. Being in the staff filing namespace does not make metadata
tenant-public. Current permission is checked again for the actual command and
any subsequent Read/Download/Share action. A visible container cannot expose a
hidden target or other equal-byte use. An inaccessible home is not Unfiled;
disclose a neutral unavailable location only when that fact itself is permitted.
Preserve Q28 origin restrictions, Q38
discovery limits and Q41 exact share/version/end; no participant/external folder
browsing appears. Clear or disregard unauthorized late results after context
change; do not broaden permissions to repair a picker. Proof: P02/P03/P10/P12/
P14/P16/P18/P21.

### U09 — Finite, recoverable commands and batches

**H / plausible:** a lost response duplicates an effect or a stale move restores
an old folder over a newer deliberate choice.

Use coherent source organization commands with exact scope/actor/targets,
expected state and semantic operation identity. Reconcile a matching committed
result under current disclosure rights before new-command eligibility. Changed
intent conflicts. Do not mutate filing from read/render/provider callbacks.
Bound explicit bulk selection; distinguish selected rows from all matching
results and deduplicate the actual intended source operation, not byte equality.
The reconciled proposal makes one submitted finite bulk Move all-or-none: a
stale or denied selected member changes none, with lawful selection preserved
for deliberate correction. Do not silently omit blocked entries. If a limit
requires multiple batches, split explicitly before commit and retain each
batch's result; never call several separately committed batches one atomic act.
Report acknowledged success, conflict, failure and pending/unknown truthfully.
Recover unresolved intent without repeating a committed effect. Bulk Move is
the clearing path before empty-only removal; an incompletely cleared folder
cannot be removed just because earlier batches succeeded.
Readable history follows its actual retention rule. Preserve minimum required
deduplication/result evidence or reject unverifiable stale operations; expired
readable history cannot make an old semantic act executable as a new command.
Proof: P05/P09/P11/P13/P17/P18/P20.

### U10 — Accessible composition and low-bandwidth recovery

**M / likely without complete testing:** the picker requires dragging, hides
its path on mobile or loses input/focus on a failed move.

Use existing base-maia/Base UI components and normal accessible commands.
Provide keyboard **and** simple click/tap alternatives to dragging. Keep a
readable current/selected destination, searchable bounded results and clear
selection count. Avoid forcing exhaustive tree loading. Preserve meaningful
focus and lawful input through validation, conflict, retry and slow responses.
Announce status without stealing focus or continuously repeating counts. Support
zoom/reflow, touch/voice, long labels, RTL/IME, contrast and safe rendering.
Show real pending/success/failure; do not hide an entry permanently because of
an optimistic move that failed. Selecting a filter/label/destination must not
unexpectedly navigate, issue mail or perform another source action.
Proof: P04/P05/P13/P16/P19/P20.

### U11 — Practical repair, privacy and no outward side effects

**H / plausible:** routine filing errors require SQL, or a generic audit/log
leaks private filenames, old paths or sensitive query text.

Before commit allow edit/cancel. After commit use a current authorized correction
to the actual filing/tree state, preserving original attribution. A removed
folder may be recreated only as a new lawful identity; old queries/grants cannot
revive by matching its name. No universal snapshot Undo, restore of old access,
evidence disposal or original-file alteration. Maintain enough restricted
source/operation evidence for diagnosis without a broad private-name/query
corpus. No new notification, reminder, task, participant prompt or read receipt
is selected. Applicable source retention and privacy/restore controls remain.
Proof: P05/P12/P15/P17/P18/P21/P22.

### U12 — Explicit qualification, not presumed generic machinery

**H / plausible:** adjacent CMS folders or CRM views are represented as the
ordinary source capability, or unchecked legacy data inherits permissions.

Adopt the scoped organization command, home-only correction rule, empty-only
removal, label/view semantics and ownership in canonical authoring sources at
the authorized stage. Preserve all specialized folder/library owners. Prove
native effective roles, typed references/constraints and all mutation paths,
current-authority races, migration/restore and composed user journeys. Bound
tree depth/width, page/selection counts, name/query sizes and latency/resources
through actual qualification; no unlimited recursion, zero-cost promise or
vendor quota inheritance. No new general drive, graph, schema designer, automatic
classification, public link or bulk-package product follows. Proof: P01–P22.
