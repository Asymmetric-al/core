## Exact minimally sufficient owner wording

These clauses are proposed amendments to be folded into the parent's corrected decision, not a published specification.

**O-A01 — Selected capability and scope.**

> For an ordinary native Private Document Request that remains unfinished, a currently eligible confirmed recipient may initiate a text-only question about a Document Request Item, including before supplying a file, and reply to deliberately shared staff guidance in that item context. Authorized staff may respond through an explicit participant-visible action. The source owns the operation, audience, current context and staff work route. The recipient is not required to ask a question, provide an essay, select a staff member or enroll in a broader product role.

**O-A02 — Item acceptance and source authority.**

> Clarification eligibility follows the current source-authorized scope of the unfinished request. An accepted item may remain discussable when the source permits it; text grants no correction, unacceptance, waiver or fulfillment power. An actual restriction on discussion still applies. Source/P12 checks for recipient text, staff text, internal review, evidence decisions and recipient administration remain distinct. A read grant, assignment, folder, matching address, mention or service credential supplies none of the missing authority.

**O-A03 — Shared text and internal discussion.**

> Expose only the currently permitted shared text needed to understand this recipient's exchange in this source purpose. Internal review notes, staff task discussion and protected historical content remain separate. Never publish them by changing a visibility flag, switching composer modes, quoting an old thread or linking a file preview. Deliberate outward reuse contains only facts currently authorized for this recipient. Reused bytes, new recipients and other requests do not share a conversation automatically. Staff author presentation is source-approved; it does not disclose private staff rosters, contacts or review history.

**O-A04 — Durable source receipt and work.**

> A successful send means the owning source durably received the exact text and can recover its accountable staff work; it does not mean a human read it or that an answer will arrive immediately. Attribute the act from trusted context and bind its exact request/item/purpose and, when relevant, the intended evidence or instruction basis. Preserve one permanent effect across retry and lost responses. Existing request/My Work surfaces show newly received clarification to the current authorized source route independently of optional email. Preserve accepted work through absence, reassignment, source closure and access expiry; do not create a new task per message, automatic Support conversation or general inbox.

**O-A05 — Current human decisions without a new completion gate.**

> A newly admitted clarification is relevant source decision context, not automatically a new file, correction, unmet requirement or evidence decision. At the affected source boundary, a human acceptance, return or requirement decision prepared before newly received clarification cannot silently commit against the older context or rebase itself. Present the newly received currently permitted text and allow the same meaningful source action after deliberate reassessment. No separate Reply, Resolve, acknowledgment, read-count, dwell, essay or second approval is required. Coordinate only the affected item and actual aggregate dependencies; unrelated work remains independent.
>
> Receipt does not retrospectively invalidate an already durable acceptance. If all required human decisions already committed and Q22 fulfillment only awaits technical continuation, later text remains source-visible with accountable follow-through; it does not invent another final approval or automatically hold fulfillment. Material information is considered through the existing source review/remediation commands. A real new source restriction or changed requirement participates in Q22's actual predicate; a message merely being present or unanswered does not. Preserve the original decisions, fulfillment occurrence and subsequent remediation history.

**O-A06 — Closure and access ordering.**

> Order participant message admission with current source eligibility, recipient change, revocation, expiry and closure. Admission-first preserves the received message and its owned follow-through; closure-first denies new in-request text without claiming it was received. Unknown send outcomes reconcile under the original effect identity and current disclosure. Completion or expiry does not make an admitted question answered, discard it, reopen work, extend a grant or promise that an in-request answer remains readable. Use the existing qualified source-help route where further contact is needed. Independent staff source work may continue under its own authority.

**O-A07 — Fresh access, context and history.**

> Fresh unfinished access must expressly admit the clarification operation and its narrow same-recipient current shared-text context within the original requirement/purpose lineage. An old unsent command cannot borrow the fresh grant or auto-send after return. A deliberate new authorized send may reuse a lawful draft after current context is checked. No existing grant is silently expanded by rollout. Completed or fresh-completed access gains neither messaging nor a general conversation archive from Q30. No internal notes, superseded file bytes, another recipient's history or ended-purpose content follows from receiving text.

**O-A08 — Optional controls and communication ownership.**

> Reuse existing source restrictions, current person/team responsibility and qualified handoff. A adds recipient initiation; it does not silently select tenant Off defaults, replies-only modes, new per-item routing controls or a staffing/presence/SLA engine. Any legitimate existing restriction is explained safely with an actually owned next route. Stopping new intake cannot erase already received work. Q20/Q26/Q27 retain their exact event meanings and choices. Q30 selects no new outward email/SMS/bell event, default, reminder, digest, email-reply ingestion or read/typing receipt. A separately authorized notice must use its qualified source/P17/P6 contract; shared text is not a reason to invent a dispatcher or fake Party.

**O-A09 — Data and recoverability.**

> Current scope applies before text, excerpts, counts, errors, search, pagination, caches and recovery are disclosed. Retain the source's minimal needed attribution and disposition under its actual classification, retention, hold, redaction and restore rules; do not promise perpetual transcript bodies or duplicate them into ordinary audit/events/logs. Safely render untrusted text. Files continue through the qualified upload/evidence route rather than message attachments. Preserve lawful draft/focus/context on recoverable failure, isolate drafts across user/tenant/request/recipient/purpose changes, and do not introduce an unapproved private offline cache. Known receipt remains known if a secondary refresh fails; unknown commitment is not a failed send to be blindly duplicated.

**O-A10 — Exact adoption boundary.**

> Q30 explicitly supersedes only Q23's no-recipient-text-channel reservation for this ordinary request capability and supplies the narrow shared-text entitlement necessary for it. It preserves Q23 internal-note/history restrictions, Q03 evidence lineage, Q21 exact staff acceptance, Q22 fulfillment and Q06–Q19 access periods. At the authorized formal publication stage reconcile native source/P4/P12/P9 bindings, the relevant current-decision-context rule, current disclosure and the complete incorporated contracts and declared projections. Preserve specialist P21/P26/P27/P28 purposes and qualification. No whole Support/Workflow Studio dependency, new permission engine or legacy-data backfill of invented authority is implied.

## Closure and decision race resolution

| Ordered case                                                                          | Required result                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Question arrives before staff prepares acceptance                                     | Current source context includes the received question. Staff can decide without replying or performing a message acknowledgment ritual.                                                                                                       |
| Question is admitted after preparation but before the affected human decision commits | Reject the stale decision basis; retain the staff draft and lawful reading context. Refresh exposes the new permitted information. The ordinary source decision remains the only business action needed.                                      |
| Staff decision and applicable fulfillment commit first                                | Preserve them. A later attempt cannot post under unfinished-request authority. A lost reply recovers the existing outcome only where current disclosure permits.                                                                              |
| Human decision commits; a question arrives before deferred automatic fulfillment      | Keep prior acceptance intact and the question visibly owed to the source. No new universal completion gate; fulfillment follows actual requirements. Existing source remediation handles material facts and retains both historical outcomes. |
| Question commits; fulfillment/expiry occurs before staff responds                     | Retain source staff work. Do not label the question answered or promise an in-request response remains accessible. Further contact uses actual permitted source help/communication; no access renewal.                                        |
| Recipient changes or fresh access is granted while a message/draft is pending         | Old admitted identity and text remain attributed to their real source occurrence. New identity/grant does not inherit sending or history. Recheck any new deliberate act and discard late old-context disclosures.                            |

This is an extension to existing source currentness, not a new review workflow. There is no safe way to know whether arbitrary incoming human text is materially significant by merely counting unread messages or running a generic classifier. Requiring current context for a pending human decision and retaining post-decision follow-through is the smallest honest boundary. Qualification must prove both sides of every ordering, including the deferred-fulfillment interval.

## User and staff flexibility without additional product machinery

- Questions before upload need an item context, not a fake file version. A version reference is present only when the meaning actually depends on an exact version.
- Staff can deliberately accept the same existing evidence after clarification under Q21/Q23. Sending the answer is not acceptance and no replacement upload is required merely to clear the conversation.
- An accepted item remains readable/discussable only under its applicable source rights; the fact another item is unfinished does not override a real source restriction.
- Current staff person/team routing is sufficient. It need not expose a roster, require personal claiming, establish online presence or confer review/egress permissions.
- The participant sees a clear tenant/request/item audience and honest Received/awaiting staff state. Staff use a plainly labeled outward action distinct from internal notes. No configuration step is imposed on the recipient.
- Neither stale context nor a send failure should erase lawful text or force repeated navigation. No forced third pane alongside Q29 paired reading is needed.
- Preserve actual source alternatives and capable help for mistaken or impossible requests. A does not require answering every message with prose when the correct meaningful source action already communicates the outcome.

## Suggested single glossary addition

**Document Request Clarification:** A source-owned text question or reply about a Document Request Item, shared between its currently authorized recipient and authorized staff for that request purpose. It is distinct from internal review notes, file submission or correction, a formal Request changes decision and evidence acceptance.

_Avoid_: file-wide chat, staff note, evidence acceptance, request approval.

This one term is justified because Q30 introduces participant-visible text where Q23 expressly reserved it, and conflation with staff notes or evidence is the main design hazard. It does not prescribe a thread/message schema, new workflow object or a broad discussion platform. Preserve the existing twenty-one definitions. The parent may use the term only if the full Q30 review adopts it; this note does not ratify it.
