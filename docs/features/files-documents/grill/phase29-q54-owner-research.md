## Recommended next decision

**For ordinary staff evidence intake, should Asym keep deliberate Add existing file as the reuse path, or additionally suggest eligible existing versions as possible exact-file matches for the staff member's selected file?**

Recommend **A — Keep deliberate Add existing file; no new exact-file suggestion capability in this ordinary lane.** This is a complete, permanent initial product boundary, not a disabled feature, deferred implementation task or hidden “enable when cheap” switch. Q28's manual source-qualified reuse and Q53's new local supply already support the underlying job. An on-demand content-fingerprint lookup would still be the new matching capability; it cannot be smuggled into A as ordinary metadata search.

**B — Add optional, source-qualified exact-file suggestions** is credible. It can locate an eligible file whose name or known context does not help the staff member find it manually. It needs a separate narrowly adopted matching/discovery purpose and useful timing before the relevant new source act. A browser-computed fingerprint can be untrusted discovery input over independently authorized existing versions; returning permitted candidates need not wait for the incoming file to reach storage. That query does not certify the incoming bytes. B cannot inherit Media's default, reveal a protected match, interrupt or silently switch Q53's already-authorized Upload and add, or promise universal transfer savings.

Illustration, not observed ministry feedback: Nora selects Elena's inventory file for the same eligible ordinary item. A legitimate version of those bytes may already be held under an eligible source use, perhaps with an unfamiliar permitted name. With A, Nora can use Add existing and the approved metadata/source picker, or complete Q53's Upload and add. With B, a qualified early hint can propose an eligible existing version and offer deliberate existing-file selection, without certifying that an unverified incoming local file is identical. Keeping the new upload remains valid where its own source conditions permit. Equal bytes do not decide that the two source acts have the same provenance or purpose.
