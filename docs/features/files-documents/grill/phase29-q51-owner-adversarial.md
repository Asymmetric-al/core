## Judgment and concrete recommendation

**Accept with required amendments.** The smallest complete product is a saved-comment **Notify a colleague** action, usable immediately after posting and later, with one explicitly selected qualified staff colleague. Ordinary comments remain independent. Use the existing governed P17 informational center and P6 truth, with a qualified same-database transaction that commits the source request, complete one-member message plan, local available projection and result together. No separate accepted-but-not-visible queue, external provider or new utility timer is needed.

One semantic cue is allowed for the exact active Q45 visible revision and stable target staff human, across requesters and transport keys. A later real active revision, including lawful Restore, can be explicitly notified; revision changes never send automatically. Read/archive, time passage, policy toggles, access return or alternate staff contexts do not reset the old slot. The cost is that unchanged repeated nudges use actual follow-up comments or existing qualified coordination instead of a reminder/cooldown feature. That is preferable to lifetime-per-comment deduplication, which would overrestrict substantial later corrections, and to unlimited repeats, which would create a new noise-control product.

The strongest B remains unaddressed Q45 comments with actual qualified source-review/task coordination. It has less interruption and producer complexity. A is recommended because it preserves the exact observation/context during a deliberate colleague handoff, not because missed-comment rates or Asym preferences were measured.

High-impact findings:

1. **High / likely if omitted:** an attractive mention picker can grant access, expose a staff directory, send during typing or borrow Support recipients. The new source act needs actual eligibility, safe discovery and a deliberate final command.
2. **High / plausible:** a copied bell/queue row bypasses P6/P17, produces false success, or leaves half an action. Explicitly qualify complete local atomic composition rather than add another notification writer.
3. **High / plausible:** using transient role/session/email identity for deduplication permits repeat cues or moves unread history across contexts. Stable human deduplication and exact original presentation authority are different bindings.
4. **High / plausible:** edited/withdrawn/Restore content, access loss and optional-control changes can revive old unread work or leak stale text. Use exact source revisions and a monotonic Q51-only unread stop, distinct from current inability to evaluate permission.
5. **Medium / likely if omitted:** only authors can notify, or a creator departure strands a valid cue; alternatively notification claims the comment author sent it. Author and attention requester are distinct, with real current source powers and truthful attribution.
6. **Medium / plausible:** a wrong but already qualified target drives a new recall/Undo platform or forced comment deletion. Precommit Cancel is local; postcommit correction can target the correct colleague without reposting, while real privacy misuse uses its qualified owner remedy.

No Critical severity or deployed Q51 disclosure incident is established by this review.

## Exact proposed amendments

### O-C01 — Saved-comment act and source scope

Provide Notify a colleague on a saved, active, currently source-eligible Q45 comment, immediately after posting and later. Bind immutable source/Tenant/environment/use/file-version/purpose/comment and the exact current Q45 visible revision. It requests attention to that observation, not to any latest upload or all equal-byte uses. Posting, editing and lawful source work remain complete without it. The initial product has no integrated send-on-Post, raw `@text` parser, follower recruitment, group broadcast, participant message, task per comment, assignment, deadline, Resolve flag or read receipt.

### O-C02 — Current requester and truthful attribution

Authorize the new command through the current source's qualified comment-create capability plus current read of the exact comment/source context and its attention policy. Comment Read alone, reviewer responsibility, file access, draft authorship or staff rank does not confer the act. This explicitly adopts a new operation using compatible existing capability ownership, not a bespoke role or second permission engine. A qualified staff actor may direct another author's comment without editing or impersonating them. Preserve original author separately from attention requester. A lawfully committed request does not generically require the requester's ongoing session/employment; real source/privacy/grantor dependencies still govern.

### O-C03 — One real eligible colleague

Each deliberate command targets one explicitly selected current staff human, other than the requester, in the exact Tenant/source context. No self-target, arbitrary address, default first match, group, whole team, external reader or recipient invitation follows. The target must currently qualify for the exact comment/context, but need not be the responsible reviewer or be allowed every historical byte; preview failure alone is not disqualification. Directory/name/disambiguation facts have their own current source/P12 disclosure. Resolve actual native principal and exact eligible staff assignment/access basis server-side, without email/name/digest/profile-duplication heuristics. Ambiguous or unproved identity is not a permitted recipient.

### O-C04 — Native informational purpose and identity adoption

Adopt one exact ordinary-comment producer and typed exact-comment destination in P6/P17, with the compatible actual staff/no-Party branch and current source fences. Do not mint a generic mention contract, reuse Q27/Q32/Support/finance keys or treat the demo bell as implementation. Local-only qualification must work without Resend, email sender proof, SMS, push, external prepared-material or Recent sent-copy machinery. No email record, provider state or fake transport result is created. Channel expansion requires its actual separate owner adoption.

### O-C05 — Atomic local admission and truthful availability

Use one qualified authoritative database transaction to establish the source attention request and permanent business slot, invoke the complete one-member P6 compiler through its public source seam, release the fully verified parent before local member materialization, create the exact local available event/role-safe projection, and persist required source history/result. No independent private-child call, direct bell-row insertion or separately committed source-plus-projection calls qualify. No successful Q51 admission remains pending in a second queue. Success requires the exact one eligible local member and available projection; compiler zero/rejection/unknown is never represented as successful Notify. Preserve the general compiler's valid zero-result contract elsewhere rather than inventing a child. Bound actual transaction/lock/recovery work; no remote services inside it.

### O-C06 — One semantic request per visible revision and human

Deduplicate the exact source comment's existing Q45 visible revision and stable target staff human across requesters, transport keys and alternate contexts. Keep presentation separately pinned to its actual admitted assignment/role/access basis. Do not create another content/lifecycle revision graph or use transient sessions, current email, policy generation or assignment switching to reset the business slot. Same-revision read/archive, expiry, Off/On, access return or restored data never refunds the slot. Unchanged repeated nudges use actual follow-up/qualified coordination, not a new cooldown or reminder engine.

### O-C07 — Replay versus another actor's duplicate

Recover the original requester's matching committed operation under current safe result disclosure before applying fresh new-action checks. Preserve original target, occurrence, source revision and outcome; changed material intent conflicts. A different actor making a currently qualified same-revision/same-person request receives a safe truthful Already requested result without new cue or rewritten requester attribution. It is not authority to read another actor's protected operation receipt. New-operation eligibility and current source/recipient disclosure still apply to that business duplicate.
