# Q02 — View my submitted file

**Status:** Historical question prepared 2026-10-20. Conrad subsequently
selected A and ratified the completed required amendments on 2026-10-20.
Q01 A and its required amendments are ratified; this question does not reopen
recipient confirmation or grant a new read capability before selection.

## Decision to make

For the ordinary new private document-request experience, should a currently
authorized recipient be able to reopen a safe preview of the exact file they
submitted, or see only their submission receipt and status?

The receipt/status experience is already required by the Phase34/41 participant
contracts. Those contracts do not establish a universal right to inspect every
submitted file's contents. Preview is a distinct source-authorized read.

| Option                                                       | Experience                                                                                                                                            | Tradeoff                                                                                                                                 |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| A — Receipt/status plus View my submitted file (recommended) | Return to the same request page and deliberately inspect a qualified preview of the exact received submission while current source access permits it. | Helps people check which document arrived; adds safe rendition and ongoing read-authorization requirements.                              |
| B — Receipt and status only                                  | See admitted submission details and progress, with no server-held file content through this ordinary request lane.                                    | Simpler and less retrieval exposure; checking file contents relies on the recipient's retained local copy or source-approved assistance. |

## Recommendation and scope

Recommend A as an Asym product judgment, not a claim of industry-standard
post-submission viewing. Microsoft, Box and Dropbox official collection guides
document upload/confirmation behavior; the inspected pages do not establish
ongoing own-submission readback. The potential benefit needs participant proof.

The ordinary approved profile should include the useful readback journey rather
than hiding it behind arbitrary feature toggles. Stricter source confidentiality
or purpose policy remains authoritative. Own submission means an exact admitted
actor/recipient/request/file-version relationship, never all files with the same
email, person, filename or digest.

Receipt, safe-preview readiness and business acceptance remain separate. A
delayed, unsupported, limited or failed preview preserves truthful receipt;
there is no automatic original download or third-party viewer fallback. Current
permission governs every read. Preview is a real disclosure and can be copied;
a hidden download button is no guarantee against copying.

This question does not decide original downloads, replacement/deletion,
corrections, staff materials, other participants' submissions, prior-version
archives or post-closure duration. Existing Phase18/21/26/28 source-owned reading
and publication rules remain intact. Reuse only the qualified shared rendition
mechanics with the new request's audience authority; do not copy Support staff
permissions into a recipient viewer.
