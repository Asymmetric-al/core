# Q18 r2: Import undo and reversal (external practice)

_Scope: how other products undo or reverse imports and migrations, how they word it, and what UX, accounting, migration and privacy practice say about it. Written for the Q18 decision (F14: "Undo" vs "Prepare reversal" wording, and which record families get a reversal workbench in v1). Research agent, read-only web research, all URLs accessed 2026-11-03._

Labels: **VV** = vendor or standards page fetched and quote checked · **S** = secondary (search-engine summary of an official page that refused fetching, community post, consultancy blog) · **U** = unverified (not found, or my inference). Quotes are short because the fetch tool caps them.

**Blocked (403 or empty):** support.virtuous.org, support.neonone.com, support.keela.co, help.salesforce.com, central.xero.com (JS-only), ico.org.uk, sap.com Fiori, community.klaviyo.com. Claims from these pages are labelled S.

## Summary

1. **"Undo import" is the dominant label** (Planning Center, Little Green Light, Zoho, Mailchimp). Behind the same words sit very different behaviours: deleting only what was created, blindly reverting later edits, or restoring a whole database.
2. **No vendor found does what Asym decided:** restore a field only if it still holds the imported value, and report later edits. Most either ignore updates (Mailchimp, Zoho, HubSpot import delete, Salesforce) or overwrite later edits (Planning Center People, Little Green Light). HubSpot's "Restore CRM changes" comes closest: it is preview-first and reports partial failures with reasons.
3. **The best precedents refuse instead of warning.** Planning Center only _warns_ that undoing after a merge "can completely delete the merged person". Neon refuses to delete imported accounts that have later activity. Givebutter keeps contacts linked to online transactions. Planning Center Giving keeps created profiles "unless they have had additional activity".
4. **Money is never undone by deletion in serious tools.** Bloomerang card gifts "can be refunded but not deleted". Raiser's Edge posted gifts are adjusted. Virtuous prefers a reversing transaction. QuickBooks voids keep a record. Event sourcing undoes only by appending "a compensating event". German bookkeeping law forbids changing an entry so that "der ursprüngliche Inhalt nicht mehr feststellbar ist" (the original content can no longer be determined).
5. **No donor CRM found reverses a whole migration after go-live with live data.** Remedies end at test-load review: Bloomerang allows 14 days on the test server, and Funraise says "An import is final". Cloud cutover guidance (AWS, Azure, Dynamics) requires a named fix-forward-or-roll-back decision-maker, go/no-go criteria and explicit "points of no return".
6. **Undo windows are short and stated:** Planning Center People 48 hours, Planning Center Giving 2 weeks, HubSpot 14 days, Zoho 30 days, Notion 7–90 days. WCAG technique G164 recommends "a stated time" within which a request may be cancelled.

### 1.2 Patterns across vendors

- **Three undo models.** (a) Delete what was created and leave updates (Mailchimp, Zoho, HubSpot import delete, Salesforce, Neon, Givebutter). (b) Blind revert of everything, including later edits (Planning Center People, LGL). (c) Restore a snapshot or backup of the whole store (DonorPerfect, Airtable, Notion per page). Asym's conditional, field-level restore is a fourth model. Only HubSpot's restore tool approaches it, with a preview, a count-typed confirmation and a failure-reason CSV.
- **Typed confirmation is common for import undo:** Planning Center ("Undo import"), Mailchimp ("UNDO"), HubSpot (the number of changes).
- **Money gets separate, stricter treatment** even where people-undo exists. Planning Center Giving uses a different window (2 weeks, versus 48 hours for People) and a commit-reviewed batch. Givebutter will not delete contacts with online transactions. Bloomerang card transactions cannot be deleted (§3).

## 2. UX practice

### 2.1 Undo versus confirmation

- NN/g: "Use a confirmation dialog before committing to actions with serious consequences"; "Do not use confirmation dialogs for routine actions"; "Be specific and inform users about the consequence"; answer options should "summarize what will happen", e.g. "Delete file" / "Keep file"; and still "go to great lengths to provide undo". VV https://www.nngroup.com/articles/confirmation-dialog/
- NN/g heuristic 3: a "clearly marked 'emergency exit'"; "Support undo and redo"; exits "easy to find and well signposted". VV https://www.nngroup.com/articles/user-control-and-freedom/
- Ministry of Justice (GOV.UK-derived) confirm-an-action pattern: use it when "the action cannot be undone (or not undone easily)". "Show the important details" in a summary list. Afterwards a notification banner "tells the user what effect the action has had". VV https://design-patterns.service.justice.gov.uk/patterns/confirm-an-action/
- GOV.UK warning button: "Only use warning buttons for actions with serious destructive consequences that cannot be easily undone by a user"; add "an additional step which asks them to confirm it"; button text should describe "the action it performs". VV https://design-system.service.gov.uk/components/button/
- Cloudscape: typed "confirm" only "for high severity deletions"; state the "potential cascading effects"; the button uses the same verb as the title; "You can't undo this action." VV https://cloudscape.design/patterns/resource-management/delete/delete-with-additional-confirmation/

### 2.2 Wording: Undo, Revert, Roll back, Reverse, Restore

- **Microsoft Style Guide:** "undo" is "OK to use as a verb to describe the action associated with the Undo command. Don't use as a noun." VV https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/u/undo . No "revert" entry exists (the URL returns 404), so no guidance either way (U).
- **Atlassian:** use "imperative verbs such as 'Save', 'Remove', or 'Create'", not "vague terms such as 'Done'", in 1–2 words; "inform them whether any actions they take can be easily undone." VV https://atlassian.design/foundations/content/designing-messages/warning-messages
- **GOV.UK check answers:** the final button "clearly shows the action it performs" (example: "Accept and send"). VV https://design-system.service.gov.uk/patterns/check-answers/
- **Polaris:** include a toast action only "if the same action is available elsewhere on the page" (example: Undo an image deletion); action toasts persist at least 10,000 ms. S https://polaris-react.shopify.com/components/deprecated/toast (page now redirects)
- **"Revert" means a new compensating change in developer tools.** GitHub: "Reverting a merged pull request creates a new pull request that reverts the original merge commit." VV https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/incorporating-changes-from-a-pull-request/reverting-a-pull-request . Microsoft Advertising Editor separates Revert (back to the downloaded state) from undo (the last action). S https://help.ads.microsoft.com/apex/index/22/en/14072
- **"Reverse" is accounting vocabulary.** A QuickBooks reversing journal entry "doesn't delete the original journal entry". S https://quickbooks.intuit.com/learn-support/en-ca/help-articles/reverse-or-delete-a-journal-entry/00/261858
- **Users misread both words** (practitioner evidence only). "Revert" read as developer jargon: S https://forum.syncthing.net/t/override-or-delete-local-changes-not-revert-local-changes/25786 . "Undo" mistaken for "undo what I just did": S https://zanata.atlassian.net/browse/ZNTA-1554
- **No authoritative style guide settles undo versus revert versus reverse for bulk, conditional reversals** (U). The consistent advice (NN/g, GOV.UK, Atlassian) is to name the result in the final button.

### 2.3 Preview before apply

- HubSpot runs **Prepare preview → Open preview → Restore**. It is the only vendor found with a two-stage "prepare, then act" reversal, and its wording is the closest precedent for "Prepare reversal". VV (restore-crm-changes, above)
- Before import, Planning Center previews new, updated and error tabs with per-row uncheck (VV, People import page above). Bloomerang shows "how many new constituents are being created" and how many updated before **Run** (VV, Imports 101). Planning Center Giving uses in-progress batches that are reviewed before **View and commit batch** (VV, donation history page).

### 2.4 Reporting partial reversal

- HubSpot exports a CSV of "completed or partially failed restores" with "property values before and after, and failure reasons" (beta). VV
- Bloomerang bulk delete skips incomplete pledge or recurring sets and reports "how many were skipped". VV https://help.bloomerang.com/en/articles/12632672-bulk-delete-transactions
- SAP Fiori: for partial success, a summary message view at the end listing the items that failed and why. S https://www.sap.com/design-system/fiori-design-web/v1-120/foundations/best-practices/global-patterns/messaging/processing-multiple-items

### 2.5 Accessibility

- **WCAG 3.3.4 (AA)** covers pages that "modify or delete user-controllable data in data storage systems". Each submission must be "reversible", "checked", or have "a mechanism … for reviewing, confirming, and correcting information before finalizing". Technique G164: "a stated time within which an online request … may be amended or canceled". VV https://w3c.github.io/wcag/understanding/error-prevention-legal-financial-data.html (editor's draft)
- **WCAG 4.1.3:** progress and results must be status messages announced "without receiving focus". VV https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html
- **WCAG 2.2.1 and toasts:** an Undo inside an auto-dismissing toast is a known failure. A UK government design system says a toast "can't automatically dismiss if an action is included". S https://design.sis.gov.uk/components/toast ; https://gitlab.com/gitlab-org/gitlab-services/design.gitlab.com/-/issues/2771 ; https://scottohara.me/blog/2019/07/08/a-toast-to-a11y-toasts.html

## 3. Financial and accounting practice

- **Append-only with compensation.** "The only way to update an entity or undo a change is to add a compensating event … The original event remains in the stream." Compensating events "provide a history of reversed changes." VV https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing
- **Compensation is not restoration.** "you can't always roll back the data because other concurrent application instances might change the data". A compensating transaction "doesn't necessarily return the system data to its state at the start". "Define clear points of no return". For high-impact decisions, "include a human". VV https://learn.microsoft.com/en-us/azure/architecture/patterns/compensating-transaction
- **Ledger immutability in law (Germany, illustrative).** §146(4) AO: "Eine Buchung oder eine Aufzeichnung darf nicht in einer Weise verändert werden, dass der ursprüngliche Inhalt nicht mehr feststellbar ist" (a booking or record may not be changed so that its original content can no longer be determined). VV https://www.gesetze-im-internet.de/ao_1977/__146.html
- **Void versus delete in QuickBooks.** Voiding keeps "a record of the transaction in your books that don't affect your totals". Deleting removes it "everywhere except the audit log". VV https://quickbooks.intuit.com/learn-support/global/manage-lists/void-or-delete-transactions-in-quickbooks-online/00/385528
- **Bloomerang.** A refund keeps the original and adds a refunded transaction. Deletion "erases" it. "Credit card transactions can be refunded but not deleted." Processed transactions lock Date, Amount and Method until someone uses **Unlink from Processor** with a reason. Bulk-deleted transactions "are not refunded". VV https://help.bloomerang.com/en/articles/12632629-refund-or-delete-donations ; https://help.bloomerang.com/en/articles/12632578-unlinking-transactions-from-transaction-processors
- **Raiser's Edge NXT.** Once posted, a gift "can no longer be edited". The fix is **Adjust**, with an adjustment GL post date, or reversing a batch or unposting in web view with finance's agreement. S https://help.trellis.org/how-gl-post-date-and-status-work-with-your-raisers-edge-nxt-integration ; https://community.blackbaud.com/discussion/comment/275359/ ; https://community.blackbaud.com/discussion/comment/310670
- **Virtuous.** "A reversing transaction is the generally the preferred method for correcting data errors." S https://support.virtuous.org/hc/en-us/articles/360051020212-How-Do-I-Change-the-Donor-on-a-Gift
- **Planning Center Giving.** Deleting a donation is permanent and bulk edits "cannot undo", but its import undo removes imported donations within 2 weeks, before receipts exist (none are sent for imports). S https://help.planningcenter.com/en/bulk-edit-donations.html ; VV donation history page above.

## 4. Migration practice

- **Dynamics 365:** the cutover plan must include "A rollback plan in case something goes wrong", plus a go/no-go decision with set criteria, repeated mock cutovers, and a cutover window "usually less than 48 hours". VV https://learn.microsoft.com/en-us/dynamics365/guidance/implementation-guide/prepare-go-live-cutover-strategy
- **AWS:** the rollback plan needs "Defined checkpoints" and "A point of contact who will make the decision to either fix forward or roll back". Rolling back without new data is simple. Rolling back after new transactions needs fail-forward replication, dual writes or a restore. VV https://docs.aws.amazon.com/prescriptive-guidance/latest/best-practices-migration-cutover/cutover-stage.html
- **Donor CRMs do not reverse a migration after go-live.** Bloomerang corrects issues reported "within fourteen (14) days … after data is placed onto the testing server", "your exclusive remedy". Funraise: "An import is final." VV via q05-r2 (https://bloomerang.com/tac ; https://university.funraise.org/lesson/data-migration). HubSpot Smart Transfer can revert only what the transfer created (above). DonorPerfect's whole-database restore wipes everyone's later work. No donor or church CRM checked offers whole-migration reversal over live data (U beyond those checked).
- **Targeted correction beats full rollback after go-live.** Consultancy blogs say rolling back after weeks of live use is more disruptive than fixing forward, and that "partial rollbacks often create data consistency issues". S https://aptitude8.com/blog/migration-rollback-planning-hubspot ; https://resources.rework.com/vi/guides/data-migration/rollback-planning (attribution per claim not verified). Planning Center suggests bulk-editing to fix a mis-categorised donation import. S https://help.planningcenter.com/en/bulk-edit-donations.html

## 5. Privacy

- GDPR Art. 5(1)(c): "limited to what is necessary". Art. 5(1)(e): kept "for no longer than is necessary". Art. 17(1): erasure "without undue delay". The Art. 17(3)(b) and (e) exceptions cover a legal obligation and "legal claims". VV https://gdpr-info.eu/art-5-gdpr/ ; https://gdpr-info.eu/art-17-gdpr/
- ICO: where erased data survives in backups, the controller must put it "beyond use" (no operational use, overwritten on a schedule, disclosed). Its storage-limitation guidance is under review after the Data (Use and Access) Act. S https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/individual-rights/right-to-erasure/ ; https://complydog.com/blog/gdpr-delete-personal-data-from-backups
- Append-only stores conflict with erasure. Keep personal data outside the immutable log, or use per-subject crypto-shredding. VV (event-sourcing page above)
- **Before-images are personal data.** Vendors time-box undo data: HubSpot 14 days (restore history 90), Planning Center 48 hours or 2 weeks, Zoho 30 days, Notion 7–90 days, Airtable snapshots up to 3 years. Asym's 30 days sits mid-range (U: the reasoning is mine; windows from the VV sources above).

## Implications for Asym

**Adopt**

- **Plain verb at the entry point: "Undo import".** It is the most common label (Planning Center, LGL, Zoho, Mailchimp), and Microsoft's style guide permits "undo" as a verb. Show the deadline on the import page ("You can undo this import until 3 Dec 2026"), which satisfies G164 and WCAG 3.3.4 "reversible".
- **HubSpot-style preview between entry and action.** "Undo import" opens a review page, not a dialog. It shows counts: fields that will be restored, fields left alone because they were edited since (with who and when), people who will be archived, people kept because they were touched, and any money excluded. The final button names the result, e.g. "Restore 1,204 fields and archive 37 people" (NN/g, GOV.UK, Atlassian). "Prepare reversal" works as an internal step name but not as the user's button: HubSpot's "Prepare preview" is the only precedent, and it never appears alone.
- **Count-typed confirmation for large undos** (HubSpot) rather than a magic phrase. The undo itself should never live in a toast (WCAG 2.2.1).
- **Partial-result report as a persistent page plus CSV,** with before and after values and a reason per skipped row (HubSpot beta, SAP Fiori). Announce progress and completion as status messages (WCAG 4.1.3).
- **Refuse, don't warn.** Merged people, people with gifts or later activity, and anything linked to money are excluded and reported (Neon, Givebutter, Planning Center Giving). Planning Center's warning-only merge hazard is the counter-example.
- **Keep money vocabulary separate.** "Reverse", "adjust", "refund" and "correction" belong to the Phase 15 money path (QuickBooks, Raiser's Edge, Bloomerang, Virtuous). Using "Reverse import" for people would suggest money moves. The glossary term "Import reversal" can stay internal.
- **v1 workbench scope (U, inference from vendor practice).** Give People imports (fields, custom-field values on people, created people) the full workbench: every vendor that has import undo has it for contacts. Money gets no workbench, only the owner correction path. For notes, files, custom-field definitions and website content, v1 can rely on owner tools plus an "everything created by import X" filter for targeted fixes (HubSpot's import records tab, Neon's selective delete, Notion and Airtable restore owned by the content tool).
- **Switch: make go-live an explicit point of no return,** with a named go/no-go decision-maker (AWS, Azure, Dynamics). Before go-live, the abort label should say what happens ("Cancel this switch: nothing imported becomes visible"). After go-live, offer only targeted, per-family correction (fix forward), never whole-switch reversal. No donor CRM offers that.

**Avoid**

- "Revert", "Roll back" and "Restore snapshot" in user-facing copy. They imply returning to an earlier state of everything (Airtable, DonorPerfect, AWS rollback), which Asym does not do, and the glossary already lists them under _Avoid_.
- Whole-database or point-in-time restore (DonorPerfect wipes coworkers' entries).
- Blind reversion of later edits (Planning Center People, LGL "changes … will be lost").
- Delete-only undo that silently leaves updated values (Mailchimp, Zoho, Salesforce) without saying so.
- Hard deletion of created people (Bloomerang, Givebutter, Planning Center). Archive them instead, as decided.
- Unstated or open-ended windows (Mailchimp's "at any time"). They clash with storage limitation and with the 30-day deletion of before-images.
