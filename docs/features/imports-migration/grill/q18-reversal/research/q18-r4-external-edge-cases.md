# Q18 r4: Edge cases and modern practice for import reversal (external)

_Scope: edge cases and modern practice for Option B ("Prepare reversal" review page with three groups, a final button that names the result, a downloadable results list, People-only reversal by Asym within 30 days). Covers stale previews, long-running jobs, concurrency, what "touched" means, list and opt-out removal, archive versus delete, wrong-file imports, approval, deadline display, and naming. Builds on `q18-r2-external-reversal.md` and does not repeat it. Research agent, web only, accessed 2026-11-03._

Labels: **VV** = page fetched and quote checked · **S** = secondary (search summary of a page that refused fetching, community post, third-party guide) · **U** = unverified or my inference.

**Blocked (403):** developer.salesforce.com (Bulk API pages), ico.org.uk and cy.ico.org.uk, discuss.hashicorp.com. The EDPB breach PDF could not be parsed. Claims from these sources are labelled S.

## 1. Stale plans: prepare, then apply

- **Terraform refuses the whole plan.** A saved plan fails with "Saved plan is stale … the state was changed by another operation after the plan was created." S (error text as quoted in a user issue: https://github.com/Azure/caf-terraform-landingzones/issues/433). The fix is a fresh plan; "Terraform refuses to apply an outdated plan." S https://buddy.works/docs/terraform/troubleshooting . One CI guide recommends this: if the saved plan is stale, "run a fresh plan and stop for review instead of applying unreviewed changes". S https://oneuptime.com/blog/post/2026-02-23-how-to-implement-plan-and-apply-stages-in-cicd-for-terraform/markdown
- **HubSpot keeps a prepared restore for 14 days and documents no recheck.** A prepared restore "remains visible for you to action for up to 14 days". The preview shows the "current and last known property value". The article does not say what happens if values change between preview and Restore. VV https://knowledge.hubspot.com/object-settings/restore-crm-changes . For workflow restores, HubSpot says to "turn off your workflow before restoring" to stop further changes, and warns that a restore reverts all eligible updates, "including changes you may want to keep". VV https://knowledge.hubspot.com/workflows/restore-workflow-crm-property-changes
- **Compare-and-set is the web standard for lost updates.** If-Match "can check if the modification … will not override another change that has been done since the original resource was fetched". On a mismatch the server returns "412 Precondition Failed". VV https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-Match
- **GitHub reverts can conflict.** "You may need to revert individual commits if reverting the pull request causes merge conflicts". The revert is a new PR, not an erasure. VV https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/incorporating-changes-from-a-pull-request/reverting-a-pull-request
- **Database undo assumes nothing moved.** Flyway: "Undo migrations assume the whole migration succeeded and should now be undone". They "work for undoing schema changes but not so well for undoing data changes". VV https://documentation.red-gate.com/fd/undo-migrations-273973334.html
- **Simplest robust pattern (U, synthesis).** Treat the preview as advisory. At apply time, re-check every row with compare-and-set (does the current value still equal the imported value, and is the person still untouched?). Report rows that drifted as "Changed after you prepared this". Also give the prepared reversal a short life and a fingerprint, for example the tenant's latest change sequence over the affected people. If the fingerprint moved, show the updated counts again before applying, so the button text and any typed count stay true. This combines Terraform's "don't apply unreviewed changes" with If-Match's per-row safety, and avoids HubSpot's undocumented 14-day gap.

## 2. Long-running bulk jobs

- **Cancel stops new work; it does not roll back.** Salesforce Bulk API: "When a job is aborted, no more records are processed. If changes to data have already been committed, they aren't rolled back". Its outcome states are JobComplete, Failed and Aborted. Only the job creator or a user with "Manage Data Integrations" can abort. S https://developer.salesforce.com/docs/platform/api-asynch/guide/bulk-api-2-job-states.md (403; text via search)
- **Shopify adds an intermediate CANCELING state.** Statuses are CREATED, RUNNING, CANCELING, CANCELED, COMPLETED, FAILED and EXPIRED. Cancel "Starts the cancelation process"; "There may be a short delay … until the operation is actually canceled." VV https://shopify.dev/docs/api/admin-graphql/latest/enums/BulkOperationStatus ; https://shopify.dev/docs/api/admin-graphql/latest/mutations/bulkOperationCancel
- **Concurrency is capped per shop.** Shopify: "each app can run up to five bulk mutation operations per shop simultaneously" (2026-01 and later). Earlier versions allow one operation of each type. A `bulk_operations/finish` webhook fires on complete, fail or cancel, but "Webhook delivery isn't always guaranteed", so status polling stays. Partial output is kept at `partialDataUrl`. VV https://shopify.dev/docs/api/usage/bulk-operations/imports
- **One run per group.** GitHub Actions concurrency: "at most one running job or workflow in a concurrency group at any time". By default, pending duplicates are cancelled. VV https://docs.github.com/en/actions/using-jobs/using-concurrency
- **Completion notice.** HubSpot sends an email or in-app notification when a workflow restore finishes. VV (workflow restore page above). HubSpot import completion emails have been reported as "a little misleading". S https://community.hubspot.com/t/list-upload-notifications/78783
- **Let people leave the page.** Cloudscape, for operations over 10 seconds: "Allow the user to perform other tasks (such as navigate to other pages) while the operation is in progress", and give "feedback indicating when the operation is expected to be complete." VV https://cloudscape.design/patterns/general/user-feedback/ . NN/g: use percent-done for processes of "10 or more seconds", "Don't try to be exact", and "give users the option to stop the process". VV https://www.nngroup.com/articles/progress-indicators/
- **Accessibility.** WCAG 4.1.3 example: "An application displays a dynamic progress bar"; announcements are "intermittent". Techniques ARIA25 and ARIA27. The page cautions against noisy live regions: "User testing should be carried out to ensure the appropriate level of feedback is achieved." VV https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html
- **Implication (U).** Run the reversal as a server-side job that the user can leave. The import page shows a persistent status, and a notification fires on finish. The job is idempotent and resumable per row, so a retry after a crash skips rows already done. "Stop" means "stop after the current batch", and the results list shows exactly which rows were already reversed. "Cancel" must never imply a rollback.

## 3. Concurrency between imports

- **Reverse order is the common rule.** Little Green Light: "the most recently imported file (completed import) can be undone", then the next, and so on. Its alternative for older imports is bulk editing. VV https://help.littlegreenlight.com/article/677-delete-an-import-from-the-flex-importer . DonorSnap (nonprofit CRM): "Reversing must be done in the backwards order of the import"; "Any manual changes made after that import would be lost". VV https://donorsnap.com/support/docs/excelimport-loadeddatalisting/
- **No vendor found protects a newer import's value when an older import is reversed.** They avoid the problem either by forcing order (LGL, DonorSnap) or by ignoring updates entirely (Zoho, Mailchimp, Pipeline CRM: "Only newly created records can be deleted this way"). VV https://help.pipelinecrm.com/article/undo-an-import . Asym's "restore only if it still holds the imported value" rule handles this per field, without forcing order (U).
- **Pause conflicting writers.** HubSpot says to turn the workflow off before restoring (§1). Terraform's state lock exists to stop concurrent applies. S (buddy.works above).
- **Redo.** Planning Center: "Undoing an import is permanent and cannot be reversed." VV https://help.planningcenter.com/en/138558-import-a-csv-file-in-people.html . HubSpot's import API has a terminal REVERTED status. S https://developers.hubspot.com/docs/api-reference/latest/crm/imports/cancel-import.md . No vendor found offers "redo"; the path is to re-import the file (U).
- **Created people later used as match targets.** No vendor documentation was found (U). By Asym's own rule, a later import updating the person is a "touch", so the person stays and is listed as "Updated by import #N".
- **Undo cascades.** DonorSnap: if created contacts have donations or interactions, "those records will be deleted since the Contact will no longer exist." VV (DonorSnap above). Zoho: merged duplicates are "completely deleted … and cannot be retrieved". S https://help.zoho.com/portal/en/kb/crm-help-old/troubleshooting/articles/old-troubleshooting-recycle-bin-audit-log

## 4. What "touched" means in practice

| Vendor                   | What blocks deleting a created record                                                                                    | Source                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| Planning Center Giving   | "additional activity outside of Giving since the import took place". Not defined anywhere                                | VV https://help.planningcenter.com/en/154395-import-donation-history.html |
| Planning Center People   | Nothing is blocked. Only a warning not to undo after merges                                                              | VV (People import page above)                                             |
| Neon CRM                 | Later donations, registrations, memberships, households or relationships                                                 | S (q18-r2)                                                                |
| Givebutter               | Online transactions: card, ACH, Venmo. "Contacts without any transactions, or only offline transactions, can be deleted" | VV https://help.givebutter.com/en/articles/5497872-how-to-import-contacts |
| LGL, DonorSnap, Pipeline | Nothing; later edits are discarded                                                                                       | VV (above)                                                                |

- **Activity fields in other CRMs.** HubSpot's "Last activity date" covers a "note, call, tracked and logged sales email, meeting" plus "completed tasks". "Last engagement date" covers "one-to-one email opens and clicks, lead revisit notifications, meeting bookings" and "form submissions". "Last modified date" covers "any property … updated". None covers record views. VV https://knowledge.hubspot.com/properties/hubspots-default-contact-properties . Salesforce LastActivityDate comes from completed tasks and events, not views. S https://www.salesforceben.com/why-your-salesforce-contacts-last-activity-date-is-lying-to-you-and-how-to-fix-it/
- **Implication (U).** Define "touched" as any write or durable event by an actor other than this import. That includes field edits, staff-added tags or lists, notes, tasks, gifts, pledges, receipts, consent changes, merges, another import's update, donor-portal sign-in or account creation, and any message sent to the person. Views and searches are excluded. Email opens and clicks follow a send, which already counts. Publish the list in the "Stays as it is" reason text.

## 5. Removing list memberships and tags

- **Klaviyo: removing from a list leaves consent alone.** "It removes profiles only from the selected list and does not change their email suppression or unsubscribe status." Suppressed profiles "cannot receive email marketing". VV https://help.klaviyo.com/hc/en-us/articles/115005077307-How-to-remove-suppressed-profiles-from-a-list
- **HubSpot: deleting a contact can lose the opt-out.** After a restorable delete, re-creating the contact restores "subscriptions, unsubscribes". After a permanent delete, "Subscription preferences, including unsubscribes, aren't restored". "List membership is deleted" in both cases. VV https://knowledge.hubspot.com/privacy-and-consent/understand-restorable-and-permanent-contact-deletions
- **Mailchimp:** "if someone unsubscribed from your emails before you archived them, you can't import them as subscribed." VV https://mailchimp.com/help/archive-unarchive-contacts/ . Its undo page says nothing on tags, groups or unsubscribes. VV https://mailchimp.com/help/undo-contact-import/
- **Regulators back suppression over deletion.** ICO: put objectors on a suppression list "instead of deleting them", "retaining just enough information" to respect the objection. Keeping that list "isn't for direct marketing purposes". S https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/direct-marketing-guidance/respect-peoples-preferences (403). FTC CAN-SPAM: "You must honor a recipient's opt-out request within 10 business days." VV https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business
- **Implication.** Removing an import-added membership must only remove membership, never change consent. An opt-out, suppression or restriction is never removed, including one the import itself recorded (Option B already says so). If a list membership or tag drives sending (for example a "Monthly newsletter" list), the review page should say that removing it stops those sends (U).

## 6. Archive or delete for wrongly created contacts

- **Restore windows.** HubSpot: restorable "up to 90 days", then permanently deleted. Deleted contacts drop out of contact-report counts and "will not be re-enrolled in workflows". VV (HubSpot deletions page above). Salesforce Recycle Bin: 15 days. Mass Delete needs "Modify All Data" and handles 250 records at a time. S https://resources.docs.salesforce.com/204/latest/en-us/sfdc/pdf/salesforce_massdelete_undoimport.pdf ; https://www.owndata.com/blog/how-long-is-deleted-data-stored-in-salesforce . Zoho: 60 days. S https://help.zoho.com/portal/en/kb/crm-v2-1/manage-crm-data/recycle-bin/articles/crm-v2-recycle-bin
- **Mailchimp archive semantics.** "Archived contacts don't count toward your billing tier". They cannot receive "marketing emails or texts". Their data stays in reports. And: "archiving is not a legal substitute for deletion". VV https://mailchimp.com/help/archive-unarchive-contacts/
- **GDPR.** Erasure is owed when data are "no longer necessary" (Art. 17(1)(a)) or "have been unlawfully processed" (17(1)(d)). VV https://gdpr-info.eu/art-17-gdpr/ . A person imported from the wrong file has no purpose or lawful basis in this tenant, so archiving alone leaves the duty open (U, inference).
- **Implication (U).** Archive is the right default for a mistaken but legitimate import, such as a bad mapping of real supporters. Archived people must be excluded from sends, lists, counts and billing, and shown in reports as archived. A wrong-file case needs a separate purge path (§7), with a defined retention before hard delete, in line with HubSpot's 90 days and Zoho's 60.

## 7. Wrong-tenant or wrong-file imports

- **Definition.** A personal data breach is "a breach of security leading to the accidental or unlawful destruction, loss, alteration, unauthorised disclosure of, or access to, personal data". VV https://gdpr-info.eu/art-4-gdpr/ . Commentary splits breaches into confidentiality, integrity and availability breaches. S https://guichet.public.lu/en/citoyens/support/glossaire/v/violation-donnees-personnelles.html . ICO-derived policies list "Sending personal data to an incorrect recipient" and "Alteration of personal data without permission" as examples. S https://coningsby.parish.lincolnshire.gov.uk/downloads/file/369/data-breach-policy
- **Clock and records.** Notify the authority "not later than 72 hours after having become aware of it", "unless the personal data breach is unlikely to result in a risk". A processor notifies the controller "without undue delay". "The controller shall document any personal data breaches" even when it does not notify. VV https://gdpr-info.eu/art-33-gdpr/
- **Who is who (U).** If org A's file lands in org B's tenant during a Switch run by Asym operators, Asym as processor must tell both controllers. If a staff member uploads the wrong file or sensitive columns, the tenant is the controller and needs an incident record.
- **Implication (U).** People reversal (archive, 30-day before-images) does not end exposure. The data stays readable to the wrong tenant's admins, and the before-images are themselves copies. Wrong-file or wrong-tenant cases need an operator-run purge: hard-delete the people, values and stored source file, and purge the before-images early. Keep an incident record of counts, time, who and actions, without the personal data. Put the 72-hour clock in the runbook. This is incident handling, not a "Prepare reversal" outcome.

## 8. Approval and confirmation for large reversals

| Tool                   | Gate                                                                                                                                                                                | Source                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| HubSpot Restore        | Super Admin only; type "the displayed number"                                                                                                                                       | VV (restore page above)                                                                                   |
| HubSpot bulk delete    | Separate "Bulk delete" permission                                                                                                                                                   | S https://knowledge.hubspot.com/user-management/hubspot-user-permissions-guide                            |
| Salesforce Mass Delete | "Modify All Data"; 250 per pass                                                                                                                                                     | S (above)                                                                                                 |
| Planning Center People | Type "Undo import"                                                                                                                                                                  | VV (above)                                                                                                |
| GitHub repo delete     | Admin; "type the name of the repository"                                                                                                                                            | VV https://docs.github.com/en/repositories/creating-and-managing-repositories/deleting-a-repository       |
| Google Workspace       | Multi-party approval: "one admin must approve certain sensitive actions initiated by another"; needs two or more super admins; aims to prevent "unauthorized or accidental changes" | VV https://workspaceupdates.googleblog.com/2024/04/multi-party-approvals-for-sensitive-admin-actions.html |

- **NN/g on typed confirmation.** Generic confirmations become automatic and "provide no protection at all"; "if you warn people too much, they stop paying attention". "For particularly dangerous operations, require a nonstandard action", but "reserved for the most dangerous and rare actions". VV https://www.nngroup.com/articles/confirmation-dialog/
- **Research.** "Attractors" that force attention to the key field (such as typing a value shown in the dialog) made participants two to three times more likely to decide in an informed way. Some attractors resisted habituation. S https://microsoft.com/en-us/research/wp-content/uploads/2016/02/a6_Bravo-Lillo.pdf ; https://www.usenix.org/conference/soups2014/proceedings/presentation/bravo-lillo
- **No evidence was found comparing a typed count with a typed phrase (U).** A typed count (HubSpot) does make the user read the number, which an attractor needs. A fixed phrase ("Undo import", "UNDO") does not. Second-person approval appears only for security settings (Google), not for CRM undo.

## 9. Showing the deadline and time zone

- **GOV.UK:** "4 June 2017", "5:30pm", "midday (not 12 noon …)". "Midnight is the first minute of the day, not the last." "when mentioning a deadline, use 'on or before'". VV https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/style-guides/a-to-z-style-guide/
- **Microsoft:** time zones "Don't abbreviate unless space is severely limited. If you must abbreviate, use ET, CT, MT, and PT". "Don't specify standard time or daylight saving time unless" it matters. Times always include AM and PM. VV https://learn.microsoft.com/en-us/style-guide/a-z-word-list-term-collections/term-collections/date-time-terms . Google: "Don't abbreviate the name of the time zone"; spell it out with a UTC label. VV https://developers.google.com/style/dates-times
- **Absolute or relative.** GitLab Pajamas: default to absolute, and use it whenever users need dates "for technical, security, or legal reasons"; any relative label gets the absolute time in a tooltip; add the time zone where it matters. VV https://design.gitlab.com/content/date-and-time . Nord: don't rely on relative text alone when the exact time matters. S https://nordhealth.design/components/timestamp
- **Reminders.** Dropbox sends an event email after bulk deletes ("you can still restore them until" a date). S https://www.dropboxforum.com/discussions/101001013/why-did-i-get-an-email-about-deleted-files/385785 . SaaS trial practice is a reminder about 7 days before expiry that names the date. S https://userlist.com/blog/trial-expiration-emails-saas/ . No CRM was found that sends an undo-deadline reminder (U).
- **Implication (U).** Write "You can reverse this import until 3 December 2026, 5:00 PM Eastern Time", using the tenant's time zone, and add "(in 30 days)" as a secondary hint. "EST" is wrong whenever daylight saving time applies, and the 30-day window can cross a DST change (US clocks changed 1 November 2026). Avoid midnight deadlines. Store the time in UTC and render it locally. Optionally notify the importer once, about 7 days before the window closes.

## 10. Naming

- **"Reverse" for imports exists in nonprofit CRMs.** DonorSnap writes "Reversing must be done in the backwards order of the import" (VV above). Knack titles its page "Can I undo or reverse an import?" VV https://docs.knack.com/v3/docs/can-i-undo-or-reverse-an-import . The button labels everywhere are still "Undo" or "Undo import".
- **"Reverse" is money vocabulary in giving products.** Virtuous: a reversing transaction is "a new reversing transaction" that will "negate the amount and splits applied". VV https://docs.virtuous.org/api-reference/gift/create-reversing-transaction.md . Raiser's Edge NXT: "Reverse or Unpost Gifts". S https://community.blackbaud.com/discussion/comment/310670 . Stripe: "platforms can reverse transfers"; transfer reversals "subtract from the destination account's balance". VV https://docs.stripe.com/api/transfer_reversals . Nacha ACH: a Reversal corrects an "Erroneous Entry" (a "duplicate entry, incorrect receiver, incorrect dollar amount") within "5 banking days". VV https://www.nacha.org/rules/reversals-and-enforcement . So "reverse a wrong file" already has a meaning in payments: moving money back.
- **Comprehension.** No controlled study compares undo, revert and reverse (U). Practitioner threads say "revert" reads as developer jargon, and that "undo" can sound as if changes vanish from history. S https://forum.syncthing.net/t/override-or-delete-local-changes-not-revert-local-changes/25786 ; https://pmichaud.com/pipermail/pmwiki-users/2005-February/009992.html

## Implications for the review

**Adopt**

- Re-validate each row at apply time with compare-and-set, and give the prepared reversal a short life plus a fingerprint. If anything moved, re-show the counts before the final button so its text, and any typed count, stay true (§1).
- Run the reversal as a resumable server-side job, one per tenant. Block new imports touching People while it runs, and block reversal while an import runs. The user can leave the page, gets a notification on finish, and sees progress through polite status messages (§2).
- Give "Stop" honest wording, e.g. "Stop after this batch. Rows already reversed stay reversed." List them in the results file (§2).
- Allow reversal in any order, relying on the per-field "still holds the imported value" rule. Show "Changed by a later import (#N)" as an explicit reason (§3).
- Publish the definition of "touched", covering writes, messages, gifts, consent, merges, portal sign-in and later imports, and excluding views (§4).
- Removing a membership never changes consent. Opt-outs and suppressions always stay, and the review page says when removing a list stops sends (§5).
- Write the deadline as an absolute date, time and named zone, with relative text secondary. Optionally send one reminder about 7 days before the window closes (§9).
- Name the result in the final button. Use a typed count only above a threshold, and require an admin-level permission for People reversal over that threshold (§8).

**Avoid**

- Applying a stale preview blindly (HubSpot's 14-day prepared restore with no documented recheck) (§1).
- Calling Stop "Cancel" or implying rollback (Salesforce and Shopify both leave processed rows applied) (§2).
- Forcing reverse order (LGL, DonorSnap). It blocks fixing an older bad import whenever a good one followed (§3).
- Using "reverse" or "reversal" on any button near giving data. Stripe, Virtuous, RE NXT and Nacha use it for moving money (§10).
- Treating archive as the answer to wrong-file or wrong-tenant imports. Mailchimp says "archiving is not a legal substitute for deletion" (§6, §7).
- Hard-deleting people in a way that loses an opt-out, as HubSpot's permanent delete does (§5).

**Open**

- Should a wrong-file or wrong-tenant purge be a separate operator incident flow, with a 72-hour clock, early purge of before-images and the source file, and an incident record? It is not covered by "Prepare reversal" (§7).
- Expiry edge: what happens to a reversal prepared or running when the 30-day window or the before-image deletion job arrives? Proposal: honour jobs accepted before the deadline, and stop the purge job from racing a running reversal (§1, §9).
- Is redo needed, or is "import the file again" enough? No vendor offers redo (§3).
- Threshold and approver for large reversals. Google-style second approval exists only for security settings, and there is no CRM precedent (§8).
- Do archived people count toward plan limits, appear in reports, or still receive receipts and transactional mail? Mailchimp's answer is no billing, no marketing, and data kept in reports (§6).
- Is "Prepare reversal" the right label, or "Undo import" with the review page? This conflicts with r2's recommendation and with §10's money-word collision.
