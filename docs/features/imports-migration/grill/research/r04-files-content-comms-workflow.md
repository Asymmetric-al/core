### 1.3 What Phase 29 decides about private import inputs and parser derivatives

- **Ownership split:** shared custody "owns immutable bytes, intake, technical safety and processing, copies, source-authorized delivery, access evidence and authorized physical disposition. Each consuming source owns document meaning, currentness, acceptance, audience, purpose and records obligations" (`custody-and-integration.md:5`). "Ordinary request behavior does not replace ... import ... authority" (`:3`). Import is a separate source owner in `PR2430:.../proof.md:13`.
- **No effect from bytes alone:** "Uploading, renaming, linking, previewing, restoring or moving bytes does not ... import rows ... unless the independently authorized owning command explicitly performs that effect" (`proof.md:16`, AC29-P01-02).
- **Every door includes import paths:** "Views/materializations, REST/GraphQL/RPC, Storage, **import/worker/operator paths** and legacy scripts cannot bypass the same restrictions" (`proof.md:46`, AC29-P03-03). Design repeats it (`PR2430:openspec/changes/add-files-documents/design.md:101`).
- **Per-profile admission:** each profile names "source owner/version, permitted actors/actions, actual formats/limits, original-fidelity or discard rule, processors/egress, current delivery rule, copies and records obligations" (`custody-and-integration.md:30`, AC29-D02-02). Client name/MIME/classification/Tenant/digest/completion flags are untrusted (REQ29-D03, `:37`).
- **Immutable versions / receipt:** finalization establishes exact object/generation identity, byte length/type and cryptographic integrity before source admission; "Browser success, upload callback, object listing, file signature or scan result alone cannot finalize the source contribution" (REQ29-D04, `:49-55`). "Digest equality cannot merge those facts or establish authenticity, consent" (AC29-D01-02, `:16`); "no bytes-only permanent business deduplication is introduced" (AC29-D04-02). **Implication:** Phase 30 binding the plan "to exact source bytes" (`roadmap.md:4349`) is compatible, but "same bytes = same import" is a P30-owned semantic rule that custody will not supply.
- **Derivatives:** "Every rendition or derived output shall bind immutable source/input identities and digests ... profile/processor build, options, current restrictions, coverage and output integrity ... conversion ... creates a distinct output" (REQ29-D06, `:80`). "Extraction/OCR/AI use requires its own source/egress/coverage/retention qualification. Embedded instructions are data, not authority" (AC29-D06-06, `:91`). A parsed staging set built from an import file is a derivative that needs its own declared custody profile.
- **Malware / hostile content:** intake validates content against the versioned profile and bounds bytes, entries, nesting, XML, sheets/cells, memory, CPU, wall time (REQ29-D05, `:66`). "**Parsers run with minimum privileges, no ambient credentials and no unapproved network fetch or private-file submission to public malware services.** Candidate engines, dependencies, licenses, isolation and processing location require current qualification" (AC29-D05-02, `:73`). "Observing a clean scan cannot certify authenticity, signature validity, financial acceptance or public rights" (AC29-D05-05). Hostile tests go "beyond extension/browser MIME, including archive bombs ... scripts/macros" (AC29-D05-01). XLSX: "A missing saved spreadsheet value is unavailable rather than zero; readers do not execute macros, refresh external data, recalculate" (REQ29-P12, `proof.md:173`).
- **Size/type limits:** Phase 29 deliberately does **not** set an import upload limit. "Actual finite transfer/session/resume/grant and cleanup bounds are qualified per profile" (AC29-D03-05, `:47`). "Before each profile activates, publish finite measured units ... **Unknown limits block that profile; vendor or avatar limits are not ordinary defaults**" (AC29-D23-01, `:400`). The only concrete CSV/XLSX numbers are **D32 preview-only** limits (20 MiB original, 50 sheets, 100,000 populated cells, 100,000 CSV cells, 1,000,000 Unicode scalars), explicitly "not ordinary upload defaults" (AC29-D07-03, `:103`). Preview creates no "CRM file copy" or new retention purpose (AC29-D07-08).
- **Retention/disposal:** custody "shall consume actual versioned source obligations ... No universal number of years, read-reset clock, global hold boolean or unconditional retain-forever fallback" (REQ29-D12, `:172`). "Derived previews, optional packages, temporary candidates, originals ... follow their actual class rules" (AC29-D12-05). Disposal is separate and fenced (REQ29-D13/D14). #2368: "Phase 29 executes the owning domain's retention decisions and doesn't set its own retention period." **P30 or the target owner must supply the retention class for import source files and staging derivatives.**
- **Legacy file migration (REQ29-D17)** census explicitly includes "import ... paths actually reached" (AC29-D17-01, `:250`) and forbids "destructive reset, guessed backfill, new fake provenance or Twenty resurrection" (AC29-D17-03). Design repeats it (`design.md:107`).
- **Export versus import:** "P30 inbound differs from optional P31 destination" (`PR2430:.../owner-reconciliation.md:21`, R-EXPORT).
- **OpenSpec tasks (all unchecked):** 9.10 "Qualify E10 — Financial/backfill/import evidence"; 9.19 "Qualify E19 — Missionary self-import/CSV" (deps 2.2, 2.3, 1.1); 10.1 "Qualify F30 — migration imports and target admission when its source lane is reached", deps "1.1, 1.2, 1.3, 2.2, 2.6, 7.1 and this exact source gate; no unrelated future consumer is a dependency" (`PR2430:openspec/changes/add-files-documents/tasks.md:397,451,481-485`). ### 2.3 Rules Phase 30 must honor for CMS content (ADR-0173 clauses)

- **Never through the Payload plugin as product:** "Payload's exact-pin plugin may provide qualified parsing/serialization mechanics behind an adapter, but its generated collection UI, routes, default limits, match-field choices, status defaults, Jobs Queue, and partial-write result are not product authority" (clause 4, `:56-63`). Context: "the exact Core-pin Payload implementation processes rows and locale updates partially, while its generic version fallback may be published" (`:11-13`).
- **Private quarantine before parsing** with file-count, compressed/decompressed size, entry, nesting, row/node, field, string, relation, image budgets; "rejects traversal and ambiguous/polyglot content; scans applicable bytes; never executes macros, HTML, JavaScript, templates, or archive contents" (clause 13, `:134-143`).
- **Remote media retrieval** only qualified HTTPS, blocks private/link-local/metadata networks, "moves the result into Phase 29 intake" (clause 14, `:144-152`); media "never makes media publicly eligible" from source URL, upload, checksum or download (clause 9, `:101-108`).
- **No destructive guessing:** "External content never updates by title, slug, email, path, position, or fuzzy resemblance" (clause 15, `:159-160`); "Only a package carrying an exact, authorized Asym identity and lineage can propose an update; otherwise possible duplicates are review information and the safe default is a new private identity ... never blind upsert" (clause 22, `:224-228`). **Contrast:** owner-constraints Phase 30 lets the general importer "auto-merge high band only" for identity (`owner-constraints.md:366-372`); for CMS content, no fuzzy/high-band update is allowed.
- **Semantic idempotency key** "derived from Tenant/Site, source system/snapshot, artifact digest, plan digest, target adapter version, and intended command—not from an ephemeral provider event ID" (clause 22, `:220-224`).
- **No-write check is real:** "Payload preview, sample rows, client validation, or a transaction that is intentionally rolled back is not this contract" (clause 17, `:177-180`). Four issue classes: "Must fix before creating drafts", "Needs review before release", "Will not be imported", "Information"; "no ... green completed with warnings state" (clause 18).
- **Commit is separate and outward-effect-dark:** "Import never publishes, activates D1, changes a serving head, activates navigation/redirects/schedules/forms, creates users, sends messages, fires ordinary automations, updates public search, or emits public media. Batch-origin suppression prevents side-effect fan-out while required audit/outbox facts remain durable" (clause 21, `:215-219`). "Source authors never become users automatically" (clause 16, `:169-170`).
- **Two-pass closure**, per-item atomicity, resumable run (clause 23); locale outcomes exact with no default-locale guessing (clause 24); "Only one committing content-portability run may own a Site write cohort at a time" (clause 25).
- **Reversal is a checked plan, not undo theatre**; edited/referenced/scheduled/released facts block automatic reversal (clause 29, `:282-290`).
- **Certified sources only:** "Other CMS or custom site always exists as a request/approved-sample lane, not a claim of universal compatibility ... Unknown versions, custom plugins, or changed exports pause for qualification" (clause 11, `:118-125`).
- **Spreadsheet export is non-reimportable:** "Review in a spreadsheet creates a readable governed CSV that is explicitly non-reimportable" (clause 5, `:64-66`). CSV uses shared `csvSafeCell`, UTF-8 BOM, RFC 4180, CRLF (clause 7, `:85-87`), which exists in `packages/lib/csv.ts`.

## 7. Discrepancies and tensions

1. **Who holds parsed staging rows.** ADR-0173 clause 26: staged content bodies "stay in Phase 30 private staging/custody" (`ADR-0173:261-262`); ADR-0173 clause 2 lists "staged rows" under Phase 30. Phase 29 F30 and #2368: "private input/derivative custody" and "parser derivatives under #2368 custody" (P29). Phase 28 REQ28-R26 puts "staging, previews, error files" under "private P29 purpose-bound custody" (`relationships.md:495`). Undecided whether structured staged rows in Postgres are a P29 custody derivative (with P29 hold/disposal/restore) or P30-owned database state. _Handling:_ decide explicitly in the Phase 30 grill; at minimum, whatever holds staged rows must honor the target purpose's classification, expiry and disposal.
2. **"Undo" vocabulary.** Owner constraints: "time-boxed batch undo with before-image capture" (`owner-constraints.md:378-385`). Roadmap: "Do not promise universal time-window undo" (`roadmap.md:4395`). Phase 29 F30: "irreversible target effects need source successors, not generic Undo" (`PR2430:.../custody-and-integration.md:368`). ADR-0173 clause 29: "Reversal is a checked plan, not undo theatre". These are reconcilable (undo only while no downstream coverage exists), but the user-facing promise must be decided.
3. **Matching strictness differs by profile.** Owner constraints allow "auto-merge high band only" across UI/API/bulk (`owner-constraints.md:366-372`); ADR-0173 forbids content updates "by title, slug, email, path, position, or fuzzy resemblance" (clause 15); Phase 28 D17 forbids auto-merge (`owner-constraints.md:347-352`); Phase 44 forbids email merges. _Handling:_ the importer's dedupe step must be target-owned, never a single global confidence policy.
4. **Signed URLs versus bearer prohibition.** Owner constraints Phase 29 (still at PR head): "signed, expiring access URLs" and "private docs signed-URL only" (`owner-constraints.md:174,186`). Phase 29 spec: strict private purposes "forbid reusable provider bearer URLs" (`PR2430:.../custody-and-integration.md:116`, REQ29-D08). ADR-0173 clause 10 allows a short-lived transport URL "only after that check". The later, ratified Phase 29 spec controls; import source files are strict private.
5. **Malware scanning.** Phase 29 and REQ28-R26 require "quarantine/scan controls"; the #2083 implementation departure accepts structural-only validation without a malware scanner. That departure is not owner-ratified and appears nowhere in the Phase 29 spec.
6. **Plugin adapter versus installed reality.** ADR-0173 clause 4 contemplates "Payload's exact-pin plugin ... behind an adapter". `@payloadcms/plugin-import-export` is published at `4.0.0-beta.3` on npm (`npm view`, 2026-10-31, dist-tags `latest` 3.92.1, `beta` 4.0.0-beta.6) but is not installed or configured; the repository copy is a vendored v3.77.0 historical mirror.
7. **Issue #2429 says PR #2430 is a draft; `gh pr view` reports `isDraft=false`.** Cosmetic.
8. **"Exact reimport" versus bytes-only dedupe.** Phase 30 requires exact reimport convergence (`roadmap.md:4363,4401`); Phase 29 forbids "bytes-only permanent business deduplication" (AC29-D04-02); REQ28-R21 says "file hash ... alone is never person identity". Not a contradiction, but a digest can only short-circuit recovery of the same run, not establish identity.
9. **Suppression keyed by email.** Phase 6 keeps `email_suppressions` as the single don't-contact source of truth (`phase-06-...md:250`), but the table is keyed by `(tenant_id, email, suppression_type)` with free-text `source`. No source says where imported phone/SMS opt-outs, postal do-not-mail, or Party-level do-not-contact from a legacy system land.
10. **Three "D17"s.** Phase 21 D17 (opening evidence), Phase 28 D17 (self-import), REQ29-D17 (file migration cutover). Easy to conflate in tickets.
11. **No Phase 41 owner constraints.** `owner-constraints.md` has no Phase 41 section, yet the roadmap routes application targets "use Phase 41" (`roadmap.md:4367`).
