## One control where reading happens

Place **Reading: Compact ▾** in the conversation reader utility header beside **Find**. On a narrow screen it remains a labelled control in the conversation header's utility row, not an unlabelled icon squeezed between destructive actions. Retain the existing Support shell/list/detail hierarchy; the label remains available in an empty reader pane so an authorized staff member can choose a default before opening a conversation. No tenant-settings detour, new profile-settings route or administration permission is required.

The menu is short and single level:

```text
Your Support reading default
Only for you in River Mission. Changes save automatically.

● Compact
  Fold repeated quoted history and signatures
○ Full
  Show complete message content

──────────────────────────────────────────────────
This conversation
Expand repeated content
```

River Mission is an illustrative tenant label, not production data. Show the real currently authorized tenant name. Compact remains the initial choice; it does not make type smaller or change folder/list density. The menu offers one permanent choice group and one clearly separated temporary action, not two competing sets of Compact/Full radios. Add **Use my default (Compact)** to the temporary group when overrides exist; show the actual confirmed default in parentheses. With no active conversation, temporary actions are absent; saving the personal default still works.

Use the existing shared Base UI DropdownMenu radio components. Exactly one effective mode exists; there is no nullable mode or Both state. A radio's proposed/checked selection must be accompanied by accurate Saving/confirmation/failure status, not called a saved value before acknowledgement. Unknown preference state is visibly distinct and cannot fabricate a confirmed saved checkmark. Underlying copy clearly distinguishes the current local choice from the last confirmed default where they differ.

## What Compact actually does

Each message keeps its author, audience/recipients, time, delivery state and attachment controls. Normal body text has the same Maia typography, spacing and line height as Full. Only whole regions meeting the conservative repetition contract fold. Use **Show quoted history** or **Show repeated signature**, with a small directional icon, descriptive accessible name tied to its message, and visible focus. Labels explain the region; they do not imply it is irrelevant, removed, private or safe to ignore.

The first unique closing/contact detail remains readable. An unmarked or uncertain signature stays visible. A changed link, image, number, table cell, emphasis or inline answer keeps the whole affected quote open. A quote-only or signature-only message must not become a blank-looking response: keep its content visible when it is the only substantive body region. Nested quotations are folded as the largest wholly eligible region rather than creating many nested controls. If a parent is changed/uncertain, leave that parent open; do not pursue inner word-level folds that make an inline answer hard to follow.

Do not hide current drafts, signatures in the composer, prepared/send review material, internal notes or work history. D33 does not change what the requester receives. Full in this feature refers to email-body reading, not raw transport source, source history restoration or a staff's unrestricted access to all linked records.

## Ordinary Compact journey

1. Maya enters Support in River Mission. A successful absent-preference read resolves to Compact without creating a row. If the preference is not yet known, the reader can start temporary Compact without blocking authorized messages.
2. She opens a conversation from the inbox. Normal content appears immediately; repeated eligible history has labelled disclosures. New inline content, first forwarded context and uncertain material remain visible.
3. She opens **Show quoted history**. It expands in place. Focus stays on the disclosure or intentionally navigates to the result, and no preference write occurs. She can open another region without closing the first.
4. She chooses **Expand repeated content** in the Reading menu. The reader policy becomes temporary Full for this conversation, shown as **Reading: Full · this conversation**. The saved-default radio remains Compact. Progressive loading continues; Full does not download the whole archive or its files.
5. She chooses **Use my default (Compact)** when finished. This clears temporary expansion rules for this conversation, except an active Find target/focused region that must remain reachable. Restoring Compact preserves the visible message anchor and does not move Send beneath the pointer.
6. She opens another conversation. The saved Compact default applies. Returning through the same qualified navigation session restores her earlier safe anchor/disclosures; a fresh visit/reload uses the saved default. No per-conversation expansion rows are stored.

An individual section expansion does not calculate or save a new global mode even if it happens to be the last collapsed section. The header mode describes the current default/temporary presentation rule. Only the conversation-wide temporary action sets **Full · this conversation**; this avoids a moving label based on how many regions have loaded.

## Choosing and saving Full

1. Maya opens **Reading: Compact** and selects **Full** in **Your Support reading default**. The visible copy makes the persistent effect explicit before selection. No second confirmation or Save dialog is added.
2. The current reader shows Full immediately and preserves draft/focus/message position. Display **Saving…** beside the utility control or in its status region; announce it politely without repeated spoken updates.
3. On confirmed success show **Default saved** quietly. The control is **Reading: Full**. Future Support conversations in this tenant and the same authorized Support reader through CRM use Full on other devices after normal preference retrieval.
4. Another staff member and Maya's other tenant remain unchanged. Existing open readers on other tabs/devices learn the changed default for their next entry; they do not abruptly collapse, expand or jump while someone reads.
5. Choosing Compact later is the reset. It is an explicit conditional Compact save that retains a revision fence, not a delete or reset-all-preferences command. Both choices remain available even when the current email has no foldable content; a small explanatory line can say that this message has no repeated sections, without disabling the personal setting.

Full displays all current safe body content through the same reader. It retains quotation indentation, links, alternative text and tables within qualified rendering, with safe overflow where inherently needed. It does not grant remote-image fetch, execute arbitrary HTML, recalculate attachments or expose raw email source. It does not automatically collapse old whole messages; source-window navigation is a separate existing control.

After an external conflict, stop automatic queued writes and ask for an explicit reapply of the current desired mode through the same small menu. This is ordinary conflict recovery, not a modal approval workflow.

## Search, CRM and attachment journeys

**Search:** Maya finds a phrase in an older quote. D22 loads the exact permitted original region, reveals it and highlights the match even beyond mounted history. Her saved Compact setting stays Compact. Clearing Find leaves the inspected region open; a later explicit reset can compact it when no active focus/match depends on it. No inaccessible match count or placeholder reveals hidden sources. Browser Find is supplementary, not a replacement for this journey.

**CRM:** she opens a linked conversation from an authorized Party record. The same reader resolves her current tenant/profile preference and keeps CRM return context. A Support link does not reveal restricted giving/member-care context. After inspecting the conversation she returns to the same CRM record/position. No second preference, interaction record, source copy or background CRM mutation exists.

**Attachment:** she deliberately previews a qualified D32 attachment and returns. Mode, open regions, source message anchor and draft are preserved while current access is rechecked. Full reading never eagerly opens files. A source restriction that occurs while the preview is open wins over restored reading state. Download original remains separate; this control does not attach a file to the reply.

**New arrival and merge:** a newly received message is readable under the current reader policy but does not steal focus or rewind scroll. Existing new-message behaviour remains; no new mark-read rule is introduced. Merge/Undo changes context and invalidates dependent repetition proofs without changing original content or personal preference. Original message IDs and current scope govern return anchors; if an anchor is no longer eligible, return to the nearest permitted stable context with an honest notice, not substituted text.

## Visual and accessibility discipline

Use a quiet, text-led utility control, not a theme/density dashboard. Keep body text the visual priority. Maia's existing compact utility variants may keep the header tidy; they must not shrink the email body. Use semantic background/foreground/muted/border/ring tokens and existing radius/spacing/type. Do not copy ReUI's icon rails, coloured tag assortment, 440px fixed list or v3 mail's Radix primitives merely to resemble the screenshot.

The shared menu must support arrow navigation, Enter/Space selection, Escape dismissal and predictable focus return, with programmatic grouping/check state. Disclosure controls expose aria-expanded and control the corresponding permitted region; collapsed descendants are not tabbable. Text descriptions wrap at 320 CSS px and 400% zoom; no page-wide two-dimensional scrolling is introduced. Essential touch controls have 44 CSS px targets and no hover dependency. Test screen reader announcements, RTL/LTR mixed quotations, Thai/CJK, long names, literal dates/timezones and large font settings. Opening history is immediate; do not animate height or auto-scroll long distances. Existing reduced-motion and Base UI motion tokens govern any menu animation.

No screenshot or primitive documentation establishes these outcomes. The [browser-reference review](phase26-d33-browser-reference-review.md) records what was actually observed. [P01–P36](phase26-d33-proof-and-operations.md) require actual qualified implementation and participant evidence. This is the complete proposed journey, not a promise that the current scaffold already behaves this way.
