## Recommended complete journey

1. **Ordinary answer:** Staff open an external Reply with its current From/To/Cc and exact source target visible. The body is empty apart from its separate governed signature/required framing. No history is appended, and no quotation setting is required.
2. **Discover:** Near the existing reply-target context, provide a quiet text-labelled **Quote message** action. It means the specifically identified message; avoid the ambiguous label Original, which could mean the earliest thread email. Each eligible external message also offers **Quote message** in its ordinary message actions. Both invoke the same insertion. No bulk history picker or multi-select is added.
3. **Choose less when useful:** A valid selection within one qualified source message may offer **Quote selection** as an accelerator. It uses an exact source revision/range, not screen DOM text as authority. Whole-message Quote remains fully operable without text selection; staff can trim the inserted quote. If precise selection mapping is not qualified, do not silently quote the whole message under a Quote selection action.
4. **Insert into existing work:** Use the stable remembered draft caret at a valid block boundary. With no valid remembered caret, insert at the end of the authored body before the managed signature. Never overwrite selected authored content, place source content inside the managed signature, split required framing or insert into another draft/mode. This is one ordinary undoable edit. After insertion place the caret in an ordinary paragraph after the block so the answer can continue outside quotation; preserve prior content and expose the inserted block for inspection without a full-screen transition.
5. **Review naturally:** Show the quote expanded when added. Use a restrained logical-side border, readable body type and a compact source line. The Source/Open message and Remove quote actions are reachable by keyboard and touch. No small grey italic wall of text, hover-only controls, nested card dashboard, permanent modal or automatic collapse. Source reading Compact/Full does not alter included bytes. If the user later chooses to collapse an inserted quote, label it as included and make every byte inspectable before Send; initial implementation need not add collapsing at all.
6. **Trim/edit in place:** The quote text is editable in the same composer; no second Edit quote dialog or editor. Source identity/attribution is the narrow locked semantic unit. Any meaning-bearing canonical alteration from the inserted excerpt, including trimming, ordered/list/table structure or link destination changes, displays **Edited excerpt from …** in both the composer and delivered HTML/plain text; only qualified presentation-only formatting is exempt. This deliberately conservative marker avoids a complex deletion-versus-rewriting classifier or a false verbatim attribution. If a source-selected excerpt is inserted unchanged, it is an excerpt, not a claim to contain the whole message. Do not silently say X wrote after rewriting X's words.
7. **Remove/undo:** Remove deletes that inserted block only, with ordinary local Undo and no confirmation modal. Undo uses current source authority; a restricted quote cannot reappear. Subsequent typing, another quote and preexisting files survive. An accidental double-click/replayed insertion action adds one block; a new deliberate insertion may quote the same source again. There is no one-quote cap beyond the governed complete-document budgets.
8. **Send:** The same visible complete canonical draft, including quote bodies and permitted source attribution, is validated and compiled by the existing path. No new quote confirmation on a routine valid send. Only an actual changed audience/source/permission, unsafe content or invalidated preparation requires targeted inline repair/review. Successful quotation insertion means only the draft changed; it is not delivery, a new conversation event or a completed CRM action.

This placement is a product judgment using D18's existing grammar. Always appending to a hidden footer is the strongest simpler placement alternative, but makes useful inline question-and-answer awkward and risks another history container. A generic freeform clipboard-only answer is less work to build but fails source lineage, reliable selection and a discoverable mobile journey.

## Exact proposed seam language

**ES01 — One canonical quotation.** A source-derived quote is copied once into the current canonical Reply document with a stable source identity, exact eligible source revision/excerpt and occurrence provenance qualified by Support. It is not a live source reference, provider template, raw HTML footer, duplicate conversation or newly published Saved Section. Ordinary source updates never silently rewrite a saved quote; actual source restriction/expiry still stops unsafe use.

**ES02 — Trust and transformations.** Source, tenant, actor, source attribution and eligibility are server-derived. Caller-provided text, HTML, source IDs, selected ranges and hidden attributes are not authority. Verify source resolution before acquisition and complete source/recipient eligibility before preparation/admission. Known source-bound editor cut/copy/unwrap/Undo transformations retain the affected dependency; explicit removal releases only dependencies proven no longer represented. Do not create document-wide permanent taint, a clipboard surveillance service or a similarity/secret classifier. Independent retyping or external clipboard provenance has the limits already stated in D16; the product does not promise perfect disclosure detection.

**ES03 — Honest editable attribution.** The inserted quote body supports ordinary editing within the qualified Reply profile. The source label cannot be edited into another sender/date. Compare meaning-bearing canonical content with the inserted qualified excerpt, including text/order, meaningful list/table structure and link destinations; these changes produce recipient-visible Edited excerpt attribution, while only qualified presentation-only formatting is exempt. The marker does not imply the source itself was edited. Undo back to the exact eligible semantic excerpt may clear the marker. This changes only the draft, never the source message or D35 note history.

**ES04 — Safe conversion.** Quote acquisition derives eligible semantic text/formatting/safe links from the authorized source, not arbitrary fetched remote HTML or a browser screenshot/DOM. Script/style/tracking/remote resource loads, recipient variables, protected action nodes, macros and mentions cannot execute. Literal brace tokens remain literal. Incoming nested quoted text actually included in the selected body remains visible for review; no recursive fetching of older messages. No heuristic removal of signatures or headers may silently change meaning. Where conversion must omit unsupported formatting/content, show the omission concisely and never claim the complete original was included. Unrepresentable meaningful content offers a safe qualified excerpt/normal answer path rather than a misleading success.

**ES05 — Assets are separate.** Quoting text never acquires, reattaches, republishes or refreshes an old file, inline image, signature logo or action link. Any actual included asset or destination requires its own admitted source/recipient/retention capability. Existing source signature/address text is not automatically a second managed signature and remains within complete-message disclosure review. Source-derived structured tokens are resolved to permitted inert content; they do not activate P17 variables or domain actions in the outgoing reply.

**ES06 — Context change.** Quoting an earlier message does not retarget the reply, widen recipients, restore removed Cc/Bcc, change inbox/assignee or update CRM. A deliberate reply-target/From/recipient change preserves the quote and authored work but invalidates affected audience/source approval and displays the actual affected excerpt/source for targeted review. D2's exact addressing model remains authoritative. An unavailable target/source never falls back to the newest email, current CRM address, forwarded private header or another tenant's cached body.

**ES07 — Ownership.** Support owns source qualification, draft/quote provenance, target/audience, current permissions and atomic reply admission. P17/Email Studio owns the shared canonical profile, complete message compilation, immutable presentation dependencies and exact preparation. P6 owns the sealed envelope, dispatch/reconciliation and provider facts. Quotation is human content use, not a new template publication/review workflow. P17 and the provider cannot append mutable history after staff approval or create an independent Support mailer.

**ES08 — Source fences and recovery.** D16/D17 restrictions and expiry apply to quote copies, drafts, prepared material, rendered caches, known descendants and replay. Keep unrelated safe authored work. If the affected contribution cannot be separated safely, stop affected preparation until clean review; never silently redact and send. Before dispatch admission requalify current authority. After may-have-submitted/accepted, preserve actual sealed evidence and reconcile without replacement/resend/rekey. Provider outages do not authorize a different payload or alternate sender.

**ES09 — Shared surfaces.** The same source and draft capability may be entered from an authorized CRM Support record. CRM navigation preserves draft/source/selection and return context, but CRM linkage does not grant Support or file disclosure rights. Requester, participant, authenticated staff, CRM contact/organization and source author remain distinct; matching email is not permission. Internal notes, guidance, member-care/giving data and merged-view neighbors do not become eligible quote sources automatically.

**ES10 — Scope and maintainability.** Qualify only the necessary Reply blockquote/source metadata in the existing code-owned shared schema and purpose validation. Do not widen signature, reusable-wording, public guidance or internal-note profiles merely because Reply supports it. No second editor, general document provenance platform, source-history synchronization, AI rewriting, history default preference or tenant quote-policy builder is introduced.

## Release proof required at the existing seams

No runtime proof below was executed by this review. These are falsifiable acceptance outcomes to carry into the authorized implementation stage, not claims of current safety.

1. Empty new Reply produces no prior history; quoted source adds only after deliberate action. Signature/footer remain exactly once and correctly positioned.
2. Message/selection actions insert at the expected boundary without deleting selected authored text. Touch/keyboard fallback works without text selection. Ordinary Undo removes only this insertion.
3. One delayed acquisition arriving after draft/mode/tenant change changes nothing; a concurrent local edit preserves text and resolves a stale insertion bookmark deliberately.
4. Duplicate delivery of the same insertion action adds once; a separate later deliberate insertion of the same source works. Multiple blocks preserve individual provenance and total schema budgets.
5. Source quotation never changes Reply/Reply-all recipients, thread target, From, CRM identity or support state. Explicit retarget/recipient change tests preserved text plus precise reviewed deltas.
6. Text editing/trim changes delivered attribution to Edited excerpt; formatting-only changes do not. Equivalent HTML/plain text source labels and content remain truthful. Long/RTL/non-Latin names, combining marks and IME are tested.
7. Known source-bound copy/cut/unwrap/Undo cannot strip dependency. Clearing one occurrence while another remains does not release the source fence. Removing all actual occurrences does not block unrelated new text permanently.
8. Nested quotes/signature-address text are visible as included; an image-only/unsupported source does not produce misleading empty successful quotation. Historical files/remote pixels/protected action URLs never appear implicitly.
9. Literal brace text, mentions, malformed links, unsupported nodes/attributes and hostile source HTML cannot execute, substitute values, fetch URLs or become source authority through compilation.
10. Revocation/expiry before insertion, after insertion, before preparation and before dispatch admission produces appropriate source-gated failure; late responses, Undo, autosave, cache and restored drafts cannot resurrect text. In-flight/accepted/unknown envelopes retain honest reconciliation.
11. Two-tenant, same-tenant restricted-source, forged source/range/author, changed-role and service-worker negative tests prove equivalent boundaries. Current CRM+Support authority is intersected, not propagated.
12. Matching editor/source/compiler schema qualification succeeds; unknown old code/schema fails read-only/repair without silently stripping metadata or invoking an unqualified serializer. Existing last-known-good prepared outcomes remain recoverable.
13. Core Base UI/base-maia token checks, actual keyboard/focus/screen-reader, narrow reflow/zoom/mobile keyboard, reduced motion, images-off and actual representative HTML/plain-text email-client tasks pass. Visual aesthetics require actual rendered review; the document alone does not prove beauty.
14. Complete-document depth/size/count boundaries are inherited from the qualified D23/P17 profile and tested at below/equal/above limits. Source fetches are bounded and performed on demand, with no full-thread-body prefetch or per-message editor mount. Measured insertion responsiveness, larger valid sources and offline recovery must be recorded against the release's named existing performance budget.

## Synthesis

The selection is sound. The narrow permanent implementation is an exact-source, editable quote insertion in the shared Reply composer. Reuse D18 insertion/Undo, D23 editor/signature, D16/D17 source fences and the existing Support → Email Studio → P6 chain. First qualify semantic/source conversion and recipient-authorized use, then the one-step interaction, then actual compilation/send recovery and cross-surface tests. Editor configuration and formatting toolbar are insufficient foundations alone.

No new external dependency, generic workflow engine, quotation settings page or multi-message history builder is necessary. Keep repeated point-by-point quotations possible within existing document limits. Monitor only ordinary operability signals already qualified by the root's D36 controls; access, source provenance, attribution and dispatch invariants are release requirements, not risks to accept through monitoring.
