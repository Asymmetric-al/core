## Recommended bounded architecture

Support supplies the original attachment occurrence, exact source authorization and staff inspection context. A narrow Phase-29-compatible private byte/preview capability supplies immutable byte identity, processing, hygiene, private storage/serving and derivative cleanup. Apps render the read-only result through shared UI. The source retains classification, relationship, purpose, retention, restriction and independent business meaning. This is one reusable capability, not a second File Manager or an early dependency on the entirety of Phase 29.

The root's proposed supported set — PNG/JPEG/WebP/static GIF, PDF, DOCX, XLSX, PPTX, TXT and CSV — is a defensible bounded interpretation of C, provided each profile passes actual safety, fidelity and accessibility gates. The list is a product choice, not a claim that these formats are harmless. File extensions do not select authority or override MIME/byte/package validation. Unsupported, password-protected, macro-bearing, corrupt or oversized files keep truthful metadata and only a separately permitted original-download path; preview failure never triggers automatic download.

Use distinct qualified presentation profiles rather than forcing every format into a print PDF. Images need bounded decoded dimensions and an explicit animation policy. PDF/word-processing/presentation inspection needs honest page/slide coverage and passive output. XLSX should use a read-only saved-value sheet view, not claim a print-area PDF is a complete workbook. CSV/TXT remain escaped text/tabular data with explicit encoding/delimiter coverage. Never calculate formulas, load external data, run macros, activate hyperlinks/embeds, submit forms or infer authoritative CRM/giving facts from any preview.

On deliberate Preview, qualify exact source/bytes/scan and request or reuse one matching derived result. The artifact identity binds tenant, original occurrence, immutable source byte version/digest and renderer/profile version. Attempt generations fence late workers; current restriction/expiry remains an independent serving gate. A file or conversion result cannot become Ready merely because a storage upload or converter HTTP request succeeded. Privately store, verify output metadata/integrity/coverage and conditionally promote it against current source controls. Stale outputs remain cleanup-only.

No raw public, provider or reusable signed storage URL reaches the browser. Every source/full/range/preview request uses an Asym-owned boundary with current source authorization and D16/ADR0037 no-store controls. This does not require issuing a guest protected-action link merely for ordinary authenticated staff inspection. A file renderer/worker receives only the exact permitted input and no application/tenant credentials or general network capability. Independent authenticated control-plane services can obtain/store bytes; the parser process need not contact Supabase, Resend, cloud metadata or the Internet.

## Material findings and permanent clauses

Each likelihood below is a qualitative judgment about an unamended implementation, not an observed Asym incident rate. The findings amend C; none requires replacing C with download-only support.

### DC01 — File occurrence, byte identity and preview identity must stay distinct

**Material: Yes. High / likely with the current URL-shaped row.** A changed URL, same filename or global content hash could point a preview at the wrong source or grant another tenant's artifact. A new conversion could impersonate an original or an official receipt.

> “A preview binds one tenant-qualified original attachment occurrence, exact immutable source byte version/digest, actual source-purpose context and versioned rendering profile. Its own output digest/length/coverage and renderer version identify a derived result. Filenames, URLs and viewer position are never identity. No cross-tenant content-hash cache or authority reuse is introduced. The original remains unchanged; the derivative never becomes a P18 current document, signed receipt or CRM record.”

**Proof:** Identical filenames/different bytes; same bytes in different tenants/purposes; source replacement; attachment moved through current conversation topology; recognized receipt-like PDF without official provenance. Every result resolves to its exact permitted source.

### DC02 — Metadata availability, scan readiness and preview support are separate facts

**Material: Yes. Critical / current status is insufficient.** S03 calls a listed metadata collection available; a viewer could then open unknown or unscanned input.

> “Derive file actions from current source-owned custody, integrity, classification, scan and access evidence, plus a separate preview-profile eligibility result. A filename match, provider list response, extension, parser success or familiar sender never proves clean readable bytes. Missing/pending/failed/blocked scan has its true state and no ordinary preview. Unsupported preview does not mean unsafe download, and clean scan does not mean every active document feature is permitted.”

**Proof:** Metadata-only, missing bytes, stale scan for older digest, forged MIME/extension, encrypted content, transient scanner failure and a clean file with active links. No fallback bypass or automatic download.

### DC03 — Private serving must check the current source, including every range

**Material: Yes. Critical / plausible if raw URLs are reused.** Signed URLs and CDN behavior can outlive source restriction. Public email-assets is explicitly the wrong custody class.

> “Original and derived preview bytes stay private and are served through the qualified Asym source-authorized boundary. Recheck current tenant/principal/source/byte version and relevant original/CRM/classification permissions for metadata, HEAD, full-file, page/tile/text and each range request. Apply the exact inherited no-store/no-transform/CDN no-store controls; do not return a reusable signed/public/provider URL, public image optimizer or service-worker cache. Restriction wins before new serving; an already-authorized stream is honestly in flight and terminated where feasible. Previously received local bytes cannot be recalled.”

**Proof:** Preview open during redaction/expiry, new range after revocation, same URL after logout/tenant switch, stale CDN response, filename/size/error side channels, browser optimizer bypass and direct storage access. No forbidden content is served after a winning current gate.

### DC04 — Untrusted document parsing needs real process and resource isolation

**Material: Yes. Critical / plausible malicious or malformed input.** Office/XML/PDF/image parsers are executable attack surfaces. Converter allow-list configuration alone is not a full process boundary.

> “Parse/render untrusted files in a restricted worker process separate from the privileged API/control plane. Supply one exact read-only input and a bounded output location. Deny general network/DNS/cloud-metadata access, application credentials, host files and other jobs' files. Disable macros, scripting, DDE, external relationships, URL/file includes, embedded executables, interactive forms and automatic link actions. Patch/pin the actually qualified renderer/runtime image; a clean antivirus result does not relax sandbox limits. Public remote document viewers and arbitrary URL conversion endpoints are not an approved private-file path.”

**Proof:** OOXML external image/relationship, file URL, internal-address/DNS rebinding attempt, macro concealed in a normal extension, PDF JavaScript/launch/embedded file, SVG/script, parser crash and process escape fixture. Capture zero unauthorized network/file access in a nonproduction isolated test.

### DC05 — Office conversion success is not complete or faithful inspection

**Material: Yes. High / documented converter behavior.** A document can return HTTP200 while missing linked content, hidden slides or unsupported layout. A PDF print area can omit most of a workbook.

> “Each profile declares what the preview covers and which unsupported/omitted elements it can detect. Preserve native page/slide/sheet identity and truthful coverage; never label the first page, print area or truncated output a complete document. Known omissions are visible. Rendering does not validate signatures, recalculate finances or establish business facts. Original download, where separately authorized, remains explicit and is never replaced by the generated approximation.”

**Proof:** PDF with many pages; workbook outside print area; hidden sheets/rows/slides; tracked changes/comments; missing font/glyph; linked images; signatures/embedded objects; page/output cap. The displayed scope is independently explainable and missing content cannot become a false empty/zero result.

### DC06 — XLSX/CSV values are data, not executable formulas or accounting truth

**Material: Yes. High / normal specialized documents.** Spreadsheet recalculation, external data links, formula injection and hidden ranges can produce different values or disclose context.

> “Use a read-only saved-value workbook/table projection. Never evaluate formulas, DDE, external connections or imported code. Mark formula/cache provenance and unavailable cached values; missing is not zero. Keep sheet names/hidden state, cell references and supported range coverage truthful. Escape every displayed value. Parse CSV encoding/delimiter/quoting explicitly and surface ambiguity; text beginning with formula characters remains text. No preview fact writes CRM, giving, receipts or imported rows.”

**Proof:** Formula without cached result, stale saved result, external link, CSV leading `=`, embedded line breaks/quoted delimiters, duplicate/hidden sheets and sparse distant cell coordinates. Large blank ranges cannot force dense allocation or appear as complete bounded data.

### DC07 — Published preview readiness must be a fenced promotion

**Material: Yes. Critical / asynchronous race.** Source redaction or expiry can occur after conversion starts but before its output upload completes. A late worker must not bring restricted content back.

> “Admission records a source/byte/profile-bound work identity and attempt generation. Upload output only to private tentative custody. Before Ready promotion, verify output digest/length/type/coverage and recheck current source existence, version, restriction/expiry, scan and purpose controls. Promotion is conditional and atomic in product state. A stale, cancelled or superseded attempt cannot publish, even if its upload succeeded or its worker lease expired. Late output remains cleanup-only. Storage and DB are not one distributed transaction; crash-safe orphan cleanup accounts for their partial results.”

**Proof:** Restriction wins before admission, mid-render, after upload or before promotion; double worker; cancelled attempt returns last; storage success/DB failure; DB marker without output; wrong digest. Current source gates deny stale outputs independently of physical deletion progress.

### DC08 — Retry/reuse must bind the exact source, never widen the processing purpose

**Material: Yes. High / likely retries and repeated inspection.** Repeated clicks can create duplicate jobs or let a renderer-upgrade/fallback change output silently. A revoked viewer can retain a progress stream.

> “Coalesce equivalent requests only within the same tenant/source byte/profile identity and qualified source purpose. A successful matching result may be reused after current access checks; ordinary opens do not create new generations needlessly. Bound retry attempts and distinguish transient processing/storage failure from deterministic malformed, unsupported, password-protected or budget-exceeded input. A materially changed renderer/profile creates a new result identity, never overwrites the old evidence. A closing viewer is not source revocation; a revoked viewer loses result/progress access even if an owner-valid job continues for other authorized use.”

**Proof:** Concurrent opens, failed request replay, delayed old render after upgrade, one viewer revocation, last viewer closing, permanent malformed input and transient worker outage. No new business communication or indefinite retry storm.

### DC09 — Resource budgets must bound decompression and output, not only upload size

**Material: Yes. High / plausible resource exhaustion.** A small ZIP/image/XML/PDF can consume huge memory/output; a handful of distant cells can imply an enormous grid.

> “Publish and enforce a versioned preview resource profile before activation. The proposed starting bounds are 20 MiB source bytes, 200 MiB cumulative expanded package bytes, 200 document pages/slides, 40,000,000 decoded pixels per image, and XLSX 100,000 populated cells/50 sheets. They are preview-only limits, intersected with existing receiving/byte policy; they do not change intake/send limits. Also bound archive entries, XML/entity/depth/relationship parsing, generated-output bytes, page/tile dimensions, total processing memory and process-tree CPU. Sparse ranges use bounded rendering, not dense expansion. The proposed 30 CPU seconds and 60 elapsed seconds per attempt mean different measured resources; allow at most two transient attempts, not deterministic retries. State units, comparison equality and cap behavior exactly in the final profile.”

**Proof:** At/below/above every cap; ZIP bomb, excessive XML structures/styles, sparse extreme sheet, decompression bomb, giant PDF dimensions and output amplification; aggregate CPU versus wall timeout; fair concurrent tenants. All limits are proposed engineering budgets, not measured capacity. A partial result is not silently complete.

### DC10 — Database and storage grants must preserve original-source authorization

**Material: Yes. Critical / current broad writes insufficient.** Existing table RLS and storage ownership do not automatically authorize the source occurrence or prevent changing a permitted row into another source's Ready preview.

> “Keep source/preview state and mutation in packages/api under trusted server context. Enforce same-tenant attachment/message/source/byte/result relationships with actual constraints or a typed owner-validated reference contract at domain boundaries. Preserve stable source TEXT IDs. Require non-null source/version/profile identity, unique logical work/result generations, nonnegative finite counts/lengths, valid state/output combinations and immutable tenant/actor/source attribution. Normal users cannot set scan/Ready/digest/storage-key fields, reparent output or erase required restriction evidence. Verify effective grants, SELECT, USING/WITH CHECK, column permissions, views/RPC EXECUTE/search_path and privileged service-role paths, including storage list/read/write/upsert/delete. No source authorization is inferred from a bucket folder name or object uploader.”

**Proof:** Same tenant/forbidden source, cross-tenant keys, forged status/digest, update-parent transformation, permissive-policy union, owner-delete cascade, direct storage upsert and list metadata leak. PostgreSQL's applicable USING fallback must be considered; missing explicit WITH CHECK syntax alone is not a vulnerability claim.

### DC11 — Preview custody must remain finite and subordinate to source expiry

**Material: Yes. High / likely if a cache becomes an archive.** Temporary inputs, converted PDFs, text layers, thumbnails and logs can outlive source deletion. Preview use could repeatedly extend retention.

> “Every temporary and durable derived class has an explicit owner, fixed finite processing/cache/disposal schedule, source lineage and restore barrier before activation. Cache expiry is bounded by its creation purpose and the source's earlier applicable deadline; reads do not extend the original content lifetime. Source restriction denies serving first, then disposes all eligible derivatives and tentative attempts through existing D16/D17/P29 mechanisms. A hold can preserve required bytes without ordinary preview access. Do not copy content into logs, diagnostics, URLs, progress events or a search corpus. Do not borrow P17's execution-material deadline as a universal preview policy.”

**Proof:** Expiry during open/read, stale temporary files, failed-job orphan, held source after ordinary expiry, restore of old storage, regenerated cache after source denial and logs with unsafe filename/content. Shared physical bytes under a valid independent owner do not reopen an expired Support occurrence.

### DC12 — Source topology, CRM and other preview contexts cannot grant extra access

**Material: Yes. Critical / realistic linked/merged sources.** A current root, CRM link, held-intake reviewer or known donor can be mistaken for permission to every original or official document.

> “Keep the preview attached to its original source occurrence through merge/Undo/related work, source correction and CRM linking. Reauthorize current source and relevant domain floors for each context. The same Support detail in CRM uses the same source/result, not a copied CRM file. Held intake, ordinary messages and private notes retain their own purposes; a viewer available in one does not release another. Viewing does not create a Party, change last contact, verify identity/receipt, perform a refund or finish Support/task work. Known independent official artifacts retain their P18/source checks; an uploaded receipt-shaped PDF remains user-supplied evidence.”

**Proof:** Merge original A/B with different visibility, Undo after restriction, file shared independently in CRM, held intake preview, restricted-care subject and forged receipt metadata. No hidden count/name/range leak or duplicate history.

### DC13 — Existing PDF/Email Studio infrastructure must not become an accidental converter

**Material: Yes. High / plausible reuse shortcut.** A PDF package, public email-assets bucket or P18 custom-document purpose could seem convenient, but each carries different publication, privacy and authority assumptions.

> “Qualify the narrow private attachment-preview renderer independently of P18 official generation. Reuse shared private byte/access/worker/UI primitives only where their contracts fit. Do not add preview conversions to Document Studio publications, facts packages, issuance/current heads or the system-message catalog. Do not send originals to DocRaptor or another external processor merely because an API key exists. New processors require an explicit qualified purpose/data boundary; prefer isolated private processing for this bounded feature. No attachment is inserted into a Tiptap draft, P17 publication or P6 send by Preview/Download.”

**Proof:** Known receipt PDF, DOCX preview, public logo bytes attached privately, converter outage, Email Studio unavailable and click from an unsent reply. Independent source work still operates; no alternate mailer, renderer fallback or public asset promotion.

### DC14 — Rollout must qualify the actual renderer and remove old URL bypasses

**Material: Yes. High / current scaffolding is incomplete.** New UI can claim support while metadata-only custody, public/raw URLs, stale workers or old grants bypass it.

> “Inventory actual original/thumbnail/preview delivery, metadata mappers, old clients, upload and provider retrieval paths. Establish private immutable byte/scan/source authority, fenced generation/promotion and current serving first. Qualify each exact renderer/profile/runtime/font/validator build and supported-format corpus, then the UI and all current-context journeys. Unsupported profiles stay unavailable rather than silently falling back to a public viewer or another converter. New-conversion disablement preserves source access, cleanup and qualified original download; rollback cannot revive URL bypasses or erased derivatives. Renderer upgrades produce explicit compatible/new result identity and rerun affected corpus proof.”

**Proof:** Mixed old/new state, stale job after deploy, malicious corpus, renderer/profile upgrade, missing font, current access revoke, storage restore, kill switch and rollback. No actual live provider/file conversion result is claimed by this source review.

## Logical data and state model

Avoid duplicating source scan, classification and privacy state into independently editable preview flags. A processing state can be persisted while current eligibility is derived from its source owner.

| Logical fact                     | Owner/invariant                                                                                                                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Original attachment occurrence   | Support source identity and message relationship; current source protection remains independent of current merged root.                                                                    |
| Immutable original byte identity | Phase-29-compatible byte owner; digest, measured length/type/version and private storage provenance.                                                                                       |
| Source eligibility               | Current source/byte/classification/scan/retention/access contract; not a successful preview result or uploader ID.                                                                         |
| Preview profile                  | Code-owned supported-format, parser/output/coverage/budget contract with version and exact qualified runtime. No tenant-authored executable conversion recipe.                             |
| Logical preview work             | Same-tenant source occurrence/byte/profile identity with bounded intent; no duplicate job per click or cross-tenant hash identity.                                                         |
| Attempt                          | Monotonic generation, bounded worker lease/resources, safe failure reason and private temporary output. Lease expiration alone never permits stale publication.                            |
| Derived result                   | Immutable digest/length/type/coverage/renderer provenance, fixed custody schedule and source restriction linkage. Ready promotion proves its exact output; current use still reauthorizes. |
| Display session/request          | Current tenant/principal/source context with no-store serving; progress/read descriptors are not bearer access grants.                                                                     |

User-visible states distinguish Not requested, Preparing, Ready with declared coverage, Preview unsupported/too large, Processing failed/retryable, and source Pending/Blocked/Unavailable/Expired according to what the viewer may know. Source denial is not a new retryable renderer error. A neutral inaccessible state must not reveal a forbidden filename or existence count. Exact physical tables/API spellings and a generic pipeline DSL are not frozen here.

## Primary technical evidence and tradeoffs

- [Supabase Storage access control](https://supabase.com/docs/guides/storage/security/access-control) documents separate policies for operations and complete service-key RLS bypass. A privileged byte worker must independently enforce the source contract; bucket access is not sufficient.
- [Supabase asset serving](https://supabase.com/docs/guides/storage/serving/downloads) distinguishes public access, authenticated private access and signed URLs. It explicitly states that Storage signing keys are separate from Auth key changes. [Smart CDN](https://supabase.com/docs/guides/storage/cdn/smart-cdn) explains caching behavior. Core's D16/ADR0037 current-source boundary wins over a convenient reusable signed-URL implementation.
- [Gotenberg LibreOffice conversion](https://gotenberg.dev/docs/convert-with-libreoffice/convert-to-pdf), opened 13 September 2026, documents Office support and warns of layout/font differences. Linked resources can be omitted despite a successful response. Defaults can export interactive form fields, omit notes/hidden slides, or alter sheet coverage under certain options. This is evidence that a configured converter needs an explicit fidelity/passivity profile, not a recommendation to install it unchanged.
- [Gotenberg outbound filtering](https://gotenberg.dev/docs/outbound-url-filtering) and the project's [SSRF advisory](https://github.com/gotenberg/gotenberg/security/advisories/GHSA-rm4c-xj6x-49mw) show why subprocess network behavior and exact version matter. OS/container egress isolation is a stronger required boundary than trusting one library filter. The advisory is not a claim that current Core runs the affected software; the inspected dependency list does not include it.
- [LibreOffice PDF link behavior](https://help.libreoffice.org/latest/en-US/text/shared/01/ref_pdf_export_links.html?DbPAR=SHARED&System=MAC) documents automatic exported hyperlinks. Read-only output therefore still needs active-action restrictions and safe viewer behavior; PDF conversion by itself does not make content inert.

No converter is silently selected through these comparisons. The permanent owner and proof contract is decided; exact third-party implementation must pass it before activation. This is a proportionate new technical capability required by the selected broader previews, not a speculative whole-document platform.

## Synthesis and remaining proof

First settle the supported profiles and explicit truthful coverage; then qualify immutable private source custody, scan eligibility and serving/restriction controls. Next establish fenced conversion/result cleanup and actual isolated renderer tests, followed by all shared Support/CRM/intake-context UI journeys. Finally qualify capacity, accessibility, malformed/hostile corpus behavior, restore and mixed-version rollback. Optional rendering must never block unrelated Support work or weaken a source gate merely to show a preview.

The proposed input/expanded/page/pixel/cell/sheet/CPU/wall budgets need the root's final exact output/memory/parser profile and prospective qualification; they are not measured throughput. Missing safety, source, fidelity or cleanup proof blocks the affected profile, rather than becoming a monitor-only exception. Runtime observations must separate actual byte acquisition, successful conversion, valid output, Ready promotion, current authorized serving and user-visible completeness.
