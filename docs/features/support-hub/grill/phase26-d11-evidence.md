## Independent challenge, corrections and final synthesis

The data review identified exact owner reuse, safe bidirectional context without whole-source access, actor/destination separation, tenant-aware references and partial helper admission. The lifecycle review separated active interests from historical links, current results from human review, and current handling from frozen creators. The vendor review distinguished consultation, tracked work and transfer, and rejected unnecessary enterprise fields, note propagation and fabricated CRM history.

The draft was independently challenged again. Adopted corrections, all included in the fully ratified D11 record:

1. **Existing completed work:** binding evaluates the current result immediately and closes the subscribe/result race; no wait for an event that already happened.
2. **Immutable meaning:** original source set, target and purpose/scope are fixed within an interest generation; correcting/expanding meaning requires a reviewed new generation.
3. **Equal assignees:** never suppress a fresh unobserved result solely because the same worker owns both work items. Suppress only qualified actual duplicates/self-generated attention.
4. **Merged result fan-out:** one owner occurrence produces one review per current handling root, retaining all affected interests. Undo partitions contributions without copying work.
5. **Queue versus notification:** a shared queue work item is not a recipient-specific P6 notification. Resolve current qualified staff recipients separately; no fabricated queue addressee.
6. **In-flight email:** source end blocks new unauthorized admission/egress/presentation; it cannot recall a previously authorized in-flight email. Retain truthful P6/Resend outcome.
7. **Task due versus Support reminder:** only a current owner-qualified missed promise requiring Support action produces review; specialist reminders do not automatically reopen Support.
8. **Free-text disclosure:** explicit source disclosure floors and safe-summary authority are necessary. Do not promise perfect sensitive-text detection or install a speculative classifier.

9. **Ending the last blocker:** stopping a Support interest revalidates the entire resulting D3 plan; it cannot leave a conversation Waiting without its real blocker.
10. **Distinct D5 wording:** the task-card action is **Stop following this work…**, avoiding D5's ratified **End follow-up…** conversation-resolution label.
11. **Keyboard and dismissal scope:** the help panel fences background requester-Send shortcuts, separates selection/multiline Enter from submission, and distinguishes dismissal before versus after admission.

These are reconciled permanent clauses, not optional warnings left for implementers. They preserve A while making it less brittle and better aligned with Core's boundaries. They add no new product-wide workflow engine or second CRM.
