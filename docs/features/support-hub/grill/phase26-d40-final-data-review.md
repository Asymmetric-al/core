The initial source investigation identified real mismatches: recipient-route Save resumes other reviews, thread routing follows current handling, address extraction is not the selected single-mailbox equality contract, current bridge writes do not prove unique atomic admission, and broad Support CRUD does not enforce the proposed disposition boundary. These findings are retained as current-source gaps in C01–C18 and the root's R/proof requirements. They are not described as newly repaired code or tested database security.

**F01, email-origin scope:** the actual R03/C02/L03/UX02 now preserve D26 manual correction and D29 form handling. The selected action does not become an all-origin classification platform. **F02, inbound versus outbound:** R22/C14/L09/UX15/P25 explicitly distinguish a held input lacking admission eligibility from a mailbox-wide outbound suppression. Other legitimate communications remain subject to their own owners. **F03, held-source creation:** R09/C04/L01/UX07/P09 permit policy creation from qualified D19-held input without first releasing it or changing its gates. **F04, late actionable recovery:** R07/C13/L09/P07 require new real owner/P6 recovery to make its affected original/current work home visible after a valid Mark, without repeated reopening from duplicate/reviewed outcomes or fabricated human-content/reading events. All four are closed in the reviewed documents; their real implementation proofs are still required.

The first-acceptance protocol, receiving-scope resolution, semantic active uniqueness and same-input gate exception are the most consequential implementation obligations. The integrated text does not invent an already-deployed policy-version API, use a timestamp as a concurrency proof or demand an unrelated global event/permission platform. Actual source/owner checkpoint and locking design must be qualified before activation, including unbound receiving scope and policy-unavailable recovery.
