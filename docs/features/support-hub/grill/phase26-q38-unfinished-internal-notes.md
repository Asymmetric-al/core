## The question

**When someone leaves a new Internal note unfinished, how should Asym preserve it for later?**

Imagine a staff member starts an internal note in a Support conversation, checks an authorized CRM record, and then handles another request before finishing. They have not clicked **Add note** and are not ready to share the text. Later, they need to find it and continue. This is an illustrative interruption in an existing authoring task, not a claim about measured ministry habits.

| Option                                              | What the user experiences                                                                                                                                                                                               | Main advantage                                                                                                                       | Main tradeoff                                                                                                                                         |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A — Automatically save note drafts in My drafts** | Meaningful new-note work saves privately while they write. It appears beside their saved replies, clearly labeled **Internal note**. Opening it resumes the same note in its source conversation.                       | Consistent write, leave and resume behavior without remembering Save or remembering which conversation contains the unfinished note. | Adds governed private storage for unfinished notes and requires correct separation from replies and published notes.                                  |
| **B — Save note drafts deliberately**               | **Save note draft** stores the current version privately in My drafts. Later edits need another deliberate save; unsaved changes remain clearly identified and protected on navigation.                                 | Explicit control over when internal working text becomes a retained draft, with the same useful return path once saved.              | A recurring Save step and more interruption prompts; people may expect the automatic saving already chosen for replies.                               |
| **C — Keep notes as current-session work**          | The current Note text survives supported mode/context changes that retain it. Before leaving would discard it, Asym explains the loss and offers Stay or deliberate Leave. No saved note or My drafts entry is created. | Smallest persistence and retained-content scope.                                                                                     | No dependable cross-session return. The person must finish, keep the working context or knowingly leave the text behind; a browser crash can lose it. |

These are **three alternative policies**, not three settings to build. All keep D37's accepted external Reply saving and discovery unchanged. B is the strongest alternative when deliberate retention control matters more than reducing steps. C is a legitimate smaller-scope choice, provided app-controlled navigation never silently discards work.

## Single recommendation: A

**Automatically save new note drafts privately and make them available in the existing My drafts view.** It closes a specific interruption gap in an editor people already use. It needs no new destination, notebook, editor or collaborative workspace. The consistency benefit is a product judgment grounded in the actual journey; it is not a claim that all vendors agree or that persistence is free to implement.

The intended experience is simple: select **Internal note**, write, see truthful save status, leave, select the clearly identified note in **My drafts**, continue in the same composer, then deliberately choose **Add note**. A Reply draft and a new Note draft in the same conversation remain separate work. Posting one cannot clear or convert the other. A saved unfinished note stays private to its author under current source permissions; the later posted note has the conversation's qualified internal visibility.

Reuse the existing compact metadata rows, Base UI and base-maia design language. Use a textual **Internal note** or **Reply** distinction in both the row and resumed composer; color alone is insufficient. Keep the source clear on mobile before opening the keyboard. No body preview, additional note tab, count badge, settings hierarchy or new reminder system is implied. Saved means acknowledged current work; errors and pending files remain honest without noisy success toasts after every save.

## Boundaries preserved by every option

**Saving and posting are different.** Draft creation, save, discovery, restoration and mode switching do not add a note, send mentions, notify followers, change work status or assignment, create CRM activity, execute business actions or send email. Deliberate Add note retains the existing authorized admission and any separately qualified attention effects.

**Support owns its working material.** If A or B is chosen, reuse the appropriate private Support draft owner/controller with an explicitly qualified Internal note purpose. Do not create a shadow message, duplicate notebook, provider draft or second CRM. Do not blindly copy email recipients, signatures, transport states, readiness validation or external-reply cardinality into notes. Exact note identity/cardinality, schema, saving cadence, incomplete work, source merge behavior, file/mention references, retention and post/discard consumption are part of the chosen answer's subsequent review.

**Email Studio remains a shared capability at the right boundary.** P17-governed canonical schema/editor/reusable wording can support note authoring. Support owns private note storage if selected and actual note admission. Saving or restoring a note does not prepare an outgoing email or publish an Email Studio template. An independently authorized attention email after actual note admission still uses its own P17 presentation and P6 delivery/reconciliation path; the draft itself creates none. External Reply preparation and delivery continue unchanged.

**CRM shows the same authorized Support work.** Preserve source context and return navigation without copying content or granting access from a CRM relationship, assignment or conversation membership. Current tenant/author/source privacy applies to metadata, text, files and operation recovery. Saving a note is not evidence that another Core domain completed a task. D16/D17 restrictions and custody apply without a new arbitrary retention lifetime.

**Recovery must be honest.** A/B require exact acknowledgments, conditional current-version saves, original-operation recovery and terminal post/discard fences; C promises only the working-state continuity it actually provides. Keep separate Reply/Note state through rapid navigation, account or source changes, lost acknowledgments, multiple tabs, uploads, IME and CRM visits. D35's posted-note correction editor remains local and outside My drafts under every option.

The full adversarial review of the selected answer will close its exact contract and proof requirements. **Q38 remains unanswered; A is the single recommendation.**
