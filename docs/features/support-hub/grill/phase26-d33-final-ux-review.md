## Pressure-test synthesis

The actual contract resolves the principal confusion that could make C difficult to use: **choosing the personal default saves; expanding content only changes the current reader.** The toolbar and menu state remain meaningful when a region is manually expanded, the conversation is temporarily Full, a save is pending or rejected, and another device has changed the confirmed default. The complete proof set explicitly checks these states rather than only a successful first save.

Its conservative content rule is proportionate to the problem. It uses qualified structural repetition and historical content instead of trusting a quote marker, current signature template or language-specific closing. Unknown or modified material stays readable, including the sole substantive region of a response. Full keeps the same safe source and current authorization. These constraints may leave some real repetition expanded, but avoid presenting an incomplete new reply as the complete current request; the package states that tradeoff and does not claim perfect detection.

The personal preference remains a small extension of the actual shared owner. Revision fencing is justified by asynchronous save/reset and cross-device behavior; it is not expanded into a workflow, event log or approval system. Explicit absent/error states and stable current reading prevent preference outages from becoming data changes or content jumps. The reader's source and preference failures are correctly handled independently.

The proposed interface uses the founder's examples selectively: utility placement and responsive hierarchy inform composition, while Core's exact Base UI/Maia system governs implementation. The parent documented what its browser inspection actually showed, including negative evidence. That is consistent with the research and avoids treating a polished demo or existing primitive as proof of a complete accessible Support journey.

## Proof limits and final disposition

**Pass for the complete proposed D33 UX and fidelity contract. No material findings remain.** The documentation covers first use, temporary expansion/reset, saving either default, same-value confirmation, failures and ambiguous saves, remote changes, sole/inline/forwarded content, search, files, CRM return, source changes, mobile/keyboard/AT and maintenance without unrelated scope.

P01–P36 and O01–O06 remain the required implementation/release and operating obligations. In particular, the renderer/segmentation corpus, effective RLS/service path, revision races, source restrictions, mobile/assistive-technology behavior, declared performance fixtures and representative staff comprehension must actually be executed. This Pass does not establish measured preference prevalence, detector accuracy, task-time savings, universal document accessibility or a tested perfect UI. No code, external state or real message was changed by this independent review.
