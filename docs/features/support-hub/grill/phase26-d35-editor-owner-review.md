## External patterns evaluated

Tiptap supports extension-schema content checking and a content-error callback, and documents weaker HTML validation. Its suggestion that unknown content may be stripped for some non-collaborative applications is inappropriate for a previously admitted Support record. Adopt explicit validation/error handling, while retaining D23's stricter validation of original JSON attributes, purpose and references before any parser normalization. [Official invalid-schema guidance](https://tiptap.dev/docs/guides/invalid-schema); [immutable documentation source](https://github.com/ueberdosis/tiptap-docs/blob/de0873c397b84b221b1924193301819200333f74/src/content/guides/invalid-schema.mdx).

The documented Snapshot extension requires a subscription/trial, Document server and private-registry packages; its example brings a collaboration provider and Yjs transformation, and its restore operation creates another version. That solves collaborative document history. D35 needs only explicit, author-attributed Support note saves and safe read-only earlier bodies. Reject that service/dependency expansion here; local Undo remains an unsaved editing operation, and Support retains its own minimal source revisions. [Official Snapshot documentation](https://tiptap.dev/docs/collaboration/documents/snapshot); [pinned source](https://github.com/ueberdosis/tiptap-docs/blob/de0873c397b84b221b1924193301819200333f74/src/content/collaboration/documents/snapshot.mdx).

The current composable React API is an alternative to `useEditor`/`EditorContent`, not evidence that a working shared wrapper must be rewritten. Preserve the current shared composition and SSR setting, isolate the active editor and use selective subscriptions where useful. [Pinned composable API guide](https://github.com/ueberdosis/tiptap-docs/blob/de0873c397b84b221b1924193301819200333f74/src/content/guides/react-composable-api.mdx), [pinned Next.js guide](https://github.com/ueberdosis/tiptap-docs/blob/de0873c397b84b221b1924193301819200333f74/src/content/editor/getting-started/install/nextjs.mdx). The live Next.js page timed out on the final fetch; its checked pinned source supports this limited SSR statement.

These sources establish APIs and tradeoffs. They do not prove Asym's authorization, usability, browser fidelity or performance. The strongest product alternative remains an ordinary new clarification/correction note with no edits: simpler storage, but needless chronology entries for minor corrections. Selected A is proportionate if the following source boundaries are captured.

### Deliberate removal is not parser loss

The initial suggestion to lock all existing mention and inline-image node presence was rejected after UX/data challenge. It would make deleting a paragraph unnecessarily difficult. The final E03 contract allows deliberate removal/movement and protects authority-bearing attributes, source membership and file bytes. Unsaved Undo may restore a still-allowed reference from the loaded current base; it cannot reintroduce a revoked reference or import a new target. Removing an inline image does not delete the original file, and the unchanged file list remains visible. Sensitive-data removal uses D16 across representations.

This distinction does not require storing every keystroke or building a semantic edit interpreter. The server validates the admitted base and complete candidate under a closed purpose-specific contract. The qualified editor must reject unsupported persisted semantics rather than silently normalize them away. Pasted appearance is not proof of an authorized typed reference.
