# D34 A — Composing-only awareness: independent UX research

**13 September 2026. Founder selected A and requests an accurate, low-lag, complete experience.** This report supplies a proposed meaning, timing envelope and staff journey for the parent's adversarial synthesis. Numeric settings below are explicit product/engineering judgments to qualify, not independently ratified values or universal vendor norms. No runtime, provider, user setting or real message was changed.

## Recommended experience

Show one quiet **Maya is composing** cue for currently authorized recent composition in the same Support context. Use the same neutral wording for a reply or internal note. Do not expose text, keystrokes, recipients, attachment names, draft length or the fact that a draft is an internal note. Mere viewing stays invisible under the selected A.

The cue is a short-lived advisory signal, not a claim that Maya owns the work, will send, is continuously typing or has read all updates. A missing cue does not establish that nobody else is working. The existing D1/D2/D4 authoritative send-collision gate remains mandatory and independent; live awareness cannot acquire, delay, cancel or override a send/assignment/work transition.

Use the current shared reader utility area so staff can notice composition before starting a competing draft, without a new global activity rail or viewer roster. Keep the cue visually distinct from assignment and From identity. Preserve the D33 Reading/Find controls, current temporary disclosures, message anchor and actual Tiptap draft. No modal, sound, toast per transition or animated typing dots are needed.

### Reported friction, not verified incidence

The [30 April 2026 Intercom community report](https://community.intercom.com/ideas/fix-teammate-presence-it-s-causing-duplicate-work-14456) describes disappearing/inconsistent signals leading to duplicate effort and asks for a signal while a ticket remains open. These are self-selected reports, not a measured defect rate or proof of every current edition's behavior.

They expose an expectations problem: work can continue while somebody thinks or researches without typing. Keeping an open tab permanently marked as composing would solve that complaint by overstating activity and reintroducing viewing presence. The recommended solution instead states a bounded recent-composition meaning, avoids flicker during short pauses and preserves actual assignment/communication tools for longer investigation. No measured Asym work-overlap frequency or task-time gain was available.

## What qualifies as composing

Recommended meaning: **recent deliberate activity in the active, visible, authorized Support composer**, with a brief inactivity grace. Publish only a minimal activity signal. Do not stream keystrokes, DOM events or content values to peers.

| Staff/browser event                                                                                              | Recommended behavior                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Actual user text insertion, deletion, cut/paste, dictation or permitted drop                                     | Starts or refreshes composition immediately at the leading edge. Do not wait for a debounce that only fires after typing stops.                                                                                         |
| IME composition begins/updates/commits                                                                           | Qualifies as composing without waiting for a Latin-keyboard-style keyup or final committed string. Transmit no preedit/candidate text. Avoid duplicate starts for composition and input callbacks from the same action. |
| Deliberate formatting, link insertion, saved-wording insertion, attachment or recipient edit in the active draft | Can qualify as actual composition work through the same local input classification, without revealing which action or data occurred. No separate public activity kind is needed.                                        |
| Focus alone, browser autofocus, opening a conversation, restored/hydrated draft or programmatic content refresh  | Does not start composing. This is crucial because the composer may be mounted/focused automatically while someone merely reads.                                                                                         |
| Short pause to think, correct a value or use the composer toolbar                                                | The existing active cue continues within the inactivity grace; toolbar focus must not cause a start/stop flicker.                                                                                                       |
| Last substantive text deleted                                                                                    | Do not use body nonemptiness as the only composing test: deletion is real composition and a person may be rewriting. The ordinary idle rule still ends it. No draft length is disclosed.                                |
| Inactivity deadline reached while editor remains open                                                            | End this composing episode. Do not replace it with Paused, Away, Last active or Still has a draft. The private draft remains recoverable.                                                                               |
| Reply/note admitted, explicit discard/cancel, conversation/scope exit, logout or loss of source rights           | Stop the episode promptly; no awaiting external email delivery. If admission is unknown, preserve D4 recovery truth separately instead of asserting Sent.                                                               |
| Browser hidden/backgrounded or window loses active interaction                                                   | Stop/suspend publication promptly through the qualified activity policy; do not keep renewing because a tab exists. No passive viewing state appears.                                                                   |
| Reconnect/return with an existing draft                                                                          | Reauthorize, clear stale remote state and require new deliberate composition activity before announcing composition. Restoring a draft or reopening a tab alone is insufficient.                                        |

This event table is product meaning for qualification, not permission to treat every editor transaction as human input. Root's implementation contract must distinguish actual local user operations from hydration, signature background refresh, remote state, undo replay and automated preparation. A user intentionally applying Undo/Redo to their draft is composition; a passive restoration of an old transaction log is not.

Browser evidence matters. Mozilla's [input-event documentation](https://developer.mozilla.org/en-US/docs/Web/API/Element/input_event) and [compositionstart reference](https://developer.mozilla.org/en-US/docs/Web/API/Element/compositionstart_event) distinguish user editing and IME behavior from assumptions based on individual keys. [Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API) documents hidden-page timer throttling and the distinction between visibility and focus. [sendBeacon guidance](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon) explains why unload-style events are unreliable, especially on mobile. Those facts require a server expiry fallback; no close-event handler can prove instantaneous disappearance everywhere.

## Proposed explicit timing envelope

These are **recommended qualification targets**, chosen for email composition and independently adjustable from source/send safety. They are not established by a competitor's settings and must be tested on the supported deployment.

| Timing                        | Proposed value and exact meaning                                                                                                                                                       | Tradeoff                                                                                                                                                                                                                            |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Start publication             | Leading-edge, no intentional wait for a pause; local dispatch target within **150 milliseconds** of the qualifying action on an interactive supported client                           | Makes the cue useful before more parallel drafting. This is a local feedback/dispatch target, not network-delivery proof.                                                                                                           |
| Inactivity grace              | **30 elapsed seconds** since the last qualifying local composition action                                                                                                              | Longer than chat-style two-second stops, reducing flicker while staff think. It can remain visible briefly after somebody stops; it does not promise continuous typing.                                                             |
| Active renewal                | At most once every **5 elapsed seconds** while the composition episode remains eligible                                                                                                | Limits traffic without transmitting each action. Renewals stop on idle/hidden/exit/invalidation; an unchanged open tab cannot renew indefinitely.                                                                                   |
| Server lease                  | **15 elapsed seconds** from the last accepted qualified lease renewal                                                                                                                  | Clears lost-stop/crash states within a bounded server freshness window. It is not a guarantee of fifteen seconds from the real person's last action; delayed/admitted traffic, fencing and client clock handling must be qualified. |
| Explicit stop propagation     | Send immediately on the declared stop; target **p95 ≤1 elapsed second** from a qualifying explicit stop to the observing client's updated cue under the healthy connected test fixture | No success claim from sending a packet alone. Lost/offline events use the lease rule. Idle removal begins at the inactivity deadline, not one second after the last key.                                                            |
| Start-to-observer propagation | Target **p95 ≤1 elapsed second** from qualifying start to correct visible cue under the same healthy connected fixture                                                                 | Gives a measurable low-lag objective. No zero-lag, hard universal upper bound or offline guarantee is asserted.                                                                                                                     |

The fifteen-second lease and thirty-second activity grace are different clocks. While the person remains in the grace period, valid renewals can keep the lease current. At inactivity expiry the publisher stops; if that stop is lost, the existing lease bounds residual display from its last accepted renewal. The actual server/observer protocol must reject stale generations/sequences, expire locally against trustworthy server freshness and prevent delayed old starts from reviving a stopped or changed context. Do not add a second artificial UI minimum-visible time after an authoritative stop merely to smooth animation.

Compared with the recommendation, a two-second idle stop would often blink between phrases and miss thinking time; keeping composition active for an entire open tab would label passive/abandoned work as active. Thirty seconds is a proportionate starting judgment, not a measured optimum. If later measured evidence requires a different value, change the explicit qualified profile and proof together rather than quietly letting clients disagree.

## Display and interaction design

Use one stable inline cue in the current conversation's reader utility area, where it can be noticed while reading and before the first reply action. Preserve D33's Reading/Find location. The cue should not alter global list density, reorder work or add live avatars to every tenant list row. A separate broad queue-presence project is unnecessary to fulfill A.

Recommended copy:

- One peer: **Maya Chen is composing**.
- Several peers: show up to **two permitted display names**, then a compact qualified count; on narrow screens use **3 teammates composing** with a reachable disclosure for the currently permitted names.
- No current eligible cues: no affirmative Nobody is working label. Ordinary conversation content remains.
- Awareness unavailable: a quiet **Live composing cues unavailable** state. Keep existing source/collision protections and composer usable; do not show an all-clear state.

The two-name inline limit is a layout choice, not a presence population or query cap. Do not truncate the underlying authorized peer set or manufacture an exact count from partial coverage. Names use the actual permitted staff identity, not first-name extraction, CRM contact matching, public responder-signature personalization or copied email addresses. Distinct same-name people remain distinguishable through existing authorized identity treatment. If identity cannot be disclosed, the owner must explicitly qualify any generic activity cue rather than using a generic label to leak a forbidden person's existence.

A small disclosure may list only current permitted composers; it has no search, activity history, duration, last-seen or management view. Keep its order stable while the same set remains, rather than reordering on each renewal. Changes should not shift the send action under a pointer, add/remove a tall banner or steal focus. Avoid pulsing avatars, red danger styling and typing dots that imply live keystroke visibility. A neutral icon may supplement text but cannot replace it.

A concise explanation available from the cue can say **Shows recent drafting activity. Drafts stay private.** The ordinary flow does not need a warning panel or acknowledgement each time. Do not offer Wait, Take over, View draft, Stop teammate or Ask to edit actions. The staff member can continue their own authorized draft; actual committed changes trigger the existing collision review.

### Full staff journey

1. Maya reads a permitted Support conversation. This alone publishes no activity. Her D33 reading mode and expanded sections behave normally.
2. Maya deliberately starts writing or editing. A current authorized colleague sees the quiet composition cue promptly, with no draft data.
3. The colleague can avoid duplicating effort or continue distinct authorized work using existing controls. No automatic assignment, status, Follow, notification or coverage change occurs.
4. Maya pauses briefly or uses the draft toolbar. The grace avoids visual flicker. A long idle pause, switching away or leaving ends the cue; it creates no Paused/Away record and does not discard the draft.
5. On an actual reply/note admission the cue stops. Provider-queued/sent/failed facts remain in their existing conversation status path. If two people both attempt to send, current atomic collision protection still decides the safe result.
6. If a network/background event makes awareness uncertain, users receive no false guarantee from a blank area. An explicit unavailable condition is visible when known; stale cues expire and current work remains usable.
7. Returning through CRM or D32 file preview preserves the same permitted draft, reading mode and local view state. Mere return/recovery does not resurrect composition; a new deliberate edit starts a freshly authorized episode.

## Mobile, keyboard and accessibility

IME, dictation, paste and touch toolbar edits must be first-class input. A mouse/Latin-keyboard-only detector would make activity appear inconsistent across international and mobile users. Keyboard navigation, selecting text for reading, opening D33 history or moving focus through controls does not by itself count as composing.

Use Core's actual shared Base UI/Maia primitives, semantic tokens, readable typography and accessible targets. The cue and any name disclosure work in a narrow current conversation, at text zoom and with mixed RTL/LTR names. Do not copy a vendor's hover-only tooltip or color-only composing border. The presence element is not a clickable person/CRM access shortcut unless that existing action is independently authorized.

W3C's [status-message guidance](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) supports making meaningful changes available to assistive technology without taking focus or unnecessarily interrupting work. Announce a meaningful aggregate composing change politely; **do not announce every heartbeat or keystroke**. Duplicate or same-state renewals produce no new spoken message. A disappearing cue must not be announced as confirmation that nobody is working; a quiet **Composing cue ended** is more accurate where an announcement is needed. Actual screen-reader testing should tune aggregation without delaying visual freshness or adding a new notification-preference matrix.

Do not depend on a background mobile timer firing exactly on schedule. Visibility change, app suspension, lost connection and wake/resume must be tested against server expiry. No permanent offline history, background polling of all conversations or real-time activity capture after logout is needed. Existing native/browser lifecycle limits remain observable rather than hidden behind a universal accuracy promise.

## Privacy, source and product boundaries

Every published/observed cue needs current tenant, real staff identity and exact qualified conversation/source scope. CRM links, shared addresses, assignment or a continuing merged root do not automatically entitle someone to another original source's activity. Do not collapse differently authorized source contexts into one public room merely because the UI groups them. Current source loss, move/merge/Undo and identity changes invalidate stale signals without turning absence into an inaccessible-peer hint.

D2 private drafts remain private, including notes. D15's no viewing/read-surveillance roster stays intact: A does not expose passive readers, last access, duration or reading analytics. D6/D7 work availability and coverage remain explicit owner facts. D33 default/disclosure state is unaffected. P17/P6 preparation/dispatch, public signature identity, requester notifications and D32 bytes remain separate; no cue authorizes a message, refresh, attachment retrieval or CRM action.

Minimal short-lived technical state is sufficient. No activity timeline, typing statistics, per-person productivity metrics, per-click business audit, third-party draft telemetry or durable event queue is justified by this cue. A malicious or mistaken authorized client may falsely claim composition; because the cue conveys no lock/authority, it cannot directly prevent work or bypass controls. The security contract must nevertheless prevent forged other-person/tenant/source state and unbounded publication.

## Independent disposition

**Accept A with required amendments.** A brief current composing cue is a useful addition when it remains neutral, private, bounded and independent of authoritative work. The proposed thirty-second inactivity grace, five-second renewal, fifteen-second lease and connected one-second p95 visibility target are a concrete starting envelope for qualification, not an industry standard or zero-lag guarantee.

The parent should reconcile the exact timing/identity/protocol values in its final source/data/UX contract and require browser, input-method, current-authorization, multi-session, failure, accessibility and production-shaped latency proof. No Asym presence runtime, lease protocol, staff task-time improvement or perfect accuracy was demonstrated by this research. The product is not complete until those actual outcomes are proved; neither a vendor indicator nor a polished mock is that evidence.
