# D32 — Broader attachment viewing: renderer and owner review

**13 September 2026. C — Broader document previews is selected; D1–D31 remain fully ratified. Disposition: Accept with required amendments.** This independent review supplies the permanent processing and ownership contract for the D32 synthesis. It is grooming evidence, not a deployment, library installation, renderer qualification, security certification or proof that any current attachment route works.

The proportionate permanent solution is a shared, privately operated attachment-preview capability: current source authorization, an isolated processing worker, bounded format-specific representations and one passive viewer. DOCX/PPTX may become static PDF previews; XLSX needs a saved-value sheet projection rather than a print rendition. Exact implementation builds are engineering release evidence. Choosing and qualifying them does not require another product-scope vote, but an unqualified build must not be exposed as complete support for the selected format.

## Current primary technical evidence and alternatives

All external documents below were opened on 13 September 2026. Vendor behavior supports a candidate, not Asym conformance. No attachment was sent to any vendor, no package was installed and no conversion or browser execution was performed.

**Gotenberg/LibreOffice is the strongest initial candidate for privately operated DOCX/PPTX conversion.** Gotenberg's upload route accepts Office documents and returns PDF. Its documentation explicitly warns that linked content is dropped from untrusted uploads in recent versions even when conversion succeeds. Its single-page sheet mode ignores print ranges and hidden-sheet status. These are reasons to qualify static document/slide output carefully and avoid spreadsheet print previews. The API's much broader supported-format list does not become Asym's allow-list. [Conversion behavior](https://gotenberg.dev/docs/convert-with-libreoffice/convert-to-pdf)

Current Gotenberg **8.37.0**, released 11 September 2026, is pinned for research to commit `430ed38cc545e301603aa6fdb1efbacba587eff4`. Release notes identify LibreOffice 26.8.0 and unoconverter 0.5.0, security fixes and a prior missing-math dependency that could drop DOCX content. This makes the exact image, fonts and bundled dependencies material qualification inputs; it does not mean that today's newest release has passed Asym's corpus. [Exact release](https://github.com/gotenberg/gotenberg/releases/tag/v8.37.0)

Gotenberg defaults are not the desired production policy: outbound filtering is permissive, the request-body limit is unset, and a LibreOffice instance serializes work while its queue limit defaults to disabled. Disable unused URL-download/webhook/routes and independently deny worker egress; impose bounded queues and process resource limits. Configure any postprocessor chain explicitly so output is not determined by whichever engine happens to succeed. [Configuration](https://gotenberg.dev/docs/configuration)

**A maintained, locally bundled PDF.js display/viewer integration is the strongest initial PDF-viewer candidate.** Official stable release **6.3.289** was checked at commit `1c8020a7d4e43668ac287a3ecf9a8dbea17e4c56`. Its layered API allows a controlled application viewer, but shipping the generic full viewer unchanged does not establish a passive interface or current source authorization. Core and worker assets must match. A browser worker improves responsiveness; it is not proof of isolation from hostile inputs. [Getting started](https://mozilla.github.io/pdf.js/getting_started/), [exact release](https://github.com/mozilla/pdf.js/releases/tag/v6.3.289)

**An isolated XLSX parser plus a plain, bounded grid is preferable to an Office rendering engine.** SheetJS CE distinguishes raw values, formatted values and formula expressions; it does not automatically compute formula results. A formula with no saved result must remain unavailable. Use saved values with correct sheet/cell coordinates and disclose the static projection. [Cell model](https://docs.sheetjs.com/docs/csf/cell/), [formula behavior](https://docs.sheetjs.com/docs/csf/features/formulae/)

SheetJS's current official installation documentation names **0.20.3** at its authoritative CDN and reports the npm `xlsx` endpoint as stale at 0.18.5. This is an explicit supply-chain pitfall: resolve the exact official artifact and digest during qualification, rather than blindly adding an npm package called `xlsx`. This review does not endorse suppressing vulnerability reports simply because vendor guidance suggests it. [Installation and distribution](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)

Parser defaults also need a product profile. SheetJS's `raw` parsing choice for text does not make every XLSX value a raw string; worksheet limits and error behavior require care. Render extracted scalar data as escaped text, not its optional HTML output. A row limit alone does not establish a bound on archive expansion, parser memory or all sheets. [Parse options](https://docs.sheetjs.com/docs/api/parse-options/)

**Remote Microsoft viewing is not a default substitute for Core's byte boundary.** The Graph preview API currently supports SharePoint and OneDrive for Business and returns a short-lived embed URL that acts with the caller's permissions. Using it would add Microsoft custody/identity/authorization requirements to an Asym attachment. It can suit files already governed there, but does not justify exposing private Core file URLs to an anonymous Office viewer or silently uploading copies. [Microsoft Graph preview, updated 27 January 2026](https://learn.microsoft.com/en-us/graph/api/driveitem-preview?view=graph-rest-1.0)

## Required owner and format amendments

Severity and likelihood below describe an underspecified implementation, not measured Asym incident frequency. Each clause narrows or completes C rather than creating a new file-management product.

### O32-01 — Source bytes remain authoritative

**Material concern: high severity, plausible.** An attractive converted PDF can be mistaken for the original receipt, spreadsheet evidence or an official regenerated document, changing meaning and audit history.

**Exact language:** “An attachment preview is a disposable representation of one immutable source attachment version. It preserves source identity, digest, content generation and representation-profile provenance. It does not create a P18 publication, facts package, generation request, issuance, canonical artifact, P19 statement run, CRM document copy or financial fact. Download original returns only the source owner's exact qualified original bytes.”

**Proof:** Opening from Support and the same authorized CRM detail returns the same source identity. Conversion/retry creates no business document, CRM mutation, task or issuance. A changed source version cannot reuse a prior derivative under the new identity.

### O32-02 — Explicit initial matrix and honest coverage

**Material concern: medium severity, likely.** Advertising generic “Office support” imports legacy, macro-enabled, encrypted and active formats that have not passed safety/fidelity tests.

**Exact language:** “Initial preview families are PNG, JPEG, WebP, static GIF, PDF, DOCX, XLSX, PPTX, TXT and CSV, each subject to its qualified content profile and finite limits. Extension and sender MIME are hints, not proof. Legacy Office, macro-enabled content, encrypted/password-protected content and other unqualified formats are unsupported for preview. Preview unavailability neither grants nor automatically denies a separately qualified original download.”

Qualification must detect format/container mismatch and macro payloads even under a renamed allowed extension. Animated GIF does not silently enter the static-GIF family. Unsafe, restricted and unsupported are distinct outcomes. No new password collection/decryption or legacy-format expansion is needed.

### O32-03 — One private processing boundary

**Material concern: critical severity, plausible.** Arbitrary document parsers can read local files, request intranet/metadata URLs, execute active content or consume all process memory. A scanner pass does not prove a safe parser invocation.

**Exact language:** “The shared preview boundary accepts server-issued source identities and qualified processing profiles, never caller-supplied fetch URLs, paths, credentials, command options or arbitrary converter endpoints. It supplies only the authorized immutable input to an isolated, nonprivileged worker with no application secrets, no external/local-network fetch authority, bounded resources and private per-job temporary custody. Unused converter routes, callbacks, URL download, active scripts/macros and embedded execution are disabled. Conversion output remains untrusted until validated.”

A private service wrapper, constrained process/container and existing shared job infrastructure are sufficient; no tenant-installed converter, general execution engine or public conversion API is needed. State and temp/profile separation must prevent a prior tenant's document from becoming another tenant's input or output.

### O32-04 — DOCX/PPTX are static approximations

**Material concern: high severity, plausible.** Fonts, layout, charts, math, missing linked content, comments, tracked changes, slide notes, hidden slides and embedded objects can change or disappear without a transport error. A generic warning cannot excuse an undetected known destructive transformation.

**Exact language:** “DOCX and PPTX previews are read-only static representations. The qualified profile freezes fonts, locale, layout/content options and treatment of revisions, notes, hidden content and embedded objects. It never refreshes external resources or runs embedded code. The viewer states that formatting may differ and identifies known omitted or unsupported content. When the profile cannot produce an intelligible, honestly described representation, preview fails or is unsupported; it never claims complete fidelity because conversion returned success.”

Use main document/visible-slide content as the ordinary inspection surface; do not unexpectedly expand comments, deleted revision text, notes or hidden slides. Coverage must disclose excluded content. This is not a document editor or a legal comparison tool. Exact treatment is tested in the declared per-format profile, not changed by arbitrary per-request flags.

### O32-05 — XLSX is saved values, never a calculator

**Material concern: high severity, likely.** Print ranges omit data; hidden sheets can be unintentionally expanded; formula caches can be stale/absent; date and identifier coercion can alter interpretation.

**Exact language:** “XLSX preview presents a bounded read-only projection of saved cell values with sheet identity and original row/column coordinates. It does not calculate formulas, refresh links, execute macros, import data or assert that cached results are current. Missing cached results display unavailable, distinct from empty cells, zero and formula errors. Formatting must not silently coerce identifiers, dates or numeric precision into different values. Hidden content and truncated/unsupported ranges are explicitly distinguished from visible complete coverage.”

The default must respect normal visible sheet/range presentation instead of silently unfolding hidden data. A hidden-content warning is not a new row/column authorization model: qualified original access already concerns the whole attachment. Selecting supported sheets is reading, not modifying the file. Charts, pivots, images and other features outside the value projection must be disclosed rather than represented as independently verified calculations.

### O32-06 — TXT/CSV are escaped inspection, not import

**Material concern: medium severity, likely.** Treating CSV as a spreadsheet can run formulas, lose leading zeros, change dates or misparse quoting/newlines. Guessing an encoding/delimiter can produce a plausible wrong table.

**Exact language:** “TXT is bounded escaped text with qualified encoding/newline handling. CSV is a bounded parsed text-cell table: no formulas, automatic numeric/date conversion, HTML interpretation or external links. Preserve cell positions, duplicate/empty headers and quoted delimiters/newlines. Ambiguous or invalid parsing must be disclosed or unsupported; it must not invent a successful import or silently alter source data.”

No general import mapper, delimiter workflow platform or automatic CRM update follows from preview. Native semantic text/table controls are appropriate; Tiptap is not required for these read-only cells.

### O32-07 — Passive PDF and image viewing

**Material concern: high severity, plausible.** The generic viewer may expose scripting, form mutation, links, embedded files, print/download and unsupported active layers; a canvas-only display can exclude assistive-technology users.

**Exact language:** “The application viewer is passive and read-only, with qualified page/image navigation and accessible controls. It does not execute document actions/scripts, edit form fields, launch embedded attachments, follow external URLs automatically or expose an unguarded native Download/Print/Share path. Supported static annotation/form appearances must not silently disappear. Original download remains the distinct application action under current source authority. Image decoding is bounded and produces only the qualified static presentation.”

Do not indiscriminately hide every PDF annotation and thereby remove a filled value that is necessary to understand a document; qualify static appearances. Preserve a text/semantic layer where available. Scanned PDFs without readable text are reported honestly; OCR is not added. Canvas, a browser worker and an iframe each solve different problems and are not a security/accessibility certificate.

### O32-08 — Access is rechecked for every representation

**Material concern: critical severity, plausible.** A preview URL, page tile, byte-range route, CDN cache or storage capability can survive a conversation restriction, mailbox permission change or content redaction.

**Exact language:** “Current tenant/source authorization and content/hygiene disposition gate preview admission and every subsequent metadata, original-byte, derivative, page/range and retry access. Cache keys include tenant, immutable source version and qualified representation profile; hash equality across tenants is not an access grant. Private delivery obeys D16's access-time and no-store contract. A reusable upstream/provider URL is never exposed as the authority.”

Loss of authority stops future access and best-effort ongoing work/streams under the existing contract. The product must not promise recall of pixels or bytes already received by the device. A direct link from CRM is navigation, not authority. Filename discoverability under D22 must not bypass this gate.

### O32-09 — Restriction wins over late completion

**Material concern: high severity, plausible.** A conversion started before expiry/redaction can finish afterward and repopulate a cache, search result or “Ready” UI with restricted content.

**Exact language:** “A processing attempt is bound to the source's current content/safety generation. Final promotion verifies that generation and the owning retention/disposition again. A late completion after restriction is discarded and cleaned up; retries cannot resurrect it. Original and all derived bytes/text/temp files obey the source's retention and purge policy, while only permitted content-free audit evidence survives.”

Preview is not a retention extension, a new source of truth or a source for D22 indexing. A representation may be regenerated only while the exact original and current purpose remain eligible; never rebuild from expired private copies or preserved logs.

### O32-10 — Bounded work and truthful failure

**Material concern: high severity, likely without limits.** ZIP expansion, huge worksheet dimensions, images, fonts, recursion, nested objects and long-running conversion can overload a web server or starve other tenants. Unlimited retry can repeat permanent resource failures.

**Exact language:** “Each qualified format profile declares enforced finite input/decompressed-byte, archive-entry/depth, image-pixel, page/sheet/cell, CPU, memory, wall-time, queue and concurrency limits as applicable. Enforcement precedes dangerous allocation where possible and remains enforced by the process boundary. Work is asynchronous, tenant-fair and idempotent for the same source/profile generation. Retry is bounded and distinguishes permanent rejection from transient processing failure.”

The root's quantitative contract must use declared units and boundary tests; this review does not invent evidence that a particular volume is safe. Unsupported, hygiene pending, blocked/restricted, processing, failed and ready-with-coverage-warning must not collapse into a misleading single success state. Retry never silently changes engines or uploads to another provider. Eligible Download is offered deliberately, not automatically triggered.

### O32-11 — Email Studio and Tiptap remain separate

**Material concern: high severity, plausible.** Opening a preview could be treated as permission to attach a converted file, import its text into a reply, publish a reusable asset or feed model/search retrieval.

**Exact language:** “D32 viewing creates no P17 message preparation, P6 dispatch, provider event, template publication, saved-reply change, signature change, recipient change or attachment to a draft. Tiptap continues existing authoring purpose profiles; it does not parse arbitrary Office/PDF files. Any later deliberate attachment action uses the already qualified source/asset/preparation/send contract and current recipient/disclosure checks. Preview derivatives are not automatically promoted to email assets or authoritative documents.”

No new email purpose or provider credential follows from file inspection. P17/P6 outages do not need to disable already qualified private viewing, and a converter outage does not disable ordinary replies. Viewing does not complete a giving/receipt/refund action or create evidence of customer delivery.

### O32-12 — One engineering qualification contract

**Material concern: high severity, plausible.** Floating builds, arbitrary converter options, undocumented fonts or a silent fallback can change output across retries and make a security patch impossible to assess.

**Exact language:** “The release identifies one qualified representation profile for each supported family, with exact parser/renderer/image versions, assets, locales/options, complete dependency/license inventory, corpus and limits. Unknown or failed mandatory evidence keeps the affected profile unavailable; it does not weaken source access or silently switch processing implementations. A material engine/profile change reruns the corpus, obtains a new profile identity and prevents stale representation reuse.”

A profile identifier and narrow shared adapter suffice; do not build a tenant-configurable renderer registry or recreate P18's official-document contest. Security rollback may return only to a still-qualified safe build. If none is safe, disable the affected preview and retain truthful independently eligible download. Exact release selection is ordinary implementation evidence within C, not a dangling user decision.

## Required proof before activation

These are falsifiable acceptance groups, not executed tests. The root's full D32 review owns the final merged identifiers and numerical boundaries.

1. **Same source, no side effects:** Support/CRM entry reaches the same qualified attachment; no P18/P19/CRM/financial/task/P17/P6 authority is created or changed by preview. Download returns the exact original digest, not its preview.
2. **Format admission:** extension/MIME spoofing, renamed macro payloads, encrypted files, malformed ZIPs, legacy formats and animated GIF do not pass as a qualified allowed family. Unsupported is distinct from unsafe.
3. **Isolation:** hostile external relationship/file paths, network/metadata requests, scripts/macros, XML entities, parser paths and converter callbacks cannot escape the worker. No app/provider credentials are present. A second tenant never sees temp data from the first.
4. **DOCX/PPTX meaning:** multilingual/RTL/CJK text, licensed/missing fonts, math, tables, long documents, notes/hidden slides, tracked changes, embedded charts and missing linked content produce the declared representation/coverage or a truthful failure. A success response alone is insufficient.
5. **XLSX meaning:** multiple/hidden sheets, empty/hidden rows, sparse dimensions, merged cells, leading-zero identifiers, very large numbers, dates/date-system cases, errors, cached/uncached formulas, external references and chart-only sheets preserve or disclose their declared projection. Nothing is recalculated or refreshed.
6. **TXT/CSV meaning:** Unicode, invalid encoding, BOM, quoted commas/newlines, duplicate/empty headers, empty cells, leading zeros and formula-looking text are inert and positionally correct; unsupported ambiguity is not silently guessed.
7. **Passive viewer and access:** no active document capability or hidden viewer control bypasses current source access. PDF form/annotation static appearances are correct or explicitly unsupported. Text/semantic navigation and the actual supported assistive/browser/mobile matrix pass; a scan is not falsely described as searchable text.
8. **Access races:** revoke, move, merge, change tenant/inbox permission, expire, redact and delete during queueing, conversion, ready state and byte/page/range requests. Late completion cannot promote or resurrect content, and no reusable link bypasses the restriction.
9. **Bounds and fairness:** exact-limit and one-over tests cover all declared units, plus compressed-resource bombs and concurrent tenants. No partial table/document silently claims full coverage. Cancellation and bounded retry release resources.
10. **Dependency change:** upgrade parser/renderer/font/profile with old and new workers/caches present; mismatched jobs or assets cannot be promoted as qualified. Previous unsafe build is not a fallback. License/SBOM and output corpus evidence attach to the actual deployment digest.
11. **Custody and logs:** originals, representations, extracted cell/text data, temp files, debug dumps and provider/worker diagnostics obey the declared source retention and content-minimization policy. No content enters D22, AI, a public asset store or telemetry.
12. **Real production-shaped qualification:** complete selected-format corpus, failures, source-auth/browser/range/CRM journeys and load tests against the actual chosen deployment. Source/document research is not substituted for these results.

## Synthesis and disposition

**Accept with required amendments.** Preserve C with the explicit bounded matrix and permanent private worker/viewer contract above. The source/byte/derivative distinction, XLSX saved-values semantics, passive rendering and current-authority fencing must be settled in the D32 decision before it is recorded as complete. The chosen engineering build, exact capacity evidence, dependency/renderer qualification and actual browser/assistive journeys are mandatory implementation release work, not permission to postpone safety or another product-choice interview.

Implement the narrow shared byte/preview contract first, qualify one profile per family, then expose the same viewer from Support and authorized CRM detail. Keep P18 generated-document authority, P17 email preparation, P6 dispatch, Tiptap authoring and P29 future file-management breadth separate. There is no justified dependency on a full File Manager, Office collaboration suite, new document editor, AI extraction pipeline or universal file-conversion platform.

No new monitor-only exception is proposed in this owner review: source leaks, unsafe processing, incorrect meaning and missing activation evidence are release failures. Root's operational controls should name owners/signals/thresholds for the bounded runtime queues, failed profile rates, purge lag and vulnerabilities after the safety contract is implemented. This review has established source and design constraints only; it has not proved any parser, renderer, provider, database route or UI safe in execution.
