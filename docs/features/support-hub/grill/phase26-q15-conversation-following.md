## The next single decision

**How should a colleague stay informed about a Support conversation without taking over responsibility?**

Illustrative example: Alex handles Maya's receipt question. Sam adds an internal note that helps Alex answer. Sam wants to see Maya's eventual response, while Alex remains responsible for Support follow-up. Sam should not need to take the assignment, add their address to the donor's email, or post a fake self-mention merely to keep track. This example tests the design; it is not evidence of measured ministry behavior.

A direct mention asks for attention to a particular contribution. Responsibility establishes who owes the actual work. Following expresses optional continuing interest. Personal delivery preferences decide permitted channels. Current permissions decide what can be shown. These are different facts.

## Three meaningful alternatives

| Option                                                  | What Sam experiences                                                                                                                                                                                   | Strongest benefit                                                                           | Main tradeoff                                                                                                                      |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **A — Deliberately follow conversations (recommended)** | Sam selects **Follow conversation** when continued updates are useful, and **Stop following conversation** when they are no longer wanted. Replying or adding a note alone does not enroll Sam.        | Clear personal control; supports continuing collaboration without surprising subscriptions. | Requires one deliberate action to start following.                                                                                 |
| **B — Direct attention only**                           | Sam receives relevant directed attention through qualified mention/responsibility contracts, but has no ongoing Follow feature. Sam revisits existing views/search or asks Alex to mention them again. | Smallest additional state and least optional notification traffic.                          | More remembering and repeated coordination when a colleague wants the eventual outcome.                                            |
| **C — Automatically follow after participating**        | A human reply or internal note automatically starts ongoing following; Sam can explicitly stop. Merely viewing a conversation does not enroll Sam.                                                     | Saves the initial Follow action and keeps active contributors informed.                     | Helping once may produce unwanted future updates; enrollment and the precedence of an explicit stop need unusually clear behavior. |

All three retain source-qualified attention already required by D11/D12, accountable shared queues and D14's quiet due review. B does not remove required assistance or custody attention. Ordinary assignment/mention event eligibility still requires its exact producer contract; existing UI toggles are not evidence that those contracts are already implemented. No option blasts every new Unassigned conversation to every team member.

These are alternative launch postures. Offering all three does not select a new tenant or personal configuration matrix. Any founder amendment can be pressure-tested with the selected answer.

## Single best recommendation

**A — Deliberately follow conversations.**

Asym already keeps the Support coordinator responsible while colleagues help with bounded work. A gives those colleagues an intentional way to see what happens next, without making every helpful note an enduring subscription. One clear action is a proportionate cost for predictable ongoing updates. B is the strongest smaller alternative; C favors convenience when participation usually means continuing interest, which has not been established for Asym's users.

Use a compact, text-labelled **Follow conversation → Following** control in the existing conversation action area. Its stop action remains available in the same place; a tooltip is not the only explanation or way to stop. Suggested helper: **Get updates about this conversation. Assignment stays with Alex.** For shared handling, name the responsible inbox instead. A small **Notification preferences** link uses the existing shared settings. No routine confirmation modal, avatar wall, read-surveillance display or new personal Open/Waiting/Resolved lifecycle is needed.

The stop helper is explicit: **Stops optional updates for you. It does not change who handles the conversation or stop required attention.** Stopping does not recall already-authorized email or delete historical evidence. Under C, automatic Following would need to be plainly visible and equally easy to stop.

The same authorized control can be reached when opening Support from a CRM record, with the user's return location and draft preserved. Following a conversation does not follow the CRM record, every related conversation, a delegated task, or all conversations involving the same person.

Explicit following is documented in [HubSpot's help desk](https://knowledge.hubspot.com/help-desk/manage-tickets-in-help-desk) and [Help Scout](https://docs.helpscout.com/article/671-follow-a-conversation). [Front](https://help.front.com/en/articles/2198) demonstrates the strongest competing auto-subscription model and its additional entry/exit rules. [Intercom's current guide](https://www.intercom.com/help/en/articles/187-how-teammates-get-notifications) documents no per-conversation Follow and suggests self-mentioning as a workaround. There is no universal vendor consensus on auto-follow; A is the recommended Asym product judgment.

## Boundaries that remain settled

- Following is optional staff interest, never Support ownership, a new task, reply coverage, requester To/Cc membership, CRM relationship, representation authority or an access grant.
- The shared P17 notification center, engagement model, preferences and presentation policies remain authoritative. An ordinary informational follower update cannot become required work merely because it is unread. Required source attention stays independently actionable.
- Stopping optional following cannot suppress a separately qualified direct mention, assistance/custody result or current work duty. Reading, dismissing or archiving a notice cannot resolve Support, clear a reminder or finish Finance work.
- D14 does not gain per-target alerts, Due soon emails or a ticking stream of follower updates. A technical delivery event, timer tick or unrelated CRM edit is not automatically meaningful follower activity.
- D12 related conversations do not inherit followers. D10 merge/Undo must preserve exact original/source intent and current access, rather than widening a follower to previously unrelated or restricted material. This includes later sources added to an already-followed merged view.
- Distinguish **Stop following conversation** from D11's **Stop following this work**, which ends Support's interest in a delegated action. Neither phrase should ambiguously operate the other control.
- Source-qualified in-product updates reuse P17/P6. Any optional staff email needs its own qualified source plan and the existing Email Studio/P6/Resend path. Following alone does not authorize a channel, template, arbitrary notification email or provider send.

## Pressure cases for the selected answer's full review

The answer review must settle a finite useful event set, self-generated updates, overlapping recipient reasons, clear Follow/Stop persistence, current access and revocation, subscription scope through D10/D12, provider uncertainty, source-end/reopen behavior, concurrent stop/event processing, and effect-free migration. Existing P17 grouping must preserve each source purpose while preventing duplicate presentation or emails for the same qualified effect; distinct required occurrences must not be collapsed just because the recipient and time coincide.

Test a colleague who helps once; a follower who later becomes the handler; a former handler who still wants permitted updates; direct mention after explicit Stop; a new requester reply after Resolve; revoked access between admission and display; merged originals with different follow scopes; Undo and continued work; and one source event qualifying through more than one recipient reason. These are foreseeable dependencies, not new ratified D15 rules or a reason to require a broad workflow platform.
