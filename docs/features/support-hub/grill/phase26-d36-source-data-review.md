## Minimal permanent data and preparation contract

These are logical invariants and exact proposed requirement language. They do not mandate new table names or a second quote/history service.

**C01 — One canonical reply draft.** “New ordinary external Support replies contain newly authored content and the governed signature/footer, with no automatically appended earlier body. A deliberate quote is part of that same private canonical draft, not a live reference expanded at Send, another email, a CRM note, a Saved Section or a new transcript.”

**C02 — Exact original source.** “Quote insertion names an admitted external email's stable tenant/original/message identity and current canonical content revision. The source-read command derives tenant/actor from trusted context, checks current staff read/use authority and source privacy/expiry, and derives the selected content from that canonical revision. Caller HTML, DOM offsets, snippets, body strings, source URLs and search hits are not authority. Reply-target identity and quote-source identity remain distinct; selecting a quote never retargets the reply.”

**C03 — Proportionate source eligibility.** “The normal quote action uses the eligible external email already in the current source context. An explicitly chosen earlier eligible email may be quoted without synthesizing a whole merged transcript. No internal notes/revisions, staff guidance, private drafts, unrelated merged/linked histories, CRM/care/giving data or files enter this action merely because staff can see them. The command does not search a person's other records or create a new customer model.”

**C04 — Disclosure is not an email recipient's staff ACL.** “Staff source-read/use authority and permission to disclose the selected content to the explicit outgoing audience are distinct checks. Ordinary permitted external correspondents do not need a staff account, CRM record or Support source-read permission. Apply the existing D2 source/recipient/classification and protected-record disclosure rules to the actual reviewed content; preserve legitimate Reply-all and deliberate recipient editing. Adding an endpoint requires requalifying existing quotes and any required concrete audience review, not a blanket denial or universal approval modal.”

**C05 — Preserve exact reviewed meaning.** “Keep quoted literal text inert. Do not resolve merge variables, @mentions, CRM values, protected actions or script/URI commands found in quoted content. Do not fetch remote images or attach historical files. Preserve safe line/block/Unicode order, semantic quotations and permitted visible text; disclose material omissions. Existing embedded signature/address text is content to review, not an instruction to reconstruct extra headers or silently strip signatures.”

**C06 — Stable bounded provenance.** “Bind each source-derived quote occurrence to the draft, exact source revision, selected canonical range/content descriptor, qualified rendering profile and destination/review generation. Its protected dependency follows supported draft save/restore, editor Undo and relevant derivations into preparation. Use exact owner IDs/types and same-tenant constraints, not source-email/name/text matching. Do not add original quote bodies to immutable audit logs; the governed canonical draft/preparation owns necessary content custody.”

The chosen editing interaction must make provenance preservation feasible. A reviewed source excerpt or protected quote block is simpler to qualify than arbitrary HTML replay. If supported quote edits cannot retain precise mapping, conservatively keep the whole originating-source dependency for the candidate and require clean review after a source stop. Do not erase lineage by converting a block type or accepting spoofed hidden editor attributes. This is not a demand for character-level source graphs or universal clipboard detection.

**C07 — Save as one effect.** “The existing draft command atomically persists the canonical document, active quote dependencies and current draft revision; no Saved state is returned for body-only success. Conditional revisions prevent late insertion/save/remove from overwriting newer work. A replay of the same save/quote intent cannot duplicate a quote, restore a deliberately removed quote or change another draft. An identical durable outcome is distinguishable from the latest draft state.”

The implementation can use existing draft CAS and local insertion transaction identities; it does not need a quote ledger per click. A unique logical source occurrence or editor transaction token should dedupe a retried insertion, while deliberate repeated quotation remains an explicit authored choice if the product allows it. Do not dedupe solely by equal text; two different emails may intentionally say the same thing.

**C08 — Source changes are explicit.** “A new incoming email, source reclassification, merge/unmerge, changed Party/contact, changed response endpoint or inbox move cannot replace the chosen quote or reply target. Changed actual content/source/disclosure authority invalidates affected quoted material and preparation. Preserve separable authored text and explain a targeted repair. A late fetch cannot insert into another tenant, conversation, draft, compose mode or obsolete editor revision.”

**C09 — Current privacy/retention fences.** “D16/D17 govern known source-derived quote copies. Restriction/expiry prevents future quote reads, restored draft use, preparation and new dispatch even when worker cleanup lags. Copying material into a draft is not native publication, new purpose or a renewed source lifetime. An actual admitted reply keeps D17's qualified native-admission semantics without automatically renewing a different linked original merely because it was quoted. No snapshot/Undo/old writer recreates withdrawn material.”

“Preserve the distinction between tracked source-derived representations and independently authored/received quoted emails. Do not claim a D16 operation erased every occurrence everywhere or silently rewrite separately owned sent evidence. Known derived content must be enrolled in the existing finite representation/correction inventory; when admitted copies are independent evidence, the actual privacy/records owner governs their correction. Identify affected original/representation in review and preserve factual communication outcomes. Recipient mail already sent is not remotely recalled.”

This is the required reconciliation with D16's scope. A global cascade deleting every matching quote would contradict accepted independent-evidence protection. Conversely, dropping all dependencies at admission would let prepared/Recent/source-backed views resurrect restricted data. The later schema must classify each actual materialization explicitly and prove its disposal/restriction owner.

**C10 — P17 prepares what staff reviewed.** “Support qualifies exact source/actor/target/audience and draft generation. Email Studio/P17 validates the complete compatible structured document, source references, signature/footer, assets and subject, then freezes canonical HTML and real plain text plus exact dependency/source evidence through its existing preparation contract. No quote is added by a mutable template token, provider template, a second Support serializer or late history query. Source IDs and private admin URLs are not accidentally transmitted as attribution.”

**C11 — P6 dispatch and immutable recovery.** “Before P6 admits actual dispatching, current source stop/expiry and disclosure fences must still pass for the sealed material. Serialize competing stop/dispatch admission using the existing owner guard/claim protocol, not a check-then-network promise. A stop winning first blocks submission. A dispatch admitted earlier may be in flight/accepted/unknown; preserve that exact evidence and prohibit unsafe later payload-bearing retries. Never edit, split, regenerate or rekey an already sealed/possibly submitted envelope to remove a quote.”

**C12 — CRM continuity.** “The same source-owned reply composer and current quote behavior work when entered from an authorized CRM Support conversation. Restore CRM/list/draft context on return. Quote addition/removal/save creates no Party/contact, relevance link, communication event, last-contact update, donor reply, giving action or work-resolution claim. A real admitted send projects through the one existing P6/Support lineage and D9 read model with its actual recipient outcomes.”

**C13 — Database access closure.** “Store source/draft/preparation references using tenant-aware endpoint constraints and immutable identity/actor fields. Versioned closed JSON/schema validates source node/selection/profile/state, finite size/depth and canonical body/dependency parity before persistence. Raw quote/dependency/control data is not directly editable through browser table grants. Current exact-source/privacy/disclosure checks apply in the canonical command and all views, RPCs, definer/service-role paths, exports and storage representations. No added permissive policy can preserve the old broad mutation route.”

“If direct reads are admitted, they must exclude private drafts and inaccessible source IDs/content/existence before pagination/counting. Updates must not change tenant, original source, author, destination owner or accepted-send identity. Both old-row and allowed-result checks must be effective, whether explicit or inherited, and qualified DB constraints must prevent invalid endpoint/state combinations. Deletion cannot cascade into original messages, CRM/giving records or required effect/replay evidence.”

**C14 — Limited resource and outage scope.** “Read/quote one explicit bounded eligible source or selection; never fetch the entire conversation merely to add context. Use existing qualified source/editor/complete-message budgets and validate decoded/serialized sizes before insertion, save and preparation; publish exact profile limits and test equality plus one-unit-over behavior. Do not silently truncate a quote and label it complete. Oversized/unavailable quote work leaves the existing draft usable and adds no quote; current source-disclosure failure must not expose a prohibited preview.”

No new numerical universal byte limit is needed in this subreview. Parent may propose a qualified finite profile, but it must distinguish a new engineering target from existing vendor or intake/send capacities. Source-conversion latency is not typing latency: ordinary typing/send-without-quote should not depend on retrieving history.

**C15 — Compatible activation.** “Qualify canonical source conversion, editor round-trip, private draft CAS, source dependency inventory, complete preparation, current dispatch fences and all old writer/read paths before enabling quotes. Existing source-incompatible drafts remain readable/repairable under current permission rather than silently stripped/autosaved. Do not invent provenance on legacy body text, create mass duplicate history, or migrate by email/subject matching. Old readers must reject unsupported canonical versions. A kill switch stops new quote acquisition/preparation without altering possibly sent effects or removing existing source stops.”

## Required proof and ownership before activation

This review executed source reads, official-doc checks and documentary analysis only. The following are required independently falsifiable tests, **not passed runtime evidence**:

1. New Support and CRM-entry draft has no automatic historical text; correct governed signature/footer and D2 headers/recipients remain. Nonstaff requester and legitimate group reply succeed without a CRM identity.
2. Exact selected source and excerpt survive editor save/restore/Undo/remove/retry; source/quote choice never changes the D2 target. Two identical phrases in one source and in different messages remain distinct.
3. `{{donor.name}}`, HTML, escaped tags, @names, URLs, bidirectional text, Thai combining characters, emoji and MIME/HTML alternatives remain literal/safe with consistent HTML/plain-text output. No network resource request or recipient mutation comes from quote rendering.
4. Forged other-tenant/message/source revision/author/draft owner, note/history source, direct table write and raw HTML route fail; all protected views/RPCs/service-role/storage paths enforce equivalent policy. Include same-tenant staff with different source scopes, revoked access, guest/anon and actual current super-admin policy rather than assuming universal bypass.
5. Quote read or insertion races with draft recipient/target change, tenant/logout/navigation, another-tab save, explicit removal and changed editor revision; late response never changes newer work. Ambiguous persisted save reconciles original outcome without duplication.
6. Exact quote source redaction/expiry races with save, restore, preparation, envelope seal and P6 dispatching. Test deadline equality and delayed cleanup; affected quote remains unavailable while separable response survives.
7. Actual send-before-stop records possible acceptance/unknown honestly; no new-key/rewritten-envelope retry. A sealed multi-member envelope cannot be partially cleaned and resent.
8. Canonical outgoing review, prepared HTML/plain text and actual qualified email transport bytes match, with no late history addition. Deliberate quote removal removes its serialized bytes/dependency without removing signature/footer or independently selected files.
9. D9 CRM navigation preserves private draft and source authorization, introduces no duplicate Activity/contact/Party, and later real send projects once with truthful per-recipient outcome. Linking/unlinking/Party merge alters neither source quote nor actual audience.
10. Legacy unknown source references/unsupported node version cannot be stripped into writable success; compatible roll-forward/rollback and restore barriers preserve source restrictions and operation identity.
11. Bounded source/editor/mail exact ceilings plus one-unit-over are enforced in decoded and serialized units. Large/nested source cannot induce whole-conversation eager load; source fetch failure leaves no phantom quote or false Saved state.
12. Source/quote lifecycle telemetry carries opaque correlation and reason codes, never bodies/names/addresses/filenames. Existing records/privacy, Support draft, Email Studio and P6 owners can diagnose and correct their own boundary.

Monitor only after those prevention gates: one confirmed disclosure or accepted unqualified source stops the affected source/quote/preparation path (Core security + Support owner); one preview/prepared byte mismatch stops affected P17 preparation generation (Email Studio owner); first ambiguous save shows unconfirmed state and enters existing draft reconciliation (Support draft owner); first source cleanup obligation beyond its registered deadline alerts the actual representation owner while source serving remains blocked. These are thresholds and responses, not a new monitoring subsystem or routine quote-click business audit.

## Synthesis

Record A and the necessary C01–C15 safeguards in the D36 grooming package, with the parent-selected simple user journey. The implementation order is source/profile and existing permission qualification, canonical quote/draft round-trip and provenance, atomic private-save/recovery, P17 complete-message and P6 dispatch fences, CRM reuse, then negative/race/migration/email-client/accessibility/capacity proof and scoped activation. No new owner, CRM model, template family, generic workflow, AI extractor, history server or third-party quote service is justified.

The strictness is at the existing source and send boundaries. Normal staff work can stay small: choose the current permitted message or excerpt, see the exact added quotation, remove it easily, then send through the same familiar composer. Do not substitute a recurring approval wizard for authoritative implementation.
