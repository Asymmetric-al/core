Separate the stable source/version/profile/projection input key from the technical generation identity. An original source correction/restriction invalidates current ordinary use across all its derived generations, not just the last one. ## Request → preparation → read

1. The UI requests Preview for an exact original occurrence in a current authorized conversation/CRM-origin scope. The server derives tenant/actor and resolves current source/bytes/hygiene/policy. It accepts no raw provider URL, output bucket, renderer command or actor/owner field from the caller.
2. If a matching unexpired qualified result exists, the response describes availability; actual bytes still require current authorization. If a matching generation is queued/running, return its status. If no eligible result exists, atomically admit one intent/generation, dispatch/recovery intent and audit correlation.
3. The trusted supervisor fetches only the qualified original through the file owner. Actual streamed byte counts must match allowed bounds; an absent or changed object cannot be silently replaced. The parser receives local read-only input, no credentials or network and a finite scratch/output allowance.
4. Preflight validates the declared format/feature structure and safe limits. The profile creates inert output plus a coverage manifest. A completed process, HTTP200, valid PDF header or storage upload alone is insufficient success.
5. Output lives in private tentative custody. Ready promotion rechecks exact source generation, byte identity, current purpose/eligibility, attempt claim/profile, output digest, limits and manifest. It atomically transfers accepted outputs to Ready custody and its source-bounded deadline; the 15-minute sweeper can delete only remaining scratch/unpromoted outputs. Cleanup and promotion conditionally claim the same immutable object's custody: deletion-claimed output cannot be promoted, and an old tentative claim cannot delete promoted output. Ready expiry has its own guarded disposal path; keys are never reused across generations. If stale/restricted/expired, record cleanup-only disposition and preserve fences. Never publish first and repair authorization later.
6. The reader obtains bounded full/range/page/grid data via the current source-authorized gateway. Conditional/range/cache requests are not authorization shortcuts. Content remains no-store with no reusable provider/storage bearer URL. The browser reader has no application credential/DOM access and only a narrow, validated source-bound data bridge if needed by its isolation model.
7. Closing the viewer is navigation. Source restriction/expiry and current revocation remain enforceable on later requests, client reconnect/visibility return and delayed responses. An old response cannot repopulate a newer restricted view. Already delivered information cannot be remotely recalled.

This is compatible with current `packages/api` business ownership and approved `packages/database` reads. Shared storage/preview mechanics can be a bounded Phase29-compatible predecessor; C does not wait for the entire future File Manager. There is no app-local binary repository or direct browser lifecycle mutation.

## State and recovery semantics

Technical lifecycle is admitted/queued → processing → Ready or classified unavailable/failed. Source eligibility is orthogonal and dominates every state. Limited is a truthful coverage condition of a usable qualified rendition, not permission to serve partial corrupt output. Restricted/expired source prevents ordinary generation/use irrespective of stored technical result.

At most two parser attempts are allowed per generation, and only classified transient failures use the second. Unsupported, malformed, malicious/blocked and over-budget inputs do not retry automatically. A timeout is not permission for simultaneous replacement workers; reconcile/fence the prior attempt first. After budget exhaustion, show the persistent processing issue. An authorized operator may deliberately admit an audited replacement generation after correcting the cause and rechecking current source/profile/budgets; ordinary repeated opens cannot bypass the exhausted generation into unlimited work.

Same semantic command identity returns/reconciles the same generation under current disclosure rights. Changed input under the same identity conflicts. Coalescing does not share access between actors or tenants. New source/profile/delimiter inputs create distinct identities. A callback from an old worker cannot promote output under a newer claim/generation, even after the old lease expires.

The source record and required dispatch/cleanup intents must commit atomically. Blob writes are external effects, so staging keys/attempt inventory precede I/O. Partial writes or success with a lost response reconcile exact object identity and cleanup; no orphan can become an authorized file by being present in storage. Use the already-qualified shared workflow ledger/claims/recovery, without a second event engine.

## Profile data behavior

DOCX/PPTX may use an isolated maintained converter to static pages. Pin fonts/locale/options and classify detected missing fonts/resources, revisions/comments, hidden/embedded media and other unrepresented features. Silent omission of linked content despite a successful response is an explicit known tool behavior to defend against, not a supported fidelity claim. Untrusted external paths/resources remain blocked even when allowing them would make the page look better.

XLSX requires a saved-value extraction profile. Preserve typed raw cell values, coordinates, workbook date system, visible sheet/row/column state and cached-formula presence. Do not use JavaScript float coercion for arbitrary precision/raw values or turn missing `<v>` into zero. Supported style rendering is qualified; unsupported formatting keeps the raw value and a visible limitation. No calculation engine, external link refresh, HTML cell rendering, print-range omission, hidden-sheet export or automatic data import exists.

Text/CSV uses a strict declared decoder and literal parser. A per-view delimiter participates in output identity. Preserve empty cells, leading zeros, quotes/newlines and formula-looking values. No DTD/HTML/URI/formula execution occurs. Any safe text fallback has its own encoding/size qualification and exactly the same source authority.

## Resource units and limits

These are proposed preview-only engineering ceilings, not universal file-upload or sending limits. `MiB = 1,048,576 bytes`; `GiB = 1,073,741,824 bytes`; megapixels here means decimal pixels. An existing stricter source/provider/purpose limit wins.

| Dimension                   | Initial ceiling / exact interpretation                                                                                                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Original input              | 20 MiB actual streamed bytes per file.                                                                                                                                                                 |
| Expanded package data       | 200 MiB cumulative actual uncompressed OOXML/package bytes, including hidden resources. Metadata declarations are preflight only.                                                                      |
| Package structure           | 10,000 entries; depth 128 for XML; no DTD/external entity expansion, archive path traversal, duplicate ambiguous member names or arbitrary nested archive extraction.                                  |
| Pages/slides                | 200 actual output pages or visible slide renditions. Exceeding this yields Too large/unavailable, never first 200 labelled complete.                                                                   |
| Raster limits               | 40,000,000 pixels per decoded image and 256 MiB aggregate decoded-image working data per attempt; total process memory remains separately bounded.                                                     |
| Workbook                    | 50 total sheets, including hidden; 100,000 total populated cells, including hidden. Sparse dimensions are validated but never allocated densely. These limits include inputs parsed even if not shown. |
| Text/CSV                    | 1,000,000 decoded Unicode scalar values; table also capped at 100,000 populated cells. Empty field/row representation remains bounded by input/output limits and chunked parsing.                      |
| Generated outputs           | 50 MiB cumulative ready/tentative output-byte content per generation.                                                                                                                                  |
| Attempt                     | 60 elapsed seconds; 30 aggregate process-tree CPU seconds; 2 GiB aggregate process-tree memory; 512 MiB scratch. Supervisor enforcement covers descendants, not just HTTP timeout.                     |
| Retry                       | At most two attempts per generation; second only for classified transient failure, under unchanged source/profile intent.                                                                              |
| Temporary/tentative custody | Maximum15 elapsed minutes from attempt start, earlier where source/owner disposal requires. Register before I/O.                                                                                       |
| Ready rendition custody     | Maximum24 elapsed hours from first Ready admission, bounded sooner by source expiry/restriction/owner obligations. Reads never renew it.                                                               |

Parser allocation/entry/XML/style/relationship handling must remain bounded before expanding data; size limits are not a substitute for process isolation. Profile qualification must prove high-compression, sparse-sheet, many-empty-cell, deeply nested and huge-dimension behavior. Limits do not justify silently dropping data. A profile may decline a file within the outer size caps when its unsupported features or fidelity cannot be made truthful.

## Security, RLS and retention

Use least-privilege database/storage grants and RLS. Inspect actual SELECT/USING/WITH CHECK relationships, permissive policy combinations, source/tenant FK constraints, function execution grants, fixed search paths, invoker/definer views/functions and service-role handlers. Server commands alone may mutate generation/status/profile/result/owner/audit fields. A permitted source row must not be transformable into another tenant/owner/version by a client patch.

An `email-assets` bucket explicitly public for exported email images is not a private preview store. Raw short-lived signed URLs also do not satisfy D16's current restriction boundary. Cache invalidation and token expiry do not recall independently delivered bytes. Private full/range delivery and all derived forms must remain tied to current source access with safe response headers and no-store behavior.

No cross-tenant content-digest reuse or side-channel lookup. Jobs use isolated scratch namespaces; clean them between attempts and prevent state leakage through fonts, caches, temporary paths or converter profiles. Operational logs include opaque correlations/status/budgets only, never raw filenames/text/cell values/URLs/tokens. Source and access history use their owners' retention; an error log must not become a secret archive.

The 24 h rendition / 15 min scratch lifetimes are cache/custody product choices, not P17 prepared-message rules or D17's original-content retention. Expired derivatives can be regenerated only from a still-authorized source; original source expiry cannot be reset by previewing, copying, merging, profile change or restore. A hold preserves actual owner-required evidence in restricted custody without restoring ordinary reader access.
