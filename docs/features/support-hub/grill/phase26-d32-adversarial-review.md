## Exact corrected decision

Support provides one deliberate, read-only attachment viewer for **PNG, JPEG, WebP, still GIF, ordinary unencrypted PDF, DOCX, XLSX, PPTX, plain TXT and CSV**, subject to the declared profile's file, feature and resource qualification. Documents/slides use static reading renditions; spreadsheets use a bounded visible-sheet/saved-value view without recalculation. Plain text and CSV remain literal data. A file card separates **Preview** from **Download original**, shows truthful availability, and returns staff to the same conversation/draft and CRM origin when closed.

The original attachment is authoritative evidence of what was received, not authority for a business action. Preview renditions are private, versioned, disposable representations of that exact source. Support owns the source occurrence and restrictions; a shared Phase29-compatible file capability owns immutable bytes, private delivery, hygiene and preview mechanics. A narrow isolated conversion/parser pipeline serves this need without creating File Manager, Document Studio, another CRM or an editor. No public Office/Google URL viewer or public Email Studio asset bucket is used.

Every access rechecks the original source and current audience. Rendering never sends, inserts into a draft, publishes an asset, updates CRM/giving, validates a receipt, changes Support status or expands D22 search into attachment content/AI. Converted Office layout, saved spreadsheet values and omitted features are labelled honestly. Failure/unsupported content offers Download original only if independently permitted; it never automatically downloads or bypasses hygiene. C is complete only when every included format lane passes its release proof; shipping A alone must not be labelled completion of C.

## Why C survives the strongest alternative

A, common image/PDF preview with downloads for other formats, remains cheaper to build and maintain. Its strongest argument is that actual tenant attachment distributions and additional-format frequency are unmeasured. C is nevertheless a coherent founder-selected product scope: staff can inspect ordinary Office/text attachments without an external-application detour. The permanent compromise is a declared bounded set and truthful representations, not arbitrary-format support or a vaguely extensible document platform. Legacy Office, macro-enabled, encrypted/password-protected, archive, executable, audio/video, HTML/SVG and other unlisted formats have no preview in this release; original download remains governed by the existing file policy and may also be unavailable.

The selected list is a product judgment. Current vendor offerings are comparisons, not proof that these formats dominate ministry work or that a particular conversion is complete. [Research evidence](phase26-d32-evidence.md), [independent UX research](phase26-d32-ux-research.md).

## Required decision clauses

### D32-R01 — Bounded broader scope

“Provide all declared initial preview lanes: PNG/JPEG/WebP, still GIF, static ordinary unencrypted PDF, DOCX, XLSX, PPTX, TXT and CSV. A format name is not eligibility: source permission, actual byte/type/structure, hygiene, supported features and resource limits must pass. Publish the profile's supported and excluded features with the product. Do not call a filename chip, thumbnail-only display or image/PDF-only implementation completion of C.”

### D32-R02 — One source, separate derivative

“Support owns each original attachment occurrence and its parent-message context. The file owner holds immutable original byte identity/digest and qualified storage/hygiene facts. Preview records identify the exact tenant, source occurrence, byte version, renderer/profile build, projection inputs and source restriction generation. A ready result cannot point to a different source/version or serve a newer file under an old name. File names are presentation, never keys or storage paths. Derivatives are not P18 Generated Documents, current official PDFs, CRM attachments or Email Studio assets.”

### D32-R03 — Metadata-first, explicit actions

“Show a compact card at its message with currently permitted name, type, actual size, source and availability. Do not disclose a forbidden name merely because metadata exists. Preview and Download original are separately labelled actions. Do not auto-open, eagerly convert every file, or automatically download when preview fails. Existing already-qualified inline message images/authoring remain governed and are not removed or broadened by this control. Same-name files retain distinct occurrence identities.”

### D32-R04 — Complete in-context reader

“Preview opens one shared responsive reader, with readable source/file identity, current format-specific controls, persistent close and Download original when allowed. Preserve conversation, draft, recipients, scroll, focus, list/search and CRM return context. A viewer is not a new routed work record, mark-read/review action or status mutation. Close restores the invoking context. Switching files within the selected message must reauthorize each file and preserve identity; do not build a global file browser.”

### D32-R05 — Current source authorization

“Derive tenant and actor from trusted server context. Before metadata, conversion admission, source reads, ready promotion and every protected rendition/full/range retrieval, check the relevant current source/file purpose, membership/inbox/CRM scope, classification, hygiene and restriction/expiry state. A viewer/assignee/requester/CRM association is not an access grant. A worker acts through a narrow product claim, not a copied UI permission or raw service-role bypass. Reusing cached bytes does not reuse an authorization decision.”

### D32-R06 — Isolated parsing and rendering

“Use one shared owner-qualified preview pipeline with deterministic per-format profiles. Original untrusted binary parsing, image decoding, Office conversion and workbook extraction run outside ordinary web/API request workers in bounded isolated jobs. The parser has no network egress, credentials, tenant storage access, host mounts or ability to resolve document-supplied paths. A trusted supervisor supplies only the authorized input and receives bounded output. Disable macros, external references, linked resources, DTD/entity expansion and executable/embedded content; configuration allow-lists alone do not replace process/network isolation.”

“Do not pass private source URLs to public Office/Google/demo viewers, external conversion sites or a generic fetch proxy. Use the shared existing durable workflow envelope/claim/recovery pattern; no tenant workflow builder or second scheduler is introduced. A specific maintained tool such as a LibreOffice-based converter is a candidate implementation, not evidence of safe or faithful behavior until its exact profile passes.”

### D32-R07 — Admission, lifecycle and publication

“Separate source/hygiene eligibility, technical generation and user-visible availability. A preview request atomically records the exact requested profile/input and durable generation intent. Coalesce identical currently eligible work for the same tenant/source/version/profile/projection inputs; concurrent opens cannot create competing ready outputs. Queued → processing → ready is a technical lifecycle, not proof of source access. Unsupported/over-budget/invalid input is terminal for that exact profile; transient failure may retry within the declared budget. Restriction/expiry invalidates ordinary use in every technical state.”

“Outputs upload into private tentative custody with a known attempt identity and cleanup deadline. Storage success is not Ready. Ready promotion atomically rechecks source generation, byte/profile identity, eligibility and required manifests/audit; late/superseded results stay cleanup-only. Partial object success, lost responses and duplicate callbacks reconcile the same intent. A revoked requesting viewer cannot read a result; an independently eligible later viewer may reuse it only under current source-purpose authorization.”

“Successful promotion atomically transfers the accepted output's custody to the Ready/source-bounded deadline; the 15-minute tentative sweeper retains authority only over scratch and unpromoted outputs. Cleanup must claim the same immutable object's current unpromoted custody conditionally; once deletion is claimed, promotion is forbidden. A stale cleanup claim cannot delete a promoted output. Ready expiry uses its own guarded disposal path. No object key is reused for another generation.”

### D32-R08 — Private delivery and browser isolation

“Serve original and rendition data through the currently source-authorized private capability with no-store treatment, bounded full/range requests and no reusable public/signed-provider URL escape. Range and conditional requests require the same authority as a full read. Renderer workers/browser contexts receive only narrowly permitted data; PDF/binary rendering is isolated from application credentials, DOM and unrestricted navigation/network. Cross-context messages are typed, source-bound and origin-checked, never arbitrary fetch/HTML/command instructions. Disable scripting, embedded-file launching, form submission, external resource fetching and automatic link activation.”

“A browser reader is still executable software processing untrusted bytes; use a maintained patched build, restrictive CSP/embedding policy and actual isolation tests. Already-delivered DOM, memory, clipboard, screenshots or downloaded originals cannot be recalled. Revocation blocks future retrieval and invalidates current clients without claiming remote erasure.”

### D32-R09 — Truthful coverage and fidelity

“A successful parser/converter response does not prove complete content. Bind a coverage/limitations manifest to the result: representation type, included pages/slides/sheets or text scope, detected omitted features, missing resources/fonts/cached values, profile/build and output digest. Show a short persistent summary with expandable details. Mark a result Limited when material features are omitted. If coverage cannot be established under the profile, report Preview unavailable rather than Ready complete. Never infer that formatting, a signature image or a calculated-looking value validates a document or financial fact.”

### D32-R10 — DOCX reading profile

“Render the visible main document, headers/footers and supported embedded images into static pages. Use a defined no-markup reading view that shows the final-text presentation of revisions without accepting or changing those revisions. Detect comments, tracked changes, hidden text, embedded objects and external links; disclose omitted material. Do not export comments/revision history/hidden text accidentally or run linked content. A document with unsupported layout, fields or missing fonts/resources must carry exact limitations or become unavailable when meaningful legibility/coverage cannot be established. Preserve the immutable original.”

### D32-R11 — PPTX reading profile

“Show visible slides in original order as static pages. Preserve original slide numbering when hidden slides are omitted. Disclose hidden slides, speaker notes, transitions/animation, linked media and embedded objects that are not represented. Do not autoplay media, execute actions or present a missing animation state as proof of the complete presentation. Unsupported/fidelity-losing content gets a Limited indication or unavailable result under the declared profile, never silently substituted blank slides.”

### D32-R12 — XLSX saved-value profile

“Provide a read-only grid of visible worksheets, rows and columns using saved cell values and original sheet/cell coordinates. Never recalculate formulas, refresh external data, execute macros or use a print-area PDF as a complete workbook. Show a formula's saved cached result with its provenance; missing results are Unknown, not blank/zero or newly computed. Preserve cell types, raw decimal/text values and leading zeros. Format only supported date/number/currency/percent styles faithfully; otherwise expose the raw saved value with a clear unsupported-format indication. Excel dates retain their workbook date-system meaning and are not silently converted into timezone instants.”

“Retain sparse structure and original indices without allocating a whole rectangular sheet from an untrusted dimension. Hidden/filtered rows, columns, sheets, comments, charts/drawings and unsupported features are omitted and disclosed; hidden content is not a separate authorization boundary. Pivot definitions, refresh and interactivity are omitted, but visible saved pivot-result cells remain ordinary saved cells in the grid; no cache is refreshed. No unhide, formula editing, sorting that rewrites source meaning, data import, total calculation or export/re-serialization is added. A selected-cell detail can show saved/raw value and formula as escaped text, never evaluate it. All-hidden/empty/missing-cache cases are explicit states.”

### D32-R13 — Literal text and CSV

“TXT uses strict UTF-8 with optional BOM, or UTF-16 with a required BOM. Unsupported/malformed encoding is reported without silent replacement-character loss. CSV has explicit Comma default plus per-view Semicolon or Tab choices and View as text. Parse choice belongs to projection identity and affects no tenant preference. Preserve quoting, embedded newlines, empty fields, leading zeros and formula-looking text literally; never infer numbers/dates/booleans, execute formulas or dereference links. Ragged or malformed records produce a truthful text fallback or unavailable table, not guessed alignment.”

“Escape all text and control display safely, with bidi/isolation handling where needed. File extension does not authorize HTML/SVG/script rendering. No active syntax, shell, HTML or URI interpretation is introduced. Viewing text is not publishing it into D22 search.”

### D32-R14 — Images and PDFs

“Images preserve aspect ratio, orientation and readable zoom using a qualified inert rendition with unnecessary metadata stripped; the original remains unchanged. GIF, animated PNG and animated WebP previews show the first composited still frame and explicitly say animation is not shown. They must not imply the first frame represents the complete animation. If the qualified decoder cannot establish that representation within bounds, preview is unavailable. PNG/JPEG/WebP decoding respects both pixel and decoded-memory bounds.”

“PDF preview displays qualified static pages and their available text/navigation layer without document scripting, external fetching, embedded-file launch, executable actions or form submission. Existing form appearances, annotations and layers must follow a declared static profile; missing appearances, dynamic XFA/encryption, unsupported layers/attachments or other omissions are disclosed or rejected. No password entry, signature verification or document repair is added. Search within the currently authorized preview may use its existing text; image-only sources state that searchable text is unavailable. No OCR or cross-file indexing is implied.”

### D32-R15 — Explicit resource ceilings

“Preview eligibility is bounded by the smallest applicable existing source/provider policy and this preview profile. Initial engineering ceilings are: 20 MiB original input; 200 MiB cumulative expanded package bytes; 10,000 package entries; XML depth 128 with no external entities/DTD; 200 output pages or visible slides; 40,000,000 pixels per image; 256 MiB cumulative decoded-image working data; 50 total workbook sheets; 100,000 populated cells; 1,000,000 decoded Unicode scalar values for text/CSV; and 50 MiB total generated output. Exact-boundary tests must count actual streamed/decoded data, not trust metadata or ZIP declarations.”

“Each parser attempt has maximum 60 elapsed seconds, 30 aggregate process-tree CPU seconds, 2 GiB process-tree memory and 512 MiB temporary disk. Permit at most two attempts for the same generation and only after a classified transient failure; deterministic unsupported/corrupt/oversized inputs never retry automatically. No output is silently truncated and labelled complete. These are proposed engineering limits to qualify, not vendor capacities or changes to accepted intake/send limits. An otherwise eligible original can remain downloadable when preview exceeds its narrower limits.”

### D32-R16 — Failure and low-bandwidth behavior

“Distinguish Checking file, Preparing preview, Ready, Limited, Unsupported, Too large, Unavailable due to source restrictions, and Failed to prepare using source-safe copy. Do not reveal protected filenames or internal malware detail through an error. Keep conversation and draft usable while generation runs. Closing the viewer is not cancellation of admitted shared work; returning may reuse the same eligible result. Never report provider/storage acceptance as a finished preview or treat unknown outcome as permission for a blind new conversion.”

“Load a bounded first page/sheet and fetch additional authorized content deliberately/within a bounded reader window; do not download all attachments on thread open. Offer Retry only where the prior intent's result and remaining allowance permit it. Download original is separate and independently eligible in every failure state. Network failure, failed hygiene and unavailable source are not interchangeable.”

### D32-R17 — Derivative retention and source revocation

“Derivatives are dispensable working copies with a fixed maximum 24 elapsed hours from first Ready admission, further bounded by the source's current restriction/expiry and owner obligations. Reads do not extend this deadline. Distinguish the stable source/version/profile/projection input key from each technical generation identity: expiry retires the generation, and a new deliberate eligible admission may create a new generation under that unchanged input key, with concurrent opens coalescing one live generation. Never renew the old deadline or change an old command receipt. Original source retention is never extended. Temporary/tentative attempt material has a fixed maximum 15 elapsed minutes from attempt start and is registered for cleanup before byte I/O. Required cleanup recovers crashes/orphans using the same identity.”

“D16/D17 source restriction immediately fences future access/promotion across originals, thumbnails, extracted grids/text and page renditions. Reconnect/visibility-return/current updates invalidate stale client representations. Retention changes, merge/Undo, object restore or delayed worker completion cannot resurrect restricted content. A legitimate hold preserves only owner-required custody; it does not grant ordinary preview access or manufacture a Support archive.”

### D32-R18 — Database, grants and trusted attribution

“Represent lineage with same-tenant primary/foreign keys from source occurrence to immutable byte version and preview generation. Require valid finite byte sizes/digests/profile identity, explicit lifecycle and generation, valid timestamps and uniqueness for one semantic generation. Generated outputs are immutable once Ready; a new profile/input produces a new generation. Reference counts and owner-governed deletion must not cascade-delete another domain's original or required audit. Keep source eligibility separate from technically ready bytes.”

“Business reads/commands live in `packages/api` and approved `packages/database` collections. Derive tenant/actor/owner/audit fields from trusted context. Revoke direct client mutations of lifecycle/lineage/result fields; inspect actual grants, USING and WITH CHECK, overlapping permissive policies, views, RPC EXECUTE/search_path and storage policies. Privileged services independently enforce product claims. Current broad CRUD, a public bucket or a filename/type/URL record is not this contract; existing tenant FKs/RLS are acknowledged, not alleged absent.”

### D32-R19 — CRM and whole-product continuity

“CRM opens the same currently authorized Support original and viewer with preserved return context. A person/household/organization association, message participant, requester, authenticated user, assignee or CRM owner does not become an attachment access grant. Linking/unlinking/person merges change authorized source relationships through their owner, not copied file ownership. Support conversation merge/Undo preserves original attachment lineage and restrictions; no earlier source becomes visible solely through grouping.”

“A requester-supplied receipt, bank-like spreadsheet or missionary document is evidence attached to a conversation, not a verified financial/CRM/care record. Viewing, downloading or closing the preview cannot change contact details, grant care access, issue receipts, refund gifts, modify recurring gifts, complete tasks or resolve Support. Existing deliberate owning-domain workflows retain validation, approvals and history. Preview creates no duplicate CRM task or interaction.”

### D32-R20 — Email Studio, Document Studio and TipTap

“Preview/read/download does not prepare, send, forward, attach to a reply, publish a reusable asset or alter sender/recipients/signature. P17/Email Studio governs later qualified outbound content/preparation; P6 owns transport and communication evidence. Preview derivatives cannot be silently used as message originals or promoted into the public email-assets bucket. Explicit later reuse follows D18/D23/D24 source/asset controls and rechecks current authority.”

“P18 Document Studio owns official generated-document identity/currentness and its own qualified renderer profile. D32's conversion output is a preview only, with no issuance, signed authenticity, canonical accessible PDF or archival-validity claim. TipTap remains the rich-text editor for messages/notes/signatures/wording; binary/document viewing uses the shared reader, not an imported editable document in TipTap. Existing source/operational failure attention remains with its owner; no per-preview email notification family is introduced.”

### D32-R21 — Search, AI and cross-representation disclosure

“D22 conversation/filename search remains unchanged. Preview text/grid extraction serves this exact authorized reader only; it is not a new search corpus, AI retrieval source or reusable knowledge article. Find within this preview covers the entire declared represented authorized content, including not-yet-displayed pages/sheets, through bounded current-authorized reads. No matches requires completed coverage of that scope; incomplete search reports incomplete coverage and offers retry, never a false zero. Image-only content is labelled nonsearchable. Untrusted document text/instructions never authorize a tool, data mutation, external fetch or message. No automatic OCR, summarization, classification expansion or financial extraction occurs.”

### D32-R22 — Privacy and access evidence

“Log technical operation/profile/status/size/budget/latency identifiers without source bodies, cell values, filenames, storage URLs or tokens. Record durable source/byte access audit under the file owner's existing meaning; generation logs and access events are not communication/CRM interactions. Only currently authorized users inspect safe history. Retention/redaction/export/backups follow their source and platform owners. No cross-tenant content-digest cache or raw-byte deduplication grants another tenant access or leaks existence through counts/timing/lookup.”

### D32-R23 — Accessibility and visual craft

“Use the existing `base-maia`/Base UI shared components, semantic tokens and Core typography. One restrained reader shell adapts its content controls; do not build separate applications for formats. Primary controls have readable labels, visible focus, adequate contrast, touch targets and keyboard equivalents. Mobile uses a full-height responsive reader, predictable close/back, retained file identity and reachable actions. Pan/zoom/rotate/page/sheet navigation has non-drag and keyboard alternatives.”

“Support direct page/cell navigation and a semantically usable text/grid reading mode for represented content without silently replacing the visual source or inventing missing alt text. Preserve logical focus and source coordinates in virtualized grids, provide accessible paging/text fallback for the same represented values, and disclose source text/image-only limitations. Meet WCAG2.2 AA for product controls, reflow and input; test actual supported assistive technology. An untagged/scanned original is not made accessible by a canvas or an unverified automatic transcript; source limitations cannot excuse inaccessible product chrome.”

### D32-R24 — Concurrency and idempotency

“Conversion intent, source/profile generation and required dispatch/audit/cleanup intent have an atomic admission boundary. Identical requests reconcile the same semantic generation; changed input under the same identity conflicts. Old responses cannot replace newer authorized state. A cancellation/restriction/new profile races promotion under one current generation fence; stale outputs never become Ready. Duplicate range requests may reread authorized bytes but cannot duplicate generation or mutate source work. Export/download is an independent deliberate read effect, not a reusable authorization token.”

### D32-R25 — Dependencies, performance and maintenance

“Own one maintained format-profile registry in the shared preview capability, not tenant custom plugins or Support-specific replicas. Pin the qualified parser/converter/viewer build, fonts, locale behavior, security settings, supported features and output contract. Patches/profile changes create explicit new lineage and revoke unsafe ready renditions where required. Do not switch engines silently after admission or reuse a transitive dependency as an undeclared contract. Use finite tenant-fair queues and bounded worker pools; no parser runs for every list row or keystroke.”

“The actual engine selection and deployment sizing must pass the declared safety/fidelity/accessibility/resource corpus before activation. This is implementation qualification of the decided capability, not permission to defer its product meaning or to import P18's official-renderer role. A dependency outage leaves source work and qualified originals available; it cannot weaken policy or route files into a public service.”

### D32-R26 — Migration and rollout

“Qualify immutable source/byte custody, hygiene, private delivery and source-revocation enforcement before the new viewer. Inventory legacy URL/local/metadata-only records; do not declare them Ready from extension/count alone or invent a digest for missing bytes. Migrate only trusted retained bytes through their owning connection and current policy; unavailable legacy records keep truthful repair state. Do not fetch arbitrary stored URLs. Deploy compatible readers/contracts, fence legacy bypasses, then activate by qualified tenant/profile scope.”

“A kill switch can stop a renderer, new generation or serving an unsafe profile while preserving source restrictions, cleanup, history and unrelated Support work. A code rollback cannot restore public/raw-URL access or removed bytes. Post-write correction is an explicit new rendition/profile or safe roll-forward; preserve source identity and original evidence.”

### D32-R27 — Required proof and monitored risk

“Trace this decision through the glossary/ADR and later authorized OpenSpec/design/tasks/tickets to real release evidence. Execute all P01–P40 in the proof ledger, including malformed/hostile input, tenant isolation, revocation, actual sandbox/network denial, content fidelity, accessibility, concurrency, migration and representative load. Reference probes and document review do not establish production conformance. Block activation of any claimed format lane that fails; keep policy-safe diagnostics and existing original access without calling the narrowed rollout full C.”

### D32-R28 — No unnecessary expansion

“This is a staff inspection feature within Asym. It creates no editor, annotation/redaction canvas, external sharing links, bulk ZIP export, public file library, personal document store, requester portal archive or D29 form upload. No new broad mandatory CRM/missionary workflow or AI assistant is required. The supported set can evolve only through explicit shared-profile qualification and product scope decisions, not automatic package support or competitor parity.”
