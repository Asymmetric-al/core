## Required implementation sequence and limits

1. Qualify current actor/tenant/source contracts and the private canonical draft plus immutable operation/terminal evidence. Close the public-message writer/read bypasses first.
2. Implement and test atomic whole-bundle create/save/discard, current source/retention gates and consumedSend linkage, including same-op/no-op/concurrency and unknown results.
3. Qualify the shared Tiptap closure and canonical validation; add the narrow autosave/ACK/hydration/navigation controller without a collaboration platform.
4. Add metadata-only My drafts and existing-reader resume using shared Base UI/Maia; preserve CRM/list context.
5. Run P01–P32 and capture actual limits, versions, plans and role/browser/staff evidence before activation. Stage rollout by eligible cohort with owner kill switches and compatible roll-forward.

The initial20/50row query bounds and750ms/5sautosave attempt timings are exact proposed interface/engineering limits, not source-provider constraints. D23's broader numeric payload/operation profile and D17's actual retention/custody inventory remain required qualified dependencies; no invented default lifetime replaces them. No runtime task is performed by this document.
