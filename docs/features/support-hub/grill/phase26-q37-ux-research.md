14 September 2026. ## The actual unresolved user task

A staff member begins a reply, leaves the conversation to consult another authorized record or handle other work, and later needs to find the unfinished reply. D2 already requires safe private draft restoration; it does not tell the person where to find all their saved replies across conversations. This is an inherent consequence of the accepted writing/navigation journey, not an invented ministry workflow. No frequency or measured productivity benefit is asserted.

The question is the primary discovery surface for **the current staff member's saved, unsent Support reply drafts**. It does not add shared drafts, supervisor surveillance, drafts of every Asym artifact, note-edit recovery, AI-generated replies, outbound prospecting, or a new Support status. Current source qualification and actual save/recovery behavior are implementation obligations irrespective of the chosen surface.

## Three genuine alternatives

| Option                                              | User journey                                                                                                                                                 | Strongest benefit                                                                                                                | Real cost                                                                                                                                 |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **A — A dedicated My drafts view (recommended)**    | Open My drafts in Support navigation, recognize a saved reply from permitted conversation metadata, then resume in the same qualified conversation/composer. | One predictable place to review and return to unfinished replies without remembering the prior inbox or status filter.           | Adds one visible navigation destination and a list to maintain accurately.                                                                |
| **B — My draft filter and badges in Conversations** | Stay in the existing conversation list, apply My draft, then open a marked conversation and resume.                                                          | Reuses the familiar workspace, filters and list; especially useful when the person is already working in a chosen inbox or view. | Other active filters may hide a draft. Scope must remain obvious and there must be a clear path to find all permitted saved reply drafts. |
| **C — A Resume draft picker**                       | Open a visible Resume draft action, browse/search permitted metadata in a compact picker, then return directly to the chosen conversation/composer.          | Quick switching from current work with less permanent sidebar space and without maintaining a full list page.                    | Less room to scan several unfinished replies and their context at once; the entry must be discoverable on touch and by keyboard.          |

C is not a recent-only list: every currently permitted saved reply draft must remain discoverable, with bounded retrieval. It is not a global Asym search or a body index. B is not a request to make a shared saved-view definition own draft membership or private bodies. A is a source-derived personal view, not a second draft store or private mailbox product. All three retain ordinary direct restoration when the staff member returns to a known conversation.

**Single recommendation: A.** A stable My drafts destination makes a previously saved reply easy to locate even when work status, current inbox filters, or the person's memory has changed. B is the strongest simpler alternative because Core already has qualified conversation views. C is a credible focused-switching option using a small chooser pattern. A is a product judgment for Asym, not a claim that vendors agree, users universally prefer it, or a dedicated page has already passed usability testing.

## UX consequences to carry into the selected answer's review

1. **Recognize, resume, continue.** Use concise currently permitted conversation identification and honest save state. Opening an item restores the original draft in the existing composer; it does not start an empty reply, change recipient defaults, or retarget to the latest email. No second editor is necessary.
2. **Draft ownership is not work assignment.** My means authored private work of the signed-in person in the current tenant. A conversation assigned to a teammate can still have this person's permitted draft; a conversation assigned to this person does not expose someone else's text.
3. **Do not confuse stored and local work.** A list cannot claim a network-unconfirmed keystroke is saved. Local pending work and durable saved work need truthful handling under the existing save/recovery contract; the question does not select new autosave or offline storage machinery.
4. **Preserve the open draft during navigation.** Choosing another item must respect pending saves, conflicts and uncertain outcomes. A response bound to the former tenant/user/draft cannot clear or populate the newly opened editor. Cancellation returns focus/place without changing work.
5. **Every permitted draft remains findable.** Status, inbox retirement, merge or saved-view filters must not accidentally strand authorized unfinished work. Actual source access, privacy restriction and expiry still apply. A stale list is never a grant; unavailable source context cannot be recreated from CRM data or cached quotations.
6. **Separate uncertain sends.** A draft with an unresolved admitted send is recovered through its original operation; it must not masquerade as a fresh unsent item ready for another Send. Browsing does not reset an admission identity.
7. **Keep overview and attention meanings stable.** Unsent writing is not automatically new team work, target fulfilment, handled communication or an activity-timeline event. D30 metrics, D14 targets and D15 attention do not derive new facts from opening a draft list.
8. **Design one visual language.** Use Core Base UI/base-maia and shared semantic tokens. A normal text label and readable rows/picker items are sufficient; no large card wall, novelty animation or colour-only Draft state. Exact placement, columns, sort, count unit, density, shortcut and empty/error copy get review after selection.
9. **Mobile and keyboard are first-class.** A/C need visible navigation/action reachability rather than shortcut-only discovery. B needs an obvious active-filter indicator and scope reset. Opening and canceling preserve focus, text selection and valid local work; no keyboard event submits a reply accidentally.
10. **Use the same source through CRM.** A draft begun while viewing permitted CRM context remains the same Support draft. A dedicated tenant-wide My drafts entry must not silently erase the CRM record anchor; deliberate broader Support navigation preserves a return route. CRM needs no duplicated draft table, body projection or reply authority.

Discovery reads are owned by Support's qualified personal draft/source boundary. A list, badge or picker neither selects an external audience nor prepares/sends an email. Email Studio/P17 continues to govern canonical composition, managed signature/footer, qualified source material and complete-message preparation when an actual reply is reviewed. The existing full-message/send checks remain mandatory upon resumption. No automatic send, supervisory draft sharing, reminders about drafts or mass discard is bundled into the next question.
