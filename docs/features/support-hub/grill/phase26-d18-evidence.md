## Independent adversarial synthesis

Independent [data/CRM](phase26-d18-data-crm-review.md), [lifecycle](phase26-d18-lifecycle-review.md) and [UX/vendor](phase26-d18-ux-research.md) reviews challenged the proposed and completed answer. Their reports preserve initial alternatives; the final R01–R28 and companions govern any disagreement.

| Adopted correction                                                   | Final result                                                                                                                                             |
| -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Personal save versus global publication review was ambiguous         | R03: validated personal authoring is explicitly nonpublication; Shared follows existing review, and protected source cannot be laundered through My.     |
| Too many canned “types” and formats could expand the model           | R04/R05: two purposes, practical content forms, qualified style vocabulary; no general tables/blockquote, new layout or macro engine.                    |
| One-use placeholders can send unresolved instructions or change CRM  | R08: narrow typed manual-input node, fresh insertion identity, server admission checks, no CRM mutation.                                                 |
| Note-only picker filtering does not protect later mode switching     | R04/R11/P03: separate drafts, retained provenance and external preparation denial even after mode switch/Undo. Internal notes have no email preparation. |
| An unsent insertion was described too broadly as D17 content         | R18: draft class and inherited source restrictions first; admitted reply/note enters D17. P17 preparation and P6 Recent copy remain distinct.            |
| Historical Shared audience can become a stale authorization grant    | R13/P21: current audience covers old revisions/deep links/new preparation; narrowing is explicit, widening qualifies all exposed variants/assets.        |
| Shared files could remain hotlinked to personal custody              | R14/P25/P29: re-prove sharing authority and establish destination-owned occurrences; no partial exposure or dependence on creator employment.            |
| Alias uniqueness and personal priority add leakage/selection hazards | R10/R20: aliases are optional nonauthoritative search hints; duplicate permitted candidates require explicit choice.                                     |
| Routine Archive could unnecessarily block safe existing drafts       | R15: stop new selection; preserve safe inserted material, while actual safety fences govern dangerous use.                                               |
| New RLS can leave old permissive access active                       | R20: reconcile effective grants/policies and test both USING/WITH CHECK plus privileged paths.                                                           |
| Save-as-conversation can defeat D16/D17                              | R06/R18: clean generic authoring, no automatic transcript harvest; known copies keep actual dependencies and correction.                                 |
| Current code could be overstated as automatic canned sending         | Evidence explicitly records the server's skipped send action and distinguishes raw local interpolation from the shared compiler.                         |
