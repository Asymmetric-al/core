## Primary technical evidence

[PostgreSQL17 RLS documentation](https://www.postgresql.org/docs/17/ddl-rowsecurity.html) distinguishes grants, old-row visibility and resulting-row checks; permissive policies combine with OR and privileged roles can bypass RLS. The local configuration pins major17; production engine/version and effective grants were not queried. D16 therefore requires actual database role tests, not one new policy shown in isolation.

[Supabase Storage access control](https://supabase.com/docs/guides/storage/security/access-control) and [storage schema guidance](https://supabase.com/docs/guides/storage/schema/design) distinguish permissions, metadata and physical objects. Deleting metadata is not proof of byte disposal. [Download documentation](https://supabase.com/docs/guides/storage/serving/downloads) states signed storage URLs use separate signing machinery; Auth key rotation is not a revocation strategy.

[Supabase Smart CDN](https://supabase.com/docs/guides/storage/cdn/smart-cdn) documents cached signed responses potentially surviving token expiry, delayed object invalidation and independent browser caches. This supports the private source-gated delivery requirement and legacy-URL rollout barrier. It does not establish which CDN plan the current tenant uses or an observed Core exposure. A new gateway cannot retrospectively revoke an old issued URL.
