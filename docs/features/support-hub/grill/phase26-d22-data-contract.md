# Search source, query, lifecycle and extension contract

This fully founder-ratified D22 contract, 12 September 2026, accompanies [R01–R26](phase26-d22-adversarial-review.md). Logical names describe required meanings, not invented physical tables/RPCs. Current source and intended owner contracts remain distinct. Broader/AI search is explicitly future scope.

Eligibility is an intersection: source admission/purpose, allowed indexing classification, owner availability/revision, context source basis and current actor field/resource authority. Phase10 restricted-tier data and P9 excluded care/finance-provenance remain outside ordinary indexing even for cleared actors. A general donor-care message is not excluded merely because it mentions a receipt: use the actual owner classification, not a keyword classifier. P6/P17 Recent, reusable Email Studio sources, drafts/preparations, raw MIME/header/evidence and held intake are not fallback source kinds.

Each projection item retains tenant, source kind, immutable original conversation/source/attachment ID as applicable, current source revision, projection/query-normalization version, purpose/classification eligibility and original owner time. A current-root ID is a derived routing/grouping value; it cannot replace original provenance. Preserve the minimum safe withdrawal/revision fence required for replay and restore without retaining forbidden text.

## Exact literal query contract

The new normal form is **literal all-fragments within one source item**, plus quoted phrases. This is not PostgreSQL's English full-text meaning and not a general query language.

1. Preserve the typed string for current authorized editing. After trimming outer Unicode whitespace, reject more than 256 Unicode scalar values or 1,024 UTF-8 bytes before parsing. Reject invalid scalar sequences/NUL and unsupported non-whitespace control characters with a clear input error. Blank means no text predicate, not a failed search. A nonblank one-character query is valid subject to resource limits.
2. Separate atoms on whitespace outside quotation. Normalize qualifying whitespace sequences to one space for matching. Straight double quotes pair with straight double quotes; typographic opening/closing double quotes pair together. Text enclosed in either pair is a contiguous phrase. Apostrophes are literal. Do not treat OR/AND/NOT, colon, `%`, `_`, `*`, `?` or parentheses as operators.
3. Backslash escapes a supported double-quote delimiter or another backslash. Before another character it remains literal, preserving ordinary path-like text. Quoted and unquoted adjacent runs within one whitespace-delimited atom concatenate into the same literal atom, so a phrase can include a literal prefix/suffix without a second operator model. An unclosed/mismatched delimiter, empty quoted atom, or more than 16 nonempty atoms is invalid; return the specific repairable error and do not run an older/broader/empty query as its result.
4. Apply the same versioned NFC and Unicode full casefold to eligible source runs and parsed atoms, with a bounded normalized expansion profile. Do not assume JS lowercasing or PostgreSQL17 lower() equals full casefold. Preserve accents, punctuation and stopwords. A source fragment may match inside a word; no language stemming, fuzzy match or spelling correction. All atoms must be verified within one eligible item; repeating an atom does not require extra occurrences.
5. A literal fragment or quoted phrase must lie wholly in an eligible contiguous display run. Never bridge a redaction, hidden node, expired span, field boundary or different message. Separate unquoted atoms may be found in different currently eligible runs of the same item. No excluded characters influence matching or ranking. Owner-rendered removal placeholders are not source text.
6. Maintain offsets from normalized runs back to current visible source grapheme ranges. Casefold expansion, combining marks and whitespace folding cannot make highlights reveal adjacent hidden text or split a grapheme. Return escaped text with trusted marks, not HTML supplied by the sender or an unsafe headline function.

Examples: `receipt address` requires both fragments in one item; a participant named Alex plus a message saying receipt does not satisfy `Alex receipt`. Use Person or email=Alex plus q=receipt for an explicit conversation-level conjunction. `"not received"` preserves not and requires contiguous normalized wording. `100%` means literal percent; `a_b` is not an SQL wildcard. A phrase split between subject and requester name is not a hit. Two phrases in one query must both appear within the same item. Text separated by a redaction marker cannot manufacture a phrase, although visible unquoted terms on either side can satisfy a same-item conjunction.

Query and normalization versions are stored with saved definitions/handles. Old q substring/concatenated semantics are not silently reinterpreted as this language; supported old meanings run under an explicitly declared legacy compatibility contract or receive reviewed upgrade/reconciliation. New-source coverage and a parser version are separate facts.

## Structured scope and result order

The effective query contains trusted tenant/actor purpose, mandatory CRM/report/source basis, current inbox/view/work filters, Search in, optional Person or email, text/normalizer/coverage version and current ordering. Text matches source items; work/label/person filters operate over the qualified conversation scope with their explicit owner meaning. A Person or email criterion matches only a permitted Support detail item with literal normalized name/address fragments (or an explicitly selected stable eligible participant reference), not all linked CRM records. Email text remains a lookup clue, not identity or provider mailbox canonicalization.

D20/D21 filters retain their accepted AND/Any/All/No labels/current-target meanings. No new free-form date criterion is smuggled in; a D21 report drilldown keeps its exact component-first cohort as mandatory context. Ordinary broader search removes work filters only through the explicit UI action. In CRM/report context, source-basis escape requires Open in Support Hub with fresh authority. Empty text retains remaining filters; syntax failure never removes them.

For an unconfigured text search, Best match has a small deterministic order: exact full Support reference/ID result first; otherwise select each root's newest qualifying source match by original owner admission/creation instant, unknown last, then stable kind-prefixed source identity. Order root results by the selected match and stable continuing-root identity. No hidden source, repeated phrase, length or occurrence-count boost. An explicit supported saved/user sort takes precedence without changing the text predicate; preview selects the best qualified matching item by the rule above. The transient automatic search sort never overwrites underlying queue/view preferences. Clear text removes that transient order while retaining deliberate filters/sort.

When text is blank, Search in is a retained dormant preference, not an existence condition. Clear filters resets it to All, removes ordinary work/person/label refinements and retains text, current inbox boundary, view identity as Modified where applicable and mandatory CRM/report context. Empty Find clears highlighting/navigation. The exact-reference tier requires the entire parsed query to contain one atom equal to the complete permitted reference; a matching atom among other atoms does not qualify.

## Current source pipeline and database boundary

Use the shared packages/api query/list boundary and a private server-side Support projection in Asym Postgres. Reuse qualified P9 pg_trgm candidate-index patterns and shared governance; a P9 architectural commitment is not evidence the extension exists locally or that name-search indexes support bodies. No new external search vendor is selected. A tsvector candidate is permissible only if it cannot omit literal matches and the exact verifier remains authoritative; ordinary English lexical search is not such proof.

The authoritative stages are: trusted context and structured scope → index-eligible current source/field intersection → candidate source retrieval → exact current-revision literal verification → source-safe match attribution → D10 continuing-root mapping/deduplication → qualified order/count/page → current-authorized response. Authorization is a semantic invariant even if the database optimizer rearranges safe operations. Nothing inaccessible may influence result membership, ranks, counts, facets or timing diagnostics that disclose its existence. Candidate/projection data never goes to the browser for permission filtering.

Projection rows and source references use tenant-aware immutable identities, valid non-null source-kind/revision/version/state constraints and verified actual endpoints. For multiple source kinds use qualified typed tables/relationships or one controlled writer that proves each endpoint—not unchecked arbitrary polymorphic references. Catalog/body metadata availability and file-byte capability are distinct. Grants revoke raw unneeded anon/authenticated projection access; search RPC/view permissions and invoker/definer/search_path, USING/WITH CHECK, owners, service roles and jobs preserve the same restrictions. Existing broad message GET and service hydration cannot be repurposed as a safe global text dump.

Source admission/correction/restriction records durable projection work or a reliably discoverable current-revision gap atomically under its owner. Worker identities are narrowly authorized; payloads carry references, not a duplicate raw body. Each worker rereads current source authority, compares revision/withdrawal fences and commits one projection outcome idempotently. Older retries and rebuild snapshots cannot replace a newer projection or reindex forbidden material. Projection failure does not reverse real source admission, change sending state or reset D14/D17 time.

## Completeness, chunking and resource limits

Assess index coverage over the eligible structured **pre-text-filter** scope. An unindexed item cannot yet be known not to match the query. Excluded/private/index-forbidden sources are outside declared coverage; unreadied eligible sources are gaps. Emit a truthful incomplete state without revealing hidden source counts. A count/zero/completed ranking is authoritative only when the relevant corpus and exact query completed under current gates. Do not declare complete because every already-returned hit has an index row.

Use source-targeted reads and tenant-leading indexes rather than all-tenant hydration. Normalized literal substring retrieval may use escaped parameterized LIKE/position with pg_trgm candidate indexes, followed by exact verification. Short/punctuation-only patterns can have no useful trigrams and require broad scans. Apply permitted work/person/inbox scope, budget execution and return Refine search when needed. A timeout or truncated candidate list is not a successful zero. Do not discard single-character languages simply to fit a trigram optimization.

Do not concatenate an entire conversation into one tsvector. PostgreSQL17 text search has vector, lexeme and positional limits and language-dependent transformations; those cannot become undisclosed source truncation. If a large item is segmented for storage/index efficiency, candidate retrieval may use any qualifying segment to locate its parent, but must not require all query atoms in one segment. Final verification evaluates all atoms against that one complete eligible source item. Phrase candidates need sufficient overlap derived from the maximum **normalized** phrase length or an equivalent streaming candidate/verifier that cannot miss boundary matches; redaction/field boundaries remain hard. Never fetch/scan a file's contents for filename search.

The deployment profile fixes and tests normalized expansion, current source/segment size, page size, excerpt length/count, query/row/time limits, concurrent work and per-tenant fairness, cancellation, worker/backfill batches, query/handle/cache lifetimes and recovery/freshness deadlines. These values are explicit activation evidence, not speculative universal quotas. Source units over a supported processing boundary become an owner-repair/coverage condition; they are not silently omitted or clipped. UI query bounds are independently 256 scalars/1,024 bytes/16 atoms.

## Revisions, privacy, live pages and navigation

At source restriction/redaction/expiry admission, current serving gates invalidate all stale derived contributions before asynchronous physical deletion. A returned candidate's old body/revision cannot establish a hit even if the old index is still present. Metadata/detail/filename revisions and owner policy matter as much as message bodies. Retained exact IDs/withdrawal fences contain no forbidden content. Restore must apply current source constraints and disposed-generation fences before projecting or serving old records.

Search uses live data, not permanent result membership. A page cursor binds the authorized query/coverage/version/sort and stable keyset; current authority is always rechecked. Mid-query/page topology and source changes can invalidate a continuation or alter ordering. Do not silently substitute a new query or claim snapshot completeness; return the current valid page or a scoped Results changed/Refresh state as appropriate, preserving opened source and draft. Never keep long-lived sensitive result bodies to simulate a snapshot. Selected action IDs are explicit and current commands reauthorize them; changing search membership cannot retarget bulk work.

Match navigation carries original source ID/revision and current root/context qualification through a bounded private handle, not a raw excerpt in a URL. Reopen rechecks source identity and permission; if changed, show current qualified state and match refresh instead of resurrecting the excerpt. Filename navigation stops at metadata; explicit byte access uses the original attachment/version and current storage/hygiene gate. Find in conversation uses the same exact query and eligible source basis, traversing all declared searchable retained items with bounded paging, not the mounted DOM.

Queries, excerpts, normalized text and index material are sensitive derivatives with owner lifetime. Source-derived material cannot remain searchable/readable beyond source authority; physical retirement follows the actual bounded owner cleanup, lawful preservation and restore policy. Independently authored query text remains governed configuration under D20, while known source-derived query fragments retain their restrictions. Search logs/Recent copies cannot create a new retention purpose. D20 handles are authenticated references, not bearer grants. Caches and in-flight requests carry tenant/principal/acting scope plus query/source versions; revocation/tenant switch fences late responses. UI cannot retract a screenshot or previously observed text, but Asym stops new serving and clears stale controlled representations promptly under its owner contract.

## CRM, Email Studio and future AI

CRM search applies D9 original-source relevance/correspondence basis before D10 root union. A record linked to B does not inherit A's old searchable messages. D12 relations do not recursively enlarge the corpus, and a Staff context citation proves no access to its target. Exact references or participant strings create no Party, identity link, contact history, receipt or approval. Shared underlying Asym identity remains authoritative; no cross-system sync is introduced.

P17 Email Studio owns reusable wording and exact preparation; Support owns admitted conversation/draft/recipient/source facts; P6 owns actual tenant Resend delivery evidence. Only actual eligible admitted Support source text participates. Search/Find does not call Resend/provider search, prepare messages, copy a note into a reply or consume P6/P17 Recent. Index failure is local to search; an otherwise valid reply still follows its independent admission/delivery controls. A search hit is never permission for a financial/care/contact mutation.

Future AI/broader retrieval can consume a later-qualified version of the typed source contract: original identity, current eligible projection/revision, mode/coverage semantics and retrievable evidence. Actual AI context/egress/citation/retention/suggestion/connection requirements remain with Phase40 and shared Core owners; file content with Phase29-compatible mechanics and its semantic owner. No embeddings, provider keys, extraction, unused adapters, AI query grammar or disabled AI UI now. A future feature cannot reinterpret a saved keyword query or lift indexability exclusions merely to improve recall.

## Migration and proof

Inventory actual stores and source-type eligibility, index existence, legacy q semantics and current URL/caching behavior. Add compatible projection/version/withdrawal contracts; backfill only current eligible originals with original admission times. Legacy sources with uncertain admission or retention are not silently treated as safe. Fence old raw-message/body/index endpoints, fixture authority and raw-query serialization. Old searches require exact legacy compatibility or explicit reviewed upgrade, not a partial migration that reports false complete results.

Gate source kind and tenant activation on real coverage/privacy/query proof. Search stop controls preserve ordinary source work and current owner navigation while denying unsafe retrieval; old destructive/leaky code cannot be the rollback fallback. Recover through current-source roll-forward and rebuild. [P01–P40](phase26-d22-adversarial-review.md) define source, grammar, permissions, failures, concurrency, migration, accessibility and production-shaped acceptance. No runtime/API/database/index implementation is executed during this grooming review.
