## Permanent shape

Use **one flat tenant-owned selection catalogue** containing stable references to exact eligible public Site/Page/locale variants. Support owns selection and its ordinary lifecycle. Web Studio/Page, Site Locale, domain, public generation, route, source safety and public projection owners retain every authoritative publication and URL fact. There is no Support article body, per-inbox content copy, generic taxonomy, private knowledge library or public-help-center expansion.

The current shared public reader must be extended through its own server contract to expose a qualified bounded selected-guidance projection. It cannot be treated as already complete: current code is still tenant-rooted with a null Site seam and mutable lookup fields, while the accepted later planning contracts require exact public generations, locales and canonical domain authority. Reusing the owner means qualifying those semantics, not adding a button over the old raw page query.

## Findings, proposed exact clauses and proof

Severity/likelihood concern the unamended design or reuse of observed source, not asserted production incidents. All findings preserve A while narrowing the required owner seams.

### F01 — Stored “published” is not current public eligibility

**Material concern: Yes. High severity; high likelihood with S01–S05 unchanged.** A page can be a draft over an older publication, in an unreleased locale, on a suspended Site, past a public window, or withdrawn by its source. Staff editorial access can still make it look available. The wrong preview/link would break the selected promise or leak content. G02–G04 govern the correction.

**DR01:** “A guidance result requires the exact currently admitted public source representation: trusted operational Tenant/environment/Site and CMS mapping, stable Page/source identity, exact Site Locale, active coherent public generation, current source/reach/window/lifecycle safety and currently valid public route. A Payload \_status flag, staff Preview, draft/version read, scheduled candidate, successful HTTP read, index hit or cached title is not this authority. Private or unknown source remains unavailable. New unpublished edits never replace the currently released public representation in the finder.”

**Proof:** published Page inside private/unreleased locale; suspended Site; future/past window; private newer draft over live revision; source withdrawal while CMS still published; anonymous/staff/expired-session normalized source equivalence; unknown mapping and unsupported source family.

### F02 — Stable catalogue identity must not be a URL, slug or assumed UUID

**Material concern: Yes. High severity; high likelihood if S01/S02/S06 are reused.** Mutable slugs, stringified CMS ids and site-null context can retarget selection across Pages or confuse operational/CMS identity. Hard foreign keys into Payload would violate migration ownership. G01/G02/G08 provide the permanent boundary.

**DR02:** “Support selection stores a closed typed soft reference to the exact qualified source identity and Site/locale variant. Preserve actual owner ID types, including numeric/string CMS identifiers; never equate CMS and operational Tenant IDs or invent a UUID mapping. Server-owned mapping validates scope on every favorable use. Slug, title, URL, creator, current inbox and list position are display/input hints, not identity. Use same-owner composite FKs for operational catalogue controls where appropriate; do not add Support-to-cms hard FKs or direct queries into Payload-owned tables.”

**Proof:** same slug across two Sites/locales; moved path; numeric CMS id versus operational UUID; removed/recreated document; corrupted mapping; cross-Tenant reference; migration/restore preserving old stable ids without rekeying.

### F03 — One tenant catalogue with explicit, independent management rights

**Material concern: Yes. High severity; medium likelihood.** Per-inbox article copies, accidental authority from D19 reviewer status or assuming a CMS admin can curate all Support can produce fragmented results and overbroad permissions.

**DR03:** “Use one flat tenant-level selected-guidance catalogue. Reuse the current Support shared-content-management capability with explicit tenant oversight for selection maintenance; introduce no new role enum, per-inbox body/list copy, nested folder/topic taxonomy or general publication approval workflow. Ordinary use still requires current Support context rights. Catalogue maintenance, source read/reference permission and CMS edit/release permission are distinct. Inbox assignment, intake-review responsibility, CRM ownership or Payload role confers none of the others. Staff may select only exact currently qualified public variants they may reference for this purpose.”

**Proof:** ordinary responder versus curator versus source editor/releaser; scoped curator lacking tenant-level catalogue management; staff loses role; two inboxes consume one catalogue without changing each other; CRM-only viewer cannot invoke unauthorized draft insertion; no tenant-wide private CMS enumeration.

### F04 — Listed and Shared by link cannot share one assumed search population

**Material concern: Yes. High severity; medium likelihood.** Excluding all Shared-by-link guidance unnecessarily loses legitimate public instructions; putting it in the public search index to make a staff finder work violates its discovery disposition. G04/G05 resolve the distinction.

**DR04:** “D27 may explicitly select an exact owner-qualified Shared by link — public variant for the authenticated staff guidance purpose, as well as Listed public guidance. This selection does not change public reach, navigation, site search, sitemap or indexing. Default public discovery may consume Listed source discovery; exact Shared-by-link selection requires the owner's separately qualified reference/projection path. Do not enumerate all anonymously readable Pages, crawl guessed URLs, use editorial private search as the public list, or treat the public search projection as exhaustive for the selected staff population.”

**Proof:** selected Shared-by-link result usable by authorized staff while absent from public search/sitemap; unselected Shared-by-link not broadly enumerated; unknown source cannot be found through guessed slugs; Listed→Shared-by-link preserves only explicit staff selection without widening public discovery.

### F05 — Selection lifetime differs from source publication lifetime

**Material concern: Yes. High severity; medium likelihood.** Automatically deleting a temporarily unavailable selection creates manual maintenance; re-adding every republished Page can revive a deliberate removal. Pinning a catalogue to one old article revision creates stale guidance and needless reapproval.

**DR05:** “Selection has one active/removed lifecycle with protected generations and immutable change attribution. It selects the stable exact Site/Page/locale variant, not a frozen article body or one editorial revision. Current source availability is derived separately. Ordinary approved source updates use the current qualified publication without a second Support publication; private drafts remain invisible. Unpublish/withdrawal makes a still-selected entry unavailable, not deleted. Valid republication of the same source variant restores eligibility only if selection is still active. A removed entry stays removed; explicit Add again is a new current-authorized generation. Adding a locale/Site/source successor never selects it implicitly.”

**Proof:** source unpublish/republish versus Remove/re-add; two curators race; old Add replay after Remove; late source event after removal; same source ordinary update; same URL points to different Page; new locale stays unselected.

### F06 — Ordinary removal is not source withdrawal or recall

**Material concern: Yes. High severity; medium likelihood.** Curators could assume Remove retracts already sent links, or an implementation could revoke all drafts/history and break ordinary communication merely because the catalogue was tidied.

**DR06:** “Remove from guidance stops new catalogue discovery/selection/insertion; it does not unpublish the source, erase an already authored independent link, modify an admitted message or recall delivered email. New use of existing typed inserted references still proves applicable public/source authority. Genuine source safety/withdrawal is stronger and follows current P17/Support source-serving and dispatch fences, independently of catalogue status. The UI distinguishes curation cleanup from source publication or safety repair and routes the latter to its actual owner. Ordinary catalogue removal cannot pretend to be universal URL blocking.”

**Proof:** remove unused selection; existing draft link remains authored but still source-qualified; source withdrawal blocks unsafe new use; already sent bytes remain historical; possibly submitted message reconciles its original identity; no ordinary Remove mutates a CMS publication.

### F07 — URL continuity must prove the same resource, Site and locale

**Material concern: Yes. High severity; plausible likelihood.** An old path can redirect to a replacement Page; a former hostname can belong to another Tenant. Following HTTP redirects or rebuilding from a current slug can silently change the guidance. G06/G07 own continuity.

**DR07:** “The website owner supplies the current canonical HTTPS URL from the exact current Primary Site Domain, locale route and source identity. Support never constructs it from the admin/login host, a mutable Tenant slug, provider preview host, arbitrary URL or generic default Site. Same-Page path continuity may preserve identity only under the owning route contract. A redirect to a different Page, Site, locale or owner is not automatic selection continuity; require deliberate replacement. A reclaimed hostname cannot validate old source authority. Future insertions use the current qualified URL; previously authored/sent URL and label retain their exact history and are never silently rewritten.”

**Proof:** same-Page path move; different-Page retirement redirect; primary-domain cutover; old domain disconnected/reclaimed cross-Tenant; alias/preview host rejected for new canonical link; missing route returns unavailable rather than homepage; no implicit cross-locale replacement.

### F08 — Exact language selection cannot silently fall back

**Material concern: Yes. Medium–high severity; high likelihood in sparse locale content.** A French-labelled link could return English guidance, source-change could overwrite an approved translation, or “all languages” could silently expand the catalogue. G03 governs the source.

**DR08:** “Each selected variant is exact Site Locale and source lineage. Request/draft language may guide the visible filter but cannot create a missing translation, choose an unselected locale, mix fields or silently follow browser language. Another available language is an explicit labelled staff choice. Show actual source language and public destination; ordinary translation Source changed is not equivalent to withdrawal, while current safety narrowing still wins. Do not add an internal translation/AI workflow or change the source locale's publication.”

**Proof:** locale enabled but not released; source locale public/target absent; approved target with newer source draft; explicit alternate language insertion; locale withdrawal while preview open; direction/script/accessibility; source title language and URL language agree.

### F09 — Additive shared queries must be complete and purpose-correct

**Material concern: Yes. High severity; high likelihood if current updates/detail methods or loaded-page filtering are reused.** A ten/twenty-item source page, per-result hydration or stale index can omit the only matching guide or turn failures into zero results. S02/S03 provide no ready complete finder.

**DR09:** “Add a bounded selected-guidance consumer query/projection to the shared published-content owner boundary. Apply current tenant/catalogue selection/source eligibility and the declared search predicate over the complete qualified population before result pagination/counts. Reuse existing public-safe source normalization and qualified read/search primitives; do not create a second article authority, public-search head or index arbitrary raw Payload bodies. Batch current-source proof and indexed selected references; avoid per-result remote source calls. Cursors bind exact scope/query/catalogue/source-generation semantics. If a page/owner/budget is incomplete, report incomplete/unavailable rather than zero or complete. No all-content crawl, external search vendor or D22 conversation-corpus expansion is introduced.”

The physical projection plan is a later owner implementation choice. It must handle explicitly selected Shared-by-link variants without violating G05's public index eligibility; a thin rebuildable staff-purpose projection is not permission to copy an article archive.

**Proof:** match beyond first page and source batch limits; mixed Listed/selected Shared-by-link population; concurrent selection/source changes; unavailable source/page; multibyte query boundaries; deterministic ties; no N+1 body reads; registered size/query/transaction budgets under skewed tenants.

### F10 — Cache invalidation is not the public eligibility fence

**Material concern: Yes. Critical severity for restricted disclosure; plausible likelihood.** Missed invalidation or a late index write could expose withdrawn titles/snippets after the source is no longer public. Tags do not isolate caches. S07 and G02–G05 distinguish these concerns.

**DR10:** “Serve results, counts, previews and favorable insertion proofs only after bounded current owner-generation/admission checks, independently of asynchronous index/cache cleanup. Source withdrawal and safety changes suppress positive output first; late older upserts cannot restore availability. Cache identity includes trusted Tenant/environment/Site/locale/public-source generation plus catalogue/current actor-purpose scope and query where relevant; tags are invalidation handles only. No stale-while-revalidate success when current eligibility is unknown. Reuse existing owner outbox/convergence/watermark/recovery primitives without a new queue or distributed transaction.”

**Proof:** paused index/cache worker; withdrawal with warm cache; stale generation after republication; remove/re-add in another tab; permission/tenant switch with delayed response; unknown admission fence; copied preview cannot outlive current permitted serving authority.

### F11 — A staff preview must not run a public application inside Support

**Material concern: Yes. High severity; plausible likelihood.** A live page preview may submit forms, run scripts/embeds, make unrelated requests or use staff session privilege. A raw rich-text conversion can populate restricted source records or misrepresent unsupported page sections. S04/S05 are relevant.

**DR11:** “Preview uses a passive bounded projection of the same currently eligible public representation, with supported text/link/media semantics and truthful notices for omitted interactive/unsupported sections. Do not mount active forms, arbitrary scripts, remote embeds, donor actions or private editorial Preview in Support. Open public page is a deliberate normal navigation to the owner-supplied URL, not proof of unrestricted embedded execution. Link insertion uses the existing qualified Tiptap/P17 link contract; CMS Lexical/compiled page content is not converted into a new Support article/editor authority.”

**Proof:** public Page containing form/video/custom block; signed-in staff versus anonymous projection; populated rich-text relationship; malicious URL/HTML/redirect; unsupported-section disclosure; no request/CRM/form effect from preview; actual public-page navigation preserves safe context.

### F12 — Current proof across owners must not become a distributed transaction claim

**Material concern: Yes. High severity; medium likelihood.** Selection Add could rely on stale public proof, while an attempt to atomically publish CMS, update Support and send email would violate owner boundaries and retain locks across I/O.

**DR12:** “Selection mutation is a Support-owned conditional local command with trusted actor/Tenant, exact source reference, current curation capability, current source-reference proof, expected catalogue/pair generations, durable semantic occurrence, audit and invalidation intent. Commit the entire reviewed bounded set or none; keep provider/CMS network I/O outside. A positive source proof is exact and bounded by the existing owner version/fence/expiry contract, never permanent authority. Recheck source eligibility at each favorable query/preview/insertion and at the qualified P17 preparation/admission seam. A change after earlier proof makes that use stale/blocked; no claim of one distributed CMS/Support/Resend transaction.”

**Proof:** source withdraws between Add preview/commit/use; lost Add response; duplicate command and changed payload; one invalid item in a selected set; current role loss; exact removal/Add ABA race; no source publication occurs as compensation for a failed selection.

### F13 — Supabase and Payload access boundaries must both remain effective

**Material concern: Yes. Critical severity; plausible likelihood.** Applying public operational RLS to a cross-schema CMS read or copying Support's broad staff CRUD into the catalogue can reveal private source/control metadata and permit unauthorized scope changes. G01/G08 and S08 resolve the owners.

**DR13:** “Support catalogue control/audit/history lives behind the existing packages/api/Phase12 boundary with non-null operational Tenant, trusted actors, valid typed states, scoped uniqueness and immutable attribution. Deny raw browser control/audit writes and unauthorized source-reference reads; qualify all grants, effective RLS USING/WITH CHECK/SELECT, RPC/definer/service paths and retained readers. CMS remains protected by its exact public/owner access adapter, not a claim that operational RLS automatically covers cms. Payload Principal Link, role or overrideAccess is not independent authority. No generic server proxy, source-ID pass-through, cross-schema migration or new credential is added.”

PostgreSQL USING may supply the effective WITH CHECK when omitted; omission is not itself a defect. Current Support core UPDATE already has both. The actual issue is effective capability, immutable fields and all entry paths, as in D26.

**Proof:** client forged Tenant/source/actor; direct raw Add/Remove/audit rewrite; cross-Site current capabilities; privilege loss; malicious CMS mapping; public-marker missing/wrong; definer RPC execution; service worker current checks; no unrestricted source title/status leaks.

### F14 — Minimal retention, repair and rollout must prevent shadow archives

**Material concern: Yes. High severity; medium likelihood.** Retaining copied full articles, private queries and previews forever creates an unintended archive. Broken selections can trigger recurring cleanup or a “fix” that republishes content automatically. Old readers can bypass new publication requirements after rollback.

**DR14:** “Keep active selection configuration for its legitimate active purpose, with minimal protected generations/receipts sufficient for correction and replay. Apply the actual finite owner retention to removed selections, audit, query state, previews and derived metadata; no article body or raw query analytics archive. Source content remains with its owner; inserted message labels/URLs and exact body follow D16/D17/P17/P6 history, not a catalogue copy. Show source-unavailable versus removed versus query-failed distinctly and route repair to the actual selection/source/Site/domain owner. Migration admits only evidenced exact mappings and qualified public variants; no mass seed from all published rows, guessed locale/URL or historical emails. Fence old raw readers/writers and preserve adverse/removed state on restore; broad email/Support work remains available when this optional finder is disabled.”

**Proof:** stale source selected then removed; source restored but selection removed; retention deletes preview derivatives; request query containing sensitive text absent from ordinary logs; migration across numeric/string IDs and two Sites; rollback after source withdrawal; finder failure does not block writing a plain reply; no routine direct database repair.

One current active entry per Tenant/exact source/Site/locale variant prevents accidental duplicates. The logical unique key must use true owner identity and scope, not normalized title/URL. P24 currently isolates deployment environments by database; retain environment as trusted execution/cache/audit context and do not add an inconsistent partial environment key to only one table. A future shared-environment database change belongs to the platform owner.

Selection controls and source publication are independent: **not selected → Add after qualification → selected/available; selected → source unavailable → selected/available after valid same-source recovery; selected → Remove → removed; removed → explicit Add again → new selected generation**. A public redirect to a different resource is a replacement decision, not a same-source recovery. Appropriate conditional Undo is a new current-authorized command and never restores stale source authority or prior mutable snapshots.

## Realistic complete cases

1. **Public flag, private Site Locale:** an editor has published Spanish Page data but the Spanish Site Locale closure is not released. The finder cannot use its staff Preview or raw published flag. Existing English guidance remains available only as an explicit actual-language option if selected.
2. **New private draft over live guidance:** Support continues to use the exact old released public projection. It neither exposes the draft nor removes the guide merely because the author is editing.
3. **Shared-by-link instructions:** an authorized curator explicitly selects the exact public variant. Staff can find it inside the private selected catalogue; it remains absent from the public site's search/sitemap. The UI never calls it private or guaranteed undiscoverable elsewhere.
4. **Guide source withdrawn:** it immediately stops positive finder/preview/insertion use, even with a delayed search deletion. The catalogue retains a minimal repairable unavailable selection. Source republication restores eligibility only while selection remains active.
5. **Curator removes an otherwise public guide:** no new picker insertion; earlier authored or sent URLs are not deleted or recalled. A real content problem uses the source owner's correction/withdrawal authority.
6. **Path move versus replacement:** same stable Page/Site/locale gets a new canonical URL through owner continuity. 8. **Public page includes a form:** passive preview presents supported public information and an honest omitted-interaction indication. Opening the public page is explicit; preview does not submit the form, act as a staff session or call a donor operation.
