## Six operating controls

These controls handle residual operation after mandatory proof. Severity failures are not accepted as a way to avoid fixing the design. Owners are accountable Core role owners; tenant staff do not need access to private operations payloads or SQL.

| Control                                     | Signal and threshold                                                                                                                                                                                                                                                                   | Owner                                                     | Response                                                                                                                                                                                                                                                         |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| O01 — Source/authority/privacy breach       | **One** cross-tenant/other-author/hidden-version disclosure or unauthorized edit; one known redacted/expired representation served after its current source fence.                                                                                                                     | Core security and exact Support/source privacy owner      | Disable affected edit/history path, preserve minimal evidence, apply current source containment, correct the writer/read/cache/restore boundary and re-run negative proof before reactivation. Never export the exposed body into diagnostics.                   |
| O02 — Revision/effect integrity             | **One** forked current head, duplicate accepted operation effect, no-op creating a revision, Saved without durable required source/result obligations, or operation-key reuse after pruning.                                                                                           | Support API/data owner                                    | Fence affected mutation path, reconcile the original operation/head using trusted control facts, repair the atomic/identity boundary and prove the triggering race. Do not fabricate another note or silently delete a valid revision.                           |
| O03 — Unintended business or message effect | **One** routine edit causing a new note/alert/donor send, author/source/audience change, financial/CRM fact mutation, or native human/retention clock renewal.                                                                                                                         | Support source owner with P17/P6 or affected domain owner | Stop that producer/callback, reconcile actual in-flight effects without claiming recall, restore correct owner mapping and prove both negative edit and positive independently authorized new-note paths.                                                        |
| O04 — Source projection recovery lag        | Required edit invalidation/safety-continuation oldest unresolved age **over60seconds for5minutes**. Current read/safety gates must already withhold stale forbidden results.                                                                                                           | Support projection/search owner and Core operations       | Inspect identifier-only failed work, retry/reconcile the original source effect, diagnose blocked dependency/capacity, expose truthful currentness and repair without replaying Save. Unsafe disclosure escalates immediately to O01 regardless of age.          |
| O05 — Sustained interaction failure         | Save or selected-history-body p95 **over2seconds for15minutes with at least100 observations**, or unexpected operation errors **over1% for15minutes with at least100 attempts**, excluding expected validation/authorization/conflict/backpressure outcomes from that error numerator. | Support API/UI performance owner and Core operations      | Check exact source/query/profile/network conditions, repair plans/worker/consumer regressions and apply fair backpressure. Keep unknown results truthful; never reduce authorization/history retention to hit a metric. Report excluded backpressure separately. |
| O06 — Canonical editor loss                 | **One** saved silent node/attribute loss, renderer-empty-as-success, new/retargeted prohibited reference or unintended actual file-membership change.                                                                                                                                  | Shared editor/Support source owner                        | Disable affected profile/writer, preserve the lawful original source for repair, correct validation/adapter/cohort and prove faithful supported deletion versus accidental loss. No lossy auto-migration or hidden restoration.                                  |

All six signals use minimized identifiers/outcome classes, not note text, private references or per-person productivity reports. Historical operation identity/material and metrics retention remain governed by their own finite purposes. These proposed timing thresholds are explicit operational choices, not claimed measured current performance.
