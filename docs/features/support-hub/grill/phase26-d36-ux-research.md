# D36 — Optional quotations that stay part of the reply

**Research date: 14 September 2026.** The founder selected **A — New reply only; add a quote when useful**. This is independent UX/vendor research for the selected answer and its adversarial review. Detailed recommendations below are proposed amendments until reconciled into the D36 decision package. This document does not implement the feature, change providers, send messages, or ratify additional scope.

**Recommendation:** Keep the ordinary reply completely unchanged. Put a modest, labelled **Add quote** action beside the selected reply-message context. One ordinary activation adds eligible text from that exact message directly into the existing composer, visibly separated from the worker's answer. The quote is removable in place, and choosing a shorter excerpt is an enhancement of the same action. No mandatory modal, source-search wizard, new settings hierarchy, or automatic history append is needed.

The strongest competing implementation is selected-text quotation alone. It can be fast for expert mouse users, but hidden discovery, touch selection, screen-reader selection, virtualized messages and focus loss make it an inadequate sole path. Keep a persistent labelled entry point; offer selection as an accelerator only when it preserves the same source and authorization contract.

## Proposed seamless journey

### 1. The ordinary reply

The worker opens the existing Support conversation, either directly or through an authorized CRM record. The composer shows the current recipient summary and which message is being answered. New-reply-only is the actual initial content state; it is not a collapsed block containing invisible earlier mail. The worker writes and sends normally without addressing a quote setting, answering a prompt, or opening a preview wizard.

Use **Add quote**, not **Show history**, **Include original**, or an unlabeled quotation-mark icon. “Original” can mean the first email, the selected message, or raw MIME. “Show” implies reading rather than adding bytes to the outgoing message. The modest label belongs close to the selected reply-message context, visually subordinate to the answer and Send. It should not be hidden inside the typography controls alongside a generic blockquote command.

### 2. Add context from the selected message

Activating **Add quote** acts on the exact identified reply-target message. In the ordinary eligible, within-budget case, it inserts the qualified content directly in the same composer. No confirmation dialog is needed for a reversible draft insertion. It must not silently choose the most recent message, the first email, or the full merged Support timeline.

The inserted quote starts expanded and visibly separated: a subtle logical start border, normal readable text, a compact **Quoted message** label, permitted sender/date attribution, and **Remove quote**. Use the existing Maia spacing/type/color tokens. The label and state cannot depend on pale color alone. No new card stack, bordered box inside another bordered box, or decorative avatar row is necessary.

Keep authored reply text outside the managed quoted source. Preserve the reply's current content, selections, attachments and governed signature/footer. An add action must not overwrite the answer, focus the wrong draft, or replace a whole editor value. Placement should remain predictable in the existing approved body/signature ordering; the parent D36 editor contract must decide this once for all entry points rather than different components guessing.

A short success state such as **Quote added** is sufficient if focus remains in the answer. Move/restore keyboard focus deliberately according to the action: the newly inserted source must be reachable, but do not jump the viewport to its end or steal the caret when an asynchronous response arrives after the worker resumed typing. Never animate new content above the active caret in a way that loses position.

### 3. A shorter excerpt

Some questions need one sentence, not a long received email. Let the worker select an exact contiguous passage in a qualified source and use **Quote selection** as an accelerator. The persistent **Add quote** path must still work with keyboard, touch, screen readers and no selection.

Selection must refer to one currently permitted canonical source representation. It must not capture arbitrary page selection, CRM text, private notes, hidden DOM, collapsed history, multiple message cards or unrelated browser content. A stale selection, changed message or unsupported projection should preserve the draft and offer a clear return to the selected message; it must not silently insert a different passage. Client-side selection text alone is not source evidence.

Where whole-message quotation is too large or a narrower passage is needed, provide **Choose excerpt** from the quote/source context. A normal text selection or accessible plain-text excerpt control may be appropriate; an elaborate range-builder or AI summarizer is unnecessary. The final implementation must qualify the accessible path before advertising excerpt support. Do not label paraphrased/rewritten words as a verbatim statement by the original sender. Generic authored blockquote formatting remains distinct from a source-bound quote, with D16/D17 provenance preserved when editing/removing source-derived material.

### 4. Quote another specific eligible message

For a worker reading earlier correspondence, a per-message **Quote message** action can feed the same composer operation. It must clearly add quoted content without changing the selected reply target or recipients. This is a shortcut to an intentional source, not a conversation-history picker or permission to quote every timeline item. If the final scope admits only the selected reply source, omit the extra action rather than displaying a control that silently retargets the reply. Do not create two competing definitions of **Quote message**.

### 5. Remove, Undo and continue

**Remove quote** removes the draft inclusion immediately without a modal; it does not delete the received source or current authored answer. Integrate with the existing editor Undo/Redo where technically sound. Undo restores the same source-bound material only while still permitted; it cannot revive expired/redacted content or a stale audience approval. Canceling a pending add also prevents a late response from inserting content.

An included quote should not be represented by an unchecked-looking toggle or three faint dots. If later manual collapse is supported, label it **Quoted message included — Show** and keep removal reachable. Collapsing changes only display. The simplest initial implementation can leave the quote expanded and avoid a new collapse preference entirely; long quotes should be shortened rather than silently clipped.

### 6. Recipient and source changes

Editing To/Cc is not quotation editing. On an actual audience change, requalify the selected sources for the final recipients. If the change makes previously reviewed context consequential, show a concise local review cue, preserve the worker's own text and identify the action required. Do not show a generic warning on every unaffected reply.

Staff permission to read the source is not blanket permission to disclose it. Message participants, CRM contacts, represented organizations and authenticated staff are different facts. New addresses, CRM merges or contact email updates do not silently inherit old source-disclosure authority. Ineligible quoted context must not remain sendable because it was added earlier; it also must not disappear invisibly while Send otherwise proceeds with a changed message.

### 7. Send and recipient experience

The recipient receives the authored reply, deliberately included quote and governed signature/footer represented in the complete reviewed canonical message. Plain text must carry the same substantive content and truthful attribution as HTML. No staff-only source links, internal IDs, old Bcc/header reconstructions, stale credentials, private download tokens or unreviewed assets are added. Permitted address/signature text already inside the source is part of complete content review, not evidence that a safe automatic stripping algorithm exists.

Support source/context admission, P17 Email Studio complete-message preparation, and P6 actual dispatch remain the same path for Support and CRM. No template or delivery adapter adds history after review. No quote action changes threading headers or makes a previously non-email intake an incoming email. A donor reading the reply does not need an Asym login to see the actual included permitted text. Native email grouping remains client-dependent.

## Base UI, Maia and accessibility

Use the existing approved Base UI/Maia components and editor integration; vendor pixels, Radix-based old mail examples and raw external HTML should not become a second visual system. Quoted content is semantic body content. Controls surrounding it should be native buttons or existing Base UI compositions, with visible names.

- [Base UI Toolbar](https://base-ui.com/react/components/toolbar) supports composition with menus/tooltips and warns about arrow-key conflicts with inputs. Reuse the existing editor toolbar instead of inventing a nested toolbar for a single quote action. [WAI APG Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/) recommends that toolbar grouping generally contain at least three controls; a lone **Add quote** is a regular button.
- If a per-message menu is used, [WAI APG Menu Button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/) requires coherent Enter/Space activation and managed focus. The menu is an optional shortcut, not the only way to quote the currently selected message.
- [Base UI Collapsible](https://base-ui.com/react/components/collapsible) provides controlled button/panel semantics. Its `hiddenUntilFound` keeps content in the DOM; therefore hiding is not authorization or exclusion from serialized email. There is no need to adopt this prop or add collapse if an expanded block is sufficient.
- [WCAG 2.2 target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) sets a 24-by-24 CSS-pixel minimum or applicable spacing/exceptions at AA. Treat that as a floor, not an ideal touch design; retain Core's roomier interaction target tokens where defined. Do not copy tiny screenshot ellipses.
- [WCAG status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) explains announcing success/wait/error states without taking focus. Announce **Quote added**, **Quote removed**, or a blocking qualification failure concisely; do not read the full email aloud automatically or continuously announce validation.
- Inspect keyboard-only, screen reader, touch, browser zoom and reduced-motion behavior. Base UI compliance is not inherited automatically by arbitrary editor node views; actual integration testing is required.

## The smallest complete design

Ship the ordinary reply, one clear add action, an expanded and attributed source block, removal, safe Undo behavior, an accessible deliberate excerpt path where supported, and truthful current-source failure handling. Keep source navigation in the current conversation rather than a new search product. One canonical operation can support a source-local shortcut without creating a new service or settings framework.

Reject a quote wizard, a mandatory confirmation after every reversible insertion/removal, automatic per-user quote-default settings, a full-history gallery, magical signature/forward stripping, generic AI summarization, remote-content loading, or an additional mailer. Each adds cost or ambiguity without evidence that it solves D36's actual problem. A provenance-preserving canonical quote representation is necessary domain integrity, not permission to build a general quotation management platform.

## Acceptance evidence to require

1. With no quote action, the newly prepared HTML/plain body contains only the authored answer and governed signature/footer; no historical body is appended by a later layer.
2. An ordinary eligible quote can be added from the selected-message context without leaving the composer or opening a confirmation dialog, and removed in one local action without losing authored text.
3. Add/Remove/Undo never changes To/Cc, selected reply source, headers, CRM identities, attachments, assignment, note history or business-domain action state.
4. Every insertion shows the exact included content and truthful source attribution; quoted and authored text remain distinct in both rich and plain output.
5. Selected-text quotation cannot cross source boundaries, capture hidden/internal content, depend solely on the clipboard, or silently replace a stale selection.
6. Add while typing, rapid double-click, delayed result after cancellation, retarget, mode switch, unmount, restored draft and CRM navigation preserve the user's intended draft with no duplicate or misplaced quote.
7. Permission, audience, redaction and retention changes invalidate stale copied material and prepared sends correctly; normal unrelated changes do not add unnecessary prompts.
8. Long/nested/malformed/attachment-only content produces a truthful bounded experience with no silent truncation, hidden extra bodies, accidental file inclusion or remote network loads.
9. Keyboard/touch/assistive-technology users can discover, add, inspect, remove and return to writing without a mouse-only selection gesture, focus trap, lost caret or color-only state.
10. During real usability qualification, measure successful add/remove, wrong-source incidents, unwanted-history incidents, lost-draft incidents and recipient comprehension. There is no existing Asym study proving this proposal beautiful or friction-free; set release task-success criteria in the final proof contract and test them.

**Independent UX disposition: Accept A with required amendments.** The selected default is sound. Seamless means the optional inclusion lives in the ordinary composer, with explicit source identity, immediate reversible actions, exact content visibility and the same owner/authorization path from CRM. It does not mean hiding transmitted material or allowing a UI shortcut to bypass source/audience preparation.
