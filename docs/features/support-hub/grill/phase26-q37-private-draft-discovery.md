**14 September 2026. Unanswered.** D1–D36 and all amendments, including D29-X01, are fully ratified. The next decision is how staff find and resume their own saved, unsent external Support replies after leaving a conversation. Private draft ownership, restoration, source permissions and guarded sending are already required; this question chooses the discovery surface.

**After leaving a conversation, where should staff find replies they started but have not sent?**

Illustrative example: Maya begins an answer, saves it, then moves to another request or checks an authorized CRM record. Later, she remembers she has unfinished writing but cannot remember which inbox or conversation it was in. The desired outcome is to find the existing draft and return to the exact conversation, audience and content with current permissions and review. This is a usability fixture, not a claim about observed ministry draft volumes.

## Three actual alternatives

| Option                                      | How it works                                                                                                                                                                                                   | Strongest benefit                                                                                                                            | Real tradeoff                                                                                                                                       |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A — A private My drafts view**            | A clearly named Support entry lists the current person's eligible saved reply drafts across their accessible Support inboxes. Open one to resume the same draft in its conversation.                           | A stable place to scan unfinished writing without remembering the inbox, assignee or work status; room for clear context and mobile reading. | Adds one navigation destination and a qualified personal read projection. It must stay a writing view, not a new team queue or status.              |
| **B — A My draft filter in existing views** | A personal draft indicator and filter refine the normal conversation list within its visible inbox/status/view scope. The existing broader-scope path remains available.                                       | The smallest extension: familiar lists and filtering without another destination.                                                            | Other filters can hide unfinished replies. Staff may need to widen the scope to see all their drafts, and the UI must make that limitation obvious. |
| **C — A Resume draft picker**               | A visible Resume draft action opens a compact searchable picker over all eligible own saved replies, using permitted metadata, then returns to the chosen conversation. It is not limited to a recent handful. | Quick switching near the current work, without a new primary list page; optional keyboard access can reuse the existing command pattern.     | Less room for scanning many drafts or long conversation titles. Complete pagination, mobile layout and focus/return behavior need care.             |

These are alternative primary discovery approaches, not three new tenant settings. All preserve the same private canonical draft and source authorization. None changes what Saved means, adds shared drafting, schedules a send or makes a status change.

## Single best recommendation: A

**Recommend A — A private My drafts view.** The accepted product already promises that people can leave and restore a reply. A clear place to find that work completes the journey: **My drafts → choose the conversation → continue writing**. It reduces the need to remember a conversation or understand how work-status filters interact with a private draft.

B is the strongest smaller alternative. It is worthwhile if minimizing navigation is more important than having a complete personal overview, but its scope needs to remain explicit: My draft inside a narrowed Open/inbox view is not necessarily all my drafts. C is credible for people who prefer a compact resume interaction and usually know which draft they want; it reuses an existing command/picker capability but has less scanning space.

This recommendation is a product judgment based on an already accepted task, not a measured Asym usability result or a claim that every help desk uses the same model. It does not select exact row fields, count behavior, ordering, limits, keyboard shortcut, empty-state rules, retention duration or a new default landing page. Those details must follow the selected policy and its full review.

## Research supporting the alternatives

The [current UX research](phase26-q37-ux-research.md) records source dates, editions and limitations. [HubSpot's updated Help Desk editor](https://knowledge.hubspot.com/help-desk/use-the-updated-reply-editor-in-help-desk), updated21August2026 and documented as beta for Service Hub Professional/Enterprise, provides user-private saved drafts and a Drafts entry. It supports a named return destination, not copying HubSpot's entire customer/ticket model.

[Missive's official search/filter documentation](https://missiveapp.com/docs/core-features/search-and-filter) explicitly lists My drafts, demonstrating a real filtering alternative. Its [draft FAQ](https://missiveapp.com/docs/core-features/conversations/faq) also documents shared/collaborative reply drafts; Asym does not adopt that visibility model. Search/discovery convenience is separate from authority to read someone else's writing.

[Help Scout's folder documentation](https://docs.helpscout.com/article/1429-about-default-folder-views-in-help-scout), updated13November2025, excludes drafts on Closed conversations and counts only Active conversations in its Drafts sidebar. This illustrates a concrete mismatch to avoid: permitted saved writing must not be mistaken for current Open workload, and an explicit current-view filter must not silently masquerade as a complete draft inventory. No inherited status-based deletion or donor-facing promise is selected.

[Intercom's Command-K documentation](https://www.intercom.com/help/en/articles/6272267-how-to-use-command-k-with-intercom-inbox), dated16January2025, demonstrates searchable permission-aware navigation/actions. It does not document draft retrieval. C is an Asym application of that interaction pattern, supported by Core's existing Support command surface, rather than a claim that Intercom ships the proposed draft picker.

## Boundaries that remain true in every option

1. **Private means private.** Discover only the current actor's currently permitted saved replies and safe metadata within the current tenant. Assignment, following, composing awareness and CRM links do not expose a colleague's draft, count or existence. Current access loss wins over a saved reference or stale list.
2. **One draft, multiple entry paths.** Resume the existing source-owned canonical draft in the same Support reader when entered through either Support or authorized CRM context. Do not copy content into CRM, Email Studio's reusable drafts, a task or another mailbox. Preserve return context and unrelated safe working text.
3. **Saved is not sent.** Confirmed server-saved drafts, unsaved local edits, failed saves, unresolved send admission and queued/accepted/delivered messages retain distinct meanings. An unknown send outcome follows the existing recovery path and cannot be relabelled an ordinary safe-to-send-again draft. Finding or opening a draft does not execute its staged work plan.
4. **Restore context under current checks.** Preserve exact reply target, audience, content, attachments, signature, quotation dependencies and staged action as governed by D2/D4/D23/D24/D36. New input or changed authority still requires appropriate review. A finder cannot silently readdress a draft, transfer its author or bypass collision/source checks.
5. **No draft-body search expansion.** D22 excludes private drafts from ordinary Support full-text search. An authorized finder/picker may use permitted conversation metadata and own-draft control facts without indexing private draft bodies or scanning restricted CRM data. D20 saved definitions still store criteria, not draft content or materialized membership.
6. **Initial scope is saved external Reply drafts.** Existing separate new-Note working-state preservation remains intact. This question does not create server persistence for D35's local posted-note edits, a shared approval queue, multiple new draft types or an offline outbox. Any separately established durable new-note contract must be evidenced and reconciled explicitly rather than inferred from a local editor state.
7. **Email Studio and delivery keep their roles.** Support owns private human drafts and save/admission. P17 supplies governed schema/content/presentation and complete-message preparation; P6 owns actual dispatch and reconciliation. Listing/filtering/opening drafts sends no email, creates no new prepared delivery, publishes no template and creates no CRM interaction. Deliberate Send retains the already-ratified boundaries.
8. **Scope without new platform work.** Use Base UI/base-maia and the existing qualified lists, filters or picker primitives. No new global personal-work product, private-draft admin access, provider draft synchronization, recent-only cutoff, retention timer, autosave cadence or arbitrary capacity limit is chosen here. Existing source expiry and privacy requirements remain in force.

## Verified remaining gap

The [independent gap review](phase26-q37-gap-review.md) pins D2/D4/D23 restoration, D20's existing filter catalog, D22's indexing exclusion and D35's posted-note edit limits. None chooses a cross-conversation finder for private replies. Current local draft reset, draft-mode writer and missing qualified finder are source gaps, not accepted behavior. A view cannot simply expose current raw draft rows and call them private.
