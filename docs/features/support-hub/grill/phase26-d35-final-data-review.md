## Material correction found and verified

The original proposed wording allowed a No changes result to record an operation binding optionally. It also left the minimal key-retention guarantee too implicit. An admitted no-op key could consequently be forgotten and reused for changed meaning; response-cache/material cleanup could release a previously used operation identity while the note was still capable of editing. This is a **High-severity, plausible integrity failure** under pruning/retry, independent of whether a no-op creates a revision.

The actual **R09/R11**, data **admission step 7** and subsequent retention paragraph now require:

- Every admitted Save, including No changes, records a minimal immutable content-free operation binding/result.
- An equivalent candidate creates no editorial revision, Edited timestamp, activity, notification or invalidation event.
- The binding or equivalent durable rejection fence remains until the note is irreversibly non-editable and restore/replay cannot re-enable its identity.
- Response caches and body material may expire independently; expiry never frees the operation key. No extra body, diff or unlimited content history is retained for this purpose.

The actual **P06/P15/P17** and **O02** cover no-op binding, changed meaning, cache/material pruning and operation-key reuse. **Resolved.** This is a precise safeguard within the existing source-owned operation model, not a new receipt platform or permanent private-text archive.

The proof ledger also now includes **P16**: close/unmount the reader before the Save acknowledgement, return and recover the same actor/tenant/note operation using a minimal handle, without persisting the private candidate or issuing a new save. This makes R11's supported navigation recovery falsifiable while preserving R08's honest limit on unsaved browser/OS loss.

## Substantive cross-document checks

**The final reference policy is usable and enforceable.** The main, UX, data and editor documents agree that supported mention/inline-image appearances may be intentionally removed or moved, including paragraph deletion. Retained typed reference targets/source/purpose remain a currently valid subset of the loaded base; unsaved Undo can restore still-allowed base references. This avoids frozen-node editing traps without permitting new notifying targets, remote assets, file-membership changes or history-token re-acquisition. Static/canonical validation still precedes potentially lossy parsing.

**The save protocol preserves both integrity and user intent.** Current-base comparison precedes new no-op/effect admission, while an already-bound same operation reconciles before stale-base rejection. A→B→A text equality does not reuse a head identity. A lost acknowledgement is Checking, not failure or cancelled commitment. Result receipt and current source read have separate meanings, so an old success cannot overwrite a later corrected or restricted note. The proof checks competing candidates, same-operation retries, changed semantics, pruning, expiry and navigation before acknowledgement.

**History privacy does not depend on guessed cross-version text mapping.** A current redaction does not imply that the same offsets/phrase identify every older representation. R14 and the data/editor contracts require source-qualified safe mapping or restriction of the affected older body and known derivatives as a whole. They explicitly reject fuzzy/first-match redaction and unauthorized restoration. D16's actual disposal path remains separate from routine editing; D17's original generation/deadline still controls all versions. There is no body-bearing undeletable audit or new retention interval created by Edit.

**The SQL contract is semantic, not a misleading syntax checklist.** Current source uses TEXT note/conversation IDs and broad grants; the final contract preserves actual IDs and requires same-note current-head relationships and a single closed mutation owner. It correctly evaluates effective USING/WITH CHECK and SELECT/RETURNING, grants, privileged paths and current source authority. The original-author equality is an authoritative invariant, not a browser menu condition or email comparison. It does not claim current migrations already satisfy it.

**Source and external effects remain separate.** A correction produces no new optional follower/mention message or P17/P6 send. Existing unsafe outstanding source-dependent material is fenced through its actual owner; valid body-free historical events and actual in-flight/delivered evidence are not indiscriminately erased. A genuinely new note or deliberate authorized attention retains its own positive effects. No note edit changes D29 acknowledgement configuration, outbound signatures, CRM last contact, giving or protected-care facts.

**D34 reuse is explicitly qualified.** The edited original note's source/author authority controls its technical composing context. Switching from an A-source note edit to a B-source Reply does not reuse a broad merged-root instance or reveal edit mode/history/candidate content. Save correctness remains the conditional source command even during awareness failure. D33 preference and D22 Find remain reading capabilities, not revision writers.
