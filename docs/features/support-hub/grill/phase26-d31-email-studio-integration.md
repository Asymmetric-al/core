## The exact seam

1. **Read/preview:** no send, draft materialization, template activation, provider preparation or recipient lookup is created by opening the chooser. A broken Email Studio/Resend connection cannot be a prerequisite to record internal follow-up when the Support command itself is available.
2. **Schedule/replace/remove:** the atomic effects are the D3 source reminder/state revision, trusted business evidence and required shared recovery/dispatch intent. No new system-message key, template, Delivery Plan, staff email or donor acknowledgement is generated.
3. **Due:** a valid current generation produces the accepted Open review cause. It is source work/UI history. There is no automatic external chaser or claim that the underlying donor-care action is complete. Existing independently qualified workflow failure escalation keeps its owner, audience and P17/P6 contract; this decision neither adds routine reminder alerts nor suppresses legitimate failure recovery.
4. **Compose:** staff may use the existing independent reminder control while a TipTap reply draft is open. Recipient audience, Reply/Note distinction, attachments, signatures and approved guidance insertion remain unchanged. D24-R05 forbids storing/applying a reminder preset in a curated reply/work shortcut.
5. **Send:** D4's ordinary Send preserves the current valid reminder. A separately chosen, already-qualified work action retains its D3 effect. This decision adds no combined Send-and-remind action, scheduled-send interpretation or new automatic message family. Prepared human reply material, group admission, provider outcome and ambiguous delivery follow their already-ratified contracts.
6. **History and CRM:** reminder changes appear as Support work history through the same currently authorized record. Only real outbound effects have communication history under their actual identity. No duplicated CRM task/Activity/delivery record is manufactured for a timer event. Resolving Support never proves receipt/refund/contact/recurring-gift/task completion.

The current Supabase support adapter's outgoing-message update clears `snoozed_until` and sets status Open. That behavior conflicts with D4's accepted ordinary-send preservation contract. The new chooser cannot be activated while that ordinary-send writer still silently erases reminders. Qualify/fence **every** old writer, including outbound message updates, bulk/palette actions and due jobs, rather than correcting only the visible menu. The [data review](phase26-d31-data-review.md) pins the exact source lines and tests; no runtime fix is claimed here.
