## Exact proposed amendments

Severity/likelihood below concern the unamended design, not an asserted production incident. The quoted clauses specify the permanent path; implementation names and storage layout remain with their actual owner.

### G27-01 — Frozen link content, typed source provenance

**Material concern: yes. Severity high; likelihood high if a raw URL is the complete model.** The source could become unidentifiable after a slug change, or a live reference could silently rewrite an authored message. This changes the source/material contract.

> A Guidance insertion produces a safe informational link occurrence in the canonical authoring document: human-readable label and exact owner-resolved public href, plus narrow typed source provenance for the selected tenant-owned Page/source, Site, exact locale, public route identity and qualified public-generation/material evidence. Use the owners' real typed identifiers, not a slug as identity or an assumed universal UUID. Enclosing tenant/environment authority derives from trusted context. Client attributes and cached descriptors are claims to validate, not permission tokens. The server derives the actual surviving source-dependency manifest from the canonical document.

> The copied label and URL are authored message content. The article body remains solely CMS content; it is not copied, expanded, embedded or rerendered within email. Observed article/publication revision is provenance; routine current article changes do not require the old article revision to remain the active public head. Source eligibility and safety remain separate current controls.

This is a narrowly registered P17 informational-link/source-material extension. It is not a new Role Layout, protected-action capability, article-document store, generic arbitrary reference graph or global URL registry. Proof: a routine article edit leaves saved draft and prepared bytes unchanged; spoofed source IDs/hrefs cannot claim qualification.

### G27-02 — Exact public URL and audience proof

**Material concern: yes. Severity critical; likelihood medium.** Staff preview access, default locale, current browser host or a reused domain could produce a wrong/private link.

> Public guidance qualification uses the shared current public-content contract for the exact source/Site/locale and trusted public origin/path. It proves current public serving/reach and source eligibility, including required source/domain/locale safety. It never uses an admin/preview URL, session token, portal route, unresolved bare Site root, current browser location, public-host guess, or fallback locale. Choosing another available language is deliberate; it does not silently change the email's language or translate the label. Source language and Site remain visible where they matter.

> Public means source-authorized public output, not everything a staff member can read. Guidance selection is a separate approved use from public search discovery. Listed/Shared-by-link/no-index meaning remains with P23; the finder cannot silently list a source publicly, create a sitemap/search result or broaden its distribution. An explicit qualified source-selection policy determines which eligible reach states this staff workflow may offer.

Proof: staff credentials cannot reveal draft content through preview; a cross-Site locale, retired host, private action or alternate domain does not qualify from a published flag alone. A public page is never treated as identity, consent, financial action or access authority.

### G27-03 — One deliberate insertion, no collateral changes

**Material concern: yes. Severity medium/high; likelihood high in everyday composition.** A stale picker result or paste can replace the wrong draft, signature or surrounding answer.

> Insert link targets the current authorized draft, purpose, editor selection and revision. It creates only that link occurrence in one coherent draft-history operation. Preserve existing text, signature, recipients, attachments and staged D24 work. If the draft/tenant/mode/source changed while lookup was loading, require a safe reapply rather than targeting the newest editor silently. Insertion sends nothing, publishes nothing, creates no note or work action and never performs automatic full-article quotation.

The preview is a passive source-owned published projection, not an editable Tiptap instance, app-authorized iframe or general web browser with forms/actions. The existing qualified editor renders the link as ordinary useful text; no new persistent approval badge is required on every sentence. Proof: rapid mode/tenant/draft switches and delayed results cannot cross-target insertion; standard undo leaves preexisting signature/assets and later independent edits intact.

### G27-04 — Editing, paste and Undo preserve truthful qualification

**Material concern: yes. Severity high; likelihood high if default link behavior is used unchanged.** Editing href can retain a false source badge; mark removal or Undo can discard known source restrictions.

> Label edits do not silently change the destination. Href edits and URL-only paste re-evaluate the source association: a different URL cannot continue to be presented as the approved selected guidance unless the public owner qualifies that exact destination/continuity. Preserve applicable D18 known source-derived label/material provenance and safety restrictions; removing a badge, changing mode, serializing HTML, plain-text paste, Replace, Undo or draft restoration is not declassification. Deliberate removal/replacement of the affected occurrence must remove only its actual material and preserve unrelated authored work.

> Qualify the exact link/paste/history schema so unsupported source metadata cannot silently disappear on save or source checks. App-controlled rich clipboard transfer carries validated structure/provenance; hostile clipboard metadata grants nothing. Arbitrary externally pasted or manually typed URLs remain under the existing ordinary-link policy and are never automatically called Approved guidance. No claim is made to detect all retyped text or police every URL on the Internet.

Use existing D18 derivative guards at the smallest link/material occurrence. Do not invent paragraph tracking, universal URL normalization, automatic page crawling or a generalized data-loss-prevention engine. A source change that cannot be safely represented fails the affected conversion/copy and preserves the editable draft. Proof: paste a different URL over a selected guidance link, remove link formatting, cross-copy Reply/Note and restore a now-restricted link; no stale qualification or silent source laundering results.

### G27-05 — Reply, Internal note, signature and CRM stay separate

**Material concern: yes. Severity high; likelihood medium.** Guidance lookup could switch purpose, add a public recipient or produce a second CRM composer.

> Guidance is available in the same canonical permitted Support detail, including the D26 CRM entry. Lookup preserves Reply/Internal note mode and does not transfer authority between them. Inserting a public link into a note remains internal-note authoring; Add note uses its owner validator, not external email preparation. Later Reply conversion retains current source/audience rules. Guidance insertion never edits the D23 managed signature or its public-responder fields, recipient list, sender, Reply-To, subject, CRM association or D24 pending work.

The selected guidance itself is public; adjacent private note/CRM context remains private. Consulting it grants no record access or business-action authority. Proof: CRM view-only staff can consult only the permitted source; inserting or sending still needs its actual draft/action capability; no duplicate P6 event or CRM Activity results from lookup.

### G27-06 — Email Studio and D18 reuse retain the link contract

**Material concern: yes. Severity high; likelihood high once teams reuse useful answers.** A saved reply can flatten the link into stale HTML, lose known safety provenance or turn a library edit into live fanout.

> The same qualified informational-link/source representation is valid in eligible Email Studio body content and D18 Reply/Internal note reusable wording. Authoring, save/offer/publish/import, insertion and eventual preparation use the owner-appropriate current validation. A private candidate may remain saved for repair without becoming insertable/published merely because it contains an unresolved link. An active reusable source cannot gain use authority from a cached prior qualification. Insertion copies exact structured wording and its known link provenance; it does not resolve a mutable latest article body or introduce a live nested source.

> Routine guidance article edits, routine saved-reply updates and removing an item from the guidance finder do not rewrite existing drafts or publications. Actual source withdrawal/restriction remains enforceable against affected known derivatives and new uses under D18/P17. Source currentness and existing library publication are separate facts. Contextual Manage source opens the actual CMS owner; Manage wording opens Email Studio; neither action grants the other's permissions or implicitly republishes anything.

There is no automatic Save conversation as template, article-to-saved-reply converter or general knowledge import. Proof: a D18 item containing two guidance links preserves exact copies and only the affected restriction; a library outage does not block a qualified ordinary reply that uses none of its unavailable material.

### G27-08 — Prepare, admit and dispatch through one fence contract

**Material concern: yes. Severity critical; likelihood medium under concurrency.** A link can become unsafe between preview and sending, or dispatch can silently rerender it to a different address.

> Before preparation, resolve and validate only the guidance occurrences actually present in the reviewed document through the qualified public-owner material contract. Establish exact source/route/language/current public-eligibility and safety evidence, bounded dependency identities and the disposition/fence needed for this use. A known invalid occurrence blocks only the affected preparation. Valid continuity may justify its existing href; changes to authored href/label remain explicit. P17 seals the exact document, dependency evidence, HTML and real plain text once.

> D4 admission claims exact preparation under its current source/material checks. P6's final submission boundary re-proves the registered current material/safety fences using the existing qualified local authority; it performs no full CMS read, article render or arbitrary URL/network fetch. The source's adverse change and the submission claim use the existing safety-epoch/state linearization semantics: adverse first blocks; may-have-submitted first becomes honest reconciliation, not recall. No component re-resolves after sealing, including retries.

This explicitly adds a narrowly defined guidance-source family to P17's material/dependency conformance. It does not make every ordinary URL a CMS dependency. Source owners expose current authoritative adverse evidence; an asynchronous usage index or cache notification is not the send fence. Do not wait for fanout over every saved reply/draft before an adverse restriction becomes effective. Proof: source withdrawal races preparation, D4 admission and P6 submission; exact stage outcomes and unchanged retry bytes match P17 semantics.

### G27-09 — Contain source unavailability instead of blocking Support

**Material concern: yes. Severity high; likelihood high during service faults.** CMS cold-read failure could disable all replies or be mistaken for a nonexistent article.

> Distinguish valid current proof, known unavailable/restricted source and temporarily unavailable proof. Reuse currently valid owner-qualified immutable material and authoritative adverse fences when their contract permits it; never claim a stale cache alone proves current eligibility. If required proof cannot be obtained, preserve the affected link/draft and hold its preparation with a precise owner failure. Other composition, existing saved wording, internal work and replies without that unproved dependency remain available under their own gates. Removing/replacing the affected material is an explicit reviewed edit, not automatic fallback.

No per-keystroke checking, arbitrary URL HEAD request, global CMS-health send switch or new public-content replica is required. After preparation, only the registered current fence contract matters at dispatch; the CMS author's UI uptime is not an additional gate. If the authoritative fence itself is unavailable, the affected operation fails safely under its existing owner. Proof: guidance lookup unavailable, source known withdrawn and core fence read failure have different truthful outcomes; no unaffected reply acquires a CMS dependency.

### G27-10 — Preserve source identity through site and language changes

**Material concern: yes. Severity high; likelihood medium.** A bare URL or current-site default can send people to another tenant, language or visitor task after a move.

> Bind the link's source identity, Site and exact locale independently from its editable visible label and frozen href. Domain roles, Site suspension/retirement, exact locale publication, Page purpose continuity and explicit owner replacements follow P23/P24. Never infer continuity from matching title/path, substitute the Default Site Locale or redirect a private/app/protected destination through ordinary guidance. A qualified old public route to the same Page/Site/exact locale may continue; a different-Page replacement does not inherit Guidance selection/approval and needs deliberate source reselection for new use/preparation. Absence of proof keeps the affected new use unavailable. Changing browser/UI locale never retargets a saved link.

A guidance reference creates no everlasting domain reservation or positive hosting dependency merely because a sent email can exist outside Asym. Source owners retain domain/site lifecycle and honest external-link limits. Known unsubmitted consumers respond through the registered source fence; external accepted copies cannot be recalled. Proof: primary-domain change, retired Site, source-language withdrawal and same-Page continuity preserve precise approved meaning or block correctly; a different-Page successor remains ordinary navigation evidence until deliberately reselected.

### G27-11 — Retention, history and copy limits remain source-owned

**Material concern: yes. Severity high; likelihood medium.** A source snapshot or email receipt could become a hidden permanent article/archive or protected URL store.

> CMS retains its article/version/publication evidence under its owner policy. Guidance selection holds only necessary typed references and bounded configuration/provenance, not full article HTML. Draft, reusable wording, admitted Support content, sealed provider material and Recent copy retain their existing D18/D16/D17/P17 purposes and ceilings. Source lookup/insertion does not renew conversation retention. P6 durable history stores only permitted safe source/dependency references and hashes; no new full URL, source-body or personalized-label archive is introduced. P17 Recent copy still excludes URL/action targets.

Expired or safety-restricted content cannot be reconstructed from an article preview, saved draft, search index, cached response, provider history or restore path. Received external email copies remain independent custody. There is no click/open tracking, automatic efficacy score, customer deflection credit, CRM last-contact event or D14 fulfillment solely from finding/inserting a link. Existing relevant library insertion metrics retain their own meaning; D27 does not require another analytics product. Proof: cleanup/replay/restore and absent source metadata remain safe and truthful.

### G27-12 — Copy, import and schema evolution fail at the affected boundary

**Material concern: yes. Severity high; likelihood medium.** Portability could move a source reference into another tenant as if it still carried publication/disclosure authority, or an old reader could silently drop the new schema attributes.

> Native copy/export/import preserves eligible structured link provenance as data, never tenant source-use authority. An authorized replacement uses the actual destination owner and normal authoring review. > Version the minimum canonical schema/adapter/serializer contract needed for the optional typed guidance provenance. Qualify Tiptap paste, markup, plain-text, selection, Undo/Redo, copy-in and shared compiler round trips together. Unsupported material remains repairable/read-only or fails the affected conversion according to D23; no silent metadata loss, automatic upgrade or broad rich-text converter. Existing P17 publications/prepared artifacts are never recompiled in place.

Proof: same-tenant reusable copy retains source restrictions, destination tenant import grants none, old schema readers cannot admit new source-tagged material falsely, and neither source nor destination publication is activated by import.

P17 requires its existing purge/finality rules; body-free identity/evidence supports later reconciliation. Preserve original content meaning and identity without rewriting or recalling mail, while every actual copy follows its own retention authority.

These are consistency corrections within the selected A decision, not additional product scope.
