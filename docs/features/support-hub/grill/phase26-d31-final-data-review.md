## Proportion and semantic review

The full source/work lifecycle is still owned by D3; D31 does not create recurrence, personal presets, a second task/scheduler, preview persistence, signed proof of viewing, AI timing or a new scheduled-message family. Quick activation commits the actual displayed candidate; Custom has explicit Set/Update. Ordinary valid use does not acquire an unnecessary second confirmation.

Zone edits before admission are deliberate input changes, so their new candidate must be visible. Once admitted, the exact normalized operation identity and result are immutable for retry purposes. Display conversion, default-setting changes, current viewer context and relative label refresh cannot become new semantic input to an old command. Current authorization still governs receipt disclosure and further actions; an original receipt does not preserve revoked access.

These are appropriate independent requirements rather than a fictitious single long-lived executor promise.

The proposed load/latency and recovery targets are explicitly prospective release gates, with hardware/distribution/dependency conditions and separate client/network metrics. Their exact values are product/engineering judgments, not measured capability or customer-visible SLA. Runtime failures cannot be relabelled passing reference examples. Kill-switch/rollback language preserves accepted due work and does not restore the old unsafe timer writers.
