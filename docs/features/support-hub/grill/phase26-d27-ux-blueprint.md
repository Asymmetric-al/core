The full ratification appended below governs current status. This remains exploratory grooming, not formal specification, implementation or release proof.

The staff-facing name is **Guidance**. Supporting text says **Published pages selected for Support**. This is a selection of maintained public pages, not a claim that an administrator legally approved every statement or that the content never changes.

## The ordinary Support journey

1. **Stay in the conversation.** Staff read the request and start their normal reply or internal note. Their current inbox, recipients, purpose, signature, draft and work state remain visible. A clearly labelled Guidance action sits with related insertion tools such as Saved replies, without giving it a separate main navigation area. Opening Guidance is deliberate; Asym does not extract a search query from a sensitive message.
2. **Find a page.** Guidance opens in the existing auxiliary context surface; it replaces that surface's current content with a recoverable Back path instead of adding a fourth persistent pane. At narrow widths it becomes a single layered sheet/full-screen surface. Initial focus enters Search guidance. Blank input shows the selected, eligible corpus in a restrained paginated list. Results use a title and short source description, with Site/language only where useful for distinction. Search covers title, summary and eligible public text through the owner projection, including deliberately selected Shared-by-link Page bodies. If coverage is updating or incomplete, staff see that status; No matches is reserved for a complete qualified search. No hero images, card grid, tag cloud, popularity score or AI panel is needed.
3. **Understand the scope.** Language and Site filters appear only when there is a genuine choice. An explicitly resolved conversation language/site may initialize them; otherwise the visible scope is All languages/All sites. Staff can clear either separately. Searching Thai or Spanish never silently becomes English; zero results never silently broadens a Site. Matching title, description and snippets use safe text rendering, including right-to-left text, punctuation and international names.
4. **Preview before choosing.** Activating a row opens its preview rather than inserting immediately. Show the source title, language, public Site/domain and a public/link-only indication where it matters. Render readable source-owned public text and allowed static media. Forms, donation widgets and embeds do not execute here. A notice such as “This page includes interactive content. Open the public page to use it.” preserves meaning. Open public page uses the qualified public URL; it never opens a CMS editor preview under the guise of recipient access.
5. **Insert deliberately.** At a valid caret, the button reads Insert link and inserts the human-readable Page title. For ordinary selected text it reads Link selected text, preserving staff wording. Protected signature/content or an invalid/stale selection gives “Choose where to insert this link in your draft” and returns focus to the draft, with no loss or implicit replacement. Source eligibility is checked again; the selected Page is not assumed safe just because an earlier result was visible.
6. **Return to the same draft.** The finder closes/returns focus to the linked text using the existing editor's convention. One insertion command creates one link and one normal undo step. A succinct live announcement confirms insertion; no blocking success dialog is needed. Staff can change visible wording, Undo, continue writing or remove the link. Recipient, purpose, signature and status remain unchanged.
7. **Review and send normally.** This action does not send or resolve. P17 prepares the whole actual reply, including the Guidance dependency and current signature once; Support authorizes/adopts the reply; P6 delivers under existing invariants. An internal note stays internal. When a source is unavailable, the inline message identifies the affected link and offers an appropriate replacement/removal/retry path. It never suggests bypassing a privacy hold by stripping provenance.

Illustration only: a donor asks how to find a receipt. Staff may search “receipt,” preview the tenant's published instructions and link the words “how to find your receipt” in a personal answer. This does not issue a receipt or attest that the requester may access a specific gift. If a tenant has no such Page, staff can answer normally or use existing saved wording. The example is not a compulsory template or invented universal ministry workflow.

## Starting from CRM

1. Open the CRM record under CRM permissions. Use the ratified D9/D26 Support overview or Communications view to choose an applicable conversation. The compact overview remains its existing preview, not the only source of history.
2. Open the same canonical Support detail inline where practical, with the existing full-page fallback. Joint authorization determines what can be read and done; a CRM record owner is not automatically a Support worker, and a Support handler is not automatically allowed to read restricted CRM data.
3. Use precisely the same Guidance surface, source qualifications and draft. No second CRM copy of the Page, transcript, editor or selection is created. A read-only staff member can consult public guidance but has no insertion action without the existing draft capability.
4. Return to the CRM record with its filter/scroll/selection preserved. No Activity, last-contact timestamp, donor preference, relationship, receipt/refund or case resolution is created by lookup or insertion. Actual correspondence and actual business actions retain their existing owners and histories.

Unidentified requesters, shared email addresses, represented organizations, merged/unlinked CRM records and reopened work do not change these rules. A Page's public access does not prove identity, household membership, financial access or language preference.

## The curator's first-use journey

1. An authorized curator opens **Manage guidance** from the finder or the existing Support settings area. Staff without this capability see the useful finder and an explanation if no guidance is selected; they do not get broken management links or an unrelated admin invitation.
2. The management view is one simple list: Page, Site/language, current eligibility and last selection change. Active selections and Removed history are distinguishable. Available, Unavailable and Checking are current derived conditions. These names must not be overloaded as CMS publishing states.
3. Choose **Add guidance**. The source-owner selector lists referenceable public Page variants under the curator's independent source-reference permission, with current public qualification. The curator selects an exact Site/Page/language. A public page address can identify an owner-resolvable candidate if the shared selector supports that operation; an arbitrary pasted URL is never crawled or accepted as a substitute for stable source identity.
4. Preview the Page and its public destination. For Shared by link — public, explain that recipients can view and reshare it; selection does not make it listed in public search. Review source scope, then **Add to guidance**. One command creates one selection with trusted history. Double-click/retry cannot add duplicates.
5. Return to the list with the outcome visible. During favorable search convergence the curator sees Checking/Updating, not false success about instant search availability. A new translation or another Site's similarly titled Page is not added automatically.

No custom ordering hierarchy, inbox clones, personal variants, Support keywords, per-article review workflow or mandatory multi-person approval is introduced. Existing tenant oversight can manage coverage and curator permissions. Source-reference permission is not CMS edit/publish permission.

## When a suitable public page does not exist

Preserve the Support draft. A CMS-authorized person may use the existing **Open Web Studio** work path to create or improve the source under its normal editor, review and publication rules. Returning to Support requires explicit selection of the now-qualified exact public variant; a draft/editor preview is not eligible.

A Support-only worker can communicate the content gap through the tenant's existing authorized work process. This decision does not add a new generic request queue or automatically create a ticket, nor copy the private conversation into a CMS task. Any transferred context is a deliberately selected safe source reference or non-sensitive description. Ordinary Support work can continue without a new Page.

## Accessibility, visual quality and low-bandwidth behavior

Use the existing base-maia/Base UI structure, type scale, spacing, borders and focus treatment. A calm text list, readable preview width, concise metadata and one clear insertion action make the feature fit Asym better than an illustrated knowledge dashboard. Source titles can wrap; Site/language context must not be reduced to inaccessible tooltip-only text. States use text and icons, not color alone.

Keyboard navigation must preserve text-editing keys and IME input, announce selected results and respect the app's existing shortcut conventions. Do not invent a global shortcut that conflicts with composing. Return focus to the original trigger or insertion point. A slow prior search response cannot replace a newer result set or steal focus. Screen readers receive one relevant result/update announcement, not repeated full-list narration. Opening the public Page uses safe external-link handling and does not leak a private conversation URL as referrer/context.

On a phone, Search → Preview → Insert/Back is one stack. Back restores query/filter/scroll; closing restores the draft. Do not require precision hover or a modifier key to preview. Reflow and zoom must leave primary actions reachable without two-dimensional page scrolling. Respect reduced motion. Lazy-load public media and cancel obsolete preview/search requests; text remains useful on a slow connection. Do not introduce offline article downloads or persist sensitive preview/draft context beyond existing owner rules.

### Accepted product and owner boundaries

One manually opened Guidance finder works inside the canonical Support detail also used through CRM. One flat tenant-curated reference set identifies exact owner-qualified public Site/Page/locale lineages. Staff search titles, summaries and eligible public text, including body-only matches in selected Shared-by-link Pages without broadening public discovery. Simple visible Site/language filters do not silently widen or translate. Incomplete coverage is shown to staff; No matches describes only a complete qualified search.

Preview uses safe passive source-owned public content; no forms, giving widgets, scripts, arbitrary embeds, private previews or full CMS editor execute in the Support staff context. Insert link uses a valid caret and source title; Link selected text preserves staff wording. Stale/protected targets require a valid insertion position. The exact private Tiptap draft, purpose, recipients, signature and work state survive consultation, navigation, insertion, cancellation, Undo and CRM return. Read-only consultation does not grant draft mutation. Guidance creates no Party, CRM Activity, last-contact update, financial action, automatic message or resolution fact.

Web Studio owns source content, language/publication and public destination; the shared public-content/runtime owners supply current stable mapping, public generation, route/domain/safety proof and complete derived search. Support owns selection, current draft/work authorization and send admission. The current null-Site/mutable-key source is not sufficient implementation evidence; owner-qualified P23/P24 contracts must precede activation. ### Accepted curation, temporal and safety behavior

Active/Removed selection intent is separate from Available/Unavailable/Checking source eligibility. Removal changes future offers without changing publication or otherwise safe existing copied links. Ordinary source edits update future previews/new links without rewriting composed/prepared/sent content or requiring per-revision Support approval. Exact same-Page/Site/locale owner continuity may preserve an old href; different-Page redirects and reclaimed domains do not inherit selection approval or source identity. Replacement-source use is deliberate.

Unpublish/loss of public eligibility without qualified continuity stops new use and fences exact definitely-unsubmitted dependent sends through existing owner no-new-public-use dispositions/P17/P6 safety epochs. Dangerous withdrawal preserves applicable D18 known-material restrictions. A transient proof failure holds only affected new qualifications/preparations, not unrelated Support work. Current public/safety restoration may recover Active finder selections. Removed selections stay Removed, but safe already-copied links may requalify from current source proof without re-adding them. Fenced/terminal prepared effects never auto-revive; current authorized P17 recovery/successor preparation and admission apply.

### Accepted Email Studio role and delivery seam
