## Initial substantive finding — F02, source-only legacy baseline

**High severity; plausible implementation/migration failure.** The original integrated R05 required reading order to be allocated at first eligible publication, but all currently qualified legacy content predates that new control ordinal. R23/P25 said to qualify source order without distinguishing historical source import from the rejected per-person enrollment cutoff. Implementers might attempt to reconstruct historic COMMIT order using message IDs/timestamps, fabricate admission events or exclude legitimate old sources indefinitely. None is necessary.

**Required permanent clarification, accepted by the root:** before personal markers/ACKs can be admitted for an original, gate all relevant source eligibility writers and capture the complete already-committed qualified eligible baseline under its source protocol. Assign stable internal reading-control ordinals; preserve real content IDs, dates, provenance and existing activity. All later eligible admissions serialize above that boundary. Do not claim reconstructed historic commit order, fabricate Read, fan out staff rows, change D15/D17 events or introduce a per-user activation cutoff. Unknown/incomplete baseline cannot enable acknowledgment, and an old-dated late first-eligible contribution cannot appear below a live read cut.

This changes implementation/migration precision, not selected personal meaning or initial Unread semantics. C04/C15 now contain the correction. Actual R05/R23/P25 must be rechecked before closing this finding; the existing migration proof group is extended rather than a new product/platform introduced.
