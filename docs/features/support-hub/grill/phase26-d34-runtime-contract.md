## Request path

`current visible reader → qualified Core API control → app-schema ephemeral lease → private server-originated refresh hint → current-authorized HTTP snapshot → isolated peer cue`.

Typing and the existing private draft editor never wait for this path. A cue reports recent authenticated intent, not the draft. Supabase carries the private wake; actual names are obtained only through Core's current read boundary. This avoids trusting raw client Presence and cached room membership without creating a second message/CRM authority.

Use existing browser Supabase ownership through `packages/database`; one qualified browser client per actual browser auth context, and owned/refcounted channels. Different tabs have separate browser runtimes—no new cross-tab coordination service is introduced. Same-topic requests in installed realtime-js2.103.0 reuse the existing channel even if configuration differs, so every issued topic has immutable private configuration. Remove only the component's owned channel when its last consumer leaves. Never call global removeAllChannels/disconnect as one reader's cleanup.

The server uses the qualified adapter's bounded REST send without keeping one RealtimeChannel object per observer forever. If SDK `channel().httpSend()` is used, dispose the ephemeral owned channel after the send; the lack of an actual socket does not prevent a warm client's in-memory channel registry from growing. Server credentials remain in the existing server-only credential boundary. No package install/upgrade is required by this decision.

## Endpoint and render ownership

Business logic remains in `packages/api`; thin app route reexports and the shared database client matrix remain authoritative. Core uses Cache Components and its current runtime map prohibits route-segment `dynamic`, `runtime`, `preferredRegion` and `maxDuration` exports. Do not paste a generic force-dynamic example. Current cue responses use private/no-store HTTP handling and current authenticated request context; neither Next shared cache nor CDN/persisted TanStack cache may store names/active state. Follow Core's TanStack convention for the narrow read model rather than installing SWR because a generic skill suggests it.

Keep volatile timers, sequence/window, latest input/eligibility and in-flight desired state in the feature controller, outside React render state where they do not affect presentation. The view changes for an actual permitted actor-set or availability change. A renewed deadline can update an internal timer without rerendering the full conversation/editor. Never route-refresh per wake, move the editor between parents on a cue change, serialize extra draft content or subscribe the entire page to every activity tick.

The installed Tiptap3.22.3 `useEditor` branch does not force transaction rerenders when `shouldRerenderOnTransaction` is absent/false, despite generic older commentary. Existing parent/draft onUpdate costs still need profiling. Preserve `immediatelyRender:false`, draft serialization and qualified input adapters; do not silently replace current draft behavior or add a collaboration extension. Subscribe to actual intentional composition, including IME/paste/toolbar actions; not every transaction or keydown is user input.

## Subscription, refresh and control orchestration

Register only a current visible eligible client reader, not SSR, prefetch or an offscreen list. Obtain its private topic, subscribe, then reconcile after subscription to close a snapshot-before-subscribe gap. An initial snapshot may run in parallel for responsiveness, but does not replace post-join reconciliation. A failed join does not prevent current HTTP snapshots.

There is one serialized control stream and one coalesced snapshot path per instance. A combined accepted control can carry its current snapshot. Periodic refresh, hints and post-join reconciliation share single-flight/backpressure; a wake during a request sets one dirty follow-up instead of creating concurrent snapshot-only reads. Snapshot-only reads do not advance the control generation. A just-completed combined response may satisfy a pending periodic read. Process a valid control ACK separately from its peer projection: a later snapshot can supersede old peer data without losing the ACK's accepted sequence/window; an ACK cannot overwrite a newer displayed projection. A pending current start/stop flushes after a known control result or read-only reconciliation, rather than waiting another5seconds.

Ordinary combined refresh is5s while locally composing **or** displaying at least one still-trusted peer, otherwise10s. Count the union once. Use bounded timer jitter only for background scheduled renewals, while maintaining the hard deadlines and declared maximum interval; do not delay leading starts/stops. Hidden/inactive instances cease composition; hidden readers stop renewals and requalify on return. Token/session/source changes fence old results. Logout clears volatile state. Strict Mode, repeated mount, hot reload and async teardown must never stop a newer generation.

Only meaningful transitions wake eligible observers; unchanged liveness renewal never fans out. Natural expiry is locally timed and reconciled, not a job/event per expiration. Wakes are hints: duplicates/out-of-order delivery coalesce into current reads. No missing hint needs a durable replay queue. A server lease transaction is authoritative for the ephemeral state; the subsequent REST wake is bounded best effort. Catch non202 rejection/timeouts;202 never proves the recipient saw a cue.

## Latency and cost proof

Let N be live reader instances, F the union of instances locally composing or displaying a current peer cue. Ordinary combined traffic is `(N−F)/10 + F/5` requests per second. Each may require one lease update and an authorized snapshot. With N500/F300 that is80requests/s; with N1,000/F1,000 it is200requests/s. These are arithmetic examples, not measured capacity. State transitions, wake-triggered snapshots, joins, auth queries and cleanup add cost. Wakes scale with transitions×eligible observers. REST batching reduces HTTP envelopes, not necessarily delivered-message quota counts.

Healthy connected release target: p95≤1,000ms from qualifying start/explicit stop to the other eligible reader's rendered cue/removal. Instrument input, control admission, dispatch, wake receipt, snapshot completion and paint without content. Report p50/p95/p99 and loss/unknown rates, not just average websocket latency. Count transitions delayed by ordinary in-flight controls; do not cherry-pick only an idle transport. Separately report cold registration, reconnect, broker failure and constrained networks.

The minimum repeatable release fixture uses1,000 total active instances across20tenants,500 fast instances, one100-instance eligible source context and at least10,000 start/explicit-stop samples after warm-up. Include the deployment's supported representative near/far staff regions, actual Supabase primary/Vercel region/Node/runtime/SDK versions, and measured network RTT/loss. Synthetic mock clocks do not establish regional behavior. Also run one noisy tenant, simultaneous reconnect, overflow N+1, two-device staff and mixed-version cases. The one-second healthy target is assessed only for declared supported connected-network conditions; degraded-network results must meet truthful expiry/no-lost-work behavior, not a universal zero-lag promise.

Before enabling real tenants, record actual plan quotas and confirm the declared deployment ceiling at ≤70% of measured sustainable requests and provider configured message/connection/join capacity under the tested mix. “70%” is an operating headroom rule, not proof a vendor guarantees it. A failed target requires latency-path optimization or a reviewed smaller activation envelope; do not silently weaken authorization or claim the target passed.
