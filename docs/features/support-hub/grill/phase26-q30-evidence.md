# Q30 evidence — Focused versus configurable Support reporting

**Research date: 13 September 2026. Q30 is unanswered; D1–D29 are fully ratified.** The [question](phase26-q30-support-overview.md) concerns presentation/composition breadth, not whether truthful reporting, tenant isolation or prior source semantics are optional.

## Why this is the next meaningful choice

The session has resolved intake, work ownership, replies, assistance, CRM continuity, privacy, search/views/labels, approved content, feedback and requester Help. D14, D21 and D28 already specify report families. Their existence does not settle whether the lead reviews them through a focused overview, separate report pages or saved configurable compositions. This is a genuine remaining product tradeoff. By contrast, runtime RLS/provider/migration/collision proof is mandatory delivery work, not a feature vote; the roadmap's older unresolved items cannot reopen already-ratified answers. Manual priority is also a weaker next branch because D10 already incorporates priority behavior in merge/Undo.

The source contains an Overview scaffold today. A improves and qualifies that permanent presentation; it is not justified by claiming no overview exists. B can keep a coherent Reports index and every required report without a combined overview. C starts from an effective default and composes only approved blocks. This treats the simpler and broader alternatives fairly.

## UX recommendation and risks

A should use restrained information hierarchy: scope first, current actionable work, then period-based results with links to the full accepted reports. The page helps a person decide where to investigate; it is not an alternate inbox or a wall of attractive but incomparable cards. Desktop/narrow layouts should preserve the same reading and keyboard order, with textual meanings and usable row/table alternatives rather than hover-only chart facts.

The most consequential pitfall is a global “last 30 days” filter applied to a card labelled “currently waiting.” It can hide an older unresolved request while making current work look healthy. Another is combining current-label topics, target-due periods and response-completion samples as if they count the same things. The recommendation keeps Now independent and each result's exact population visible. Unknown/partial/disabled/loading/error states stay distinct from zero.

The public/current product evidence supports the navigation pattern, while Core's ratified contracts provide the metric truth. There is no measured Asym team-lead study, tenant dashboard-configuration demand, production performance result or accessibility test for this proposed page. The illustrative donor-care scenario is a design test case. A full selected-answer review must specify the final card selection, interaction, source/authorization, failure, migration and proof obligations before implementation; asking the scope question does not silently freeze them now.

## Email Studio and scope discipline

Opening a report, changing a filter or saving a layout is not an email trigger. No scheduled management digest, daily summary, public reply promise or new feedback invitation is included in Q30. Phase 33 owns any later separately authorized report run/schedule/snapshot and recipient eligibility; P17 owns governed message preparation, P6 dispatch/history. Each recipient must be independently authorized. The newly ratified D29 web confirmation and D28 feedback families remain unchanged.

Support owns support-specific source facts; shared reporting owns reusable metric/composition capabilities where qualified; CRM and giving remain authoritative for their own records. A useful fixed overview does not require duplicating those records or waiting for a generic custom BI product. If C is selected, its exact bounded shared composition and maintenance contract must be completed as part of the chosen scope.

The recommendation is **A**, with B and C retained as genuine choices. Q30 remains unanswered. Source/format/link validation and independent review can establish documentary consistency; no runtime test or new formal specification is claimed.
