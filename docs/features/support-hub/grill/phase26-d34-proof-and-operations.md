## Deployment sequence and rollback

1. Complete owner source/session predicates and additive schema/closed commands. Validate actual grants/RLS/service paths in isolated test tenants, with no real mail.
2. Qualify SDK/REST adapter and client island; exercise missed-hint/current-snapshot behavior and the full input/source matrix.
3. Execute P01–P36 and name actual deployment roles/versions/regions/quotas/ceilings. Existing D1/D4/D2/source/privacy prerequisites must pass independently.
4. Enable a bounded consenting pilot under current product release policy, then expand within the measured envelope. No new commissioning process for every ordinary staff member or user-configurable heartbeat is introduced.
5. Kill/rollback affects only awareness. Current clients clear on known disabled response and otherwise at trust expiry; server ignores/rejects old controls. Leave finite compatible rows/policies until old consumers are drained; roll forward repair and issue fresh instances. Do not drop schema or widen access to make rollback appear healthy.
