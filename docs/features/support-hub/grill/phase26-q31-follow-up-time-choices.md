# Q31 — Choosing a follow-up reminder time

**13 September 2026. D1–D30 and every adopted amendment are fully founder-ratified. Q31 is unanswered.** This question concerns the time-choice interface and how much preset customization to provide. It does not reopen D3's reminder, work-status, ownership, due-processing or recovery contracts.

## The question

**How should staff choose a follow-up reminder time?**

For example, Maya needs to return to a donor-care inquiry tomorrow after checking some information. She should be able to choose the intended time quickly, see the actual date/time/timezone before committing, and later find the shared follow-up. This is an illustrative task, not evidence of every ministry's working hours or an assumed morning schedule.

D3 already guarantees an explicit date/time choice and one shared follow-up reminder. D3-R07 deliberately left a morning hour, default delay and personal preference hierarchy unselected. The current detail menu has quick options but computes “Tomorrow morning” as sixteen elapsed hours; other entry points hardcode twenty-four hours. Those source details need reconciliation under every option. They do not decide which experience the product should provide.

## Three actual options

| Option                                                     | What staff get                                                                                                                                                                                         | Strongest benefit                                                                                                                                      | Cost and limitation                                                                                                                                                                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **A — Consistent quick choices plus Custom (recommended)** | A small ready-made menu of common choices, each displaying its resolved date/time/zone, alongside **Choose date and time**. The same meanings apply across permitted reminder entry points.            | Fast for common follow-ups, predictable across the team and useful without setup. Custom handles exceptions.                                           | Product must select and maintain a sensible small menu with honest calendar/duration meanings. The defaults will not match every person's routine.                                                                             |
| **B — Choose date and time every time**                    | Open the clear date/time control directly, with its timezone visible and exact result reviewed before commitment. No quick-preset menu.                                                                | Fewest concepts and preference settings; no ambiguous “morning” or “later” shortcut to learn. Strong when most follow-ups have a specific agreed time. | Routine delays require more repeated selection. It retains the same complete scheduling, validation and recovery behavior, not a simplified backend.                                                                           |
| **C — Quick choices plus personal saved presets**          | Start with useful ready-made choices, then let a staff member create and maintain reusable personal time choices alongside Custom. Applying one still schedules the same shared conversation reminder. | Helps staff with recurring individual timing patterns without repeatedly entering them.                                                                | Adds preference ownership, edit/reset/delete behavior, cross-device/tenant scope and version/validation work. Personal choice definitions must not become private alarms, team policy or authority over another person's work. |

These are alternative current product scopes. C includes a useful default and never forces setup. A's “consistent” menu does not imply a new tenant/inbox preset-policy editor. B retains the already-required shared date/time controls and every D3 safeguard. All three show the actual resolved result before the committing action; that need not add a separate confirmation modal.

## Single best recommendation: A

A provides the most useful balance: common follow-ups take few steps, while an exact custom time remains available. It completes the ordinary journey without asking every tenant or staff member to administer presets. The strongest case for B is predominantly appointment-like follow-up with specific dates; the strongest case for C is repeated personal timing patterns that the default menu cannot reasonably serve.

The exact preset names, number, durations, morning hour, timezone default and calendar-resolution behavior will be specified and adversarially reviewed after this scope choice. A label such as Tomorrow morning is only acceptable when its precise date/time/zone is visible and correct; it cannot be a disguised fixed-hour addition. No universal nine-o'clock ministry schedule is assumed. Existing qualified explicit Custom remains available regardless of the selected answer.

## Boundaries that remain settled

- **One shared reminder:** the choice schedules the existing conversation follow-up. C personalizes the reusable input choices, not ownership or visibility of the resulting reminder. No personal alarm, recurring reminder series, multiple competing clocks or new task/reminder domain is introduced.
- **Work meaning remains D3's:** scheduling does not replace Open/Waiting semantics; a due valid reminder returns work to Open for review, with its cause visible. Existing cancellation, replacement, new-input, Resolve, coverage, revocation and retry rules remain authoritative.
- **Exact time before commitment:** distinguish elapsed duration from local calendar intent. Show the relevant zone and any daylight-saving adjustment. Reopening the picker or retrying cannot silently renew the accepted reminder. Validation/current authorization happen at the shared server command boundary; browser time is not business authority.
- **No hidden office-hours coupling:** a follow-up reminder is not D14's reply target, a service-hours budget or a public response promise. No calendar-hours/business-hours pause, holiday roll-forward or default working week is inferred from a shortcut name. Any chosen calendar-aware convenience needs explicit, reviewable meaning and the correct shared calendar owner.
- **Consistent allowed entry points:** conversation control, qualified bulk action and keyboard path use the same permitted resolved meaning. Prior exact-ID/per-item bulk rules remain accepted. D24 shortcuts remain unable to store or apply reminder presets. Any reminder choice while a reply is being composed is a separate deliberate use of the existing qualified D3/D4 control; it does not extend the shortcut patch or add a combined-send operation.
- **CRM continuity:** the current shared reminder is visible through the same authorized Support detail from CRM. It does not change a CRM task due date, record ownership, giving/care action, contact identity or Activity history merely because a time was selected.
- **Email Studio boundary:** selecting a reminder time sends/prepares nothing. If used while composing, D4's explicit reviewed work intent and P17/P6 send contract remain separate. No scheduled-send feature, reminder email, automatic follow-up campaign, template action or provider call is added. D30's eventual overview configurability does not automatically authorize personal reminder customization.
