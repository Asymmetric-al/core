**Recommendation: ask what should happen to an unfinished new Internal note when its author leaves the conversation. Recommend A — Save notes automatically in My drafts.** The existing product already provides Internal note composition and requires separate preserved working state. D37 deliberately qualifies durable persistence/discovery for external Reply only. The remaining gap is whether unpublished new notes receive comparable durable save/resume, and whether saving is automatic or explicit. It is not permission to edit published notes differently, create a personal notebook, or expose colleague writing.

## Concrete user decision

Illustrative test fixture: Maya starts an Internal note explaining an issue for colleagues, then needs to inspect an authorized CRM record or handle another conversation. She has not selected Add note and is not ready to share the text. Later she wants to finish it. This is an ordinary interruption in an already-supported authoring task, not an assertion about measured ministry habits or note length.

**Question:** When someone leaves a new Internal note unfinished, how should Asym preserve it for later?

| Option                                        | Concrete experience                                                                                                                                                                                                                    | Strongest benefit                                                                                                                                 | Real cost                                                                                                                                                                                              |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **A — Save notes automatically in My drafts** | Meaningful new-note work saves quietly as a private draft. It appears beside the author's saved replies with its purpose clear; opening it resumes the same Internal note in its source conversation.                                  | A consistent write/leave/resume expectation across the two existing composition modes, without remembering another Save action or conversation.   | Expands qualified durable private custody to unpublished new notes. Mode distinctions, privacy/retention and deliberate Add note remain essential.                                                     |
| **B — Save note drafts explicitly**           | A deliberate Save note draft stores the private note and makes it discoverable in My drafts. Unacknowledged later changes remain visibly unsaved until deliberately saved again; leaving uses an honest guard.                         | The author deliberately decides when internal working text becomes a retained draft, while saved work remains findable.                           | Adds a save habit and more interruption prompts. Staff can expect Reply-style autosave and forget that notes differ. This is not a promise that unsaved text never exists in transient browser memory. |
| **C — Keep notes as current working text**    | Preserve separate Note work during qualified mode switches and mounted context navigation. Before leaving would destroy it, offer an explicit stay/leave-unsaved choice; new notes do not get durable draft storage or My drafts rows. | The narrowest product and retained-content scope. Appropriate when notes are normally completed immediately and later continuation is not needed. | No acknowledged cross-session return for unfinished notes; interruptions can force staff to finish, retain the current context or deliberately abandon their work.                                     |

These are alternative product policies, not three new user or tenant settings. All preserve D37's already accepted Reply autosave and My drafts destination. B is the strongest competing policy if deliberate control over retaining new internal writing matters more than consistency. C remains a legitimate no-new-persistence alternative; it must not silently lose text during app-controlled navigation.

A is the single recommendation because the accepted UI already makes both Reply and Internal note ordinary composition modes. Reusing the qualified private draft capability can close a predictable interruption gap without another screen, notebook or editor. This is a product judgment, not vendor consensus, proof of actual staff demand, or a zero-cost engineering claim. Current external documentation and UX evidence are owned by the companion research artifact.

## Boundaries all options preserve

1. **New unpublished notes only.** D35 posted-note correction continues to use explicit Save changes/Cancel, local working state and visible admitted revision history. Q38 adds no autosave or finder for those editors.
2. **Private until Add note.** A/B may retain an owner-only draft under current tenant/source and Internal note capability; current source/privacy authority still governs it. Assignment, followers, composing awareness, CRM relationships or administrator status do not expose another person's draft. A draft in an Internal note mode is not yet a note visible to staff.
3. **Saving never posts or notifies.** Mode switches, draft save, discovery and restoration perform no Add note, @mention notification, follow update, work ending, assignment, CRM Activity or external mail. Deliberate actual note admission alone supplies its true downstream triggers.
4. **Same source and purposeful separation.** Keep Reply and new Note state distinct, even when both exist in one source conversation. Resume the exact intended mode and qualified source; never convert a note to Reply, copy internal recipients into email or infer source/ownership from CRM identity. My drafts metadata never indexes private prose.
5. **One qualified owner path.** If durable notes are chosen, extend the appropriate Support private-draft capability with a qualified Internal note purpose rather than a new document service, shadow message row or provider draft synchronization. Exact schema/cardinality/save scheduling are reviewed after selection; no guessed implementation detail is recorded as answered now.
6. **Honest persistence and recovery.** Saved requires acknowledgment of the exact current note bundle. Navigation protects local changes/files proportionately, original-operation recovery handles lost acknowledgments, current source restrictions take precedence, and a terminal post/discard cannot be resurrected by a stale save. For C, preservation is working-state continuity rather than a fabricated server guarantee.
7. **Email Studio stays at its actual seam.** Support owns a note's private working state/persistence if chosen, current source/actor eligibility and actual note admission. The shared P17-governed canonical editor/schema/reusable-wording capability may support authoring and validation; this does not make a note an Email Studio publication or prepare it as outgoing email. Any separately authorized attention email produced after actual note admission retains its own P17 presentation/P6 delivery path. Saving or opening the draft creates none.
8. **CRM continuity uses the same capability.** Draft work begun from an authorized CRM Support context resumes in that same source with return navigation. CRM retains its own note/data ownership; no Party/contact creation, financial mutation, restricted-context inheritance or duplicate timeline body results.
9. **No bulk or speculative product additions.** No team draft queue, draft transfer after departure, co-editing, approval workflow, scheduled posting, generic personal notebook, new private-body search, note reminders or AI action authority is selected by this question.
