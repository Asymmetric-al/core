## Scope and periods

Now scope is explicitly All accessible inboxes or one exact current inbox under current source rights. Missing, forbidden or no-longer-qualified selected ID is invalid, never All. Retirement alone is not invalidity: preserve still-owner-qualified retained work and references without creating an archive-access grant. Its three blocks have one compatible scope and coherent evaluation cut; U≤N when complete, and the three status counts partition N. Reply attention is separately deduplicated; its groups and the three summaries are not additive.

Results has no overview-level inbox or CRM filter. Do not filter historical populations through today's active-inbox catalog; a retired source remains included only where its owner preserves meaningful current report access. It covers each report's current authorized population with its own accepted historical/current dimensions. Period/zone is common input, not common cohort meaning. Full-report navigation passes period/zone only; source-specific narrower filters belong there. Metric drilldown preserves the exact native cohort and kind, which differs from generic report navigation.

A report zone determines the half-open UTC interval derived from inclusive local calendar dates. It never changes a stored source/target calendar or evidence time. Current day results are evaluated only through the trusted read/evaluation time, visibly partial. The fixed overview's 1–366-date range and four presets bound interaction; a source owner's tighter execution constraint must surface explicitly, not silently narrow population. Full reports retain their own qualified capabilities. Resolve skipped/ambiguous local calendar boundaries using the qualified shared timezone/date owner; no browser-duration arithmetic assuming every date is 24 hours.

## Server read boundary and evaluation evidence

Use packages/api/source-owned report readers returning only required aggregates, coverage and safe navigation descriptors. Thin app routes authenticate, validate and delegate. A result logically carries:

- Stable owner/block/definition version and measured grain/unit.

No particular wire schema, central DSL or persistent evaluation table is implied. Reuse current owner machinery. A timestamp is not an MVCC snapshot or durable replay facility. Single-statement or qualified read-transaction consistency must prove a block's value/detail semantics; independently owned blocks need not pretend to share a distributed snapshot. Never hold a database transaction open while a person browses. A derived read model can serve only if it preserves required authorization granularity, complete contribution evidence and current restriction/withdrawal semantics; an all-tenant cached total cannot be fixed by filtering its final label.

## Detail, pagination and re-evaluation

Detail descriptors are source-issued/validated bounded query context, not a browser-supplied SQL filter or access capability. Derive current tenant/actor at use. Reuse exact definition/cohort/kind and current source rights. If the owner supports safe replay of the original read cut, disclose that evaluation. Otherwise rerun current source facts under the same semantic criteria and show Updated since overview with new As of evidence. Source erasure/access loss wins over count equality.

Targets are target instances; response durations are completed waits; invitation metrics are invitation effects. Their detail may link multiple rows to one conversation. Conversation-level Now detail is distinct current continuing IDs. Never translate a report predicate to D20's ordinary Created filter, duplicate a merged root per label, or claim a page of 50 rows is a complete aggregate.

Use owner keyset detail paging capped at 50 records here, stable tie-breaks and current authorization for every page. If data changes between pages, follow the existing owner's coherent snapshot/re-evaluation behavior; do not silently create missing/frozen historical rows. The overview displays only five leading labels but computes rank/count across the complete qualified population.
