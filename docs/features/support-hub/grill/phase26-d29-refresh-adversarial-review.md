A person can ignore every guide and still contact the tenant. The tenant maintains this through the existing content, app, routing and Email Studio owners rather than a second help-center platform.

Include the initial form, validation errors, persistent receipt, public full page, authenticated app presentation, long supported contact strings, translations and RTL content. Author-created overlays/sticky UI must not entirely obscure keyboard focus under WCAG2.2 SC2.4.11. Pointer targets meet SC2.5.8's 24-by-24 CSS-pixel minimum or its actual permitted exceptions; use 44-by-44 CSS pixels for standalone primary touch actions as the product target. Prove mobile virtual-keyboard usability separately without misclassifying the browser keyboard as author-created content. Do not claim that 200% text resizing or a narrow screenshot alone passes reflow or whole-journey accessibility.

## What the fresh review changes

**One material new requirement gap:** D29-R26/P40 name 200% zoom and narrow mobile without an exact reflow boundary. A form can pass those checks and still clip the Send action, contact address or error text at the effective 320-pixel viewport used by a low-vision reader. **Severity: Medium; likelihood: plausible under normal zoom/long-label layouts.** W3C distinguishes text resizing from reflow and defines the focus/target conditions. This **amends proof and presentation qualification**, not A's scope. X01 is the permanent fix; the three supplemental proof groups in the [proof/seam ledger](phase26-d29-refresh-proof-and-seams.md) make it falsifiable. [W3C reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [focus](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html), [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

**No new data, source, CRM or Email Studio architecture gap was found after the independent refresh.** Current legacy code is not certified: hardcoded FAQ claims, incomplete actual Site/operational tenant mapping, broad legacy Support grants/helpers and unqualified form-origin contracts remain material implementation hazards. Existing R08/R10/R13–R15/R21/R28 and their proof already require the appropriate owner fixes before activation.
