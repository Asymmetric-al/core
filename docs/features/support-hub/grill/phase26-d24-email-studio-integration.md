## One wording source, one Support combination

**Email Studio / Phase17** owns the published Shared D18 Reply wording source: its canonical structured document, Tiptap purpose profile, authored language variants, allowed typed variables, one-use fill-ins, source/asset eligibility, publication and compilation. **Support** owns the shortcut's name, guidance, use scope, exact selected source publication, bounded work choices and configuration lifecycle. This division lets wording remain independently useful as a Saved reply without becoming executable content.

The shortcut stores an exact qualified source reference, not a second HTML/text body or a live latest-content alias. Personal My replies must first use D18's deliberate shared contribution/publication journey. An internal Saved note or restricted conversation body cannot be promoted into external reusable wording merely by selecting it. Shortcut availability grants neither source access nor permission to perform its pending Support changes.

## Creation and change journey

From **Support settings → Reply shortcuts**, a maintainer selects published Shared wording or opens **Create/Edit wording in Email Studio**. The contextual link preserves the candidate and return location. The actual owning editor uses the ratified Tiptap profile. There is no duplicate body editor in the shortcut form, new template gallery, raw-HTML escape hatch or automatic extraction of live donor/care text.

P17 publication and Support activation are distinct. Source publication follows P17's actual use/author/publish/review rules; shortcut activation follows current Support configuration authority and revalidates exact source purpose/scope/variants/assets and target compatibility. A curator without publishing authority can select an existing eligible publication. A source editor does not acquire Support activation or conversation access.

Publishing wording does not activate a shortcut, repoint another active shortcut or rewrite a draft. **Review and activate** selects an exact immutable configuration version. If contextual publication succeeds but activation conflicts, the visible result is **Wording published; shortcut still a draft**. Reconcile the exact existing owner outcomes before retry; do not pretend both failed or publish blindly again.

Routine newer wording is an available update, not an automatic replacement. The maintainer reviews and deliberately adopts it in a new shortcut version. Current withdrawal, incompatible structure, inaccessible assets or scope restrictions can make the pinned dependency unusable; authoritative checks outrank cached health. Archive remains available even if the source cannot compile. Routine archive of the shortcut stops new selection; safety withdrawal and derivative restrictions remain their separate owner-controlled paths.

## Use, editing and preparation

**Use shortcut** copies the exact eligible structured wording and asset occurrences into the current private Tiptap Reply draft through D18 and stages one visible Support plan. Selection, preview, save and draft recovery create no live assignment/status/label/message/provider effect. Work metadata is not an executable message node. Copying text cannot copy work authority.

Normal human editing affects the draft, not shared publication. **Change shortcut → Keep current reply** preserves the actual previous wording/assets/signature and their provenance while replacing pending work; it does not claim the newly selected source was inserted. Explicit whole-body replacement follows D18's reviewed replacement and coordinated Undo. Detaching pending work does not erase source restrictions. The actual final human document is compiled, not reexpanded from a mutable shortcut source at send time.

D23 owns the managed signature copy, inbox selection and approved public-responder presentation. The actual authenticated responder is distinct from assignee, shortcut creator, CRM owner and requester. A shortcut cannot change signature, recipients, sender, Reply-To, subject, thread, group disclosure or protected-document purpose. Existing P17 Service message presentation and Brand Kit remain the surrounding frame. There is **no new system-message template key**, per-shortcut Role Layout, hidden appended signature or marketing-campaign enrollment. D13 Support request received remains its distinct automatic confirmation; Internal notes remain non-deliverable.

P17 validates and compiles exact current body/audience/locale/signature/assets into ready immutable preparation. HTML and real plain text derive from the same canonical document. Ready preparation has no dispatch authority until claimed. D4's single conditional local transaction then claims it and admits the actual message plus all valid Support work/reminder/handling/label/history/use-receipt/dispatch-intent effects. An unchanged qualified body need not be gratuitously recompiled solely for a work-field edit, but the compound intent must be re-reviewed and current preparation must still be exact and eligible.

## Delivery, CRM and recovery

**Phase6 and the tenant Resend connection** own the sealed envelope, provider requests and delivery evidence. No direct Support mailer, provider template mirror, alternate account fallback or Resend CLI runtime is introduced. CLI use is separately authorized operational tooling. Queued admission is not successful delivery. Lost admission responses reconcile the original durable intent; provider failure does not replay or roll back previously committed work or today's later handling.

CRM Party/relationship, giving, project and care domains retain their records, disclosure and action authority. Email Studio variables cannot manufacture missing identity or infer permission from an address match. A shortcut can communicate authorized facts or coordinate an existing owner journey, but cannot execute or certify refunds, gift changes, official receipts, CRM edits or care actions. Only actual admitted correspondence contributes its permitted history; library use/maintenance creates no false contact event.

Source, draft, preparation, admitted correspondence, minimal use receipt, configuration audit and technical logs have separate finite lifetimes. No extra reply body or resolved donor values are retained in shortcut telemetry. D16/D17/D22 restrictions and restore barriers apply to known derivatives; a reusable source cannot restore expired correspondence. Owner-qualified imports create inactive remapped candidates without personal content or permission/activation transfer.
