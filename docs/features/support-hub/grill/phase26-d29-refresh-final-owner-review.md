## F01 — Keep acknowledgement enablement with the Form/Route Plan owner

**Medium severity; plausible maintenance mistake.** Refreshed UX Journey6 step6 directs a maintainer who wants optional visitor email to the Email Studio entry, without first identifying where the optional child is enabled. This could imply that Email Studio owns the form's acknowledgement On/Off setting. Ratified **D29-R17**, the original data contract and original Email Studio integration place zero-or-one Visitor Acknowledgement configuration in **P23's Form/Route Plan**, while P17 owns the compatible message publication, wording and preparation.

**Exact correction:** “Enable or disable the existing zero-or-one Visitor Acknowledgement through the form/Route Plan owner's Confirmation controls; it starts Off for the standard Help form. Use the linked Email Studio entry to select/edit the compatible Live web-Contact publication and inspect its message readiness. Do not create a second acknowledgement switch or template editor.”

This is the existing **R17/R24 and P27/P38** seam, not a new setting or management workflow. Browser acceptance remains independent of optional email readiness, and a message-content editor cannot change the Contact Primary Outcome or recipient source authority.

## F02 — Preserve exact scope in the full human-precedence restatement

**Medium severity; possible misapplication if a compact restatement is implemented alone.** The refreshed seam says a later qualifying human reply terminates acknowledgement authority, referring to D13-R15, but omits the original explicit qualifier **same current request and exact confirmation recipient**. Without it, an implementer could suppress another recipient's or unrelated request's acknowledgement merely because some human email occurred.

**Exact correction:** “A later qualifying public human reply **for the same current request and exact confirmation recipient** ends all further acknowledgement provider-call/decrypt authority, including otherwise permitted indeterminate same-key follow-ups. Already-in-flight facts reconcile without recall; later human-delivery failure never revives that acknowledgement.”

This retains ratified **D29-R18/P29** and D13-R15 in full. It does not broaden human reply coverage, suppress siblings globally or introduce a new grace period.
