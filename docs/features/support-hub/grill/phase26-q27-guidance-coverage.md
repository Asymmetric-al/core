# Q27: Guidance available while handling Support

**Historical Q27 evidence: the founder selected A on 12 September 2026. The [D27 review](phase26-d27-adversarial-review.md) records all amendments, fully founder-ratified on 12 September 2026. Unanswered/no-ADR statements below describe the earlier question stage.**

**D1–D26 and every adopted amendment are fully founder-ratified. Q27 is unanswered.** This is one choice about staff guidance lookup. It does not bundle a new public help center, portal, channel, AI product or internal knowledge platform into an already accepted decision.

## Practical context

Illustrative example: Maya asks where to download a giving statement. If Harbor Mission maintains a public how-to page, the worker should be able to find the correct current page and include its link while keeping the request and draft open. An internal procedure for investigating an exception has a different audience and ownership requirement. The example is not evidence that all tenants have these pages or follow this process.

D18 already provides saved reply and internal-note wording, including ordinary links and qualified files. Those remain available in every option. A saved reply is wording to insert; a guidance source is something staff consults or links to. D22 searches admitted conversations, not either content library. This question decides whether to add direct guidance discovery and what it covers.

## Three actual options

| Option                                           | Staff experience                                                                                                                               | Strongest benefit                                                                           | Main cost or limit                                                                                                                 |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **A — Find approved public guidance in Support** | Find selected current public guidance from the conversation, preview it, then deliberately insert its public link into the existing draft.     | Reuses the public-content owner and keeps useful maintained explanations close to the work. | Requires a qualified selection/lookup/public-URL seam; the new finder does not include a general staff-only guidance library.      |
| **B — Keep saved replies and manual links**      | Use the existing D18 reply/note library, or open the relevant page elsewhere and paste its link.                                               | Smallest scope; a modest, maintained saved-reply library may already meet the need.         | Staff must know where to find and check the source; no guidance finder is available within the request.                            |
| **C — Find public and internal staff guidance**  | Consult public references and independently authorized internal procedures within the same working context, with clear separate sharing rules. | Covers cases needing both a requester-facing explanation and a staff process/checklist.     | Adds a real internal-content ownership, maintenance, access and disclosure contract that current Core evidence does not establish. |

These are alternatives for the scope, not three tenant modes to implement. C is a credible broader choice, not an unsafe feature by definition. A's public-only finder does not remove D18's existing Saved notes or internal wording. B remains a workable product choice rather than a straw-man broken experience.

## Single recommendation: A — Find approved public guidance in Support

A offers a proportionate improvement beyond saved wording: find the maintained public source where staff is already answering. It can consume Core's existing public-content boundary without requiring a new internal knowledge owner, broad content editor or requester self-service site. B is strongest if saved replies already make the few useful links easy to find. C is strongest if broader staff procedure lookup is part of the intended need and worth its additional lifecycle contract.

This recommendation is product judgment from Core's actual boundaries and documented help-desk workflows, not a measured claim about tenant prevalence, time saved or satisfaction. Do not create mandatory guidance setup where the tenant has no suitable published content, nor automatically suggest that a requester read an article instead of receiving a helpful answer.

## Concrete candidate journey for A

1. **Open Guidance deliberately.** Use a clearly named action beside the existing content tools in the same Support detail used from Support Hub or CRM. Preserve current conversation, audience, Reply/Internal note mode and private draft. Do not open it automatically or derive a query from private conversation content.
2. **Find a useful source.** Search the deliberately selected public guidance set, not every public news item, campaign or missionary page. Show source title, concise description, language and site when needed for disambiguation. Keep filters small and scope visible; no silent broadening after zero results.
3. **Preview.** Read the current public-eligible source and see its actual public destination. Open public page and Insert link are clear keyboard/touch actions. Staff editorial preview rights do not make an unpublished page shareable; an active published flag alone does not prove current site/route/language eligibility.
4. **Insert the link, not the article.** Add a normal human-readable link at the draft insertion point, preserving surrounding wording, managed signature and attachments. Ordinary Undo removes the insertion. No automatic article-body copying, dynamic embed, send, status change or shortcut execution. Read-only staff can consult an eligible source; insertion requires an editable draft.
5. **Continue the normal reply.** Add a concise response suited to the person's need and send through D4/P17/P6 as usual. Article access is not permission to perform a receipt/refund/contact action. The selected answer's review must define exact source-withdrawal and failure checks without inventing an arbitrary URL crawler or making the whole Support surface depend on CMS uptime.
6. **Maintain the original source.** Authorized authors edit/publish in Web Studio/CMS; Support selection controls what the finder offers without copying the body or granting publishing rights. A contextual Manage source handoff returns to the permitted draft. Removing an item from the finder does not unpublish its site or recall sent email.
7. **Handle missing guidance honestly.** No matching item and unavailable lookup are distinct. Normal composition and existing saved replies remain usable. No suitable pages means a concise empty state, not fabricated sample articles or automatically turning the current conversation into public knowledge.

This is a candidate journey so the option is concrete. Exact curation roles, selection rules, lifecycle, source-use checks, query limits, fallback behavior and proofs receive the selected answer's full adversarial review; they are not silently ratified by this question.

## Core, CRM and Email Studio ownership

Web Studio/CMS owns published guidance content, its versions, public presentation and publication lifecycle. The shared `PublishedContentReader` boundary owns qualified public reads; its concrete Payload access stays in admin. Current methods provide page detail/navigation/updates, not a ready generic guidance search. A therefore needs a qualified additive lookup/selection capability rather than a direct second Payload reader. [Public reader ADR](https://github.com/Asymmetric-al/core/blob/7abd2c11ffd4ed70c6775c4fd6f51c996e4350dd/docs/adr/0027-transport-agnostic-public-content-reader.md), [current interface](https://github.com/Asymmetric-al/core/blob/7abd2c11ffd4ed70c6775c4fd6f51c996e4350dd/packages/api/src/cms/public/reader.ts#L121).

Support owns this use context and any deliberately maintained source selection. It should reference source identities through the owner contract, not copy whole articles or add cross-schema SQL foreign keys into Payload-owned tables. Supabase operational and Payload CMS migration ownership remains disjoint even though both use the platform's database. [Reference-not-copy ADR](https://github.com/Asymmetric-al/core/blob/7abd2c11ffd4ed70c6775c4fd6f51c996e4350dd/docs/adr/0029-reference-not-copy-cms-operational.md#L10).

Email Studio/P17 retains saved reply/note wording, signatures, typed fields, presentation and preparation. Guidance lookup inserts a qualified link into the existing Tiptap draft; it does not create a second email editor, convert CMS rich text into reusable wording, add a template key or change source ownership. The article preview uses the published-content rendering boundary, not a new Tiptap authoring instance. P6 remains delivery authority. D26's shared detail makes the same experience available when working through CRM; viewing guidance grants no CRM access or business-action authority.

C would require an explicit minimal internal source owner and currentness/audience/disclosure lifecycle. CMS drafts, arbitrary readable files, CRM case histories and repository engineering docs are not that authority. D18 Saved notes remain useful inserted wording; Phase29 bytes and Phase40 future global search do not already constitute a staff knowledge product. Public self-service remains a separate later audience/journey choice in all options.

## Research and proof limits

Help Scout documents distinct Saved Reply and Docs-link actions with preview; Zendesk separates linking from article-text quotation; Intercom distinguishes internal and public content purposes. Those facts support a deliberate lookup/preview/share boundary while showing why public-plus-internal scope carries additional responsibilities. We do not copy their AI suggestions, automatic article-request tickets or entire knowledge platform.
