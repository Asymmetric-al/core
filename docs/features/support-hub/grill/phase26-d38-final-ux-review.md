## Clarification applied and verified

The earlier blueprint UX06 correctly preserved purpose independence, but its statement that an unrelated Reply save must not block Note resumption could be read too broadly during destructive navigation. The consolidated **R13/P13 already required both dirty purposes to participate** when leaving would destroy either candidate.

The blueprint now explicitly says independence applies while the other controller and permitted work remain safely retained. Any navigation destroying dirty text or local file bytes from either purpose—including an inactive purpose—uses the same combined save/leave guard. A Note acknowledgment never marks the Reply saved. This closes the ambiguous reading without adding another dialog, timer or workflow.

This is **F02**. The final actual R08/P09 were also re-read for **F01**: direct mentions use their independently governed producer; D15 optional following, its Off/Stop/frontier and overlap rules cannot silently subsume them. Final R10/P19 were re-read for **F03**: operation-specific authority allows still-qualified private read/custody after only posting permission is lost, without implicitly allowing edits or publication. These refinements agree with the blueprint's already separate attention and read-only paths. They introduce no new product option or authority bypass.
