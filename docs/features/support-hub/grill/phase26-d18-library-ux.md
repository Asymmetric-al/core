# Saved replies: complete staff and maintainer experience

**D18 and this complete blueprint are fully founder-ratified, 11 September 2026.** This blueprint implements the product meaning of [D18](phase26-d18-adversarial-review.md) in words and illustrative layouts. It is not a rendered interface or a passing usability test. D4's composer and Email Studio/P17 ownership remain settled.

The [Email Studio integration record](phase26-d18-email-studio-integration.md) explicitly maps authoring, publication, draft/notes, external preparation, transport and owner qualification.

## The everyday experience

Alex opens a request from CRM and stays in the same authorized Support conversation. Alex needs the maintained receipt-help instructions and a short personal closing. **Use template** opens one **Saved replies** picker in context. The current Reply/Internal note purpose is clear; an optional language selector reflects the declared draft language. A visible control works on touch; the optional slash command is a faster path to the same picker, not a separate feature.

```text
Saved replies                         Reply · English
[ Search replies…                                  ]
All   Shared   My replies   Favorites

Receipt help                         Shared
Request the information needed to review a correction.

Thanks for checking                  My replies
A short closing.

Preview: Receipt help
Thanks for letting us know. Please describe the correction
you need. We’ll review your request and explain the next step.

No fill-ins · No files
[ Insert ]     Replace reply

New saved reply                            Manage library
```

The layout illustrates hierarchy, not required pixel dimensions or prepublished tenant wording. Empty search can show favorites and a small recent list; typed search ranks matching wording first. Scope is always distinguishable; language and usage guidance appear when relevant. No row needs simultaneous scores, badges, avatars and analytics. A longer preview or included files is inspectable without requiring an extra modal before every short phrase.

Alex inserts the shared instructions at the caret, then adds a personal closing. The draft remains editable. Any required one-use fields become clear inline controls, with a compact unresolved-fields summary only while needed. Completing them changes this draft only. The existing named **Send reply** action and **After sending** choice remain exactly D4's. Library use sends nothing, changes no status and adds no CRM interaction.

## Content forms and safe styles

| Form                                        | Appropriate use                                              | UX and safety rule                                                                                                                        |
| ------------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Greeting, thanks, empathy or closing phrase | Add a short human passage around the actual answer.          | Neutral names/pronouns by default; do not duplicate the shared signature.                                                                 |
| Complete answer                             | A maintained explanation of a known process.                 | Complete still means editable body content; Insert does not become automatic Replace or Send.                                             |
| Clarifying request                          | Ask for the minimum information needed.                      | Use a clear one-use field; never request passwords or complete payment credentials as a generic template.                                 |
| Step-by-step instructions                   | Help someone complete a real supported task.                 | One action per numbered step, descriptive links, meaningful plain text; images supplement instructions.                                   |
| Progress update                             | Explain actual current work and the next step.               | Use only when the described work is real. No guessed response-time promise, automatic Waiting change or reminder.                         |
| Outcome explanation                         | Describe an actually verified owner-domain result.           | Wording does not perform or prove a refund, receipt correction or contact change. Actual protected facts/artifacts come from their owner. |
| Internal handoff/investigation outline      | Structure a staff-only note.                                 | Internal note purpose only; no implicit mention, delegation, task, assignment or requester-visible content.                               |
| Language or phrasing variant                | A translated, concise, detailed, warm or formal alternative. | Independently authored wording, clearly labelled. No automatic tone engine or required matrix of every style.                             |

Use the shared editor's qualified paragraphs, headings, lists, emphasis, links and images. Generate HTML and plain text from one source. Do not add snippet-specific fonts, CSS, promotional layouts, a general table/blockquote builder, tracking pixels, video embeds or live nested snippets. Quoted wording can remain plain text. Tenant voice and existing shared presentation are respected; a new Support signature policy is not smuggled into the library.

## Starter examples

These are synthetic opt-in authoring examples, not automatic Shared publications or assertions about a tenant's policies. Selecting an example creates a draft. The author reviews wording and purpose before saving or publishing. Field notation below describes real structured fill-in controls, not literal bracket syntax to send.

| Title / purpose                         | Example wording                                                                                                           | Use guidance                                                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Thanks for checking / Reply             | Thank you for checking with us.                                                                                           | A short fragment that needs no CRM lookup.                                                                               |
| Receipt help / Reply                    | Thanks for letting us know. Please describe the correction you need. We’ll review your request and explain the next step. | Use when accepting review of a receipt question; it does not issue or correct a receipt.                                 |
| One detail needed / Reply               | To help with this, please provide **Needed information**.                                                                 | Needed information is a required one-use text field. Ask only for the information the current authorized workflow needs. |
| Current update / Reply                  | Here is the latest update: **Current update**. The next step is **Next step**.                                            | Both fields required. The staff author must describe actual work, not a predicted provider/financial success.            |
| Practical steps / Reply                 | Please follow these steps: **Instructions**. If anything is unclear, let us know which step needs help.                   | Instructions is a required one-use text field; an author may instead write a maintained numbered list using the editor.  |

No ready-made “refund completed,” “receipt attached,” financial amount, protected link or guaranteed response-time example is published without its actual owner qualification. The starters are useful writing scaffolds, not domain automations.

## Find, preview, insert and correct

**Find:** search titles, descriptions, optional aliases and authorized reusable text across the complete library. Filters narrow scope, purpose, language and a simple category when needed. Titles can use ordinary spaces and international text. Aliases are optional search hints, not a requirement to remember magic words. Similar Shared/My titles display both permitted candidates; no invisible personal priority. Current authorization precedes result membership/counts. Favorites point to the shared identity and therefore offer the current eligible revision at the next insertion without cloning it.

**Preview:** focus or deliberate selection exposes the same full preview for keyboard, touch and pointer users. It shows the exact language, wording, required fields and files, plus concise author-only usage guidance clearly outside the outgoing body. A permitted but context-incompatible item can explain why it is unavailable. Unauthorized items expose no title, body, count or cause. Opening a preview does not count as insertion or change a draft.

**Insert:** preserve the saved caret/selection and current editor identity. If the user typed, navigated or changed mode while content loaded, safely revalidate the bookmark or ask to insert again; never overwrite new typing. One completed insertion is one Undo unit. **Replace reply** or **Replace note** remains an explicit secondary action. A blank draft needs no extra confirmation. Combining several passages preserves field identities and avoids duplicate file appearances.

**Correct:** Undo affects only that insertion and cannot recover newly restricted content or transform internal-only wording into Reply. A file already attached before the insertion survives its Undo. Library updates leave existing drafts unchanged. If a source becomes unsafe, explain the affected field/file and preserve unrelated authorized writing; do not silently swap a different template or remove an attachment without showing the problem.

**Mode:** switching between Reply and Internal note preserves separate drafts. An internal-note template remains internal even after a later switch or Undo. External preparation rejects internal-only provenance. Add note uses Support's note admission and shared authoring validation; it never creates email preparation or Resend work.

## Personalization without accidental CRM edits

The authoring tools distinguish **Insert information** from **Add fill-in field**. The former is an approved typed owner value. The latter is information the staff author supplies for this one use. There is no “fill missing CRM property” behavior.

Fields show their meaning: replying author is not the assignee; a conversation with several related Parties has no implicit first/primary Party. Unknown names use neutral wording. A visible group receives one body safe for every admitted recipient, not personalized fan-out. Shared library preview uses synthetic fixtures; real recipient information stays in the current authorized draft.

Required fill-ins have a label, instruction and no silent sample default. Unresolved or whitespace-only values block Send/Add note with a focusable repair link. Optional defaults or phrase removal are deliberate. Repeated occurrences within one insertion share a value; another insertion starts fresh. Literal brace text is not executed. Filled values cannot become URLs, mentions, markup or a shared-library edit merely because they resemble syntax.

## Save to My replies

**New saved reply** opens the same qualified Email Studio authoring surface without losing the conversation. Required fields are title, Reply/Internal note, language and reusable content. Optional description, alias and category live under details. The primary action says **Save to My replies**. It validates and commits an immutable authoring revision, not a system-message publication. It sends nothing and requires no additional reviewer merely because the tenant reviews publications.

The personal authoring class admits only qualified reusable human wording and assets. It cannot impersonate a protected notice/layout or erase a protected source's provenance. Source safety, shared authoring validation and actual Send/Add note admission checks still apply; only external replies require email preparation. This distinction is an explicit owner extension, not an assumption that current canned-response CRUD is safe.

Create generic wording from a clean editor. Do not harvest the selected conversation, old outgoing message or filled draft automatically. A later source-derived shortcut must earn its complete provenance and generalized-content safeguards; it is not needed to make New saved reply useful. Saving a link to a private receipt does not make it reusable.

## Offer wording to Shared

An author chooses **Offer to Shared**, sees the exact candidate, language, purpose, assets and proposed audience, then submits. This exposes that candidate to qualified maintainers, not all My replies or the inspiring CRM record. The personal item remains unchanged. Editing it afterward does not alter the submitted snapshot.

Files/images receive checked destination custody before they become visible in the offer. Sharing never depends on a personal file URL that disappears when the creator leaves. Invalid assets block the affected offer without partial exposure. True safety/source restrictions still follow known copies.

Status is visible in the author's existing library details: awaiting review, changes requested, declined/withdrawn or published outcome. Reuse Email Studio's existing review and staff attention. No extra approval application or mass email. The author may withdraw a pending offer; after publication, the independent Shared item is managed through its own action. If the author already has Shared publishing rights, they can create and publish the destination candidate directly under the normal review rules.

## Maintain Shared replies

Shared maintainers can create, edit, review, publish, organize and archive within their authorized scope. Usual copy edits can self-publish after the owner checks. Protected content and the tenant's stricter publication rule still require their actual review; no Support exception lowers that floor.

The management list provides name, purpose/language, scope, state and useful edited/usage context. Optional flat categories and favorites keep everyday selection simple. Selecting an item exposes its versions, assets, languages, contributions and safe audit details. A colleague need not read implementation hashes to understand the action. Concurrent edits show a clear comparison/reload path and preserve the uncommitted draft.

Publishing applies the reviewed future usable revision. It never updates existing drafts or messages. A reviewed audience change applies current authorization to all old revisions and links; earlier broad visibility is not a permanent access grant. Widening visibility evaluates every exposed language/asset. Shared content remains tenant-managed after creator departure.

**Insertions** is a small maintenance measure, not staff performance or number of emails sent. It counts completed editor insertion identities, including those later undone, once; previews, retries and imports do not count. Unknown old coverage is labelled. No leaderboard or automatic retirement based solely on low use.

## Languages and files

Each logical item can have separately authored language variants. The current selected language is visible. Missing translations offer an explicit alternative-language choice or ordinary writing; no hidden fallback or automatic translation. A source-language change can mark a linked translation for review without silently replacing it. Real safety revocation can stop an affected variant. Long translated names and RTL remain supported, not squeezed into English-only controls.

Reusable files are approved general guidance assets with version, filename, type, size and readiness shown. Images carry useful alternative text. The shared owner checks safe reuse and actual audience at insertion and sending. Protected artifacts and expiring donor-specific links use their actual owner flow in the current conversation. Updating a library asset does not rerender an existing prepared message.

## Archive, restriction, departure and recovery

| Situation                                            | Clear behavior                                                                                                                          |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Routine wording is no longer useful                  | **Archive** stops new selection. Explain that safe existing drafts/history stay unchanged.                                              |
| Archived item is useful again                        | **Restore** rechecks current rights, content/assets and publication rules.                                                              |
| Content is unsafe or no longer authorized            | Existing source-safety restriction blocks the affected use; it is not merely hidden from the picker.                                    |
| Shared creator leaves                                | Shared content and its independently valid assets remain under tenant stewardship.                                                      |
| Personal author loses membership/use rights          | Ordinary My access stops; no automatic sharing or hard-delete cascade. Qualified tenant custody and retention govern.                   |
| Save or publish response is lost                     | **Checking whether your change was saved…** Reconcile the operation; retain the draft.                                                  |
| Library search fails                                 | **We couldn’t load saved replies. Try again.** Keep ordinary qualified composition available.                                           |
| An item changes audience or is restricted while open | Remove newly forbidden source display/use and preserve only material the user may still retain. No stale body behind a disabled button. |

My replies means ordinary personal use in the current tenant. Explain exceptional authorized records/security custody honestly without exposing private content to routine shared editors. A different account invited with the same email cannot inherit the former person's personal library.

## Accessibility and proof

Use the existing shared Base UI/base-maia controls, semantic tokens, visible focus and proper labels. Desktop can use a compact list/preview arrangement; mobile can use a full-height sheet with reachable search, preview and Insert. Keep the virtual keyboard from covering required controls. Escape preserves the draft; Tab navigates normally; Enter in a picker or fill-in cannot also send. Scope any character shortcut so ordinary typing, URLs, paste and IME remain intact.

Require keyboard/screen-reader/touch parity, 200%/400% zoom/reflow, long names, mixed scripts, RTL, images-blocked/plain text and low-bandwidth tests. Automated a11y checks supplement actual focus and comprehension testing. Staff must demonstrate that they can find the intended item, identify its audience/language, distinguish personal save from Shared publication, resolve a required field and explain archive versus safety restriction. [W3C combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/), [character shortcuts](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html), [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

The [D18 proof groups](phase26-d18-adversarial-review.md) require those actual outcomes. No mockup, rendered UI, browser/AT test, ministry usability study or performance gain is claimed here.
