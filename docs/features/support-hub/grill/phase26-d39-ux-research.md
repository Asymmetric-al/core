## Recommendation

Keep the selected personal cue, automatically clear it only after an explicit, qualified opening of currently authorized content, and provide ordinary **Mark read / Mark unread** actions. A colleague opening the same conversation never clears your indication. Reading remains separate from shared work, notification engagement, replying, comprehension and business completion.

The smallest coherent journey is a quiet dot and title emphasis in the existing list, a normally readable conversation, and one state-appropriate action in existing conversation menus. No timing preference, unread counter, new filter, manager dashboard or extra confirmation is needed. A valid current view can clear your cue without proving that you examined every old quotation or attachment. The cue is an orientation aid, not a promise that a person understood something.

## What the evidence does and does not settle

**Verified repository facts:** the current Support scaffold projects a global `unreadCount`, shows row/card cues, and has no qualified personal read command in the inspected paths. The existing timeline can treat a failed message query as an empty list, and the shared viewer can turn malformed canonical content into a blank div. These are gaps against intended behavior, not existing architectural authority. See the exact source paths and [actual-component probe](phase26-d39-reader-probe.json).

**Product judgment:** use one automatically qualified open policy and a deliberate personal revisit action. Give older or newly accessible other-authored content the same honest absent-marker meaning: no personal view is recorded. Do not pretend staff read old content at activation, fan out history to every user, or make that old history an urgent workload. Self-only or empty sources do not automatically acquire unread cues. Manual marking may apply to eligible self-authored content because it is a deliberate revisit intent.

**Illustrative journey, not observed ministry research:** Ava and Ben can access a donor-care conversation. Ben opens a new reply while Ava is working elsewhere. Ava's cue remains. Ava returns through an authorized CRM link, opens the current conversation, and later marks it unread to revisit. This creates neither a CRM interaction nor a new service obligation. Assignment, permissions and current business actions remain independently governed.

**Unresolved empirical proof:** no representative Asym staff study, live browser implementation, screen-reader run, production network benchmark or Supabase policy exercise was performed by this UX research. Implementation acceptance must verify the exact interaction across realistic low-bandwidth, mobile, keyboard and restricted-source fixtures. No target latency or magical no-lag claim is inferred from competitor copy.

## Strong alternatives reconsidered

| Alternative                        | Strongest benefit                                                                                 | Why it loses for the selected need                                                                                                                                                               |
| ---------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Shared read state                  | One cue signals whether any authorized teammate has looked.                                       | A teammate's glance removes Ava's catch-up information. Shared work already has better owners. Restriction-aware scope is harder and a no-name cue does not eliminate small-team inference.      |
| No ordinary read cue               | Least storage and visual pressure. Existing work status, assignments and reminders remain usable. | Returning staff lose a useful personal orientation signal and must inspect more unfamiliar conversations. The selected A addresses this without becoming a work system.                          |
| Manual-only read changes           | No accidental automatic acknowledgments.                                                          | Requires an extra action for ordinary reading and leaves forgotten cues. One validated open plus a durable manual-unread intent preserves convenience without treating selection alone as proof. |
| Per-user timing options            | Allows immediate-selection versus load-based styles.                                              | Adds another preference and support explanation. The current rendering failure proves that waiting an arbitrary number of seconds is not the correct correctness boundary.                       |
| Per-message dwell/viewport history | Appears precise about which fragments were on screen.                                             | Does not establish comprehension, adds surveillance/retention and complexity, and makes tall messages, AT and merged history brittle. A bounded source-qualified view frontier is sufficient.    |
