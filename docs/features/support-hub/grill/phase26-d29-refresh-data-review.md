## Technical documentation refresh

PostgreSQL 17 documents separate old-row `USING` and new-row `WITH CHECK` behavior, their applicable fallback, and the additional SELECT requirements of relevant `RETURNING`/upsert paths. Supabase documents that RLS, table grants and service access must be considered together. D29-R21 and its data contract already use this effective-policy approach. The original Support migration even supplies an explicit UPDATE check; its concern is breadth and protected-field/command enforcement, not missing syntax. [PostgreSQL CREATE POLICY](https://www.postgresql.org/docs/17/sql-createpolicy.html), [Supabase row-level security](https://supabase.com/docs/guides/database/postgres/row-level-security).

This documentation refresh establishes semantic interpretation, not execution of the intended policies. No fresh external technical fact requires a new D29 architecture or limit.
