## Current product research

The [independent vendor comparison](phase26-q24-vendor-research.md) checks actual product/help/API behavior, editions/dates and limitations. The strongest comparisons are manual workflows versus staged response-and-action macros; snippets/playbooks are not treated as equivalent features.

- [Zendesk using macros](https://support.zendesk.com/hc/en-us/articles/4408887656602-Using-macros-to-update-tickets), edited September 4, 2026: previews and editable ticket/comment changes before submission support clear review. Stale updates, conflicts and permissions are documented concerns.
- [Intercom using macros](https://www.intercom.com/help/en/articles/6584504-using-macros-in-the-inbox), relative update date: queued actions below the composer are reviewed before Send. Its documented mobile limitation must not be copied as silent partial execution in Asym.
- [HubSpot help-desk macros](https://knowledge.hubspot.com/help-desk/create-and-use-macros-in-help-desk), August 18, 2026, Service Hub Professional/Enterprise: editing followed by Send and apply supports C as a real alternative. Workflow enrollment and broad ticket-property updates are vendor choices. The page's Super Admin wording versus broader sharing requires caution; no inferred permission model is adopted.
- [Help Scout manual workflows](https://docs.helpscout.com/article/1398-manual-workflows), September 9, 2026: contextual maintained manual combinations support A's product shape. Its note/mail/bulk actions and runtime guarantees are not automatically Asym scope.
- [Front macros](https://help.front.com/en/articles/824576): broader actions, branches and external integrations demonstrate a larger product. A deliberately avoids that rules/dependency expansion.

These sources establish available behaviors, not vendor architecture or measured Asym benefit. The two-label/assignment example is illustrative. No actual tenant frequency, time saving or demand measurement was obtained. A is a proportionate product judgment; B remains the strongest no-build alternative, and C remains a credible larger capability if the founder values integrated reply/action reuse enough to accept its added qualification.
