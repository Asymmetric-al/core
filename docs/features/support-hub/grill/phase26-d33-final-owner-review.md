The strongest safety property is conservation: expanding qualified folds yields the same permitted source representation as Full. Repetition is not a new authoritative body, a statement that content is unimportant, an access grant or a semantic summary. Incomplete/unsupported comparison stays open; incomplete source rendering is a truthful separate failure. Exact current source/restriction/render/segment lineage prevents stale maps and highlights from changing meaning or restoring removed content.

No live P17 or profile lookup determines historical equality. No unqualified network resource is fetched to establish sameness or display a raw-original fallback. No private transcript or map enters the public Email Studio asset store, a generic preference JSON archive, cross-tenant digest lookup, D22 attachment corpus or future AI context. D32's independent file controls and current source/byte policy remain authoritative; opening a fold creates no new file conversion.

Preference persistence remains proportionate. The absolute two-value command and expected monotonic revision distinguish desired-state reconciliation from a historical transport receipt. Missing rows require no backfill; explicit Compact establishes a fence rather than deleting a row and reopening old writes. The data race table addresses first inserts, lost acknowledgements, same-value saves, stale Full replay after Compact, rapid local intent and external conflicts. No durable workflow/outbox, broad settings-object patch, per-click business audit or offline surprise queue is added.

P31 requires actual finite byte/node/depth/comparison-window/time limits and boundary tests before activation; P32/P33 qualify real warm/slow-network/large-history conditions with bounded source windows. O01–O06 give named owner responsibilities, signals, thresholds and corrective actions; source leaks, false folding and inaccessible core paths remain release/incident failures rather than accepted monitor-only defects.
