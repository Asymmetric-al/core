## Final wording corrections verified

Two ambiguities in the first actual Email Studio table were reported and resolved before this Pass:

1. **D15 versus direct attention.** The corrected owner row says D15 owns optional following; direct-mention/required attention retain their independently qualified producer/source/audience contracts. It no longer assigns the whole mention domain to D15. Routine edit creates neither; genuine separate source events retain their normal effects.
2. **Publication versus network control.** The local editor row now prohibits **note/message publication** on mount/input/Cancel. It no longer bans every network publication, which would have contradicted expressly qualified D34 start/stop metadata. P07 states the same distinction.

These are owner/protocol clarifications, not new product scope. The rejected immutable-node-presence proposal is not reintroduced: deliberate text/reference appearance removal remains supported, with unchanged file custody and strict admitted-reference validation.

## Save and lifecycle checks

The final no-change correction is coherent. Every admitted Save binds the semantic operation, even when it creates no revision. R11 and the data contract retain a minimal binding or durable rejection fence until the note is irreversibly non-editable and restore/replay cannot revive that identity. Cache or material pruning never releases a key. This protects replay without storing a second body or requiring an indefinite history exemption. P06/P15/P17 require actual proof.

Operation outcome and currently readable head are separate. Replaying a successful old operation cannot replace a newer head or return forbidden old content. Lock waiting refreshes authoritative eligibility, and an A→B→A text sequence still has distinct revision identities. A possibly accepted Save cannot be cancelled by closing the UI. Required invalidation/safety obligations commit with the source; secondary failure is repaired against that edit rather than manufacturing another note.

Positive native-human provenance is explicit at creation/migration as well as editing. The inspected current generated mention-activity callback cannot qualify a row as native-human merely because it uses the note endpoint. All old writers must be fenced before activation; a compatible current-body projection is derived only. Disabling Edit preserves accepted outcomes/history/current privacy, and rollback cannot restore broad writers or erased bytes.
