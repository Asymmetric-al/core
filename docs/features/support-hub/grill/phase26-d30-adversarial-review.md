## Exact corrected decision

> Support Hub provides one focused, ready-made **Reports → Overview**. It complements ordinary work views rather than becoming every worker's forced landing page. **Work now** shows all unfinished conversations, unassigned unfinished conversations and conversations awaiting a reply, with the accepted status/target distinctions and exact current-work drilldowns. Its own **Currently handled in** control selects all accessible inboxes or one currently authorized inbox.
>
> **Results for a selected period** presents four fixed report sections: Reply targets, Reply times, Request labels and Feedback. These cover the inboxes the viewer can currently report on, explicitly independent of the Work now filter. Each retains its existing source-defined population, unit, time basis, attribution, uncertainty and drilldown. There is no common total, health score, staff leaderboard, universal “Inbox” filter or invented donor identity. Existing detailed reports supply narrower source-appropriate filters. Turning targets or feedback Off does not erase retained historical results. All-age review queues stay reachable separately.
>
> The overview reads source-qualified server projections through the existing Core boundary. It never becomes a CRM, Support state, email, target, feedback or reporting-definition write authority. Current authorization precedes counts and cached responses. Empty, disabled, missing permission, incomplete evidence, failed reads and stale information remain distinct; a missing value is not zero. Navigation preserves context and opens the same authorized Support detail from either Support or CRM.
>
> Future full configurability is an accepted product direction. Preserve stable, versioned source-owned report blocks and shared reporting ownership now; do not prebuild layout persistence, a drag-and-drop editor, arbitrary formulas, a reporting DSL, a warehouse or a second semantic layer. Future composition must preserve each block's scope/meaning and current permissions. Viewing this overview sends no email; any later separately authorized scheduled reporting remains Phase 33 → Email Studio/P17 → P6.

## Exact required amendments

### D30-R01 Scope, necessity and strongest alternatives

Accept the focused fixed overview as a useful common starting place. B—work views and separate reports—is the strongest simpler alternative and remains a complete way to work. C—a useful default plus configurable approved blocks—is credible for differing recurring review needs, and the founder intends that direction eventually. A's current scope is complete without a builder: it assembles already-required answers and their next actions. No measured Asym study establishes a productivity lift, mandatory weekly review ritual, universal team-lead role or current need for custom layouts. Do not copy a vendor feature list or turn the overview into Asym's whole-product dashboard.

### D30-R02 Entry, terminology and ordinary work

Use the existing Support **Reports → Overview** route and navigation, with **Overview** as the page title in Support context. Keep work views, search and direct conversation links available. Do not change every staff member's landing preference, create a second Support Studio destination or require opening reports before handling a request. Navigation from a report through Support and permitted CRM context preserves its explicit return location and any separately qualified safe conversation draft; opening an overview does not create a case, note or Activity.

### D30-R03 Fixed Work now composition and counting

Provide three concise summaries: **All unfinished**, **Unassigned**, and **Replies needing attention**, all labelled in **conversations**. All unfinished counts distinct currently permitted continuing work components whose D3 state is Open, Waiting for requester or Waiting on our side; include future-deferred Open. Show those three state counts as its breakdown without calling all unfinished work urgent. Unassigned is the D6-qualified unfinished subset with no current assignee, including waiting/deferred work and any owner-required review distinctions; it does not reset routing or mean safe to claim. Replies needing attention counts distinct continuing conversations with at least one still-owed D14 contribution. Fulfilled-but-unscored timing evidence is not outstanding reply work. Use complete source queries, not hydrated-page length.

### D30-R04 Live groups, overlap and review destinations

Within reply attention preserve D14's overdue, timing needs confirmation, within-target and untargeted distinctions. A conversation can have several underlying reply periods and appear in more than one such group; show the overall distinct-conversation count and label groups as overlapping, never sum them. The detail exposes all permitted underlying obligations. Unassigned is already part of unfinished, and reply attention is not another additive workload. Existing D3 due/follow-up and actionable delivery-recovery destinations remain directly discoverable alongside intake, handoff and feedback review as plain named links under **Other work and review queues — all dates**, outside the Work now filter's visual scope. Do not create a combined problems badge, copy P17 attention state or infer zero hidden reviews. These links use each existing owner's scope and do not inherit the overview date/inbox controls. A fulfilled reply or zero summary never certifies delivery recovery, due follow-up or independent review complete; no new queue is invented.

### D30-R05 Work now inbox control

Place **Currently handled in** inside Work now. Default to **All accessible inboxes**; allow one current authorized inbox using the existing searchable accessible selector. All accessible means the viewer's current permitted work population, not the entire tenant or every original component. Missing, forbidden or no-longer-qualified selected scope is **Selected inbox unavailable**, never empty ID interpreted as All. Require deliberate selection of another scope; preserve safe date settings. Retirement alone does not invalidate an inbox reference: retain still-owner-qualified unfinished work and selected scope, with a clear Retired label where its metadata is permitted. No retired label grants new access. Now has no Created date, historical period, donor, label or employee-performance filter. Counts/links carry the exact source predicate and current scope.

### D30-R06 Independent Results scope

Results has only its period and reporting-timezone controls at overview level, with persistent text: **Across the inboxes you can report on. Work now filters do not apply.** No global Inbox selector is introduced. D14 historical facts, D21 current responsible inbox and D28 original invitation inbox cannot silently be treated as one dimension. Each section aggregates only its currently authorized owner population. Do not filter historical populations through today's active-inbox catalog; retain retired source references only where their owner preserves meaningful current report access. **View full report** carries period/zone and a safe return context, not the Now predicate; the full report exposes its qualified narrower dimensions. Clicking an actual metric instead carries that metric's exact cohort/kind/evaluation context. This is the permanent simple A design; it does not require inventing a new historical inbox dimension.

### D30-R07 Period, timezone and simple controls

Offer Last 7 days, Last 30 days, This month (month start through today) and Custom; initialize a new context to Last 30 days including today. Show actual local date endpoints, timezone and **Through [evaluation time]** for an incomplete current day/month. Resolve a qualified staff reporting timezone, then tenant reporting timezone, then visibly UTC if neither exists; allow an explicit valid IANA reporting timezone without rewriting source calendars. Date picks are inclusive local dates compiled by the owner into a half-open start-to-next-day interval, with current-period evaluation bounded at the trusted evaluation instant. Custom applies on deliberate Apply, spans 1–366 local calendar dates and ends no later than today in the selected zone. This is an overview interaction/query bound, not a new source retention period or a limit on separately qualified full reports. Explain longer-range access through the full report; do not truncate silently. Range/zone validation preserves previous results under their previous visible label until a valid replacement is applied.

### D30-R08 Reply targets section

Reuse D14 **Targets due in [period]**: finalized original target instances in the owned due cohort, First and Next separate. Show **On time among assessed** as on-time / assessed, alongside assessed versus finalized count, unknown evidence, exclusions and separate potential unconfirmed targets. Assessed includes confirmed unanswered-overdue misses; ordinary late cleanup/Off cannot improve the past denominator. Keep on-time, replied-late, unanswered-overdue and unavailable outcomes traceable. Do not average inbox percentages or pool candidate contributions into finalized target counts. No targets due is a complete empty result; disabled current policy is a separate configuration fact and does not blank history.

### D30-R09 Reply times section

Reuse D14 **Waiting periods ended by a staff reply in [period]** with separate First/Next, median, p90 and exact measured sample. The fixed overview presents **Elapsed time** explicitly; qualified service-hours analysis remains in the full report and is not silently pooled into this preview. One reply can end several waits; counts are completed waits, not messages, conversations or staff effort. Accepted-but-uncertain timestamps and uncertain cohort membership remain disclosed under D14. The median convention and nearest-rank p90 are unchanged; round display only. Genuine zero elapsed time is distinct from no data. The always-visible current-work area prevents favorable completed-response summaries from concealing unanswered work.

### D30-R10 Request labels section

Reuse D21's component-first cohort and current categorization, labelled **Current labels on conversations started in [period]**. First qualify current permitted components and their earliest original start; a later merged original cannot independently pull an older component into a recent period. Show N total, labelled L and unlabelled U only under complete metadata, with L+U=N when that equality is qualified. Show up to five highest-count currently permitted labels, stable-ID tie break, plus View all labels. Each count is distinct cohort conversations carrying the label; multiple labels overlap and percentages use N. No pie, Other residual or claim that the top five cover the whole cohort. Ordinary archived labels remain labelled as archived when permitted. Preserve separate Start date unconfirmed evidence rather than guessing membership or calling an incomplete population complete. Unknown metadata, missing names and privacy restrictions never become No labels or exposed raw IDs.

### D30-R11 Feedback section and Off history

Use D28 **Invitations issued in [period]** as the fixed preview cohort, with original source/inbox provenance and responses to that exact cohort **as of this evaluation**. Issued includes distinct effects whose submission may have begun, including indeterminate submission. Show issued/responded counts and the three rating counts/distribution with the qualified submitted-rating denominator. Never divide all responses received during the period by invitations issued during the period or only confirmed provider acceptances. Show response windows still open when relevant; no response is neither positive nor negative. Feedback Off is current configuration only: retain currently authorized historical results and all-age review navigation. With no eligible history, explain Off/not yet measured separately from error. Show no individual comments, donor names, case subjects or employee rankings on the overview; the existing authorized Feedback report/detail owns them.

### D30-R12 Conservative presentation and interpretation

The fixed historical composition is exactly Reply targets, Reply times, Request labels and Feedback. No automatic comparison arrows, red/green trend verdicts, overall health/satisfaction score, fundraising value, staff productivity, resolution SLA, predicted capacity or AI commentary is added. Existing genuine trends remain in detailed reports. Use short tables/definition lists and restrained horizontal comparisons only where they communicate meaning; values, units, sample/coverage and important uncertainty must be available without hover. A tiny card that cannot explain a metric uses a concise qualified summary and full-report link rather than concealing its denominator.

### D30-R13 Evaluation consistency and freshness

Each returned section/block has a source-qualified metric/definition revision, typed scope, period/timezone where relevant, measured unit, trusted evaluation/read-cut evidence, computed time, source-through/completeness state and exact detail descriptor. The three Work now totals and breakdowns come from one coherent authorized read cut. A displayed timestamp alone does not make separately read statements consistent. Each historical block keeps internal numerator/denominator/sample/detail coherence; do not promise one atomic snapshot across independently owned blocks. Show block-level evaluation time when it differs. Current source/privacy/permission gates still apply at serving, independently of historical evaluation time or cache TTL. Derived read models must disclose their actual supported freshness and withdrawal conformance.

### D30-R14 Refresh and interaction stability

Provide one explicit **Refresh** action for all visible results. Read on entry and after an applicable context change. Refresh Work now automatically no more than once each 60 elapsed seconds while visible and online; pause when hidden/offline and coalesce focus/reconnect/manual/invalidation triggers. The visible page says **Updated [time]**, never promises instantaneous live state. Period results refresh on entry, applied period/zone changes, explicit Refresh or a known relevant invalidation, not every minute merely because Now refreshes. If Now cannot obtain a current qualified read after 120 seconds, mark it **Out of date**; retain previously allowed values only under the applicable current-authority/retention contract. Unknown current authority means clear those values, not serve a stale fallback. Late responses from older context/revision cannot replace newer results. Do not move focus, re-order active controls or repeatedly announce every refreshed count.

### D30-R15 Exact detail, live change and safe return

A Work now count opens its exact conversation-level query; a target/wait/label/invitation metric opens its native-grain report detail and can then open canonical conversations. A number of waits need not equal a number of conversations. The descriptor binds owner/definition, scope, cohort, kind, evaluation and current tenant/principal context, never a browser-written arbitrary query. Recheck current access before opening. If the original evaluation can be replayed safely under current source rights, label it; otherwise deliberately perform a current re-evaluation with the same semantic criteria and state **Updated since overview**. Never freeze revoked access to force matching counts, silently substitute a current Created filter or construct missing historical facts from a timestamp. Back returns the prior valid control state, scroll and focus context; source restriction still wins over cached content.

### D30-R16 State model and partial failure

Every block distinguishes Loading, Ready with data, Ready empty, current policy Off with/without retained history, Incomplete/unknown evidence, Unavailable/failed and Stale. Missing permission does not reveal hidden names, totals or a count of forbidden inboxes. Do not initialize business values to zero or show perfect percentages while loading. Do not label an incomplete scan an exact total. Retry only the failed read where safe; one block/source failure cannot block ordinary Support navigation or overwrite unaffected results with zero. After an applied context change, old results are not displayed beneath new labels. An unavailable source must not trigger a public/client cache or broader role fallback.

### D30-R17 Shared implementation and future full configuration

Record future full configurability as the founder's intended direction. Implement the fixed composition as ordinary code-owned use of stable, versioned owner-qualified block/read/detail contracts. Keep presentation order and titles separate from metric identity and source meaning; avoid UI-position keys, copied formulas or one opaque mutable dashboard blob. These seams are required now because they preserve one definition and safe evolution, not to build hypothetical infrastructure. No persisted per-user/tenant layout, drag editor, generic registry administration, expression language, custom joins or hidden disabled Configure button ships under A. Future composition belongs with qualified Phase 33 shared reporting, can arrange only compatible authorized blocks and must complete its own save/share/reset/compatibility/retention UX before activation. It never gains authority over metric definitions or underlying records.

### D30-R21 Query completeness, bounds and precision

Compute complete authorized populations and deduplication before aggregation/ranking; page detail through existing owner keyset contracts, with at most 50 rows per page in this surface. Database/API row caps and the current adapter's 2,000-row limit are not complete-report boundaries. Do not fetch every message body or publish a raw aggregate-source dump. Return only the required aggregate/coverage/detail metadata. Counts use exact nonnegative integers with checked serialization; ratios derive from exact owned numerators/denominators, remain undefined at zero denominator and round only for display. Do not average percentages or percentiles. Align indexes/query plans to actual tenant/current-home/status/source-time/original/target/feedback predicates. If an owner cannot provide a complete query within its qualified budget, show unavailable with the full report's qualified path rather than truncate.
