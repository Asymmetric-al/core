# Send with explicit work intent and prepared human replies

**Status:** Fully founder-ratified, Phase 26 D4, 10 September 2026, including all amendments, adjustments, changes and updates. D1–D3 remain fully ratified. This includes every D4-R01–R17 clause, P01–P18, the complete blueprint and adopted evidence corrections. This is a grooming ADR, not a formal specification or implemented behavior.

## Decision

Default Send reply performs no work transition and preserves a valid reminder. It never writes back an old snapshot or bypasses D1/D2 collision and authorization rules. D3 independent new-input/due/adverse evidence may still create Open review. A labelled After sending selector stages an explicitly named current-draft action; selecting does not send and a new draft does not inherit it.

Before local admission, the exact human reply is fully server-validated, compiled and durably prepared against its reviewed audience, work action and dependencies. One Support transaction admits reply, optional D3 transition/history/reminder effects and durable dispatch intent. Phase 6 owns asynchronous transport and evidence through the qualified tenant Resend connection. Unknown delivery is reconciled under the existing exact sealed identity, never blindly resent.

## Email Studio and ownership

Optional eligible reusable wording inserts nondestructively into the draft with revision/provenance. It does not change recipients, subject, work, reminders, CRM or owner outcomes. Phase 17's qualified shared compiler, compact Service-message-compatible presentation and preparation are reused; human correspondence stays outside the system-message catalog. No new layout role, provider-template authority, Support sender or second CRM is introduced.

The existing Phase 17 preparation-material classes cover different purposes. D4 ratifies a narrow distinct human-reply class with a seven-day maximum and all earlier utility/privacy/safety/acceptance/provider-window deadlines, through the shared material-contract generation. It is not a Support conversation retention decision. All exact fences, purge, group-cardinality and owner authority requirements remain in the full review.

## Why this tradeoff

Send-and-resolve and Send-and-wait are efficient for the appropriate intent but incorrect defaults for investigative/courtesy updates. Preserving work is predictable across all four D3 states. The additional selector step for nondefault actions makes their effect explicit without a confirmation on every ordinary reply. Saved wording and shared presentation improve reuse without making every reply a system publication.

Current Support queued rows, template-test-send, mutable template versions and scalar webhook handling do not implement this contract. Qualify and complete shared owners before activation, fence old/direct/macro writers and prove the full path; do not copy a test endpoint into production.
