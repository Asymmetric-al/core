## Decision

Adopt the complete [D34 R01–R28 corrected decision and23-category review](../../grill/phase26-d34-adversarial-review.md) as the proposed amendment package for selectedA. Show a quiet “Maya Chen is composing” line near the current composer without draft content, passive viewers, history or lock/takeover behavior. Keep current-source/version send admission independent; no cue or absent cue establishes who owns or will finish the work.

One finite Core app-schema technical session holds trusted observer/composition state. Authenticated closed API controls derive tenant/profile/actual session and exact original-source context. Supabase private per-observer server-only content-free refresh hints trigger current authorized snapshots for names. The qualified source/identity owner governs each control, snapshot and fanout admission; private join policy is defense in depth, not fresh per-event authority. No raw lease publication, custom managed-realtime schema object, generic presence workflow or new socket platform is added.

Fixed control windows and ordered sequences prevent delayed reports from reviving expired activity. Reconcile unknown ACKs read-only without replaying typing. Control ACK acceptance is independent of peer-projection freshness. Snapshot expiry is conservatively anchored to request start and current context. Lost hints repair through bounded combined refresh/expiry rather than durable retries.

The initial proposed profile is5s fast/10s quiet combined refresh,15s composing liveness,30s local idle,30s observer lease,15s fixed control window and12s hard snapshot trust. Ready leading dispatch targets150ms; healthy connected peer display/removal targets p95≤1,000ms in the declared actual fixture. These are testable engineering choices, not measured deployment results or zero-lag promises. Finite rate/instance/source/payload/cleanup bounds live in one versioned runtime contract.

## Alternatives and tradeoffs

Existing assignment/private drafts/committed-update checks without a cue is the strongest simpler alternative, but the founder explicitly selects early composing awareness. Raw client Presence is convenient but cannot supply trusted named identity/current source authority. Shared-room named broadcasts leave stale subscribers in a sensitive audience. Direct high-frequency Postgres Changes adds publication/per-change cost/delete complexity. A custom Vercel WebSocket server is now supported, but creates a second connection/shared-state operational owner. The selected narrow lease/snapshot/hint approach uses the current stack with explicit bounded overhead.

## Domain and Email Studio seams

P17 Email Studio keeps governed wording/signatures/authoring and immutable outbound preparation; P6 keeps dispatch/retry/provider outcome and durable communication evidence. Awareness creates neither and shares no draft/recipient/attachment/mode data. Cue ending on admission is not a Sent claim. CRM opens the same authorized Support reader, without copied person/draft/Activity or inherited financial/member-care access. Assignment, coverage, Follow, SLA clocks, D24 work and D33 reading remain separate. No passive activity history, customer-visible typing or AI action/retrieval authority is introduced.
