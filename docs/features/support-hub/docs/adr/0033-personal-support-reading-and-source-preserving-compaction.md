## Decision

Provide one personal Compact/Full default through D20's shared personal-preference owner, scoped to the current tenant and actual authenticated staff member, initially Compact. The qualified Support reader uses it identically from Support Hub and CRM. Place a labelled reading-default radio menu beside conversation Find; explicitly distinguish automatic saving from temporary region/conversation expansion and truthful local-only failure state.

Both modes read the same current permitted safe source. Compact uses conservative, whole-region meaning-aware repetition maps; uncertain/changed/first/only context remains visible. Full removes display folding without becoming a raw-source escape or an eager archive fetch. Preserve D22 complete Find/exact navigation, D23 static history/signature provenance, D16/D17 source restrictions and D32 file/context behaviour. A derived map never becomes source authority.

Use exact shared Base UI/base-maia/Zinc semantic components and Core geometry/motion. ReUI shells and shadcn v3 mail are selectively evaluated layout references, not a new primitive base or code import. Current generic renderer and CRM-only preference helpers require qualification rather than blind reuse.

## Why this tradeoff

One common Compact default is smaller, but requires repeat work from staff who prefer Full. Full for everyone avoids fold interpretation but adds repeated scrolling. The founder selects persistent personal choice. Limit its cost to a closed enum and conditional owner command, not a settings hierarchy, per-inbox override or workflow platform. A distant profile setting obscures the feature; a bare temporary toggle obscures whether it saves. A labelled contextual default menu with separate temporary controls is the clearest permanent path.

## Owner and lifecycle consequences

Current tenant/profile/key uniqueness, trusted attribution and a monotonic expected-revision command prevent stale saves and delete-to-reset ABA. Initial absent state is Compact without write-on-read; explicit Compact/reset persists the revision fence. A stale equal desired value confirms current state without another effect; a different value conflicts. Local disclosure/current-mode state remains independent, and passive refresh never reshapes active reading. Source revocation dominates every mode/cache/return path.

P17 Email Studio owns actual governed wording/signatures/outbound preparation; P6 owns delivery. Reading preference, folding and Find cannot change recipients, outbound quotes, headers, draft/signature/send review or produce preparation/send events. CRM uses the canonical authorized Support source without duplicated Activity/person/task or consequential business writes. No AI, raw-source archive, whole-shell replacement or new file/document authority is added.
