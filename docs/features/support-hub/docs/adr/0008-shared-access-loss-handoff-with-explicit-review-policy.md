## Consequential boundaries

Access denial never waits for Support policy, portfolio enumeration, Pause, cover or reviewer availability. The owner retains durable causal evidence without security-critical per-principal fan-out. Support binds the current inbox policy once at first durable handoff admission, before bounded enumeration. Existing pursuits keep it through retries and later settings changes. New content within the same unfinished episode does not recapture a mode; a genuinely later reopening needs current qualification unless an unresolved review already governs it.

Invalid-handler repair, pending handling and completed Shared release are distinct. Canonical repair conditionally clears the invalid individual with previous identity, handoff condition and history atomically. An unavailable legacy reference cannot appear as a current valid handler; a cleared ID cannot bypass C by appearing ordinarily claimable. Preserve work status, team/inbox, reminders, history and owner facts.

Pause holds autonomous A release, not security denial, invalidation or discovery. Qualified manual A claiming/handoff remains possible; C requires a qualified reviewer to choose and perform Shared release, explicit eligible assignment or No handoff needed for genuinely complete work. Review concerns assignment, not an extra permission to send or Resolve. An unresolved C requirement survives moves and temporary resolution, becoming dormant outside actionable unfinished counts while Resolved and reactivating on relevant work. A qualified reviewer can settle it explicitly.

Restoration before invalidation may obsolete a loss; restoration after valid invalidation cannot silently cancel C or restore the old assignment. No automatic handback occurs. An unresolved A move binds destination policy once under current move/scope authority; a valid explicit handoff in that command may already settle it. Every writer uses one current conditional Support command and durable per-item history/recovery; no initial-intake replay, guessed default or arbitrary administrator fallback is permitted.

Support handling changes no Party, CRM owner, financial/care/representation permission, private draft or admitted mail author/audience/effect. Actual author revocation may separately block provider I/O through P12/P17/P6. Preserve original delivery evidence and bounded reconciliation rather than rekeying or impersonating a replacement.

## Why this tradeoff

Shared-only is simpler but cannot express the founder's review requirement. Review-first everywhere adds needless routine administration. A designated successor is useful when a person has been deliberately chosen, but is an explicit handoff rather than another automatic policy. One per-inbox choice makes the behavior visible and works for confirmed owner changes originating outside a single removal dialog.

The UI uses a compact Assignment setting, honest owner-action impact/results and contextual Review handoff actions in Support. Shared views remain projections; operational escalation uses the shared Mission Control task model. The fixed Support lifecycle-policy capability must be explicitly qualified in later authorized OpenSpec; custom Phase 34 automations retain manage/preview/test/activity safeguards. No current coarse role helper, RLS policy or polished UI is proof of the required owner substrate.
