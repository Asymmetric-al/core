## Why this shape

Whole-conversation transfer remains the stronger alternative when the specialist should conduct the remaining requester exchange. Quick clarification can use a permitted internal note/mention, and already-authorized direct action needs no delegation ceremony. For a bounded specialist step, retained coordination avoids an unnecessary donor-facing handoff. The governing shared-task requirement makes a new Support child-ticket engine the wrong permanent path.

The present persisted task helper is contribution-oriented and ties assignment to its initiating actor. Separate task/link/history calls and generic in-memory Tasks UI are not a ready Support integration. Extend the actual shared owner command and closed source contracts; do not disguise Support work as Finance or swap actor IDs to assign a specialist.

## Required boundaries and current work

Keep the trusted initiator separate from Support handling, task queue/assignee and actual owner-action performer. Give specialists a minimal purpose-authorized task brief without granting the full Support transcript or CRM/finance/care access. Safe owner results can return to Support without exposing whole restricted tasks. Source-derived content retains its disclosure floor; free-text authoring is not an automatic declassification path.

Admit work/brief/source interests/receipt/history/required dispatch atomically in the shared owner boundary. One stable occurrence reconciles identical retries; changed meaning conflicts. Bind exact existing work rather than fuzzy title/Party/gift matches, and evaluate its current result immediately so reuse of completed work cannot wait forever. There is no blanket semantic dedupe of independent free-text requests.

Original source scope, owner target and purpose remain fixed within each interest generation. Revisions needing different meaning require a reviewed new generation. Multiple source interests may rely on one task. D10 merge/Undo composes or partitions current interests without copying work, resetting owner status or repeating an action. One owner occurrence produces one review per current handling component while preserving all affected contributions.

Asking for help preserves D3 work/reminder unless staff explicitly select a valid new plan. Task due and Support reminder stay distinct. Relevant input, results, missed promised work or adverse correction create current review; routine progress does not mirror task states into Support. Review acknowledges the exact owner result considered; it is not a task checkbox, financial approval, requester reply or Support resolution. Legitimate independent owner work may continue after Support has finished its obligation.

Stop following this work ends only the conversation's current interests. Optional task dismissal is a separate explicitly selected owner-authorized effect; no generic Support action cancels an independent refund or shared operation. The resulting D3 plan is revalidated so ending the last blocker cannot leave invalid Waiting; this work-specific label is distinct from D5's End follow-up. Historical references and permitted reliance evidence remain. A late duplicate cannot resurrect ended work, while a genuinely relevant correction of a relied-on result can require review.

## Coherent UI, notifications and CRM

Keep Internal note/mention, Ask for help and the existing assignment/transfer control distinct. Use a small contextual panel with visible current responsibility, relevant existing work, concise brief and eligible destination; disclose dates/details only when needed. One compact Internal work card shows actual owner progress and clear Result ready/Needs input review actions. The ordinary reply remains D2/D4/P17/P6/Resend, with no automatic recipient expansion or task-completion email.

Use qualified shared notifications for actual current recipients, not a duplicate Support alert producer or a fictional P6 queue recipient. Equal assignee IDs cannot suppress an unseen required result. Required queue work survives notification failure. Actual staff in-product/email evidence follows P6/P17 and never becomes donor correspondence merely through a Support source link. In-flight authorized email is not recalled by ending a task.

CRM retains D9 peer context/correspondence and one current Support conversation projection. Shared tasks and business actions retain their owner history, while actual communication retains P6 history. No new Party, fake donor interaction, copied task state or last-contact update is created. All read/write/egress paths preserve tenant/source/owner authority and current revocation.
