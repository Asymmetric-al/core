# Shared implementation and testing decisions

## S01 — Delivery boundary and source adoption

The donor application owns surface routes, composition and local interaction. Canonical shared API/domain modules own business reads and mutations; shared Auth owns native session/cookie/callback integration; approved database hooks/collections own admitted client data; shared UI owns base-maia/Base UI/Figtree/Zinc components. Public content comes from the published-content boundary under P22/P23/P24, never from a private viewer-aware published cache. No Payload runtime is imported into donor/missionary applications. Asym Postgres owns CRM and financial truth; Twenty remains retired.

Each new surface adopts its exact existing source or the narrow extension expressly defined in this specification. A logical source contract is not a claim that a named runtime function currently exists. Complete the producer before enabling the consumer, and retire all reached incompatible routes, callbacks, GraphQL/RPC writers and browser fallbacks. Distinct current source, accepted target, active predecessor specification and release evidence must remain distinguishable in every task.

The four contract appendices are normative together. IC governs identity/personal contact, RC recurring/wallet/pledges, EX experience/content/communication and D records/documents/recognition/export. A specific rule wins only within the subject it explicitly governs; a duration, primitive or donor context in one section is not a global replacement elsewhere. Final F01–F14 clarifications are incorporated, not left for builders to reconstruct. Historical alternatives and evidence observations are not open product choices.

## S02 — Logical contracts, authority and data invariants

A protected read's typed result supplies the exact admitted logical subject/purpose, appropriate source/currentness basis, safe requested facts, declared coverage/availability and bounded continuation/destination descriptors. It distinguishes available complete/explicitly limited, known empty, updating and safe unavailable/denied outcomes. Physical property spelling remains the owner's convention; meanings and fail-closed behavior are mandatory. Amount, record existence, labels, dates, facets/counts/order and links each obey current field/purpose admission. A private descriptor or cursor is input, not authority.

An owner command receives deliberate desired action/value, exact server-resolved scope/resource, expected relevant source revision/terms and durable semantic operation identity. Financial commands additionally require the source-reviewed intent/authorization and exact account/mode/rail/binding evidence. Before secondary effects, commit the authoritative accepted result and required audit/outbox atomically. Plain CRM changes use their ordinary atomic change/audit/activity record; no generic provider journal is added to contact updates. Result distinguishes rejected-before-effect, accepted/applying, independently succeeded children, known no-effect failure and indeterminate external effect. An HTTP timeout never chooses a financial outcome. Same-operation reconciliation does not create another charge, email, export or detach; terminal transport caches are not semantic lifetime.

Required relational references carry Tenant plus the appropriate owner/entity/subject/source key, with non-null closed discriminants where authority requires them. Validate both old-row admission and effective new-row scope/state, immutable actor/owner/purpose/source attribution, unique semantic effects and append-only historical facts on every privileged and direct route. No default/global Tenant, nullable wildcard recipient/issuer, caller-provided role/author/audit actor or generic polymorphic ID bypass is introduced. P12 remains the sole fine-grained PDP with existing coarse RLS; no parallel permission rules in UI, CMS, provider metadata or read models.

Independent source updates, callback replay, out-of-order delivery, authority contraction, expected-revision/ABA conflicts, absent-row admission races and partial success have explicit owner tests. Locks protect actual aggregate admission and deterministic multi-record ordering; they do not span provider calls or human reading. Source reconciliation and durable outbox delivery remain idempotent. Invalidation consumes canonical source changes, never browser arithmetic or a webhook's unqualified arrival order.

## S03 — Contextual client state and readable experience

Use one shared request/cache owner and the approved Query-backed DB adapter for actual collections. Table performs source-manual filtering/sorting/paging presentation, Store local draft, Virtual rendering; none calculates authority or money. Single-object reads and commands need no unnecessary DB/Table/Virtual instance. Qualify then-current stable compatible releases across all package consumers, core/adapter types, root overrides and lockfile; an installed beta or Labs adapter is not compatibility proof. ReUI is inspiration for actual grids under its applicable license, not another engine or a mandate to grid every list.

Private state binds current Tenant/human/authorized subject/purpose/versions/query and is discarded on context loss or revocation, including retained DB rows and hidden drafts. Abort plus generation fencing rejects late responses independently. No public cache, private persistent browser storage, full-roster sync, provider credentials or personal query text in URLs/logs/analytics. Server current authorization is re-proved at every operation and egress boundary; a cache's staleTime is not permission.

Preserve the accepted small default counts, sort orders and section-specific empty/unknown/error behavior. Core touch target design baseline44 CSS pixels, readable focus/contrast/real heading/list/table semantics,320px reflow,200% text and400% zoom, supported RTL/CJK/long names and reduced motion are tested in actual composition. Material names, amounts, source consequences and tax/record distinctions wrap instead of inheriting a preview clamp. Native links navigate; buttons command; success follows actual committed/browser/provider fact. No duplicated desktop/mobile focusable controls, auto-reordering under focus, modal stack, fake progress or data-error business task.

## S05 — Confirmed testing decisions and honest prior art

Conrad confirmed this approach on9September2026: one primary complete donor-journey acceptance seam through the actual donor app and canonical APIs, with narrowly necessary supporting owner, database and provider/artifact proof. Catalog success does not prove actual renderer bytes or qualified source intake. Add new tests at these existing exported owner seams rather than a private helper per rule.

**Database:** reuse actual disposable migration/SQL assertion infrastructure on the supported target version, with restricted database roles and genuine separate concurrent connections. ## S07 — Compatibility, rollout and records

Additive owner migrations/grants and source commands precede new readers/writers. Deploy narrow public contract versions with explicit rejection of unsupported old shapes. Establish authoritative backfill provenance, interrupted replay and index/constraint safety before admitting legacy data; never infer donor identity, monetary receipt, verification, consent or tax case from a convenient old string. Migrate reached compatibility routes and alternate writers together. Preserve committed source/custody evidence and current permitted historical access under exact owner rules.

The old recurring `/donor-dashboard/pledges` route is only a validated GET/HEAD compatibility redirect to canonical `/donor-dashboard/recurring`; fixed campaign commitments use `/donor-dashboard/campaign-commitments`. Preserve only supported recurring selectors/return context; never translate a legacy ID into the fixed-total product or redirect a mutation. Other route spellings remain logical descriptors unless an existing owner fixes them; there is no broad URL redesign or menu builder.

Contain independently: new financial command admission, provider initiation, read projection, export preparation/egress, new document issuance and communication admission as owned. Continue already accepted reconciliation, source correction, audit and disposal without issuing a duplicate effect. Roll-forward is preferred after immutable writes; rollback cannot delete money, pretend a charge was undone, revive old authorization, widen file access or reset an expiry. Purpose-specific raw/detail/semantic evidence schedules remain separate; no universal timer/cascade. A legal hold may preserve restricted evidence, never extend an expired public capability.

Performance/availability monitors in the four contracts keep their exact signal, sample threshold, owner and response. Bind roles to actual maintainers before release. Missing samples are unknown; no UI label, synthetic test, vendor marketing statistic or registry metadata is production evidence. Normal monitoring cannot waive zero-tolerance access/money/case/duplicate-effect invariants.
