# Financial and shared contract — bounded UX review

9 September 2026. Read-only review of the complete financial contract, all 74 financial-story acceptance sets and shared decisions. No root contract, source, provider or external state was changed.

## Required precise corrections

1. **Financial D13 final paragraph overstates the no-side-effect boundary for imports.** “Read/enable/import/display correction creates no … state change” can prohibit the source-qualified import of an identified/submitted record or the legitimate source transition whose projection D14 then consumes. Q28's controlling language is that historical imports do not create credit/thank-you/receipt/notice **merely because the portal now reads them**, and that the read path does not manufacture a source transition. Replace with: **“Portal read, projection enablement, refresh and presentation correction create no task, Home/bell item, message, receipt, credit or source-state transition. Qualified source import/correction retains its independently authorized state effects; exposing or replaying history adds no acknowledgment/credit effect. Existing P14 acknowledgment eligibility remains independent.”** Keep story D61's no replayed imported sends/credits, but clarify this does not prohibit legitimate source import/state admission. This is a source-versus-presentation distinction, not new import functionality.

2. **Shared S06 G07's phrase “No live private content … on GET” is too broad.** The actual contract permits current authenticated private content reads and denies private data in public artifacts; it forbids business-effect admission on ordinary GET. Replace the final G07 sentence with: **“No private viewer content or tokens enter shared public HTML/RSC/cache artifacts, and ordinary GET/HEAD performs no business-effect admission.”** Preserve the separate qualified Auth/document capability protocols. This prevents a global phrase from appearing to prohibit the portal's legitimate private read seam.
