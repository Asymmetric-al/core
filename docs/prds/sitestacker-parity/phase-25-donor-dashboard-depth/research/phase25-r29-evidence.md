## Findings that change the implementation

<!-- prettier-ignore -->
| Verified finding | Permanent consequence |
| --- | --- |
| A received DAF grant has sponsor legal ownership and advisor recognition. The advisor may never have personally funded the DAF or claimed a deduction. | No personal receipt, duplicated personal monetary giving or “you already took a deduction” language for the grant. |
| A QCD-intended IRA gift is not a DAF soft credit. The custodian is not automatically its legal donor. | Source-resolve owner/beneficiary versus custodian; retain properly admitted personal monetary history and dedicated QCD acknowledgment. |
| A QCD amount excluded from income cannot also be deducted, but IRA-origin money does not determine every personal tax result. | Explain the no-double-benefit rule without calculating eligibility or permanently forbidding a legitimate source-authorized reclassification. |
| P14's recognized amount can be partial or capped and may exist for several advisors. | Never relabel it as a full grant amount. Grant amount permission is independent; omit list money when only partial recognition is admitted. |
| The real QCD document catalog exists and starts dark; ordinary US annual purpose excludes QCD. | Reuse that purpose, complete source/qualification gates, and prevent generic receipt fallback. |
| Current donor receipt code constructs generic text outside that purpose resolver. | Reconcile the direct route as well as UI before activation. Current code is evidence of a predecessor, not the final design to preserve. |

**Result: 46 tests passed, 0 failed, two files.** The JSON report includes nested describe suites; those are not eleven test files. These tests verify actual purpose catalog integrity and fail-closed availability, including the distinct dark QCD purpose. They do not verify end-to-end QCD intake, donor identity, actual renderer/legal qualification, target RLS, a live database or donor comprehension.

The target `getPartyCreditActivity` search in `packages`, `apps`, `supabase/migrations` and `tests` had no matches. QCD symbols do exist in the real catalog, types and tests. No tests were added to mirror a proposed design. T01–T22 describe the meaningful future DB, source, API, renderer, migration and user-facing proof. Spec acceptance does not turn them green. Current Q14 G01 remains an unresolved native Auth contract, independent of this choice.

## Reconciled review findings

Owner, tax/data and UX lanes independently reviewed the choice and then the completed draft. Their material corrections were incorporated: explicitly visible not-a-tax-receipt/no-new-deduction meaning; QCD intent rather than certified qualification; inherited-beneficiary identity; source-effective gift-date ordering and explicit undated placement; no received-date inference from gift date; a minimal typed source result; allowance for a legitimate ordinary-case successor; no credit freeze/awareness fact on read; direct generic-receipt route convergence; and 24 elapsed hours rather than an invented business-day calendar.

Twenty-one categories have material implementation/design concerns; C22 found no additional independent concern after its listed checks. All concerns have proposed required language, effect and acceptance proof in the main review. The number reflects overlapping ways the same few source/UX mistakes can cause harm; it is not twenty-one separate subsystems to build.

Current source references, existing five setup paths, reverse-patch check and sixteen prior bundle hashes are verified before recording this review. Q29's new bundle preserves the finished review/evidence and decision state; it does not replace older immutable bundles. Canonical source, ADRs, OpenSpec, package versions, live databases/providers, GitHub and donor messages remain untouched. The authorized output is this durable grooming decision and its traceability, not implementation or publication.
