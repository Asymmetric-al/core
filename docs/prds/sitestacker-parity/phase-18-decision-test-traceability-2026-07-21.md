## Test namespace and evidence rule

Every executable requirement uses `P18-DNN-*` for a ratified decision and `P18-X-*` for cross-cutting proof. A test ID is not complete merely because a unit test with that name exists. Completion requires the evidence type named in the row against the same public contract and, where specified, the real database, deployed cache/CDN path, exact renderer, final bytes, assistive technology, qualified reviewer, or production-shaped workload.

All single, API, scheduled and batch behavior is tested through the same Generated Document service. Deterministic fakes are allowed for renderer, object store, clock and identifiers in service tests; database-enforced truth uses real Postgres/Supabase. Direct prototype preview/render, `.txt` receipt/statement, Unlayer and migration routes are forbidden seams.

## Detailed release-blocking assertions

### `P18-D01-*` — product boundary

- Catalog validation rejects unknown purpose/lane/block/field/case/output/records keys and any tenant-authored official purpose.
- One ordinary general/custom document can be created and published without developer help while an official document remains protected in the same product.
- Native package round-trip and hostile import tests prove exact schema/dependency reporting, destination-owned quarantine, no silent loss, no real data/secrets/artifacts/authority/review transfer, and no auto-publication; unsupported foreign/legacy formats fail without an approximation runtime.
- Architecture tests prove Phase 18 cannot select statement populations, send messages, mutate ledger/source facts, manage general files, or traverse arbitrary CRM data.

### `P18-D02-*` — authority, state and idempotency

- State-machine/property tests reject illegal transitions and derive user states/qualifiers without overloading generation, issuance, artifact, delivery, access or records truth.
- Duplicate submit/refresh/timeout/crash/replay/concurrency converges to one request/artifact; changed input under an existing semantic key conflicts.
- Attempts never become document identity/currentness and stale fences cannot finalize.

### `P18-D03-*` — renderer qualification

- Charter/corpus/candidate/validator hashes predate result inspection; held-back fixtures differ materially from development fixtures.
- Every hard gate covers protected extraction, 100+ pages, tables, pagination, Letter/A4, English/French/RTL/CJK, licensed fonts/glyph failure, PDF/UA-1, required PDF/A-2a, manual assistive technology, no-network/filesystem, resource/fault/determinism and production operations.
- A failed hard gate cannot be offset by score/cost. Exactly one passing material winner or no winner is recorded; no-winner keeps production dark.

### `P18-D04-*` — artifact and one-document truth

- Purpose contract alone selects `accessible-v1` or `accessible-archive-v1`; tenant, route or provider downgrade fails.
- Exact order—finalize, validate, hash, private store, read back, promote—is failpoint-tested. Byte change after hash/promotion is impossible.
- Database concurrency proves at most one current eligible publication and one canonical artifact per request/profile.
- Portal, staff, missionary-authorized, print, full/range and Phase 17 handoff all match stored generation/digest/length.

### `P18-D05-*` — authoring and governance

- Closed-schema/fuzz tests reject raw HTML/CSS/JS, executable payloads, absolute positioning/overlap, invalid semantics and renderer source.
- Keyboard/screen-reader/non-drag tests cover every block, structure/check action, conflict, comparison, preview, publish and schedule state.
- Synthetic proof allocates/sends/stores no official identity and cannot resolve real donor data.
- Protected review is different-human, current-capability and step-up enforced; split edits/role switches/service identities cannot evade it.

### `P18-D06-*` — data boundary

- Crafted requests cannot enable/preview/render/export any fact outside current tenant, purpose, audience, recipient, source role, lane, classification and privacy policy.
- Existence-sensitive forbidden facts are absent from search, counts, samples, errors, logs, imports and output.
- Named single roles fail visibly on ambiguity; collections preserve source membership/order/bounds and never silently truncate/filter/sort/group/aggregate.
- Labels may change without binding drift; type/meaning/privacy change cannot masquerade as rename and policy narrowing wins over stale publication/cache/queue work.

### `P18-D07-*` / `P18-D08-*` — jurisdiction and U.S.

- Server resolves pack only from verified issuer. Donor country, currency, Site, locale, template, staff choice and forged IDs cannot select it.
- Every eligible U.S. contribution maps to one supported case, typed specialist obligation, non-tax recognition or explicit unsupported result—never a default cash case.
- `$75` and `$250` exact boundary suites prove gross/eligible comparison and no aggregation.
- Text/semantic assertions prove required content present/absent; noncash value cannot leak through visible or hidden channels.
- Audience matrix covers legal contributor, DAF sponsor/advisor, employer/employee, tribute, household, missionary and restricted worker.
- Specialist obligations dedupe, separate multiple duties, retain deadline provenance and reject dismiss/delete/force-close.

### `P18-D09-*` — U.S. identity

- Parser/formatter property tests cover fixed ten-character Crockford alphabet, case/separator/input aliases, round trip and rejection of partial/fuzzy/confusable/invalid version inputs.
- Forced named-constraint collision tests prove four retries plus fifth success and five-collision fail-closed behavior without catching unrelated uniqueness errors.
- Concurrency proves one logical reference/current version; correction race cannot create two `v2`s.
- Valid reference possession reveals nothing without authorization; unauthorized/unknown responses are indistinguishable.

### `P18-D10-*` / `P18-D12-*` — Canadian activation and signer

- Nonparticipant end-to-end traces prove zero Canadian UI/fields/queries/rows/jobs/storage/exports/crypto/alerts/donor questions and meaningful overhead.
- Activation is all-or-nothing against exact issuer/proof/pack/signer/records/locale/continuity/epoch revisions; stale task returns the exact cause.
- Cash/cumulative/noncash/split/replacement positive and negative fixtures prove source facts and protected fields; Québec overlay appears only when applicable.
- Proof loss, pause, suspension, revocation, end and reactivation fixtures prove effective intervals, donor disclosure, no retroactive suspension-period receipt and unaffected gifts/non-tax work.
- Signer interval constraints allow one current/one ready successor; asset access/metadata/export tests prove isolation; failed successor leaves current intact.

### `P18-D11-*` — Canadian serial

- Real-database concurrent allocation locks only the exact issuer, advances once and atomically writes reservation; exact replay reuses it and changed fingerprint conflicts.
- Format/property/load tests cover unbounded positive `BIGINT`, minimum six-digit display, ordering and `R-999999 -> R-1000000`.
- Failure matrix proves no final bytes -> accounted not-issued; possible official bytes -> conservative canceled; no state reuses a serial.
- Replacement promotes successor and cancels predecessor in one transaction only after artifact proof; failed replacement leaves valid predecessor current.
- Activation blocks if safe continuity cannot be established without external-history import; no migration subsystem is invoked.

### `P18-D13-*` — protected access and cache behavior

- `GET`, `HEAD`, link previews, scanners and selector-only requests reveal no document facts, create no session, consume no grant and cause no state change.
