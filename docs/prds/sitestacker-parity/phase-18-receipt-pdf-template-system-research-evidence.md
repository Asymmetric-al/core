3. [IRS Publication 1771](https://www.irs.gov/pub/irs-pdf/p1771.pdf) — substantiation and disclosure detail and example wording framework.

5. [IRS Topic 506](https://www.irs.gov/taxtopics/tc506) — current overview of monetary/noncash documentation and special property rules.
6. [IRS Form 8283 and instructions](https://www.irs.gov/forms-pubs/about-form-8283), [Form 8282 and instructions](https://www.irs.gov/forms-pubs/about-form-8282), and [Form 1098-C and instructions](https://www.irs.gov/forms-pubs/about-form-1098-c) — evidence that specialist obligations cannot safely be hidden in one ordinary acknowledgment template.
7. [IRS exempt-organization recordkeeping](https://www.irs.gov/charities-non-profits/eo-operational-requirements-recordkeeping-requirements-for-exempt-organizations) — records sufficient to substantiate reporting and activities; no universal Phase 18 retention number.

## Security, delivery and caching evidence

1. [OWASP Server Side Template Injection](https://owasp.org/www-community/attacks/Server_Side_Template_Injection) — reason to forbid arbitrary template code and object access.
2. [OWASP SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) — reason to deny renderer network/ambient filesystem access.
3. [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) and [OWASP API1 Broken Object Level Authorization](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/) — per-request object authorization and nonrevealing denial.
4. [Vercel Cache-Control headers](https://vercel.com/docs/caching/cache-control-headers) and [Vercel CDN Cache](https://vercel.com/docs/caching/cdn-cache) — browser, generic CDN and Vercel-specific caches have separate directives/priorities; response/deployment proof is required.
5. [Resend email API documentation](https://resend.com/docs/api-reference/emails/send-email), [domains](https://resend.com/docs/dashboard/domains/introduction), [webhooks](https://resend.com/docs/dashboard/webhooks/introduction), and [open/click tracking](https://resend.com/docs/dashboard/domains/open-click-tracking) — Phase 17 owns delivery; Phase 18 supplies only exact artifact/access action identity. Provider acceptance/open/click cannot prove human receipt or legal issuance.
6. [NIST SP 800-88 Rev. 2](https://csrc.nist.gov/pubs/sp/800/88/r2/final) — disposal method/evidence must match media and sensitivity; a deleted database row is not complete sanitization proof.

Every protected HTML, redirect, error, full-PDF and range response MUST emit exactly:

- `Cache-Control: private, no-store, no-transform, max-age=0`
- `CDN-Cache-Control: no-store`
- `Vercel-CDN-Cache-Control: no-store`

It MUST also use `X-Content-Type-Options: nosniff`, a safe content disposition, a restrictive first-party CSP on guest landing/error pages, no third-party analytics/resources/service worker, no raw object URL, and no transform. Tests MUST verify effective deployed headers and cache bypass through the real Vercel route/CDN configuration, including redirects, denials, errors, `GET`, `HEAD`, full downloads and ranges—not only route-unit response objects.
