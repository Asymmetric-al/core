## Purpose

This is the durable traceability index required by D16. It prevents a broad implementation story from silently dropping a ratified safety, UX, migration, or anti-overengineering clause. It also prevents the opposite error: a planning document, test name, schema proposal, or Target Live label being reported as working product evidence.

Every clause below has status `specified`. The target implementation anchors are forward contracts, not existing symbols. The `evidence` field remains `pending implementation` until a row has one of the two evidence levels defined under **Evidence-State Rules**. A row may move to `implemented` when lightweight implementation evidence records one code SHA, reviewed source anchors, any applicable migration/version, and focused tests. Only an immutable, generation-bound CI/manual proof artifact that also records the required environment, catalog generation, harness, result, and evidence hash may move a row to `proved`.

The source-line anchors record authoring provenance only; they do not create a
scratch-space or local-file dependency. Every ratified option is named below,
every clause's coverage sentence is reproduced in this checked-in register, and
its normative product result is carried by the checked-in PRD/manifest/OpenSpec/
ADR package. The source digest was computed over the exact UTF-8 bytes with
`sha256sum` (equivalently `Get-FileHash -Algorithm SHA256` without newline or
encoding conversion); byte and line counts are independent cross-checks.

## Stable Identifier Contract

Decision clause ids are immutable. Stable proof and acceptance ids use:

- `P17-D<two-digit decision>-T<three-digit case>` for automated or named manual conformance cases;
- `P17-D<two-digit decision>-E<three-digit case>` for named acceptance examples;
- `P17-D<two-digit decision>-SUBJ<three-digit subject>` for stable atomic release-pack subjects (including every subject emitted by the release-pack allocation fixture);
- `P17-KEY-<name>@1` for a Target Live key-specific proof pack;
- `P17-SCOPE-<two-digit case>` for shared tenant/platform scope proofs, beginning with `P17-SCOPE-01`; and
- the security/provider ids defined in the PRD (`P17-REV-*`, `P17-ACT-*`, `P17-AUTH-*`, `P17-RSE-*`, `P17-HDR-*`, `P17-CON-*`, `P17-RPY-*`, `P17-ID-*`, `P17-ERASURE-*`, `P17-RET-*`) as supporting stable ids.

Moving a test file or implementation module does not change its test, example, subject, or supporting id. Splitting a case creates suffixed child evidence under the same semantic parent; weakening or deleting a ratified case requires a dated product-decision amendment. Evidence producers and closure validators must recognize every namespace declared above, validate its canonical syntax and meaning, and reject any unknown id. A proof artifact citing an unknown id, an unreferenced clause, or a Live key with an applicable unproved id fails closure.

## Evidence-State Rules

| State                      | Permitted claim                                                           | Required evidence                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `specified`                | Normative docs agree on requirement and target seam.                      | PRD, ADR where applicable, OpenSpec, census/manifest/traceability close with no known contradiction.                                                                      |
| `implemented`              | Named code/schema/UI path exists at one code SHA.                         | Lightweight implementation evidence: reviewed source anchors, applicable migration/version, and focused tests; no claim of production proof.                              |
| `proved`                   | Every applicable stable id passes in the required environment/generation. | Immutable, generation-bound CI/manual proof manifest with hashes, environment, catalog generation, fixtures, accessibility/security/provider results and no open blocker. |
| `inapplicable-with-reason` | A clause or ADR does not apply to one key/step.                           | Code-owned reason accepted by contract and closure gate; never a blank or client-selected waiver.                                                                         |

Percent-complete, “mostly ready,” a UI badge, a published template, a migration file, provider acceptance, or one passing happy path is not a traceability state.

Implementation CI MUST also generate the canonical
`phase17-obligation-exclusion-closure@1` artifact. It contains every contiguous
unique `OBL-001`–`OBL-041` row as
`{row_id, product_meaning, source_owner_anchor, disposition,
blocker_or_migration_rule, tenant_visibility}`, plus every ordered entry under
the census **Explicit Exclusions** heading as `{ordinal, canonical_text}`.
Unicode NFC, ordered arrays, lexicographically ordered object keys, UTF-8
without BOM, and SHA-256 over the exact canonical JSON bytes produce its
artifact digest; the catalog-generation evidence
stores both that digest and the digest of the cited census source. CI rejects a
missing/duplicate/reordered obligation, changed field, missing/extra exclusion,
or source/artifact digest mismatch. A prose claim that the census was reviewed
cannot substitute for this agreement proof.

## Mechanical Closure

CI must fail if:

1. any global or D1–D20 clause id is absent from the generated trace graph;
2. a stable test/example/subject/supporting id has no executable or named manual artifact;
3. an artifact cites an unknown or reused id with different meaning;
4. a Target Live key lacks its key-specific proof pack or any applicable decision proof;
5. a row is marked `implemented` without one code SHA, reviewed source anchors,
   any applicable migration/version, and focused tests, or is marked
   `inapplicable-with-reason` without a code-owned reason, or is marked `proved`
   without an immutable proof artifact containing the code SHA, catalog
   generation, environment, harness, result, and evidence hash;
6. a changed PRD/ADR/OpenSpec/manifest clause invalidates an evidence digest without returning the row to specified/implemented;
7. the current census, `phase17-obligation-exclusion-closure@1`, expanded
   manifest, release-pack allocation/subject-coverage map, generated
   projections, OpenSpec, implementation, and traceability hashes do not agree;
   or
8. a ratified test/example was weakened, deleted, or reclassified without a dated product-decision amendment.

The present package intentionally ends at `specified`. It gives an AI developer exact ownership, target seams, stable namespaces, and release gates without pretending the full product already exists.
