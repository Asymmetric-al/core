## Problem statement

The repository currently has several incompatible prototypes:

- live donor receipt and annual-statement `.txt` downloads recomputed from mutable projections;
- a staged-gift hard-coded receipt email path;
- correction-time JSON snapshots that rerender on demand;
- a `gift_receipt_records` scaffold whose output is explicitly non-official; and
- mutable PDF Studio roots plus direct preview/render and Unlayer-compatibility paths.

None is a complete official-document authority. Together they create split-brain identity, mutable history, unclear legal truth, inconsistent authorization, accessibility uncertainty, and paths that could silently rerender a past document with current facts or branding.

Nonprofit staff nevertheless need a modern visual authoring experience, automated everyday acknowledgments, reliable batches, official Canadian receipting where deliberately activated, exact correction history, accessible documents, donor self-service, and clear recovery. The solution must provide that breadth while keeping legal, financial, recipient, delivery, and records truth in their proper owning domains.

## Solution

Build one clean canonical generated-document system from day one. It has one tenant-facing Document Studio, one structured template model, one facts-to-exact-PDF production boundary, one current-first document experience, and one exception-oriented repair surface.

The permanent pipeline is:

1. the owning source freezes authorized facts and, where applicable, issuance authority;
2. Phase 18 resolves one complete currently compatible publication;
3. one tenant-scoped idempotent Generation Request freezes every meaningful pin;
4. fenced render attempts produce one candidate through the one D3-qualified renderer;
5. final bytes are completed, validated, hashed, stored privately, read back, and atomically promoted;
6. users access those exact bytes through current authorization; and
7. Phase 17 separately delivers that exact artifact and records communication outcomes.

This phase removes rather than adapts the repository's non-production receipt, statement, snapshot, Unlayer, mutable-root, browser-production-data, hard-coded-send, live-text, and on-demand-render paths. There is no legacy/foreign conversion import, dual runtime, compatibility fallback, migration console, or manufactured history; only the D1 native authoring package is supported.

## Product outcomes

1. Staff use three destinations only: **Templates**, **Documents**, and **Batches**.
2. Donors and permitted missionaries see one logical document and one current authorized PDF action, never several technical copies.
3. Templates have broad safe visual freedom but cannot invent, calculate, suppress, or traverse protected truth.
4. U.S. everyday acknowledgments are automatic and complete within a bounded federal pack; uncommon duties become governed specialist obligations.
5. Canadian official receipting is absent for nonparticipants and becomes automatic for ordinary eligible cases only after one proof-gated exact-issuer activation.
6. Every ready artifact is the exact validated private bytes; open, download, print, resend, range access, correction, retention, and restore preserve that identity.
7. Single, API, scheduled, and batch generation use the same public application boundary and semantics.
8. Failures name one cause owner and one safe next action. Successful automatic recovery stays quiet.
9. The launch contains no legacy runtime or speculative generalized platform.

## Goals

- Consolidate every generated receipt, official statement, optional purpose-separated Support overview, tribute notification, pledge statement, and approved custom document onto one canonical `pdf_*` bounded context.
- Define durable identity, authority, state, correction, access, retention, and evidence contracts before product code is written.
- Provide structured visual authoring that is fast for ordinary nonprofit staff, accessible without drag-and-drop, and safe by construction.
- Qualify at most one exact production renderer through a pre-registered production-shaped evidence contest.
- Produce one universally accessible canonical PDF and escalate the same artifact to an archival profile when the purpose requires it.
- Make tenant isolation, exact issuer scope, object authorization, idempotency, concurrency fencing, and private storage database/application invariants rather than UI conventions.
- Preserve clear ownership with Phases 7, 10, 11, 12, 13, 14, 16, 17, 19, 29, and 38.

## Implementation decisions

1. **D1 — One Universal Document Studio:** official/tax, governed-business, and general/custom lanes share one product and kernel; tenant freedom remains bounded by immutable purpose authority, and native package portability creates only a destination-owned quarantined draft.
2. **D2 — Five durable authorities:** publication, Facts Package, Generation Request, optional source-owned issuance, and exact artifact stay distinct behind one request state machine and one calm timeline; attempts are subordinate and delivery remains external.
3. **D3 — One evidence-qualified renderer:** a pre-registered production-shaped contest may select at most one exact production winner; no hard-gate winner means rendering stays dark.
4. **D4 — One logical document and one current PDF:** accessible and archival obligations apply to the same exact bytes, with purpose-owned profile escalation, immutable history, and atomic currentness.
5. **D5 — Structured visual authoring:** flow-first semantic blocks, soft presence plus server CAS, protected truth, exact synthetic proof, and proportional independent review replace arbitrary HTML/code and hard locks.
6. **D6 — Approved Data Views:** broad useful typed facts, bounded roles/collections/conditions, and safety-live controls are supported without arbitrary record traversal, formulas, queries, or calculations.
7. **D7 — Code-owned jurisdiction packs:** one shared kernel uses separate immutable U.S. and Canadian packs selected only from verified issuer authority.
8. **D8 — Complete everyday U.S. acknowledgment:** common federal cases are native and automatic; uncommon duties become evidence-gated Specialist Document Obligations rather than disappearing or expanding into a universal forms engine.
9. **D9 — Short U.S. reference:** first issuance creates one opaque `ACK-XXXXX-XXXXX` locator and immutable `vN` publication history; the reference never grants access.
10. **D10 — Deliberate Canadian activation:** the complete everyday registered-charity pack is structurally absent until one exact issuer passes the finite federal/Québec, signer, serial, locale, custody, records, restore, and responsibility gates.
11. **D11 — One issuer-owned Canadian series:** `ca_r_v1` uses a short `R-` lifetime sequence with permanent nonreuse and accounted dispositions; an exact copy preserves serial/bytes and a true replacement receives a new serial citing the retained canceled predecessor.
12. **D12 — One protected signer authority:** one current signer and at most one ready successor use protected evidence/mark and exact-byte/shared-checkpoint integrity; no mandatory per-receipt Asym seal, tenant PKI, or generic signature product ships.
13. **D13 — Scanner-resistant exact-artifact access:** portal authorization and a selector-plus-fragment mailbox capability both reprove exact recipient/current lineage; inert reads reveal nothing and every protected response carries the exact no-store/no-transform headers.
14. **D14 — Purpose-owned records controls:** separate preservation floors and privacy ceilings, bounded contract options, monotonic holds, exact custody, Canadian closure proof, staged disposal, and restore suppression are exposed through one quiet records surface rather than a general records suite.
15. **D15 — Bounded whole-publication recovery:** configured inheritance is normal; before freeze the fixed code-owned recovery order is one compatible same-scope prior followed by one exact-locale permitted ancestor, and after freeze every retry preserves identical pins.
16. **D16 — Publish now plus one appointment:** immediate publication is primary; one optional future appointment pins candidate, approval, civil/UTC/time-zone-data evidence and resolves every cancel/publish/race explicitly.
17. **D17 — Clean pre-production replacement:** one canonical generated-document system has zero legacy runtime or migration product; a destructive cutover proceeds only after the environment gate proves there is no real production or irreplaceable reliance, otherwise work stops for re-grooming.

## Authority hierarchy

When sources conflict, apply this order:

1. source-owned immutable facts, eligibility, legal recipient, money/ledger truth, correction effect, and optional issuance;
2. the immutable Document Purpose Contract and jurisdiction pack;
3. current safety/privacy/restricted-person/authorization policy;
4. the exact compatible Document Definition Publication frozen on the request;
5. the exact Facts Package and other frozen request pins;
6. the final stored artifact digest, length, object generation, and read-back evidence; and
7. derived UI projections, provider events, caches, search indexes, filenames, and operational dashboards.

Provider URLs, renderer status, email events, filenames, templates, staff selections, Sites, locale, currency, donor country, or storage metadata never establish legal or document truth.

## Canonical vocabulary

- **Document definition:** Stable tenant-owned design identity.
- **Draft:** Mutable CAS-protected semantic tree; never production authority.
- **Commit:** Immutable candidate plus complete dependency/proof graph.
- **Publication:** Immutable approved executable definition for future generation.
- **Publication head:** Server-resolved current publication for an exact tenant/environment/purpose/issuer/jurisdiction/scope/locale/class slot.
- **Approved Data View:** Immutable typed purpose-scoped semantic facts contract.
- **Facts Package:** Exact frozen values, source revision, policy fingerprint and digest supplied by the owner.
- **Generation Request:** One tenant-scoped idempotent orchestration intent with all meaningful pins.
- **Render Attempt:** Fenced append-only technical evidence subordinate to a request.
- **Issuance authorization/validity:** Optional source-owned decision that an official identity is required and valid, including exact issuer/recipient/coverage and correction/void/replace effect.
- **Document identity:** Phase 18 code-owned D9/D11 allocation of the U.S. acknowledgment reference or exact-issuer Canadian serial, its version/nonreuse/disposition evidence, and artifact linkage; never a substitute for source issuance authority.
- **Artifact:** Exact immutable validated private PDF bytes plus custody evidence.
- **Logical document:** Stable recipient-facing chain with at most one current eligible publication.
- **Copy:** Re-access or redelivery of exact current bytes; creates no version/serial.
- **Correction/replacement:** Source-authorized immutable successor; never overwrites predecessor evidence.
- **Delivery:** Phase 17 communication activity; separate from generation, issuance, access, and human reading.
- **Recipient authorization epoch:** Immutable interval binding the exact recipient/representative and accepted contact point.
- **Records Schedule Contract / hold / disposal:** Purpose-owned preservation/privacy/custody rules, monotonic protection, and verified end-of-life.

## Product information architecture

### Templates

The default list is purpose-first and shows title, purpose, scope/locale, current version, readiness, last change, scheduled successor where present, and one context action. A starter gallery is filtered by purpose, jurisdiction and locale. Copying a starter creates a tenant draft; system starters are never edited in place.

The editor has one compact top bar, a left **Pages / Structure / Add** rail, dominant page-aware canvas, and contextual inspector. The Managed Truth Rail explains **Owned by**, **Why managed**, **You can change**, and **Change at source**. The normal field picker shows only usable human-named facts with synthetic examples. Existence-sensitive forbidden facts are absent, not disabled clues.

Save states are exactly **Saving…**, **Saved**, **Offline — changes kept on this device**, and **Conflict needs review**. A local recovery copy is short-lived and bound to tenant/user/draft/schema/last server revision. Conflicts stop autosave and offer **Review changes** or **Make a copy**. There is no silent merge of protected/structural content and no CRDT platform.

**Exact PDF preview** uses the exact candidate pipeline and source-owned synthetic cases only, is watermarked **SAMPLE — NOT AN OFFICIAL DOCUMENT**, allocates no identity or serial, creates no donor history, and sends nothing. Checks group **Must fix**, **Review**, and collapsed **Passed**. Every issue names scenario, page, block, owner, consequence, and permanent fix.

Publishing defaults to **Publish now**. Standard changes may self-publish after proof. Protected changes require a different currently authorized person and step-up. The reviewer sees semantic/block-linked and production-rendered comparison, impact, and exact evidence; structural failure cannot be approved away. Restore always creates a new draft.

Native portability uses one versioned Asym semantic-template package, not HTML, PDF, provider JSON, or a legacy converter. Export includes the semantic graph and declared dependency identities/digests but no real donor data, secrets, generated artifacts, approval evidence, authorization grants, publication heads, operational history, or signer source assets. Import first produces an exact compatibility/loss report and, only after destination-tenant authorization, a destination-owned **Quarantined draft**. Nothing is silently dropped, mapped, trusted, proved, reviewed, or published; the ordinary destination proof/review/publication path remains mandatory. Unsupported foreign formats fail honestly rather than approximating content.

One optional **Schedule publication** path creates at most one immutable future appointment for that head. Its only fields are date, time, and named IANA time zone. The UI states current versus scheduled and what already-frozen work keeps. No scheduling question is shown to people who publish now.

### Documents

The list shows one row per logical document: human title/recipient, purpose, covered gift/period, one primary state, optional official qualifier, separate delivery qualifier, last activity, and one primary action. **Needs attention** is a saved filtered view, not a new subsystem.

The detail page presents a semantic HTML status/facts summary and one **View or download PDF** action. The HTML is not a second official document. Staff may also see **Send current copy**. Official identity, issue/correction date and currentness are clear; renderer, hashes, attempts and provider IDs stay behind permissioned **Technical details**.

One collapsed **History** timeline preserves correction/replacement/cancellation and evidence. Prior official artifacts are **Canceled/Replaced — do not use**, cannot be resent through normal actions, and need evidence permission to inspect. Missing current access never causes a rerender.

Failures use one of: **Fix source facts**, **Open template**, **Fix publication**, **Retry generation**, **Review validation or archive**, **Correct and replace**, **Review specialist follow-up**, or **Review/Retry delivery**. A generic retry or force-send is forbidden.

### Batches

Preflight freezes or identifies the exact source-owned item set/cutoff and reports **Ready**, **Already current**, **Excluded**, and **Needs attention**. It groups blockers by root cause before donor rows, hides zero-count categories, and never promises future serials.

The run is item-authoritative and derived as **Completed with issues** when mixed. Staff may generate ready items while blocked items remain uncreated/unnumbered where true. Retry targets eligible failed items only. Successful and ambiguous items never rerun blindly. Aggregate milestones use polite announcements; per-item noise is forbidden.

## End-to-end production sequence

1. Source owner resolves current tenant, issuer, recipient, purpose eligibility, coverage, facts revision, correction authority, and safety policy.
2. Phase 18 validates the exact Purpose Contract and Approved Data View, then assembles and hashes an immutable Facts Package.
3. The publication resolver applies configured assignment/inheritance, then the finite D15 compatible recovery policy if needed.
4. One admission transaction fences expected publication/safety/authority epochs and writes the immutable Generation Request or returns an existing exact replay.
5. Where the source contract authorizes and requires pre-render identity, the Phase 18 code-owned D9/D11 identity command allocates the U.S. reference or exact-issuer Canadian serial once after admission and records its nonreuse/disposition independently; the source retains issuance validity and correction authority.
6. A fair queue claims an attempt with lease/fence, compiles the semantic publication using only frozen facts/assets/fonts/locale, and invokes the one qualified renderer in a bounded no-network/no-ambient-file environment.
7. The system applies every authorized byte-changing finalization step, validates the exact final PDF, hashes it, writes a new opaque private object generation, and reads it back to confirm digest and length.
8. One transaction rechecks fences, links issuance where applicable, promotes the artifact/current head by CAS, and appends lifecycle evidence. No donor can access staged bytes.
9. Search/read projections update from authoritative records. Reconciliation repairs projections but never rewrites facts/artifacts.
10. Phase 17 receives the exact artifact identity and separately manages message preparation, outbox/provider state, communication history, bounce and resend.
