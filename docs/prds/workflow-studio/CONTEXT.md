# Workflow Studio domain glossary

Current planning language integrated 2026-09-22. This glossary explains the [owning contract](README.md); it does not grant authority, rename existing source records, or prove implementation. Existing business glossaries remain authoritative for their domains.

| Term                               | Meaning and boundary                                                                                                                                             |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workflow Studio                    | Shared Phase 34 Mission Control authoring/operations product, with contextual entry points and source-scoped participant views.                                  |
| Editable workflow                  | Tenant-designed process using only supported typed constructs, source actions and approved scope.                                                                |
| Automation                         | Configured approved trigger/condition/action behavior, using the same language and engine as longer workflows.                                                   |
| Protected process                  | Native source-owned operation exposed as Managed by the owning product; its policy is not copied into a second builder.                                          |
| Recipe                             | Stable requirement and example process such as GEN-01; a specified recipe is not a live tenant template.                                                         |
| Capability pack                    | Source-certified domain recipes delivered by the assigned phase, not a separate execution engine.                                                                |
| CORE                               | Phase 34 acceptance for 57 recipes and shared mechanisms using real non-mobilization tracers; independent of downstream packs.                                   |
| MOBILIZATION                       | Phase 41 application domain and 12 MOB recipes; prioritized after CORE.                                                                                          |
| GIVING                             | Phase 35's 15 contribution/recognition/recurring recipes, preserving native money and recovery owners.                                                           |
| EVENTS                             | Phase 37's three event recipes; registration/capacity remains event source truth.                                                                                |
| CARE                               | Phase 38's nine sealed recipes including GEN-18; actual care source/provider proof is separate from CORE privacy denial tests.                                   |
| FULL                               | Combined evidence rollup; never a prerequisite of CORE or a contributing checkpoint.                                                                             |
| Work package                       | Stable WS-01–WS-26 source planning identifier; not a phase, GitHub issue ID or completion claim.                                                                 |
| Work slice                         | One explicitly scoped part of a package, with a delivery checkpoint and dependency edges.                                                                        |
| Blueprint                          | Inert synthetic structured fixture BP-01–BP-16; all bindings require real owner qualification before publication.                                                |
| Form blueprint                     | Inert candidate field set FORM-01–FORM-04; not a universal personnel/clinical instrument or deployed form.                                                       |
| Dialect / AST                      | Versioned canonical structured definition (`asym.workflow/1`); visual graph coordinates are not executable truth.                                                |
| Compiler / IR                      | Pure validation/normalization into derived execution representation, digest, dependencies and diagnostics; compilation has no effects.                           |
| Semantic digest                    | Deterministic digest of executable meaning and pinned contracts; excludes diagram layout and camera state.                                                       |
| Template lineage                   | Stable identity across publications, preventing a version change from restarting the same subject journey.                                                       |
| Draft                              | Mutable revision-checked definition; save does not publish, enable enrollment or modify active runs.                                                             |
| Publication                        | Immutable accepted definition, semantic/registry versions and exact dependency snapshot.                                                                         |
| Binding                            | A source-qualified trigger/publication/scope association with independent enabled/disabled/suspended state and activation generation.                            |
| Binding manifest                   | Exact resolution of symbolic contracts, roles, messages, forms, subflows and source versions; a missing entry blocks affected publication.                       |
| Preflight                          | Immutable, expiring evidence of exact reviewed impact; final action still checks current authority, source state, revisions and digest.                          |
| Subject                            | Typed source occurrence or record, such as a conversation, document requirement, contribution or application; not universally a person.                          |
| Enrollment                         | Accepted start under tenant/environment/template lineage and source-semantic uniqueness policy; not assignment, amendment or application identity.               |
| Historical-dark                    | Imported/historical events have no outward effects absent a separately reviewed and authorized bounded backfill.                                                 |
| Run / engagement                   | Durable coordination instance pinned to a publication and plan revision, linked to source records.                                                               |
| Lifecycle                          | Active, on hold, discontinued or complete business-process disposition; distinct from execution health.                                                          |
| Operational health                 | Healthy, waiting, needs assignment, blocked or needs attention; a technical retry does not decline an applicant.                                                 |
| Plan revision / amendment          | Attributable future-work change with impact preflight, source rules, fencing, reason and history preservation; not re-enrollment.                                |
| Held disposition                   | A terminal source-business deferral requiring an authorized successor/revision or new engagement; distinct from pause/resume at a continuation point.            |
| Stage                              | Presentation grouping of node identities, not an independent scheduler or source-decision authority.                                                             |
| Node                               | One supported structured construct: sequence, task, evidence, action, wait, choose-one, parallel, subflow or finish.                                             |
| Occurrence                         | One activation of a stable node/path in a run; distinct from the node, source business occurrence and execution attempt.                                         |
| Attempt                            | One execution effort for an existing operation identity; retry does not create a new business effect.                                                            |
| Task result                        | Source-accepted task response; task creation or a generic checkbox does not establish money, approval, evidence or business completion.                          |
| Evidence result                    | Owner-qualified exact evidence version with identity, purpose, category, currentness and review; upload/clean scan is insufficient.                              |
| Communication result               | Source request/dispatch/provider outcome; acceptance, delivery, reading and business completion remain different.                                                |
| Process result                     | Declared engagement outcome supported by source facts, not an orchestrator success badge.                                                                        |
| Fact contract                      | Typed source meaning with version, scope, completeness/freshness, classification, purpose/audience and wake mechanism.                                           |
| Unknown                            | Fact unavailable/stale/incomplete; does not imply false or absence. Access denial is blocked, not a fact value.                                                  |
| Exclusive choice                   | One true alternative with all competing alternatives known false; overlap or true-plus-unknown blocks.                                                           |
| Parallel selected set              | Branches frozen at activation; unselected/canceled work cannot count as affirmative evidence.                                                                    |
| Join                               | Declared all/any/quorum completion rule including required branches; initial certified policy is all-required. Wider joins require proved remaining-work safety. |
| Subflow                            | Separate linked child engagement at exact publication, bounded delegation, cancellation and source-approved output; never broader authority or recursion.        |
| Role binding                       | Eligible responsibility resolution to a principal, allowed queue or Needs assignment; no access grant.                                                           |
| NHI                                | Existing Phase 12 non-human identity: single Tenant, own least-privilege grants, active human owner and live owner capability ceiling.                           |
| Participant session                | Private task-purpose admission through the accepted identity/PDP contract; no inferred donor/missionary membership or widened anonymous access.                  |
| Application                        | Phase 41 source identity and accepted business record; multiple applications may concern one Party without being the same workflow run.                          |
| My Journey                         | Common Phase 34 participant composition plus Phase 41-specific application experience and source-safe milestones.                                                |
| Operation intent                   | Durable request for one registered source effect with exact inputs, source identity, claim/fence and truthful outcome.                                           |
| Permanent semantic effect identity | Effect-owner identity across native callers, workflows, retries and publications; supplemental provider dedupe is not sufficient.                                |
| Fence / cancellation epoch         | Monotonic product proof preventing stale unsubmitted work after a winning change; cannot recall an already admitted external effect.                             |
| Outcome unknown                    | An effect may already have occurred; expiry or missing response does not authorize blind retry.                                                                  |
| Durable wait                       | Exact source predicate/version correlation plus post-registration recheck, event consumer and overdue reconciliation; timeout never approves.                    |
| Source clock                       | The source owns timing, pause/expiry/late-answer behavior and authorization lifetime; generic Studio defaults do not override it.                                |
| Simulation                         | Real evaluator with synthetic adapters/virtual clock and no live transport, credentials, business intents or history.                                            |
| Source certification               | Exact adapter, version, purpose, authority, evidence, failure/recovery and provider proof; distinct from parsing a schema.                                       |
| Tenant-ready / published / enabled | Separate readiness, immutable-definition and deliberate activation facts; one does not prove the others.                                                         |
| Native web automation              | Required Web Studio AU01–AU12 editing/publication/safety/recovery; independent of optional COM workflows.                                                        |
| Inngest execution                  | Shared bounded durable execution of product-owned work; no process, permission, financial or source-clock authority.                                             |
| Eve dynamic workflow               | Separate governed agent plan capability; not the tenant Studio language and not a grant to Studio actions.                                                       |
